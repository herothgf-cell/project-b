# 승객 공통 선택 효과 밸런스 v1 — 2026-11-06

현재 독립 선택 효과 시스템에 맞춘 **첫 플레이 기준값**이다. 사람의 장시간 플레이 통계로 확정한 최종 밸런스는 아니다. 사용자 승인으로 이 값을 출하 기본값으로 승격했다. 관리창 `default`, 기본값 복원, 설정 파일 없는 새 게임도 같은 값을 사용한다. 새 성공/실패 조건을 추가하지 않는다. 사용자가 수정한 대사는 유지한다.

2026-11-07 보완: 아래 공통 선택 효과는 유지하되 **등장/요청 비중과 신규12명의 개별값은 [다양화1차](content-design/17-passenger-roster-v1.md)가 우선**한다. ShortRoad/RouteAdvice는 비활성, 요청0/1/2=25/60/15%. 구 passenger-balance-v1은 과거 스냅샷이고 현재 구성 가져오기는 passenger-roster-v1을 사용한다.

## 조정 기준

- 단발 응답은 즉시 작은 보상, 실제 운행 약속은 종료 보상으로 나눠 같은 선택의 보상을 중복 지급하지 않는다.
- 실제 판정이 있는 실패만 조정한다. 법규/M과 겹치는 요청 실패 감점은 줄인다.
- 운행 중 S·피로 점/분, 모든 비율 효과, 자연 피로 추가율은 0. 긴 운송/대기나 보류만으로 보상을 얻거나 기본 피로를 상쇄하지 않는다.
- 대화에 참여하는 공감/지역 대화는 피로 +1을 한 번 적용한다. 조용한 배려는 피로 0이다. 기본 자연 피로 싱글 4/6/8점·PVP 5/7.5/10점/분은 유지한다.
- 명시적 보류·판정 불가의 추가 효과는 0. 안전한 응답 기회를 실제로 무시했을 때만 기존 미응답 판정에 따라 -2.

## 요청별 설정

모든 표의 S는 만족도 점수다. 표에 없는 단계/비율/피로 효과는 0이며, 요청에 없는 실패 판정은 만들지 않는다.

| 요청/선택 | 즉시 S | 즉시 피로 | 운행 중 | 종료 성공 S | 종료 실패 S |
|---|---:|---:|---|---:|---:|
| 조용한 운행 수락 | 0 | 0 | 기존 후속 수다 제한 | +3 | 판정 없음 |
| ETA 빠르게/내비대로/여유 안내 각각 | +1 | 0 | 없음 | 0 | 판정 없음 |
| 편안한 운행 수락 | 0 | 0 | 불필요한 급가감속 M 추가 -1 | +6 | -4 |
| 제시간 도착 수락 | 0 | 0 | 없음 | +6 | -3 |
| 큰길 / 짧은 길 수락 각각 | 0 | 0 | 기존 경로 행동 | +5 | 판정 불가 0 |
| 안전 하차 수락 | 0 | 0 | 기존 목적지 변경 | +4 | -4 |
| 공감: 이야기 듣기 / 조용한 배려 | +3 / +2 | +1 / 0 | 없음 | 0 | 판정 없음 |
| 경로 추천: 빠른 길 / 짧은 길 | 0 | 0 | 기존 경로 행동 | +4 / +4 | 판정 불가 0 |
| 면접: 응원 / 조용한 준비 | +3 / +2 | 0 | 없음 | 0 | 판정 없음 |
| 음악 요청 | 0 | 0 | 실제 음악 변경 미구현 | 0 | 판정 없음 |
| 운임 안내 / 결제 나중에 확인 | +2 / +1 | 0 | 없음 | 0 | 판정 없음 |
| 지역 대화 / 안전 운행 안내 | +3 / +2 | +1 / 0 | 없음 | 0 | 판정 없음 |
| 목적지 변경 수락 | 0 | 0 | 기존 목적지 변경 | +4 | -4 |
| 경유 용무 수락 | 0 | 0 | 기존 경유·무료 대기 | +5 | -4 |
| 불법 요구 안전하게 거절 | +1 | 0 | 실제 위반은 기존 법규/M 평가 | 0 | 판정 불가 0 |
| 모든 명시적 보류 | 0 | 0 | 없음 | 판정 불가 0 | 해당 없음 |
| 분실물 | 해당 없음 | 해당 없음 | 하차 후 별도 텍스트 사건 유지 | 해당 없음 | 해당 없음 |

미응답: Quiet M -5→-2, Empathy/Interview/LocalChat S -5→-2. 조용한 운행의 편집 프로필에 있던 시험값 0도 이번 균형값 -2로 조정한다. 나머지 미응답 규칙은 유지한다.

기존 출하 기준 대비 주요 변화: 운전형 성공 +8→+5~6, 실패 -10→-3~4; 단발 응답 종료 +5→즉시 +1~3. 음악은 실제 변경 없이 보상되던 +5→0. 음식 허용은 즉시 +5→+3으로 조정하고 기존 부스러기 -2·흘림 -6 및 확률/작업 시간은 유지한다. 나머지 유형·상황의 추가 선택 효과는 기존 0을 유지한다. 반복 상황 응답에 점수를 새로 주지 않는다.

## 공통 요소와 누적 한계

- 현재 요청 개수0/1/2건=25/60/15%. 그룹/요청 가중치는 다양화1차 표를 따른다. 표시 시점과 안전 조건은 유지한다.
- 종료 요청 합계 상한 ±10 유지. 서로 다른 요청 2개 기준 최대 순수 요청 보상은 +10(종료 +6 두 개가 상한 적용), 단발 +3 두 개는 +6, 단발 +3과 운행 +6은 +9다. 음식 허용이 함께 있으면 추가 +3까지 가능하다. 기존 주행·시간·청결 평가와는 별도다.
- Comfort는 불필요한 급가감속 1회 기본 M -2 + 요청 추가 -1 = -3, 종료 실패 S -4. 기존 -4와 종료 -10에서 완화한다. M과 S는 서로 다른 지표이므로 이를 단순 합산한 최종 S -7로 해석하지 않는다. 필요한 안전 제동은 계속 제외한다.
- ETA 세 답변은 실제 오차 실패 판정이 없으므로 같은 +1. 빠른 도착을 말하는 것만으로 더 큰 보상이나 피로 가산을 주지 않는다.
- 법규 감점, 일반 M 감점/회복, 운임·보너스, 만족도 요구치, 기한, 청결 비용, 기본 자연 피로는 그대로다. 기존 경제를 동시에 재설계하지 않는다.
- Quiet 약속 위반 관찰 부재, 목적지/경유 실패의 도달 제한 등은 [실제 판정표](content-tuning-request-outcomes.md)를 따른다. 숫자를 조정했다고 판정 공백이 해결되지는 않는다.

## 적용과 후속 편집

관리창을 다시 불러오면 `default`의 최신 다양화1차 값을 편집한다. 이미 열어 둔 창의 미저장 편집은 자동으로 덮어쓰지 않으므로 필요한 내용을 먼저 내보내고 **불러오기 → default**로 갱신한다. 별도 `passenger-balance-v1`도 불러올 수 있다. 버전 관리된 원본은 `config/content/presets/passenger-balance-v1.json`이다. **기본값으로** 버튼은 최신 다양화1차로 복원한다. 과거 passenger-balance-v1을 가져오면 제외한 경로 요청이 다시 켜질 수 있으므로 최신 구성은 `config/content/presets/passenger-roster-v1.json`을 사용한다.

이번 값은 **다음 새 싱글 캠페인 또는 새 PVP 방**부터 적용된다. 현재 운행/이어하기는 저장 당시 수치다. 적용 전 default/active 원본은 `config/content/backups/`에 보관하며 원래 대사·타 프로필은 보존한다. 관리창에서 수정한 뒤 저장·게임에 적용하면 된다.

실제 게임 코어 미리보기로 단계 결과를 확인한다. 이 미리보기는 자연 피로·실제 주행 사건·성공 판정 관찰을 시뮬레이션하지 않는다. 이후 사람 플레이에서 요청 충족률, 운송별 최종 S/요구치 초과량, 휴식 주기를 보고 미세 조정해야 한다.
