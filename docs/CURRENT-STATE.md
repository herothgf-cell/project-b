## 다른 PC에서 시작

기존 로컬 작업을 먼저 보존하고 저장소 루트에서 실행한다.

```powershell
git status --short
git switch main
git pull --ff-only
pwsh -File tools/update_distribution_manifest.ps1 -VerifyOnly
pwsh -File tools/check_workspace.ps1 -Strict
```

테스트만 할 때는 Unity/지도 압축 해제 없이 exe를 실행한다. `EungyeTaxi_Data`, `MonoBleedingEdge`, `UnityPlayer.dll`을 포함한 **실행 폴더 전체**가 필요하다. GitHub 저장소 ZIP을 받았다면 먼저 전체를 압축 해제한다. 임의로 만든 실행 ZIP을 `builds/EungyeTaxi` 안에 두면 manifest의 파일 수 검사가 실패할 수 있으므로 정식 배포 목록과 구분한다.

개발할 때는 Unity Hub에서 위 버전/Windows 빌드 지원을 설치하고 `unity/EungyeTaxi`를 연다. `Library/Temp`는 새 PC에서 생성한다. 기존 지도 재수입이 필요할 때만 `distribution/maps/Eungye-map-inputs-2026-10-20.zip`을 저장소 루트에 풀고 입력 검사를 다시 수행한다. **존재하는 입력의 해시 오류를 우회하지 않는다.** 자세한 절차는 [PC 이동 안내](work-history/README.md), [지도 입력 안내](work-history/map-transfer-guide.md).

```powershell
# Unity.exe 설치 경로는 각 PC에 맞게 지정한다.
# Unity 실행 프로세스의 실제 종료 코드와 로그를 확인한다.
& '<Unity 설치 폴더>/Editor/Unity.exe' -batchmode -quit `
  -projectPath "$PWD/unity/EungyeTaxi" `
  -executeMethod PrototypeBuild.BuildHybrid -logFile "$PWD/artifacts/build.log"
```

Windows GUI 실행은 셸이 먼저 반환할 수 있으므로 자동화에서는 `Start-Process -PassThru`와 `WaitForExit()`로 실제 빌드 종료를 기다린다. 실행 폴더를 바꾸면 실제 소스 커밋과 수행한 검증만 manifest에 기록하고 전수 해시 검증한다.

## Git과 별도로 옮겨야 하는 것

| 대상 | 옮기는 방법 |
|---|---|
| 개인 캠페인·사용자 편집 지도 | 게임 종료 후 `%USERPROFILE%/AppData/LocalLow/Taxi Prototype/은계 택시 시뮬레이터/` 전체를 별도 백업/복사. `RoadMaps`와 백업 JSON 포함. 기존 새 PC 파일도 먼저 보존 |
| PvP 닉네임 | PlayerPrefs 로컬 설정. Git/캠페인 파일로 동기화되지 않으므로 새 PC에서 다시 입력 |
| 원시 NGII/OSM 입력 | 재수입 작업에 필요한 경우 별도 복사. 정식 프로젝트 지도만 사용하는 개발에는 필수 아님 |
| `artifacts/` 증거 | 필요할 때 별도 복사. 이력/선별 PNG만 Git에 포함 |
| 현재 PC의 미추적 실험/ZIP | 정식 실행·개발 필수가 아님. 필요한 작업만 선택 백업하며 `Library/Packages/ProjectSettings` 같은 루트 실험 폴더를 실제 Unity 프로젝트와 혼동하지 않음 |
