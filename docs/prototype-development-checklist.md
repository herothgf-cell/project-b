# 프로토타입 개발 우선순위 체크리스트

기준일: 2026년 10월 16일 · 버전: 0.1 · 구현 확인 기준: `main` / `9c27de6`

기존 주행·영업 기반에 대표 운전 상황, 독립 법규 기록, 생활 비용과 납부 일정을 연결한다. **P0 준비 → P1 핵심 판단 → P2 생활·경제 → P3 캠페인 완주** 순서로 진행한다. P0~P3은 모두 프로토 필수이며, 번호는 착수 순서를 뜻한다.

기준: [로드맵](content-design/00-RoadMap.md) · [통합 범위](prototype-scope.md) · [콘텐츠 목록](content-design/README.md)

## 상태와 완료 표시

| 표시 | 의미 |
|---|---|
| 기존 구현 | 코드에 기반 기능이 있음. 새 기획 전체의 완료를 뜻하지 않음 |
| 보완 | 기존 기능에 새 조건·화면·연결을 추가하거나 동작을 변경 |
| 신규 | 현재 기반에 없는 콘텐츠·상태·처리 추가 |
| 검증 | 이미 있는 기능도 새 상황에서 동작·화면·경계를 재확인 |
| 미완료 체크 | 구현 또는 해당 완료 기준의 검증이 남음 |

아래 기존 상태는 개발 착수 전 소스와 과거 검증 문서의 확인 결과다. 이번 개발에서 실행한 빌드·Player 검사는 문서 끝의 구현·검증 업데이트에 별도로 기록했다. 작업은 구현 후 완료 기준을 확인하고 근거를 남겼을 때 체크한다.

착수 전 v1 코드의 `fuel`은 연료 **잔량이 아니라 누적 비용**이다. 이번 v2의 잔량은 `CampaignAccount.Fuel`로 분리했다. 정체 시험은 새 출구 콘텐츠 전체가 아니며, 시험 재시작도 사건 카드에서 영업 상태를 보존하는 복습 기능은 아니다.

## 우선순위 요약

| 우선순위 | 결과물 | 먼저 끝나야 할 것 | 단계 완료 모습 |
|---|---|---|---|
| P0 | 기존 실행 확인·제작 위치·공통 처리 기준 | 없음 | 기존 운송을 유지하며 새 작업을 시작할 수 있음 |
| P1 | 출구·우회전·독립 법규·히스토리·복습 | P0 | 선택 → 판정 → 이유 확인 → 다시 해보기 |
| P2 | 승객 요청·주유·식사·주차·보험·세금 | P0, 매너 예외는 P1의 상황 정보 | 영업 → 방문/납부 → 수입과 비용 반영 |
| P3 | 3일 캠페인·통합 저장·화면·플레이 검증 | P1·P2 | 새 도전 → 3일 영업 → 결과 → 이어하기/재도전 |

P2의 장부·거점 작업은 P0 이후 P1과 병렬 진행할 수 있다. 개발자가 한 명이면 표의 순서를 따른다. 화면과 저장은 각 기능을 만들 때 함께 연결하고 P3에서 전체 흐름을 확인한다.

## P0 개발 시작 전 기반 정리

참고: [06 맵·주행](content-design/06-world-map-and-driving.md), [통합 범위](prototype-scope.md).

- [ ] **P0-01 기존 은계 실행과 기본 운송 확인 — 검증.** 지도 자료를 준비하고 수동/보조 주행, 시점 전환, 호출·길가 승차·하차·정산을 확인한다. 완료 기준: 같은 빌드에서 기본 운송 1회를 끝내고 막힘·입력·화면 문제를 기록한다. 과거 자동 검사 결과만으로 완료 처리하지 않는다.
- [ ] **P0-02 상황·거점 위치 선정 — 보완.** 출구 대기열과 우회로, 우회전 교차로, 주유소·식당·주차장 각 1곳 이상의 제작 위치를 잡는다. 완료 기준: 짧은 영업 동선 안에서 접근·정차·복귀가 가능하고 필요한 신호·표지를 미리 볼 수 있다.
- [x] **P0-03 공통 상태와 조정값 정리 — 신규 기반.** 사건·운송·거래·하루 정산을 식별하고 법규/매너, 현금/미납/예정 납부를 분리한다. 3일·480초·30,000원을 새 목표로 두고 비용·감점 제안값은 조정 가능하게 모은다. 완료 기준: P1·P2가 사용할 상태와 중복 처리 기준, 기존 v1을 보존할 새 저장 버전의 경계가 정해진다.

## P1 운전 판단과 기록을 먼저 완성

참고: [01 운전 상황](content-design/01-driving-situations.md), [02 법규](content-design/02-driving-evaluation.md), [03 히스토리](content-design/03-history-and-mastery.md), [06 맵·AI](content-design/06-world-map-and-driving.md).

- [x] **P1-01 우회전 신호·보행 상태 연결 — 신규·보완.** 전방 차량 신호, 우회전전용신호, 보행 신호, 보행자의 없음/횡단 의도/횡단 중을 구분한다. 완료 기준: 화면·AI·판정이 같은 상태를 사용하고 현재의 보행자 안전 여부 고정값을 실제 관찰값으로 바꾼다. 선행: P0.
- [ ] **P1-02 출구 정체 A/B/C 제작 — 신규·보완.** 신호 대기열 뒤 합류, 직진 우회, 앞부분 진입을 실제 운전으로 수행하게 한다. 완료 기준: 상대 진행 방해·진입 포기를 구분하고, 합법적 대기·우회로도 운송을 마칠 수 있다. 놓친 출구는 다음 경로로 재탐색한다. 선행: P0.
- [x] **P1-03 우회전 R1~R5 제작 — 신규.** 전방 적/녹색, 전용 적색/녹색 화살표, 횡단 중·횡단하려는 보행자 조건을 재현한다. 완료 기준: 조건별로 신호·보행자·정지 위치가 일치하며 R5의 두 보행 상태를 각각 확인한다. 선행: P1-01.
- [x] **P1-04 독립 법규 판정과 점수 — 신규.** L01~L04·L06·L07을 빈차 포함 평가하고 준수/위반/보류/기회 없음을 구분한다. 완료 기준: 사건당 최대 감점 1회, 규칙별 이력은 각각 유지하며 승객 교체로 초기화되지 않는다. 법규 총점이 운임·매너를 자동 변경하지 않는다. 선행: P1-02·03의 상황 조건.
- [x] **P1-05 사건 카드·일일 누계·요약 — 신규.** 조건·행동·결과·판정·근거·보조 사용 여부와 요약 최대 2개를 표시한다. 완료 기준: 출구 C의 L06+L07은 사건 1건/-15점, 우회 B의 미수행 차로 변경은 평가 기회 없음으로 남는다. 유효 5건 미만은 기록 부족, 다음 날 점수만 초기화한다. 선행: P1-04.
- [x] **P1-06 동일 상황 복습 — 신규·기존 재시작 보완.** 결산 카드에서 준비된 장면을 다시 시작하고 원래 결산으로 돌아온다. 완료 기준: 영업 시간·연료·현금·매너·법규 누계가 바뀌지 않고 원래 사건이 보존된다. 기존 시험의 운송/잔액 초기화를 영업 상태에 적용하지 않는다. 선행: P1-05.

P1에서는 L05 보호구역 상황을 만들지 않는다. L08은 속도·행동 사실만 기록하고 감점은 보류한다. 자동 신호 정지·영상 리플레이도 제외한다.

## P2 승객 요구와 생활 비용 연결

참고: [04 승객](content-design/04-passengers-and-reservations.md), [05 경제·납부](content-design/05-daily-operation.md), [06 거점](content-design/06-world-map-and-driving.md).

- [x] **P2-01 현금·미납·거래 장부 — 신규·기존 정산 보완.** 실제 지급 운임을 입금하고 지출·미납·예정 납부를 분리한다. 완료 기준: 목표액은 `현금 − 시작 현금 − 미납`, 미납 결제는 현금과 미납을 함께 줄여 비용을 두 번 빼지 않는다. 같은 지급·결제 재입력도 한 번만 반영한다. 선행: P0-03.
- [ ] **P2-02 거점 접근과 정차 메뉴 — 신규.** 주유소·식당·주차장을 지도·내비·상호작용에 연결한다. 완료 기준: 빈차 정차 후 비용·시간·확정/취소를 확인하고 도로로 복귀할 수 있으며, 주차장에서 납부 관리·영업 종료를 선택한다. 선행: P0-02, P2-01.
- [x] **P2-03 연료·주유·고갈 지원 — 신규·자동 비용 교체.** 잔량·소모·부족 안내·보충 결제와 고갈 종료를 구현한다. 완료 기준: 주유 구매와 기존 자동 연료비가 중복되지 않는다. 탑승 중 고갈은 운임 0원 종료 → 공급/지원비 → 영업 시간 30초 경과 → 빈차 복구로 한 번만 처리한다. 선행: P2-01·02.
- [x] **P2-04 식사·주차비 — 신규·기존 비용 보완.** 하루 첫 식사, 미식사 마감 비용, 일일 주차비를 연결한다. 완료 기준: 방문 식비와 마감 식비가 중복되지 않고 주차비는 하루 한 번만 발생한다. 다음 날 식사 여부를 초기화하고 연료는 유지한다. 선행: P2-01·02.
- [x] **P2-05 보험 갱신 — 신규·자동 비용 교체.** 기존 계약의 만료 안내·조기 갱신·직접 결제·새 계약 시작을 구현한다. 완료 기준: 2일차 만료 제안에 맞춰 3일차 출발 전 유효 계약을 확인하며 미갱신·자금 부족은 출발 차단과 재시작 안내로 연결한다. 일일 보험료는 중복 차감하지 않는다. 선행: P2-01·02.
- [x] **P2-06 세금 고지·직접 납부 — 신규.** 기한·알림·조기 납부·완납·미납을 구현한다. 완료 기준: 3일차 기한 제안에서 미납이면 현금을 자동 출금하지 않고 비용과 미납을 한 번 반영한다. 결제·마감 재입력으로 이중 비용이 생기지 않는다. 선행: P2-01·02.
- [ ] **P2-07 승객 요청과 매너 예외 — 신규·보완.** 운송당 상호작용 요청 최대 1개로 조용한 운행/도착 문의를 제공하고 수락·안전상 보류를 표시한다. 완료 기준: 안전상 보류·도착 문의는 무감점, 조용한 요청 미처리는 응답 기회가 있었을 때만 제안 감점한다. 필요한 위험 회피 제동을 구분하면서 기존 100%/70%/시간 초과 0원 지급을 유지한다. 선행: 기존 운송·내비, 맥락 예외는 P1의 상황 정보.

시작 현금 10,000원, 보험 6,000원, 세금 1,500원 등은 [05의 게임용 제안값](content-design/05-daily-operation.md)이다. 현실 금액이나 사용자가 별도로 확정한 비용으로 취급하지 않는다. 사고 책임 판정·수리비·보험 청구는 P2에 추가하지 않는다.

## P3 캠페인 통합과 최종 확인

참고: [07 캠페인](content-design/07-campaign.md), [통합 범위](prototype-scope.md), [05 저장 기준](content-design/05-daily-operation.md).

- [x] **P3-01 3일 영업과 마감 연결 — 보완.** 3일·하루 480초·목표 30,000원으로 바꾸고 준비·영업·마감 예고·마지막 운송·정산을 연결한다. 완료 기준: 마감 후 새 수락 차단, 미탑승 호출 취소, 탑승 임무는 원래 기한 내 완료/실패 후 정산한다. 일시정지·결과·복습에는 영업 시간이 흐르지 않는다. 선행: P1·P2.
- [x] **P3-02 성공·실패·다음 날 판정 — 보완.** 순수익 목표와 보험 갱신·세금 납부 완료를 함께 확인한다. 완료 기준: 목표만 달성한 미완납 상태는 남은 날로 진행하고, 모두 충족하면 정산에서 성공한다. 마지막 날 목표/납부 미충족과 보험 만료·자금 부족을 구분해 안내한다. 선행: P2-05·06, P3-01.
- [x] **P3-03 통합 저장·이어하기 — 보완·신규 상태 추가.** 현금·미납·납부·연료·식사·법규 사건·승객 결과를 같은 하루 정산으로 저장한다. 완료 기준: 기존 v1 보존·새 버전 새 도전, 저장 실패·재시도에도 중복 없음, 진행 중 종료 시 당일 수입/비용/납부/기록을 함께 되돌린다. 선행: P1·P2의 데이터와 P3-01·02.
- [ ] **P3-04 전체 화면·안내 정리 — 보완·신규.** 준비·주행·운송 결과·거점·납부·하루 결산·히스토리·캠페인 결과를 연결한다. 완료 기준: 법규와 매너, 결제/미납/예정 납부를 구분하며 신호와 보행자 시야를 가리지 않는다. 기존 ‘새 7일 도전’ 등 문구를 새 범위와 맞춘다. 선행: 각 기능의 화면, P3-01~03.
- [ ] **P3-05 전체 플레이와 예외 검증 — 검증.** 정상 운행·우회 선호·법규 위반 선택 캠페인을 비교하고 연료 고갈·납부 누락·보험 자금 부족·저장 실패를 확인한다. 완료 기준: 합법적 운전으로 비용과 목표를 감당할 수 있고, 경로별 실제 소요·순수익·기록이 설명 가능하다. 자동 판정 검사와 실제 화면/수동 주행을 구분해 기록한다. 선행: P3-01~04.
- [ ] **P3-06 전달 빌드와 조작 문서 — 보완·검증.** 실행 파일, 구현 범위, 조작법, 저장 위치와 재시작 방법을 맞춘다. 완료 기준: 새 환경에서 필요한 지도 자료를 안내하고, 실제 제공 기능과 미구현 항목을 문서에서 구분한다. 과거 검증 문서를 새 완료 증거로 대체하지 않는다. 선행: P3-05.
