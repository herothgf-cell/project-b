# 승객·대화·효과·법규 관리 도구 설계안

작성: 2026-11-05. 상태: **사용자 구현 승인·설정 도구 단독 구현/검증 완료, 사고 기능과 공동 배포 통합 진행**. [실행 안내](../../content-tuning-tool-guide.md), [실제 검증/제한](../../work-history/2026-11-05-content-tuning-tool-implementation.md).

## 요청과 선택한 방향

승객 요청 / 대화 선택지 / 선택에 따른 효과 / 법규별로 현재 내용을 정리하고, 현재 설정에 영향을 주는 요소를 사용자가 직접 조정하는 도구를 만든다. 사용자는 **게임과 별도로 켜는 관리창, 표와 검색으로 편집**하는 방식을 선택했다.

검토한 접근은 별도 관리창(목록·검색·여러 항목 비교가 쉽지만 실행 도구가 하나 추가됨), 게임 내 설정창(플레이 중 접근이 쉽지만 편집 공간과 입력 충돌이 생김), Unity 개발 도구(코드 연결이 쉽지만 Unity 설치와 조작이 필요함)다. 사용자가 첫 번째를 선택했다. 아래 로컬 브라우저·Node 구성과 적용 시점은 작성자의 제안이며 추가 합의로 표시하지 않는다.

## 목적과 완료 모습

코드를 열지 않고 현재 값과 기본값을 비교하고 변경·검증·저장·복원한다. 한 항목에서 관련 대사, 선택지, 실제 효과, 발생 조건, 영향을 받는 지표를 따라갈 수 있어야 한다. 편집 화면에만 값이 바뀌고 게임은 예전 값을 쓰는 결과는 허용하지 않는다.

최초 프로필은 현행 동작과 같은 값이다. 새 콘텐츠·법규 판정·음악/에어컨/창문 조작을 추가하는 작업이 아니다. 차량 물리, 지도 geometry, 신호 프로그램, 보험/과실·새 사고 시스템은 범위 밖이다.

## 화면 구성

좌측에는 다섯 분류, 가운데에는 검색/필터가 있는 목록, 우측에는 상세 편집을 둔다. 상단에는 프로필 이름·변경 개수·검증·저장·게임 적용 대기 상태를 둔다. 저장 전 변경 요약을 확인하고 기본값/저장값으로 되돌릴 수 있다.

| 분류 | 직접 다루는 내용 |
|---|---|
| 승객 요청 | 기존17종의 이름·요청 대사·사용 여부·상대 가중치·성공/실패/미응답 점수, 발생 가능한 시점·조건 설명 |
| 대화 선택지 | 요청/유형/변주/상황별 승객 대사·기사 답변·후속/완료 대사. 기존 행동에 연결된 문구 수정 |
| 효과 | 선택 즉시/실제 행동 시/하차 시 효과 구분. 만족도·청결·준비/하역·재고정·용무 시간·섭취/흘림 확률·후속 대화 정책 |
| 법규 | 행동/조건별 현행 게임 감점·M 영향·관찰 시간/거리/속도·준수 회복, 구현 상태와 관련 요청·자료 연결 |
| 공통 영향 요소 | 요청 개수 비중/발생 진행률·간격, 유형 가중치, 요구 만족도·시작 편차·청결 가산、운송 기한 계수·여유, 도착/안심 회복·요청 합계 한도·운임/보너스 계수 |

검색은 한국어 이름·대사·ID·영향 지표를 대상으로 한다. 필터는 싱글/PVP 공통·전용, 변경됨, 사용/제외, 구현/부분/기획, 만족도/청결/시간/운임/법규 점수다. 각 값에 단위·기본값·현재 편집값·효과 발생 시점·적용 범위를 표시한다.

예: 음식 섭취 허용 선택에는 기사 답변, 만족도 기본+5, 실제 섭취 청결-2, 흘림25%·추가-6, 실제 섭취 발생 조건을 함께 보여 준다. 확률을 바꾸면 관련 효과 설명도 같은 설정으로 생성한다. 운전 점수→승차 운임 보정, M→최종 만족도→운임/보너스 연결을 각각 표시한다.

## 편집 가능 범위와 고정 동작

첫 버전은 기존 콘텐츠와 기존 평가 경로를 조정한다. 새 요청 종류·새 선택 행동·임의 스크립트 실행·새 법규 감지기를 UI에서 작성하지 않는다. 기존 선택의 문구와 지원된 효과 수치는 수정할 수 있지만 의미를 임의 교체하지 않는다. ETA/요금/목적지 등 실데이터 자리표시는 토큰 목록과 미리보기를 제공한다.

전제조건·예외·충돌 방지·정차 필요 작업·기회 없는 요청 중립·동일 사건 중복 방지·법규 점수/M 분리 등은 설명과 연관 항목으로 표시한다. 고정 상태인 항목은 이유를 보이고 비활성 편집 컨트롤로 편집 가능한 것처럼 꾸미지 않는다. 변경 가능한 발생 수치와 기존 안전/의미 제약을 구분한다.

법규 카탈로그76항목은 검색 가능한 자료 색인으로 제공하며 코드에 연결된 항목만 게임 수치를 편집한다. F/L 번호를 같은 번호라고 가정하지 않고 행동·조건별 안정 ID로 연결한다. 실제 법률·범칙금·법정 벌점·면허시험 자료는 출처·기준일을 가진 참조 정보다. 이 도구가 조정하는 수치는 게임 평가다. 신규 법률 감수는 별도 작업이다.

## 저장과 실행 구조 제안

- 로컬 HTML/CSS/JavaScript 관리창과 Node 표준 라이브러리 서버. 현재 PC에서 Node v24.21.0 확인. `tools/start_content_editor.ps1` 한 번 실행해 브라우저를 연다. 외부 서비스·로그인·추가 패키지·공개 호스팅 없이 사용한다. Node가 없는 다른 PC에는 설치 안내를 명시한다.
- 버전 있는 JSON 카탈로그/기본 프로필을 `config/content/`에 관리하고 Unity `Resources`에도 같은 검증된 산출물을 포함한다. 빌드 전 두 사본의 동일성을 검사한다. 프로필은 `schemaVersion`, ID, revision, contentHash, 안정 항목 ID별 값으로 구성한다. 알 수 없는 필드·중복 ID·누락 필수값을 거부한다.
- 사용자 프로필은 저장소의 `config/content/profiles/`에서 이름별 저장/내보내기/가져오기. 실행본은 `builds/EungyeTaxi/content/active-profile.json`에서 다음 새 세션의 설정을 읽는다. 파일명·폴더는 정해진 위치로 제한하고 임의 경로 쓰기 API를 두지 않는다.
- `저장`은 편집 프로필 저장, `게임에 적용`은 검증된 프로필을 실행본의 active 파일에 원자적으로 교체한다. 서버는127.0.0.1만 바인딩하고 Origin/세션 토큰·본문 크기·경로를 검사한다. 저장 충돌은 파일 revision/hash 비교로 감지하고 조용히 덮어쓰지 않는다. 로컬 백업은 배포 폴더 바깥에 둔다.
- 게임 실행 시 active 파일이 없으면 기본 프로필. 손상/미지원이면 파일을 보존하고 눈에 보이는 오류와 기본값 사용 상태를 보여 준다. 유효하지 않은 일부 값만 섞어 쓰지 않는다. 관리창에는 마지막 적용 파일 상태를 표시하고 실행 중인 게임이 새 값을 읽었다고 추측하지 않는다.
- 배포 폴더 파일 추가 시 `distribution/EungyeTaxi-build-manifest.json`을 재생성/전수 검증한다. 사용자가 이후 편집한 active 프로필의 해시는 출하 manifest와 달라질 수 있으므로 검증기는 출하 파일 일치와 허용된 사용자 프로필 변경을 별도 결과로 보고한다. 실행 DLL/지도 같은 출하 파일 검증을 느슨하게 만들지 않는다. PVP 위임 manifest도 이 계약을 따른다.

## 게임 반영 시점·저장·LAN

실행 중 즉시 덮어쓰기는 첫 버전에 포함하지 않는다. 적용된 프로필은 **다음 새 싱글 캠페인 또는 새 PVP 방** 시작 때 고정한다. 관리창에 이 시점을 명시한다. 새 프로필을 시험하려고 기존 캠페인을 삭제할 필요가 없도록 저장 경로가 분리된 `테스트 실행`을 제공한다. 테스트 프로필/실행은 별도 결과로 표시하고 기본 저장을 덮어쓰지 않는다.

싱글 checkpoint에는 활성 프로필의 전체 유효 설정·버전·hash를 함께 저장한다. 이어하기는 저장 당시 설정을 복원하며 디스크의 새 프로필로 진행 중 약정을 바꾸지 않는다. 프로필 없는 과거 저장은 해당 legacy 정책의 기본 설정으로 복원하고 기존 운임 정책2/3/4 등 버전 분기를 유지한다. 프로필 파일이 없어져도 유효한 checkpoint는 자체 snapshot으로 복원할 수 있어야 한다. 기존 JSON 본체·백업의 손상 보호를 유지한다.

LAN은 호스트가 검증한 유효 프로필 snapshot·schema·hash를 시작 전 전송한다. 참가자는 호스트 설정으로 표시/응대하며 로컬 프로필로 독립 평가하지 않는다. 봇도 동일 설정을 소비한다. 미지원 schema·변조 hash·초과 크기는 시작 전에 명확히 실패한다. 전송 프로토콜을 갱신하고 양쪽 빌드 갱신을 안내한다. 기존 설정 미지원 버전과의 암묵적 대전을 허용하지 않는다.

## 데이터 연결과 검증

설정 ID마다 단위·타입·범위·기본값·지원 모드·실제 소비 함수·연관 표시/저장/통신 지점을 기록한 registry를 둔다. UI 필드는 이 registry로 생성하고 Unity 런타임은 같은 계약을 검증한다. 설정 추가만 되고 소비자가 없는 항목은 `연결 안 됨`으로 처리하고 게임 적용 대상에 포함하지 않는다.

가중치는 음수 금지·유효 후보 합계 양수, 개수 비중 합계100, 진행률/최대 요청 수/선택지 수는 기존 스케줄·입력 지원 범위 안에서 검증한다. 초기 버전의 요청 수 상한은 현행2개다. 길이·시간·속도는 유한수/허용 범위, 점수·회복·청결·운임 계수는 명시 범위를 검증한다. 관계식(시작≤종료<하차 중단, 상한≥하한 등)을 함께 검사한다. 정확한 편집 범위 표는 구현 계획에서 소비자와 복원 검증을 함께 대조해 확정한다.

하드코딩된 표시 문자열만 바꾸지 않고 실제 계산/랜덤 배정/이행 판정/상태 검증의 같은 상수를 함께 전환한다. 예를 들어 준비 시간을 변경하면 `Validate()`의 기존10초 상한도 활성 설정과 저장 snapshot 기준으로 검증한다. 누적/과거 사건은 기록된 결과를 유지한다. 수정 프로필로 기존 저장·사건의 결과를 소급 재계산하지 않는다.

미리보기는 실제 설정을 소비하는 C# 평가 코어를 사용한다. 정해진 입력(기본 운임·요구/시작 만족도·주행/요청/청결·도착 시간·법규 사건)을 넘겨 결과와 근거를 받는다. 관리창 JavaScript에 정산식을 다시 구현하지 않는다. 미리보기용 실행 도구를 함께 배포하고 사용할 수 없으면 단순 표시임을 밝히며 실제 계산처럼 제시하지 않는다.

## 검증과 납품

1. 기본 프로필의 현행 동등성: 고정 seed 요청/유형 추첨, 선택지·대사, 만족도/청결/준비 시간, 법규/운임/보너스 대표 경계값이 기존과 동일.
2. 수정 전달: 실제 프로필을 수정해 UI 저장→runtime load→실제 계산→효과 설명→snapshot/복원까지 값이 전달됨을 확인. 불가능 조합·부정확 hash·범위 초과·손상 파일·중복 저장도 검사.
3. 관리창: 한국어 검색/필터·선택·변경/원복·가져오기/내보내기·충돌·오류·테스트 실행을 실제 브라우저에서 확인. 좁은 창에서도 편집/저장 버튼 접근 가능.
4. 싱글/PVP: 독립 테스트 저장, 기본 회귀, 호스트/참가자/봇 동일 프로필·재접속·미지원 거부. 위치 제어 검사, 자동 물리 주행, 사람 수동 플레이, 전체 캠페인 결과를 분리.
5. `PrototypeBuild.BuildHybrid`와 배포 manifest·필수 지도 입력 검증, 실행 도구/사용 안내/원복 절차/현재 값 목록/체크리스트·작업 이력 갱신. 다른 미커밋 HUD/메뉴/서비스 작업과 분리하고 지도·제품/회사명·기본 저장 위치 보존.

구현 순서는 카탈로그·기본 동등성 → 설정 소비/저장·LAN → 관리창·실제 미리보기 → 통합 검증·배포다. 사용자 검토 후 구현 계획으로 세분화한다. 이 문서 단계에서는 게임 코드·배포 실행본·지도·저장파일을 변경하지 않는다.
