# 경로 판단 중심 보조 운전 설계

상태: 사용자 승인 후 1차 비교 시제품 구현·자동 검증 완료. 브랜치: `feature/assisted-route-driving`. 결과와 한계: [검증 기록](../../assisted-driving-validation.md).

## 목적과 성공 기준

사용자는 익숙한 길과 교통 흐름을 읽어 빠른 경로를 선택하는 재미에 집중하고 싶다. 차선 변경에서는 주변 간격을 관찰하고 방향 입력으로 이동하며, 정밀한 조향 부담은 줄인다. 기존 도로·교통·승객 시스템으로 작은 주행 시험을 먼저 완성한다.

성공 기준은 조작 부담 감소, 자발적 경로 변경, 선택 결과의 이해다. 자동으로 목적지까지 데려다주는 기능은 목적에 포함하지 않는다.

## 현재 코드와 접근 방식

`TaxiController`는 WheelCollider 조향·가감속을 처리한다. `RoadNavigation`은 중심선에서 우측 차로를 계산하지만 내부 그래프를 공개하지 않는다. `TrafficSystem`의 시험 교차로 경로는 별도로 생성된다. 차로 보조가 내비 경로를 그대로 따라가면 플레이어의 경로 선택이 사라지고 재탐색 때 조향이 튈 수 있다.

검토한 접근은 조향 보정 강화, 차로 경로를 따르는 보조 조향, 차량을 궤도에 직접 고정하는 방식이다. 보조 조향을 선택해 기존 충돌·가감속을 활용하고 플레이어의 방향 선택을 유지한다. 단순 보정만으로는 버튼식 차선 변경을 제공하기 어렵고, 궤도 고정은 주변 차량과 충돌할 때 순간 이동이나 겹침을 만들 수 있다.

## 첫 구현 범위

- 기존 수동 모드와 전환 가능한 보조 모드. 시험 구간 밖에서는 상태를 표시하고 수동으로 복귀한다.
- 현재 지도에서 검증한 연결 구간을 사용한다. 지도 전체를 자동으로 주행 가능하다고 간주하지 않는다.
- 차로 유지, 같은 방향 인접 차로로 한 번씩 변경, 교차로 직진·좌회전·우회전 선택.
- 가속·제동·신호 진입 시점은 플레이어가 결정한다. 보조는 조향과 회전 중 속도 안정화를 담당한다.
- 기존 승객 운송과 내비게이션을 사용한다. 호출 목적지가 보조 모드의 회전 선택을 덮어쓰지 않는다.
- 같은 출발·도착 지점의 대안 경로 두 개와 재현 가능한 정상/정체 시험 상황.
- 경제·지도·차량 종류의 추가 확장은 이 시험 결과 이후에 진행한다.

## 조작안

보조 모드 전환은 H, 가감속은 기존 W/S와 위/아래 방향키, 강한 제동은 Space를 사용한다. A/D 또는 좌/우 방향키는 차선 변경 요청이다. 키를 유지해도 여러 차로를 연속 변경하지 않는다. 패드 왼쪽 스틱은 중립 복귀 후 다시 기울였을 때 한 번 요청한다.

교차로 접근 시 Q/E로 좌/우회전을 예약하고 같은 입력을 다시 누르면 직진으로 되돌린다. 기존 깜빡이와 연동하며 HUD에 선택 방향과 가능한 방향을 표시한다. 차로 변경 입력과 회전 예약을 분리해 접근 중 입력 의미가 갑자기 바뀌지 않게 한다. 진입 후에는 선택을 고정한다.

위 키 배치와 위험 처리 방식은 이 검토안의 구현 가정이다.

## 차선 변경과 위험 처리

플레이어가 이동 시점을 선택한다. 뒤차와의 거리·접근 속도를 관찰할 수 있도록 기존 거울과 측후방 화면을 활용한다. 위험한 접근은 경고하되, 요청을 저장했다가 나중에 자동 실행하지 않는다.

요청 시 이미 겹치게 되는 차량·장애물이 있으면 즉시 거절하고 이유를 표시한다. 움직이는 뒤차와의 충돌을 무조건 방지하는 자동 운전은 제공하지 않는다. 진행 중의 반복 입력은 무시하며, 기존 충돌과 매너 판정은 유지한다. 반대 차로·존재하지 않는 차로로 이동하지 않는다.

차선 변경은 현재 위치에서 목표 차로까지 연속적인 목표 궤적을 만들고 물리 조향으로 추종한다. 정지 중에는 차체를 옆으로 이동시키지 않는다. 후진 시에는 수동으로 전환하며 메시지를 표시한다.

## 교차로와 경로 선택

검증된 차로 연결만 선택지로 제공한다. 회전 가능 차로에 들어가지 못한 경우 해당 회전을 선택할 수 없으며, 지나친 회전을 위해 역주행하거나 순간 이동하지 않는다. 직진이 불가능한 구간에서는 미선택 상태를 미리 알리고 끝점 전에 정지하도록 보조한다.

정상적인 신호 대기와 앞차 제동은 플레이어가 수행한다. 미지원 구간의 끝점 정지는 경로 이탈 방지 기능으로 별도 표시한다. 물리적으로 경로를 크게 벗어나면 자동 재부착하지 않고 수동 복귀 안내를 표시한다.

## 구성과 책임

- `AssistedRoadNetwork`: 검증 구간의 방향별 차로·연결·허용 회전을 보유. 지도 도로 ID와 연결해 중복 좌표의 근거를 추적한다.
- `AssistedDriveController`: 모드, 입력 요청, 차로 변경·회전 상태, 조향 목표를 관리. 내비게이션의 목적지 경로와 독립적으로 동작한다.
- `TaxiController`: 기존 물리 구동에 보조 조향 출력을 적용. 자동 테스트 입력은 기존 우선순위를 유지한다.
- `TaxiSignals`와 HUD: 중복 입력을 막고 회전 예약·보조 상태·요청 거절 이유를 표시한다.
- 시험 시나리오: 동일 출발/도착·교통 초기 조건·경과 시간을 기록한다. 기본 게임 경제에 시험 보상을 누적하지 않는다.

## 검증

정책 테스트: 입력을 유지해도 한 번만 변경, 중립 복귀 후 재요청, 반대 방향 차로 거절, 정지/후진 처리, 교차로 진입 후 선택 고정, 전환·복귀 시 예약 초기화.

Unity 실행 검증: 직선 차로 유지, 양방향 차선 변경, 좌·우회전, 인접 차량 거절, 접근 중인 뒤차 경고, 충돌 후 수동 복귀, 일시정지, 승하차, 기존 수동 운전과 자동 시험의 회귀 여부.

경로 시험은 두 경로 모두 완주 가능하고 정상/정체에서 유리한 경로가 바뀌는지 확인한다. 출발 상태와 신호 시간을 맞춰 반복 측정한다. 조작 편의와 재미는 사용자 플레이로 별도 확인하며 자동 테스트 통과를 재미 검증으로 취급하지 않는다.

## 단계

1. 차로 유지와 차선 변경을 기존 수동 운전과 비교한다.
2. 교차로 선택 및 대안 경로를 연결한다.
3. 정상/정체 시나리오에서 경로 판단을 검증한다.
4. 검증 결과에 따라 승객 기한·매너·경제 균형을 조정한다.
