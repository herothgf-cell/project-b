# 국도 42호선 실제 차로 시험 설계

## 목적과 범위

사용자 요청은 은계 국도 42호선의 실제 차로 연결을 내비게이션과 H 보조 운전에 함께 반영하는 것이다. 좌회전 경로가 우회전 차로에 표시되는 문제를 해결하고, 운전자가 직접 가감속하면서 올바른 차로에서 회전할 수 있어야 한다. 기존 영통·은계 영업 모드는 보존하고 은계 국도 42호선 시험 모드에서 먼저 검증한다.

## 시험 교차로 선정

2025 패키지 `일반국도_42호선_SEC002`를 사용한다. EPSG:5186 기준 아래 중심 반경 65m에 좌우로 회전하는 실제 링크가 모두 있다. 이름은 게임 시험용이며 실제 교차로 명칭이 아니다. 각 중심은 시험 영역 식별용 근사 좌표다.

| 식별자 | X | Y | 반경 내 링크 | 좌/우 회전 형상 링크 |
|---|---:|---:|---:|---:|
| R42-A | 182400 | 537630 | 57 | 5 / 4 |
| R42-B | 182690 | 537570 | 64 | 6 / 4 |

두 중심은 약 296m 떨어져 있다. 지도 서쪽 경계에 붙은 후보보다 진입·진출 여유가 있고, 연속 교차로에서 차로 준비를 시험할 수 있다. 회전 형상 수는 시작·끝 접선 각도가 40~140도인 링크를 센 값이며 교통 규칙 판정이 아니다. 실제 진행 가능 여부는 연결 ID와 코드 명세를 함께 검증한다.

추가 연결 검사에서 A의 좌회전 형상 5개, B의 좌회전 형상 6개는 앞뒤 링크가 노드 ID로 연결됨을 확인했다. 우회전 형상 링크는 같은 검사에서 앞뒤 연결이 모두 성립하지 않았다. 따라서 두 구간은 우선 시험 후보로 선정하며, 우회전은 원본 연결 구조·코드 및 구간 누락 여부를 더 확인해야 한다. 이 문제를 좌표 근접 연결로 덮지 않는다. 해결되지 않으면 해당 우회전을 미지원으로 표시하고 다른 검증된 시험 경로를 선정한다.

## 구조 선택

기존 폭 기반 추정 차로에 정밀 차로를 섞으면 임의 연결이 다시 생길 수 있다. 모든 지역을 한 번에 교체하면 미확보 구간의 기능이 사라진다. 따라서 시험 모드에서 정밀도로지도 전용 그래프를 공통으로 사용하고, 기존 지도는 기존 그래프를 유지하는 방식을 선택한다.

1. Python 변환기는 선택한 구간의 원본 ZIP을 읽고 EPSG:5179에서 5186으로 변환한다. 원본 링크 ID, 노드 ID, 좌우 인접 링크 ID, 차로 번호, 갱신일과 출처를 보존한다. 원본은 변경하지 않는다.
2. 차로 중심선의 실제 정점을 유지한다. `tonodeid`와 `fromnodeid`가 연결되는 방향만 진행 가능하다. 공간적으로 가깝다는 이유로 연결하지 않는다. 잘린 경계는 종료 지점으로 취급한다.
3. 좌우 인접 ID는 동일 방향 여부와 공간적 겹침을 검증한다. 인접 차로 존재가 곧 변경 허용이라는 뜻은 아니므로 노면선 코드와 차로 변경 구간을 대조한다. 불명확한 변경은 허용하지 않는다. `laneno=91` 같은 특수 값을 일반 차로 번호로 표시하지 않는다.
4. 내비게이션과 보조 조향은 동일 그래프와 회전 링크를 사용한다. 내비게이션은 도로 중심에서 임의 오프셋을 만드는 대신 실제 차로와 회전 링크를 표시한다. 차로 변경 안내도 검증한 연결만 사용한다.
5. H는 조향만 보조한다. W/S/Space 가감속, 제동, 신호 판단은 사용자에게 남긴다. 좌우 차로 변경 및 회전 요청은 해당 링크에서 가능한 경우만 수락한다. 신호나 연결 끝에서 자동 감속하지 않으며 지원 구간 끝을 알리고 수동으로 전환한다.
6. 실제 노면선과 표시를 시각화하고 차로선과 도로 표면·충돌체의 정렬을 확인한다. 추정 차선을 같은 위치에 겹쳐 그리지 않는다. 신호 주기는 원본 객체에 없으므로 시험용 설정임을 표시한다.

## 사용자 흐름

전용 실행기로 국도 42호선 시험 모드를 시작한다. 실제 진입 차로에 차량을 배치하고 좌회전·우회전 목적지 프리셋을 제공한다. 화면에는 다음 회전과 준비 차로, H 상태를 표시한다. 차로를 놓치면 확보된 그래프에서 다시 탐색하며 연결되지 않은 길을 가로지르는 안내를 만들지 않는다. 원본으로 경로를 만들 수 없으면 경로 없음으로 명확하게 알린다.

시험 모드는 캠페인 저장·목표 금액에 영향을 주지 않는다. 일반 차량이 시험 모드에서 주행한다면 동일한 검증 그래프를 사용해야 하며, 기존 추정 회전 경로로 진입시키지 않는다.

## 변경 대상

- 새 HD 지도 변환기·설정·검증 보고서와 재생성 가능한 JSON.
- `MapData.cs`: 선택적 정밀 차로 데이터와 출처.
- 공통 정밀 차로 그래프: 방향 연결, 인접 차로, 경로 탐색, 원본 곡선.
- `RoadNavigation.cs`, `AssistedRoadNetwork.cs`, `AssistedDriveController.cs`: 정밀 지도 모드 분기 및 공통 그래프 이용.
- `WorldBuilder.cs` 및 도로 환경: 실제 노면 표시와 도로 표면 정렬.
- 시험 모드·전용 실행기·회귀 검사. 기존 영통·은계 기능도 검사한다.

## 완료 기준

- R42-A/B의 선택한 좌·우회전 경로에 진입→회전→진출 노드 연결이 존재하고 원본 ID로 추적 가능하다.
- 연결 없는 차로, 반대 방향, 미검증 인접 차로, 잘린 지도 경계에 가상의 회전·변경 연결이 생기지 않는다.
- 내비게이션 경로와 H가 따라가는 경로가 같은 차로·회전 링크다.
- 차로를 놓친 후 재탐색과 도달 불가 상태를 검사한다.
- H 활성·회전·차로 변경·종료 중 사용자의 가속/제동 입력을 변경하지 않는다.
- Unity Player에서 두 교차로의 좌우회전과 차로 변경을 물리 주행으로 확인하고, 기존 지역의 내비게이션·보조 조향 회귀 검사를 통과한다.
- 원본 갱신일이 2020/2022인 객체를 현재 현장 규칙으로 단정하지 않는다. 최종 보고에 시험 범위와 아직 대조하지 못한 규칙을 명시한다.

## 현재 상태

사용자가 설계를 승인한 뒤 구현과 실행 파일 빌드를 완료했다. `Play-Route42.cmd`로 시험한다. 자세한 구현·검증 기록은 `../plans/2026-10-15-route42-lane-network.md`에 있다. 우회전은 원본의 진입→회전 곡선 연결을 사용하고 자료가 끝나는 곁도로에서는 이어지는 도로를 생성하지 않았다. 이 시험 모드는 차로·내비게이션·조향 검증에 한정하며 실제 신호 시간 미확보로 신호 운영과 일반 차량은 제외했다.
