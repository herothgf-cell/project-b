# 거리뷰 신호·승객 응대 후속

## 사용자 요청

- 첨부1/2 좌회전 신호 누락,2 차선별 좌회전 차로를 네이버 거리뷰와 대조해 수정.
- 첨부3 좌회전 금지 접근과4 횡단보도 신호는3구 여부를 거리뷰로 확인하고 월드/내비를 함께 맞춤.
- 점수 변동 알림과 내비 겹침 해소.
- 기사 선택 답변을 승객 발언처럼 표시하지 않고 실제 선택에 대한 승객 반응을 표시, 발언 바깥 큰따옴표 제거.
- 활동적인 요청 빈도/가중치 증가. 추가 답변으로 **주행 중 새 요청 표시**를 승인했다. 실제 적재/정리/휴식 등의 정차 조건은 보존한다.

## 확인·적용 기준

- 위치: 이미지1 J7917_2565 동향(axis1/-1),2 J7973_3744 북향(axis1/-1),3 J1927_5181 서향(axis1/+1),4 J6480_2573 동향(axis0/+1). 실제 거리뷰 방향/촬영월/링크를 별도 근거로 기록한다.
- 3/4구 외형은 회전 허가와 별도 명시 데이터로 관리한다. 확인되지 않은 전체 교차로를 일괄 변환하지 않는다. lane 시각 수정 시 실제 enabled 방향 연결/표시와의 대응을 함께 확인한다.
- 기존 유효 좌회전 연결에 대해서만 수요 추론을 보완한다. 명시 방향지시등 우선, 좌회전 전용 차로 또는 같은 현재 차로/해당 교차로의 유효 내비 경로에 한정한다. 잘못된 축/이미 통과/비활성/이전 경로/오프로드/유턴은 제외하며 통행 허가를 새로 만들지 않는다.
- 알림은 실제 내비 하단보다12논리픽셀 아래에서 쌓아 두 시점/기본 해상도의 겹침을 없앤다.
- 요청 배정 번들0/1/2건 가중치25/60/15→15/60/25. SafeStop2→3, DestinationChange1→2, ViaStop1→2. disabled/enable 상태와 기존 대표 요청 연결은 보존한다. 설치 프로필의 이전값20/60/20·각1은 별도로 기록하고 사용자 종료 뒤 요청한6개 값만 백업/해시 후 적용한다.
- 새 요청은 대화 가능할 때 주행 중에도 나타나며 이전 선택/수면/작업/경유대기/모달과 겹치지 않는다. 두 요청 사이 실제 주행20초·진행률85% 마감·기존 저장 필드는 유지한다.
- NPC 반응은 기사 문구와 별도로 계산한다. 선택·효과·기사 기록·사용자 편집 원문은 보존한다. 큰따옴표는 발언 바깥 쌍만 정리하고 문장 속 인용은 유지한다.

## 검증·배포

수정 전 실제 두 접근의 Q-on/off 재현, 잘못된 내비 수요 차단, 명시3/4구 월드/HUD一致, 차로 연결·내비 경로, 실제 주행 요청 표시/작업 안전·반응/복원·LAN·UI 캡처를 검증한다. 게임용 신호 시간은 촬영 신호 주기와 동일하다고 주장하지 않는다.

필수 지도 입력을 변경하면 실제 ProjectMap 저장/해시/로컬 manifest·관련 배포 ZIP을 갱신하고 Strict/출하 SHA256을 검증한다. 사용자 세이브·제안서 편집은 보존한다. 기존 main을 보존해 새 실행본과 문서를 함께 게시한다.
