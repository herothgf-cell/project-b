# 캐주얼 조작·신호 대기 개선

사용자 승인: 직전 제안에 대한 “이렇게 진행해줘”. 추가 승인 절차 없이 그 범위에서 구현한다.

## 방향과 대안

- 선택: 키보드/패드의 브레이크·반대 조향을 명확하게 하고 저중속 코너를 쉽게 만든다. 교통 판단과 보행 보호는 유지한다.
- 미선택: 물리 전체 교체/초고속 회전, 전역 시간 배속, 모든 녹색 단축. 기존 H 경로·경제·법규 평가를 무너뜨릴 수 있다.
- 신호는 기본 게임용 프로그램에만 수요 제어를 덧붙인다. 편집·교육·실제 자료 기반 별도 프로그램은 그대로 쓴다.

## 구현 계약

- S 일반제동은 기존0.18 대비1.5~2배 범위에서 물리 비교로 결정한다. Space 긴급제동은 유지한다. 전진 제동 후 S를 계속 누르면 정차 유지, 놓았다 다시 눌러 후진한다. 후진 중 W도 같은 규칙이다.
- 수동 입력 시작/반대 조향을 빠르게, 복귀는 부드럽게 한다.15~35km/h의 수동 최대각 감소를 완화하고 고속/H 기하·전복 억제를 보존한다. LAN 권한/예측은 같은 함수와 정차 상태를 쓴다.
- 초록불 대기열의 같은 차로 추종·상충/출구점유를 분리해 검사한다. 실제 재현된 문제가 있을 때만 예약 조건을 고친다.
- 신호 수요는 NPC 접근·모든 택시의 실제 위치/방향/깜빡이·보행 대기에서 모은다. 내비 목표가 없어도 반영한다. 최소 녹색/황색/정리·보행 완주를 보존하며 빈 단계 생략·대기열 녹색 연장·최대 대기 방지를 적용한다.
- 인접 접근은 같은 교통 시계와 선행 감지로 준비시키되 충돌 안전과 대기 수요가 우선이다. 실제 현장 신호 연동이라고 표시하지 않는다.
- HUD는 현재 신호 변경과 내 방향 진행 예상 시간을 구분한다. 수요에 따라 달라지는 값은 예상이라고 표시한다. 우회전에는 진행 허가로 오해할 숫자를 주지 않는다.
- LAN은 호스트 신호 상태를 복제하며 참가자가 독자적으로 빈 단계를 생략하지 않는다. 저장 파일/지도/운임 변경 없음.

## 검증과 수용

기존 식의 실패 검사 → 새 모델/실제 PhysX 비교 → 실제 싱글/PVP·LAN 순서.20/30/40km/h 정지 거리,90도 좌우 코너·고속 전복/차선 변경, S정차/해제/후진, 같은 차로3대 연속 출발, 상충 녹색0/보행 완주·대기 상한·수요 없는 택시 접근을 확인한다. 자동 물리와 사람 체감·다른PC 검증은 구분한다.
