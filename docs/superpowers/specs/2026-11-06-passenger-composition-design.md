# 승객 프리셋·특성 조합 상세 설계

사용자는 2026-11-06 앞선 구조 검토의 프리셋+특성 조합 방향을 선택하고 상세 기획, 관리 툴 업데이트, 요소별 확장 및 효과 정리를 요청했다. 이 문서는 구현 계약이며 기획자용 상세 설명은 `docs/content-design/15-passenger-presets-and-traits.md`로 제공한다.

## 선택한 접근

유형 계속 추가는 조합 폭발, 임의 스크립트 편집기는 검증 부담이 크다. 승인된 방향대로 기존 행동 모듈을 조합하는 프리셋 편집기를 기존 관리창 안에 추가한다. 신규 행동은 별도 개발 필요로 표시한다. 기존 공유 선택지 효과·요청 판정·청결·정산을 재사용한다.

## 데이터 계약

기존 schema2 프로필의 문자열 설정 키 `passenger.presets`에 JSON을 저장한다. 기존 해시·세션 snapshot·PVP 호스트 복제를 그대로 사용한다. 값은 `{version:1,presets:[...]}`이며 최대32프리셋, 문자열 최대32000자, 전체240KiB 제한을 유지한다. 기존 프로필에 이 키가 없으면 그대로 검증/복원 가능하고 새 편집 이관에서 기본값을 보충한다. 없는 값은 기존 승객 동작이다.

각 프리셋 필드는 정확히 `id,name,enabled,weight,pool,traits,intro`이다. id는 영문소문자/숫자/_/- 1~48, name1~60자, intro0~240자, enabled bool, weight정수0~100, pool은 기존 PassengerType 이름12종 중 하나, traits는 중복 없는 아래 ID 배열이다. pool은 기존 등장 확률/하루한도/쉬는 운송 규칙을 보존하는 배정 그룹이며 행동 자체를 결정하지 않는다. 같은 pool 안 enabled/weight>0 후보를 고정 시드로 선택한다. 해당 pool에 활성 프리셋이 전혀 없으면 일반 프리셋/기존 일반 행동으로 안전 폴백하며 거절·재수락으로 재추첨하지 않는다. Drunk pool의 프리셋에는 body.drunk 필수, 다른 pool에는 금지하여 기존 하루한도를 우회하지 않는다.

특성 ID:
- 대화: `speech.quiet`, `speech.talkative` (서로 배타, 없으면 표준)
- 신체: `body.drunk`, `body.sleepy`, `body.sensitive` (음주와 졸림은 공통 기상에서 중복하지 않음)
- 목적: `purpose.hurried`, `purpose.route`, `purpose.errand`, `purpose.precise` (최대1)
- 소지품: `item.luggage`, `item.muddy`, `item.food` (최대1; 오염 짐은 보호 작업 포함 모듈)

기본12프리셋은 General[], Drunk[body.drunk], Sleeping[body.sleepy], Comfort[body.sensitive], Hurried[purpose.hurried], RouteChecking[purpose.route], Errand[purpose.errand], Luggage[item.luggage], MuddyLuggage[item.muddy], Food[item.food], PrecisionStop[purpose.precise], Talkative[speech.talkative]. 각 weight1·enabled true·intro空. 기존 변주는 고정시드로 유지한다. 기본 프리셋이 단일 기존 특성일 때 기존 동작·숫자 동일.

## 실행 계약

최종 구현 판단: 주 행동(졸림/대화 선호/소지품)최대1, 대표 요청(승차감 민감/목적)최대1, 독립 음주(졸림과 배타), 독립 조용함(대화 선호와 배타). General 그룹은 없음/조용함만. 일반 특수 그룹은 선택될 실제 프리셋의 요청 가용성을 사전 검사해 빈/불가 그룹을 추첨에서 제외하며 다른 가용 그룹으로 비중이 재분배된다. 취객 별도 추첨/최종 후보 없음은 무특성 일반 폴백한다. 프리셋ID 사전식 정렬·예약 seed 저장으로 목록 정렬/재수락 재추첨을 방지한다. 명시적 조용함은 흔들림/필요제동·재고정 안내를 막지 않는다.

실행 상태는 프리셋 ID·이름·특성·소개·각 행동의 선택/진행/예정 사건을 저장한다. 여러 행동의 준비/대화는 한 번에 하나를 제시하며 필수 구토/안전 경고 우선. 짐과 음식/수면 등의 행동이 중복 실행되지 않게 효과ID를 모듈별로 구분한다. 기존 대표 요청은 공유0~2슬롯 안에 연결하고 상충 경로/조용한 운행 규칙 유지. 명시적 quiet는 일반 후속 수다만 제한한다. intro는 사용자 소개이며 실제 작업/안전 안내를 대체하지 않는다.

출하 지원 조합의 범위는 기존 행동을 실제 실행할 수 있는 조합으로 검증한다. 구현상 연결되지 않은 조합은 무시하지 않고 양쪽 검증에서 차단하며 이유를 기획 문서·툴에 표시한다. 최종 지원/배타표는 구현과 일치하게 기록한다. 손님 ID만 추가해 기존 행동을 조합하는 작업에 새 C# enum 추가가 필요 없어야 한다.

## 도구 계약

기존 관리창 첫 분류에 승객 프리셋. 목록/검색/선택, 새 승객·복제·삭제, ID·이름·사용·가중치·배정 그룹, 분류별 특성 체크, 소개 대사, 결과 행동/효과 요약·충돌 사유를 표시한다. 기존 하단 검증/저장/내보내기/가져오기/게임 적용 흐름 사용. 자동 저장/사용자 기존 프로필 덮어쓰기 없음. 새 기본값·이관·앱 재로딩·동시 편집 충돌/해시 보존. 공유 효과는 기존 편집 화면으로 연결하고 새 승객이 선택한 행동의 효과를 공유함을 알린다.

## 검증

Node와 C#에 동일 유효/무효 픽스처: ID중복, 알 수 없는 특성, 초과길이, 잘못된수, 배타, 음주 pool, 전체크기. 기본12동등성, 신규 음주+조용함+짐 조합, 기존 음식/수면/요청/효과 회귀, 저장 복원/추첨 안정성. 관리창 실제 추가·복제·저장·재로드·검증 오류와 1280/800 화면. 게임 통합 빌드와 실제 Player 조합 fixture, manifest 재생성/검증. 사람 장시간 주행·다른PC는 별도이며 자동 검사로 대체 주장하지 않는다.
