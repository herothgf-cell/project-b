# 승인된 설명·평가 UI 후속 정리

요구: 운송 종료 평가/답하지 않았을 때/모든 요청에 적용되는 공통 설정을 나누고 중복 점수 편집 제거. 모든 값의 게임 내 적용 시점과 영향 대상을 화면에 표시. 후속 제한 효과가 확률 감소가 아닌 어떤 추가 대화 차단인지 정확히 설명.

1. 현재 코드와 후속 제한 경로 확인(완료). Quiet/공감·면접 조용한 응대는 추가 상황 반응과 취객 일반 수다 제한. 별도 예약 요청/필수 안내 유지. 승객 유형의 Quiet와 상황 응대 Quiet는 별도 범위를 구분.
2. 모델/실제 DOM 회귀 먼저 작성: 요청 점수 편집 한 번, 미응답 별도, 카드 결과는 읽기 요약+평가 연결. 필드별 시점/대상 metadata 및 고정 범위 테스트.
3. 모델 카드 resultIds로 점수 요약을 보존하고 편집은 평가 한 곳. fieldInfo를 렌더러에서 공통 사용. 프로필/게임 코드는 유지.
4. 전체 Node/브라우저 확인, 독립 리뷰. 실제 C:/git/project-b의 해당 UI·검사·안내·전용 이력만 반영/선택 커밋. 동시 사고/지도 빌드와 사용자 프로필은 보존. 배포 검사는 동시 빌드 상태와 구분.

이전 worktree의 미커밋 내용을 보존하기 위해 최신 C:/git/project-b 기준 writable overlay에서 개발한다. 실제 실행 중 관리 서버는 정적 assets를 읽으므로 브라우저 새로고침으로 UI 갱신 가능(API/route 변경 없음). 사용자 편집 중이면 강제 새로고침하지 않는다.
