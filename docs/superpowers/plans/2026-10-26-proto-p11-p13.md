# P11→P12→P13 및 최종 안정화 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 요청 다양화, 지역 수요/공차 성과, 승하차 공간 점유를 순서대로 개발한 뒤 안정화와 통합 검증을 수행한다.

**Architecture:** 기존 단일 요청의 관찰 상태를 요청별 기록으로 분리하고 기존 UI/정산은 집계 결과를 사용한다. 수요와 영업 성과는 별도 모델, 공간 점유는 기존 승하차 후보/내비를 사용하는 별도 컴포넌트로 구성한다. 같은 운송 ID와 구형 저장을 보존한다.

**Tech Stack:** Unity2022.3.62f2, C#, Windows, 기존 PowerShell 검사/BuildHybrid.

**Spec:** `docs/content-design/17-proto-operation-expansion.md`, `04-passengers-and-reservations.md`, `11-passenger-request-effects.md`.

## Global Constraints

- 사용자 최신 지시: **P11→P12→P13 개발 후 마지막에 안정화·완성도 검증**. 기존 문서의 안정화 우선 문구보다 우선한다.
- 중간 단계마다 전체 모델/지도/빌드/캠페인 검사를 반복하지 않는다. 각 단계가 통합된 시점에 집중 검사1묶음을 실행한다. 실패 때만 해당 항목 재검사.
- 중간 검사는 컴파일·해당 기능 계약 확인이다. 수동 플레이·완성도 검증 완료로 표시하지 않는다.
- 기본 실행 `builds/EungyeTaxi/EungyeTaxi.exe`, 최종 빌드 `PrototypeBuild.BuildHybrid`.
- `.mmst`/PNG/기존 사용자 변경은 수정하지 않는다. 코드·기획·작업 이력은 단계별 함께 커밋, 원격 push는 별도 요청 전 하지 않는다.
- 새 지도 연결·실제 상권 통계·수요 할증·보험·차량매매·전역 공사/날씨·단골 기능은 추가하지 않는다.
- 진행 불가 컴파일 오류는 즉시 해결하되 저장 교체 경고의 별도 원인 진단/수동 체감/성능 작업은 P13 뒤로 둔다.
- 사람의 수동 운전/주관적 조작감은 자동 검사로 대체하거나 완료 표시하지 않는다. 가능한 자동 물리 주행과 별도 인계한다.

1. 구형 단일 요청 저장을 불러올 때 다시 추첨하거나 기존 약정을 변경하지 않음 → Task1 저장 호환 사례.
2. 신호 대기 후 출발/창 중첩으로 대화가 위험 조작을 유도하지 않음 → Task1 공간/입력 사례.
3. 메뉴·서비스·순간 이동·재시작으로 공차 시간/거리가 이중 적립되지 않음 → Task2 경계 사례.
4. 목적지 변경/경유 중 점유를 만나도 기존 요청·운임·기한·승객 위치가 불일치하지 않음 → Task3 복합 사례.
5. 저장 교체 실패/프로세스 재시작에도 마지막 정상 저장을 잃지 않음 → Task4 오류 주입/새 프로세스 복원.

## 실행 방식 및 시험값

권장 실행은 같은 세션에서 순차 구현(Native), 마지막에 한 번 독립 코드 리뷰다. 작업마다 새 구현/리뷰 에이전트를 반복하지 않는다.

- P11은 기존 기획 시험값 사용: 0/1/2건20/60/20%, 최초 요청 승차/운행 중 각50%, 운행 중 진행률25~65%, 이전 응답 이후 실제 주행20초와 별개 정차,85% 이후 미발생 중립, 합계-10~+10, 속도0.1m/s 이하2초.
- P12 시험안: 기존 영업 단계0~300/300~900/900초 이후를 재사용. 주거/업무/상업의 상대 가중은 초반3/1/1, 중반1/3/1, 후반1/1/3, 중립1. 초과 영업은 후반 유지. 현실 수요 자료로 표현하지 않는다.
- P13 시험안: 일반 후보 중 안전한 쌍만 사용, 동시 점유1대·30게임초, 대체 후보는 직선150m 이내와 합법 경로300m 이내·안전 보행 연결을 모두 검증. 안전한 쌍을 확보하지 못한 후보에는 대기만 제공한다. 숫자는 설정/문서로 분리하며 실제 맵 검증에 따라 보수적으로 축소한다.
- P13 기한 보호안: 사건 ID별 한 번, 잔여 점유시간 또는 합법 대체 ETA와 여유10초를 기준으로 해당 픽업/운송 기한을 최대90초 보정. 영업/연료 시간은 멈추지 않음. 강제 우회는 기존 짧은 길 등 요청의 미이행 감점에서 제외하되 다른 위반은 면제하지 않음.
- 위 P12/P13 수치는 구현을 위한 제안 기본값이지 사용자 지정 확정 수치가 아니다. 실행 계획 확인 시 함께 검토한다.

## Task2: P12 지역 수요·공차 성과

**Files:** 새 Scripts `PassengerDemandPolicy.cs`, `OperationMetrics.cs`; 수정 `PassengerJobs.cs`, `FullMapOverlay.cs`, `EconomyLedger.cs`, `BusinessProgress.cs`, `ServiceStops.cs`; `ProtoExpansionTests.cs` 확장. 지역 태그는 기존 후보 카탈로그에 게임용 별도 설정으로 연결하고 원본 지도 형상/ZIP은 변경하지 않는다.

**Interfaces:** `PassengerDemandPolicy.Weight(string region,double elapsed)` → 상대 가중; `OperationMetrics.Observe(float metres,float seconds,bool occupied,bool service)` → 집계; `Capture/Restore` → 당일/캠페인 누적과 집계 시작 여부. P11 배정 시드는 수요 갱신과 분리한다.

- [ ] 현재 후보 ID/유형을 대조해 지역 태그를 명시적으로 매핑하고 알 수 없는 후보는 중립값을 사용한다. 후보 안전/접근 필터를 통과한 뒤 비중만 적용한다.
- [ ] 일반 호출에 적용하고 고정9코스 구성·수락 호출·저장된 후보를 수요 변경으로 교체하지 않는다. 후보 부족이면 기존 안전 후보로 완화한다.
- [ ] 지도에 상대 수요, 호출 비교에 픽업/운송/총 예상시간을 구분한다. 운임 예상과 실제 순이익을 혼용하지 않는다.
- [ ] 픽업 이동 포함 공차/탑승 거리와 미탑승 이동/대기/서비스 시간을 누적한다. 이미 영업 시계에 반영한 서비스 시간은 집계만 하며 추가 소비하지 않는다. 순간 이동·연습·메뉴 정지 제외, 날짜 경계/구형 저장 시작 시점 표시.
- [ ] `ProtoExpansionTests.RunP12`: 단계 경계, 상대 분포,중립/후보 부족,수락 호출 유지,픽업/서비스/정지/순간이동 집계,날짜 이월/복원 중복 방지 검사1묶음.

## Task3: P13 승하차 공간 점유

**Files:** 새 Scripts `StopOccupancyPolicy.cs`, `StopOccupancySystem.cs`; 수정 `DriveSession.cs`, `PassengerJobs.cs`, `FareTrip.cs`, `PassengerRequestUI.cs`, `BusinessProgress.cs`, `FullMapOverlay.cs`; `ProtoExpansionTests.cs` 확장.

**Interfaces:** `StopOccupancySystem.IsOccupied(string stopId)`; `TryGetAlternative(string stopId,out MapStop stop)`; `Resolve(bool useAlternative)`; `Capture/Restore`에 사건ID·원래/대체 stableID·남은시간·기한 보정 적용 여부 보관. 요청과 시스템 대체는 다른 사유로 구분한다.

- [ ] 고정 코스/시설을 제외한 일반 후보의 실제 안전 공간을 확인해 점유 후보/대안 쌍을 선택한다. 차량 크기와 진입·승객 보행 경로 검증 실패 시 해당 후보를 사용하지 않는다.

- [ ] 이미 점유한 승차지는 새 호출에서 제외. 진행 운송은 유지하며 안전 정차 시 대기/대체 선택을 제공한다. 대안 없음은 유한 대기와 설명으로 처리한다.

- [ ] 사건별 기한/ETA 보호와 P11 경로 평가 제외 사유를 기록한다. 운임 할증·요청 건수 소모·무제한 시간 연장은 금지. 원래 약정/요청/경유 기록은 보존한다.
- [ ] `ProtoExpansionTests.RunP13`: 정상/점유/대안 없음/해소,겹침 생성 방지,픽업/하차 대체 동기화,기한 보정 한 번,목적지/경유 요청 공존,저장 복원 검사1묶음.
