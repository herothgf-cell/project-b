# 시작 메뉴 간소화 Implementation Plan

**Goal:** 사용자 이미지와 후속 답변에 따라 모드 메뉴·싱글 시작 메뉴를 정리하고 버튼 한 번으로 운행한다.
**Architecture:** 기존 UnifiedModeBootstrap/DriveHUD/OneDayHUD를 사용한다. 새 저장 스키마 없이 실제 복원 여부·준비 상태를 읽어 시작/계속하기를 구분한다.
**Tech Stack:** Unity 2022.3.62f2, C#, IMGUI.
**Spec:** 이 문서의 사용자 확정 요구.

## 사용자 확정 요구

- 모드 버튼은 `싱글 (체험판)`, `PVP`, `게임 종료`. 싱글/PVP 하단 설명 제거.
- 싱글 메뉴의 현재 지역·지역 선택·전용 빌드/정산 설명 제거, 지도 편집 버튼 숨김.
- 새 캠페인은 `영업 시작`만 표시, 버튼 한 번으로 실제 운행. 기존 영업 준비 패널을 추가로 거치지 않는다(후속 사용자 답변).
- 기존 진행은 `영업 계속하기`와 `처음부터 시작`. 초기화 확인·복원 오류 원본 보존 유지.
- 기존 운전 연습·게임 종료·앞차 추종 설정 유지. PVP 흐름·지도·운송·저장 경로 유지.

## 작업

- [x] 기존 UnifiedModeTests에 새 캠페인/저장 복원/운행 중 메뉴 구분 검사 추가, 실제 실패 확인.
- [x] BusinessProgress에 메뉴 상태와 시작/복귀 행동 연결. DriveHUD의 공통 싱글 메뉴를 준비 상태에서도 사용, OneDayHUD 중복 준비 화면 제거. 모드 문구/설명 변경.
- [x] 집중 Editor·저장/통합 모드 회귀, BuildHybrid 실행. 임시 저장을 사용하는 UnifiedModeProbe에서 최초 시작·복원·취소를 확인하고 화면 캡처.
- [x] 사용자 저장 보존, 정식 실행 폴더/manifest 검증, 기획·체크리스트·이력/LATEST와 실제 소스 커밋 기록.

## 점검 초점

최초 진입이 자동 저장만으로 즉시 계속하기로 바뀌지 않는지, 준비 상태 저장 복원도 바로 출발하는지, 운행 중 메뉴 복귀가 운송을 초기화하지 않는지, 초기화 취소가 현재 저장을 유지하는지, 복원 오류가 정상 시작 버튼에 가려지지 않는지 확인한다.

## 환경 판단

기존 tracked 변경 없음·미추적 8항목 보존. 같은 Unity 캐시와 설치를 사용하도록 현재 체크아웃의 `codex/simplify-start-menu`에서 작업한다. 실행 폴더의 기존 미추적 ZIP은 별도 보관한 뒤 배포 검증하며 사용자 파일을 manifest에 편입하지 않는다. 이번 요청은 구체적인 화면/동작 지정이므로 추가 기획 승인 없이 직접 구현한다.
