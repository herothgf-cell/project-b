# 충돌 내구도·수리 구현 계획

사용자 확인 기획: docs/content-design/03-life-and-economy.md. 충돌 강도별 손상, 비용/시간 중심, D0 운행 불가, 검증·기본 실행 배포·main 푸시까지 승인됨.

## 계약과 판단

- D100 시작, v<1.5/3/6/10/15/그 이상에 손상0/2/6/15/30/50. 접촉 법선 접근 속도 사용, 지지면·배치 유예 제외. 모든 접촉이0.8초 끊겨야 새 사건, 더 강한 충격은 차액만.
- 수리200원/점·10+0.5초/점, 견인3,000원/30초. 현금 우선·부족금 미납. 엔진 정지 서비스 시간·컨디션 경과, 중복 결제/복구 방지.
- VehicleCare.Damage: VehicleDamage. Durability, Disabled, RepairBayId; Impact(double speed)->int, Advance(double seconds,bool touching), Suppress(double seconds), LeaveRepairBay(), Snapshot/Restore. 모델은 VehicleCare.cs 안에 배치해 기존 순수 검사 의존성을 유지.
- EconomyLedger.UseRepair(string id), UseTow(string id,string bayId). Atomic 서비스는 기존 식사·세차처럼 확인 시 한 번에 확정하고 체크포인트 전체를 저장한다. 진행 프레임이 없는 서비스의 중간 단계는 만들지 않는다.
- D0 제동/관성 정지, 호출/실제 승차 차단. 첫 유효 도착 전 취소0원·1회, 이미 도착 확정이면 확정 운임 보존. 졸음 취소와 중복 금지.
- 기존 지원 주유소의 내부 공간에서 도로/승객/교통 경로와 떨어진 견인 전용 구역을 표시·검사. 비어 있는 검증 구역만 예약/이동, 전부 점유면 무결제 대기. 기술 복구로 손상 회복 금지.
- 사용자 저장을 건드리지 않는 test 인자/독립 저장 사용. 기존 진행 저장에 손상 정보 없으면 D100. 이벤트 기차감·유예·견인 공간도 저장.
- 기존 공간에서 전용 브랜치로 작업해 대형 지도/Unity 캐시를 유지하고 작업 전 untracked8항목을 보존.

## 검토 초점

1. 충돌 전 상대 접촉 속도·법선 방향, 정차 중 타 차량 추돌과 지지면 구분.
2. 저장/로드/기술 복구/연속 접촉이 손상 재적용·무료 회복을 만들지 않는지.
3. D0·도착 확정·졸음·마감 동시 발생의 취소/운임/서비스 순서.
4. 견인 구역의 실제 물리 빈 공간과 미납 복귀, 씬/지도 변경 안전성.
5. 수리·견인의 연료/컨디션/장부를 중복 반영하지 않는지.
