# 시작 지연·저장 복원·운임 감액 수정 계획

사용자 보고: 검은 초기 화면 지연, 초기화 전 영업 시작 실패, 요구치 미달에도 보너스 표시, 만족도0에서 전액 감액 필요.

## 변경 기준

- 시작: 실제 단계별 측정으로 병목을 확인하고 결과를 유지하는 경로 탐색 최적화. 초기 로딩 상태를 보여준다.
- 복원: 실제 Player.log의 Invalid ambient pedestrian count를 재현하고 구형 저장의 보행자 필드 부재와 손상 저장을 구분한다. 기존 저장을 삭제하거나 손상 내용을 무조건 무시하지 않는다.
- 신규 운송 정책4: S<R이면 운전 점수에 따른 양의 할증을 적용하지 않고 `floor10(min(원약정, 승차점수 보정운임) * S/R)` 지급. S=0이면 기본/보너스0, 요구치 미달 보너스0. S>=R은 기존 보정·보너스 유지. 시간초과0 유지.
- 기존 완료 기록과 진행 중 구형 운송의 정산 정책은 보존한다. 신규 승차 때 정책4를 고정하여 저장한다.
- 정산3줄 유지: 최초 예상/운임 조정/실수령. 순증감을 실제 보너스로 잘못 부르지 않는다. F8의 실제 보너스와 감액 원인 구분; 만족도0을 시간초과로 오표시하지 않는다.

## 수행

1. 시작·복원 담당은 독립 원인 분석/실패 재현/최소 수정/집중 검사. 공유 Unity 편집기 슬롯은 순차 사용.
2. 운임 담당은 첨부11300원·S48/R60·승차점수100의 기존11680원 재현, 신규9040원·S0/경계/단조성·구형 보존 검사 후 계산/UI/저장 연결 수정.
3. 관련 콘텐츠04/13·범위/체크리스트와 작업 이력/LATEST 갱신.
4. 최종 BuildHybrid, 격리 저장으로 준비→영업 시작/재실행, 운임 실제 운송 연결 및 화면 확인. 사용자 저장은 읽기만 한다.
5. 소스 커밋 뒤 실제 소스해시로 배포 manifest 생성/검증, 기본 은계 실행 폴더 포함 커밋·main 푸시.

수동 전체 캠페인/전 구간 물리 주행/다른 PC 검증은 별도이며 이번 집중 검사로 완료 표시하지 않는다.
