# 승객 승하차 지점 다양화 기획

## 2026-10-26 기존 S09 연석 정차 보정

기본 은계 지도에 포함된 `은계 승하차 9`의 차로 중심은 오른쪽 도로 경계에서 약 3.04m 안쪽에 있다. 종전 폭 3m의 정차 목표는 차로 중심에 남고 대기 위치도 차도 안쪽에 놓여, 실제 오른쪽 연석에 접근한 차가 하차 판정을 받기 어려웠다. 원본 지도와 정차 허용 반경은 그대로 두고, 원본 이름·차로·폭과 일치하는 S09의 실행 중 카탈로그 사본만 폭 6.6m로 보정한다. 실행 중 택시 목표는 약 `(675.134, 1478.493)`, 기본 대기 위치는 약 `(674.359, 1480.711)`이며, 이 차로의 도로 경계는 약 `(674.725, 1479.665)`이다. 기본 지도에서 차도 안쪽에 놓인 대기 보도 앵커만 교체하며, 사용자가 `sidewalk:stop:8` 대기점을 따로 옮긴 경우 그 위치는 유지한다. 기존 저장의 안정 지점 ID `S09`는 복원 시 현재 카탈로그의 보정 위치에 다시 대응한다. 다른 정차 지점과 사용자가 편집한 S09 차량 정차 형상은 이 보정 대상이 아니다.

## 2026-10-23 추가 · 정차 후보와 실제 대기 승객 분리

- 정차 후보는 기존24곳을 유지한다. 후보 개수가 늘어났다고 모든 지점에 대기 승객을 세우지 않는다.
- 길가 대기는 캠페인·영업일·안정적인 지점ID에 따른 분포로 일부(시험값35%)에만 배치한다. 영업 예산120초마다 멀리 있는 지점만 갱신하고 택시90m 이내의 길가 승객은 갱신 때문에 갑자기 나타나거나 사라지지 않게 유지한다.
- 빈차의 가용 호출 승차지는 대기 승객을 표시한다. 수락한 호출의 승차지는 분포/재호출 대기와 관계없이 예약 승객을 보장하고 실제 탑승하면 숨긴다. 비어 있는 길가 지점에서는 보이지 않는 승객을 태울 수 없다.
- 빈 하차 지점은 하차 후90초 동안 자동 신규 호출/길가 대기에서 제외해, 하차하자마자 다른 사람이 생기지 않게 한다. 이미 기다리던 사람이 있는 하차 지점은 유지한다.
- 운송 중 하차지는 다른 가용 호출 때문에 승객이 강제 배치되지 않는다. 길가 대기 분포에 따라 승객이 있을 수도 없을 수도 있으며 승차/하차 후보를 별도 맵으로 나누지 않는다.
- 분포·갱신 차수·남은 갱신시간을 기존 정차ID와 함께 저장한다. 재실행으로 재추첨하지 않고 지도 편집 시 ID로 재매핑한다. 새 필드 없는 구 저장은 진행 운송을 유지하며 새 분포로 이행한다.
- 확률/회전율·실제 수익 밸런스는 사용자 직접 테스트 대상이다. 원본 도로·24개 정차 형상·9코스·17요청을 변경하지 않는다.

## 목적과 적용 범위

현재 은계의 승하차 지점 12곳과 고정 상황 코스 9개는 반복 영업에서 출발·도착 조합이 익숙해지기 쉽다. 같은 지역에서도 승객의 목적·시간대·호출 위치가 달라 보이도록 **일반 영업용 안전 정차 후보**를 늘린다. 정확한 위치·개수는 지도에서 수동 검토한 뒤 확정하며 실제 시설 이름은 확인 전 붙이지 않는다. 기존 9개 코스의 S01~S12와 검증 조건은 유지한다.

| 구분 | 기획 방향 | 현재 개발과의 경계 |
|---|---|---|
| 고정 상황 코스 | PS01~09는 기존 승하차·상황 연결을 유지, 대표 판단 장면 재현 | 기존 구현 보존. 새 후보 때문에 필수 경유나 상황 강제가 생기지 않음 |
| 일반 호출 | 생활권 여러 도로의 검증된 승하차 후보에서 현재 위치·접근 거리·운송 길이를 고려해 제안 | 현재는 S01~S12와 고정/순환 선택. 후보 확장은 신규 개발 |
| 길가 승객 | 일반 호출과 같은 안전 정차 후보 중 실제로 보이는 승객에게 접근 | 점유 중·반대 방향·보도 접근 불가 지점 제외 |
| 요청 중 목적지 변경·경유 | 새 후보 중 안전하고 연결된 곳만 제안. 변경 전 추가 거리·시간·약정 표시 | 기존 한 운송 ID·한 번 정산 규칙 유지 |

## 후보 유형과 배치 기준

| 후보 유형 | 승객 경험 | 배치할 때 확인할 것 |
|---|---|---|
| 주거지 인접 도로 | 출근·귀가, 짧은 생활 운송 | 건물 출입 동선과 보도 위 대기, 차량은 도로의 안전한 연석에 정차 |
| 상업·생활 시설 주변 | 식사·쇼핑·업무 운송 | 시설 입구와 택시 정차 위치를 분리, 시설 진출입·주차 차량 방해 없음 |
| 대중교통 연결부 | 환승·긴 운송 | 버스 정차 구역·횡단보도·교차로를 피한 별도 택시 승하차 자리 |
| 의료·교육 시설 주변 | 시간 민감 승객, 이동 편의 요구 | 실제 시설명은 확인된 경우에만 사용, 출입구·보행 안전과 정차 가능 여부 확인 |
| 외곽 연결 도로 | 동네 간 장거리 운송 | 해당 방향 차로에서 진입·이탈 가능한지, 반대편 유턴 강제 여부 확인 |

지도 후보는 차로 방향, 연석·승객 보도 위치, 유효한 경로, 신호/표지·정차 제한, 교차로·횡단보도 거리, 인근 시설 출입을 함께 기록한다. 위 유형은 게임 역할 분류이며 특정 실제 시설의 존재나 합법 정차를 보증하지 않는다. 정차 가능 여부가 불확실하면 후보를 공개하지 않고 검토 대상으로 남긴다.

법규 근거는 [국가법령정보센터 도로교통법 제32조(정차 및 주차의 금지)](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029241793)를 후보별로 대조한다. 교차로·횡단보도·보도·버스정류장 인접 지점은 임의의 승하차 후보로 확정하지 않는다. 이 문서는 법정 거리의 일괄 자동 판정을 구현했다고 주장하지 않으며, 각 후보의 현장·지도 자료 확인이 필요하다.

## 호출 생성과 체감 다양성

| 규칙 | 제안 |
|---|---|
| 후보 ID | 지도 표시명과 분리된 안정적인 `stopId`, 기준 지도 리비전, 접근 차로/방향, 승객 대기 위치, 유형과 검증 상태를 보유 |
| 유효성 | 현재 차로에서 승차지까지, 승차지에서 하차지까지 경로가 모두 연결되고, 픽업 시간 예산 안에 도착 가능할 때만 호출 생성 |
| 반복 억제 | 직전 운송의 승차지·하차지 조합과 동일한 제안을 우선순위에서 낮춤. 유효 후보가 적으면 반복 허용하고 허위 경로를 만들지 않음 |
| 거리 구성 | 짧은 동네 운송·중간 운송·외곽 연결 운송을 섞되, 하루 남은 시간·연료·피로 때문에 완료 불가능한 제안을 우선 노출하지 않음 |
| 수요 연출 | 시간대·후보 유형에 따라 승객 대사와 호출 설명을 바꾸되, 같은 장소가 같은 사람·요청만 생성하지 않음 |
| 안전 | 차량은 진행 방향의 오른쪽 연석에 저속 정차하고 승객은 보도에서 대기. 반대편·차도 중앙·교차로·횡단보도 정차를 유도하지 않음 |
| 중복·점유 | 수락·운송 중인 지점과 재호출 쿨다운을 반영. 복수 후보가 가까워도 핀/목록에서 구분 가능하게 표시 |

현재 `MapStop.CanStop`은 연석 위치·차량 방향·속도로 판정한다. 후보 추가 시 이 판정만으로 실제 정차 허용을 확정하지 않는다. 지도 편집으로 차로가 바뀌면 후보의 접근 연결을 재검증하고, 손상된 후보를 숨기되 진행 중인 운송을 갑자기 다른 지점으로 옮기지 않는다.

## 승객 요구와의 연결

- 호출의 목적지·약정 운임·요구 만족도는 수락 전에 보여준다. 핵심 요청 1개는 탑승 뒤 나타나므로 특정 지점에 특정 요청을 고정하지 않는다.
- 목적지·경유 요청은 실제 선택 가능한 안전 후보가 있을 때만 제시한다. 후보가 사라지거나 지도를 수정해 연결이 끊겼다면 원래 운송을 유지하고 중립 결과를 기록한다.
- 시간 민감 요청은 합법적 대기와 접근 거리를 포함해 기한을 조정한다. 먼 승차지 때문에 승객 요청을 처음부터 실패로 만들지 않는다.
- 요청 이행 결과는 [승객 요청·만족도](2026-10-27-before-planning-only/11-passenger-request-effects.md)에 따라 하차 때 판정한다. 지점 유형 자체가 만족도나 보너스를 자동 지급하지 않는다.

## 개발 순서와 검증

| 단계 | 작업 | 완료 확인 |
|---|---|---|
| 1 | 은계 지도에서 후보 위치·진행 방향·보행 대기점을 표시하고 정차/경로 연결 검토 | 기존 12곳 유지, 신규 후보마다 안전·접근·출구 근거 기록 |
| 2 | 후보 데이터를 고정 코스와 분리해 일반 호출·길가 승객 생성에 연결 | 기존 PS01~09 재현, 신규 후보 포함 호출·거리·시간·요금 검증 |
| 3 | 요청 목적지 변경·경유, M 호출 핀·미리보기, 저장 복원 연결 | 후보 삭제·지도 리비전 변경·중복/점유·시간 만료 처리 |
| 4 | 실제 운전으로 승하차 다양성·정차 체감 확인 | 한 플레이에서 같은 조합의 과도한 반복, 위험 정차, 도달 불가·비현실적 시간 예산 없음 |

위 단계는 개발 목표이며 현재 빌드에서 완료된 기능을 뜻하지 않는다. 새로운 지점 수·정확한 좌표·실제 시설명은 지도 확인 없이 확정하지 않는다.
