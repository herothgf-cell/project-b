# 시뮬레이션 요소별 행동·결과·영향

현재 기준: 2026-10-27 main 배포 소스 e9c6fae. 아래는 **구현된 게임 규칙의 연결표**이며 실제 벌점·생리 기준·현실 수익 보장이 아니다. 새로운 기능/수치를 제안하는 문서가 아니다. 세부 산식은 연결된 담당 기획을 기준으로 한다.

## 읽는 기준: 무엇이 변하는가

| 지표 | 범위·초기값 | 바뀌는 계기 | 직접 바꾸지 않는 것 |
|---|---|---|---|
| 운전 점수 | 캠페인 누적0~100, 시작100 | 실제 관찰 법규 사건·준수 회복 | 조향 성능·피로·R. 승객 요청 대답만으로 변화 없음 |
| 운전 만족도 M | 운송별0~100, 승차100 | 주행 감점·제한된 안정 주행 회복 | 캠페인 운전 점수와 다른 장부 |
| 승객 만족도 S | 운송별0~100 | S0 + (M−100) + 요청 + 안심 회복 + 안전 조기 도착 | 법규 점수를 다시 그대로 더하지 않음 |
| 요구 R | 승객별60/70/85 | 해당 승객 배정 | 운전 중 능력치로 낮출 수 없음 |
| 현금·미납·순수익 | 새 캠페인 현금10,000원 | 실제 하차 입금·서비스 결제/비용 | 예상 운임은 입금 아님. 미납은 공짜 이용 아님 |
| 시간 | 하루 예정1,200게임초, 초과 가능 | 활성 영업·서비스 소비 | 메뉴/일시정지·연습 시간은 같은 영업시간으로 합산하지 않음 |
| 연료/포만감/피로/청결 | 시작60%/80/10/100 | 이동·경과·생활·승객 사건 | 숫자가 낮다고 별도 점수를 무조건 직접 깎지 않음 |

## 1. 호출·승하차·운송 결과

| 조건 | 플레이어 행동 | 즉시 결과 | 후속 영향 | 예외·보호 |
|---|---|---|---|---|
| 호출 탐색 | M에서 선택·경로 미리보기 | 승하차 식별·예상 운임 표시 | 수락 전에는 배차·입금 없음 | 행에는 긴 계산식·요청을 나열하지 않음 |
| 호출 수락 | 별도 수락 확정 | 픽업 목표·기한 설정 | 픽업 이동도 공차·연료·영업시간 | 픽업 기한 max(150, 경로m/3+150)초 |
| 픽업 도착 | 지정 차로 방향·저속 정차 후 F | 승차, M=100·S0/운임 보정 점수 고정 | 요청 배정·탑승 거리 관찰 시작 | 청결·졸음·점유·기한·정차 조건 적용 |
| 청결 C≥80로 승차 | 정상 승객 탑승 | 시작 S0에 청결+3 | 최종 S에 포함 | M·R에 별도 가산하지 않음, 하차 때 재가산 없음 |
| 여유/보통/급함 | 같은 목적지로 운전 | 기한=max(90, 안전ETA×1.75/1.45/1.20+상황대기+45)초 | 난도와 운행 계획 차이 | 난도는 후보 ID 기반 유지. 이미 저장된 기한 소급 변경 없음 |
| 정상 하차 | 목적지 방향·저속 정차 후 F | 유효 도착·실제 지급 확정 | 같은 운송 ID에 한 번 입금·청결 처리·결과 기록 | 취객은 도착과 실제 하차 시각 분리 가능 |
| 탑승 후 기한 초과 | 목적지까지 계속 운송 | 승객 유지, 실제 하차 후0원 | 기본 운임·보너스0, 발생 비용 유지 | 도중 승객 삭제·유효 도착 뒤 기상대기로 소급 지각 처리 없음 |
| S<R | 하차 평가 | 기본 운임=floor10(min(원약정F, 보정약정A)×S/R), 보너스0 | 만족도 미달만큼 실수령 감소 | S=0이면 전액0. 과거 운송의 정산 정책 보존 |
| S≥R·기한 내 | 하차 평가 | 보정약정A 전액+S/R 기반 보너스 | 현금·하루/누적 수입 반영 | 보너스는 요청 버튼이 아닌 최종 결과로 결정 |
| 운전 점수 변화 | 실제 사건 후 다음 승객 탑승 | 승차 시 점수0/70/100 → 운임90/100/110% | 이번 운송 중 점수 변화는 다음 승객부터 | 목적지 변경도 승차 때 점수 사용 |

정확한 S0·도착 가산·보너스·구형 저장 정책은 [04 운임과 만족도](04-passengers-and-reservations.md#운임과-보너스-계산)를 따른다.

## 2. 주행·법규·안정 회복

법규와 M은 독립 관찰이다. 아래 같은 행의 두 값은 서로 더한 단일 점수가 아니다. 동일 법규 사건은 최대 감점 한 번, M은 해당 주행 사건 기준으로 중복을 막는다.

| 실제 행동·조건 | 운전 점수 | M 변화 | S·돈·기록 영향 | 예외 |
|---|---:|---:|---|---|
| 신규 사건에서 준수 확인 | +3, 상한100 | 자동 가산 없음 | 다음 승차 운임 보정·법규 이력 | 위반 동시 존재·보류·기회 없음·버튼만 선택은 회복 없음 |
| 적색 직진/적용 신호 위반 | 해당 법규 배점(적색 직진 -20) | -12 | M−100을 통해 S 하락, 법규 사건 기록 | 접근 신호·실제 진입 방향 관찰 필요 |
| 우회전 전 단순 정지 누락 | -5 | -4 | 완화된 게임 감점 | 전용 적색 위반은 별도 -20/M -12, 보행 보호 위반과 구분 |
| 실제 보행 보호 위반 | 해당 법규 -25 | 양보 위반 시 -8 | 관찰 사건과 승객 주행 평가 | 충돌이 없어도 보호 위반 가능, 불명확은 보류 |
| 역주행 | -10 | -10 | 연속 사건1회 기록, S 하락 | 반대 전진2초·8m 및 속도2m/s 이상. 주차·후진·교차로/회전 연결 제외 |
| 적색 정지선 침범 후 정차 | -1 | 0 | 법규 전용 변화 | 같은 접근에서 더 큰 위반 발생 시 최대값으로 갱신, 합산하지 않음 |
| 불필요한 급가속/급제동 | 직접 자동 변화 없음 | 각 -2 | 회복 가능한 감점 잔액 발생 | 필요한 위험 회피 제동 제외 |
| DR01 수락 후 급가감속 | 별도 법규 관찰 | 각 -4 | 기본 -2를 대체 | -2와 -4를 합쳐 -6으로 하지 않음 |
| 차량·시설 충돌 | 충돌만으로 법규 확정하지 않음 | -10 | S 하락·주행 기록 | 같은 접촉 연속 감점 방지, 수리·보험 비용 없음 |
| 인도·도로 경계 침범 | 별도 법규 관찰 | -5 | S 하락 | 지속 침범 매 프레임 중복 차감 없음 |
| 안정 새 구간350m 또는 이동45초 | 변화 없음 | +2/기회, 운송 최대+6 | 급가감속으로 잃은 M만 회복 → S 반영 | 정차·왕복 재적립·순간 이동 제외. 신호·충돌 감점 회복 불가 |
| 안정 기회에 M 회복0 | 변화 없음 | 0 | 안심 회복 S +2/기회, 총+4·R 상한 | 같은 기회에 M 회복과 중복 지급 없음 |
| 합법 대기·안전한 거절 | 변화는 실제 사건 관찰 기준 | 자체 감점0 | 시간/연료 소비는 지속 | 대기만으로 회복/보너스 적립 없음 |

전체 배점·판정 보류는 [02](02-driving-evaluation.md), M의 경계/고유 공간 적립은 [04](04-passengers-and-reservations.md#안정-주행-회복-규칙)를 따른다.

## 3. 승객 요청의 행동 결과

| 요소 | 행동·관찰 | 직접 결과 | 영향·보호 |
|---|---|---|---|
| P11 배정 | 후보별0~2건 추첨, 승차/안전 정차 제시 | 같은 후보는 목록·순서·시점 유지 | 미발생·정당한 보류는0, 복수 합계 -10~+10을 S에 반영 |
| 조용한 운행 | 실제 응대 이행 | 요청 +5 | 안전한 응답 기회를 무시한 기존 M -5와 요청 변화 중복 감점 없음 |
| DR01~05 | 승차감·정시·큰길·짧은 길·안전 하차 목표 관찰 | 달성 +8/미달 -10 시험값 | 관찰 부족·필요한 합법 우회는 중립 처리. DR01 개별 제동과 요청 전체 목표를 구분 |
| CH01~06 | 공감·추천·응원·음악 안내·요금 안내·지역 응대 | 관찰 가능한 응대 +5/미달 -5 기준 | 음악은 실제 재생 없음, 요금 안내만으로 할인/부채 생성 없음. CH01/03/06의 안전 기회 무시는 -5 가능 |
| EV01/02 | 확인한 목적지 변경·경유 실제 수행 | 달성 +6/미달 -8 | 동일 운송 ID·새 약정/기한, 경유는 F 정차 필요 |
| ETA 문의 | 빠르게/내비대로/여유 예상 안내 | 요청 변화0, 안내와 실제 차이 설명 | 기한·차량 성능을 바꾸지 않음 |
| EV03/04 | 하차 후 분실물 절차 안내/불법 요구 안전 거절 | 요청 변화0 | 분실물은 요청 수 미소모·운임 소급 변경 없음, 불법 수락 선택 없음 |

각 요청의 실제 달성 조건·선택·판정 불가 분기는 [11 개별17종 표](11-passenger-request-effects.md)가 기준이다. 수락 클릭만으로 성공 처리하지 않는다.
