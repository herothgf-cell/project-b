# 영업 전략: 요청·지역 수요·공차·승하차 공간

현재 기준: 2026-10-27. P11 요청 다양화·P12 수요/공차·P13 점유 대기는 구현된 현재 규칙이다. 대체 지점 이동은 미구현이다. 개발 순서·초기 제안·마인드맵 검토안은 [별도 변경 이력](../../../content-design/../design-history/content-design/2026-10-27-design-decisions.md)에 둔다.

## P11 요청의 연결

| 조건·행동 | 직접 결과 | 다른 시스템 영향 | 제외·보호 |
|---|---|---|---|
| 후보 생성 | 승객 ID를 기준으로0/1/2건을20/60/20% 시험 비중으로 배정 | 같은 후보 재수락·저장 복원 시 종류/순서/시점 유지 | 첫 승객·지역별 특정 요청 고정 없음 |
| 승차 또는 운행 중 안전 정차 | 한 번에 하나씩 제시·응답 후 실제 행동 관찰 | 개별 결과 합계 -10~+10을 S에 반영 | 위험 주행 중 답변 강요 없음 |
| 충분한 응답/이행 기회 없음 | 미발생·안전 보류는 중립 | M·운전 점수·운임을 대화 버튼만으로 가감하지 않음 | 진행률85% 또는 유효 도착 뒤 새 요청 차단 |
| 목적지/경유·경로 요청 수락 | 실제 경로·목표·약정을 확인 후 적용 | 동일 운송 ID로 최종 하차 한 번 정산 | 상충 경로 약속 중복 배정 방지 |

정확한 발생 간격·안전 정차 조건은 [04](04-passengers-and-reservations.md), 17종별 행동·평가 결과는 [11](11-passenger-request-effects.md)를 따른다.

## P12 지역별 수요

지역은 실제 용도지역·승객 통계가 아닌 게임용 태그다. 안전/접근 가능 후보를 먼저 고르고 상대 비중을 반영한다.

| 지역 | 일반 후보 ID (EG-GAME- 접두어) | 우세 영업 경과 | 상대 가중 |
|---|---|---|---|
| 주거 | 03·04·06·08·10 | 0초 이상300초 미만 | 해당 단계3, 나머지 단계1 |
| 업무 | 01·05·09·11 | 300초 이상900초 미만 | 해당 단계3, 나머지 단계1 |
| 상업 | 02·07·12 | 900초 이상, 초과 영업 포함 | 해당 단계3, 나머지 단계1 |
| 중립 | 미분류·기존 후보 | 특정 우세 없음 | 1 |

| 행동·조건 | 결과 | 영향·비영향 |
|---|---|---|
| 우세 지역 근처로 빈차 이동 | 해당 후보의 상대 배정 비중을 활용할 수 있음 | 이동 시간·연료·공차 거리 증가. 승객 발생·수입 보장 없음 |
| 호출 선택·수락 | 현재 호출의 픽업/운송 조건 확정 | 시간대가 바뀌어도 수락 호출 유지. 수요에 따른 운임 할증 없음 |
| 지도 보기 | 상대 수요 설명과 경로 미리보기 제공 | 호출 행은 승차/하차 식별·예상 운임만 표시. 상세 계산식을 행에 나열하지 않음 |
| 후보 부족/연결 불가 | 기존 안전·경로 필터 우선 | 가중치를 맞추려고 불가능한 호출을 만들지 않음 |

## P12 공차 수익성 기록

| 관찰 | 분류·결과 | 시간·돈·점수 영향 | 예외 |
|---|---|---|---|
| 탑승 전 이동 (픽업·시설 왕복 포함) | 공차 거리, 미탑승 이동 시간 | 실제 이동의 연료/영업시간은 기존 시스템에서 소비. 집계가 추가 비용을 만들지 않음 | 불연속 위치 복구/순간 이동 제외 |
| 승객 탑승 후 이동 | 탑승 거리 | 운임 확정은 하차 정산에서만 발생 | 거리가 누적됐다고 즉시 돈을 지급하지 않음 |
| 빈차 정차 | 미탑승 대기 시간 | 영업·공회전·컨디션은 기존 규칙 | 메뉴/일시정지 시간 제외 |
| 시설 이용 | 서비스 소비 시간 | 서비스가 이미 소비한 시간을 재차 영업시간에 더하지 않음 | 주행/대기와 분류 중복 방지 |
| 하루 정산 | 공차/탑승 거리·미탑승 이동/대기·서비스 시간 표시 | 실수령·비용·순수익과 함께 효율 비교 | 새 감점·확정 수입 예측 아님 |
| 구형 저장 복원 | 집계 시작 시점부터 기록 | 과거 지표를 추정해 채우지 않음 | 새 저장은 기존 누적값 유지 |

## P13 승하차 공간 점유·대기

| 조건·행동 | 직접 결과 | 시간·평가·운임 영향 | 예외·제한 |
|---|---|---|---|
| 일반 게임용 후보에 점유 생성 | 일시 정차 차량으로 해당 공간 차단 | 이미 점유된 장소의 신규 승차 후보 생성 제한 | 고정 코스/시설 제외. 카메라 밖·택시100m 이상, 차량/승객·출구 공간 겹침 검사 |
| 진행 호출/운송의 목표가 점유됨 | 원래 지점 유지·대기 안내 | 같은 호출/운송 ID 유지, 강제 취소 없음 | 승객을 인도·반대 차로로 옮기지 않음 |
| 정차 후 대기 선택 | 현재 점유 해소를 기다림 | 영업·연료 시간은 계속 흐름. 기한 보호는 사건에 대해 한 번 | 현재 대체 선택은 제공하지 않음 |
| 대기 해소 | 30초 뒤 전방이 비면1.5m/s로7m 이동 | 원래 지점의 정상 승하차 재개 | 전방 장애물이 있으면 이동 대기. 실제 해소 시점은30초로 보장하지 않음 |
| 시스템 지연 보호 | 잔여 대기+이동 예상+10초, 최대90초를1회 기한 연장 | 탑승 중이면 ETA·경로 요청 평가에 시스템 사유 면제 연결 | 운임 할증·중복 연장 없음, 무제한 재클릭 불가 |
| 저장·복원 | 남은 점유/이동·사건·보정 상태 보존 | 재로드로 재추첨/기한 재적립 방지 | 날짜/새 캠페인 경계는 점유 상태 초기화 |
| 대체 지점 요구 | 검증된 근거리 안전 쌍 없음 안내 | 원래 목표와 내비 유지 | 현재12일반 후보의150m 이내 안전 대체 쌍0개. 대체 이동은 미구현 |

## 구현과 추가 검증의 경계

| 범위 | 현재 제공 | 아직 제공하지 않는 것 |
|---|---|---|
| 요청 | 후보별 무작위 배정·안전 제시·복수 결과·저장 | 사람의 실제 대화 빈도/답변 여유 검증 완료라는 보장 |
| 수요·공차 | 단계별 가중·관찰 지표·정산·저장 | 현실 수요 추정·수요 할증·지역 이동의 수익 보장 |
| 공간 | 점유·해소 대기·기한/요청 보호·저장 | 검증되지 않은 대체 정차·승객 재배치 |
| 완료 상태 | 모델/Editor/위치 제어·일부 물리 주행 검증 | 모든 도로·20분/3일 사람 체감·전체 캠페인 물리 주행 전수 |

코드 연결은 [19 구조](19-content-system-structure.md), 실제 검증 결과는 [작업 이력](../../../content-design/../work-history/LATEST.md)에서 확인한다.
