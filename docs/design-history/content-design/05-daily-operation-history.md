# 변경 전 기획·구현 이력

2026-10-26 통합 정리 전 원문이다. 폐기된 수치·미구현 표기가 포함되어 있으며 현재 규칙은 [05-daily-operation](../../content-design/05-daily-operation.md)를 따른다. 날짜별 실제 검증은 [작업 이력](../../work-history/LATEST.md)을 따른다.

# 개인택시 경제와 생활 거점

## 2026-10-23 추가 · 운행 완료 비교 정산

완료 팝업은 기본 운임(최초 예상),보너스(최초 예상 대비 실제 지급 증감),최종 운임(실수령)의3줄로 간소화한다. 목적지 변경/경유 전 최초 예상 운임을 새 운송 저장과 결과에 보존한다. 예: 최초5,000원·운전 평가로 실제3,500원이면 `5,000 / -1,500 / 3,500`이다. 만족도 보너스/운전 평가 지급률/시간 초과 판정은 기존 계산을 사용하고 현금은 실제 지급액1회만 입금한다. F8의 실제 기본 지급액·계산용 보너스 분해는 유지한다. 이는 표시 변경이며 새 할인·요금 또는 비용을 추가하는 것이 아니다.

사용자 결정: 이후 수익·운송량·생활 시간 밸런스는 사용자가 직접 플레이로 확인한다. 개발 측은 거래·저장·중복 지급 회귀 검사를 유지하되 이 작업에서 자동 밸런스 조정을 하지 않는다.

## 프로토 구현 · 주유소 세차와 청결 비용

[취객·청결도 기획](../../content-design/15-drunk-passengers-and-cleanliness.md)에 따라 기존 은계 주유소 3곳에서 빈차·지정 정차 후 F7로 **세차·실내 청소**를 선택한다. 주유는 필수가 아니다. 테스트 초깃값은 **2,000원·30게임초·청결도 100점 회복**이며 취소는 무차감, 잔액 부족은 식사와 같이 미납 처리한다. 세차비를 장부 비용·하루 순수익에 1회 반영하고 청결도는 영업일 사이 이월한다. 청결도 30점 미만이면 다음 승차 지점에서 거부되므로 하차 후 생활 거점에 `주유소(세차 필요)`를 우선 권장한다. 기존 주유·연료 지원·사고 수리와는 별개다. **코드·은계 빌드에 적용했고 모델/위치 제어·저장 복원 검사를 마쳤다. 수동 하루/3일 경제 체감은 남아 있다.**

2026-10-23 구현 상태: 명칭은 `보너스`이며 모든 정상 운송에서 최종 만족도가 요구치에 도달하면 [새 산식](11-passenger-request-effects-history.md#2026-10-23-이전-정책-기록--만족도와-보너스-개편)으로 지급한다. 기본 운임의 M 기준100%/70%·시간 초과0원은 유지한다. 보너스는 결과에 기본 운임과 별도로 표시하며 거래는 합계1회 입금해 하루 순수익에 중복 반영하지 않는다. [구현/검증](../../work-history/2026-10-23-passenger-care-connectivity.md), [점수 UI 연결](../../work-history/2026-10-23-score-ui-binding.md).

## 2026-10-23 기사식당 메뉴·잔액 표시 기준

제육백반·된장찌개 정식·소고기국밥을 제공한다. 식당 앞 지정 칸에 빈차 정차 후 F7 식사 확인에서 선택한다. 모두 기존 게임값3,000원/50초/포만감+70(상한100, 식사시간 경과 반영)으로 메뉴 간 밸런스 차이는 두지 않는다. 선택·취소는 차감하지 않고 확정 때 한 번 결제한다. 잔액은 시작금10,000원+입금−지출로 즉시 갱신하며 누적 순수익은 시작금과 미납을 제외한다. 주행 잔액 UI는 [승인된 배치13](../../content-design/13-driving-map-ui.md)에 구현했다.


## 2026-10-22 추가 · 식당 앞 주차 후 식사

이 절이 앞선 도로변 식사 설명보다 우선한다. 남부 블록 도로 남측 빈 부지에 은계 밥집 건물·간판·식당 앞 주차 칸과 별도 진입/출구를 제공한다. 기존 건물과 원본 차로는 보존한다. 지도 핀은 내부 주차 공간, 내비/H 목적지는 도로의 입구 접근점이다. 입구부터 H를 끄고 직접 주차한다.

| 위치/조건 | 식사 가능 여부 |
|---|---|
| 도로변·진입로 앞/입구 | 불가, 결제/시간 차감 없음 |
| 내부 지정 주차 칸·같은 방향·정차 | 빈차이면 F7 식사 가능 |
| 칸 밖/이동 중/반대 방향/승객 탑승 중 | 불가 |
| 식당 주차 칸 | 주유·수면·영업 마감은 제공하지 않음 |

식사3,000원/50초·포만감 회복·정차 중 엔진 정지·취소 무차감 규칙은 유지한다. 식당은 게임시설이며 실제 상호/필지 확정이 아니다. 주차·휴식 거점과 승객12지점은 유지한다. 새 주차 노면을 도로 경계 판정에도 등록하고 내비/NPC 공유 차로 연결에는 새 지름길을 추가하지 않는다.


## 2026-10-22 변경 · 남부 식당 독립 배치

사용자 전체지도 붉은 표시(남쪽 블록 안쪽 도로) 부근에 ‘은계 남부 식당 (게임시설)’을 별도 배치한다. 기존 은계 승하차7 지점을 식당으로 겸용하지 않고 승객12지점과 주차/휴식 위치를 유지한다. 식당 표지·전체지도/미니맵·F7 안내·하차 후 식사 추천·식사 이용 판정·호출의 식당 접근성 추정은 같은 독립 MapStop을 사용한다.

공유 차로 그래프에서 목표 로컬 좌표(688,326) 근처의 통행 가능한 차로 정차점을 선택한다. 내비/H/NPC의 원본 도로 연결을 새 지름길로 바꾸지 않는다. 도로변 같은 방향으로 정차 후 F7 식사,3,000원·50초·포만감 회복 등 기존 효과를 유지한다. 실제 상호/식당 위치를 현장 확인한 시설이 아닌 사용자 지정 게임시설이다. 주차·수면·퇴근과 식당 도착을 혼동하지 않게 표시한다.


## 2026-10-22 변경 · 3일 장부와 운송 정산

하루20분씩3일 진행해 일별·누적 수입/지출/순수익을 비교한다. 날짜 사이 현금·미납·연료를 이월하고, 야간 수면은 피로60 회복·포만감 이월이다. 식사·주유·주차 비용과 영업 중 시간 소비는 유지하며 보험/세금은 제외한다. 하차 결과창은 확정된 기본 운임·감사 보너스·합계만 읽어 보여주며 닫기/생활거점 선택으로 중복 지급하지 않는다. 마지막 운송 결과를 닫은 후 일 정산으로 이동한다.


기준일: 2026-10-21 · 버전: 1.0 · 상태: 하루20분·운전자 구현, 자동 검사 완료·수동 밸런스 미검증

하루 운임에서 주유·식사·주차·지원비를 뺀 순수익을 비교한다. 식당은 포만감 회복, 주차장은 수면·퇴근 장소가 된다. 보험·세금·예약·사고·수리·보험 청구는 최신 제외 범위를 유지한다.

## 주유와 연료

| 요소 | 유지할 기준 |
|---|---|
| 시작 잔량 | 새 하루60%, 기존 회차 값과 구분. 새 회차에 이전 잔량 이월 없음 |
| 주행 소모 | 수평 이동1km당4%포인트 + 엔진을 켠 영업1분당0.1%포인트 |
| 안내 | 잔량15% 경고·5% 강조, 호출별 예상 부족 안내. 예측은 실제 소비와 다를 수 있음 |
| 방문 | 빈차·정차·지정 방향/주유 구역에서 이용, F7 내비와 현재 주유 동선 유지 |
| 구매 | 10%포인트씩 반복 구매. 잔여 용량보다 많이 채우지 않으며 실제 보충분×40원, 원 단위 올림, 잔액 부족 시 구매 불가 |
| 고갈·탑승 중 | 승객·운송 ID·위치·내비 유지, 지원 후 기존 기한으로 계속. 목적지 하차 전 정산 금지 |
| 고갈·미탑승 | 호출 취소·기존 지원 위치 복귀, 영업시간 종료면 정산 |
| 지원 자금 부족 | 기존 필수 지원 미납 정책 유지 |
| 새 식사·수면 | 엔진 정지 처리 적용. 예산은 소비하지만 주행/공회전 연료 소모 없음 |
| 주유·지원 경과 | 기존 시간 소모 유지. 메뉴·복습·순간 이동 거리는 연료에 더하지 않음 |

기존 `소모량 = 이동m/1,000×4 + 영업초/60×0.1`에서 식사·수면의 엔진 정지 구간을 분리해 적용했다. 주유10초의 시간 소모는 약0.0167%포인트, 지원30초는0.05%포인트다. 20분에 맞춘 연료 소모율 변경은 수동 측정 뒤 판단한다.

| 잔액 부족 식사 | 기존 생활비 미납 허용 | 전액 비용·미납을 표시, 회복은 같은 확정에 반영 |
| 남은 예산 부족 | 이용 시간보다 적으면 시작 불가 | 비용·회복 없음, 계속 운행 또는 퇴근 안내 |
| 정확히 예산 소진 | 이용 확정·회복 후 마감 | 주차비는 정산에서1회 |

컨디션은 [10 운전자](../../content-design/10-driver-condition.md)가 단일 기준이다. 식사·수면으로 법규·매너·차량 성능을 직접 변경하지 않는다. 실내 보행과 요리·수면 조작은 제외한다.

## 장부와 하루 결과

| 항목 | 계산·표시 |
|---|---|
| 시작 자금 | 10,000원, 수익에서 제외 |
| 현금 | 시작 자금 + 실제 운임 − 실제 결제 |
| 미납 | 식사·주차·필수 지원 등 발생했지만 결제하지 못한 비용 |
| 하루 순수익 | 현금 − 시작 자금 − 미납(시작 미납0) |
| 미납 결제 | 현금과 미납을 동시에 감소, 비용 재차감 없음 |
| 결과 | 수입·비용·미납·순수익·운송 건수·식사/수면 횟수와 시간 |
| 적자 | 실패 화면으로 차단하지 않고 유효 결과로 보존 |
| 다음 도전 | 같은 초기값의 새 하루, 이전 돈·연료·컨디션 이월 없음 |

연료 잔량은 현금으로 환산하지 않는다. 단순 순수익만 비교하면 식사·주유를 미룬 회차가 유리할 수 있으므로 종료 연료·컨디션·영업시간을 나란히 표시한다. 법규 점수를 돈으로 환산해 종합 순위를 만들지 않는다.

## 저장과 기존 기록

| 영역 | 정책 |
|---|---|
| 기존3일 회계 | 보존. 새1일 결과로 임의 변환·덮어쓰기 없음 |
| 새 하루 회계 | 현금·미납·연료·컨디션·생활 이용·정산 상태를 같은 재개 경계로 복원 |
| 운행 사건 | 기존 즉시 저널 유지, 회계 재시작을 이유로 위반 기록 삭제 금지 |
| 완료 결과 | 회차 ID·설정/코스 버전·실제 시간·결과 요약 보존 |
| 새 하루 시작 | 확인·저장 성공 뒤 새 ID와 초기값 적용. 취소·저장 실패는 현재 상태 보존 |

기존 보험·세금 제외를 위한 계정 이관은 유지한다. 이를 다시 활성화하거나 기존 저널을 일일 저장만으로 되돌리는 작업은 포함하지 않는다.

### 2026-10-21 10% 단위 주유 변경

최신 정책: +10%포인트 버튼만 제공하고 반복 구매를 위해 메뉴를 유지한다. 매 구매 400원(잔여 용량이 10% 미만이면 실제량×40원 올림), 영업시간 10초와 해당 공회전 소모를 적용한다. 예: 60%→약69.9833%. 95%→약99.9833%. 가득 주유/50% 선택과 그 예시는 과거 사양이다. 빈차·같은 방향·주유 구역 정차·현금 조건은 그대로다. 식사·주차의 확인/취소는 유지한다.

## 2026-10-22 추가 휴식 주차구역

사용자 승인으로 동부 주유소 출구 이후 같은 진행 방향 약80m 구간에 게임용 휴식 주차구역을 추가한다. 파란 진입/진출 유도선과 주차면에서 정차 후 F7 수면을 이용한다. 무료·100초 소비·피로40 회복은 기존과 같다. 이곳에서는 주유와 영업 마감을 제공하지 않으며, 기존 주차장은 출발·마감·수면 기능을 유지한다. 시설 선택 시 내비는 공유 방향 도로 경로로 가까운 수면 접근점을 안내한다. 실제 현장 주차장으로 확인된 시설은 아니다.

## 2026-10-22 하차 후 생활 목적지 선택

승객 하차 후 작은 선택창에 주유·식사·수면·귀가 주차장과 실제 방향 경로 거리를 표시한다. 연료15% 이하·포만감25 미만·피로70 이상·마감3분 이내 및 이동 거리로 권장 목적지를 계산하되, 플레이어가 눌러야 내비가 바뀐다. 도착 뒤 이용/비용 확인은 기존 F7 절차다. 선택창은 시계를 멈추거나 자동 결제·자동 마감하지 않는다. 새 호출 수락이나 닫기로 계속 영업할 수 있다. 시간 초과 후 목적지 하차도 같은 안내를 제공한다.
