## 1. 목적과 범위

사용자가 은계 게임 맵을 직접 보면서 차로·표지·신호를 수정하고, 변경한 차로에서 내비·조향 보조·NPC가 일관되게 움직이는지 시험한다. 네이버 거리뷰로 확인한 내용을 코드나 좌표 파일을 직접 편집하지 않고 반영하는 것이 목적이다.

사용자 요구는 차로별 좌/직/우 구분, 표지판 배치, 차량 신호등·보행자 신호등 배치, 변경 차로에 따른 내비게이션이다. 기존 논의의 차로 수·폭·좌회전 대기차로·출구 연결·정지선·횡단보도 편집, 저장과 시험 주행도 포함한다.

제안 기본값은 Windows 실행파일 내 전용 편집 모드와 마우스·키보드 조작이다. T1을 시범 대상으로 시작한다. 버튼 위치·단축키·편집 허용 수치는 구현 전 화면 검토에서 확정한다. 본 문서는 기획이며 제품 구현 완료를 뜻하지 않는다.

## 2. 현재 기반과 제공 방식

현재 `ReviewedLaneLayout`에는 T1 동남 접근의 부분 보정이 있고, `laneTurns`에는 회전 제한을 입력하는 기반이 있다. `MapCatalog`는 보조 자료 → 검토 차로 → 도로 외형 보정 순으로 적용한다. 내비·H·NPC는 공유 차로 그래프를 사용한다. `TrafficSystem`의 차량/보행 신호와 `PedestrianSignalDisplay`, `RoadSignage`, `FullMapOverlay`, `RoadNavigation`을 연동 대상으로 검토한다. 현재 기반이 사용자 편집 UI를 제공한다는 의미는 아니다.

| 방식 | 장점 | 제약 |
|---|---|---|
| 실행파일 내 편집 — 권장 | 실제 외형·교통을 보며 시험, Unity 설치 불필요 | 선택·배치·저장 UI 개발 필요 |
| Unity 전용 도구 | 기존 씬 편집 도구 활용 | 프로젝트와 Unity 설치·빌드 과정 필요 |
| 외부 웹 편집기 | 평면 지도 편집에 편리 | 게임 높이·충돌·주행과 별도 연동 필요 |

권장안은 게임 안에서 평면 편집과 3D 확인을 제공하는 방식이다. 거리뷰는 외부 브라우저에서 확인하고 링크·촬영월을 기록한다. 이미지 복제·자동 판독·지도 서비스 내장은 첫 범위에 포함하지 않는다. 동시 개발 중인 소스와 배포 상태는 구현 시작 시 다시 확인한다.

## 3. 사용 흐름과 화면

1. 메뉴의 ‘지도 편집’을 열고 T1 또는 교차로ID/위치로 이동한다. 편집 중 영업 시간과 교통 시뮬레이션을 멈춘다.
2. 왼쪽에서 교차로·진입 방향을 선택하고 중앙 지도에서 차로·표지·신호를 클릭한다. 오른쪽 속성창에서 값을 바꾼다.
3. 평면 보기에서 차로 연결을 수정하고 3D 보기에서 폭·높이·표지 가독성을 확인한다. 변경 전 형상도 겹쳐 볼 수 있다.
4. ‘검사’를 눌러 연결 끊김·겹침·신호 충돌을 확인한다. 오류를 클릭하면 해당 위치로 이동한다.
5. ‘시험 적용’으로 별도 시험 세션을 열고 출발/목적지 지정, 경로 미리보기, NPC 통과, 직접 운전을 확인한다.
6. ‘수정본 저장’ 후 유효한 저장본을 ‘기본 사용 지도’로 지정한다. 다음 실행에서도 수정본 이름·리비전을 표시한다.

상단에는 선택/차로/노면/표지/신호 도구, 취소·다시 실행, 검사, 시험 적용, 저장을 둔다. 왼쪽 목록에는 접근 방향별 확인 상태를, 오른쪽에는 속성과 근거를, 하단에는 오류·미저장 상태·적용 지도 버전을 표시한다.

시험 세션은 영업 저장·점수·연료·시간을 변경하지 않는다. 초기 버전은 편집 전 영업 상태를 보존하고 변경 지도에서의 일반 영업은 새 세션부터 시작한다. 주행 중 차량 아래 도로를 즉시 바꾸는 방식은 제공하지 않는다.

## 4. 도로·차로·노면 편집

| 기능 | 조작과 결과 |
|---|---|
| 도로 형상 | 제어점 이동으로 평면 중심선 수정, 기존 지형 높이에 맞춤·수치 보정, 인접 끝점 연결 유지 |
| 차로 수·폭 | 진입 방향별 추가/삭제·폭 조정. 번호는 교차로를 바라보는 운전자 기준 왼쪽부터 표시 |
| 짧은 전용 차로 | 시작점·벌어지는 구간·대기 길이를 조절해 좌회전 대기차로 생성 |
| 허용 방향 | 좌회전·직진·우회전·겸용 지정, 미확인 상태 별도 표시 |
| 출구 연결 | 진입 차로에서 출구 차로까지 연결선을 만들고 제거. 회전 곡선 미리보기 |
| 차로 변경 | 인접 차로와 변경 가능 구간 지정. 실선/점선 표시와 변경 규칙을 함께 관리 |
| 노면 | 중앙선·차로선·화살표, 정지선·횡단보도 위치·폭·각도 수정 |

진행 방향만 지정하고 출구 연결이 없으면 오류다. 화살표는 같은 허용 방향 데이터로 생성한다. 차로 삭제 시 연결·표지·신호·승하차 접근에 미칠 영향을 보여주고, 대상 재지정/제거를 한 번의 취소 가능한 작업으로 처리한다.

2026-10-26: 유턴을 turn=-2인 별도 연결로 구현한다. 반대 방향 출구·최소4.5m 반경·진입 차로에 연결된 단일 허용 조건 표지를 검사한다. 상시 양보/좌회전 신호/보행 신호/좌회전 또는 보행 신호를 구분하고 내비·H·NPC·노면 표시와 운행 평가에 적용한다. 현장 미확인 유턴은 자동으로 만들지 않는다.

## 5. 표지판 배치

- 목록: 제한속도, 회전 금지, 진입 금지, 일방통행, 비보호 좌회전, 횡단보도·보호구역 안내, 방향 안내.
- 위치·높이·방향·크기·문구 편집, 지면/도로 가장자리 맞춤과 자유 배치를 제공한다.
- 적용할 접근 방향·차로·구간을 지정한다. 제한속도에는 적용 시작과 종료 범위가 필요하다.
- ‘안내용 외형’과 ‘게임 규칙 적용’을 구분한다. 규칙을 지원하는 종류만 규칙 적용을 활성화하고 미지원 표지는 안내용으로 저장한다.
- 규칙형 표지는 차로 제한·속도 설정과 같은 데이터를 수정한다. 같은 구간에 상충하는 값을 넣으면 검사에서 알려준다.
- 실제 확인/추정/게임 창작, 거리뷰 URL·촬영월·확인일·메모를 저장한다. 외형 확인과 규칙 확정 여부는 별도로 기록한다.

## 6. 차량·보행자 신호등

신호기 외형, 제어 대상, 점등 순서를 나누어 편집한다. 위치만 지정하고 제어 대상을 연결하지 않은 신호기는 경고 색상으로 표시한다.

| 대상 | 배치 속성 | 연결할 대상 |
|---|---|---|
| 차량 신호기 | 위치·높이·방향, 지주/가로대, 직진·좌회전 표시 종류 | 교차로, 진입 차로의 진행 연결, 정지선, 신호 그룹 |
| 보행자 신호기 | 횡단보도 양 끝 위치·높이·방향 | 횡단보도ID, 횡단 방향, 보행 신호 그룹 |
| 신호 그룹 | 함께 켜지는 신호기와 허용 이동 | 교차로 신호 순서표 |
| 순서표 | 단계별 차량/보행 허용, 지속 시간, 황색·정리 시간 | 이동 경로 간 충돌 검사 |

첫 작업은 기존 게임 신호를 가져와 위치·연결을 편집하는 것이다. 이후 단계별 시간과 허용 이동 편집을 추가한다. 기존 축/진입 방향 기반 신호를 임의 차로 그룹으로 확장하는 개발이 필요하므로 외형 편집만으로 운영 기능 완성을 표시하지 않는다.

보행 녹색과 충돌하는 차량 진행, 교차하는 차량의 동시 진행을 검사한다. 비보호·양보 이동은 명시적인 양보 규칙과 동작 검증이 있는 경우만 허용한다. 미지원 조합은 적용을 막는다. 횡단보도 수정 시 보행 구간·충돌 판정 영역도 함께 바뀐다.

신호기를 이동해도 정지선은 자동으로 같은 위치로 이동하지 않으며 제어 대상 연결은 유지한다. 정지 사진으로 실제 신호 주기와 순서를 확정하지 않는다. 임시 운영 시간은 ‘게임 설정’으로 표시한다.

## 7. 수정 차로를 반영하는 내비게이션

기존 목적지 탐색을 확장해 새 차로 연결을 기준으로 경로와 안내를 다시 만든다.

1. 지도 적용 시 형상·허용 이동·출구 연결·차로 변경 구간으로 공통 그래프를 재구성한다. 내비·H·NPC·노면·규칙 판정이 동일 지도 리비전을 사용한다.
2. 기존 경로와 가까운 차로 조회 캐시를 무효화한다. 승하차·주유·휴식 접근점을 다시 연결하고 실패 위치를 알려준다.
3. 교차로 접근 시 ‘앞 교차로 좌회전, 왼쪽 1개 차로 이용’처럼 추천 차로와 허용 방향 화살표를 표시한다. 현재 차로 인식이 불확실하면 특정 차로에 있다고 단정하지 않는다.
4. 차로 변경이 허용된 구간에서만 추천 차로로 연결한다. 분기점이나 변경 가능 구간을 지나쳤으면 다음 가능한 경로를 재탐색한다.
5. 금지 회전·삭제 차로를 경로에 포함하지 않는다. 경로가 없으면 ‘도달 가능한 경로 없음’과 원인 위치를 표시한다.
6. 거리·예상 시간·미니맵/전체지도 경로를 갱신한다. 제한속도와 지원하는 게임 신호 대기 모델을 반영하며 실시간 현장 교통 정보로 표시하지 않는다.

예: T1의 1차로를 좌회전 전용으로 변경하면 직진 목적지 내비는 직진 가능한 차로를 안내한다. NPC도 같은 연결을 사용한다. 화살표만 바뀌고 내비가 기존 차로로 직진하면 완료 기준을 충족하지 못한다.

## 8. 저장·복원과 적용 구조

- 원본 NGII/OSM·생성 지도를 보존하고 사용자 수정본을 별도 JSON으로 저장한다. 실행파일의 사용자 데이터 폴더를 사용하며 위치 열기·내보내기/가져오기를 제공한다.
- 저장 항목: 스키마 버전, 기준 지도ID·입력 해시, 수정본ID·리비전·저장일, 대상의 안정적 ID, 형상·규칙·시설·신호·근거. 차로 순번은 ID로 쓰지 않는다.
- 적용 순서 제안: 기준 지도/기존 검토 보정 → 사용자 수정 → 노면·충돌·신호·경로 구성. 기존 T1 보정을 초기 편집 대상으로 가져와 중복 차로 생성과 덮어쓰기를 방지한다.
- 오류 있는 초안은 저장 가능하나 시험 적용·기본 사용 지정은 막는다. 임시 파일 검증 후 교체하고 이전 정상본을 보관한다.
- 실행 취소/다시 실행은 형상·연결·시설 참조를 함께 되돌린다. 교차로 원상 복원, 전체 기본 지도 복원, 마지막 정상 적용본 복원을 제공한다.
- 기준 지도 해시가 다르면 자동 적용하지 않는다. 충돌/재연결 항목을 보여주고 기본 지도로 실행하거나 명시적인 변환을 진행한다.
- 재빌드 없이 수정본을 불러온다. 다른 PC에는 수정본을 전달한다. 기본 배포에 채택할 때는 별도 검증과 Resources/배포 지도·manifest 갱신 절차를 따른다.
- 적용 실패 시 이전 정상 지도 전체로 복원한다. 그래프만 새 버전이고 신호·충돌체는 이전 버전인 부분 적용을 허용하지 않는다.

## 9. 검사 기준

| 검사 | 처리 |
|---|---|
| 없는/중복 ID, 미지원 스키마, 기준 지도 불일치 | 적용 차단 |
| 잘못된 폭, 자기 교차, 끝점 단절, 반대 방향 연결, 허용 방향/출구 불일치 | 적용 차단 |
| 건물·보도 침범, 너무 짧은 합류·급회전 | 위치 경고, 통과 불가능 판정 시 차단 |
| 없는 정지선/횡단보도 참조, 무제어 진행, 충돌하는 동시 허용, 잘못된 신호 시간 | 적용 차단 |
| 기존 필수 승하차·주유·휴식 접근 불가 | 적용 차단, 폐쇄 실험은 초안으로 보관 |
| 근거 부족·촬영월 없음·실제 치수/운영 미확인 | 경고와 추정 상태 유지 |

오류에는 대상ID·위치·수정 방법을 제공한다. 현장 사실 확인과 게임 동작 검증은 별도 상태로 관리한다.

## 10. 개발 단계와 완료 기준

다음은 개발 순서 제안이다. 상세 코드 작업 계획은 기획 검토 후 단계별로 작성한다.

| 단계 | 제공 기능 | 완료 기준 |
|---|---|---|
| E1: T1 차로·내비 | 선택·기본 형상/폭/대기차로·방향/출구 연결 편집, 저장/불러오기·취소·시험 세션 | 한 접근 방향 수정이 화면·내비·H·NPC에 일치, 재실행 후 유지 |
| E2: 노면·표지 | 정지선·횡단보도·표지 배치/회전/삭제, 규칙 범위 연결 | 외형과 규칙/충돌 영역 일치, 잘못된 참조 차단 |
| E3: 신호 | 차량/보행 신호 배치, 제어 그룹·시간표, 충돌 검사 | 정지/통과·보행 횡단과 점등 표시 일치 |
| E4: 확장·배포 | T1 전체→T2/T3, 내보내기/가져오기·버전 충돌 처리 | 다른 PC의 동일 기준 지도에서 재현, 기본 빌드·해시 검증 |

E1부터 실제 화면에서 편집하고 시험 주행할 수 있어야 한다. 데이터 구조만 추가한 상태를 편집기 완성으로 표시하지 않는다. 요청 전체 완료에는 E2/E3의 표지·차량/보행 신호도 필요하다.

## 11. 검증 시나리오

- 자료: 방향/연결 변경, 대상 삭제, 저장 왕복, 취소, 기준 지도 불일치, 적용 실패 복원.
- 경로: 금지 직진 제외, 좌회전 차로 진입, 변경 금지 구간 이후 재탐색, 도달 불가 안내, 기존 승하차·시설 경로 유지.
- 신호: 진행별 정지/출발, 보행 녹색 횡단, 상충 단계 차단, 비보호 양보, 정지선 이동.
- 실행파일: 재실행 후 수정본 유지, 지도 리비전 일치, 저장 실패/손상 파일 처리.
- 자동 물리: T1 좌/직진·NPC 연속 통과, 건물·보도 침범, 신호 대기. 위치 강제 이동 검사와 구분한다.
- 수동: 사용자가 수정→저장→시험 주행, 1인칭 가독성과 영업 저장 보존 확인.
- 성능: 동일 교차로·차량48대·동일 시간으로 적용 전후 프레임 및 재구성 시간 비교. 통과 수치는 구현 전 기준 실측을 바탕으로 정한다.

## 12. 범위 밖과 다음 작업

전국 지도, 고가/터널 신설, 전체 지형 조각, 건물 모델 제작, 실시간 교통, 거리뷰 자동 인식, 공동 실시간 편집은 첫 버전에서 제외한다. 건물명·보도 상세 편집은 후속 확장 후보이다.

다음 검토: 화면 배치, E1의 T1 시범 방향, 기존 보정 가져오기와 저장 방식. 이번 기획 작성에서는 제품 코드 변경·빌드·현장 재확인을 수행하지 않았다.
