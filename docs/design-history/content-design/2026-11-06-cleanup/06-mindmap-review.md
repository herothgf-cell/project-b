# 마인드맵 가지별 변경 검토표

## 2026-11-06 최신 게시본 반영

원격 main의 작은 방 배포 `e230a3b` 기준으로 사고 3등급·보행자 내구도 손상, 은계/A2 공업사 각2곳, 별도 콘텐츠 설정 관리창, 싱글 정산의 작은 방/조명·러그 구매를 구현50%로 추가했다. 기존 사고 검토 문구는 구현 참조와 보험·과실·현장 구조 후속으로 구분하고, 안전 대체 쌍·용무 대기·방향지시등의 오래된 미구현 표현을 정정했다.

현재346노드, 기능 말단 구현50%183 / 기획완료25%0 / 기획필요0%54다. 기존340노드의 ID·순서·접힘·task·메모·링크를 보존하고 부모 집계와 목차를 재생성했다. 차량 구매·차량 물품·이사·장기 성장에는 문서/시안이 있으나 가격·진행/범위 결정이 남아0%를 유지한다. 방 소품 구매 구현과 차량 물품 미구현을 혼동하지 않는다. 별도 작업 중인 운전 설정은 게시된 main의 구현으로 표시하지 않는다.

50%는 구현 단계이며 사람 장시간·전체3일·다른PC LAN 수용 완료를 의미하지 않는다. 아래 날짜별 설명은 당시 기록이며 현재 사고 수치는 [08의 11/06 등급표](../../../content-design/08-accident-and-workshop-proposal.md)가 우선한다. [최신화·게시 기록](../../../work-history/2026-11-06-mindmap-publication.md)을 따른다.

## 2026-11-03 현재 인계 기준

[현재 구현·다른 PC 인계](../../../CURRENT-STATE.md) · [이번 정리 이력](../../../work-history/2026-11-03-planning-handoff.md). 원래 사용자 수정본333노드를 기준으로 최근 구현7개를 더해340노드이며 말단 구현50%178/기획 완료25%0/기획 필요0%53이다. 삭제한 제작 참고 가지를 되살린 것이 아니다. 기존ID/메모/접힘/task키/자식 순서를 보존한다.

P1/P2 구현, 대화 UI/운행 중 응답, 기본 신호/목표 거리/조향, PvP 닉네임/단거리 배차/자기차 예측을 반영했다. 현재 맵은A2, A3는 복귀 이전 이력/후속 시안이다. 음악·에어컨·창문 실제 조작은0% 보류. 계산 모델의 상태 예측 구현과 운송 중 상시HUD 카드 숨김을 구분한다. 50%는 구현 단계이며 수동/다른PC/장시간 검증 완료율이 아니다.

사용자 상태를 먼저 보존 커밋한 뒤 `tools/refresh_handoff_mindmap.py`로 최신화한다. 검사만 할 때는 기존 `tools/organize_content_mindmap.py --validate-only`. 아래 날짜별 표/숫자는 당시 정리 기록이며 현재 노드 수와 다를 수 있다.


## 2026-11-02 사용자 지정 진척도·미구현 우선순위

사용자 요청에 따라 원본의 기능 말단에 **구현50% / 기획 완료·미구현25% / 기획 필요0%**의 `task.progress`를 직접 넣었다. 분류/부모는 하위 단계별 개수만 보여 주며 평균 완료율로 표시하지 않는다. 설명/참조는 제외하고 부분 구현 가지는 구현된 동작과 미구현 확장으로 나눴다. [미구현 전체 우선순위와 단계 기준](../../../future-design/2026-11-02-simulation-priorities.md)을 따른다.

기존 추천9개도 포함하며, 아이디어/검토 문서만 있는 요소를25%로 올리지 않았다. 다음 운송 상태 예측은 이번에 표시/계산/정보 없음/갱신/저장/모드 경계 계약을 구체화해25%로 표시했다. 나머지 미구현 후보는 필요한 기획 결정을 명시해0%로 두었다. 50%는 구현 단계이며 수동/다른PC/전체 캠페인 검증100%가 아니다. 현재 진행 중인 별도 UI 스타일 변경을 이 마킹의 구현 근거로 쓰지 않았다.

사용자가 원본에서 접고 편 상태와 제거한 제작 참고 가지는 복원하지 않는다. 기존 정리 직후 보관본과 이번 마킹 전 사용자 상태를 각각 보존한다. 현재 검사 도구는 이 최신 보관본을 노드 보존 기준으로 사용하고 요청받은 진척도 변경을 허용한다. 과거의 ‘기존 작업 체크 보존’은 직전 정리 당시 조치이며 이번 요청으로 기존 체크를 재분류했다.

## 2026-11-02 원본 정리 결과

[현재 마인드맵](../../../content-design/%ED%83%9D%EC%8B%9C%20%EC%8B%9C%EB%AE%AC%EB%A0%88%EC%9D%B4%EC%85%98.mmst) · [글로 보는 목차](../../../content-design/%ED%83%9D%EC%8B%9C%20%EC%8B%9C%EB%AE%AC%EB%A0%88%EC%9D%B4%EC%85%98-%EB%AA%A9%EC%B0%A8.md) · [이번 정리 전 보관본](../2026-11-02-mindmap-before-organize.mmst).

원본 `.mmst`를 직접 정리했다. 큰 가지는 아래4개이며, 처음에는 상세 가지를 접어 전체 구분을 먼저 읽도록 했다. 기존 노드 ID·작업 체크·외부 링크·사용자 메모는 보존한다. 기존 작업 진척도는 실제 구현/플레이 검증 완료를 뜻하지 않으며 현재 상태는 개발 체크리스트로 확인한다.

| 큰 가지 | 내용·변경 |
|---|---|
| 현재 플레이 기획 | 기존 맵·운전·승객·차량·생활·경제·캠페인·화면을 모음. 단일 실행/은계 싱글/자체 도시 나1+봇3, 충돌 내구도·수리·견인과 승객11유형을 최신 상태로 연결 |
| 기존 아이디어·후속 구상 | 승객/예약, 차내/차량/용품, 생활/금융/보험, 환경/교통/사고/법규, 원격 모드로 묶음. 구현된 수리비는 차량 관리로 이동하고 보험·현장 구조 등은 유지 |
| 추가 제안 (미채택) | 검토안9개의 기존/확장/신규 출처와 추천 순서를 표시. 신규 상태 예측·시설 혼잡 등을 원래 있던 아이디어처럼 합치지 않음 |
| 제작·검토 참고 | 개발 검사·Unity 제작·조작감 메모. 실제 플레이 규칙과 분리 |

취객을 진상 승객 아래에서 빼 독립 유형으로 배치했다. 예전 ‘진상’ 구상은 재촉·간섭 응대 참조로 보존한다. 현재 봇 경기와 기존 원격 사용자 PVP 원안도 구분한다. 숫자·운임·생활 효과는 담당 문서를 대표 기준으로 유지하고 맵은 요약/참조 중심으로 쓴다. 원격4유저 수용·PVP 생활 수치 후보·안전 대체 승하차를 완료로 바꾸지 않았다.

이번 정리 도구는 `tools/organize_content_mindmap.py`, 검사 전용은 `--validate-only`다. 기존 PowerShell 도구의 `-ValidateOnly`도 원본 ID/Detail-Link 검사를 지원한다. 구 정리 변환을 다시 실행해 현재 구조를 덮지 않도록 차단했다. 네이티브 앱에서의 실제 열기/시각 배치는 별도이며, 이번 검증은 JSON/노드 보존/링크/목차 대조다.

## 2026-10-27~29 이전 검토 기록

아래 표의 ‘현재/후속/이번’은 당시 검토 시점의 표현이다. 내구도·수리·통합PVP와 이번 원본 배치의 현재 상태는 위 정리 결과와 최신 담당 문서를 우선한다.

2026-10-29 추가 검토: 아래 이전 가지 판정 중 내구도/사고 수리 제외는 [Proto 확장](../../../content-design/03-life-and-economy.md#추가-기획-충돌-내구도와-수리)에서 부분 변경했다. 취객·진상은 [지속 응대 승객안](../../../content-design/02-passengers-and-fares.md#추가-기획-승객-유형과-상호작용)을 연결한다. 승객 유형/준비/청결 사건은 구현했으며 내구도·수리·견인은 사용자 승인에 따라 구현·자동 검증을 완료했다. 최종 Player·수동/전체 캠페인 검증 완료와 구분한다. 이번 작업에서는 .mmst 원본을 변경하지 않았다.


대상은 같은 폴더의 **택시 시뮬레이션.mmst**다. 아래 표는 기존 가지와 최신 기획의 대조 기준이다. 2026-10-27 후속 승인으로 원본에도 현재 규칙·후속 구상 구분과 Detail-Links 갱신을 반영했다. 이동된 기존 아이디어는 별도 가지에 보존했다.

## 표를 읽는 기준

| 작업 | 의미 |
|---|---|
| 추가 | 현재 기획에 있지만 원본 가지에 빠진 내용 |
| 수정 | 현재 문구가 최신 규칙을 잘못 설명하거나 의미가 불분명한 경우 |
| 통합·삭제 | 같은 규칙의 중복 가지를 한 곳으로 합치고 나머지는 제거/참조로 바꿈 |
| 이동 | 아이디어는 보존하되 현재 Proto가 아닌 ‘후속 구상’ 또는 별도 개발 자료로 분리 |

**이동·통합은 아이디어의 영구 폐기가 아니다.** 현재 Proto와 후속 구상/제작 참고를 구분한다. 반복 상세 수치는 대표 가지 한 곳에 두고 다른 가지는 관련 기획으로 연결한다.

| … > 추가 아이디어의 카메라/버스차로/벌금/스쿨존 등 | 이동 | 후속 법규 콘텐츠 구상 | 현재 적용 범위를 과장하지 않음 |

## 중복을 없앤 대표 가지 제안

| 규칙 | 대표 가지 한 곳 | 다른 가지에는 이렇게 남김 |
|---|---|---|
| 운임·보너스 산식 | 경제 > 운임 요금 규칙 | 승객 만족도는 ‘운임에 영향’만 연결 |
| 요청 종류·선택·효과 | 승객&보행자 > 승객 대화 > 요청17종 | 별도 변경/경유/분실물 가지는 해당 요청 참조 |
| 청결·세차 결과 | 차량 > 차량 관리 > 청결·세차 | 주유소는 ‘세차 제공’, HUD는 ‘청결 표시’만 |
| 식사·수면 회복/비용 | 맵 > 주요 시설 > 거점 이용 공통 규칙 | 운전자는 상태 변화·영향, 시설은 이용 장소만 연결 |
| 졸음 단계·마감 예외 | 운전자 > 피로도 | 캠페인은 ‘졸음 정책에 따른 당일 마감’만 연결 |
| 지역 수요 | 맵 > 지역 | 경제는 공차 성과, 호출은 이용 가능한 손님 표시만 연결 |
| 기록·연습 | 운전 점수 > 운전 점수 히스토리 | 캠페인은 하루 결과 연결, UI는 화면 위치만 |

대표 가지의 상세 기준은 연결된 기획서에 둔다. 원본을 다시 정리할 때에도 후속 아이디어와 사용자 작성 내용은 보존한다.
