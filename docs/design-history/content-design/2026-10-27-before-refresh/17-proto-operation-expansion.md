# Proto 후속 확장: 요청 → 수요·공차 → 승하차 공간

기준일: 2026-10-26. 사용자가 선택한 개발 순서는 **기존 P11 승객 요청 다양화 → 지역별 수요와 공차 수익성 → 승하차 공간 점유**다. 현재 P11/P12와 P13 대기 경로를 구현했다. 수치는 게임용 시험값이며 마인드맵 원본 수정 승인은 별도다.

실행 갱신(2026-10-27): 저장 안정화, 최종 Editor 통합 검사와 BuildHybrid, 실행파일 저장/3일 회계, 실제 지도1280/1920 및 48대 교통의 연속 물리 운송·식사·주유·휴식·초과 영업 마감 검사를 통과했다. 자동 운전기·점유 날짜 초기화·지도 표시 오류를 수정했다. 수동 조작감·경제 체감은 별도다. [최종 안정화 기록](../../../content-design/../work-history/2026-10-27-proto-stabilization.md)을 따른다. 마인드맵은 계속 미수정.

## 목표와 범위

같은 은계 지도에서 손님 응대뿐 아니라 어디서 영업하고 어떤 호출을 받을지, 막힌 승하차 공간에 어떻게 대응할지 판단하게 한다. 기존 24개 후보·방향 경로·시간·연료·정산·저장을 활용한다.

기존 시스템을 연결하는 작은 단계별 확장을 택한다. 시설/차종/생존 게이지를 대량 추가하거나 실시간 도시 수요를 재현하는 접근은 이번 범위에서 제외한다. 날씨·짐 싣기·단골/예약·일반 도로 공사·보험·대출·차량 구매·PVP는 이번 선택에 포함하지 않는다.

| 순서 | 개발 묶음 | 기존 기반과 차이 | 플레이 결과 |
|---|---|---|---|
| 1 | P11 요청 다양화 | 기존17종 요청은 있음. 순환1건에서 후보별 무작위0~2건·승차/중간 안전 정차 제시로 확장 | 같은 구간에서도 다른 응대, 앞 요청의 약속과 결과 유지 |
| 2 | P12 지역별 수요·공차 수익성 | 기존 후보/대기 분포/경로 미리보기는 있음. 지역·영업 단계에 따른 배정 비중과 공차 성과 설명을 추가 | 손님을 찾아 이동할지, 가까운 호출을 받을지 판단 |
| 3 | P13 승하차 공간 점유 | 기존 위치·방향·저속 판정은 있음. 일시 점유와 대체 정차 처리 추가 | 막힌 자리에 무리하게 정차하지 않고 기다리거나 대안 선택 |

P12/P13은 이번 문서에서 부여한 추적 번호다. 기존 Proto 완료 기준과 확장 완료 기준은 아래에서 분리한다. **최신 사용자 지시: P11→P12→P13 개발 후 마지막에 안정화·완성도 검증을 수행한다.** 중간에는 단계별 최소 집중 검사만 하고 전체 검사/빌드를 반복하지 않는다. 컴파일 오류 등 다음 개발을 막는 문제만 즉시 처리한다. [실행 계획](../../../content-design/../superpowers/plans/2026-10-26-proto-p11-p13.md) 참고.

## 1. P11 승객 요청 다양화

공통 규칙은 [04 요청 배정](../2026-10-27-before-planning-only/04-passengers-and-reservations.md), 개별 내용은 [11 요청별 효과](../2026-10-27-before-planning-only/11-passenger-request-effects.md)가 단일 기준이다. 새로운 요청17종을 다시 만드는 작업이 아니다.

- 후보 ID에 요청 수·종류·순서·발생 시점을 고정하고 재수락/저장 복원으로 다시 추첨하지 않는다.
- 승차 또는 운행 중 안전 정차 때 제시한다. 주행 중 선택을 강요하지 않으며 기회 없는 짧은 운송은 중립이다.
- 복수 요청의 관찰/효과/결과를 개별 보관하고 충돌 약속·목적지 변경 중복·점수/운임 중복을 방지한다.
- 취객 대사와 요청 선택창을 구분하고 기존 운송·구형 저장을 보존한다.
- 완료 조건: 0/1/2건과 서로 다른 제시 시점, 상충 제외, 저장 복원, 실제 운행 중 답변 여유·빈도를 각각 검증한다.

## 2. P12 지역별 수요와 공차 수익성

| 요소 | 최소 개발안 | 제약·검토 사항 |
|---|---|---|
| 지역 분류 | 기존 후보에 주거/상업/업무 태그와 중립 기본값을 연결 | 실제 지역 통계가 아닌 게임용 분류. 각 후보 매핑은 지도 검토 후 확정 |
| 시간대별 배정 | 게임 영업 초반/중반/후반에 지역별 호출 생성 비중 변경 | 실제 시계/현실 출퇴근 시간과 혼동하지 않음. 경계·가중치는 미정, 초과 영업에서도 호출 유지 |
| 수요 표시 | 지도/호출 화면에 지역의 상대 수요와 갱신 상태 설명 | 정확한 승객 수나 수입 보장처럼 표시하지 않음. 기존 핀/필터를 과도하게 복잡하게 만들지 않음 |
| 호출 비교 | 픽업 거리/예상 시간, 탑승 운송 거리/예상 시간, 예상 운임을 구분 | 기존 표시를 재사용·보완. 총 예상시간에는 추정 가능한 픽업+운송을 포함하고 변동 가능성 명시 |
| 공차 기록 | 영업 중 미탑승 이동을 공차 거리로 집계, 수락 후 픽업 이동도 포함 | 탑승 후 이동과 분리. 순간 이동/복구·연습 제외. 서비스 왕복은 미탑승 이동이면 포함 |
| 미탑승 시간 | 영업 시계가 흐르는 동안 미탑승 이동·대기·서비스 시간을 분류 | 메뉴 정지 제외, 서비스10/30초 등 이미 차감한 시간을 다시 영업시간에 더하지 않음 |
| 정산 | 공차/탑승 거리, 미탑승 시간과 비용·실수령을 함께 비교 | 기록용 지표이며 추가 요금·새 감점 아님. 예상 운임을 확정 순이익으로 표현하지 않음 |
| 생성·복원 | 지역 비중보다 기존 안전/접근 가능 조건을 우선 | 기존 수락 호출은 시간대가 바뀌어도 유지. 재실행으로 호출/누적 지표 재추첨·중복 적립 금지 |

수요로 운임을 자동 인상하는 할증은 범위 밖이다. 수요를 따라갔는데 반드시 손님이 생기는 보장은 하지 않는다. 요청 P11 배정과 호출 지역 배정은 서로 다른 선택이며, 지역 때문에 미리 특정 요청을 공개하지 않는다.

완료 조건: 동일 조건 재현과 단계별 분포 차이, 후보 부족/접근 불가 대체 처리, 픽업 이동 포함 여부, 정지·서비스·순간 이동·재시작 경계의 집계, 실제20분 영업에서 위치/호출 선택 차이를 확인한다. 구형 저장은 새 집계를 시작한 시점부터 기록하며 과거 공차 성과를 추측해 채우지 않는다.

## 3. P13 승하차 공간 점유

P12 구현 시험값: 주거 EG-GAME-03/04/06/08/10, 업무01/05/09/11, 상업02/07/12, 미분류 중립. 기존 카탈로그 유형을 참고한 게임용 태그다. 영업0~300초 주거,300~900초 업무,900초 이후 상업에 상대 가중3, 나머지1. 수락 호출·운임은 유지하며 당일 공차 지표를 정산에 표시한다. 자동 집중 검사는 통과했고 실제 UI/플레이 검증은 최종 단계에 남아 있다.

| 요소 | 최소 개발안 | 안전·기존 규칙 연결 |
|---|---|---|
| 대상 | 검증된 일반 후보 일부에 일시 정차 차량 배치 | 첫 범위는 고정9코스/주유소/식당/교차로가 아닌 일반 승하차 공간. 전역 도로 장애 시스템과 구분 |
| 점유 | 차량 전체 크기로 실제 공간과 진입 동선을 점유 | 플레이어/NPC/승객과 겹쳐 생성 금지. 접근 중 갑자기 출현하지 않게 배치 조건 검증 |
| 사전 생성 | 이미 막힌 승차지는 새 호출 후보에서 제외하거나 안전한 대안 확보 후 제시 | 완료 불가능한 호출 생성 금지. 진행 중 운송을 임의 취소하지 않음 |
| 플레이어 선택 | 원래 지점이 빌 때까지 대기 / 검증된 대체 지점 선택 | 인도·횡단보도·반대 차로를 대안으로 쓰지 않음. 대안이 없으면 유한 시간 안에 해소되는 대기만 제공 |
| 대체 지점 | 같은 목적지 주변의 안전 후보1개부터 시작 | 연결 거리·진행 방향·승객 보행 경로 검증. 선택 전 위치/추가거리/시간 안내. 공간만 변경하고 목적지 요청 건수는 소비하지 않음 |
| 승객과 안내 | 선택 확정 후 목표·내비·승하차 판정·승객 위치를 일관되게 갱신 | 순간적으로 보행자를 차도/차량 안에 옮기지 않음. 안전 보행 이동 또는 보이지 않는 재배치 방식은 구현 전 확정 |
| 시간·평가 | 시스템이 강제한 점유/대체 이동 때문에 부당한 실패를 주지 않음 | 영업·연료 시계는 유지. 보정할 픽업/운송 기한·ETA·경로 요청 평가의 범위/상한은 별도 확정. 무제한 기한 연장 금지 |
| 운임·기록 | 같은 호출/운송 ID, 최종 정산 한 번 | 시스템 대체 지점으로 추가 할증하지 않는 안. 실제 승하차 위치와 변경 사유 기록 |
| 저장 | 점유 차량·해소까지 시간·원래/대체 목표·확정 여부·시간 보정 보관 | 로드 시 재점유/중복 연장 방지. 구형 저장에는 점유 사건 없음으로 호환 |

완료 조건: 정상/점유/대체 없음/도중 해소/저장 복원, 실제 물리 차량 진입·보행 안전, P11 목적지/경유 요청과의 충돌, DR04 짧은 길·ETA 평가의 부당한 감점 방지를 검사한다. 점유 빈도·지속시간·대안 거리·기한 보정 수치는 현행 지도에서 시험 후 확정한다.

## Proto를 완료라고 부를 조건

| 단계 | 현재 판단 | 완료 기준 |
|---|---|---|
| 핵심 플레이 기반 | 구현되어 플레이 가능 | 호출→주행→승하차→생활 거점→정산/이어하기 기반 존재. 이것만으로 전체 완료는 아님 |
| 기존 Proto 기능 마감 | 구현·자동 검사 | P11 및 저장 교체 경고 수정. 수동 체감 검증은 별도 |
| 기존 Proto 플레이 검증 | 미완료 | 일반 교통 속 대표 코스·거점 왕복, 수동20분/초과 영업/3일 완주·수익/피로/연료 밸런스·장시간 안정성 |
| 이번 확장 마감 | P12·P13 대기 구현 | 현재12일반 후보 중150m 이내 쌍0개. 안전 대체 이동 미구현, 대기 경로만 제공. 수동 체감 별도 |
| 다듬기 | 계속 필요 | 조작감·가독성·빈도/수치·로딩/FPS 조정. 신규 기능 개발과 구분 |

따라서 현재는 **플레이 가능한 Proto 기반 + 남은 신규 개발 + 안정화/플레이 검증 단계**다. 새 요소를 계속 추가해야만 완료되는 구조를 피하고, 이 세 묶음 이후 추가 아이디어는 별도 승인한다.

## 마인드맵 검토용 변경안 — 원본 수정하지 않음

아래는 사용자가 검토한 뒤 적용할 목록이다. 기존 가지를 확장하고 같은 시스템을 중복 가지로 만들지 않는다.

| 기존 가지 위치 | 작업 | 추가·수정할 하위 항목 |
|---|---|---|
| 승객&보행자 → 승객 대화 → 요청17종·선택 및 평가 | 확장 | 요청0~2건 무작위 배정 / 승차·운행 중 안전 정차 제시 / 상충 약속 제외 / 요청별 이행 평가·합산 / 재수락·저장 시 배정 유지 |
| 맵 → 지역 → 상업·주거·업무 지역 | 기존 설명 구체화 | 지역 태그별 수요 / 영업 초·중·후반 배정 비중 / 게임용 상대 수요 표시 / 안전·접근 가능 후보 우선 |
| 승객&보행자 → 호출·배차와 길가 승객 | 확장 | 픽업 거리·시간과 탑승 운송 구분 / 총 예상시간·예상 운임 비교 / 수요 변화와 수락 호출 유지 |
| 경제 → 수익 관리를 볼 수 있는 가계부 | 확장 | 공차·탑승 거리 / 미탑승 이동·대기·서비스 시간 / 실제 수입·비용과 영업 효율 비교 |
| 주행 & 운송 → 안전 승차·하차 판정 | 확장 | 승하차 공간 일시 점유 / 대기 또는 대체 지점 선택 / 내비·정차 판정·승객 위치 동기화 / 강제 변경의 기한·평가 보호 |
