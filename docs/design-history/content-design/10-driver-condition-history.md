# 운전자 설정과 하루 컨디션

## 2026-10-26 피로100·졸음 운전·초과 영업 개정

사용자 요청에 따라 피로 한계의 승차 차단을 졸음 운전 위험으로 교체한다. 아래 규칙이 이후의 과거 기록보다 우선한다. 피로는 게임 수치 0~100이며, 100 이상 조건은 상한인 100에서 발동한다. 실제 생리 기준을 뜻하지 않는다.

| 상태 | 영업·운전 결과 |
|---|---|
| 피로70~99 | 휴식 권장과 운송 후 피로 예상 안내. 호출·승차·운전 가능 |
| 피로100 | 호출 수락·길가 승차·운송 계속 가능. 이동 중 졸음 사건이 간헐적으로 발생 |
| 하루 예정 영업20분 경과 | 자동 정산하지 않고 초과 영업으로 전환. 최초 경계 통과 때 피로100, 이후 시간·연료·생활비·수익 누적 |
| 초과 영업 중 휴식 | 생활 거점에서 빈차·정차 후 수면 가능. 회복 후 예정 시간을 이미 넘었다는 이유만으로 즉시 피로100을 재설정하지 않음 |
| 영업 종료 | 빈차로 생활 거점에 정차한 뒤 휴식·영업 종료를 선택. 탑승 중에는 목적지까지 운송 |

### 졸음 사건

피로100이고 실제로 이동하는 동안 **20초마다 25% 확률**로 사건을 시작한다. 정차·일시정지·결과창·메뉴·연습에서는 이동 시간을 적립하지 않는다. 먼저 2초 동안 `졸음이 몰려옵니다 · 가까운 생활 거점에서 쉬세요`를 알린다. 이어서 시야 축소 3초 또는 조작 중단 1초 중 하나를 같은 확률로 적용한다. 사건 중 재추첨하지 않고 끝난 뒤 다음20초를 새로 센다. 이미 시작된 예고·증상은 정차 중에도 시간이 흘러 종료된다.

- **시야 축소:** 화면 가장자리에서 어두운 영역이 들어와 중앙의 보이는 영역이 줄어든다. 현재 차량 조작은 가능하다.
- **조작 중단:** 짧게 조향·가속·제동 입력을 적용하지 않는다. 차량은 현재 물리 속도로 움직이며 H 조향 보조로 우회할 수 없다. 강제 충돌이나 임의 방향 회전은 만들지 않는다.
- 수면으로 피로가100 미만이 되면 대기·예고·진행 중인 졸음 상태를 해제한다. 메뉴를 닫으면 정지했던 진행을 이어가며 저장·복원은 사건 상태·남은 시간·난수 진행을 보존한다.
- 졸음 사건 자체는 점수 감점 사건이 아니다. 실제 발생한 충돌·법규 위반은 기존 관찰 기준으로 평가한다. 피로 숫자를 운임 감액률에 직접 복사하지 않는다.

### 생활 거점과 마감

휴식은 기존 주차장과 휴식 구역에서 무료로 이용하고100초를 소비해 피로40을 회복한다. `휴식·영업 종료`도 생활 거점에 빈차·정차한 뒤 무료 수면100초·피로40 회복을 한 번 처리하고 정산한다. 초과 영업에서도 수면·식사·세차 이용을 남은 시간0이라는 이유로 차단하지 않는다. 탑승 중 휴식·마감은 목적지 하차 뒤로 미룬다. 일일 정산은 실제 초과 시간·비용·운송 결과를 포함해 한 번만 기록하고, 다음 날에는 기존 야간 피로60 회복을 추가 적용한다.

피로·예고/졸음 상태·초과 영업과 마감 선택은 주행 HUD 및 거점 메뉴에서 설명한다. `20분 경과=즉시 게임 종료`나 `피로100=신규 승객 금지`라는 과거 안내는 새 흐름에서 사용하지 않는다. 실제 승객의 운송 기한은 초과 영업 여부와 별개로 유지한다.

### 검증 기준

피로99.9/100, 이동·정차·메뉴 경계, 추첨 성공/실패, 예고 후 두 증상, H 보조·키보드·자동 입력 차단, 수면 즉시 해제, 저장·복원 중 재추첨 금지,20분 경계 단일 전환, 초과 호출/하차/거점 휴식/정산/다음 날을 검사한다. 자동 상태·위치 제어 검사와 실제 교통 속 수동20분·3일 체감은 구분한다. 수치와 증상 길이는 밸런스 검증 전 시험값이다.

## 2026-10-22 변경 · 다음 날 수면과 상태 HUD

현재 기본 캠페인은3일×20분이다. 날짜1~2의 정산 후 다음 날 수면으로 피로60 회복(최소0), 포만감은 이월한다. 현금·연료·운전 점수도 이어가며 새 캠페인에서만 초기화한다. 아래 독립 하루/이월 없음 문구는 이전 설계 기록이다. 야간 수면은 다음 날 영업 예산을 차감하지 않는다. 영업 중 식사50초·수면100초와 기존 효과는 유지한다.

포만감·피로·연료는 그릇/침대/주유 아이콘, 숫자, 게이지를 함께 표시한다. 상태가 조향·가속·제동을 강제로 바꾸지 않는 규칙을 유지한다.


기준일: 2026-10-21 · 버전: 0.2 · 상태: P7 컨디션 구현·자동 검사 완료, 수동 하루 밸런스 미검증

하루 20분의 영업에서 식사·수면 시점을 선택하고 하루 수익을 비교한다. 배고픔·피로는 영업 가능 시간에 영향을 주며 조향·가속·제동·시야를 강제로 바꾸지 않는다. 수치와 시간대는 아래 테스트 초깃값이며 실제 생리 기준이 아니다.

## 수치와 변화 제안

시간 단위는 [캠페인](../../content-design/07-campaign.md)의 영업 예산이다. 1분은 실제 주행 60초에 해당하고, 게임 시각으로는 36분이다.

| 요소 | 초깃값·범위 | 변화 | 영향 |
|---|---|---|---|
| 포만감 | 시작 80, 범위 0~100 | 깨어 있는 영업 및 수면의 예산 1분당 -5 | 25 미만이면 배고픔 안내·깨어 있을 때 피로 증가율 1.5배 |
| 피로 | 시작 10, 범위 0~100 | 깨어 있는 예산 1분당 +4, 배고프면 +6 | 70부터 휴식 권장, 100이면 신규 운송 수락 불가 |
| 식사 | 식당에서 3,000원 제안 | 게임 30분 = 예산 50초 소비, 완료 시 포만감 +70(상한100) | 경과 중 통상 피로 증가, 수면을 대신하지 않음 |
| 수면 | 지정 주차장에서 추가 이용료 없음 | 게임 60분 = 예산 100초 소비, 완료 시 피로 -40(하한0) | 수면 중 통상 피로 증가 없음, 포만감은 경과만큼 감소 |
| 일시정지·메뉴·복습·결과 | 변화 없음 | 컨디션·영업 시계 정지 | 창을 오래 열어 상태가 회복되지 않음 |

식사는 경과에 따른 포만감 감소와 피로 증가를 먼저 적용하고 회복량을 더한다. 수면은 경과 포만감 감소와 피로 회복만 적용한다. 경과 중 배고픔 경계를 넘으면 해당 구간부터 증가율을 바꾸며, 프레임 수에 따라 결과가 달라지지 않게 한다. 단순 정차는 깨어 있는 상태다. 마감 후 마지막 운송의 추가 실제 시간에도 같은 변화율을 적용하되 영업 예산을 새로 지급하지 않는다.

## 상태별 행동

| 상태 | 운전·운송 | 다음 선택 |
|---|---|---|
| 포만감 25 이상·피로 70 미만 | 정상 운전·승객 수락 | 운송·거점 방문 자유 선택 |
| 포만감 25 미만 | 조작·운임 변화 없이 피로가 빨리 증가 | 식당 안내, 식사 또는 계속 영업 |
| 포만감 0 | 수치 하한 유지, 굶주림 자체로 운송 중단 없음 | 식사하면 회복. 추가 중첩 페널티 없음 |
| 피로 70~99 | 현재 운송·신규 수락 가능 | 휴식 권장, 예상 운송 후 상태 안내 |
| 피로 100·빈차 | 신규 호출 수락·길가 승차 차단 | 직접 주차장으로 이동해 수면 또는 퇴근 |
| 피로 100·픽업 전 | 아직 탑승하지 않은 호출 취소, 픽업 기한 종료 | 매너/법규 자동 감점 없이 휴식 안내 |
| 피로 100·탑승 중 | 기존 운송과 원래 기한 유지, 조작 성능 유지 | 목적지 하차 후 수락 차단. 승객을 도중에 내리게 하지 않음 |

차단은 수락·승차 직전에 재확인한다. 새 호출 목록을 열어 두었다고 피로 제한을 우회하지 않는다. 수면 후 피로가 100 미만이고 영업시간이 남으면 다시 영업할 수 있다.

## 식사와 수면 이용 흐름

| 단계 | 식당 | 주차장 수면 |
|---|---|---|
| 접근 | 직접 이동·빈차·정차 | 직접 이동·빈차·정차 |
| 호출 처리 | 픽업 전 호출이 있다면 취소 후 이용 | 동일 |
| 확인 | 가격·50초 소비·예상 포만감 | 100초 소비·예상 피로 |
| 확정 | 결제/미납·시간 경과·상태 회복을 한 번 처리 | 시간 경과·회복을 한 번 처리 |
| 완료 | 영업 복귀 또는 마감 | 영업 복귀 또는 마감 |
| 취소 | 돈·시간·상태 변화 없음 | 동일 |

반복 식사는 허용하되 매번 비용·시간을 소비한다. 자동 마감 식비와 자동 포만감 회복은 제거한다. 자금 부족 식사는 기존 생활비 미납 정책을 유지하며 미납도 순수익에서 차감한다. 수면에는 별도 요금을 붙이지 않고 하루 마감 주차비는 한 번만 낸다.

남은 예산이 이용 시간보다 짧으면 해당 행동을 시작하지 못하고 종료를 안내한다. 정확히 같으면 이용 완료 후 정산한다. 탑승 중에는 식사·수면 불가다. 피로 한계·저연료·적자가 겹쳐도 식사 미납과 무료 수면 경로를 제공하며 신규 대출 시스템은 만들지 않는다.

|---|---|

운행 사건의 기존 즉시 저장 저널을 이번 기획 때문에 삭제하거나 회계 저장으로 되돌리지 않는다. 새 하루의 기록은 별도 식별자로 분리하고 이전 완료 결과를 보존한다.

| 반복 | 새 하루 초기값 동일, 완료 결과는 보존, 재시작 취소/저장 실패는 현 상태 유지 |
| 밸런스 | 일반 교통에서 식사1회·휴식0~1회가 자연스러운지 측정. 수치로 강제 정답을 만들지 않음 |

## 구현 근거 (2026-10-21)

`DriverCondition`은 Unity 물리와 독립이며 배고픔 경계를 구간 적분한다. 큰 시간 한 번/0.1초 분할 검사, 피로100 픽업 취소·탑승 유지, 메뉴 정지, 식사/수면 회복·중복 방지·남은 시간 경계·저장 복원을 자동 검사했다. 실제 운전 성능 코드에는 컨디션 입력을 추가하지 않았다. 수동 조작 체감과 하루 식사/수면 횟수의 적절성은 P7-06에서 확인한다.

## 2026-10-22 수면 접근 보완

기존 주차장에 더해 동부 주유소 인근 게임용 휴식 주차구역에서 동일한 무료 수면(100초·피로40 회복)을 제공한다. 사용자 승인에 따른 생활 동선 보완이며 하루1,200초, 컨디션 누적/한계와 조작 독립 규칙은 유지한다. M 전체지도 시설 필터의 ‘휴식 주차’, 미니맵 P 표시 및 F7 안내로 찾아간다. 실제 주차장 위치/운영 정보를 재현한 시설이 아니다.
