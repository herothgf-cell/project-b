# 첫 출발 전 숙소 벽 메모와 차고 택시

## 요청과 변경

- 첫날 영업 준비의 ‘내 목표’는 선택 버튼이 없는 안내 카드였고 첫 출발은 바로 인트로로 이어졌다. `OneDayHUD`, `PersonalRoomHUD`, `BusinessProgress`에서 준비 카드와 첫 출발 버튼을 기존 아침 숙소의 메모 선택으로 연결했다. 메모 하나를 저장하면 준비 화면으로 돌아오고, 영업 시작을 눌러 출차한다. 기존 경력도 준비 화면에서 메모를 바꿀 수 있다.
- 차고에서 물리가 멈춰 있으면 차체 원점에서 생성된 바퀴 네 개의 위치가 첫 주행 프레임까지 갱신되지 않았다. `TaxiController`가 생성과 주차 위치 초기화 때 각 차축 아래에 휠을 놓는다. 주행 중에는 기존 서스펜션 자세를 따른다.
- 빈차등 자동화 때 추가한 `BusinessProgress.RefreshRoofSign`이 지붕 양면의 원래 글자를 준비 중에는 공란, 영업 중에는 빈차·예약·공란으로 덮어썼다. 이 갱신을 제거해 기존 모델의 양면 TAXI 표기를 복원했다.
- 실행본 검사는 `ShiftDevEndProbe`의 첫날 이야기 시나리오에 추가했다. `OneDayTrafficDriveTest`의 첫 운송 시나리오에도 출발 전 메모 선택을 반영했다. 관련 기획은 `docs/content-design/`의 28·32·33번 문서와 개발 체크리스트에 있다.

## 재현

1. `builds/EungyeTaxi/EungyeTaxi.exe` → 은계 싱글 → 새 경력. 준비 화면에서 **목표 고르기** 또는 **내 목표 → 숙소 벽 메모 열기**를 누른다.
2. 차·집·오늘을 버티기 중 하나를 골라 준비 카드에서 확인한다. **영업 시작**을 누르고 인트로 세 번째 컷에서 차고 바퀴를 본다.
3. 출발 후 C로 외부 시점으로 바꿔 지붕의 TAXI를 확인한다. 자동 검사는 `pwsh -File tools/test_father_story_player.ps1`로 실행한다. 실행마다 별도 저장과 캡처 폴더를 사용한다.

## 검증

- 수정 전 빌드에서 새 경력 첫 출발 시 `memo=False parkedWheels=False`를 재현했다. 수정한 별도 통합 실행본에서 두 값 모두 True, 첫날 이야기 위치 제어 38건과 재실행 7건 통과. 빈차·탑승 시점에 지붕 양면에서 TAXI를 확인했다. 첫날에 선택한 목표 변경, 3일차 재선택과 저장 복원을 포함한다.
- Unity 2022.3.62f2 `PrototypeBuild.BuildHybrid` 종료 0. `pwsh -File tools/check_workspace.ps1 -Strict` 필수 입력 문제 0. 자동 물리 주행과 수동 전체 캠페인은 이번에 수행하지 않았다.
- 첫 숨김 창에서 얻은 초기 캡처가 검은색이라 검증용 해상도를 1280×720으로 다시 설정하고 화면을 재검사한다.
