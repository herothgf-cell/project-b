# 2026-11-06 미응답 감점의 음수 입력 통일

## 요구사항·구현
사용자는 미응답 감점도 다른 효과와 같이 `-2` 형태로 입력하기를 요청했다. 양수 감점량을 받던 `request.Quiet.unanswered`의 관리창 입력·기본값·범위·복원·연결 요약을 `-100~0점`의 M 변화량으로 표시했다. `-2`는 M 2점 감점, `0`은 감점 없음이다. 이미 부호 있는 공감/면접/지역 대화의 미응답 S 증감은 그대로다.

기존 프로필과 실제 게임은 양수 감점량을 사용하므로 화면 입력 경계에서만 부호를 변환한다. 저장 형식·schema/hash 규칙·게임 소비 코드·기존 감점 의미를 바꾸지 않는다. 기본값/저장값 복원에도 같은 변환을 쓰며, 잘못된 양수 입력은 범위/프로필 검증에서 거부된다. 일반 항목 상세 화면도 같은 입력 방식을 사용한다.

## 변경 파일
- `tools/content-editor/public/app.js`: 부호 있는 표시/입력 변환, 범위·기본값·복원·연결 표시 일치.
- `tools/content-editor/public/content-model.js`: 적용 시점·영향 대상과 -2/0 예시 안내.
- `tests/content-editor/context-ui.test.mjs`: 실제 카탈로그 입력/재열기/복원/0·-100·잘못된 양수/기존 S 음수 유지 회귀2개.
- `tests/ContentTuningTests.cs`: 실제 요청 클래스의 2점 감점·한 번 적용·0점·잘못된 저장값 거부·공감 -2 유지 검사.
- 사용 안내·체크리스트·LATEST와 이번 기록.

## 검증·결과
- 먼저 신규 화면 검사2개가 기존 `5` 표시 때문에 실패하는 것을 확인한 뒤 수정했다.
- Node 관리창·프로필·서버·manifest 전체58개/실패0/exit0.
- 실제 C# 콘텐츠/요청 모델649개 통과, Unicode/이관 C#·Node hash 일치/exit0.
- 실제 관리창에서 -5 기본값·-100~0 범위·-2 및0 입력의 API 검증 통과를 확인했다. 검사 입력은 -5로 되돌리고 저장/게임 적용을 누르지 않았다. 기존 탭과 사용자가 불러둔 프로필은 보존하고 수정판을 새 탭에 열었다. 화면 증거: `artifacts/signed-unanswered-input.png`.
- 게임 실행 파일·배포 manifest·사용자 active/sample 프로필은 변경하지 않는다. 최종 hash/manifest 검증은 아래 영수증을 따른다.

## 실행·남은 항목
실행 기준은 `C:/git/project-b`(이 PC 로컬 환경)의 `설정 관리.cmd`다. 승객 요청 → 조용한 운행 → 답하지 않았을 때에서 확인한다. 프로필을 저장하고 게임에 적용하면 기존과 같이 다음 새 세션부터 사용한다.

화면 입력 변경이므로 Unity 재빌드/새 물리 주행·수동 전체 캠페인·다른PC LAN 검사는 수행하지 않는다. 기존 은계 싱글/A2 PVP·LANv9 `builds/EungyeTaxi/EungyeTaxi.exe`, 출하140파일116,826,789바이트를 유지한다. 필수 지도 입력/ZIP·OSM·실행 폴더를 바꾸지 않으며 외부 관리 worktree와 다른 작업의 미커밋 자료를 보존한다.

최종 영수증: 통합 manifest VerifyOnly exit0(사용자 active 포함141파일/출하140파일); 사용자 active/sample·배포 manifest·실행 Assembly4파일의 시작/종료 SHA256 동일. 이번 검사는 기존 Player/전체 캠페인 검증을 새로 수행한 것으로 표시하지 않는다.
