# 2026-11-24 은계 제한속도 바탕 (도로별 제한속도, 과속 판정, 속도계 표시, 일반 차량 속도)

## 요구

[후보 4종 상세 기획](2026-11-24-next-candidates-detail-design.md) 2.1의 "제한속도 바탕"을 구현한다. 사용자가 조사 뒤 "확인 안 된 일반 도로는 50을 게임 추정으로 표시해 넣고 구현을 시작"하기로 정했다(2026-11-24). 조사 근거는 [조사 기록](2026-11-24-speed-limit-camera-survey.md)에 있다.

범위는 은계 싱글이다. PvP와 다른 지도는 바꾸지 않았다(LAN v25 그대로). 지도 문서와 필수 지도 입력은 건드리지 않았다.

## 구현

| 내용 | 동작 |
|---|---|
| 제한속도 자료 | 새 파일 `config/maps/eungye-speed-limits.json`(실행본용 사본 `Assets/Resources/eungye-speed-limits.json`). 확인된 도로 2개(수인로 60, 대은로 50)와 어린이보호구역 지점 13곳(단속 카메라 12, 로드뷰 1, 모두 30)을 근거와 함께 담았다. |
| 조회 순서 | 지도 편집기의 제한속도 표지 → 보호구역 지점 반경 안이면 30 → 파일의 도로 이름 → 이름이 "번길"로 끝나면 번길 값 → 일반 도로 값. 이름 없는 차로는 일반 도로 값이다. |
| 게임 추정값 | 일반 도로 50, 번길 30, 보호구역 지점에서 반경 60m. 설정 툴에서 바꾼다. |
| 속도계 표시 | 속도계(1인칭 디지털, 3인칭 다이얼)에 붉은 테두리의 원형 제한속도 표시. 제한을 넘으면 안쪽이 깜빡인다. |
| 과속 판정 | 제한 + 10km/h를 3초 넘기면 운전 점수 −5, 20km/h 넘게 초과한 상태면 −10. 한 번 기록한 뒤 20초 동안은 다시 기록하지 않는다. 손님을 태우고 큰 초과로 기록되면 손님 만족 −3과 "과속 · 손님이 불안해해요". |
| 일반 차량 | 순항 속도가 "시속 약 47km 고정"에서 "그 차로 제한속도의 90%"로 바뀐다. 50 도로 45, 수인로 54, 보호구역·번길 27km/h. |
| 끄기 | `law.speed.enabled`를 0으로 두면 이전 동작(제한속도 없음, 순항 13m/s)으로 돌아간다. |

지도 편집기 표지로 걸린 과속(다른 지도, 사용자 지도)은 이전 수치(여유 3km/h, 2초, 5점) 그대로다.

퇴근 후 드라이브 중에는 속도계 표시는 나오지만 과속을 기록하지 않는다(드라이브는 법규 기록을 남기지 않는 기존 규칙).

### 정한 것

- **지도 문서를 바꾸지 않았다.** 보호구역은 지도 문서의 구간 표지 대신 "확인된 지점 + 반경"으로 넣었다. 실제 구간의 시작과 끝을 확인하지 못했기 때문이고, 지도 입력 해시와 지도 ZIP을 다시 만들 필요가 없다. 구간을 조사하면 지도 편집기 표지로 옮길 수 있다(표지가 우선 적용된다).
- **표지판 모형은 세우지 않았다.** 위치를 확인한 표지가 로드뷰 한두 곳뿐이라 화면 표시를 주 수단으로 했다.
- **기본값을 켠 상태(1)로 넣었다.** 상세 기획은 시험판을 꺼진 채 넣는다고 적었으나, 직접 확인하려면 켜져 있어야 해서 이전 작업들과 같이 켰다. 운전 점수와 교통 흐름이 달라지므로 불편하면 끄면 된다.
- 단속 카메라(과태료)는 이번에 넣지 않았다. 상세 기획 순서의 8번이다.

### 기존 플레이에 주는 영향

- 지금까지 은계에서는 과속이 판정되지 않았다. 이제 일반 도로에서 시속 60km를 3초 넘기면 감점된다.
- 일반 차량이 일반 도로에서 약간 느려지고(47 → 45), 수인로에서 빨라지며(47 → 54), 학교 앞과 번길에서 크게 느려진다(47 → 27). 호출 소요 시간과 급행 미션 달성률이 달라질 수 있다. 재지 않았다.
- 길안내의 예상 시간은 바꾸지 않았다(편집기 표지만 반영하는 기존 계산 그대로). 번길이 실제보다 빠른 길로 계산된다.

## 설정 (설정 툴 "법규")

| id | 기본값 | 뜻 |
|---|---:|---|
| `law.speed.enabled` | 1 | 은계 제한속도 켜기 |
| `law.speed.defaultKmh` | 50 | 일반 도로(게임 추정) |
| `law.speed.alleyKmh` | 30 | 번길(게임 추정) |
| `law.speed.zoneRadius` | 60m | 보호구역 지점의 적용 반경(게임 추정) |
| `law.speed.toleranceKmh` | 10 | 과속 판정 여유 |
| `law.speed.seconds` | 3초 | 과속 판정 지속 시간 |
| `law.speed.repeatSeconds` | 20초 | 다시 기록하는 간격 |
| `law.speed.penalty` / `heavyOverKmh` / `heavyPenalty` | 5점 / 20 / 10점 | 감점과 큰 초과 기준 |
| `law.speed.passengerPenalty` | 3점 | 큰 초과 때 손님 만족 감점 |
| `law.speed.trafficPercent` | 90% | 일반 차량의 제한속도 대비 순항 |

확인된 값(수인로 60, 대은로 50, 보호구역 30과 그 위치)은 설정 툴이 아니라 자료 파일에 있다.

### 검사 중 찾아 고친 것

- **이름 없는 차로가 50으로 읽혔다.** 지도의 차로 2,128개 가운데 670개(좌회전·유턴 대기 차로, 교차로 연결 차로)에 도로 이름이 없어, 수인로 한가운데의 대기 차로가 일반 도로 값 50으로 나왔다. 이름 없는 차로는 "들어오는 쪽으로 이어진 도로"의 이름을 따르고, 없으면 "나가는 쪽 도로"를 따르도록 고쳤다(`TrafficSystem.LimitRoadName`).
- **설정 툴 시험 4건이 실패했다.** 새 `law.speed.*` 항목이 "옛 프로필에 없어도 되는 은계 싱글 항목" 목록에 없어, 예전 프로필을 옮기는 시험이 "누락된 ID"로 실패했다. 설정 툴(`tools/content-editor/profile.mjs`)과 실행본(`ContentTuning.cs`)의 목록에 `law.speed.`를 추가했다. 고친 뒤 109건 통과하고, 실행본을 다시 빌드해 검사 4종을 다시 돌렸다.
- 검사 자체의 문제 세 건(차로에서 5m 떨어진 좌표, 차로와 어긋난 주행 방향, 강제 주행이 교차로를 지나며 생긴 신호 기록을 과속으로 센 것)은 검사를 고쳤다. 강제 주행 중 신호 위반 1건이 따로 기록됐는데 과속 판정과는 무관하다.

### 검사의 한계

- 속도는 검사가 차체에 직접 넣었다. 사람이 가속 페달로 넘는 상황, 손님을 태운 상태의 손님 반응, 20km/h 넘는 큰 초과(10점)는 실행본에서 보지 않았다(큰 초과의 점수 계산은 규칙 검사에서 확인).
- 일반 차량은 25초 시점의 한 장면만 봤다. 수인로에서 실제로 54km/h까지 오르는지, 학교 앞에서 줄이 길어지는지, 교차로 교착이 늘어나는지는 보지 않았다.
- PvP 실행 검사는 다시 돌리지 않았다. PvP와 공용인 `TrafficCar`·`TrafficSystem`·`DrivingLaw`의 새 동작은 모두 "은계 싱글일 때만" 조건 뒤에 있다.

## 미검증 / 남은 것

- **사람 플레이를 하지 않았다.** 속도계 표시가 눈에 들어오는지, 여유 10km/h와 3초가 답답하거나 느슨하지 않은지, 학교 앞에서 일반 차량이 27km/h로 가는 것이 답답하지 않은지는 직접 봐야 한다.
- 호출 소요 시간, 급행·초록불 미션 달성률, 하루 수입에 주는 영향을 재지 않았다.
- 보호구역 반경 60m가 교차하는 다른 도로까지 30으로 만드는 곳이 있는지 지점별로 보지 않았다.
- 카메라가 없는 일반 도로의 실제 제한속도, 보호구역의 실제 시작·끝.
- 길안내 예상 시간에 제한속도 반영.
