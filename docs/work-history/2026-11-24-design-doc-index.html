요구

  • 기획서 전체를 한눈에 보는 목록을 만든다. 예시 형식은 다른 저장소의 추가 기획서 목록(index.html: 문서 목록 → 구현 현황 → 검토 중인 제안 → 개선점 목록 → 문서 사이의 관계 → 미결 결정 방식 → 수정 기록)을 따른다.
  • 내용이 많으므로 상위 카테고리 밑에 하위 카테고리로 나누고, 문서·장 단위로 링크한다.
  • 항목마다 구현(배포 실행본 반영 여부 포함), 미결(결정 대기·승인 전·설계안), 개선 필요(사람 플레이 미확인, 알려진 실패, 피드백 대기)를 정리하고 근거 기록을 붙인다.
  • docs/content-design/README.md와 docs/CURRENT-STATE.md에서 링크한다.

실제 구현

  • 새 문서 기획서 목록과 현황. 이름은 예시의 index를 따르되, 이 저장소의 대문자 문서 이름(README.md, LATEST.md)에 맞춰 INDEX.md로 했다. 형식은 이 저장소 기획 문서와 같은 Markdown이다.
  • 구성: 상태 표기 → 문서 목록(00~09·PvP·보관) → 기획 항목별 현황(A 전체·이야기, B 운전 3묶음, C 손님 4묶음, D 생활·차량 4묶음, E 화면, F 하루·경력, G 다음 단계 후보 3묶음, H PvP, I 색인·보관·제안서) → 08 진행 순서 → 결정 대기 9건 → 개선점 목록 12건 → 문서 사이의 관계 → 결정 방식 → 수정 기록.
  • 상태의 근거: LATEST.md, CURRENT-STATE.md, 개발 체크리스트, 08과 각 담당 문서의 구현 표시, 2026-11-19~24 작업 이력(상세 기획, 확인 목록의 결정 기록, 자리 비움 체크리스트, 돌발 1차의 미검증 항목).
  • 같은 시각 다른 작업이 미커밋으로 고치던 것(직접 플레이 피드백 3차, 유혹)은 "진행 중"으로 적었다. 그 작업이 커밋되면 이 문서의 해당 줄을 "구현·배포"로 바꿔야 한다.
  • README의 문서 목록 안내 문장과 CURRENT-STATE의 첫 줄 링크 묶음에 링크를 하나씩 더했다.
