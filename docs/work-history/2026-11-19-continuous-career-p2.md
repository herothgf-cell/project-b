# P2 계속 영업 모드

기획28과 준비·마감 시안에 따라 3일 캠페인의 같은 슬롯에서 계속 영업할 수 있게 한다. P1 배포 `ba19767` 기준으로 작업했다.

- 3일차 정산의 **계속하기**로 4일차가 열린다. 현금·장부·운전·승객 기록, 차량·색·장식, 방 소품을 유지하고 완료 방의 읽기 전용 잠금을 해제한다. 기존 3일 도입과 완료 기록도 유지한다.
- **새 경력**은 새 파일을 만들고 활성 슬롯을 가리킨다. 일시정지의 **저장된 경력**에서 같은 저장 폴더에 있는 이전 슬롯을 다시 고를 수 있다. 파일 선택은 슬롯 이름 형식과 존재 여부를 검사한다.
- 차량 후보 2종·숙소·목표 없음 중 준비 화면에서 임시 선택한다. 차는 판매가를 빼기 전 후보 가격, 숙소는 편집 가능한 `home.upgrade.price` 160,000원이다. 넓은 호실 금액은 기획22의 임시 R 10,000원 × 16이다. 현재 있는 차량 목표는 보유 여부를 표시한다. 실제 호실 이전과 벽 메모·달성 연출은 후속 범위다.
- 오늘과 이전 일차의 현금으로 진척을 비교하고, 최근 3일 순수익 중앙값으로 예상 영업일을 표시한다. 긍정적인 수익 자료가 없으면 일수 예측을 생략한다. 마감 기록에는 완료 운송 수, 기록된 운송 경로 중 최장 거리, 무위반 연속일을 표시한다. 이전 저장에 경로 거리 필드가 없으면 당시 최장 거리는 표시하지 않는다.
- 캠페인 외부 형식 4에 계속 영업과 목표를 보존한다. 기존 2·3 버전과 P1 계정 스냅숏을 읽으며, 날짜 상한은 3일 도입에만 적용한다.

주요 변경은 `BusinessProgress`·`CampaignSaveLocation`·`CampaignAccount`·`EconomyLedger` 저장과 장부, 준비/정산/HUD 및 차량 UI, 콘텐츠 목표 가격, 테스트·기획·체크리스트다.

## 검증

- `pwsh -File tools/test_content_tuning.ps1` 873건 및 C#/Node 프로필 해시 일치. 추가 모델은 3일 제한, 최근 3일 중앙값, 소유 유지, 4·5일 상태와 저장 복원을 검증한다.
- `pwsh -File tools/test_personal_room.ps1` 17건, `pwsh -File tools/test_vehicle_garage.ps1` 55건. 생성 설정 `node tools/content-editor/choice-catalog.mjs . --verify` 확인.
- `tools/test_personal_room_player.ps1` 43건, `tools/test_vehicle_garage_player.ps1` 64건(차고·재실행·PvP 외형). 같은 기능의 오른쪽 목표 카드 배치 보완 전 빌드에서 실행했다.
- `ApprovedEungyeRoads.VerifyAndBuild` 종료 0, 은계 r47의 39곳·1,482경로, r14~r46 저장 이관 1,063건. 오른쪽 목표 카드 배치를 포함한 최종 `PrototypeBuild.BuildHybrid` 종료 0. 지도 입력 변경 없음.
- 콘텐츠 편집기 `node --test tests/content-editor/*.test.mjs` 103건.
- 최종 실행본의 `pwsh -File tools/test_career_player.ps1` 16+5건. 위치 제어로 3일을 마감해 4·5일차를 진행한 뒤 다른 프로세스에서 다시 열었다. 새 경력 슬롯 생성 전에 기록한 기존 파일의 내용이 그대로인지 확인했다. 기존 r47 Player의 운송 중 테스트 저장도 `-liveReloadTest` 23건으로 복원했다. 자동 물리 주행이나 수동 플레이는 수행하지 않았다.
- 은계 r47 필수 입력 Strict 문제 0. 배포 크기·SHA256은 통합 manifest에서 확인한다.

실행은 통합 실행본에서 은계 싱글을 선택한다. 3일차 마감의 **계속하기**와 **새 경력**, 일시정지의 **저장된 경력**으로 재현한다. 사람 운전의 지속 동기와 목표 밸런스는 별도다. 다음 개발은 P3 차내 조작 3종이다.
