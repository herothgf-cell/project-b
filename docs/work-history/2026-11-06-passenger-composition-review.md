## 검증과 한계

소스/문서 열람 명령 exit0. 문서 diff·상대 링크/도식 개수 검사는 아래 최종 확인 결과를 따른다. 코드 검토이며 위치 제어·자동 물리 주행·수동 플레이·전체 캠페인 검사가 아니다. Mermaid는 텍스트 구조로 제공하며 PNG 렌더 수용 검사는 하지 않았다. 현재 실행 `builds/EungyeTaxi/EungyeTaxi.exe`, 은계 싱글/A2 PVP·LANv11, `PrototypeBuild.BuildHybrid`, 실행본0bba941 유지. 필수 로컬 입력은 직전 Strict exit0/issues0 이력 인용, 이번 지도 재검사 없음.

기존 미추적 `docs/mindmaps/`, 라이선스 문서/증거 및 과거 작업 이력/도구는 수정·스테이징하지 않는다. 새 요구가 없는 현행 규칙/체크리스트의 구현 완료 표시는 바꾸지 않는다.

## 재현·후속

최종 문서 검사: PowerShell로 Mermaid3개·검토 문서 상대 링크 존재 확인 PASS, `git diff --check` exit0(기존 CRLF 정규화 안내만 발생). 최초 Python 검사는 WindowsApps 실행 별칭 접근 오류로 실행되지 않아 PowerShell 검사로 대체했다. 런타임 테스트 실패로 해석하지 않는다.

검토 문서를 Markdown/Mermaid 지원 뷰어로 열고, 근거 절의 소스와 비교한다. 새 승객 프리셋 추가와 신규 행동 개발의 경계를 먼저 합의한 뒤 제한된 조합부터 구현하는 것을 권장한다. 이번에 구현 승인이나 밸런스 변경을 확정하지 않았다.
