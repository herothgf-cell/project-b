# 2026-11-24 0단계: 선택형 미션 4종 구현 상태 확인

## 요구

자리 비움 일괄 작업(2차)의 0단계. [08](../content-design/08-fun-improvements.md) 3장 "선택형 미션" 4종이 구현됐는지 코드와 작업 이력으로 확인하고, 안 됐거나 중간에 멈췄으면 먼저 끝낸다.

## 확인 결과: 구현 완료, 추가 작업 없음

| 조건 | 근거 |
|---|---|
| 호출판에서 아이콘·추가금이 미리 보이는 선택형 | `PassengerJobsMissions.MissionCardLine`: 카드에 "[미션] 이름 · 성공 시 +N원 · 목표". 그 호출을 수락하는 것이 선택 |
| 실패해도 기본 운임 유지 | `SettleMission`은 `PassengerReward`의 운임 필드를 바꾸지 않는다. 실행본 검사에서 실패 운송의 실수령 = 기본 운임+보너스−미터기 감액을 확인 |
| 3건 중 1건 빈도 | `ApplyMissions`: 호출판마다 1건(`mission.boardChance` 100%) |
| 추가금 약정액 20~30%, 영수증 별도 줄 | 급행 30%·초록불 25%·커피 20%·칼정차 20%(100원 올림). `RideReceiptSummary.MissionRow`, 장부 `mission:<운송 id>` |
| 4종 | 급행(정차 제외 주행 시간), 초록불(신호 3곳 연속 무정차), 커피(급가감속 0), 칼정차(30cm) |

- 구현 커밋: `0018c561`(소스), `f5ceba39`(결과 기록). 기록: [선택형 미션](2026-11-23-optional-missions.md).
- 오늘 시설·효과음 브랜치를 병합한 실행본에서 다시 검사했다: `-contentTest -missionCheck` → `MISSION_PLAYER_OK checks=72`.
- 지각 0원 규칙은 그대로이고, 미션은 기한 안 도착일 때만 성공한다.

## 함께 처리한 것

- 사용자 요청("합치고 푸시")으로 `storefront-drive-audio`(김밥집·카페 건물 안 매장, 세단 엔진음) 2커밋을 main에 병합하고 다시 빌드했다.
  - 병합 커밋 `7e45f44a`, 실행본 커밋 포함, 충돌 없음.
  - 실행본 검사: 매장 40, 차내·소리 35, 미션 72, 팁 25, 빈 시간 14, 호출판 116, 화면 102건 통과.
- **푸시는 하지 않았다.** 이후 "push는 하지 마"라는 지시가 와서, 이 병합도 로컬 커밋으로만 남겼다. `origin/main`보다 앞선 커밋 중 병합분의 푸시 여부는 사용자가 결정한다.
