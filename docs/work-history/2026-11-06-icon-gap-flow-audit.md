# 시안 아이콘 차이·운송 안내 흐름 점검

## 범위와 근거
사용자 제공5장 시안과 현재655a34a 소스/직전 실제 캡처를 비교했다. 이번은 점검이며 게임 코드/실행본/지도/차량/저장 변경과 신규 Player 실행은 없다. 이전 UI160검사 통과를 이번 신규 수동 흐름 검사로 세지 않는다.

## 아이콘 차이
현재 HudGlyph는96픽셀 캐시지만 주로 단색2단위 윤곽선이다. 시안은 채워진 실루엣, 동전/웃는 얼굴/방패 같은 의미별 색 배지, 큰 아이콘, 제한적인 하이라이트/그림자를 쓴다. 해상도 개선만으로 시안 톤에 도달하지 않았다.

1. HUD 잔액: 현재 지갑 윤곽. 시안의 금색 동전 배지 방향으로 변경 권장.
2. 만족도/안전: 현재 윤곽 얼굴/방패. 채워진 초록 얼굴/방패와 진한 내부 기호로 변경 권장.
3. 연료/내구도/시설: 펌프/렌치/차량의 굵은 채움 형태를 공유. 경고에는 빨강/주황 원형 배지, 평상시는 의미별 색 사용.
4. 메뉴/지도 도구: 작은 윤곽선 위주에서 굵은 단색 실루엣으로 전환. 주행 정보보다 높은 강조는 피한다.
5. 시간/방향: 굵은 시계 테두리/바늘, 넓은 화살표 면과 충분한 크기. 기능과 신호 판정은 유지.
6. 기존 시안의 새 업적/레벨/카메라 등 미구현 기능은 아이콘을 맞추기 위해 추가하지 않는다.

## 호출→승차→요청→하차→정산
| 단계 | 현재 코드 확인 | 보완할 안내 |
|---|---|---|
| 호출 | MapDestinationUI에서 선택/수락 분리, 예상 운임과 거절 사유 표시 | 수락 직후 승차 장소와 다음 행동을 같은 위치에 요약 |
| 승차 이동 | CockpitUI가 픽업도 목적지로 표기, TaxiStatus는 예약 | 승차하러 가는 단계와 탑승후 목적지 이동을 명시적으로 구분 |
| 승차 | StopArrivalGuidance가 위치/방향/속도/공간/준비 조건을 읽고 F승차 안내 | 실제 방향·속도 부적합/준비대기를 포함한 사람 연속 주행 수용 필요 |
| 요청 | PassengerDialogueUI의 답변/단축키/효과 분리 및 스크롤 | 응답 후 진행/완료/실패가 얼마나 눈에 띄는지 추가 실행 점검 필요 |
| 하차 | 같은 실제 정차 조건의 F하차, 경유/용무/기상/짐 대기 분기 존재 | 대기 상태와 하차 가능 상태를 일관된 행동 제목으로 유지 |
| 정산 | 실제 결과 한 번 표시, 닫기는 재지급하지 않음, 실수령/계속영업 | 아래 시설 찾기 동작과 초상 연속성 보완 필요 |

### 확인된 구체적 불일치
- RideCompletionPanel의 `시설 찾기`는 `Close(); session.services.Toggle()`을 호출한다. Toggle은 현재 정차 위치의 F7 시설 메뉴이며, 일반 하차 장소에서는 시설 밖 안내를 하거나 조건에 따라 수리 비교로 간다. 사용자가 기대하는 시설 목록/검색 진입과 다르다. 생활거점 또는 기존 지도 시설 비교로 연결하는 것을 우선 권장한다.
- PassengerDialogueUI 초상은 제목 문자열, RideCompletionPanel 초상은 출발+도착 문자열로 선택한다. 같은 승객을 일관되게 표현하는 계약이 없어 얼굴이 달라질 수 있다. 기존 승객 식별자를 표시 전용으로 공유하는 보완이 필요하다.
- 픽업 상태의 예약/목적지 조합은 승차 장소인지 최종 목적지인지 헷갈릴 수 있다. `승차 장소`/`도착지`로 구분하고 수락→승차→운송 전환 문구를 대조해야 한다.

## 검증·다음 작업
소스 대조 완료, 이번 새 빌드/자동물리/수동연속운행/LAN 검사는 미실시. 아이콘은 채움형+의미별 배지로 다시 맞추는 것이 우선이다. 이어 시설찾기 연결·승객초상 일관성·픽업/운송 제목을 수정하고, 일반 운송과 준비/경유/기상/하차대기 분기의 실제 화면을 연결해 검증한다. 맵/차량 외형은 마지막 별도 검토다.
