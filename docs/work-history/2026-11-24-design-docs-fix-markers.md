# 2026-11-24 기획서 HTML에 개선 필요 표시 (문서만)

## 요구

기획 문서 내용에 개선 필요 항목을 표시한다(사용자 요청). 지금까지는 [기획서 목록](../content-design/INDEX.md)에서만 상태를 볼 수 있었다.

## 판단

md 본문에 직접 쓰지 않고, HTML 생성기가 INDEX를 읽어 표시하게 했다.

- 상태의 기준을 INDEX 하나로 둔다. 본문에 따로 적으면 INDEX와 어긋나기 쉽다.
- 같은 폴더의 다른 작업이 00~08 md를 지금도 고치고 있어 본문 편집은 충돌 위험이 크다.

따라서 md(GitHub 화면)에는 표시가 없고 `.html`에만 나온다. INDEX 상태를 고친 뒤 생성기를 다시 돌리면 표시도 따라 바뀐다.

## 실제 구현

`tools/render_design_docs.py`

- INDEX의 `항목 | 기획 위치 | 상태 | 근거·남은 것` 표에서 상태가 개선 필요인 줄을 모은다. 판정은 INDEX의 "개선 필요" 필터와 같다(`개선 필요`·`미확인`·`실패` 포함).
- 기획 위치 칸의 링크가 가리키는 문서·앵커를 찾아, 그 장 제목 옆에 빨간 "개선 필요" 배지를, 제목 아래에 상자를 넣는다. 상자에는 항목 이름, INDEX의 상태 문구(남은 이유), 근거 링크가 있다. 한 장에 여러 건이면 한 상자로 묶는다.
- `<a id="s33">` 같은 앵커는 바로 다음 제목에 붙인다. 앵커 없이 문서 전체를 가리키는 줄은 본문 맨 앞 "문서 전체" 상자로 넣는다.
- 머리말 상자에 "개선 필요 N건"과 해당 장 바로가기를, 목차에 "● 개선 필요"를 단다.
- 위치가 "—"이거나 작업 이력의 상세 기획만 가리키는 줄(예: 구역 교통 검사, 사람 사고 감경·돌발 2차·골목 주차·단속 카메라)은 붙일 기획서 장이 없어 INDEX에만 남는다.

## 검증

- `python tools/render_design_docs.py`: 44개 생성, 개선 필요 38건을 11개 문서에 표시(00 4, 01 4, 02 2, 03 1, 04 5, 05 2, 06 3, 07 2, 08 13, pvp/28 1, pvp/30 1). pvp 2건은 앵커가 없어 문서 전체 상자로 들어갔다.
- 생성된 HTML 전체 링크·이미지 2,701개 중 없는 파일 0건, 없는 앵커 0건(스크립트 대조).
- 앱 내 브라우저로 08을 열어 머리말 요약(13건)과 "조향 프리셋" 장의 배지·상자를 확인했다.

## 미검증 / 남은 것

- 08 외 문서는 화면으로 보지 않았다(자동 검사만).
- 작업 이력 상세 기획만 가리키는 개선 필요 항목은 기획서 본문에 표시되지 않는다. 해당 항목의 기획 위치가 08 5장 등으로 옮겨지면 자동으로 붙는다.

## 실행·재현

- `python tools/render_design_docs.py` (또는 `--rev HEAD`). 출력 끝에 문서별 개선 필요 건수가 찍힌다.
- 확인: `docs/content-design/08-fun-improvements.html`.
