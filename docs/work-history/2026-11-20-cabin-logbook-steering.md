# 2026-11-20 은계 차내 조작, 기사 수첩과 중속 조향

## 요청과 구현

은계 싱글 운전 HUD에 첫 운송에서 발견한 기사 수첩을 노출했다. 수첩을 열면 시간이 멈추고, 닫기나 Esc로 돌아오면 출발 당시의 주행 상태를 이어 간다. 숙소와 일시정지 메뉴로 들어간 경우에는 원래 화면으로 돌아간다.

빈차등 조작과 휴무에 따른 호출 차단을 제거했다. 지붕 글자는 영업 대기 때 빈차, 승차지로 갈 때 예약, 승객 운송 중 공란이다. 첫 출차에서 출구 안내와 호출이 바로 열린다.

K로 운전석 옆유리를 내리고 올린다. 1인칭에서 유리가 움직이고, 창문을 열면 22°C 외기와 열을 교환한다. [와 ] 또는 화면의 −/+로 희망 온도를 18~28°C 범위에서 1°C씩 설정한다. 처음에는 22°C다. 게임이 실내·설정 온도를 비교해 냉방과 난방을 선택한다. 실내 온도가 설정값에 도달하는 데 시간이 걸린다. 옛 저장의 따뜻/시원/끔을 각각 24/20/22°C로 읽는다.

## 승객

활성 콘텐츠 설정의 ‘차내 온도에 민감한 손님’은 따뜻하게 또는 시원하게 해 달라고 한다. 응대한 뒤 선호에 맞는 실제 실내 상태를 12초 유지하면 만족도 +4, 불편이 18초 지속되면 −2다. 창문 조작을 요구하는 전용 승객은 현재 설정에 없다. 음악 요청은 대화로 응대한다.

## 조향 진단과 제안

기본 민감도 100%, 기본 차량 계수 1, H 보조를 끈 상태에서 좌우 최대 앞바퀴 중심각을 계산했다. 속도별 값은 현재 C# 메서드를 직접 호출한 결과다. 반경은 축거 2.6m로 계산한 기하학적 값이다.

| 속도(km/h) | 최대 중심각 | 이론 반경 | 정면 주행에서 추가 회전 가속도(rad/s²) |
|---|---:|---:|---:|
| 35 | 17.00° | 8.5m | 1.81 |
| 40 | 13.49° | 10.8m | 0.69 |
| 45 | 9.73° | 15.2m | 0.46 |
| 50 | 4.55° | 32.7m | 0.29 |
| 55 | 3.41° | 43.7m | 0.13 |
| 60 | 2.68° | 55.6m | 0.00 |

수동 도심 곡선은 35~50km/h에서 17°부터 속도 제곱에 반비례하는 제한각까지 떨어진다. 추가 조향 여유가 47.5km/h에 최대여도 45→50km/h에서 목표각은 53% 줄어든다. 차체 회전 보조도 약해져 60km/h에서 끝난다. 짧은 키 입력에서는 반응 속도 제한도 겹친다. 기본값에서 0→최대 입력 시간은 40km/h 약 0.12초, 50km/h 약 0.14초다. 물리 모델은 좌우 대칭이며 반대 방향으로 꺾을 때는 별도 가속 계수도 적용한다. H를 켠 상태의 좌우 입력은 차로 변경이다.

현재 소스로 Unity 편집기에서 `CurveSteeringChecks.Run`을 재실행해 다음 수치를 확인했다. 평지에서 전진 속도를 고정하고 65% 입력을 4초 주었을 때 방향 변화는 45km/h 94.39°, 50km/h 48.75°였다. 현재 버전의 수동 체감과는 구분한다. [과거 물리 조건과 기록](2026-11-12-curve-steering.md).

**제안**은 먼저 40~60km/h의 수동 최대 조향각 곡선만 완만하게 펴서 같은 조건으로 A/B 주행하는 것이다. 예를 들어 50km/h 6.5°를 첫 후보로 두고 40·45·55·60km/h에 부드럽게 연결한다. 저속 주차와 좁은 직각 교차로의 감속 특성을 보존한다. 좌우 양방향 0.1초 탭, 65% 유지, 완만한 커브와 차선 변경에서 첫 0.5초의 방향 변화·횡이동량·입력 해제 뒤 흔들림을 비교한다. 긴 입력은 개선됐는데 짧은 입력만 둔할 때 반응 속도를 별도로 조절한다. 단일 변경 효과와 수동 키보드·패드 체감을 확인한 뒤 공유 물리를 쓰는 PvP 예측도 확인한다. 이번 배포에는 조향 수치 조정을 포함하지 않았다.

## 재현

1. 은계 싱글의 새 경력으로 출차 후 M 지도에서 첫 호출을 확인한다.
2. K로 창문을 조작하고 [와 ]로 온도를 변경한다. J는 기존 미터기다. 온도 민감 손님의 응대 뒤 따뜻/시원 요청에 맞춰 실내 상태를 유지한다.
3. 첫 운송을 마치고 영수증을 닫아 운전 점수 옆 기사 수첩을 연다. 수첩을 닫고 운전을 이어 간다.
4. 모델은 `pwsh -File tools/test_content_tuning.ps1`, 실제 Player 검사는 `tools/test_cabin_controls_player.ps1`, `tools/test_father_story_player.ps1`, `tools/test_first_fare_player.ps1`을 사용한다.
5. 수동 목표각은 PowerShell에서 `Add-Type -Path unity/EungyeTaxi/Assets/Scripts/DriveMath.cs` 후 `[DriveMath]::ManualSteerAngle(50)` 등으로 재현한다.

## 검증 기록

- 변경 전 모델 검사에서 옛 휴무 상태가 새 호출을 막는 사례가 실패했다. 변경 후 `pwsh -File tools/test_content_tuning.ps1` 종료 0, 최종 누적 1,471개 검사와 C#/Node 프로필·이관 해시 대조 통과.
- `pwsh -File tools/check_workspace.ps1 -Strict` 입력 문제 0. 필수 지도, 사용자 설정 프로필, 기존 작업 씬과 패키지 설정을 보존했다. 기존 씬 SHA256은 `f3b93b449d1739aa386eaf83505f644d669eb6a025453ae4967c7b5a8c2d2138`.
- Unity 2022.3.62f2 빌드는 기존 작업 씬을 보호하도록 `artifacts/cabin-nov20` 아래에 별도 프로젝트를 구성해 수행했다. 최초 시도는 저장소 루트 검사에서 중단됐다. 사본에 저장소를 초기화한 뒤 두 번째 빌드가 생성됐으나 콘텐츠 원본 대조에 필요한 폴더가 빠져 최종 후보에서 제외했다. 세 번째 시도에 원본 콘텐츠를 복사해 `CONTENT_TUNING_BUILD_COPIES_OK`를 확인했다.
- 최종 `PrototypeBuild.BuildHybrid` 종료 0. 위치 제어 Player에서 차내 23검사, 첫 경력 이야기 26검사, 같은 슬롯 재시작 7검사 모두 통과했다. 옛 휴무+냉방 스냅샷을 실제 복원 경로로 읽어 20°C와 첫 호출 복구를 확인했다. 온도 오답 감점·조정 후 보상·저장, 첫 운송 뒤 수첩 열기와 주행 재개도 통과했다.
- 일반 교통 자동 물리 주행은 2,588m, 1회 운송 수입 6,510원, 첫날 순수입 4,510원이었다. 숙소 복귀·정산 저장, 충돌 0·적신호 위반 0, `RESULT success=True`와 종료 0. 재현 로그는 `artifacts/first-fare/a96bfb3a8f7e454b91dcb107a44f2417/`.
- Unity 편집기 `CurveSteeringChecks.Run` 종료 0. 65% 입력 4초 동안 방향 변화는 40/45/50km/h에서 각각 118.44/94.39/48.75°였다. 자세 기울기는 최대 1.14°였다. 측정 로그는 `artifacts/cabin-nov20/steering.log`.
- 수첩 상태·시간 정지는 확인했다. 숨김 Player의 1600×900 및 1440×810 HUD 화면 캡처는 검게 저장되어 배치의 육안 판정에 사용할 수 없었다. 창문 애니메이션과 HUD 가독성, 키보드·패드 수동 조향 체감, 전체 캠페인 수동 플레이는 미검증이다.
