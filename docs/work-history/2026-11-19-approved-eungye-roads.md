# 은계 A~D 및 J7973 우회전 연결

## 범위

- [확정 시안과 거리뷰 근거](2026-11-17-seven-road-proposal.md). J7973 남쪽 두 모서리는 네 곳에 공통 합류 구조를 적용하라는 사용자 답변을 따랐다. 폭·위치와 신호 주기는 게임 치수다.
- r46 작업 지도에서 새 수정본을 작성한다. 원본 GIS 해시와 작업 시작 시점의 별도 사용자 파일을 보존한다.

## 변경

- A 은계로 북쪽 접근에서 북행 중간 차로와 연결 경로를 복원하고, 왕복 7차로 단면의 중앙선 이동 및 접점의 흰 점선을 작성했다. J7841 남행 유턴 구간은 흰 점선이다.
- B 은계남로에서 왕복 3차로 배분 전환과 노면선을 작성하고, 작은 교차로에 대각선 포함 동시 보행 단계 및 차량 전적색을 작성했다.
- C 은계 공영주차장 둘레에서 동서 각 측의 2+1 배분과 서쪽 방면 추가 차로 및 코너 양쪽 무신호 횡단보도를 작성했다.
- D 은계번영길에서 서행 안쪽 차로와 서쪽 배분 전환을 작성하고, 은계 공영주차장 앞 중간 신호 횡단보도의 서행 정지선을 맞췄다.
- J7973 네 모서리 각각에 신호등 섬, 인도–섬 횡단보도, 우회전 차로와 바깥 연결 차로에서 본선으로 들어가는 합류 경로를 작성했다.
- 지도 작성 코드는 `Assets/Editor/ApprovedEungyeRoads*.cs`에 있다. `ReviewedCorridorPaint`는 작성 도색의 노면 표시와 중앙선 판정에 같은 좌표를 제공한다.

## 실행과 검사

- Unity 2022.3.62f2의 `ApprovedEungyeRoads.Apply`로 프로젝트 지도에 적용하고 `ApprovedEungyeRoads.VerifyAndBuild`로 검사·통합 빌드를 실행한다.
- `builds/EungyeTaxi/EungyeTaxi.exe -presentationTest -approvedRoadViews -force-d3d11`은 실제 게임 월드의 정사영 화면 및 횡단보도 접점 검사를 생성한다. 촬영은 분리된 테스트 저장 위치를 사용한다.
- 정식 지도 r47 `2ee1a3fd415b6391086ea167da864dea1db68b58fe101af9105f5be6d482cf3e`에서 지도 모델 검증, 승하차 39곳의 방향별 1,482개 경로, J7973 네 섬의 차량 외곽 여유, 기존 조건부 유턴, r14~46 저장 이관 1,063검사를 통과했다.
- 지도 생성 입력 manifest의 바이트와 SHA256을 실제 파일에 맞췄고 `tools/check_workspace.ps1 -Strict`가 종료 0, 필수 입력 문제 0으로 성공했다. 선택 재수입 지도 2개는 로컬에 없다.
- 최종 `BuildHybrid` 종료 0. Windows Direct3D 실행본의 노면·시설 검사 351건을 통과했고 A~D 및 J7973 본체·남북 접근 총 7화면을 직접 검토했다. 첫 화면을 보고 B의 대각선 횡단보도를 실제 갈림길 중심으로 옮겼고, J7973 네 코너 보도 접속과 남서쪽 짧은 합류를 다시 작성했다.
- 격리된 r46 Player에서 운행 중 저장을 새로 만들어 9건을 검사했다. r47 Player에서 이어하기 23건을 통과해 승객 상태, 요금 정산 1회, 다음 영업일 기록이 이어지는 것을 확인했다. 첫 복원 시도에 사용한 보관 파일은 이미 운행을 종료한 상태여서 활성 승객 검증에 사용할 수 없었다.
- 지역 화면은 `artifacts/approved-*.png`, 종합 화면은 `artifacts/j7841-report/r47-final-overview.jpg`에 있다. 최종 빌드 로그는 `artifacts/j7841-report/r47-final-build.log`, Player 로그는 `r47-final-player.log`다.
- 지도 검사, 실제 실행본의 고정 카메라 확인, 이어하기 검사는 각각 수행했다. 장시간 수동 운전과 전체 캠페인 플레이, 현장 실측은 별도다.
