# 2026-11-02 PVP 졸음·공복 기반 생활 기획 수정

## 요구와 반영
사용자 요청: 운임 감액을 빼고 기존 졸음·집중력 저하를 활용,20분 가정에서 식사/휴식의 의미와 포만감을 함께 검토한다.

기존 생활·경제 문서의 PVP 전용 항목을 수정했다. 피로60/80 감액과 인위적인 승차 준비 지연 후보를 제외하고 공복 피로 가속→피로100→기존 눈감김/시야/입력 제한으로 연결한다. 식사는 예방, 휴식은 누적 피로/졸음 회복 역할이다. 경기 시간은 미확정이며20분은 분석 사례다.

추천 시험값은 간편식1,000원/15초/포만+60, 휴식무료/45초/피로−40이다. 이전 휴식20~30초를45초 후보로 바꿔 유료 식사의 짧은 정차와 무료 휴식의 더 긴 정차를 구분했다. 비용·효과 수치는 사용자 확정값/게임 적용값이 아니다. 초기상태/자연소모는 현행 유지 후보다. 졸음 뒤 개인 복귀, UI/봇의 예상 종료 상태 판단, 서비스 완료/경기 종료 경계 후보를 명시했다.

## 마지막 필수 확인과 한계
DriverCondition/Drowsiness/봇 시설 기준을 읽고 구간별 식을 독립 계산했다.1200초에 서비스 시간을 포함하고 이동 우회0초, 식사는600초 시작/615초 회복, 휴식720초 시작/765초 회복으로 계산했다. 무회복(포만0/피로100), 식사(40/90), 휴식(0/75.5), 둘다(40/47) 계산 일치.14분 식사 시작이면 종료 피로97도 확인했다. 이는 수학 계산이며 Unity 플레이·운임/손익 검증이 아니다.

같은 우회에서 식사로30초를 아껴도 추가 운송/호출 확보가 없으면 돈을 더 못 벌 수 있다. 실제 접근시간과 기회비용까지 포함해 비교하도록 기록했다.20분에 둘 다 의무화하지 않으며 늦은 급성 피로에는 휴식, 중반 허기에는 식사 선택을 제안한다.10/15/20/30분·사람/봇·장/단거리 균형, 개인 완전 졸음 복귀와 서비스 종료 경계는 후속 구현/게임 검증이다.

코드/실행본/캠페인 수치/저장/지도 입력 변경 없음. Unity 실행·재빌드는 하지 않는다. 변경 문서 링크와 diff를 확인한 뒤 게시한다.

최종 확인: 문서 링크 대상/앵커 확인 통과, `git diff --check` 종료0. 계산4개 시나리오와14분 식사 사례 일치. 문서만 변경했으므로 실행 검사 결과를 추가하지 않았다.
