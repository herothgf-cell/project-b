# P7 배포본의 새 경력과 4일차 동기 점검

2026-11-19. 은계 r47 통합 배포 42ba71f에서 백그라운드 Player를 실행했다. 기존에 열려 있던 게임 창, 키보드·마우스, 사용자 경력에는 입력하지 않았다. 테스트 저장과 로그는 별도의 실행 디렉터리에 두었다.

## 관찰

- 첫 메뉴의 싱글 설명은 ‘3일 영업 · 저장한 운행 이어하기’다. 4일차가 존재한다는 단서와 첫 차를 물려받은 사연이 드러나지 않는다.
- 첫 경력 검사에서 26초 3컷 → 숙소 운전석 → K로 빈차등 켜기 → 첫 탑승·미터기 → 하차·아버지 수첩 발견 순서로 진행했다. 첫 운송을 마치는 행동이 수첩의 첫 페이지와 다음 단서로 이어지는 순간이 가장 선명한 시작 동기다.
- 같은 이야기 저장에서 첫날 밤 목표를 미루고 2일차 수다 손님의 질문에 답했다. 3일차에 목표를 다시 고를 수 있었다. 경력 초기에 결정을 강요하지 않으면서 이틀 뒤 선택할 이유가 생긴다.
- 별도 경력 저장에서 3일차 마감 뒤 같은 슬롯으로 4일차 준비에 진입했다. 차량과 방 조명, 현금이 이어졌고, 4일차 마감과 5일차 준비도 통과했다. 첫날과 이튿날의 버튼은 다음 일차를 알려 주는데 3일차에는 ‘계속하기’로 바뀐다. ‘4일차 영업 준비’로 쓰면 보상을 이해하기 쉽다.
- 첫 3일 미터기 자동 보조는 4일차부터 종료된다. 운전석 표시는 바뀌지만 처음 계속하기를 누른 사람이 조작 변경과 감액을 예상할지 확인이 필요하다. 4일차 첫 탑승에 ‘오늘부터 미터기는 직접 켭니다 [J]’를 한 번 보여주는 방법이 있다.

## 방법과 범위

배포 실행본을 새 작업 디렉터리에서 숨김 창으로 실행했다. 첫 이야기와 같은 저장의 재개는 `-fatherStoryCheck`, `-fatherStoryReloadCheck`, 계속 영업은 `-careerCheck`, `-careerReload`를 사용했다. 이야기 검사는 승하차·숙소 위치를 제어하고 경력 검사는 운임을 입력한다. 승객 이야기 검사는 `-contentTest -passengerStoryCheck`와 재실행 `-passengerStoryReloadCheck`를 사용했다. 별도 물리 주행은 `-oneDayMode -oneDayTrafficTest -contentTest`로 게임 시계 4배속, 일반 차량과 차량 물리를 켜고 진행했다. 첫 운송과 경력 전체의 기록은 서로 다른 저장에서 얻었다. 동일 저장으로 4일간 일반 운송을 반복했을 때의 피로도, 장기 목표의 실수입 진척과 사람의 재방문 의사는 미검증이다.

## 자동 물리 주행에서 처음 막힌 지점

승차 지점 30 → 하차 지점 38, 제시 운임 6,600원, 승객 탑승 구간 약 898m였다. 검사기는 제안 중 접근과 운송의 합이 짧은 경로를 골랐다. 게임 시계 177.9초에 이미 1,043m를 빈 차로 달렸고 196.0초에 승차 지점에 도착했다. 영업일 1,200초 중 약 16%다. 목적지 접근 도착은 374.3초였다. 포켓 진입과 주행 안전 판정을 통과했으나 하차 상호작용 한 번 뒤 운송 완료 판정이 실패했다. 383.2초에 검사 종료, 총 2,039m, 운송 수입 0원, 충돌·신호 위반 0건이었다. 검사는 하차 직후 종료하여 거절 메시지·승객 추가 응대 상태·재입력 결과를 기록하지 않았다. 일반 플레이의 영구 막힘 여부는 미확정이다.

한 번의 표본이지만 첫 손님을 만나기까지의 공차 거리가 승객을 태우고 이동하는 거리보다 길었다. 첫날에는 숙소 근처의 짧은 첫 호출을 우선하고, 하차가 한 번에 끝나지 않으면 다음에 필요한 행동 한 가지를 F 안내에 표시하는 방안을 우선 검토한다.
