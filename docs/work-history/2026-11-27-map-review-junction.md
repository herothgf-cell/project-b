# 2026-11-27 지도 검토 17단계: 교차로 기능과 은행로 남북길 (지도 r80·r81)

## 요구사항

- 사용자: "교차로 기능 만들기".
- 새 도로가 기존 도로를 가로지르는 곳에 교차로를 만든다. 차로 자르기, 회전 연결 차로, 교차로 규칙(정지선·횡단보도)이 필요하다.
- 첫 적용 대상은 J046-1·J047-1이다. J3754에서 은행로149번길을 건너 J3395까지 가는 남북 도로가 게임에 없다.

## 구현

### 도구

- **`MapReviewGeometryEdit.cs`(패치 적용기):**
  - `splits`: 기존 차로를 거리 지점에서 자른다(`RoadMapAuthoringOperations.SplitLane`). 지점에 점이 없으면 하나 넣는다.
    - 꼬리 조각에는 패치가 정한 고정 ID(`editor:segment:<원 차로 base64>:<접미사>`)를 붙인다.
    - 그 ID를 시설·신호 그룹·장면 객체 참조까지 바꿔 준다.
    - 다음 패치가 같은 조각을 가리킬 수 있다.
  - `attrs`: 차로의 교차로 규칙 ID, 회전 방향, 출처(`sourceId`)를 바꾼다.
  - `addFacilities`: 교차로 표지에 쓰도록 `junctionId`·`text`·`axis`·`evidence`를 실을 수 있게 했다.
- **`ReviewedMidblockControl.cs`:** 새 시설 종류 "검토 교차로"를 추가했다.
  - 지도 문서의 표지 하나가 교차로 규칙 하나가 된다. 원본 지도에 없는 교차로에 쓴다.
  - 진입 방향은 `axis` 비트로 고른다(1 = 진행 방향, 2 = 반대, 4 = 오른쪽, 8 = 왼쪽, 0 = 넷 다).
  - 폭: `width`는 진행 축 차도 폭, `length`는 가로 축 차도 폭이다.
  - `text`가 "신호"이면 신호 교차로가 된다(게임 신호 프로그램 필요). 그 밖에는 비신호이고, 정지선과 횡단보도가 생긴다.
- **`RoadMapValidator.cs`:** "검토 교차로"를 검사한다.
  - 필요한 것: 규칙 ID, 외관 근거, 진입 비트(0~15). 신호 교차로이면 신호 프로그램도 있어야 한다.
  - 기존 "신호 교차로" 검사와 축 0/1 검사는 이 종류에 적용하지 않는다.
- **`tools/map_road_add.py`의 `JunctionPatch`:**
  - `split`: 자른 뒤 머리·꼬리 모양을 Python 쪽에서도 들고 있어, 이어지는 계산이 바로 쓴다.
  - `cross_existing`: 기존 차로를 진입 / 교차로 안 직진 / 진출 세 조각으로 나누고, 가운데 조각을 새 규칙에 넣는다.
  - `turn`: 진입 끝에서 진출 시작으로 곡선 회전 차로를 만든다.
- **`map_lane_edit.LanePatch`:** 잘린 조각 모양을 `pts()`로 돌려주고, `splits`·`attrs`를 패치에 싣는다.

### r80 (`tools/map_review_r80_plan.py` → `config/maps/review/r80-junction-road.json`)

- **배경:**
  - 항공사진: 은행로144번길 막다른 끝(J3754_11003, x 377)에서 북북서로 은행로149번길(x 361, z 1147)을 건너, J3395_12007 막다른 끝(x 340)까지 가는 양방향 길이 있다(편도 1, 황색 중앙선).
  - 게임에는 녹지와 막다른 길 둘뿐이었다.
- **위치:** 항공사진 차도 가장자리를 5~15 m마다 읽어 중심선을 잡았다.
  - 남쪽 절반은 북쪽 절반보다 약 4 m 동쪽에 있어, 중심선이 교차로에서 꺾인다.
  - 첫 판은 교차로 부근에서 4 m 서쪽에 있어 고쳤다.
- **넣은 것:**
  - 도로 띠 10.5 m. 차로는 방향마다 하나씩, 중심선에서 ±1.9 m, 폭 3.3 m.
  - **교차로 `review:r80:J3575_11455`:**
    - 은행로149번길 두 차로를 교차점 ±6.5 m에서 잘라 진입 / 직진 / 진출로 나눴다.
    - 새 길 차로도 같은 방식으로 나눴다.
    - 네 진입마다 좌·우회전 연결 차로를 놓았다(8개).
    - 진입·직진·회전 조각은 새 규칙을 쓰고, 진출 조각은 원래 규칙을 유지한다.
    - "검토 교차로" 표지를 놓았다: 비신호, 네 방향 정지선·횡단보도. 근거는 항공사진이고, 운영 방식은 게임 추정이다.
  - **양 끝 T자:**
    - 막다른 차로가 새 길로 들어온다(우회전).
    - 새 길은 옆 도로의 시작 차로로 나간다(좌회전).
    - 기존 규칙 J3754_11003·J3395_12007을 쓴다.
    - 회전 반경이 나오도록 새 길 차로는 남쪽 z 1106~1109, 북쪽 z 1189~1192에서 끝낸다.
  - **보도:** 새 길이 지나는 보도 12조각 가운데 6개를 끄고 나머지는 잘랐다.

### r81 (`tools/map_review_r81_plan.py` → `config/maps/review/r81-junction-road-paint.json`)

- **고친 문제:** r80 화면에서 새 길에 차선 도색이 없고, 도로 띠 가장자리가 물결쳤다.
  - 도색이 없던 원인: 차로 출처가 띠의 객체 ID(`road:review:r80:...`)였다. 자동 도색은 도로 ID(앞의 `road:`를 뺀 것)로 차로를 묶는다.
  - 물결 원인: 띠가 성긴 항공 꺾은선을 그대로 따라서, 꺾이는 점마다 물결이 생겼다.
- **수정:**
  - r80 차로 18개의 출처를 도로 ID로 바꿨다. 규칙 ID는 그대로 두었다.
  - 띠를 매끄럽게 한 같은 선으로 옮겼다(원래 선과 최대 0.24 m 차이).
- **r81로 따로 만든 이유:** r80을 되돌리는 `git checkout`이 자동 권한 검사에서 막혔다. 그래서 r80 위에 고치는 패치로 쌓았다. 순서대로 적용하면 같은 결과가 된다.
- **참고:** r79(J044-1)의 차로도 같은 출처 실수로 도색이 없을 수 있다. 확인하지 않았다.

  - 선두 세 대가 서로 다른 세 진입에서 60초 동안 빨간불이었다.
  - 그중 하나는 Y04 남서 좌회전 연결(`join:local:4187:13357:3637:12998:-1`)이다. 이 좌회전은 `local:3577:12726:4065:11716`으로 남쪽으로 내려가 은행로149번길로 이어진다. 새 교차로가 생기면서 이 경로를 쓰는 차가 생긴 것으로 보인다.
  - **신호 기록(`-signalCountdownCheck -signalJunction J3516_12881`):** 이 교차로만 따로 보면 단계 0(축0 직진) → 1(축0 +좌회전) → 3(축1 직진)이 정상으로 돈다.
    - 단계 2(축0 −좌회전)와 4(보행)는 기록 동안 한 번도 돌지 않았다.
    - 축1 좌회전 전용 그룹은 프로그램에 없다(허용 좌회전으로 처리).
    - 이 기록을 보려고 프로브에 단계별 이동 목록 출력을 넣었다(`SignalCountdownProbe.cs`).
  - **결론:** 원인은 아직 모른다. J3516 자체는 이번에 고치지 않았다.
- "green queue clears" 3건 실패는 r78·r79에서도 나던 기존 실패다.

  - AI 차량이 새 교차로를 실제로 지나가는지 따로 관찰하지 않았다.
