# 2026-11-23 선택형 미션 4종 (08 3장 3단계, 은계 싱글)

## 요구

자리 비움 중 일괄 진행 요청의 3단계. [08 재미 보강](../content-design/08-fun-improvements.md) 3장 "선택형 미션" 중 급행, 초록불 타기, 커피 든 손님, 칼정차.

- 호출판에서 아이콘과 추가금이 미리 보이고, 플레이어가 그 호출을 골라 미션을 고른다.
- 성공하면 추가금을 주고, 실패해도 그 미션 때문에 기본 운임이 깎이지 않는다. 호출판 3건 중 1건 정도에만 붙인다.
- 급행은 정차 시간을 뺀 주행 시간 기준이며, 기존 도착 기한 0원 규칙과 겹치지 않게 처리한다.
- 추가금 초안은 약정액의 20~30%이고, 영수증에 별도 줄로 보인다. "길 아는 기사", "버스 따라가기"는 제외한다.

## 코드 대조와 재사용

| 미션 | 재사용한 판정 |
|---|---|
| 급행 | 손님 탑승 중 차가 움직인 시간(시속 1.8km 초과)만 누적한다. 기준은 호출의 안전 운송 시간(`safeRouteSeconds`, 8m/s·회전 4.5m/s) ×1.1 |
| 초록불 타기 | `DrivingManners.CheckSignal`의 신호 정지선 통과 기록(`stopped`: 통과 전 8초 안에 정지선 앞에 멈췄는지). 멈추지 않은 통과가 3번 이어지면 성공, 멈추면 0부터 다시 센다 |
| 커피 든 손님 | 운송 중 불필요한 급가감속 수(`DrivingManners.TripHarsh`, 2026-11-23 팁 작업). 필요한 제동은 기존 규칙대로 제외 |
| 칼정차 | 하차 30cm 칭찬 판정(`goodPrecise`, 팁 작업) |

## 실제 구현

- `JobOffer`에 `mission`, `missionBonus`와 진행 값(`missionDriveSeconds`, `missionGreenRun`, `missionGreenBest`)을 추가했다. 모두 기본값 0이라 예전 저장이 그대로 열린다. 운송 중 저장·불러오기에도 진행 값이 유지된다.
- `PassengerJobsMissions.cs`:
  - `ApplyMissions`: 새 일반 호출판에 미션 호출을 한 건 붙인다(3건 중 1건). 마지막 한 콜 호출판과 첫 출차 안내에는 붙이지 않는다.
  - 카드에 "[미션] 초록불 타기 · 성공 시 +1,500원 · 신호 3곳 연속 멈추지 않고 통과"처럼 목표와 추가금을 보인다.
  - 도착 확정 때 `SettleMission`이 성공 여부를 정하고, 운송 완료 때 `PayMission`이 장부 `mission:<운송 id>`(종류 `mission`)로 입금한다. 같은 운송의 두 번째 입금은 장부가 거절한다.
- 영수증: 운임 3줄 아래에 별도 줄을 둔다. 성공이면 "미션 추가금 (운임과 별도) +N원 · 이름 성공", 실패면 "미션 이름 실패 · 기본 운임은 그대로". 팁 줄이 있으면 그 위에 놓는다. 기록(F8) 내역에는 넣지 않았다(아래 남은 것).
- 완료 메시지에 성공·실패 한 줄을 추가했다.
- 설정 툴 "선택형 미션" 묶음 8개(`mission.*`).

### 지각 0원 규칙과의 관계 (어떻게 처리했나)

기존 규칙은 바꾸지 않았다. 미션 추가금은 **기한 안에 도착하고 운임이 0원보다 클 때만** 성공으로 판정한다. 그래서 지각하면 기존 규칙대로 운임이 0원이고, 미션 추가금도 없다. 급행은 "정차 시간을 뺀 주행 시간"으로 판정하므로, 신호 대기가 길어 늦지만 않으면 신호 운과 상관없이 성공할 수 있다. 반대로 주행 시간이 짧아도 기한을 넘기면 성공이 아니다. 두 규칙이 동시에 돈을 주거나 깎는 경우가 없다.

### 판단 기록 (임의로 정한 값)

| 항목 | 값 | 이유 |
|---|---|---|
| 붙이는 빈도 | 호출판마다 1건(`mission.boardChance` 100%) | "3건 중 1건 정도"를 가장 단순하게. 확률로 바꿀 수 있음 |
| 붙는 대상 | 학생 재회를 뺀 모든 호출(길목 시나리오 포함) | 운임·기한을 바꾸지 않아 시나리오 규칙과 충돌하지 않고, 시나리오만 있는 판에서도 미션이 나오게 |
| 미션 종류 선택 | 호출판 시드로 4종 중 하나 | 결정적이라 불러오기로 바뀌지 않음 |
| 추가금 비율 | 급행 30%, 초록불 25%, 커피 20%, 칼정차 20%(100원 올림) | 초안 20~30% 안에서 어려운 순서대로 |
| 급행 목표 | 안전 운송 시간 ×1.1 | 안전 운송 시간은 평균 시속 약 29km 기준이라, 10% 여유로 규칙을 지키며 달성 가능한 정도 |
| 초록불 수 | 3곳 연속 | 08 문서 제안값 |
| 성공 조건 공통 | 기한 내 도착 + 운임 > 0 | 지각 0원 규칙과 겹치지 않게 |

### 실행본 검사 결과

`-contentTest -missionCheck`(새 검사 `MissionProbe`, 사용자 저장과 분리된 시험 캠페인): `MISSION_PLAYER_OK checks=72`.
- 호출판 10개 모두 미션 1건, 카드에 "[미션] … 성공 시 +N원"이 보이고 추가금 비율·100원 단위가 맞다.
- 급행 성공 +1,800원(운임 6,000원의 30%).
- 초록불: 중간에 멈추면 실패하고 운임은 그대로(기본 운임+보너스−미터기 감액과 같음). 3곳 연속이면 +1,500원.
- 커피 +1,200원, 칼정차 +1,200원. 급행이 느리면 실패하고 운임은 그대로.
- 지각 운송은 운임 0원이고 미션 추가금도 없다.
- 장부 `mission` 항목 합계 5,700원, 같은 운송 재입금 거절, 영수증 별도 줄, 저장 파일 유지, 예전 호출은 미션 없음.
- [영수증 화면](../ui/2026-11-23-call-board/receipt-mission.png)

회귀(같은 실행본, 시험 캠페인): `-goodDrivingCheck` 34건, `-idleTimeCheck` 14건, `-callBoardCheck` 116건, `-brightUiCheck` 102건 통과.

검사를 고치며 바꾼 점(게임 동작이 아니라 검사 쪽 원인이었다):
- 처음에는 사용자 싱글 저장에서 돌려, 앞선 검사가 남긴 운송 중·영업 시간·첫 출차 상태 때문에 결과가 실행마다 달랐다. `-contentTest`로 분리된 시험 캠페인에서 돌리도록 바꿨다.
- 장부를 새로 바꾼 뒤(`Fresh`) 호출판을 만들면 판이 비어서, 호출판 확인을 장부 교체 전에 했다.
- 하차 뒤 결과 표시 동안 다음 수락이 막혀서, 운송마다 상태를 비웠다.
- 길목 시나리오 호출만으로 판이 채워지면 미션을 붙일 곳이 없었다. 미션은 운임·기한을 바꾸지 않으므로 시나리오 호출에도 붙이도록 대상을 넓혔다(학생 재회 호출만 제외).

## 남은 것 · 직접 확인

- 사람 플레이 체감은 확인하지 않았다. 실제 신호에서 초록불 3곳이 가능한지, 급행 목표가 빡빡한지, 커피 손님이 너무 쉬운지(정상 운전이면 대부분 성공) 봐야 한다.
- 초록불 판정은 "정지선 앞 8초 안에 멈췄는지"라는 기존 기록을 쓴다. 정지선 앞에서 아주 느리게 굴러 통과한 경우의 처리는 체감 확인이 필요하다.
- 운전 중 미션 진행 상황 표시(예: 초록불 2/3)는 넣지 않았다. 카드와 영수증에만 보인다.
- 기록(F8) 운송 내역에 미션 줄은 넣지 않았다. 영수증과 장부에는 있다.

## 재현

```powershell
Unity.exe -batchmode -nographics -quit -projectPath unity/EungyeTaxi -executeMethod CallBoardChecks.Run
.\builds\EungyeTaxi\EungyeTaxi.exe -contentTest -missionCheck -missionOutput artifacts/mission -logFile artifacts/mission/player.log
```
