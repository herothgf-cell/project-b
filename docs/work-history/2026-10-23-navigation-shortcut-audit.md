# 주차장→남서부 승차 지점 큰 우회 원인 검토

## 요청과 결과
스크린샷에서 사용자가 그린 남쪽 경로가 더 짧아 보인다는 제보를 대조했다. 현재 프로젝트 지도 baseline/document 및 경로 코드를 읽고 같은 형상의 주차장(승하차1)→은계 승하차8 경로를 재현했다. 실제 도로의 좌회전 가능 여부는 이번 검사로 확정하지 않는다.

- 출발 stop0: x296.288/z506.490, 서쪽 방향, NGII A2218G611368:2(4차로). 도착 stop7: x349.663/z82.831, local:2050:827:4943:827 동쪽 방향.
- 현재 그래프 경로: 32 edges / 2870.96m. 북쪽 우회→동쪽 남하→하단 서쪽 진행→서남부 블록 회전→동쪽 승차 접근. 이미지 형태와 일치.
- 출발 4차로의 유일한 next는 A222BC004016:0 우회전이며 북쪽 portal로 연결된다. 현재 위치에서 임의로 좌회전하면 차로 제약을 건너뛰게 된다.
- 서쪽 접근 3차로 A2218G611366:3은 next=[]로 끊김. 남쪽으로 이어지는 NGII A2218G611310:0도 next=[]이며, 남하 local:1903:4938:1912:2429 시작점까지 약5.70m의 간극이 있으나 연결이 없다.
- 남하 local 시작에서 같은 승차 지점까지 기존 로컬망으로 569.60m가 나온다. 출발점~교차로 회전과 단절 연결을 포함하면 약700m대의 더 짧은 후보가 가능해 보이지만, 실제 좌회전 허용과 접근 차로/차로 변경을 확인해야 한다. 유효한 경로로 확정하거나 새 연결을 생성하지 않았다.
- 원인은 최단 탐색 자체보다 입력 차로/NGII↔로컬 연결의 누락·불완전성. 주변 호출 미리보기는 RoadNavigation.PreviewTo→HdRoadGraph.Route의 길이 기준이며 단순 빠른길 설정 때문이 아니다.

## 수행한 검사
Python 표준 라이브러리로 프로젝트 baseline hdEdges/next를 읽어 길이와 차로변경 비용을 재현한 Dijkstra 대조. 실제 프로젝트 document의 같은 차로 next도 대조. artifacts/navigation-shortcut-audit.json에 경로 edge IDs/거리/단절 간극 기록. 코드/지도/실행파일/배포 manifest 수정이나 자동 물리/수동주행 검사는 수행하지 않았다.
