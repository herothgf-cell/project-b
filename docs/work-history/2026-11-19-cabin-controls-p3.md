# P3 차내 조작 3종

기획32 §3과 P3 프롬프트, 콕핏 시안에 따라 은계 싱글에 미터기 J, 빈차등 K, 에어컨 L을 연결했다. P2 배포 `863ef2e`를 기준으로 작업했다.

- 수동 미터기는 승차 뒤 J로 켜고 하차 뒤 J로 끈다. 누락된 운송은 양의 기존 정산 운임에 기본 0.5배를 적용하고 “미터기를 안 켜셨네요”를 표시한다. 열린 미터기를 끄기 전에는 다음 호출을 받지 못한다. 기존 도착 시간과 만족도 정산을 유지하고 미터기 감액은 영수증 이력에 따로 표시한다.
- 빈차등은 빈차·예약·휴무로 순환한다. 진행 중 호출은 예약으로 표시하며, 휴무를 미리 골라도 현재 운송은 계속된다. 휴무 상태에서는 호출판과 길가 새 승차를 막고, 빈차로 돌아오면 호출을 다시 제안한다.
- 에어컨은 따뜻·끔·시원으로 순환한다. 수동 모드의 답변은 실제 에어컨을 조작하지 않는다. 해당 온도를 유지한 시간으로 기존 온도 민감 특성의 성공·실패를 계산한다.
- 처음 3일에는 미터기 자동 지원과 조작 안내를 켠다. 설정의 운전 관련 탭에서 첫 3일의 미터기 보조를 끌 수 있다. 온도 요청은 첫 3일에도 실제 L 조작을 평가한다. PvP는 기존 자동 규칙을 유지한다. J·K·L과 기존 입력 충돌은 코드, 입력 액션, InputManager에서 발견되지 않았다. 기존 설정 화면은 키 재지정을 지원하지 않는다.
- 운전 화면 하단 콕핏 카드와 룸미러 아래 빈차 표시를 기존 CasualUI와 KoreanText로 표시한다. 미터기 지급 비율은 콘텐츠 관리의 차량 → 차내 조작에서 수정한다.
- 캠페인 저장 형식을 5로 올리고 운송 중 차내 상태를 저장한다. 2~4 포맷과 지도 저장 이관은 유지한다. 이전 저장의 활성 운송에는 미터기 감액이 소급되지 않는다. LAN 호스트 프로필에서 싱글 전용 설정을 제외한다.

주요 코드 범위는 `CabinControlsState`, `BusinessProgress`, `PassengerJobs`·`PassengerBehavior`·`PassengerRequest`, `CockpitUI`·`DriveHUD`·설정, 운행 이력, 콘텐츠 원본과 Runtime Resources, 검증 도구다.
