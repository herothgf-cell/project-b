# 사내망 PvP 방 목록 사전 점검

외부 서버 없이 방 목록을 사용할 수 있는지, 유선과 Wi-Fi의 실제 대역이 다를 때 사내 관리자 요청 없이 접속할 수 있는지 점검했다. 게임 코드와 배포 실행본은 이번 점검에서 수정하지 않았다.

PowerShell에서 `NetworkInterface.GetAllNetworkInterfaces()`로 현재 PC의 활성 유선과 Wi-Fi IPv4 주소와 프리픽스를 읽었다. 두 어댑터는 모두 `/22`이고, 계산한 네트워크 주소가 일치했다. 이 결과는 현재 PC의 주소 설정에 대한 확인이다. 두 다른 PC의 실제 통신이나 Wi-Fi 격리 여부는 확인하지 못했다.

배포 중인 LAN v17은 숫자 IPv4와 UDP 포트로 직접 접속한다. 기본 UDP 포트는 `7777`이며, 현재 참가 화면에는 방 자동 검색이 없다. 같은 링크에서 탐색 패킷과 게임 UDP 통신이 모두 허용되면 외부 서버 없이 목록을 구현할 수 있다. 서로 다른 서브넷에서는 일반 로컬 브로드캐스트나 mDNS에만 의존하면 방 발견을 보장할 수 없다. 두 망 모두에서 접속할 수 있는 기존 사내 목록 주소나 사내 검색 기능이 있으면 방 정보를 얻을 수 있으며, 직접 플레이에는 호스트 UDP 포트까지 별도로 도달해야 한다. [mDNS 링크 범위](https://www.rfc-editor.org/info/rfc6762/) · [라우터의 브로드캐스트 기본 동작](https://www.rfc-editor.org/rfc/rfc2644.html)

현장에서는 유선 PC가 `builds/EungyeTaxi/EungyeTaxi.exe`로 방을 만들고 `ipconfig`에서 이더넷 IPv4를 확인한다. 같은 실행본의 Wi-Fi PC에서 해당 주소와 `7777`로 참가한 뒤 역할을 바꿔 확인한다. 유선끼리 참가 성공을 기준으로 삼을 수 있다. 이 검사에서 양방향 참가에 성공하면 현재 구성에서 게임 통신이 가능하다는 뜻이며, 목록을 추가하기 전에는 별도로 탐색 패킷이 도달하는지 확인한다. 이번에는 읽기 전용 주소 확인과 LAN 코드 대조를 수행했다.
