# P1 은계 기사 숙소 거점

사용자가 지정한 [프롬프트의 공통 규칙 및 P1](../content-design/archive/codex-prompts-motivation.md), [숙소 기획](../content-design/07-home-room-and-vehicles.md), [배경](../content-design/00-game-overview.md), 지도와 정산 시안을 대조했다. P1은 은계 싱글의 숙소, 퇴근, 귀갓길 호출, 월세와 숙소 UI에 적용한다.

- 기존 시작·마감 주차장 `service:parking`의 정차점 (296.2881, 506.4904)을 사용한다. 런타임 3D 표지와 지도는 숙소로 표시하며 F7 생활거점의 첫 카드는 집 아이콘이다. 동부 휴식 주차구역에서는 휴식만 제공한다.
- 빈차가 숙소 칸에서 F를 누르면 정상 퇴근과 정산으로 이어진다. 동부 휴식 구역에서 F로 퇴근하려 하면 지정 문구를 표시한다. 졸음 강제 귀가는 기존 정차점과 견인 처리 규칙을 재사용한다.
- 영업 시각 이후에는 현재 위치 및 후보 승차점보다 숙소에 남은 주행 경로가 짧은 목적지의 호출 순위에 가중치를 적용한다. 후보마다 실제 방향 차로를 사용하고 같은 목적지의 거리 계산은 호출판 생성마다 재사용한다. 운임 변경은 없다.
- 월세 시험 기본값은 1,500원이다. 기획22에서 사용한 임시 R 10,000원(기존 목표 30,000원 ÷ 3일)의 15%다. 사람 실측 중앙값은 아직 없다. 주차비 결제 뒤 남은 현금 범위에서 월세를 한 번 부과하며 부족분을 미납에 넣지 않는다. 이미 정산한 날은 소급하지 않는다.
- 정산과 다음날 준비에 월세를 표시한다. 숙소 화면은 기존 방·차고 동선을 사용한다. 콘텐츠 관리의 생활 → 숙소에서 `home.rent.daily`와 `home.returnTrip.weight`(기본 3)를 편집할 수 있다.
- 싱글 숙소 장부는 계정 스냅숏 4를 기록한다. 기존 캠페인 외부 형식 2/3과 계정 2/3을 읽고 다음 마감부터 월세를 적용한다. 콘텐츠 프로필의 기존 해시와 기존 거래를 보존한다. 싱글 숙소 키를 PvP 호스트 프로필에서 분리해 LAN v19를 유지한다.

변경 범위는 `BusinessProgress`, `CampaignAccount`, `PrototypeSettings`, `ServiceStops`, `ProjectMapScene`, `MapDestinationUI`, `FullMapOverlay`, `PassengerJobs`의 수요 처리, `DayPreparationPresentation`·`OneDayHUD`·`PersonalRoomHUD`, 콘텐츠 원본·Resources·관리 도구, Player/모델 검사, 기획 및 인계 문서다. 기존 미커밋 작업을 분리한 체크아웃에서 진행했다.

## 검증과 재현

- `pwsh -NoProfile -File tools/test_content_tuning.ps1` 모델 857건과 C#/Node 프로필 해시 일치. 구현 전 모델은 새 숙소 설정·이관 API 부재로 실패했다.
- `node --test tests/content-editor/*.test.mjs` 103건 통과. 생성된 기본 프로필과 번들 사본도 검증한다.
- `pwsh -NoProfile -File tools/check_workspace.ps1 -Strict` 종료 0, 필수 입력 문제 0. 재수입용 선택 입력 2개 부재. 은계 r47 지도·입력 manifest에 변경 없음.
- `ApprovedEungyeRoads.VerifyAndBuild` 종료 0. 승하차 39곳, 방향별 1,482경로, r14~r46 저장 이관 1,063검사. 후속 F7 안내 보완을 넣은 `PrototypeBuild.BuildHybrid`도 종료 0. 로그 `artifacts/p1-home/build-normal.log`와 `build-release.log`.
- `pwsh -NoProfile -File tools/test_home_base_player.ps1` 종료 0, 위치 제어 13검사. 첫 실행 검사는 동부 휴식 칸에서 F7 숙소 안내가 막혀 실패했고, 최종 검사는 F 거부 → F7 첫 숙소 안내 → 숙소 F 정산, 월세 1회, 다음 날 준비, 졸음 강제 귀가와 체크포인트 복원을 확인했다. 숨김 창 캡처가 검게 나와 실제 화면의 배치를 확인했다는 근거로 사용하지 않았다.
- 격리된 r47 실행본의 `-liveSaveTest` 9검사와 최종 P1 실행본의 `-liveReloadTest` 23검사 각각 종료 0. 진행 중 승객·장부·한 번 정산·날짜 전환을 실제 새 프로세스에서 확인했다. 위치 제어 검사이며 자동 물리 주행·수동 플레이는 별도다.
- 배포 폴더 크기·SHA256 검증 기록은 통합 배포 manifest와 배포 커밋에서 확인한다.

실행은 `builds/EungyeTaxi/EungyeTaxi.exe`의 은계 싱글을 선택한다. 정차 후 F7의 첫 카드에서 숙소로 안내받고, 주차 칸에서 F를 눌러 마감한다. 정산과 다음 날 준비에서 월세를 확인한다. 빌드 진입점은 `PrototypeBuild.BuildHybrid`이며, `ApprovedEungyeRoads.VerifyAndBuild`로 승하차 전수 경로·r14~r46 저장 이관을 검사한 뒤 같은 빌드를 호출한다.

남은 확인은 사람 주행에서 종료 후 귀가 중앙값 3분 이내인지, 월세가 경제에 미치는 체감, 전체 3일과 다른 PC LAN이다. 다음 개발은 P2 계속 영업 모드다.
