# 플레이 기획 재통합·가지별 마인드맵 변경 검토

## 요구사항

사용자 지적: content-design은 개발 문서가 아니라 기획 문서이며 내용 중복이 많다. 최신 기획 기준으로 실제 마인드맵의 추가/수정/삭제를 가지별 표로 정리하되 원본은 사용자 검토 전 수정하지 않는다.

## 실제 작업

- 20개 기획 본문을 게임 개요·주행/교통·승객/운임·생활/경제·캠페인/기록·화면/안내의6주제로 통합. 별도 가지별 검토표와 README를 포함해 기획 폴더 Markdown은8개다.
- 통합18의 중복 수치 표·19의 코드 소유권을 기획 폴더에 추가 유지하지 않는다. 규칙은 각 담당 문서에만, 다른 주제는 영향/참조만 남긴다. 주행 평가·요청/운임·졸음·청결·점유·시설·경제·시간/이월의 핵심 조건을 보존했다.
- 기술 구조/지도 편집/법규 상세 후보는 technical-reference로, 사고/보험·차량 구매·PVP 등은 future-design으로 분리. 제작 명령·소스/저장 버전·테스트 수·배포해시는 기획 본문에 넣지 않는다.
- 정리 전 전체 문서는 design-history/content-design/2026-10-27-before-planning-only에 보존.20개 기존 본문은 원문 일치 확인 후 이력 폴더로 이동했다. 앞선 아카이브와 작업 이력은 유지한다.
- docs/game-design.md의 오래된 중복 개요도 별도 원문으로 보존하고 현재 기획 안내 입구로 바꿨다.
- 이동으로 끊길 Markdown 링크는 기계적 재연결. 과거 이력은 보존 원문으로, 현재 안내/범위는 새 담당 주제로 연결한다. 규칙 내용의 추가 변경은 하지 않았다.

## 마인드맵 검토

- 실제 .mmst(JSON)의15개 최상위 가지와 하위 항목을 읽었다. 가지명은 원본 기준이며 더하는 가지는 ‘추가’, 중복 제거는 ‘통합·삭제’, Proto 밖 아이디어는 ‘이동’으로 구분했다.
- 피로 한계에도 탑승 유지/수면 후 재영업, 과식 시 졸음, 보험료 할인/보행자 치료비, 호출 목록 정보, 저장 경계 설명을 최신 기획에 맞춘 수정안으로 제시.
- 요청 종류·변경/경유/분실물의 중복, 주유소/차량 상태의 청결·세차 중복, 시설/운전자 회복량 중복을 대표 가지로 모으는 검토안 작성.
- 원본 변경0. SHA256 `F1951492F9C5A13941E60A17D92EB31B1A7471FB8ABA7996D47A0C2E02F00937`를 전후 대조한다. 원본 사용자 수정은 stage/커밋하지 않는다.

## 검증·남은 범위

- 원문 이동 전20파일의 내용이 보존 사본과 동일함을 검사해 통과. 기획은8개 Markdown만 남도록 구성.
- `check_planning_only.ps1` 종료0: 관련83파일, 현재8문서, 로컬 링크1,430·앵커14·표45개 오류0. 핵심6문서의 코드/빌드/검사 명세 키워드 잔존0, 마인드맵 해시 일치. 과거 이력의 앵커는 당시 원문 기준이므로 이번 현재 앵커 검사 범위와 구분한다.
- Git HEAD의 기존20본문과 보존 원문의 내용을 비교(이동에 따른 Markdown 링크 목적지만 제외)하여20개 모두 일치. `git diff --check` 종료0. 링크707개는 이동 경로를 기계적으로 재연결했다.
- 코드/지도/배포 경로 diff0. 배포 manifest VerifyOnly 종료0: 130파일/105,870,100바이트 전체 해시 일치. .mmst 해시는 위 값 유지.
- 커밋/푸시와 최종 원격 SHA는 실제 명령 결과로 별도 기록한다.
- 문서 작업이므로 모델/Unity/물리/수동 캠페인 재시험과 재빌드는 하지 않는다. 이번 정리가 해당 게임 검증을 완료했다는 뜻은 아니다.
- 마인드맵 적용은 사용자 검토 후 별도 요청 대상. 다른 미검증/후속 범위는 LATEST의 기존 내용 유지.
