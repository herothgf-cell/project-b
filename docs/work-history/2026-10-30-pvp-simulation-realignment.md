# PVP 방향 수정 검토 — 2026-10-30

## 사용자 요구와 확정 변경
기존 시뮬레이션의 실제 화면·차량·조작·승객·교통·시설을 사용하고 유저/봇과 경쟁하는 경기 규칙을 추가한다. 외형만 차용한 별도 게임은 요구와 다르다. 새 전용 맵은 시안을 제안한 뒤 제작하며, 그전에는 은계 맵으로 테스트할 수 있다. 이 요구는 이전 자체 맵만 사용/독립 차량 구현 지침보다 우선한다.

## 코드 대조 결과
- Assets/Scripts/DriveSession.cs: WorldBuilder, TaxiController, DrivingCamera, DriveHUD, BusinessHUD, PassengerJobs, TrafficSystem, DrivingLaw, ServiceStops, VehicleDamageController 등을 생성한다.
- TaxiController.cs: Rigidbody/WheelCollider 기반 기존 조작과 물리다.
- Assets/Pvp/Runtime/PvpBootstrap.cs: 별도 맵/PvpPracticeSession/PvpNetworkSession을 실행한다. 기존 DriveSession을 실행하는 구조가 아니다.
- BusinessProgress.cs: 영업·저장·서비스·승객이 연결되어 있어 단순히 컴포넌트를 끄면 되는지 검증이 필요하다. 기존 규칙을 공유하되 경기 상태/저장 경로/권한은 분리해야 한다.

## 제안하는 진행 순서 (구현 전 검토안)
1. 기존 은계 시뮬레이션 화면·조작을 그대로 사용하는 PVP 실행 경로부터 연결한다. 기존 UI 컴포넌트를 사용하고 경기 시간/순위만 추가한다. 캠페인 날짜/이어하기 등 경기와 무관한 부분만 모드 조건으로 숨긴다.
2. 기존 승객·법규·내구도·시설 기능에 경기 상태를 연결한다. 승객 선점, 수익/운전 점수, 결과, 봇을 추가한다. 생활 요소/비용의 경기 적용 범위는 명시적으로 정하고 임의 삭제하지 않는다.
3. 기존 차량 물리를 대상으로 입력/권한/동기화를 재검증한다. 현재 평면 모터의 예측/보정 검사 통과는 재사용한 차량의 검증이 아니다. 네트워크 접속/재접속·원장의 재사용 가능 부분만 남긴다.
4. 은계 맵에서 한 창 봇 경기→두 Player 경기 검증. 화면/조작은 원본과 나란히 비교하고 싱글 저장/배포 보존도 검사한다.
5. 승인받은 새 맵을 기존 WorldBuilder/지도·교통·법규 로딩 구조로 제작한다. 기존 PvpExpandedMap을 계속 늘리는 방식은 중단한다.

## 새 맵 시안 (미확정)
| 후보 | 구조 | 경쟁 특징 | 주의점 |
|---|---|---|---|
| A 도심 격자+외곽 순환 (추천) | 중앙 역/상업지, 서쪽 주거, 동쪽 업무, 북쪽 병원/터미널, 남쪽 차고/시설. 내부 가로세로 연결과 외곽 간선 | 도심 짧은 운송 여러 건과 외곽 고액 운송의 선택, 혼잡 시 우회 | 중앙만 유리해지지 않도록 수요/운임/신호 검증 |
| B 양쪽 도심+연결 간선 | 두 생활권을 두 개 이상의 연결도로로 연결 | 권역 내 단거리와 권역 간 장거리 선택이 명확 | 연결도로 봉쇄/대기 편중 위험 |
| C 다핵 순환 도시 | 여러 작은 상권을 순환도로와 지름길로 연결 | 거점 분산과 순환 운송 | 단순 반복 주행으로 느껴질 위험 |

추천 A 개념 배치 (실제 차선/교차로 도면 아님):

    북서 주거 ── 병원/터미널 ── 북동 업무
        │           │             │
    서쪽 주거 ── 역/상업 중심 ── 동쪽 업무
        │           │             │
    남서 주유 ── 공원/상가 ── 남동 차고/정비

외곽에도 연결되는 순환 간선을 두고 내부에는 여러 대체 경로를 제공한다. 시설은 한 곳에 몰지 않고 운송 동선에서 선택할 수 있게 분산한다. 맵 크기/신호/거점 수는 후보이며 경기 시간은 10분으로 고정하지 않는다. 시안 선택 후 차선·진출입·정차 공간·보행 횡단·신호까지 포함한 상세 배치도를 제시한다.
