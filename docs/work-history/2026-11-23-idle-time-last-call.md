# 2026-11-23 운전 중 빈 시간: 정차 중 모아 보기·마지막 한 콜 (08 4장 2단계, 은계 싱글)

## 요구

자리 비움 중 일괄 진행 요청의 2단계. [08 재미 보강](../content-design/08-fun-improvements.md) 4장.

- 신호 대기처럼 멈춰 있을 때 승객 대화 선택지와 다음 호출 미리 보기를 모아서 보여 준다.
- 퇴근 전 마지막 한 콜: 숙소 방향 짧은 호출과 반대 방향 고액 호출을 함께 제시한다. 카드에 하차지→덕성프라자 복귀 거리를 보이고, 즉시 귀가도 가능해야 한다.
- 주행 중 응답을 강제하는 팝업은 만들지 않는다. 은계 싱글만 대상이다.

## 코드 대조

- 승객 요청은 `PassengerRequestUI`가 그린다(`HasPendingChoice`, `HasVisiblePanel`). 요청이 뜨는 시점과 응답 규칙은 바꾸지 않았다.
- 운행 알림 패널은 `ServiceLawZones`가 그리고, 맨 위 고정 줄(context)에 점유 안내·운전 평가·시설 대기열 상태를 넣는다(`DriveNotifications.DrawFeed`). 새 요약은 이 고정 줄을 쓴다. 기존 점유·운전 평가 안내가 있으면 그것이 우선한다.
- 숙소는 `ServiceStops.HasHomeBase`, `HomeApproach`(덕성프라자 진입 정차점)다. 귀가 안내는 기존 `GuideAfterTrip(2)`(귀가 주차장)를 그대로 쓴다.
- 남은 영업 시간은 `EconomyLedger.SecondsLeft`이고, 호출판 갱신은 `PassengerJobs.Update`의 조건에 따른다.

## 실제 구현 (`PassengerJobsCallBoard.cs`의 2단계 절)

- **정차 중 모아 보기** `StopBreakSummary()`:
  - 조건: 싱글, 손님 탑승, 도착 확정 전, 일시정지 아님, 1.5초 이상 시속 1.8km 미만(0.5m/s)으로 정지.
  - 내용: 답할 수 있는 손님 요청이 있으면 "손님 요청에 답할 수 있어요 · 요청 창에서 선택". 그리고 하차지에서 800m 안의 승차 지점 가까운 2곳을 거리·수요와 함께 "하차 후 가까운 승차 지점"으로 보인다.
  - 목적지 미공개 손님은 미리 보기를 숨긴다.
  - 움직이면 바로 사라진다. 버튼이나 응답을 요구하지 않는다.
- **마지막 한 콜** `ApplyLastCall()`:
  - 조건: 숙소가 있는 싱글, 남은 영업 240초 이하.
  - 호출판을 2건으로 바꾼다.
    - 숙소 방향: 운송 1,200m 이하 호출 중 "픽업 + 운송 + 귀가" 총거리가 가장 짧은 호출.
    - 반대 방향 고액: 하차지가 덕성프라자에서 1,500m 이상인 호출 중 운임이 가장 높은 호출에 운임 ×1.3. 없으면 가장 먼 하차지.
  - 카드에 "하차 후 덕성프라자까지 약 N m"를 넣는다.
  - 호출 목록 위에 "즉시 귀가 · 덕성프라자로 안내" 버튼을 둔다(지도 닫고 기존 귀가 안내).
  - 창에 들어가면 호출판이 바로 갱신된다(`LastCallDue`).
- 설정 툴 "운전 중 빈 시간" 묶음 8개(`stopBreak.*` 3, `lastCall.*` 5).

### 판단 기록 (임의로 정한 값)

| 항목 | 값 | 이유 |
|---|---|---|
| 모아 보기 위치 | 운행 알림 패널 맨 위 고정 줄 | 새 창을 띄우지 않고, 기존 화면 배치 검사(102건) 범위 안에 두는 가장 무난한 자리 |
| 다음 호출 미리 보기 | 하차지 주변 승차 지점 2곳·수요 | 실제 다음 호출판은 하차 뒤 차 위치로 만들어진다. 미리 확정할 수 없어 "가까운 승차 지점과 수요"로 대신함 |
| 승객 대화 선택지 | 대기 중임을 알리고 기존 요청 창으로 답함 | 요청 시점·기한 규칙을 바꾸지 않으려고 이동·재배치 대신 모아 알림 |
| 표시 지연 | 1.5초 | 신호 대기와 짧은 정체를 구분하는 최소 시간 |
| 마지막 한 콜 시작 | 남은 영업 240초 | 기본 20분 영업에서 한 콜(평균 2~4분)과 귀가를 고민할 시점 |
| 숙소 방향 기준 | 총 주행 거리 최소, 운송 ≤1,200m | "짧은 호출"을 귀가까지 포함한 일의 양으로 해석 |
| 반대 방향 | 귀가 ≥1,500m 중 최고 운임 ×1.3 | 첫 시도에서 "가장 먼 하차지"만 고르면 운임이 숙소 방향보다 낮게 나왔다(4,900원 대 7,800원). 고액이라는 요구에 맞게 바꿨다. |

## 남은 것 · 직접 확인

- 사람 플레이 체감은 확인하지 않았다. 신호 대기 중 요약이 실제로 읽히는지, 운행 알림 패널을 숨겼을 때(◀ 숨기기) 보이지 않는 점을 그대로 둘지 봐야 한다.
- 승객 요청 선택지를 정차 중에만 열도록 바꿀지(현재는 기존처럼 요청 창이 뜬다). 요청 기한 규칙과 얽혀 이번에는 바꾸지 않았다.
- 마지막 한 콜의 시작 시점(240초)과 반대 방향 운임 배율(1.3).
- 마지막 한 콜을 수락하지 않고 기다리면 같은 호출판이 유지된다. 영업 종료 뒤 처리는 기존 규칙을 따른다.
