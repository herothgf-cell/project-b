# 2026-10-29 승객 유형 통합·운행/상태 영향형 아이데이션

## 요청·결정

취객을 하나의 승객 유형으로 정리하고 택시 운행·상태에 영향을 주는 유형을 추가 아이데이션한다. 내구도·수리 기획은 사용자 1차 확인 완료. 이번 작업은 기획 문서만 변경하며 구현 착수는 포함하지 않는다.

## 실제 변경

- 승객 유형/개별 요청/사건/응대 방식을 분리. 취객을 진상의 하위 유형이 아닌 공통 주 유형으로 정의.
- 취객 포함11개 후보를 운행·시간·청결·경로·요청 연결 관점으로 정리. 현재 기능/새 제작 요소와 후보 채택 상태를 구분.
- 권장 첫 묶음은 취객·잠자는 승객·승차감 민감·재촉·경로 확인·용무/경유. 적재/오염·음식·정밀 승하차는 후속 후보. 채택과 수치는 사용자 검토 대기.
- 대표 요청이 필요한 유형은 기존0~2개 슬롯과 함께 배정. 요청0개/지도 후보 없음/호환 실패 시 배정 제외, 중복 평가 금지.
- 옛 비취객3종 균등 배정안을 가용 후보의 추후 가중치 결정으로 대체. 취객 빈도 보완 시험안은 유지.
- 내구도·수리는 사용자 1차 확인 완료로 상태를 갱신, 기존 손상/수리 수치·코드 불변.

- 추가 사용자 예시 반영: 잠자는 승객을 비취객 독립 유형으로 추가하고 미리 부탁/대화 중 수면/얕은 잠/깊은 잠4변주, 기존 기상 흐름 공통화·도착 운임 보호를 기획.

## 이어갈 작업

승객안의 후보 표에서 채택할 유형과 작업 대기/오염 범위를 선택한 뒤 상세 구현 계획을 만든다. 내구도 수리는1차 확인 완료지만 구현·체감 검증은 남아 있다. 기본 실행은 builds/EungyeTaxi/EungyeTaxi.exe / 은계, BuildHybrid. 필수 로컬 지도 입력은 기존 인계 유지, Strict 재실행 없음. 이번 제안은 현재 실행 파일에 반영되지 않았다.
