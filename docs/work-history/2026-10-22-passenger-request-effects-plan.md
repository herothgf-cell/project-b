## 보너스 금액 기준 수정 (같은 날, 최신)

사용자 결정에 따라 보너스 금액은 고정 비율 전액이 아니라 **요구 만족도 초과분**에 비례한다. 기존 매너 점수 `M`과 요청 이행 변화량 `Δ`로 최종 만족도 `S=clamp(M+Δ,0,100)`을 만들고, 승객 요구 점수 `R`에 대해 `E=max(0,S-R)`, `지급 비율=E/(100-R)`을 적용한다. 범주별 운임 비율·최대 금액 상한은 그대로 유지한다. 완주·기본 운임 전액·요청 이행·확정 법규 위반 없음 조건도 유지한다.

기존 +20/+10/+15 증가는 특히 요구85점 운송을 대부분 즉시100점으로 만들어 초과분별 보너스 차이를 없애므로 테스트 초깃값을 DR +8/-10, CH +5/-5, EV +6/-8로 조정했다. 최종 약정5,000원·요구85점·기본 매너85점의 DR 이행은 최종93점, 500원 상한×8/15의 10원 내림인 **260원**이다. 기본 운임 판정에는 기존 매너 점수 `M`만 쓴다. 문서만 수정했으며 새 계산의 코드·빌드·자동/수동 검증은 미실시다.

실행 대상은 기존 `builds/EungyeTaxi/EungyeTaxi.exe`, 빌드는 `PrototypeBuild.BuildHybrid`다. 지도 원본·생성 입력·빌드·배포 manifest는 변경하지 않았다. 작업 시작 시 다른 코드·문서·빌드 변경이 이미 있었으며 덮어쓰지 않았다. 이 문서는 기획 검토와 다음 개발의 재현 기준으로 사용한다. 실제 커밋이 필요하면 이 기록 파일에 대해 `git log -1 --oneline -- docs/work-history/2026-10-22-passenger-request-effects-plan.md`로 확인한다.
