# 두 직접 회전 경로의 차로변경 연결 복구

## 요청과 위치 대응

새 플레이 제보의 서쪽 접근 좌회전과 북행 후 우회전을, 실제 출발 차로를 유지하는 공통 그래프 연결로 복구한다.

- 이미지1 원: `J7973_3744`, 게임 `(797.331,374.396)`, 위경도 `37.4374007,126.8044880`.
- 이미지2 원: `J8066_6364`, 게임 `(806.645,636.377)`, 위경도 `37.4397614,126.8045871`.
- 이미지3는 J7973 남쪽 접근, 이미지4는 식당 남서쪽 `J5750_2576` (`37.4363443,126.8019787`)에 대응한다. 이미지4는 식당/J7973/차량의 미니맵 상대 좌표와 동쪽 연결도로 형상을 대조했다.

초기 분석에서 이미지1/2를 각각 한 블록 북쪽 J8066/J7801로 잘못 대응했다. 최초 `artifacts/direct-turn-red.log`의 실패는 잘못된 위치 fixture에 대한 결과이므로 제보 재현 근거로 쓰지 않는다. 식당과 도로 형상으로 위치를 정정한 뒤 다시 RED를 확인했다. 당시 J6481로 제시했던 이미지4 후보도 철회했다.

## 원인과 구현

서쪽 일반3차로 `A2218G611417:3`와2차로 `A2218G611415:3`,1차로 `A2218G611416:2`의 후반 약84.7m에는 차로변경 연결이 없다. 1차로 끝의 기존 분기 `A2218G611426:0`를 통해91번 좌회전 포켓에 들어가는 연결은 이미 있다. 포켓은 `A2218G611432:0` → `A2218G611439:0` → `A2218G611886:0` → 좌회전 `A2218G611452:0`로 이어진다. 포켓 진입을 새로 추측한 것이 아니라, 일반3→2→1 이동 누락을 복구한다.

J7973에서 J8066으로 가는 북행3차로의 후반 약176m에도 변경 연결이 없다. 기존 초입10~42m의1→2 변경을 이용한 뒤에는2→3 변경 출발점10m가 이미 뒤여서, 다음 교차로의 기존3차로 우회전으로 갈 수 없다.

`PlaytestLaneChangeRepair.Apply(package,northEvidence,westEvidence)`는 별도의 관찰 근거를 받아 문서 복사본에 다음14개 연결을 작성한다.

- 서쪽3→2: 해당 캡처 조각12~36m,2→1:48~72m. 각각24m이며 기존 좌회전 포켓 분기 전에 완료한다.
- 북행 인접 차로 양방향: 후반 조각20/70/120m에서 각각32m 길이, 총12개.

기존 HD 캡처 조각의 `sourceOffset` 약38m를 보존하여 편집기 lineage API에는 전역 source 거리를 전달한다. 기존 편집기 분할 연산으로 시설·신호·서비스 참조를 이관하고, 문서 전체 검사와 차량 footprint의 도로/보도/건물/물 검사를 수행한다. runtime 시작점 변경이나 가까운 차로로 재배치하는 보정은 추가하지 않았다. helper 자체는 파일을 저장하지 않는다.

## 변경 파일과 검증

- `unity/EungyeTaxi/Assets/Editor/PlaytestLaneChangeRepair.cs`
- `unity/EungyeTaxi/Assets/Editor/PlaytestDirectTurnTests.cs`
- 본 기록

정정된 RED는 `artifacts/direct-turn-corrected-red.log`에서 J8066 직접 우회전 누락, `artifacts/direct-turn-west-red.log`에서 기존 좌회전 `A2218G611452:0` 미사용으로 각각 종료1이었다. 구현 중 첫 preview는 HD의 비영 sourceOffset을 상대 거리로 처리하여 실패했고, 해당 거리 변환을 수정했다.

부모 작업자가 단일 Unity 프로세스로 `-executeMethod PlaytestDirectTurnTests.Preview -batchmode -nographics -quit`를 실행했다. `artifacts/direct-turn-final-preview.log`는 종료0, `PLAYTEST_LANE_CHANGE_PREVIEW_OK`이다.14개 연결의 문서/차량 footprint 검사, 원본 문서 불변, 근거 누락 거절, 요청한 첫 회전 사용, 북쪽 J7801 미진입을 확인했다.

| 회귀 출발 | 복구 preview 경로 길이 |
|---|---:|
| 서쪽 일반3차로 조각8m | 915.38m |
| 기존 서쪽 좌회전 포켓 | 742.73m |
| 북행1차로 후반 조각40m | 590.92m |

`git diff --check`의 해당 변경 검사도 종료0이었다. Preview의 합성 관찰 fixture URL은 테스트 복사본에서만 사용하며 저장하지 않는다. 정식 지도 저장에는 부모 작업자가 직접 확인한 Naver 근거 두 개를 사용한다.

## 작성 시점의 남은 작업

이 기록은 **preview 검증 시점**에 작성했다. 정식 프로젝트 JSON 적용·해시 갱신·Resources 준비·최종 Run·통합 빌드/배포 검사는 부모 작업자의 후속 이력에서 실제 명령과 결과로 기록한다. 이 기록만으로 기본 실행파일에 적용됐다고 판정하지 않는다.

실제 차량의 자동 물리 통과, 사람의 수동 플레이, 전체 캠페인 검증은 이 preview가 수행하지 않았다. 마지막 변경 창을 이미 지난 위치에서 직접 회전을 보장하지 않으며 정상 재탐색을 유지한다. 과거 진단의 다른 남하/북서 연결 부족을 전부 해결한 것으로 확대하지 않는다. 필수 입력 지도·ZIP·배포 바이너리는 이 하위 작업에서 변경하지 않았다.
