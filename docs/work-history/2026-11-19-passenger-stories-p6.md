# P6 손님 이야기와 기사 수첩

기획30, 아버지 수첩 기획33, 기사 수첩 시안을 기준으로 P5 배포 f352756 뒤에 작업했다.

- 은계 경력의 탑승 조건에 맞는 프리셋으로 10편을 배정한다. 좋은·보통·아쉬운 결말을 하차 영수증과 기사 수첩에 남긴다. 상가 행사와 금요일은 관련 이야기 비중을 높인다.
- 아버지 탭과 함께 이야기 30칸, 처음 태운 승객 프리셋, 12개 동네, 12개 영업 기록을 표시한다. 동네는 승하차 기록 합 3·10·25회로 열린다. 별 3곳을 모으면 아버지 수첩 비 오는 날 페이지를 여는 또 하나의 조건을 달성한다.
- 캠페인 형식 8의 수첩은 이미 확인한 결말과 대사, 최초 탑승, 운송 지점 횟수·영업 기록을 보존한다. 이전 운송 기록에는 저장된 출발·도착 지점과 확정된 일차 법규만 사용한다.
- 기존 CasualUI와 KoreanText를 사용한다. 지도/교통 원본 입력을 수정하지 않는다.

주요 변경은 PassengerStories·PassengerJobs·PassengerRequest, BusinessProgress·CampaignLogbook, LogbookHUD·RideCompletionPanel, 콘텐츠 편집기와 테스트 도구다.

## 검증과 재현

- 콘텐츠 및 수첩 모델 `tools/test_content_tuning.ps1` 1,440건, 편집기 Node 107건, C#/Node UTF-8 및 이전 프로필 이관 해시 일치. 배정 상한·가중치·설정 검증·결말과 수첩 별 진행을 포함한다.
- 승객 로스터 2,864, 행동 707, 특성 46, 구성 73, 상황 82, 개별 설정 42, 차량 관리 13,301, 정차 41, 대화 표현 16, 선택 효과 50건.
- `tools/test_passenger_reactions.ps1`는 다음 요청의 실제 이동 20초 대기 기대값에서 종료 1. P5 배포 f352756의 원본으로 같은 단독 검사를 재컴파일해 동일 실패를 확인했다.
- 수첩 지도 범위 16·수요 문구 3·카드 배치 84건을 모델로 확인했다. 지도 원본에 변경이 없다.

- 맨 처음 P6 빌드의 `ApprovedEungyeRoads.VerifyAndBuild` 종료 0, 승하차 39곳·1,482경로 및 r14~r46 저장 이관 1,063건. 같은 후보의 승객 특성 Player 86건, 승객 행동 위치 제어 92건과 재실행 6건. P5 배포본에서 운송 중 저장 9건을 생성하고 P6 후보에서 복원 23건을 통과했다.
- 저장 위치 검사와 이야기별 승하차 검사를 보완해 최종 `PrototypeBuild.BuildHybrid` 종료 0. `tools/test_passenger_stories_player.ps1` 42+9+142건. 10편의 3가지 결과를 통제된 판정값으로 검사했다. 20회 실제 위치 제어 승하차에서 좋은·아쉬운 결말을 모두 영수증과 수첩에 기록했고, 일부 요청 판정은 검사에서 주입했다. 막차 학생의 실제 요청 선택·운송 중 저장·별도 프로세스 계속·하차를 확인했다.
- 숨긴 창의 영수증 캡처는 검은 화면으로 저장돼 렌더링 품질 판정에는 사용하지 않았다. 사람이 운전한 캠페인 체감 검증은 남아 있다. 필수 지도 입력 Strict 문제 0.

통합 실행본 → 은계 싱글로 영업한다. 운행 중 손님의 요청에 응답하고, 하차 영수증과 일시정지 메뉴 또는 숙소의 기사 수첩을 확인한다. 다음 개발은 P7 낮밤 조명·라디오 자막이다.
