# 2026-11-24 기획서 목록과 현황 (문서만)

## 요구

- 기획서 전체를 한눈에 보는 목록을 만든다. 예시 형식은 다른 저장소의 추가 기획서 목록(`index.html`: 문서 목록 → 구현 현황 → 검토 중인 제안 → 개선점 목록 → 문서 사이의 관계 → 미결 결정 방식 → 수정 기록)을 따른다.
- 내용이 많으므로 상위 카테고리 밑에 하위 카테고리로 나누고, 문서·장 단위로 링크한다.
- 항목마다 구현(배포 실행본 반영 여부 포함), 미결(결정 대기·승인 전·설계안), 개선 필요(사람 플레이 미확인, 알려진 실패, 피드백 대기)를 정리하고 근거 기록을 붙인다.
- `docs/content-design/README.md`와 `docs/CURRENT-STATE.md`에서 링크한다.

## 실제 구현

- 새 문서 [기획서 목록과 현황](../content-design/INDEX.md). 이름은 예시의 `index`를 따르되, 이 저장소의 대문자 문서 이름(`README.md`, `LATEST.md`)에 맞춰 `INDEX.md`로 했다. 형식은 이 저장소 기획 문서와 같은 Markdown이다.
- 구성: 상태 표기 → 문서 목록(00~09·PvP·보관) → 기획 항목별 현황(A 전체·이야기, B 운전 3묶음, C 손님 4묶음, D 생활·차량 4묶음, E 화면, F 하루·경력, G 다음 단계 후보 3묶음, H PvP, I 색인·보관·제안서) → 08 진행 순서 → 결정 대기 9건 → 개선점 목록 12건 → 문서 사이의 관계 → 결정 방식 → 수정 기록.
- 상태의 근거: `LATEST.md`, `CURRENT-STATE.md`, 개발 체크리스트, 08과 각 담당 문서의 구현 표시, 2026-11-19~24 작업 이력(상세 기획, 확인 목록의 결정 기록, 자리 비움 체크리스트, 돌발 1차의 미검증 항목).
- 같은 시각 다른 작업이 미커밋으로 고치던 것(직접 플레이 피드백 3차, 유혹)은 "진행 중"으로 적었다. 그 작업이 커밋되면 이 문서의 해당 줄을 "구현·배포"로 바꿔야 한다.
- README의 문서 목록 안내 문장과 CURRENT-STATE의 첫 줄 링크 묶음에 링크를 하나씩 더했다.

### 추가: HTML 보기 (사용자 요청)

- `docs/content-design/index.html`: INDEX.md를 예시와 같은 카드·표 모양의 HTML 한 장으로 만들었다. 상태 칸에 색 배지(구현·배포, 구현·소스, 진행 중, 미결, 보류·제외, 개선 필요)를 붙이고, 머리말의 버튼으로 상태별로 걸러 본다. 밝은/어두운 화면을 따른다.
- `tools/render_design_index.py`: 생성 스크립트. 내용은 INDEX.md만 고치고 `python tools/render_design_index.py`로 다시 만든다.
- 확인: 앱 내 브라우저에서 열어 표 행 136개, "미결" 필터 31행 표시, 페이지 안 `#` 링크 깨짐 0건.

## 검증

- INDEX.md의 상대 링크와 앵커를 스크립트로 대조했다(파일 존재, `<a id>`와 제목 앵커). 이 기록 파일을 만든 뒤 깨진 링크 0건.
- 코드·빌드·지도는 바꾸지 않았다. 게임 실행이나 사람 플레이는 이 작업과 무관하다.

## 미검증 / 남은 것

- 상태는 2026-11-24 문서 기준이며 코드와 하나하나 대조하지 않았다. 문서와 코드가 다르면 코드가 맞다.
- GitHub 제목 앵커는 GitHub의 규칙을 흉내 낸 스크립트로만 확인했다. 웹에서 눌러 보지 않았다.
- 피드백 3차·유혹 작업이 커밋되면 B3·E·G2·구현 현황·개선점 목록의 "진행 중" 줄을 고친다.
- 새 작업을 끝낼 때 이 목록의 해당 줄과 수정 기록도 함께 고치는 것을 규칙으로 둘지는 사용자 결정이다.
