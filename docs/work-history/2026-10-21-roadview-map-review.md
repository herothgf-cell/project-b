# 네이버 거리뷰를 이용한 은계 맵 대조 방식 확인

## 요구

정밀도로지도가 없는 은계 내부 도로를 담당자가 네이버 지도 거리뷰에서 직접 살펴보고 게임 맵 정비에 활용할 수 있는지 쉽게 설명하고, `docs/map-polish-plan.md`에 그 작업 주체와 순서를 명시한다.

## 실제 변경

- `docs/map-polish-plan.md`: 담당자가 게임 좌표로 네이버 지도에서 주변 거리뷰를 양방향 확인하고, 촬영 시점과 차로·표지·횡단보도 등 보이는 항목을 구간ID별로 기록하는 단계를 추가했다. 거리뷰 확인과 게임 안 자동·수동 주행 검사를 구분했다. 사용자에게 사진 제공을 요구하지 않는다는 점을 명시했다.
- 사용자 요청에 따라 이번 채팅은 계획 정리까지만 수행하고, 다음 채팅에서 동선 선정·거리뷰 대조표 작성부터 시작하도록 인계 항목을 적었다.
- `docs/work-history/LATEST.md`: 이 확인과 남은 구간별 검토 작업을 인계했다.
- 지도 원본, 차로 설정, 생성 지도, Unity 빌드는 변경하지 않았다.

## 수행한 검증과 결과

- `config/maps/eungye.json`의 T1 EPSG:5186 좌표 `(182339.594, 538545.811)`을 EPSG:4326으로 변환해 약 `(위도 37.446146, 경도 126.800422)`임을 확인했다.
- 네이버 지도에서 해당 좌표를 검색한 후 T1 근처 계수로의 거리뷰를 직접 열었다. 화면의 촬영 시점은 `2026년 05월(최신)`이었다. 해당 근처 장면에서 중앙 분리시설, 차선, 보행 공간을 육안 확인했다.
- 문서 변경은 `git diff -- docs/map-polish-plan.md`로 확인했다. 자동 검사, Unity 빌드, 게임 수동 플레이는 수행하지 않았다.

## 미검증·남은 항목

- T1 정확한 교차로의 각 접근 방향, T2·T3 및 우선 시험 동선 전체는 거리뷰를 아직 대조하지 않았다. 이번 관찰을 실제 차로 수·회전 규칙·정지선의 확정 근거로 쓰지 않는다.
- 다음에는 짧은 영업 동선을 확정하고 구간ID별로 거리뷰 양방향 대조표를 만든다. 그 결과를 좌표 도형과 대조해 설정을 보정한 뒤 별도의 자동 주행·수동 플레이로 게임 작동을 검사한다.

## 실행·재현

1. `config/maps/eungye.json`의 T1 좌표를 EPSG:5186에서 EPSG:4326으로 변환한다.
2. 네이버 지도에서 `37.446146, 126.800422`를 검색해 주변 거리뷰 표시를 켠다.
3. 계수로의 거리뷰를 열어 촬영 시점과 각 방향의 시설을 살펴본다. 해당 장면은 교차로 전체 검증과 구분한다.
