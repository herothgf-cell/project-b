# 프로토 콘텐츠 구현·검증 기록

2026-10-16 · 작업 브랜치 `codex/prototype-content`

전체 P0~P3 완료 보고가 아니다. 구현한 기능과 아직 완료 기준을 충족하지 않은 작업을 구분한다. 원본 지도 자료와 기존 `campaign-v1.json`은 변경하지 않는다.

## 실행과 조작

`Play-Eungye.cmd` 또는 `builds/EungyeTaxi/EungyeTaxi.exe -eungye`로 실행한다. 새 도전은 3일 × 480초, 시작 현금 10,000원, 순수익 목표 30,000원이다. 시작 현금은 수익에서 제외하고 미납을 차감한다. 보험 갱신과 세금 납부도 성공 조건이다.

| 입력 | 추가 기능 |
|---|---|
| F5 | 빈차·정차 상태에서 가상 출구 대기열 시작/종료. 실제 일반 차량 8대가 신호·추종 로직으로 대기하고 출발 |
| F6 | 빈차·정차·교차로 80m 밖에서 가상 우회전 조건 변경. R1/R2/R3/R4/R5 의도/R5 횡단/끄기 |
| F7 | 빈차·정차 중 거점 안내·결제. 메뉴에서는 시간 정지 |
| F8 | 독립 법규 기록. 승객 매너와 별도이며 사건당 최대 감점 한 번 |
| Y / U | 승객 요청 수락·응답 / 안전상 보류 |
| N | 정차 후 영업 마감. 탑승 승객은 기존 운송 기한까지 처리 |

F5/F6는 검증용 가상 신호 운영이다. 실제 은계 시설/신호주기로 주장하지 않는다. 두 상황은 동시에 켤 수 없다. F5 생성 조건에 맞는 충분히 긴 다차로 접근로가 없으면 생성하지 않는다. F6의 보행자는 장면 시작 때만 나타나고, 진행 중 갑자기 반복 생성하지 않는다.

거점은 이미 연결된 오른쪽 승하차 지점을 재사용한다. 실존 업소의 위치가 아니다.

| 임시 주유소 | 은계 승하차 4 | 1158.78 / 805.60 | 783 |

우회전 상황은 `(575,257)` 근처의 기존 신호 교차로를 사용한다. 출구 상황은 현재 통합 그래프의 긴 우회전 접근로를 선택한다. 고정된 출구 장면과 양쪽 대안 경로의 수동 운송 검증은 남아 있다.

## 공통 상태·저장 경계

- `PrototypeSettings`: 3일·480초·30,000원, 비용·연료·법규 감점 제안값.
- `PrototypeIds`: 캠페인별 운송·사건·결제 ID. 운임은 운송 ID로 중복 방지한다.
- `LawLedger`: 빈차와 탑승 모두 기록하며, `Compliant/Violation/Deferred/NoOpportunity`를 구분한다. 같은 사건의 여러 규칙은 최대 감점 한 번만 적용한다. 매너·운임 API를 호출하지 않는다.
- `CampaignAccount`: 현금 변동과 부채 변동을 별도로 기록한다. 세금 미납 인식과 실제 납부를 구분하며 부채 상환을 다시 비용 처리하지 않는다.
- `campaign-v2.json`: 일일 장부·거래·연료·법규·ID를 하나의 파일로 저장한다. 임시 파일 작성 후 교체하며 `.bak`을 유지한다. 기존 v1은 읽거나 덮어쓰지 않는다.
- 저장 위치: Unity `Application.persistentDataPath` 하위. 이 프로젝트의 Windows 기본 경로는 `%USERPROFILE%/AppData/LocalLow/Taxi Prototype/영통 택시 시뮬레이터/`이다.
- 진행 중인 하루는 저장하지 않는다. 새 도전/완료 정산 체크포인트로 돌아간다. 정산 후 보험 갱신 시에는 해당 정산 항목도 재계산해 저장한다.
- 테스트는 `artifacts/campaign-v2-test.json`을 사용하여 사용자 저장 파일과 분리한다.

준비 화면에서 직접 갱신/납부할 수 있다. 메뉴 이용을 취소하면 비용·영업 시간이 변하지 않는다. 3일차 세금은 정산 전에 납부 여부를 묻고, 미납을 선택하면 현금 자동 출금 없이 부채가 된다. 보험 갱신 자금 부족으로 다음 날 출발이 막혔을 때는 새 도전 버튼을 제공한다.

우회전 사건의 연습 버튼은 별도 Player 창을 실행한다. 원래 게임은 멈춘 상태로 유지하고 연습 창은 사용자 저장을 읽거나 기록하지 않는다. 준비한 R 조건과 저장된 출구 대기열 경로를 연결했다. 출구 경로 배열은 사건 기록에 복사해 보존한다. 전체 복습 복귀의 수동 확인 전이므로 P1-06을 완료로 표시하지 않는다.

- P0: 같은 최종 빌드의 수동 입력·실물 패드·시점 전환과 거점 왕복 확인.

- P2: 전체 영업 흐름에서 거점 진입/복귀·필수 제동 예외와 요청 응답 기회 검증.
- P3: 정상·우회·위반 선택의 3일 플레이 비교, 종료/재실행 롤백과 새 PC 재현 검증.

## 후속 검증: 출구 운송·우회전 위치·3일 캠페인

체크리스트의 `[x]`는 해당 완료 기준을 구현하고 검증한 항목이다. `[ ]`에는 구현이 있어도 전체 기준의 검증이 남아 있을 수 있다.

재현 후 수정한 문제:

- 우회전 판정이 노면 횡단보도 시작보다 3.4m 뒤에서 발생했다. 그리는 코드와 판정 코드가 `CrosswalkCentreOffset`, `CrosswalkDepth`를 공유하도록 변경했다. 차량 앞부분이 실제 시작 경계를 넘을 때 보행 상태를 평가한다.
- R5 보행자가 차량 접근 전에 사라졌다. 조건을 선택한 후 접근 범위 85m에 들어왔을 때 진행 시간을 시작한다.
- 비신호 교차로에 가상 신호를 켜도 AI가 무시했다. 가상 신호가 켜진 동안에는 차량과 법규/매너 관찰이 해당 신호를 사용한다.
- 우측 출구를 빠져나가도 사건이 끝나지 않았다. 오른쪽 출구 통과 조건을 추가했다.
- B 우회 한 번이 14개 사건으로 중복 기록됐다. 같은 준비 장면은 한 번만 기록하고, 새 장면을 준비하면 다시 관찰한다.
- A의 정상적인 뒤차 추종을 이후에 통행 방해로 잘못 잡았다. 진입 직후의 반응을 관찰하되, 앞부분에 끼어든 차량이 진입 위치를 계속 점유하면 신호 해제 후 실제 방해도 관찰한다.

검증 방법은 구분한다. `ContentFlowSmokeTest`는 정지선/횡단보도 좌표를 제어하는 관찰 검사다. `ExitTransportSmokeTest`는 A/B/C 접근부를 좌표 제어한 뒤 실제 Rigidbody와 조향 보조로 목적지까지 운송한다. 전체 구간의 수동 운전 또는 대기열 속 물리 추종을 검증한 것으로 부풀리지 않는다. `CampaignDriveSmokeTest`는 날짜당 출발 위치를 배치하고 실제 물리 운송, 정상 운임, 거점 주유, 실제 게임 시계 480초와 마지막 탑승 운송 이후 정산을 검사한다. 일반 차량은 제거하고 보험/세금은 UI와 같은 계정 API를 호출한다.

초기 캠페인 실패도 보존했다. `artifacts/campaign-drive-initial-failure.txt`는 신호 무시·감점 요금과 3일차 연료 고갈로 최종 순수익 6,720원에 실패한 실행이다. `artifacts/campaign-lawful-route-stop-failure.txt`는 첫 신호 대기 검사 운전자가 일부 정지선을 놓친 실행이며 준수 운행의 근거로 사용하지 않는다. 운임이나 목표액을 검사에 맞추어 변경하지 않았다.

### 정지선 미세 흔들림 회귀 수정

정지 중 앞 범퍼가 경계를 미세하게 넘으면 적색 진입 상태가 저장되어, 녹색 출발 이후에도 위반으로 처리되는 문제를 재현했다. 법규와 매너 관찰에 같은 0.25m 진입 허용치를 적용했다. `ContentFlowSmokeTest`에서 수정 전 실패를 확인했고 최종 빌드에서 정지선 흔들림→녹색 출발은 무위반, 실제 적색 진입→뒤늦은 녹색은 위반으로 모두 통과했다. 이 값은 게임 물리 오차 보정이며 현실 법규의 허용 거리라는 의미가 아니다. R1 미정지 통과와 R2~R5 관찰도 모두 통과했다.

최종 Editor 빌드 근거: `artifacts/content-editor-build.log`의 성공 종료, `content-flow-test.txt`의 `success=True`와 Player 종료 코드 0. C# 모델 5종과 Python 34개 검사도 재통과했다.

캠페인 검사 자체의 세금 창 대기도 수정했다. 마지막 운송 결과 대기 중 세금 질문이 열리면 게임 시간이 멈추므로, 검사 운전자도 결과 대기를 종료하고 납부 응답을 처리해야 한다. 제품의 세금 창을 우회하거나 자동 납부로 바꾸지 않았다.

검사 이름의 `lawfulDrive`는 신호 제동을 켠 자동 운전자 옵션이다. **무위반 완주를 보증하지 않는다.** 각 날짜 법규 점수는 80점이며 J7917_2565와 J7973_3744에 적색 진입 관찰이 남았다. 독립 법규 점수로 운임을 직접 깎지는 않는다. 이 결과는 물리 운송·비용·마지막 운송·3일 정산·성공 조건의 통합 증거이며, 모든 신호를 준수한 정상/우회/위반 선택 비교는 P3-05에 남긴다. 일반 차량 부재, 출발 위치 배치, 납부 API 호출이라는 자동 검사 한계도 유지한다.

동일 최종 빌드에서 `-campaignTest`도 종료 코드 0/`success=True`로 완료했다. 저장 실패·재시도, 보험 부족 출발 차단, 연료 고갈 지원, 세금 질문·미납 부채·미완납 성공 차단을 확인했다. 최종 `-exitTransportTest` 역시 종료 코드 0/`DONE`으로 세 선택의 1회 판정과 목적지 운임 지급을 재확인했다.
