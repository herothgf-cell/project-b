# 승객 요청별 실제 성공·실패 판정

2026-11-06 현재 코드 조사. 아래는 실제 구현이며 새 판정 규칙을 제안하거나 적용한 문서가 아니다. 관리창은 선택지별 결과 효과를 편집하지만, **어떤 조건에서 성공/실패/판정 불가가 되는지는 게임 코드에 고정**되어 있다. 선택지마다 효과값은 달라도 같은 요청의 수락 응답들은 요청 종류의 판정을 공유한다.

## 먼저 구분할 상태

- **이행 성공**: 수락/응답 후 정상 도착 평가에서 성공 결과 효과를 적용한다. 대화형 요청의 ‘성공’은 대부분 답변 완료를 뜻하며, 운행 중 약속 준수를 계속 검사했다는 뜻이 아니다.
- **이행 실패**: 실제 실패 조건에 해당하면 해당 선택지의 실패 결과 효과를 적용한다. 현재 카탈로그에 실패 효과가 있는 요청은 Comfort·OnTime·SafeStop·DestinationChange·ViaStop5종이다.
- **판정 불가/보류**: 안전한 보류 또는 근거 부족/시스템 개입으로 중립 결과를 적용한다. 기본 효과는0인 경우가 많지만, 지원되는 중립 결과의 효과는 독립 편집할 수 있으므로 ‘항상0’과 같지 않다.
- **미응답**: 선택지를 끝까지 고르지 않은 별도 상황이다. 안전한 응답 기회가 기록되었을 때 Quiet의 M, Empathy/Interview/LocalChat의 S 미응답 설정이 적용된다. 기회가 없거나 요청이 제시되지 않았으면 미응답 감점이 없다. 보류 버튼을 누른 결과와 다르다.
- **운송 중단**: 도착 확정 전 취소·사고·견인·피로 하차 등은 선택 효과를 중단한다. 요청 실패 효과를 일괄 지급하는 분기가 아니다. 이미 도착 확정해 정산한 뒤의 중단과 구분한다.

## 17종의 현재 판정

아래 ‘성공’은 요청을 수락/응답하고 도착 평가까지 진행한 경우다. 시스템 강제 경로 보호가 걸린 경로 요청은 표의 성공/실패 조건보다 먼저 판정 불가로 확정된다.

| 요청 | 이행 성공 조건 | 이행 실패·판정 불가와 없는 이유 |
|---|---|---|
| 조용한 운행 (Quiet) | 조용히 운행 수락 후 정상 도착. 별도 위반 검사 없이 성공 처리 | 실패 분기 없음. 수락 시 후속 대화 제한을 자동 설정하지만, 나중의 약속 위반 행동을 감지·기록해 실패시키는 관찰기가 없음 |
| 예상 도착 안내 (Eta) | 빠름/내비/여유 중 예상시간 안내를 선택하고 도착 | ETA 오차는 결과 설명만 기록하고 실패로 만들지 않음. 신호·교통·우회에 따라 달라지는 ‘예상’ 안내로 구현 |
| 편안한 운행 (Comfort) | 수락 이후 급가속·급제동·충돌 사건 수 증가가0 | 하나라도 증가하면 실패. 필요한 안전 제동은 이 사건 수에서 제외. 수락 전 사건은 제외하며 개별 M 감점과 종료 효과는 별도 |
| 제시간 도착 (OnTime) | 도착 때 남은 기한이0초보다 크고, 해당 요청이 시작된 뒤 확정 법규 위반0건 | 확정 위반이 있으면 실패(기한 내라도 실패). 위반 없이 늦은 경우는 정당한 대기/우회 사유를 구분할 관찰이 부족해 판정 불가. 법규 감점이0이어도 위반 판정은 셈 |
| 큰길 (LargeRoad) | 수락 뒤 측정 주행거리1m 초과이며 실제 큰길 비율 +15%p ≥ 안내 큰길 비율. 큰길은 현재 도로 폭12m 이상 | 비율 미달·관찰 부족은 실패가 아닌 판정 불가. 합법적인 우회와 불필요한 이탈을 구분할 관찰이 없음 |
| 짧은 길 (ShortRoad) | 수락 뒤 실제 주행거리1m 초과이고 안내거리×1.25+30m 이하 | 거리 초과·관찰 부족은 판정 불가. 필요한 우회를 단순 거리 초과만으로 감점하지 않음 |
| 안전 하차 (SafeStop) | 수락 때 정한 안전 목적지에서 실제 정차·하차 조건 충족 | 지정 지점 조건 미충족이면 실패 분기 존재. 다만 일반 진행은 변경한 목적지에서 정차해야 하차 평가가 열리므로 보통 성공만 도달. 대안 없으면 수락 자체가 성립하지 않음 |
| 공감 (Empathy) | 이야기 듣기/조용한 배려 중 응답을 선택하고 정상 도착 | 실패 분기 없음. 답변 완료로 평가하며, 실제 대화를 계속 들었는지·공감 약속을 어겼는지는 추적하지 않음. 미응답은 별도 |
| 경로 추천 (RouteAdvice) | 고른 빠른 길/짧은 길 설정이 유지되고 큰길 우선 설정이 꺼져 있음 | 경로 선호가 바뀌면 사유 불명으로 판정 불가. 안내 시간/거리와 실제 차이 자체로 실패시키지 않음 |
| 면접 응원 (Interview) | 격려/조용한 준비 배려 응답을 선택하고 정상 도착 | 실패 분기 없음. 응대 완료만 검사하며 면접 결과나 응원 효과를 평가하지 않음. 미응답은 별도 |
| 음악 (Music) | 음악 관련 안내 응답을 선택하고 정상 도착 | 실패 분기 없음. 실제 음악 재생/변경 기능이 없고 텍스트 응대만 제공하므로 음악 상태를 검증할 수 없음 |
| 운임 안내 (FareHelp) | 요금 안내/하차 때 결제 확인 응답을 선택하고 정상 도착 | 실패 분기 없음. 응대 완료이며 실제 결제 수단 이행·지불 가능 여부를 별도 요청 목표로 추적하지 않음 |
| 지역 대화 (LocalChat) | 지역 응답/안전 운행 안내를 선택하고 정상 도착 | 실패 분기 없음. 짧은 대화 완료를 평가하며 발언의 사실성·후속 대화 질을 검증하지 않음. 미응답은 별도 |
| 목적지 변경 (DestinationChange) | 수락해 변경한 목적지의 실제 정차·하차 조건 충족 | 지정 지점이 아니면 실패 분기 존재. 일반 진행은 변경한 목적지 조건을 충족해야 하차 평가가 열려 실패가 발생하기 어려움 |
| 경유 용무 (ViaStop) | 약속한 경유 정차·용무 대기를 마쳐 경유 대기가 해제되고 원래 목적지에 도착 | 경유가 남으면 실패 분기 존재. 일반 진행은 경유 미완료 중 최종 하차를 허용하지 않으므로 보통 실패 평가까지 도달하지 않음. 기존 구 저장의 용무 대기 소급 면제 예외는 유지 |
| 분실물 (LostItem) | 일반 요청 성공/실패 평가 대상 아님 | 일반 추첨에서 제외되는 하차 후 조건부10% 텍스트 사건. 보관·신고 안내 기록만 있고 물품 인도/반환 임무 및71개 선택지 효과 없음 |
| 불법 요구 거절 (RejectIllegal) | 안전한 거절 응답 후 요청 시작 뒤 확정 위반 없이 도착 | 실제 위반이 있으면 요청은 판정 불가. 법규/M 기록에서 별도 평가하며 요청 실패를 중복 적용하지 않음. 불법 요구 수락 선택지는 없음 |

OnTime의 법규 관찰 기준은 요청 시작 때 캡처한 사건 수다. Comfort의 승차감 관찰 기준은 수락 때 다시 캡처한다. ‘늦었지만 요청은 판정 불가’여도 운송 지각·운임0원 등 다른 정산 규칙은 별도로 적용된다.

## 조용한 운행에 대한 해석 정정

‘조용히 가겠다’는 약속을 실제로 어겼다면 실패로 평가하는 것은 자연스럽다. 앞서 관리창에서 ‘별도 실패 판정 없음’이라고 쓴 것은 **실패가 설계상 불필요하다는 뜻이 아니라 현행 구현에 위반 관찰이 없다는 뜻**이다.

현재는 수락 시 `quietReply`를 켜서 새 신호 대기/흔들림 등 추가 상황 대화와 취객 일반 수다를 억제한다. 별도로 예약된 요청·필수 안전·승하차 안내는 유지한다. 라디오·음악 재생 상태나 운전자의 불필요한 말 걸기를 플레이어 행동으로 추적하는 목표는 없다. 따라서 정상 도착에서 기본 성공값으로 평가되며, 실패 점수 입력칸만 추가해도 실제 실패를 만들 수 없다.

현재 비지원 이유는 하나가 아니다. Quiet/공감의 지속 약속은 관찰 공백, 음악은 해당 행동 기능 부재, ETA/경로는 불확실한 교통 사유를 감점하지 않는 처리, 단발 안내·격려는 응답 완료 목표, 목적지/경유는 완료 조건을 시스템이 강제하는 구조다. 이들을 전부 ‘실패할 수 없는 요청’으로 묶으면 구현 한계와 의도를 혼동하게 된다.

새 Quiet 실패를 구현하려면 약속 위반으로 인정할 실제 행동·관찰 시점·필수 안내 등 예외를 먼저 정의하고, 해당 사건을 저장/재개/LAN에서도 중복 없이 기록한 뒤 실패 결과에 연결해야 한다. 이 문서 작성에서는 규칙을 변경하지 않는다.

## 코드 근거·조사 범위

- `unity/EungyeTaxi/Assets/Scripts/PassengerRequestObservation.cs`: 요청 시작 기준, 수락·대안, `Finish`72~92행의 종류별 판정과 `Observe`의 측정.
- `PassengerRequest.cs`: `CompleteGoal`/`CompleteUnknown`의 최초 판정 고정, `Finish`의 미응답 결과.
- `PassengerRequestUI.cs`: 모든 관찰의 종료 평가, 미발생 중립, 분실물 사건, 시스템 경로 보호.
- `PassengerJobs.cs`: 목적지 정차 후 도착 확정·요청 평가 순서, 경유 미완료 중 하차 차단, 취객 수다 표시 제한.
- `PassengerJobsActivities.cs`, `PassengerSituations.cs`: Quiet의 후속 상황 대화 억제와 실제 경유 작업.
- `PassengerJobsChoiceEffects.cs`, `ChoiceEffects.cs`, `tools/content-editor/choice-catalog.mjs`: 선택지 효과와5개 실패/중립 분기 연결.
- `docs/content-design/02-passengers-and-fares.md`, `07-passenger-dialogue.md`: 현행 기획과 텍스트/경로·예상시간 예외 대조.

이번은 소스·기획·카탈로그 대조이며 새 물리 주행·수동 플레이·전체 캠페인/Player 실험으로 판정 도달성을 검증한 작업은 아니다. 특히 목적지/경유 실패 도달성은 일반 상호작용 코드 경로에서의 추론이다. 사용자 효과값·판정 로직·빌드·설정은 그대로다.
