# 서울 경기 택시 운행 게임 기획서

작성일: 2026년 10월 14일 · 상태: 기획 초안

서울·경기도의 실제 도로 연결과 지역 특징을 바탕으로 만든 압축 도시에서 택시를 직접 운전한다. 키보드·패드로 쉽게 조작하면서, 교통 상황과 경로를 판단하고 운행을 선택해 정해진 기간 안에 목표 순저축액을 달성한다.

이 문서의 확정 사항은 대화에서 사용자가 선택한 방향이다. 세부 규칙과 숫자는 시제품 검증을 위한 제안이며, 정식 캠페인의 기간·목표 금액은 아직 확정하지 않았다. 첫 주행 시험은 확보한 영통 도엽의 T1–T2, 엔진은 Unity로 정했다. 설치된 Unity 2022.3.62f2로 제작하며 실행 방법은 [Unity 프로젝트 안내](../unity/YeongtongTaxi/README.md)를 따른다.

## 1. 확정한 방향

| 항목 | 결정 |
|---|---|
| 플레이 | 차량을 직접 조종하는 3D 운전 |
| 조작 | 키보드·패드로 쉽게 운전하고 교통 판단에 집중 |
| 배경 | 서울·경기도 중심의 실제 지리 |
| 지도 | 실제 도로 연결과 지역 특징을 최대한 살리며 이동 거리를 압축 |
| 지도 원본 | 국토지리정보원 연속수치지형도와 해당 지역의 1:1,000 수치지형도를 주 기반으로 사용 |
| 내비게이션 | 경로를 안내하지만 현장 판단과 우회로 시간 단축 가능 |
| 승객 | 목적지 도착 시간과 운전 매너 요구가 존재 |
| 영업 | 호출 선택과 길가 손님 승차를 모두 제공 |
| 경제 | 운임 수입에서 연료·보험·정비·식비 등 지출 발생 |
| 목표 | 정해진 기간 안에 목표 금액 달성 |
| 제외 | 단골 시스템과 단골 기반 성장 |

싱글플레이 PC를 시제품의 작업 가정으로 둔다. 정식 지원 플랫폼은 별도 결정한다.

## 2. 플레이어에게 주는 재미

핵심은 합법적이고 부드러운 운전으로도 시간을 줄일 수 있다는 경험이다. 반복 플레이할수록 차량 조작, 정체 관찰, 지역의 연결도로에 익숙해진다.

- 운전: 차간 거리와 제동 시점을 읽어 불필요한 정지를 줄인다.
- 경로: 긴 대기와 추가 이동 거리를 비교해 기다리거나 우회한다.
- 영업: 요금뿐 아니라 픽업 거리, 도착 후 수요, 남은 근무 시간을 판단한다.
- 생활: 수입을 늘리면서 정비와 식사 등의 비용을 감당한다.

모든 순간에 사건을 발생시키지 않는다. 편하게 주행하는 구간과 경로를 결정하는 구간을 번갈아 배치한다. 난도는 조작을 불편하게 만드는 대신 교통량, 경로 복잡도, 시간 여유, 비용 압박으로 조절한다.

## 3. 캠페인과 승패 제안

목표는 총매출이 아닌 순저축액이다. 화면에는 현재 날짜, 마감까지 남은 날짜, 목표 금액, 달성액, 남은 하루당 필요 금액을 표시한다.

최종 달성액 = 보유 현금 − 시작 지급 현금 − 아직 정산하지 않은 발생 비용

첫 캠페인 설계에서는 대출·차량 매매·투자·아이템 환금을 제외해 운행 수입으로 목표를 달성하게 한다. 시작 현금은 운영 자금이며 목표 달성액에 포함하지 않는다. 연료는 구매 시 현금 지출로 기록하고 소모 시 다시 비용을 차감하지 않는다. 차량 손상으로 이미 발생한 수리 부담은 미수리 상태라도 최종 평가에서 정산한다.

- 성공: 마지막 날 최종 정산 후 목표 달성액 이상이다.
- 실패: 최종 달성액이 부족하다. 날짜별 기록과 부족 원인을 보여주고 캠페인을 다시 시작할 수 있다.
- 조기 달성: 남은 기간의 비용이 있으므로 시제품은 마지막 정산에서 판정한다.
- 운행 불능: 연료 고갈·차량 전복 등은 비용과 시간 손실을 내고 복구한다. 현금이 부족하면 해당 비용을 미납으로 기록한다. 지급 능력이 없다는 이유로 조작 불가능한 상태에 갇히지 않게 한다.

정식 기간과 금액은 플레이테스트 후 결정한다. 첫 검증은 3일짜리 캠페인으로 실시한다.

## 4. 하루의 진행

출근 준비 → 영업 지역 선택 → 호출 또는 길가 손님 선택 → 픽업 → 운송 → 운임·평가 → 다음 운행 또는 주유·정비 → 퇴근 정산

출근 시 차량 상태와 남은 운영 자금을 확인한다. 운행 중에는 탑승객 한 팀만 처리한다. 퇴근 후에는 오늘 순수입과 목표 대비 진행 상태를 확인하고 다음 날 전략을 바꾼다.

시제품은 하루 신규 영업 15분을 제안한다. 마감 시 새 호출과 길가 승객 수락을 중단하고 진행 중인 임무만 최대 3분의 정리 시간 안에 끝낸다. 남은 임무도 정리 시간 종료 시 실패 처리하고 정산한다. 마감과 정리 시간을 화면으로 미리 알리며, 실제 시간 단위는 시제품 범위 문서에 따른다.

## 5. 승객과 영업

| 구분 | 호출 | 길가 손님 |
|---|---|---|
| 발견 | 지도·간단한 알림 카드 | 도로에서 식별 가능한 승객 표시 |
| 확인 정보 | 목적지, 예상 요금, 픽업 시간, 요구 조건 | 근처 승차 확인 시 같은 조건 제공 |
| 장점 | 다음 이동 방향과 수익을 계획할 수 있음 | 가까운 곳에서 승객을 확보할 수 있음 |
| 고려할 점 | 승객에게 가는 빈 차 이동 | 접근 방향과 안전한 정차 위치 |

호출 수락부터 하차까지 한 임무만 활성화한다. 수락 전 거절은 무료이다. 수락 후 취소의 불이익은 수락 화면에 명시하며, 시제품에서는 경과 시간과 연료 손실만 적용한다. 취소 수수료는 후속 균형 조정 항목이다.

길가 승객도 조건을 확인하고 수락한다. 차를 완전히 세우고 승차 구역 안에 들어가야 탑승한다. 운행 중인 택시에 추가 손님을 태우거나 예약을 겹쳐 받는 기능은 없다.

초기 승객 유형은 일반형, 정시 도착 중시형, 승차감 중시형의 세 가지다. 단골·관계도·연속 서사는 도입하지 않는다. 픽업·하차 조합과 교통 상황을 바꿔 운행의 변화를 만든다.

## 6. 시간 요구와 운전 매너

교통 규칙 준수는 모든 승객에게 공통이다. 승객마다 규칙의 적용 여부가 바뀌지 않는다. 고객별 요구는 도착 시간, 승차감 점수, 그에 따른 서비스 보너스로 표현한다.

| 평가 | 초기 판정 대상 | 영향 제안 |
|---|---|---|
| 정시성 | 계약 화면에 표시한 도착 시각 | 정시 보너스 지급 여부 |
| 교통 규칙 | 적신호 정지선 통과, 역주행, 게임 내 제한속도 초과 | 매너 점수 감소와 서비스 보너스 제한 |
| 안전 | 차량·고정 장애물과 충돌 | 매너 점수 감소와 수리 부담 |
| 승차감 | 지속적인 급가속·급제동 | 승차감 점수 감소 |

키보드 입력은 가속 변화율을 보정한다. 키를 한 번 눌렀다는 이유만으로 급가속을 판정하지 않는다. 감점은 실제 차량의 움직임을 일정 시간 관찰해 결정하고 이유를 화면에 표시한다. 연속된 한 위반에 매 프레임 감점하지 않는다.

초기 점수는 100점, 승차감형 요구치는 80점 이상을 임시값으로 제안한다. 구체적인 감점·속도 허용 오차·보너스 비율은 데이터로 조정한다. 실제 법규 전체를 재현했다고 표시하지 않으며, 시제품에서 판정하는 규칙을 튜토리얼에 명시한다.

내비게이션의 예상 시간은 수락 시점의 통상 교통 상태를 기준으로 만든다. 기한은 정상적인 운전으로 달성 가능한 여유를 두고, 수락 후 임의로 앞당기지 않는다. 늦더라도 운송을 완료하면 기본 운임을 받으며 정시 보너스만 잃는 방식부터 검증한다.

## 7. 내비게이션과 교통 상황

내비게이션은 기본 경로, 회전 안내, 남은 거리, 도착 예상 시간을 제공하고 경로 이탈 시 다시 탐색한다. 모든 차량의 향후 움직임을 아는 최적 해답을 제공하지 않는다. 큰 도로의 평균 혼잡을 반영하되, 눈앞의 행렬과 잠시 막힌 차로는 운전자가 직접 판단할 수 있다.

예상 시간은 합법적으로 통행 가능한 게임 도로의 거리, 제한속도, 회전·신호 대기, 알려진 혼잡을 기반으로 계산한다. 안내를 일부러 틀리게 만드는 방식은 사용하지 않는다.

첫 교통 사건은 교차로 대기 증가와 정차 차량에 따른 차로 방해 두 종류다. 사건은 플레이어가 대응할 수 있는 거리에서 식별 가능하게 배치한다. 정상 교통에서는 본선이 유리하고 정체 상황에서는 우회로가 유리한 사례를 모두 만든다.

시제품 교통은 게임 내부 시뮬레이션으로 생성한다. 실제 교통 API를 매 순간 연결하지 않아도 실행되며, 같은 난수 시드로 같은 상황을 재현해 비교할 수 있다.

## 8. 요금과 지출

시제품 기본 운임은 수락 시 경로 예상 거리·시간으로 계산해 고정한다. 실제 주행 거리를 무제한 요금으로 환산하지 않아 고의로 돌아가거나 기다리는 것이 이득이 되지 않게 한다. 정식 미터기 요금제는 우회 악용 방지 규칙을 포함해 후속 검토한다.

운행 수입 = 약정 기본 운임 + 정시 보너스 + 서비스 보너스

| 지출 | 역할 | 첫 시제품 처리 |
|---|---|---|
| 연료 | 빈 차 이동과 불필요한 주행 비용 | 주행에 따라 소모, 주유 시 결제 |
| 정비 | 충돌에 장기적인 손실 부여 | 충돌 손상과 수리 비용 |
| 보험 | 고정비 압박 | 일일 배분액 자동 정산 |
| 식비 | 생활 유지 비용 | 하루 한 번 자동 정산 |

주유량·수리 범위를 선택할 수 있게 하되 식사·보험에 별도 관리 화면을 만들지 않는다. 피로, 식당 방문, 주거비, 세금, 복잡한 보험 청구는 초기 범위에서 제외한다. 금액은 실제 택시 영업 수익이나 법정 요율을 의미하지 않는 게임 밸런스다.

## 9. 지도와 표현

지도 제작은 국토지리정보원 자료를 주 기반으로 한다. 연속수치지형도로 지역의 도로·건물·하천 등 기본 배치를 확보하고, 제공되는 1:1,000 수치지형도로 첫 지역의 상세 형상을 보완한다. ‘연속’은 도엽 간 연계 방식이고 ‘1:1,000’은 축척이므로 두 자료를 같은 구분 기준으로 취급하지 않는다. 원본 자료의 도형·속성 제공과 취득 안내는 [수치지도 V2.0 공식 자료](https://www.data.go.kr/data/15059719/fileData.do)를 따른다.

OSM은 필수 입력에서 제외하고 국토지리정보원 자료만으로 먼저 검증한다. 향후 누락 보완에 OSM을 사용할 경우 실제 반영 데이터와 ODbL 조건을 별도로 관리한다. 수치지형도는 게임용 차로·회전 규칙·신호 주기를 완성해 주지 않으므로, 도로 형태에서 주행 연결망을 만드는 작업을 개발 범위에 포함한다.

실제 지도는 도로와 지역의 설계 기반이다. 주요 연결, 방향성, 교차로 순서, 강·다리·철도 등의 경계를 유지한다. 반복되는 긴 구간은 줄이되 차로 변경과 회전 안내를 받을 공간은 확보한다.

전체 지도를 같은 비율로 줄이지 않는다. 작은 지역은 수작업으로 교차로 위치와 연결 도로를 조정하고, 건물과 강 등 주변 요소도 함께 이동한다. 압축한 도로망을 3D 도로·교통 AI·내비게이션·미니맵의 공통 기준으로 사용한다.

첫 시제품은 일반 건물의 간단한 입체 형태와 대표 랜드마크로 지역을 구분한다. 실사급 외벽과 모든 실제 상호의 재현은 목표가 아니다. 카메라는 후방 3인칭 한 종류를 기본 제안으로 두며, 운전석 시점은 추가 결정 사항이다.

첫 지역은 수원 영통역–반달공원으로 선정했다. 반달공원 남쪽 교차로 2개와 추가 1개를 시험 제작한다. 시흥 은계호수공원 주변은 사용자가 익숙한 도로를 검증할 별도 비교 후보로 추가한다. 수원2296 NGI·NDA·XML 원본을 확보해 기본 구조를 검토했다. 남쪽 시험 구역은 인접 도엽이 필요하므로 확보 도엽 내부 T1–T2를 먼저 시험하는 수정안을 [원본 검토 보고서](ngii-sample-review.md)에 정리했다. 구체적인 도엽과 시험 위치는 [지도 확보 확인 기록](map-acquisition-check.md)을 따른다.

## 10. 반복 플레이와 정식 확장

단골 대신 시작 자금, 목표 금액, 캠페인 기간, 지역, 교통 사건의 조합을 바꿔 재도전하게 한다. 초보자는 정시 운송을 익히고 숙련자는 빈 차 비율과 시간당 순수익을 개선한다.

첫 시제품 검증 후 서울·경기 연결 운행, 시간대별 수요, 비·야간, 다양한 차량, 이벤트 수요를 단계적으로 검토한다. 이들은 아직 확정 개발 범위가 아니다.
