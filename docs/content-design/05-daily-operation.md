# 주유와 운영 배경 및 하루 결산 기획서

작성일: 2026년 10월 15일 · 버전: 0.2 · 상태: 법규 성향 결산 연결 보완안

## 기획 의도

하루 운영은 운송 사이를 연결하고 다음 운행을 준비하는 생활의 흐름이다. 플레이어는 연료와 예약을 확인하고 영업을 시작하며, 필요한 때 주유소를 방문하고 하루를 마무리한다. 비용은 택시 운행의 맥락을 설명하되 복잡한 재무 최적화가 핵심 운전 경험을 압도하지 않게 한다.

하루의 성과는 수입과 운전의 변화를 나란히 보여준다. 법규를 지키며 기다린 시간이 무조건 손실로만 보이지 않도록 안전한 운송과 판단의 기록을 함께 남긴다.

## 기사 설정

| 설정 후보 | 게임에서의 생활 맥락 | 상세 기획에 미치는 영향 |
|---|---|---|
| 개인택시 기사 | 자신의 차량과 일정을 관리하고 승객이 재예약 | 주유·관리·보험·세금의 개인 부담과 납부 흐름을 정의 |
| 법인택시 기사 | 배정 차량으로 근무하고 회사와 정산 | 회사 부담과 기사 부담, 예약 전달과 근무 종료를 구분 |

1차 권장안은 개인택시 기사다. 직접 주유와 개인 예약을 하나의 일상으로 설명하기 쉽기 때문이다. 사용자가 영업 형태를 확정하기 전까지 비용 부담과 계약 구조는 설정 후보로 남긴다. 두 형태를 처음부터 별도 모드로 제공할 필요는 없다.

이 비교는 게임 서사와 콘텐츠 구성의 제안이다. 실제 보험·세금·근무 계약의 세부 조건은 선택한 영업 형태와 적용 시점을 확인한 뒤 설정한다. 회사 경영, 직원 고용과 차량 대수 확장은 초기 범위에서 제외한다.

## 하루의 흐름

| 단계 | 플레이어 경험 | 다음 행동에 주는 정보 |
|---|---|---|
| 운행 준비 | 연료, 차량 상태, 예약과 연습 목표 확인 | 먼저 주유할지 바로 영업할지 판단 |
| 일반 영업 | 호출·길가 승객 운송 | 현재 위치, 연료와 다음 예약까지 여유 확인 |
| 중간 준비 | 주유소 방문 또는 예약 픽업 이동 | 운송을 계속할 수 있는 상태 확보 |
| 영업 종료 | 신규 수락 중단, 진행 중인 운송 정리 | 남은 예약 처리 여부 확인 |
| 하루 결산 | 운행 기록, 수입·지출, 숙련 변화 확인 | 복습 또는 다음 날 준비 |

일일 영업 시간은 미확정이다. 정상 운전으로 운송을 마칠 수 있는 시간 여유를 기준으로 조정한다. 종료 시각에 도달해도 탑승 승객을 즉시 실패 처리하지 않고 안전하게 마무리하는 흐름을 기본안으로 둔다. 장시간 진행이 막히면 구조·운송 중단 같은 명시적 선택을 제공한다.

미래 예약을 남긴 채 하루를 마치려는 경우 예약 변경 또는 취소를 먼저 안내한다. 영업 종료가 예약을 몰래 지우는 기능이 되지 않게 한다.

## 직접 방문하는 주유

연료 확인 → 주변 주유소와 이동 경로 선택 → 빈차 상태로 방문 → 주유 위치에 정차 → 주유량 또는 금액 선택 → 연료와 결제 내역 확인 → 도로에 복귀.

초기에는 승객이 없는 구간에서 주유하는 안으로 시작한다. 호출 수락 전에 예상 이동과 연료 부족 가능성을 알리고, 예약이 있다면 픽업 전 방문할 여유를 확인하게 한다. 승객을 태운 뒤 연료가 부족해진 경우에는 지연 안내와 안전한 정차·지원 요청 등 예외 흐름이 필요하다.

주유량은 ‘필요한 만큼’과 ‘가득’처럼 간단한 선택으로 구성할 수 있다. 시동 종료나 주유 절차의 세부 조작은 연출 수준을 추후 정하며, 복잡한 주유 미니게임을 필수로 요구하지 않는다. 주유 중 예약 시간 경과를 적용한다면 시작 전에 예상 소요를 보여준다.

연료 고갈 시에는 안전한 정차 후 지원을 요청하고 운행을 회복할 수 있게 한다. 금액이 부족하다고 조작이 막힌 상태로 남기지 않는다. 지원 비용과 시간 손실은 후속 조정하되 반복적인 고갈이 유리한 주유 대안이 되지 않도록 한다.

## 차량 관리의 범위

차량 상태는 운행 가능 여부와 관리 필요를 이해하는 수준으로 시작한다. 정비소 방문과 수리 범위 선택은 확장 후보로 두며, 초기에는 주유 흐름과 과도하게 중첩하지 않는다. 사고가 발생했을 때는 우선 안전한 운행 중단·회복과 히스토리 안내를 제공하고, 상세 과실 분쟁이나 복잡한 보험 청구 절차를 기본 콘텐츠로 넣지 않는다.

## 보험과 세금 및 비용 표현

보험 계약의 기간, 보험료 납부 시점, 하루에 배분하여 보여주는 비용은 별개다. 연납을 채택하는 경우에는 연간 납부와 일일 참고 비용을 구분하고 같은 돈을 두 번 차감하지 않는다. 모든 보험이 일률적으로 연납이라는 전제를 두지는 않는다.

| 항목 | 플레이어에게 보여줄 정보 | 1차 표현 방향 |
|---|---|---|
| 주유비 | 이번 주유량, 결제 금액, 남은 연료 | 방문 시 현금 지출. 연료 사용 때 다시 결제하지 않음 |
| 보험 | 계약 기간, 납부 여부, 납부 주체 | 짧은 캠페인에서는 사전 납부된 계약 안내 가능 |
| 세금 | 적용 항목, 부담 주체, 예정 납부 시점 | 영업 형태 결정 후 포함 범위 확정 |
| 차량 관리 | 관리 내용과 실제 지출 | 정비 콘텐츠 채택 시 연동 |
| 기타 생활비 | 포함한 경우 항목과 발생 이유 | 필수 관리 과제를 늘리지 않는 범위에서 검토 |

짧은 게임 기간에 연간 납부일을 억지로 반복시키지 않는다. 일일 참고 비용을 표시할 경우 현금 지출과 구분해 보여주고, 납부 이벤트가 없는 날에도 비용 구조를 이해할 수 있게 한다. 세율·보험료·갱신 조건은 이번 기획에서 임의로 정하지 않는다.

## 하루 결산

첫 화면에는 오늘의 운송과 의미 있는 판단 변화를 함께 보여준다. 예를 들어 ‘운송 완료’, ‘예약 이행’, ‘보행자 상황에서 사전 감속 개선’, ‘주유 지출’을 각각 확인한다. 하나의 종합 등수로 합치지 않는다.

| 결산 영역 | 내용 | 이어지는 행동 |
|---|---|---|
| 운행 | 운송·예약 완료와 중단 이유 | 다음 날 일정 조정 |
| 법규 성향 | 규칙별 준수와 상황별 반복 행동, 대표 장면 | 독립 법규 히스토리와 복습 |
| 승객 매너·서비스 | 각 운송의 요구 달성, 승차감과 요청 대응 | 승객 운송 기록 확인 |
| 현금 | 운임·팁 등 수입, 실제 지출, 잔액 변화 | 주유와 운영 준비 |
| 비용 참고 | 기간 배분 비용 또는 예정 납부 | 장기 비용 이해 |
| 다음 준비 | 연료, 차량 관리, 예약, 연습 목표 | 복습 또는 다음 날 시작 |

현금 변화는 실제 수입에서 실제 지출을 뺀 값으로 표시한다. 비용 배분을 반영한 참고 손익을 함께 제시한다면 보험·세금 등의 현금 납부와 중복 차감하지 않고 별도 설명한다. 정확한 계산 방식은 영업 형태와 기간을 정한 뒤 기획한다.

## 목표와 실패의 방향

기존 시제품의 7일·순수익 10만 원 도전은 현재 구현 규칙이다. 새로운 기본 진행에서는 운행을 이어가며 판단 숙련을 쌓는 방향을 제안하고, 수익 목표는 별도 도전 후보로 둔다. 기본 진행의 최종 목표와 캠페인 길이는 미확정이다.

단일 운송 실패, 예약 불이행, 하루 수입 부족, 위험 행동은 서로 다른 결과로 다룬다. 수입 부족만으로 학습 기회를 끊기보다 준비를 조정하고 다시 운행하게 한다. 심각한 위험에는 운송 중단과 상황 복습을 연결할 수 있으나, 전체 진행 초기화 여부는 별도 결정한다.

## 하루 사례와 연결

출근 시 오후 예약과 연료를 확인한다. 일반 호출을 운송한 후 주유소에 들러 다음 예약에 대비한다. 예약 승객을 태우고 교차로에서 안전하게 대기한 뒤 목적지에 도착한다. 하루 종료 시 주유비와 수입, 예약 이행, 이전보다 일찍 감속한 사례를 확인한다. 다음 날에는 차로 변경 상황을 연습 목표로 선택한다.

이 흐름에서 [승객·예약](04-passengers-and-reservations.md)이 일정을 만들고, [상황](01-driving-situations.md)과 [평가](02-driving-evaluation.md)가 운전 경험을 구성하며, [히스토리](03-history-and-mastery.md)가 다음 목표를 만든다. 복습 중에는 영업 시간이 흐르지 않고 비용이나 예약 결과도 변하지 않는다.

## 결정 사항과 검토 기준

기사 설정, 하루 길이, 캠페인 목표, 주유 빈도, 정비 범위, 보험·세금의 표현 수준이 후속 결정이다. 플레이테스트에서는 주유가 자연스러운 준비인지 반복적인 방해인지, 안전 운전으로 예약과 비용을 감당할 수 있는지, 결산 후 다음 행동이 명확한지 확인한다.

현재 구현과의 차이는 [경제 구현 기록](../economy-progression-validation.md)을 참고한다. 이 기획안은 연료 구매와 기간 비용의 표현을 새로 제안하며 현재 빌드에 반영되었다는 뜻은 아니다.
