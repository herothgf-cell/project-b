# 개인택시 경제와 거점

기준일: 2026년 10월 21일 · 버전: 0.8 · 상태: 구현 6de26a5 및 검증 결과 대조

개인택시로 운송 수입을 얻고 주유·식사·주차 비용을 지출한다. 보험료·세금·갱신/납부 일정은 2026-10-21 사용자 결정으로 프로토에서 제외한다. 개인 예약과 사고는 기획만 하며 프로토타입에서 개발하지 않는다. 아래 금액·소모량·납부 일정은 게임용 제안값이다.

## 현재 구현과 검증 범위

북부·남부·동부 주유소 게임시설 3곳과 기존 임시 식당·주차장을 공유 내비와 연결했다. 주유소는 도로 우측의 서로 다른 입구·출구, 노면·캐노피·주유기·정차 구역을 갖춘다. 빈차 정차 → F7 → 길 안내/이용 → 비용 확인 → 확정·취소 흐름이다. 중복 입력·취소·자금 부족·고갈 지원·저장 실패를 자동 검사한다. 보험/세금 메뉴·비용·미납 발생·출발 제한·성공 조건은 제거했다. 구 저장은 해당 거래를 제외해 재계산하고 승객·법규 이력은 보존한다. 실제 시설을 현장 확인한 배치가 아니다.

**검증 경계:** 3곳 주유소의 자동 물리 진입·구매·출구 합류와 도로/연석/건물 간격을 검증했다. 사람이 직접 운전하는 왕복·시야·장기 캠페인 밸런스는 남아 있다. 아래에서 현재 구현값과 아직 구현하지 않은 원안의 차이를 구분한다. 결제·이용 완료 안내는 일시정지 중에도 실제 시간 4초 후 사라진다. 납부 완료 상태와 저장 실패 안내는 별도로 유지한다.

근거: [통합 검증](../prototype-completion-validation.md) · [개발 체크리스트](../prototype-development-checklist.md). 아래 상세 표는 목표 설계를 포함하므로 표의 ‘포함’만으로 검증 완료를 뜻하지 않는다.

## 개인택시와 법인택시 비교

| 항목 | 개인택시 프로토 | 법인택시 후속 검토 |
|---|---|---|
| 시작 | 이미 보유한 택시로 영업 시작 | 차량 배정·근무 형태 별도 설계 |
| 비용 | 운전자가 주유·식사·주차 비용 관리 | 회사·기사 부담 구분 필요 |
| 예약 | 프로토 제외, 개인 예약 흐름은 기획만 | 회사 배차·지정 기사 요청 별도 |
| 수익 | 실제 운임에서 게임 비용 차감 | 보수·회사 정산 기준 별도 |

면허 취득·차량 구입 과정은 생략한다. 실직 뒤 보유 택시로 생계를 이어가는 시작 설정이며 실제 사업 자격·계약을 재현하지 않는다.

## 보험·세금 제외와 기존 저장

프로토에서 결제·기한 알림·출발 제한과 완납 성공 조건을 제공하지 않는다. 구 계정 v2 저장은 원본 거래를 먼저 검증한 후 보험/세금 거래만 제외해 현금·미납·일일 순수익을 재계산하고 계정 v3로 저장한다. 별도 환급 거래를 추가하지 않아 반복 로딩 시 중복 보정되지 않는다. 주유·식비·주차·연료와 승객·법규 기록은 유지한다.

은계 임시 주차장/출발점은 좁은 승하차10 인근에서 국도42 외측 차로의 승하차1 인근으로 옮긴다. 실제 주차 시설 확인을 뜻하지 않는다.

기존 저장은 현금·남은 연료·기록을 유지하고 720초/새 소모율을 적용한다. 시작 연료60%는 새 캠페인에만 적용한다.

## 주유 흐름

| 단계 | 규칙 제안 |
|---|---|
| 연료 초기화 | 새 캠페인 잔량 60%, 다음 날 잔량 유지. 초기 자원은 현금으로 환산하지 않음 |
| 소모 | 현재: 실제 수평 이동 1km당 4%포인트 + 영업 경과 1분당 0.1%포인트. 일시정지·복습·순간 복귀 이동 거리 제외. 거점/지원의 추가 경과 시간은 시간 소모에 포함 |
| 알림 | 현재: 15% 이하일 때 주유소 안내. 원안의 20% 경고 및 호출별 예상 연료 부족 알림은 미구현 |
| 방문 | F7에서 3곳 중 선택 → 공통 내비/H로 도로 입구 앞까지 → H 해제 후 수동 진입 → 같은 방향의 주유 정차 구역에서 F7. 빈차·정차 필요. 도로변·반대 방향·구역 밖 결제 불가 |
| 선택 | 현재: 최대 50%포인트 보충 버튼 1종. 100%를 넘지 않는 실제 보충량 × 40원, 원 단위 올림. 별도 가득 주유 버튼은 미구현 |
| 시간 | 확인창 일시정지. 확정 후 영업 시간 10초 경과, 실제 대기 없음 |
| 고갈 시 운송 | 탑승 중이면 현재 위치에서 승객·ID·내비 유지. 미탑승 호출만 취소하고 출발지로 복귀 |
| 고갈 복구 | 20% 공급 후 30초 경과·1,800원 청구. 시간 소모 0.05%포인트를 포함해 직후 약 19.95%. 탑승 중 위치 이동 없음 |
| 복구 후 | 탑승 중이면 기존 기한으로 운송 계속. 마감 시간이 지나도 목적지 하차 전 정산 불가. 미탑승이면 빈차 재개 또는 정산 |

### 코드 기준 연료 계산 예시

- `소모량(%포인트) = 실제 주행 거리(m) ÷ 1,000 × 4 + 영업 경과(초) ÷ 60 × 0.1`.
- 1km를 2분 운전하면 4.2%포인트 소모한다. 새 캠페인 60%에서 55.8%가 남는다.
- 신호 대기 1분은 0.1%포인트. 가속·회전수·기어별 추가 보정은 없다.
- HUD는 정수 반올림하고 실제 장부는 소수 잔량을 사용한다.
- 60%에서 주유하면 40%포인트/1,600원 구매 후 이용 10초의 0.0167%포인트를 반영해 약 99.9833%. 35%라면 50%포인트/2,000원을 구매한다.
- 식사 이용의 10초도 같은 시간 소모를 적용한다. 확인창을 열고 기다리는 실제 시간에는 소모하지 않는다.
- 잔량은 다음 날 유지한다. 주행 중에는 현금에서 기름값을 차감하지 않고 주유/고갈 지원 시에만 결제한다.

현재의 단위는 리터나 실제 차량 연비가 아닌 압축 지도용 연료 게이지다. 계산 근거: [설정](../../unity/YeongtongTaxi/Assets/Scripts/PrototypeState.cs), [연료 장부](../../unity/YeongtongTaxi/Assets/Scripts/CampaignAccount.cs), [경과 처리](../../unity/YeongtongTaxi/Assets/Scripts/EconomyLedger.cs), [주행 거리](../../unity/YeongtongTaxi/Assets/Scripts/BusinessProgress.cs).

소모량은 압축 맵에서 주유 선택을 검증하기 위한 값이다. 잔액 부족 시 고갈 지원 같은 필수 복구 비용은 미납으로 기록한다. 일반 주유는 보유 현금으로만 구매한다.

## 식당과 주차장 흐름

| 장소 | 진입 조건 | 선택 | 종료 |
|---|---|---|---|
| 식당 | 빈차·지정 위치 정차 | 단일 식사 3,000원, 영업 시간 10초 경과 | 식사 완료·영업 복귀 |
| 주차장 | 빈차·지정 위치 정차 | 오늘 영업 종료 / 계속 운행 | 마감 시 주차비·미식사 비용 정산 |
| 시간 만료 | 새 호출 차단, 탑승 운송 마무리 | 미탑승 호출 취소 | 결과 확인 후 거점 복귀. 복귀 이동에 연료 과금 없음 |

식당 방문은 운전 능력이나 운전 점수를 바꾸지 않는다. 잔액 부족 시 식비는 미납으로 표시한다. 프로토에서 사고 발생에 따른 수리·운송 중단·보험 청구는 추가하지 않는다. 기존 물리 충돌과 승객 매너 감점은 [후속 사고 문서의 경계](08-accidents-and-repairs.md)와 구분한다.

## 장부와 목표 계산

| 항목 | 정의 |
|---|---|
| 시작 운영 현금 | 10,000원 제안. 목표 달성액에 포함하지 않음 |
| 현금 | 시작 현금 + 실제 운임 − 실제 결제 |
| 미납 | 발생했지만 결제하지 못한 식사·주차 등 생활비 |
| 보험·세금 | 프로토 제외. 예정 납부·새 비용·미납 발생 없음 |
| 목표 달성액 | 현금 − 시작 현금 − 미납 |
| 미납 납부 | 현금과 미납을 같은 금액만큼 줄임. 비용을 다시 빼지 않음 |
| 일일 손익 | 오늘 운임 − 오늘 발생 비용. 생활비 결제·미납을 구분 |
| 캠페인 성공 | 하루 정산 후 순수익30,000원 이상 |

하루 정산 후 순수익 목표 이상이면 조기 성공할 수 있다. 연료 소모 때 돈을 자동 차감하지 않고 실제 주유 때 비용을 낸다. 보험·세금은 비용과 성공 조건에 포함하지 않는다.

## 결산과 저장

| 영역 | 저장 정보 | 시점 |
|---|---|---|
| 경제 | 현금·수입·생활비·미납·목표 | 하루 정산 확정 |
| 생활 | 연료·당일 식사 여부 | 다음 날 잔량 유지, 식사 여부 새로 시작 |
| 이관 | 구 v2 보험/세금 거래 제외 후 계정v3 | 원본 검증 후 일별 손익 재계산, 반복 보정 없음 |
| 기록 | 법규 사건·일일 요약·승객 완료/실패·지급 결과 | 같은 날짜의 정산과 함께 저장 |

진행 중 종료하면 마지막 완료 정산에서 다시 시작한다. 당일 미완료 수입·생활비·연료·기록을 함께 되돌리며 부분 저장하지 않는다. 기존 `campaign-v1.json` 기록은 보존하고 새 범위는 별도 버전의 새 캠페인으로 시작한다. 기존 캠페인 v2는 이 문서의 검증된 계정 이관을 적용한다.
