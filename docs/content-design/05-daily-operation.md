# 개인택시 경제와 거점 및 납부 일정

기준일: 2026년 10월 16일 · 버전: 0.6 · 상태: 구현 6de26a5 및 검증 결과 대조

개인택시로 운송 수입을 얻고 주유·식사·주차 비용을 지출한다. 보험 갱신과 세금 납부일은 직접 관리한다. 개인 예약과 사고는 기획만 하며 프로토타입에서 개발하지 않는다. 아래 금액·소모량·납부 일정은 게임용 제안값이다.

## 현재 구현과 검증 범위

임시 주유소·식당·주차장 각 1곳을 공유 내비와 연결했다. 빈차 정차 → F7 → 길 안내/이용 → 비용 확인 → 확정·취소 흐름이다. 보험·세금도 직접 확인 후 결제하며 중복 입력·취소·자금 부족·고갈 지원·저장 실패를 자동 검사했다. 실제 시설을 현장 확인한 배치가 아니다.

**남은 확인:** 거점까지 수동 왕복·시야·출입 동선과 연료 밸런스는 남아 있다. 아래에서 현재 구현값과 아직 구현하지 않은 원안의 차이를 구분한다. 결제·이용 완료 안내는 일시정지 중에도 실제 시간 4초 후 사라진다. 납부 완료 상태와 저장 실패 안내는 별도로 유지한다.

근거: [통합 검증](../prototype-completion-validation.md) · [개발 체크리스트](../prototype-development-checklist.md). 아래 상세 표는 목표 설계를 포함하므로 표의 ‘포함’만으로 검증 완료를 뜻하지 않는다.

| 항목 | 개인택시 프로토 | 법인택시 후속 검토 |
|---|---|---|
| 시작 | 이미 보유한 택시로 영업 시작 | 차량 배정·근무 형태 별도 설계 |
| 비용 | 운전자가 비용·보험 만료·세금 기한 직접 관리 | 회사·기사 부담 구분 필요 |
| 예약 | 프로토 제외, 개인 예약 흐름은 기획만 | 회사 배차·지정 기사 요청 별도 |
| 수익 | 실제 운임에서 게임 비용 차감 | 보수·회사 정산 기준 별도 |

면허 취득·차량 구입 과정은 생략한다. 실직 뒤 보유 택시로 생계를 이어가는 시작 설정이며 실제 사업 자격·계약을 재현하지 않는다.

## 보험 갱신과 세금 납부

짧은 캠페인은 기존 계약의 만료와 기존 세금 고지의 기한이 가까운 시점에서 시작한다. 3일마다 보험을 새로 드는 설정이 아니다. 보험료·세금액·만료일은 체험용이며 실제 연간 금액·법정 납부일이 아니다.

| 요소 | 진행 규칙 제안 | 표시·예외 |
|---|---|---|
| 보험 시작 상태 | 기존 연납 계약 유효, 2일차 종료 때 만료 | 준비 화면에 만료일·갱신료·남은 날짜 |
| 갱신 가능 시점 | 현재: 준비·결산 및 빈차 정차 F7 메뉴에서 직접 갱신 | 금액·새 계약 시작·만료 확인 후 결제 |
| 갱신 결과 | 현재 계약이 끝난 직후 새 연간 계약 시작 | 조기 갱신으로 남은 보장 기간이 사라지지 않음 |
| 미갱신 | 3일차 출발 전 갱신 필요 | 게임 규칙으로 영업 시작 차단, 무보험 영업 콘텐츠 제외 |
| 갱신 자금 부족 | 결제 불가. 유효 기간 중에는 영업으로 마련 가능 | 만료 후에도 부족하면 도전 종료·재시작. 자동 대출·갱신 없음 |
| 세금 시작 상태 | 캠페인용 고지 1건, 3일차 마감까지 납부 | 고지액·납부기한·미납/완납 표시 |
| 세금 납부 | 현재: 준비·결산 및 빈차 정차 F7 메뉴에서 직접 납부 | 일괄 납부만, 분납·자동이체 제외 |
| 기한 도래 | 마감 확정 전에 미납 안내와 납부 선택 제공 | 납부하지 않으면 현금은 유지, 고지액을 미납 비용으로 반영 |
| 알림 | 첫 준비·기한 전날 마감·기한 당일 준비 | 주행 중에는 짧은 알림, 결제는 정차 후 |
| 조작 시간 | 준비·마감 메뉴에서는 시간 정지 | 영업 중 주차장 방문 이동에는 영업 시간·연료 소모 |

보험과 세금은 각각 한 번씩만 결제한다. 주유·식비 같은 생활 비용과 구분해 납부 달력에서 조회한다. 계약 선택이나 현실 세무 판단을 요구하지 않는다.

## 주유 흐름

| 단계 | 규칙 제안 |
|---|---|
| 연료 초기화 | 새 캠페인 잔량 35%, 다음 날 잔량 유지. 초기 자원은 현금으로 환산하지 않음 |
| 소모 | 현재: 실제 수평 이동 1km당 12.5%포인트 + 영업 경과 1분당 0.5%포인트. 일시정지·복습·순간 복귀 이동 거리 제외. 거점/지원의 추가 경과 시간은 시간 소모에 포함 |
| 알림 | 현재: 15% 이하일 때 주유소 안내. 원안의 20% 경고 및 호출별 예상 연료 부족 알림은 미구현 |
| 방문 | 빈차로 지정 구역 정차. 탑승 중 정상 주유는 불가, 다음 운송 전 방문 유도 |
| 선택 | 현재: 최대 50%포인트 보충 버튼 1종. 100%를 넘지 않는 실제 보충량 × 40원, 원 단위 올림. 별도 가득 주유 버튼은 미구현 |
| 시간 | 확인창 일시정지. 확정 후 영업 시간 10초 경과, 실제 대기 없음 |
| 고갈 시 운송 | 탑승 중이면 운송 종료·운임 0원. 미탑승 호출은 취소 |
| 고갈 복구 | 현재: 복귀 위치 이동·20% 공급 후 30초 경과. 1,800원 청구. 이 30초에도 0.25%포인트를 소모하므로 복구 직후 약 19.75% |
| 복구 후 | 빈차로 재개. 종료된 운송의 기한을 재개하지 않음. 영업 시간이 끝났다면 정산 |

### 코드 기준 연료 계산 예시

- `소모량(%포인트) = 실제 주행 거리(m) ÷ 1,000 × 12.5 + 영업 경과(초) ÷ 60 × 0.5`.
- 1km를 2분 동안 운전하면 13.5%포인트 소모한다. 시작 35%라면 21.5%가 남는다.
- 신호 대기 1분은 0.5%포인트 소모한다. 가속·엔진 회전수·기어별 추가 연비 보정은 없다.
- HUD의 연료는 정수 반올림 표시라 소량 변화가 잠시 안 보일 수 있다. 실제 계산은 소수 잔량이다.
- 35%에서 주유하면 50%포인트/2,000원을 구매한다. 이용 시간 10초의 0.0833%포인트 소모까지 반영하면 약 84.9167%다. 80%에서 주유하면 20%포인트/800원이다.
- 식사 이용의 10초도 같은 시간 소모를 적용한다. 확인창을 열고 기다리는 실제 시간에는 소모하지 않는다.
- 잔량은 다음 날 유지한다. 주행 중에는 현금에서 기름값을 차감하지 않고 주유/고갈 지원 시에만 결제한다.

현재의 단위는 리터나 실제 차량 연비가 아닌 압축 지도용 연료 게이지다. 계산 근거: [설정](../../unity/YeongtongTaxi/Assets/Scripts/PrototypeState.cs), [연료 장부](../../unity/YeongtongTaxi/Assets/Scripts/CampaignAccount.cs), [경과 처리](../../unity/YeongtongTaxi/Assets/Scripts/EconomyLedger.cs), [주행 거리](../../unity/YeongtongTaxi/Assets/Scripts/BusinessProgress.cs).

소모량은 압축 맵에서 주유 선택을 검증하기 위한 값이다. 잔액 부족 시 고갈 지원 같은 필수 복구 비용은 미납으로 기록한다. 일반 주유는 보유 현금으로만 구매한다.

## 식당과 주차장 흐름

| 장소 | 진입 조건 | 선택 | 종료 |
|---|---|---|---|
| 식당 | 빈차·지정 위치 정차 | 단일 식사 3,000원, 영업 시간 10초 경과 | 식사 완료·영업 복귀 |
| 주차장 | 빈차·지정 위치 정차 | 보험·세금 관리 / 오늘 영업 종료 / 계속 운행 | 마감 시 주차비·미식사 비용 정산 |
| 시간 만료 | 새 호출 차단, 탑승 운송 마무리 | 미탑승 호출 취소 | 결과 확인 후 거점 복귀. 복귀 이동에 연료 과금 없음 |

식당 방문은 운전 능력이나 법규 점수를 바꾸지 않는다. 잔액 부족 시 식비는 미납으로 표시한다. 프로토에서 사고 발생에 따른 수리·운송 중단·보험 청구는 추가하지 않는다. 기존 물리 충돌과 승객 매너 감점은 [후속 사고 문서의 경계](08-accidents-and-repairs.md)와 구분한다.

## 장부와 목표 계산

| 항목 | 정의 |
|---|---|
| 시작 운영 현금 | 10,000원 제안. 목표 달성액에 포함하지 않음 |
| 현금 | 시작 현금 + 실제 운임 − 실제 결제 |
| 미납 | 발생했지만 결제하지 못한 필수 비용·기한이 지난 세금 |
| 예정 납부 | 아직 납부하지 않은 보험 갱신료·기한 전 세금. 미납과 별도 표시 |
| 목표 달성액 | 현금 − 시작 현금 − 미납 |
| 미납 납부 | 현금과 미납을 같은 금액만큼 줄임. 비용을 다시 빼지 않음 |
| 일일 손익 | 오늘 운임 − 오늘 발생 비용. 결제·미납·예정 납부를 구분 |
| 캠페인 성공 | 순수익 30,000원 이상 + 이번 캠페인의 보험 갱신·세금 납부 완료 |

예정 납부를 남겨 둔 채 목표액만 넘겨 조기 성공할 수는 없다. 납부를 모두 끝내고 목표액을 유지하면 하루 정산에서 조기 성공할 수 있다. 실제 거리·시간 기름값 자동 차감은 주유 구매로 교체하고, 보험 일일 자동 차감도 갱신 결제로 교체한다.

## 3일 플레이 예시

| 시점 | 선택 예시 | 남는 정보 |
|---|---|---|
| 1일차 준비 | 보험 만료 2일차·세금 기한 3일차 확인, 자금 일부를 남기고 영업 | 예정 납부 보험 6,000원·세금 1,500원 |
| 2일차 마감 | 영업 수입으로 보험 갱신 직접 결제 | 현금 6,000원 감소·갱신 완료, 일일 보험료 없음 |
| 3일차 준비 | 새 계약 유효 확인·세금 직접 납부 | 현금 1,500원 감소·완납 |
| 3일차 마감 | 수입·방문비·납부액·미납을 함께 확인 | 누적 순수익과 최종 결과 |
| 세금 미납 분기 | 납부 없이 최종 마감 | 현금 자동 출금 없음·미납 1,500원·납부 조건 미충족 |

## 결산과 저장

| 영역 | 저장 정보 | 시점 |
|---|---|---|
| 경제 | 현금·수입·비용·미납·예정 납부·목표 | 하루 정산 확정 |
| 생활 | 연료·당일 식사 여부 | 다음 날 잔량 유지, 식사 여부 새로 시작 |
| 일정 | 보험 유효 기간·갱신 여부·세금 기한·납부 여부 | 정산과 함께 저장, 중복 결제 방지 |
| 기록 | 법규 사건·일일 요약·승객 완료/실패·지급 결과 | 같은 날짜의 정산과 함께 저장 |

진행 중 종료하면 마지막 완료 정산에서 다시 시작한다. 당일 미완료 수입·비용·납부·연료·기록을 함께 되돌리며, 당일 갱신 결제만 남는 부분 저장은 하지 않는다. 기존 `campaign-v1.json` 기록은 보존하고 새 범위는 별도 버전의 새 캠페인으로 시작한다. 기존 장부를 새 현금·납부 기록으로 임의 변환하지 않는다.
