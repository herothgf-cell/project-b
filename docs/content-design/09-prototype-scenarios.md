기본 실행은 내비 목적지·경로 없이 수동 운전으로 시작한다. 호출 수락/승객 탑승/사용자의 생활거점 안내 선택 때만 해당 목적지 경로를 만든다. 운전 점수 상황 구역은 내비 목표나 필수 경유지로 지정하지 않으며 구역을 지나가지 않아도 승하차할 수 있다. 목적지가 없을 때 H의 내부 차로 유지는 화면 내비 경로로 표시하지 않는다. 기존9코스·17요청을3일×20분에서 재사용한다. 상황 노출은 실제 주행에 따르며 전부 체험을 완료 조건으로 요구하지 않는다.

## 2026-10-21 구현 반영 및 초안 변경

아래 초안의 구상은 `PrototypeScenario`, `ServiceLawZones`, `ScenarioChoiceSituation`, `PassengerJobs`에 연결했다. 이 절이 과거 초안의 미구현·범위 문구보다 우선한다.

- 기존 Quiet·Eta 외 DR/CH/EV 승객 요구 확장도 이번 사용자 요청으로 포함한다. 상세 요청·응답은 [승객 기획](04-passengers-and-reservations.md)을 따른다. 대표 법규 상황이 끝난 뒤 정차 상태에서 목적지 변경·중간 경유를 확인하며 동일 운송 ID를 유지한다. 단골·예약·보험·세금·사고·수리는 계속 제외한다.
- PS01~09는 승차지–하차지의 일반 최단 방향 경로(`HdRoadGraph.Route`)에서 자연스럽게 만나는 상황이다. 교통 상황은 승하차 지점이나 내비 경유지가 아니며 `Via`/`RequireVia`로 강제하지 않는다. 승차 전에는 승차지만, 탑승 후에는 목적지만 안내한다.
- 기존 승하차 조합을 우선하되 적합한 상황 연결이 없으면 기존12곳 중 다른 조합을 선택한다. 상황은 그 일반 경로의 안전한 접근·출구 공간에 배치한다. 대표 상황 미체험·빠른 길 재탐색·우회는 승하차나 요금 지급을 차단하지 않는다.
- PS08 우회 선택은 혼잡 연결 하나를 제외해 목적지까지 다시 탐색한다. 대체 교차로도 강제 경유시키지 않는다. PS09는 일반 경로 위 실제 우회전 연결에서 정지·보행 대기를 관찰한다.
- 내비 경유 조건과 별도로 연속 위치·진행 방향으로 상황 통과를 관찰한다. 텔레포트는 통과로 인정하지 않는다. 실제 관찰하지 않은 상황은 평가 기회 없음이며 점수·운임 보상을 지급하지 않는다.
- 상황 선택 패널은 운송당 한 번·하루 최대 두 번이다. 시간·연료·물리·신호를 함께 멈추고 같은 상태에서 재개한다. 접근이 늦으면 운전 중 뒤늦은 패널을 강제하지 않는다.
- **호출 카드의 경유 상황 설명은 제거한다.** 거리·요금·시간·요구 매너를 남기고 실제 도로 접근 시 상황을 안내한다. 전체 지도는 M이다.
- **승객 픽업 대기 시간**은 `max(180초, 현재 방향 픽업 경로 거리/3 + 180초)`다. 수락부터 흐르고 일시정지 시 멈춘다. 만료 시 빈차 호출을 취소하며 운송 요금·탑승 실패 기록을 만들지 않는다. 승차 후 운송 제한 시간과 구분한다.
- 현재 기본 빌드는 [독립 하루20분](07-campaign.md)이다. 구3일 모드는 저장 호환·회귀 검사에만 유지한다. 운전 점수는 날짜 변경·재실행 후 유지하고 새 캠페인에서 초기화한다. 승객 매너와 별도다.
- `PrototypeScenarioTests`는 9개 방향 경로·실제 정차 차로·접근/출구 거리·우회를 검사한다. `-prototypeScenarioTest`는 위치 제어로 관찰 연결 연속 통과·F 승하차·픽업 만료·선택 정지를 검사한다. **위치 제어 검사는 자동 물리 주행이나 수동 플레이의 완료 증거가 아니다.** 일반 교통 포함 수동 하루20분 밸런스는 별도 남은 검증이다.

## 목적과 고정 조건

승객을 선택하면 그 승객을 태우러 가는 길 또는 목적지에 내려 주는 길에서 지정된 법규·선택 상황을 경험하게 한다. 승객 요청을 늘리는 작업이 아니라 **승객, 승하차 위치, 경로, 상황을 하나의 코스로 묶는 작업**이다. 기본 실행 지역은 은계이며 별도 연습으로 대체하지 않는다.

사용자 요구는 승객별 상황 지정, 기존 승객 요청 유지, 승차·하차 운행 경로에 상황 포함, 별도 ‘프로토 시나리오’ 기획 추가다. 아래 9개 코스·등장 순서·위치 조합은 이를 구체화한 제안이며 사용자 확정 수치나 구현 완료 항목이 아니다.

- 호출 3개 중 선택, 길가 승차, 지정 방향 정차와 F 승하차를 유지한다.
- 요청은 현재 `Quiet`(조용한 운행), `Eta`(도착 시간 문의) 두 종류다. 운송당 1개, Y 수락·응답 / U 안전상 보류, 기존 응답·감점 규칙을 유지한다.
- 현재 요청은 완료 운송 수의 짝수/홀수에 따라 교대로 정해진다. 시나리오별 이름·직업·사연으로 요청 종류를 덮어쓰지 않는다. 아래 ‘승객’은 제작·호출 식별용이며 새로운 인물/관계 시스템이 아니다.
- 요구 매너 60/70/85, 충족 100%·미달 70%·시간 초과 0원, 기존 운임 계산을 유지한다. 법규 점수나 선택 버튼 자체로 운임을 변경하지 않는다.
- DR/CH/EV 확장 범위는 문서 첫 절의 최신 사용자 요청과 04 승객 기획을 따른다. 보험·세금·사고·수리·단골·예약은 범위 밖이다.

## 구성 방식

| 방식 | 장점과 한계 | 이번 제안 |
|---|---|---|
| 승객별 고정 코스 | 어떤 승객이 어떤 상황으로 이어지는지 알기 쉽고 재현 가능. 지도 변경 시 연결 검증 필요 | 채택. 고정 승하차 후보와 지정 상황을 묶고 유효한 코스만 호출로 노출 |
| 현재처럼 상황 순환 배정 | 기존 기능 재사용이 쉬움. 같은 승객/위치의 경험을 예측하기 어려움 | 일반 운송 기반으로 유지하되 지정 시나리오에는 사용하지 않음 |
| 매 운송에 여러 상황 무작위 배정 | 조합은 많지만 짧은 영업에서 길이·중복·난이도 조정이 어려움 | 이번 초안에서 제외 |

**한 승객당 대표 상황 1개**가 기본이다. 다른 도로의 통상 신호·교통은 계속 작동하지만 추가 핵심 팝업을 겹치지 않는다. 기존 7종 법규 구역은 실제 운전으로 판단한다. 신규 선택 패널은 출구 정체·우회전 두 코스에만 붙인다.

## 승객별 코스 9개

‘수락 기준’은 제작·검증용 시작 위치다. 실제 호출은 플레이어 현재 차로에서 접근 가능할 때만 노출하며 그곳으로 순간 이동하지 않는다. PS01~PS08은 탑승 후 상황, PS09는 하차 접근 상황이다. 상황을 건너뛰어도 승하차할 수 있다. 모든 승객의 요청·수락·보류 규칙은 위 공통 규칙 그대로다.

거리와 위치는 게임 방향 그래프 검사 결과이며 실제 시설 확인 결과가 아니다. PS08의 기본 대체 경로는1191 연결을 포함하지만 이는 관찰 대상일 뿐 경유지가 아니다. 교통 비용에 따른 다른 유효 경로·큰길 요청도 허용한다. 운임 기본 거리는 일반 경로 거리이며 우회 후보의 더 긴 거리로 미리 부풀리지 않는다.

PS01/02를 포함해 각 코스의 승차지에서 길가 승차가 가능하다. 호출 픽업 경로와 목적지 경로에 교통 상황을 추가하지 않는다. 승객이 명시적으로 요청하고 사용자가 수락한 EV02 중간 정차는 별개 기능으로 유지한다.

| PS04 | 녹색·출구 공간 존재. 다른 교통 확인 후 진행 | 꼬리물기 평가 기회 없음과 준수를 구분. 과도하게 기다렸다는 이유로 법규 감점하지 않음 |
| PS05 | 비보호 표시·적색. 녹색으로 바뀐 뒤 대향 교통 확인 | 적색 진입 여부. “비보호라고 모든 신호에서 가능한 것은 아님” |
| PS06 | 비보호 표시·녹색·대향차. 대향 교통이 지난 후 진행 | 충돌 구역 진입 시 대향 교통과 간격. 양보 대기는 매너 추가 감점 없음 |
| PS07 | 비보호 표시·녹색·대향차 없음. 주변 확인 후 진행 | 같은 좌회전이라도 조건별 결과 구분. 대향차 없음이 보행자/다른 위험까지 없다는 뜻은 아님 |
| PS08 | 출구 대기열·분기·우회 안내. 계획 선택 후 직접 운전 | 실제 대기/우회/합류, 대기 원인과 정상 통행 방해를 관찰. 계획 버튼만으로 준수·위반 판정 금지 |
| PS09 | 차량·우회전전용신호·횡단보도·보행자 상태. 확인 계획 선택 후 직접 운전 | 정지·양보와 실제 통과. 하차점에 가깝다는 이유로 보행자 보호 조건 생략 금지 |

적색/황색 점멸은 F02/F03, 비보호는 F05, 출구 공간은 F06의 기존 기획 조건을 재사용한다. PS08은 기존 L06/L07, PS09는 L01~L04 중 관찰 가능한 조건만 사용한다. 새로운 배점·법적 벌점·벌금은 만들지 않는다. 불명확한 관찰은 보류이며, 미경험·기회 없음과 분리한다.

## 선택 패널 2종

PS08은 `줄 뒤에서 대기 / 다음 연결도로로 우회 / 앞부분 진입을 검토 / 직접 운전`을 제시한다. A·B는 각각 정상 연결 경로가 있어야 한다. C는 자동 끼어들기 실행이 아니라 운전 계획이다. C를 골랐다가 A/B로 바꿔도 선택만으로 감점하지 않는다. 우회 경로를 선택·주행했다면 원래 출구 경유 조건을 대체하고 우회 합류 지점 통과로 코스를 완료한다.

PS09는 `신호·보행자를 확인한 뒤 판단 / 직접 운전`을 제시한다. 정답 퀴즈나 자동 정지 버튼으로 만들지 않는다. 최초 코스는 전용 우회전 신호 없음·전방 적색·횡단 중 보행자 조건을 제안한다. 전용 적색/녹색 및 보행자 없음 비교는 같은 코스의 후속 변형으로 두며 영업 한 번에 연속 시험하지 않는다. 현장 시설 확인 없이 실제 은계 규제로 표시하지 않는다.

최초 유효 접근에만 사전 안내 후 일시정지 패널을 연다. 물리·신호·AI·영업/운송 시간·연료를 함께 정지하고 동일 위치·속도·상태에서 재개한다. 정지선 직전·회전 중 뒤늦은 팝업은 생략한다. M 전체지도·Esc·정산·연습·거점 메뉴와 중첩하지 않는다. 선택 키가 호출 1/2/3이나 승하차 F에 동시에 전달되면 안 된다. 재방문은 짧은 안내가 기본이며 상세 정책은 [P4 원안](01-driving-situations.md)을 따른다.

## 위치 선정과 호출 노출 규칙

1. 코스를 만들 때 승차점→상황→하차점의 방향·차로 연결을 검증한다. 승차 전 코스는 현재 위치→상황→승차점과 승차점→하차점을 따로 확인한다. 반대 방향·후진·중앙선 횡단으로 해결하지 않는다.
2. PS01·PS02의 승차점은 상황을 지난 뒤 정차할 수 있는 지점으로 잡는다. 같은 지점을 다른 방향으로 먼저 지나는 경우를 분리하고 지정 접근에서만 활성화한다.
3. PS08은 분기 전에 판단하고 두 합법 경로가 하차점까지 이어져야 한다. PS09는 회전·횡단보도를 벗어난 뒤 기존 방향 정차가 가능한 하차점으로 잡는다. 기존 승하차 코드의 거리 판정 통과만으로 현장 적법성을 보장하지 않는다.
4. 최초 접근 준비 거리는 기존 구역의 접근 65m 이상·출구 32m 이상을 출발점으로 삼고 현재 주행 속도에서 단서 인지·감속이 가능한지 재검증한다. 이 숫자는 제작 조건이며 법정 거리나 정지시간이 아니다.
5. 호출 카드 3개는 가능한 한 기초 법규/조건 비교/선택 상황을 서로 다르게 제시한다. 아직 미검증인 코스는 노출하지 않는다. 유효 후보 부족 시 중복을 강제하지 않고 기존 일반 호출로 채운다.
6. 카드는 거리·요금·기한·요구 매너를 표시한다. 사용자 요청으로 경유 상황 설명은 제거한다. 요청 내용은 탑승 후 시점에 표시한다.
7. Tab 빠른 길/짧은 길 재탐색에서 필수 경유를 유지한다. PS08의 우회 분기만 사전에 허용한 대체 완료 지점으로 변경한다. 다른 길 이탈은 안전한 재탐색으로 복귀하며 역주행을 요구하지 않는다.
8. 안전하게 상황 차량을 배치하지 못하면 관찰 보류로 종료한다. 기존 교통을 억지로 재배치하지 않고, 정상 경로 통과 후 승하차를 막지 않는다. 이것은 QA의 시나리오 재현 성공으로 집계하지 않는다.

## 시간·보상·기록

승차 전에는 영업 시간·연료와 별도 픽업 대기 시간이 흐르고 기존 운송 제한 시간과 승객 매너 시작은 승차 시점으로 유지한다. 빈차 접근 거리를 승차 후 약정 운임에 합산하지 않는다. 승차 후 경유 거리와 대기 예산은 기존 계산을 사용한다. PS08은 수락 전에 정상 대기/우회 양쪽을 검토해 한 번 정한 약정 요금·기한을 유지한다. 선택 뒤 무료 시간 연장이나 위반 보너스를 주지 않는다.

코스 길이는 일반 차량 포함 수동 주행으로 측정한 뒤 조정한다. 기존 한 경로 자동 물리 검사도 1,104m에 약 350초였으므로 하루20분 캠페인에 9개 코스를 전부 강제하지 않는다. **9개는 콘텐츠 후보 수이지 캠페인 의무 운송 수가 아니다.** 새 제안 노출은 초반 짧은 코스, 중반 법규/선택 비교와 식당 접근 후보, 후반 짧은 운송/휴식 선택이며 이전 코스 미선택을 실패·진행 잠금으로 처리하지 않는다. 선택 패널은 초기 제안으로 하루 최대 2회, 운송당 최대 1회다.

최신 목표는 하루20분이며 현재12분 빌드와 구분한다. 초기 체험량은3~5건 후보로 수동 측정한다. 식당/주차장 근처 목적지는 후보로 제공하되 강제 코스로 만들지 않는다. 코스별 실제 수동 주행 시간·연료·수익의 밸런스는 후속 검증한다. 운전 점수는 날짜 변경·재실행에 유지하고 새 캠페인에서만 초기화하며 승객 매너와 별도로 평가한다.

| 기록 | 기획 필드와 처리 |
|---|---|
| 코스 정의 | scenarioId, 버전, pickup/drop 별칭과 실제 지도 참조, 단계, 구역/접근/출구, 허용 대체 경로, 창작/확인 출처 |
| 수락 | offerId, scenarioId, 수락 위치·시간. 미탑승 취소도 구분 |
| 실제 운송 | 기존 tripId와 offerId 연결. 요청 종류·응답·매너·운임은 기존 기록 유지 |
| 상황 | eventId, 접근 단계, 실제 occupied, 선택 계획 또는 선택 없음, 실제 행동, 준수/위반/보류/기회 없음, 경유/우회/미발생 |
| 승차 전 법규 | offerId로 기록 후 tripId를 참조 연결. 승차가 취소돼도 하루 법규 사건은 유지하되 가짜 승객 운송 결과를 만들지 않음 |
| 중복 방지 | 한 호출의 같은 대표 상황은 1회. 후진 재진입·내비 변경·패널 재개가 중복 감점/지급을 만들지 않음 |
| 저장 | 기존 하루 정산 저장 경계 유지. 정산 이후의 코스 노출·완료도 당일 진행과 함께 되돌림. 운행 중 자동 저장 신설 없음 |

화면은 `선택한 계획`, `실제 운전`, `법규 결과`, `승객 결과`를 구분한다. 예: “우회 계획 → 실제 우회 완료 / 출구 합류 평가는 기회 없음 / 승객 요청 안전상 보류 / 기존 규칙으로 운임 지급”. 우회를 법규 시험 실패로 표시하지 않는다.

## 하차 정책 변경 (2026-10-21)

기존 탑승 후 필수 코스 미통과 하차 차단 규칙을 폐기한다. PS03~09를 지나지 않아도 목적지의 안전 정차 조건을 만족하면 정상 하차·요금 계산한다. 미체험은 평가 기회 없음으로 기록하며 완료/준수 점수를 주지 않는다. 내비의 추천 체험 경로는 유지한다. 승객 요청으로 수락한 별도 경유 정차만 유지한다. PS01/02의 승차 전 조건은 폐기했다.

## 2026-10-21 승차 독립 및 시나리오 주변 정비 (최신 결정)

이 절은 아래/위 과거 초안의 승차 전 필수 코스·호출 전용 문구보다 우선한다. PS01~09 모두 상황 미체험으로 승차·하차를 막지 않는다. 안내는 추천 경로이고 우회해도 실제 목적지에서 운임을 계산한다. PS01 S08→S01 약3504m, PS02 S10→S05 약1943m로 목적지에 이어지는 상황 경로를 검증했다. 미체험은 0점이며 실제 관찰 사건은 보존한다. 9개 코스·PS08 우회·시작점에서 각 픽업까지 주변 도로 정비를 적용한다. 실측으로 확정하지 않은 도로/시설은 게임용 임시 상태를 유지한다.

## 하루20분 후보 배치 v1 (2026-10-21)

기존 9코스 경로·운임·기한과 17요청은 유지한다. 초반 0~300초와 후반 900초 이후에는 코스 길이+픽업 접근 직선거리로 짧은 후보를 우선한다. 중반은 코스 길이 가중치를 낮추고 식당 가까운 하차점·순환 순서를 함께 반영한다. 접근 직선거리는 후보 정렬에만 쓰며 실제 내비는 기존 방향 그래프 경로다. 단계가 바뀌면 빈차 호출 목록을 갱신한다. 호출에 예상 운송 후 피로와 마감 초과 가능성을 표시하며 교통 상황 설명은 되살리지 않는다. 피로100/마감은 수락·승차 시 다시 검사한다.

설정 버전 `eungye-day20-v1-courses1`, 교통 추종 ON/OFF/혼합을 구분하여 완료 결과에 보존한다. 혼합 설정 결과는 자동 수익 비교에서 제외한다. 하루3~5건은 보장하지 않으며 수동 검증에서 측정한다.


## 2026-10-22 픽업 접근 여유

호출 정렬과 픽업 기한은 현재 진행 방향의 실제 도로 경로를 함께 사용한다. 직선상 가까워도 일방통행/우회 때문에 먼 호출은 낮게 배치한다. 픽업 기한은 max(180초, 실제 경로거리/3+180초)로 조정한다. 첫1.72km 접근에서558초 만료된 자동 주행을 근거로 한 게임 테스트 값이며 도착 보장이 아니다. 승차 후 기한과 강제 상황 경유 금지는 유지한다. 검증 결과는 [작업 이력](../work-history/2026-10-22-day-access-balance.md)을 따른다.

## 2026-10-22 신호·표시·운송 결과 보완

승객 만족도와 운전 점수는 분리하고 요청 결과는 04/11을 따른다. 교통 상황은 필수 승하차 경유지가 아니다. 임시 신호 교차로의 횡단보도 양쪽에 보행 신호기를 표시한다. 일반 임시 신호는 차량 구간 이후 보행10초·정리2초를 추가하고 시나리오가 신호/보행 관찰을 제어하면 그 상태를 우선한다. 실제 현장 주기를 확인한 것이 아니다. 비보호 좌회전 표지는 해당 신호함 위에 배치하고 도로변 중복 표지는 제거한다.

## 2026-10-23 운송·차량 상태 통합

기존 PS01~09와 S01~S12를 보존하고 일반 영업에 게임용 정차포켓12곳을 혼합했다. 교통 상황은 경유지/승하차 조건으로 강제하지 않는다. 취객은 기존 운송에 별도 특성으로 결합하며 구토·첫 도착 후 기상 대기·청결 거부·주유소 세차를 위치 제어 고정사례로 검사했다. PS08 우회 선택과 PS09 보행자 관찰도 중단 운송 저장에서 유지한다.
