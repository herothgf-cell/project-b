# 프로토 시나리오

은계 일반 영업의 승하차와 자연스러운 상황 관찰을 연결한다. PS01~09는 콘텐츠 후보이며 하루에 전부 체험할 의무 운송 목록이 아니다. 상황 미체험·합법적 우회로 승차·하차·운임 지급을 막지 않는다.

## 콘텐츠와 공통 조건

| 항목 | 규칙 | 연결 |
|---|---|---|
| 실행·캠페인 | 기본 은계에서3일×예정20분, 초과 영업·생활 거점에서 종료 | [캠페인](07-campaign.md) |
| 시작 경로 | 수동 주행·목적지 없음. 호출 수락/탑승/사용자 생활 거점 안내 선택 때 경로 생성 | 목적지 없는 H 차로 유지는 내비 경로로 표시하지 않음 |
| 승하차 | 호출 선택/명시 수락, 길가F 승차, 목적지 방향·안전 정차 | [승객04](04-passengers-and-reservations.md), [지점14](14-passenger-stop-variety.md) |
| 상황 | 일반 방향 경로에서 관찰. 내비 필수 경유지로 설정하지 않음 | 미체험은 평가 기회 없음·점수 보상 없음 |
| 요청 | 현재17종·현행 배정 사용. 승객의 명시 요청을 수락한 중간 정차는 상황과 별개 | [요청11](11-passenger-request-effects.md) |
| 요청 변경 기획 | 무작위0~2개·안전 정차 응답·다중 시점은 미구현 변경안 | [배정·등장 시점](04-passengers-and-reservations.md#요청-배정과-등장-시점--변경-기획-미구현) |
| 운임 | 빈차 픽업 거리를 운임에 합산하지 않음. 선택 버튼 자체의 보너스 없음 | [운임과 보너스 계산](04-passengers-and-reservations.md#운임과-보너스-계산) |
| 취객·청결 | 기존 운송의 별도 특성. 첫 도착 판정/기상 대기/세차 연결 | [15](15-drunk-passengers-and-cleanliness.md) |
| 범위 제외 | 단골·예약·보험·세금·사고·수리 | 각 문서의 후속 기획 유지 |

## 코스 생성과 위치 기준

| 단계 | 데이터·조건 | 실패 처리 |
|---|---|---|
| 승하차 후보 | 기존12지점과 확장 후보. 실제 `MapStop`의 방향·정차 차로 사용 | 반대 방향·후진·중앙선 횡단으로 연결을 보충하지 않음 |
| 일반 경로 | 승차→하차의 `HdRoadGraph.Route`, 가능한 한 제작된 승하차 선호 유지 | 유효한 다른 조합을 탐색, 없으면 해당 코스 미노출 |
| 상황 연결 | 신호 제어된 join 연결·코스별 회전 방향·비활성/차로변경 제외·중복 상황 구역 제한 | 미확인·안전 연출 불가는 관찰 보류 |
| 접근·출구 | 진입 차로1, 진입 길이65m 이상·출구 차로32m 이상을 후보 조건으로 사용 | 게임 제작 기준이며 법정 거리 아님, 시야·감속은 별도 검증 |
| PS08 대체 경로 | 혼잡 연결 하나를 제외해 실제 목적지까지 재탐색 | 우회 경로도 강제 경유점 없음 |
| 상황 관찰 | 연속 위치·진행 방향·신호·교통 조건 | 텔레포트는 통과로 인정하지 않음 |

현재 `PrototypeScenario.Build`는 입력 지도에서 조건에 맞는 코스·연결을 다시 선택한다. S01~S12 별칭은 문서용이며 영구ID가 아니다. 구 지도 좌표·차로 번호·거리·SHA256 표는 [이력](../design-history/content-design/09-prototype-scenarios-history.md)에 보존한다. 현재 지점은 정식 지도와 `MapStop`을 확인하고 재생성 때 경로 검사를 수행한다. `eungye-map.json`의 Stop A~H와 통합 지도 지점을 혼동하지 않는다. 좌표는 실제 시설명이나 정차 허가를 보증하지 않는다.

## 상황별 판단과 피드백

| 코스 | 플레이어에게 보여 줄 단서·행동 | 결과를 가르는 관찰 / 회고 문구 방향 |
|---|---|---|
| PS01 | 적색 점멸·정지선·교차 교통. 정지 후 안전 확인·진행 | 정지선 접근·정지·연속 통과. “정지 위치를 지켰는지” 설명; 탑승 후 실제 관찰 기록이며 승하차 통과 조건이 아님 |
| PS02 | 황색 점멸·주변 교통. 주의하며 진행 | 시선/주의를 자동 판정하지 않음. 통과만으로 준수 확정·정지하지 않았다고 위반 처리 금지 |
| PS03 | 녹색이지만 출구 공간 부족. 교차로 밖 대기 후 진행 | 진입 시점 공간·교차로 정체 위험 관찰. 뒤늦게 공간이 나도 앞선 위반 삭제 금지 |
| PS04 | 녹색·출구 공간 존재. 다른 교통 확인 후 진행 | 꼬리물기 평가 기회 없음과 준수를 구분. 과도하게 기다렸다는 이유로 법규 감점하지 않음 |
| PS05 | 비보호 표시·적색. 녹색으로 바뀐 뒤 대향 교통 확인 | 적색 진입 여부. “비보호라고 모든 신호에서 가능한 것은 아님” |
| PS06 | 비보호 표시·녹색·대향차. 대향 교통이 지난 후 진행 | 충돌 구역 진입 시 대향 교통과 간격. 양보 대기는 매너 추가 감점 없음 |
| PS07 | 비보호 표시·녹색·대향차 없음. 주변 확인 후 진행 | 같은 좌회전이라도 조건별 결과 구분. 대향차 없음이 보행자/다른 위험까지 없다는 뜻은 아님 |
| PS08 | 출구 대기열·분기·우회 안내. 계획 선택 후 직접 운전 | 실제 대기/우회/합류, 대기 원인과 정상 통행 방해를 관찰. 계획 버튼만으로 준수·위반 판정 금지 |
| PS09 | 차량·우회전전용신호·횡단보도·보행자 상태. 확인 계획 선택 후 직접 운전 | 정지·양보와 실제 통과. 하차점에 가깝다는 이유로 보행자 보호 조건 생략 금지 |

적색/황색 점멸은 F02/F03, 비보호는 F05, 출구 공간은 F06의 기존 기획 조건을 재사용한다. PS08은 기존 L06/L07, PS09는 L01~L04 중 관찰 가능한 조건만 사용한다. 새로운 배점·법적 벌점·벌금은 만들지 않는다. 불명확한 관찰은 보류이며, 미경험·기회 없음과 분리한다.

## 선택 패널과 진행

| 코스·시점 | 선택·동작 | 보호 조건 |
|---|---|---|
| PS08 출구 정체 | 줄 뒤 대기 / 다음 연결도로 우회 / 앞부분 진입 검토 / 직접 운전 | 선택은 운전 계획. 실제 행동을 관찰하며 선택 변경만으로 감점하지 않음 |
| PS09 우회전 | 신호·보행자를 확인한 뒤 판단 / 직접 운전 | 자동 정지·정답 퀴즈가 아님. 전용 신호/보행자 변형은 조건별 비교 |
| 최초 유효 접근 | 사전 안내 후 패널, 운송당1회·하루 최대2회 | 늦은 접근·회전 중에는 강제 팝업 생략 |
| 패널 표시 | 물리·신호·AI·영업/운송 시간·연료 정지, 같은 상태로 재개 | M/Esc/정산/연습/거점 메뉴 중첩 금지·선택 입력 유출 방지 |
| 재방문 | 짧은 안내, 노출 기록 저장 | [선택 이벤트](01-driving-situations.md#은계-지도-연동--상황-판단-선택-이벤트) 기준 |

상황을 지나가지 않았으면 평가 기회 없음으로 남기며 정상 목적지 하차를 허용한다. 실제 관찰한 위반은 우회·복귀로 삭제하지 않는다. PS01/02도 승차 전 필수 통과 조건이 없다. 승객이 수락받은 EV02 중간 정차는 별도 운송 요청이다.

## 호출 노출·시간·기록

| 항목 | 조건·동작 |
|---|---|
| 후보 순서 | 초반0~300초·후반900초 이후는 짧은 코스/접근 우선, 중반은 식당 접근 후보·순환을 함께 고려. 현재 방향의 실제 픽업 도로 거리를 사용 |
| 호출 표시 | 거리·요금·기한·요구 만족도·운송 후 피로/초과 가능성. 교통 상황·승객 요청 내용은 호출 카드에서 숨김 |
| 호출 수락 | 후보 부족 시 일반 호출로 보충, 접근 불가 코스 미노출. 피로·영업·청결 제한은 해당 현재 기획을 따름 |
| 픽업 기한 | 수락부터 `max(180초, 현재 방향 실제 픽업 경로거리/3 + 180초)`. 일시정지 때 멈춤. 만료는 빈차 호출 취소이며 가짜 운송 결과 없음 |
| 승차 후 | 별도 운송 기한·만족도 시작. PS08 선택 뒤 무료 시간 연장·위반 보너스 없음 |
| 체험량 | 하루3~5건은 수동 측정 후보. 식당/주차장 근처 목적지를 강제하지 않음 |
| 비교 | 코스 설정 버전·교통 추종ON/OFF/혼합 보존. 혼합 결과는 자동 수익 비교에서 제외 |
| 식별 | scenarioId/버전/지도 참조, offerId/수락 위치·시간, tripId, eventId/관찰 단계·실제 탑승 여부 연결 |
| 기록 | 선택한 계획·실제 행동·법규 결과·승객 결과 분리. 같은 대표 상황은 호출당1회, 후진/재탐색/패널 재개로 중복 지급·감점 없음 |
| 저장 | 중단 운송·요청·PS08 우회·PS09 보행 관찰·차량·시간·장부 복원. 법규 즉시 저널과 정산 기록도 구분 |

## 검증·남은 작업

| 구분 | 확인 내용·상태 |
|---|---|
| 데이터/모델 | 9코스 방향 경로·정차 차로·접근/출구·우회·중복 방지 검증 구현. 지도 변경 때 재검사 |
| 위치 제어 | 승하차/관찰/픽업 만료/선택 정지/중단 저장 검증 기록 존재. 자동 물리·수동 완료로 계산하지 않음 |
| 자동 물리 | 일반 교통 포함 코스/생활 시설 왕복·가감속·조향·연속 통과, H 사용 여부와 실패를 구분. 일부 통과 기록을 전체 코스 완료로 확대하지 않음 |
| 수동·캠페인 남음 | PS08 대기/우회·PS09 보행, 시야·조작·오감점,20분/3일 운송량·만족도·운임·생활/청결 비용 비교 |
| 신규 필수 구현 여부 | 기존9코스·17요청·선택 패널은 구현. 요청 무작위/다중 등장 변경안과 시간대/유형별 대사는 별도 미구현 기획 |

실행 결과는 [최신 이력](../work-history/LATEST.md)과 [체크리스트](../prototype-development-checklist.md)에 종류별로 기록한다. [변경 전 원문](../design-history/content-design/09-prototype-scenarios-history.md)의 개발 순서는 현재 미구현 목록이 아니다.

## 법규 자료와 확인 한계

2026-10-21에 아래 공식 자료를 열람해 기획에 쓰는 조건을 대조했다. 게임용 설명은 직접 작성하고 공식 문항·이미지·과거 금액을 복제하지 않는다.
