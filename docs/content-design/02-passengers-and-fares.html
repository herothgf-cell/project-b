선택지별 단계 효과 설정

요청·유형·상황의71개 답변은schema2 프로필에서 각각 즉시 / 운행 중 / 운송 종료 효과를 독립 소유한다. 현재 기본 수치는 위 밸런스 v1을, 사용자 프로필은 실제 선택한 답변 값을 따른다. General 유형과 하차 후 LostItem은 효과 선택지 목록에서 제외한다. 구현 기준, 편집·이관 안내를 따른다.

  • 즉시/종료 S·피로는 점과 적용 직전 현재값 대비%를 더한다. 승차 전 선택은 실제 승차 확정 때 즉시1회 적용한다.
  • 운행 중 S·피로는 점/분과 활성화 기준값 대비%/분을 더한다. 활성화 기준값은 즉시 효과 적용 뒤 고정해 저장하며 정상 운송의 영업시간에 비례한다. 자연 피로 증가율 추가%와 급가감속 M 감점 추가점도 답변별로 설정한다.
  • 요청 종료 S만 각−100~100으로 제한한 소수 기여를 합산·반올림한 뒤 기존 common.requestCap을 적용한다. 즉시/운행 중/유형·상황 종료 S는 이 상한 밖이며 최종 S·피로는0~100이다.

schema2에서는 choice.*의 단계별 효과가 현재 선택 값을 담당한다. 프리셋에 남은 구 request.*.success/failure는 이관/기존 방식과 구별하며 새 효과값으로 잘못 읽지 않는다.

  • 0은 추가 효과 없음이다. 기존 자연 피로·경로·안전 판정·물리 작업은 유지한다. 취소·운송 중단에는 종료 효과를 지급하지 않고, 도착 확정·취소·메뉴 일시정지 뒤에는 운행 중 효과를 진행하지 않는다. ETA 세 답변·공감 두 수락 답변도 서로 독립적이다.
  • 음식 즉시 효과와 Comfort의 M 추가값은 새 장부에서만 적용해 구전용 분기와 중복하지 않는다. schema1 운행 저장은 기존 방식으로 끝내며 새 캠페인/방부터 새 설정을 적용한다. LAN은 호스트 장부를 복제하며 현재 호환 계약을 따른다.
