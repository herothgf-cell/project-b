1. 승객 프리셋·특성 조합과 제작 도구 (구 15)

작성: 2026-11-06. 사용자가 선택한 프리셋 + 특성 조합의 상세 기획. 기존 동작 분석은 구조 검토, 실제 적용/검증은 작업 이력을 따른다. 이 문서는 확장 아이디어와 이번 구현 범위를 분리한다. 수치 담당은 밸런스, 대사/선택 효과는 기존 관리창 설정을 재사용한다.

1. 기획자가 만드는 것은 ‘새 유형 코드’가 아니라 ‘새 승객 프리셋’

승객 한 명은 정체성(이름·소개), 성향/상태/목적/소지품의 조합, 실제 운송 중 상태로 나눈다. ‘취객’은 최상위 카테고리가 아니라 음주 특성이 있는 프리셋 이름이다. 같은 음주 특성에 조용함·짐·경유를 달리 연결할 수 있다.

‘조용함’을 고르는 것은 일반 수다를 줄이는 조건이며 만족도 자동 가산이 아니다. ‘음주’를 붙였다고 오염이 즉시 생기는 것도 아니다. 실제 선택·사건이 일어났을 때 해당 효과를 적용한다.

2. 기존 승객을 어떻게 나누는가

최초 기본12프리셋(일반1+특수11)은 기존 행동 자료로 유지한다. 현재 출하 구성은 다양화1차17의 신규12명을 더한24명/23활성이고 경로 확인은 비활성이다. 기존34개 특수 변주는 행동 모듈의 대사/진행 변주로 재사용하며 이번에는 별도 변주 제작기까지 추가하지 않는다.

등장 그룹과 특성은 다르다. 이번에는 기존 등장 정책과 취객 하루 한도, 특수 승객 다음 일반 운송 규칙을 보존하기 위해 ‘배정 그룹’을 남긴다. 일반 특수 그룹은 현재 후보에서 선택될 프리셋의 실제 요청 가용성을 먼저 검사하고, 후보가 없거나 요청이 불가능한 그룹을 추첨에서 제외한다. 남은 그룹 안에서 기존 그룹 가중치, 그룹 내부에서는 프리셋 상대 가중치를 사용한다. 따라서 일부 그룹을 비우면 다른 가용 그룹의 상대 비중이 높아진다. 취객은 기존 별도 추첨/한도 정책을 따르며 후보 없음이면 일반으로 폴백한다. 행동은 그룹 이름이 아니라 특성으로 조립한다. 가중치2는 전체 승객의2%가 아니다.

일반 그룹은 특성 없음 또는 조용함만 허용해 쉬는 운송을 보존한다. 음주 특성은 취객 그룹에서만 사용한다. 최종 선택 단계에 후보가 없으면 아무 특성 없는 일반 승객으로 폴백하며 취객 한도를 소모하지 않는다. 향후 시간대/지역별 프리셋 직접 수요 표는 별도 확장이다.

3. 요소별 현재 제공 범위와 확장 후보

‘이번 조합’은 기존 행동 연결 범위이고, ‘후속’은 문구만 바꿔 실제 기능을 켤 수 없는 신규 기획이다. 후속 수치는 사람 플레이 이후 정한다.

7. 새 승객을 추가하는 세 가지 예

완성 예제3개를 포함한 가져오기용 프로필을 제공한다. 관리창 가져오기에서 선택하면 기본12개+예제3개를 새 프로필 ID로 보관할 수 있다. 출하 기본값이나 기존 활성 설정에 자동 적용하지 않는다. 이 작업에서 UI로 저장한 passenger-composition-example에는 예A가 들어 있으며 예제 전체는 위 파일을 사용한다.

예 A. 말없이 귀가하며 큰 가방을 든 손님

  1. 설정 관리 → 새 프로필 passenger-lab을 만들거나 별도 작업 프로필을 연다.
  2. 승객 프리셋에서 취객을 복제한다. ID quiet-night-luggage, 이름 ‘조용한 귀가 손님’.
  3. 배정 그룹 취객, 가중치1, 대화 조용함·신체 음주·목적 경유·소지품 큰 짐 선택.
  4. 소개: ‘오늘은 조금 취했네요. 가방을 싣고 조용히 집까지 부탁드려요.’
  5. 결과 확인: 짐 선택→안전 적재→가용한 경유 요청 응대→일반 수다 억제→구토/기상 예정에 따른 사건→하역→정산.
  6. 검증·저장 후 분리 테스트. 구토는25% 예정이므로 한 번 타서 반드시 발생하지 않는다. 사건 검사는 별도 테스트 프로필의 기존 구토 확률을 조정해서 확인한다.

이 이름은 코드에 새 유형을 추가하지 않아도 된다. 효과를 바꾸지 않으면 기존 짐/음주 효과를 공유한다.

예 B. 간식을 들고 편안한 운전을 부탁하는 손님

음식 프리셋 복제 → snack-comfort → 소지품 음식 + 신체 승차감 민감. 소개는 ‘간식을 가져왔는데 차가 흔들리면 힘들어요.’ 음식 허용 선택과 부드러운 운전 요청은 서로 다른 선택이다. 허용하면 S+3, 실제 섭취/흘림 오염; DR01을 수락하면 승차감 평가. ‘민감’ 특성이 있다고 구토를 자동 추가하지 않는다.

예 C. 화분을 들고 잠깐 들를 곳이 있는 손님

오염 짐 프리셋 복제 → plant-errand → 소지품 오염 가능 짐 + 목적 경유. 보호10초/그대로 선택과 경유 수락은 독립이다. 가용 경유지가 없거나 요청 슬롯이 없으면 경유를 강제하지 않는다. 실제 적용된 목표와 약속만 평가하며, 보호 없이 실은 경우 하차/중도 종료 때 추가 청결-5.

8. 확장 순서와 검증

  1. 이번: 기존 행동 프리셋화, 조합·명시적 충돌 검사, 기존 도구 저장/적용, 실제 운송/저장 연동.
  2. 다음: 프리셋별 초상·변주·요청 가중치, 지역/시간대 수요, 독립 행동 다중 진행기. 수면+짐 등을 열기 전에 준비/수면/깨우기/하역의 순서를 검증한다.
  3. 이후: 메스꺼움 상태와 운전/선택 개입, 젖은 우산·장치·관계 기억 등 새 행동.

확률은 생성 시 한 번 정하고 저장한다. 취소/불러오기/순서 변경으로 재추첨하지 않는다. 기존 저장은 당시 행동/설정으로 진행한다. LAN 참가자는 호스트 설정과 결과를 사용하며 이번 실행본을 함께 갱신해야 한다. 신규 프리셋·설정 구조를 모르는 구 실행본으로 적용하지 않는다.

자동 검사는 데이터 검증·동작·저장·통합 검사, 사람 검사는 반복 대화 피로·실제 운전 중 읽기·운송 수익/세차 빈도를 확인한다. 둘을 구분해 기록한다.

2. 승객별 대사·확률·효과 설정 (구 16)

작성 2026-11-07. 승객 프리셋·특성 조합의 개별화 확장이다. 같은 특성을 가진 승객도 필요한 항목만 서로 다른 값으로 제작한다.

1. 공통값은 기본, 개별값은 교체

flowchart LR

 B[프리셋별 개별 설정] --> C

  • 개별값은 공통값에 더하거나 곱하지 않고 교체한다. 공통 구토25%·개별10%라면 최종10%다.
  • 0도 유효한 값이다. 구토0%는 구토 없음, 추가 만족도0은 추가 가산 없음. 상속하려면 공통값으로 복원을 누른다.
  • 공통값과 같은 숫자를 명시해도 개별값이다. 이후 공통값을 수정해도 그 프리셋의 명시값은 유지한다.
  • 대사를 빈 문자열로 저장하지 않는다. 개별 대사를 지우고 기존 대사로 돌아가려면 복원한다.
  • 수정은 다음 새 싱글/새 PVP방에 적용한다. 이어하기는 저장 당시 콘텐츠와 해당 승객의 개별 설정을 사용한다. 진행 중 운송을 다시 추첨하지 않는다.

5. 기획자 편집·검증 기준

  • 요청 문구만으로 생기지 않는 기능: 면접 결과·지역 사실 보장·새 경유지·짐 파손/보상·음악 실제 조작.
  • 1차 수치는 사람 플레이로 확정한 값이 아니다. 운송별 S 초과량·요청 이행률·세차빈도·준비/경유 시간·대화 읽기 부담을 후속 측정한다.

5. 기획자 관리 순서

  1. 관리 툴에서 새 프로필 또는 기존 프로필을 연다.
  2. 승객 프리셋을 복제하고 신체 상태·소지품을 조합한다.
  3. 승객별 대사/효과에서 필요한 항목만 개별 설정한다. 명시적0도 설정으로 유지한다.
  4. 공통값/개별값과 최종 적용값을 확인한다. 같은 특성의 다른 승객에 영향이 없어야 한다.
  5. 검증→저장→내보내기/적용 후 새 운송에서 확인한다. 진행 중 운송은 저장 당시 상태와 선택을 유지한다.

새 사건의 선택·정차 작업·수면·오염·만족도·취소·재로드·원격 명령을 검사한다. 1차 값은 기획 가설이며 실제 주행/장기 수익·세차 빈도·대화 피로를 후속 확인한다. 자동 모델/위치 제어/같은PC LAN과 사람 운전·전체3일·다른PC 검사는 구분한다.

메스꺼움 휴식/봉투는 안내 사건의 두 대안이며 휴식이 이후 모든 불편을 영구 제거하지 않는다. 온도 선호는 배정 시 고정하고 대사에 표시한다. 최초 설정이 맞지 않으면 한 번 다시 조정할 수 있다. 현재 유지 선택은 중립 온도로 처리한다. 잠든 동안 음식 소비·흘림은 멈추고, 운행 중 메스꺼움/온도 상태 자체는 진행할 수 있다. 필수 사건/작업 응대를 일반 수다로 취급하지 않는다.

9. 조합·호환 경계

  • 일반 짐은 기존 적재·하역 시간을 유지한다. 오염짐은 기존 보호 준비·하차 오염 정책이며 별도 하역 시간은 없다. 수면 결합이 이 물리 정책을 자동으로 바꾸지 않는다.
  • 음주+졸림, 음주+메스꺼움, 수다+졸림은 충돌로 거부한다. 소지품 주 행동(음식/짐/오염짐)은 하나이며 젖은 우산 보조 행동을 함께 둘 수 있다. 대표 목적 요청은 기존 최대1개 정책을 유지한다.
  • 신규 설정 묶음이 전부 없는 과거 프로필은 읽을 수 있지만 중간 항목만 빠진 손상 프로필은 거부한다. 편집기 이관은 새 항목을 채우고 기존 승객 목록을 보존한다. C#/Node 이관 결과가 같아야 한다.
  • 과거의 Quiet 효과는 저장 당시 프로필을 존중한다. 새 기본값의 실패S-5는 새 프로필 정책이며 기존 저장의 점수를 소급 변경하지 않는다.
  • 공통 새 특성 설정의 손실 값은 양수 크기이며 실행에서는 청결 감소로 적용한다. 온도 만족도는 부호 있는 변화량이다.

2026-11-09 잡담 표시 보완

선택지가 없는 명시적 잡담 답변은 큰 중앙 팝업 대신 왼쪽 아래 승객 카드에서 승객 발언으로 표시한다. 같은 표시 문구는 한 운송에서 한 번만 사용하며, 저장/이어하기와 LAN snapshot에도 사용 이력을 유지한다. 다른 문구는 기존 12초 간격·6초 표시를 유지한다. 1인칭에서는 잡담 표시 동안 기존 승객 카드를 왼쪽 아래로 옮기고 운전 점수창은 오른쪽에 두어 겹침을 피한다. ‘말 걸기’는 카드 안의 작은 선택적 버튼이다. 자동 잡담을 새로 발생시키지 않는다.

기존 편집 가능한 request.LocalChat.reply.SmallTalk 대사와 새 Assets/Resources/Content/passenger-chat-lines.json의 7개 발언을 합해 기본 8개다. 같은 문구를 다른 키로 설정해도 반복하지 않는다. 구저장은 마지막 답변을 사용 이력으로 이관한다. Quiet 약속 위반 반응은 별도 1개이며 원래 위반 판정/감점은 보존한다. 실제 요청·행동 선택지는 유지한다.

2026-11-09 후속: 말 걸기 숨김·승객 표시 정리

사용자가 선택적 말 걸기 기능을 확인한 뒤 우선 숨김을 요청했다. 위 ‘말 걸기’ 버튼과 잡담 카드 표시 지침은 이번 후속으로 대체한다. 내부 잡담 데이터/구저장 호환/Quiet 관찰 API는 남기지만 일반 플레이 화면에는 진입 버튼과 답변을 표시하지 않는다. 실제 승객 요청/행동 선택은 그대로다.

승객 카드에는 offer/trip 식별자로 정한 임의 한국어 이름을 표시한다. 같은 승객은 저장·탑승·LAN에서 같은 이름을 유지하며 배정 난수 상태를 소비하지 않는다. 발언 앞의 ‘손님:’·‘손님 “…”’·‘승객:’ 화자 표기를 표시 단계에서 제거하고 상태 설명/원문 콘텐츠는 보존한다. M지도 상단 보조 범례와 우측 호출의 예상 피로 등 예측 카드는 숨기며 운임/승하차/수락·차단 사유는 남긴다. 호출 반복 보완과 실제 최종 검증은 후속 작업 이력을 따른다.
