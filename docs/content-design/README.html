문서 목록

수치와 조건을 바꿀 때는 해당 영역의 담당 문서를 기준으로 삼는다. 새 기획은 새 파일을 만들기 전에 담당 문서의 장으로 넣는다. 항목별 구현·미결·개선 필요 상태는 기획서 목록과 현황에서 한눈에 본다(브라우저용 HTML, 상태별 필터 포함).

HTML로 읽기. 이 폴더와 pvp/의 기획서는 같은 이름의 .html로도 열 수 있다(예: 00 게임 개요, 기획서 목록). 문서 사이 링크·목차·이전/다음 이동이 있고, 기획서 목록에서 개선 필요인 항목은 해당 장 제목에 빨간 배지와 이유·근거 상자로 표시된다. 기획서 목록의 기획 위치가 가리키는 폴더 밖 문서(작업 이력의 상세 기획 등)도 HTML을 만든다. 원본은 md이며, md를 고친 뒤 python tools/render_design_docs.py로 다시 만든다. 다른 작업의 미커밋 변경을 빼려면 --rev HEAD를 붙인다.

제작·배포·보관 자료

  • 개발 범위는 프로토 범위, 구현 및 검증 방식은 체크리스트와 작업 이력을 따른다. 작업 재개와 필수 지도 입력은 다른 PC에서 개발을 이어갈 때 사용한다.
  • UI 자료는 UI 폴더, 발표용 제안서와 프로토 매뉴얼은 제안서 목록, 시스템 산식과 제작 도구는 기술 참고에 있다. 사용자 프로필과 진행 중인 저장은 출하 기본값과 다를 수 있다.
  • 후속 아이디어, 이전 기획, 정리 전 마인드맵은 당시 결정의 배경을 확인할 때 사용한다.
