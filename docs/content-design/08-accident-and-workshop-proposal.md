# 사고 처리·자동차 공업사 — 프로토 상세 기획안

## 2026-11-06 후속 승인: 보행자 사고의 차량 손상

보행자/대기 승객 사고도 내구도100 기준 경미 **0~2**, 중간 **0~5**, 중대 **0~10**점을 무작위로 감소시킨다. 사용자가 이 범위를 승인했다. 각 정수는 균등하게 선택하며 손상0도 포함한다. 차량·시설의 기존 물리 충돌 손상(최대50점)은 유지한다. 동시 물리 충돌은 별도 반영하며 내구도 하한은0이다.

호스트가 신규 사건/보행자 우선 분류 시 손상량을 한 번 선택하고 안전 정차 정산에 적용한다. 선택·실제 감소량/적용 여부와 차량 적용 사건 ID를 저장/복제해 재시작·재접속·수리 후 사건 재생으로 다시 손상되지 않는다. 구 저장의 진행 중 사고에는 소급 손상을 추가하지 않는다. 중대D0은 공업사 견인칸에서 수리하고, 경미/중간D0은 기존 고장 견인·수리 절차를 이용한다. 사고비/처리 시간/운전 점수와 유료 수리 가격은 유지한다. 새 보행자 사고 팝업에는 실제 내구도 감소량을 한 행 추가한다. LAN 계약은v8이며 양쪽 실행본을 갱신한다. [실제 구현·검증](../work-history/2026-11-06-pedestrian-durability.md).

## 2026-11-06 승인 변경: 사고 등급과 결과 UI

이 절이 아래 11/05 고정값·차량 충돌 운송 유지 규칙보다 우선한다. 사용자는 다음 초기값과 기존 허용 U턴 6곳만의 표시 보강을 승인했다. 구현·실제 검사 결과는 [이번 작업 이력](../work-history/2026-11-06-accident-severity-ui.md)에 기록한다.

| 대상 | 등급 | 처리비 | 영업 시간 감소 | 운전 점수 | 복귀 |
|---|---|---:|---:|---:|---|
| 보행자·대기 승객 | 경미 / 중간 / 중대 | 3,000 / 8,000 / 15,000원 | 45 / 120 / 240초 | −10 / −25 / −40 | 중대는 공업사 |
| 차량·시설 | 경미 / 중간 / 중대 | 1,000 / 3,000 / 6,000원 | 15 / 45 / 90초 | −3 / −8 / −15 | 중대는 공업사 |

호스트가 사건당 한 번 등급을 선택한다. 초기 가중치는 보행자 60/30/10%, 차량·시설 70/25/5%다. 종류·등급·선택한 비용/시간/감점·견인 필요·처리 플래그를 저장/복제하며, 이어하기/재접속 시 재추첨하지 않는다. 기존 저장의 진행 사고는 기존 3,000원/45초를 유지하고 새 감점을 소급하지 않는다. 같은 연속 접촉은 한 사건이며, 처리비 확정 전 사람 접촉이 추가되면 선택 등급은 유지하고 사람 사고 기준을 적용한다.

유효 차량·시설 충돌도 안전 정차 후 현재 운송을 취소한다. 도착 확정 운임은 기존과 같이 보호한다. 기존 물리 손상 임계값 미만·지면 접촉은 새 사고를 만들지 않는다. 전역 운전 점수 감점은 사건 ID로 한 번만 반영하고 승객 M 점수와 구분한다.

중대 사고는 안전 정차/운송 정산 후 빈 공업사 견인칸으로 이동해야 복귀할 수 있다. 이 강제 이동은 선택한 사고 처리비·시간에 포함하며 일반 고장 견인 3,000원/30초를 추가 청구하지 않는다. 차량 내구도는 자동 회복하지 않는다. 내구도0은 공업사에서 기존 유료 수리가 필요하다. 빈 칸이 없으면 운행 잠금으로 대기하며 중복 청구하지 않는다. 일반 고장 견인/수리 가격과 기존 유료 예약 호환은 유지한다.

결과 팝업은 아이콘 + `사고 발생`, 대상/등급, 현재 운임·사고 처리비·영업 시간 감소·운전 점수 네 행, `운행 재개` 또는 `공업사에서 재개/수리`로 표현한다. 고장/정비 안내도 같은 짧은 결과 카드 방식을 따른다. 싱글은 확인 시 선택 시간을 한 번 경과하고 PVP는 해당 차량의 호스트 처리 타이머만 진행한다.

아래는 11/05 최초 구현의 기록이며 위 승인 변경과 충돌하는 값은 현재값으로 사용하지 않는다.

## 목표와 접근 선택

사고를 알아차리고, 영업 손실을 이해한 다음, 다시 운행할 방법을 찾게 한다. 기존 내구도·수리·견인을 재사용하며 사고마다 새 경제 시스템을 만들지 않는다.

| 접근 | 검토 결과 |
|---|---|
| 충돌 안내만 개선 | 작지만 보행자 접촉 후 그대로 영업하는 문제가 남음 |
| 보행자 사고 처리 + 공업사 | 이번 요청에 맞춘 상세화 대상. 운송 중단/처리 시간/복귀를 기존 서비스에 연결 |
| 보험·과실·구급차·차량 구매까지 확장 | 사용자 요청으로 후속 분리 |

사용자가 이 기획안대로 싱글/PVP 구현과 검증 후 실행 파일 갱신을 승인했다. 구현 단계와 실제 수용 결과는 별도로 기록한다.

## 포함·제외

- 포함: 일반 보행자/대기 승객의 공통 사고 판정, 안전 정차·운송 종료, 결과 화면, 사고 처리 비용/시간/장부, 공업사 건물·진입로·정비 구역·지도 핀·길안내, 기존 수리/견인의 공업사 연결, 싱글 저장·PVP 호스트 판정/봇 적용.
- 제외: 치료비 산정·상해 등급·과실 비율, 경찰/구급차/보험차 출동, 현장 장기 통제, 외형 파손/부품별 손상/성능 저하, 서비스 센터 별도 업종, 차량 구매·용품·꾸미기·정비 미니게임.

## 사고별 규칙

| 사건 | 운송 | 새 처리비/시간 | 차량 손상 |
|---|---|---|---|
| 벽/차량 충돌, D>0 | 기존 운송 유지 | 없음. 기존 손상·감점 결과만 통합 안내 | 기존 P15 강도별 손상 |
| 벽/차량 충돌, D=0 | 안전 정차 후 기존 운송 실패/확정 운임 보호 | 별도 사고비 없음. 기존 견인·수리 필요 | D0 유지 |
| 보행자/대기 승객 사고 | 안전 정차 후 진행 운송 중단 | **사건당 3,000원·45게임초** | 사람 접촉만으로 임의 내구도 차감 없음. 동시 벽/차 충돌 손상은 적용 |
| 기준 미만 사람 접촉 | 사고 처리로 전환하지 않음 | 없음 | 없음 |

사람 접촉 시작 기준은 현재 일반 보행자 기준인 몸통과 택시 차체 거리≤0.32m, 택시 속도≥1.5m/s(5.4km/h)를 우선 재사용한다. 전진/후진 모두 적용한다. 빠른 이동의 판정 누락을 막도록 직전~현재 차체 이동 구간을 검사한다. 정차한 차에 사람이 접근하는 것, 이미 탑승한 승객, 비활성 외형·배치/기술복구 유예는 제외한다. 접촉 판정은 상대 ID와 차량 ID로 호스트에서 확정한다.

같은 차량이 최초 사람 접촉부터 모든 접촉이0.8초 끊기기 전까지 일으킨 연속 접촉은 한 사건이다. 처리 잠금 중 추가 접촉은 같은 사건에 기록하고 처리비/시간을 누적하지 않는다. 복귀 후 접촉이 해제된 다음 새 사고는 새 비용을 낸다. 기존 일반 보행자 감점 경로를 공통 사건 처리로 옮겨 두 번 감점하지 않는다. 사람 사고의 기존 충돌 감점은 기본 M−10이며 콘텐츠 관리 도구의 collision 설정을 따른다. 해당 운송에1회만 적용하며 별도 운전점수/정액 벌금을 추가하지 않는다. 차량 손상 사건의 집계 규칙은 유지한다.

## 발생부터 복귀까지

1. **사건 확정**: 사건 ID·상대·운송 단계·내구도·시각을 기록한다. 신규 호출/수락/승차·서비스 구매와 H보조를 차단한다. 이미 수락한 픽업은 해제한다.
2. **안전 정차**: 가속/조향 입력을 잠그고 제동으로 멈춘다. 주변 AI는 장애물을 피하거나 대기한다. 정차 전 화면 확인을 요구하지 않는다. 끼임/공중 등으로5초 안에 정차가 불가능하면 기존 기술복구처럼 짧은 페이드 후 안전 위치를 사용한다.
3. **운송 결과 확정**: 첫 유효 도착 전 탑승 운송은0원 취소1회. 별도 취소 위약금은 없다. 도착 확정 후 하역/기상대기 중이면 확정 운임을 보존하고 안전 하차 완료로 정리한다. 공차는 운임 손실0원. 피해 대기 승객의 호출도 해제하며 사건 처리 중 다시 배정하지 않는다. 다른 차가 수락한 해당 승객도 중립 취소하고 해당 기사에 비용/감점을 부과하지 않는다.
4. **사고 처리**: 3,000원 발생 비용을1회 장부에 기록하고 엔진을 끈다. 결과 화면은 상대 유형, 운송 결과, 처리비, 처리 시간, 내구도, 다음 행동을 표시한다. 치료비·실제 법적 책임으로 표현하지 않는다.
5. **복귀**: 사고 처리 완료 후 D>0이면 운행 재개/공업사 안내, D0이면 견인 안내. 피로/연료/구토 등 다른 영업 제한은 그대로 적용한다. ‘처리 완료’가 무료 회복을 뜻하지 않는다.

사람은 짧은 놀람/정지 반응과 안내만 사용하며 유혈·신체 손상 연출은 없다. 사고 후 안전 하차/해당 보행자의 안전 위치 복원은 페이드로 처리한다. 차량 안전 위치는 사건 주변의 미리 검증된 복구 지점 중 가장 가까운 빈 곳이며 목적지/공업사로 무료 이동시키지 않는다. D0은 기존 견인 절차를 따른다. 복구 지점이 모두 점유되면 제동 잠금으로 대기하고, 추가 처리비/45초를 다시 청구하지 않는다. 실제 대기 중 게임 시계·컨디션은 해당 모드 규칙대로 흐른다.

## 비용·시간·피로의 초기 시험값

| 항목 | 제안/유지값 | 설명 |
|---|---|---|
| 사람 사고 처리비 | 신규 3,000원/사건 | 현금 우선·부족분 미납, 기존 비용/미납 장부 사용. 벌금·치료비·보험료 아님 |

| 사고 즉시 피로 증가 | **0** | 충격 피로/스트레스 게이지 도입 안 함 |
| 처리 중 피로·포만감 | 기존 깨어 있는 시간 경과 | 싱글 피로 분당4/6/8, PVP5/7.5/10. 포만 분당−5. 공복 경계가 바뀌면 구간별 계산 |

|---|---:|---:|---|
| 벽 충돌 후 D94에서 수리 | 1,200원 | 13초 | 공업사 이동 시간, 기존 감점 |
| 사람 사고, 차량 손상 없음 | 3,000원 | 45초 | 미도착 운송이면 실수령0, 정차 시간 |
| 사람 사고와 차량 충돌, D70에서 자력 수리 | 9,000원 | 70초 | 정차·공업사 이동 시간 |
| 사람 사고와 차량 충돌로 D0, 견인+수리 | 26,000원 | 135초 | 정차/공간 대기, 미도착 운송 손실 |

최대 사례는 부담이 크므로 추가 피로·추가 벌금·운임 비율 감액을 더하지 않는다. 미납으로 복귀를 보장한다. 확정되지 않은 예상 운임을 현금에서 빼지 않고 ‘이번 운송 실수령0원’으로 표시한다.

## 싱글/PVP 시간과 중단

싱글: 안전 정차 뒤 처리 확인 시45게임초를 기존 서비스처럼 일괄 경과시킨다. 확인 전에는 사고 잠금 상태를 저장하고, 결과 화면은 싱글 일시정지 상태로 추가 컨디션 경과를 멈춘다. 확인을 미뤄 운행할 수 없다. 비용은 사건 확정 후 정차 단계에서 이미 발생하므로 앱 종료로 없애지 못한다. 시간 경과/처리 완료는 한 거래로 저장해 재실행 중복을 막는다.

PVP: 정차가 확인된 호스트 시각부터45초간 해당 차량만 잠긴다. 다른 차/경기 시계는 계속된다. 비용은 시작 때 확정, 완료까지 별도45초를 다시 더하지 않는다. 남은 시간이45초보다 짧으면 경기 종료까지 잠금, 이미 발생한 비용/취소는 최종 정산에 반영한다. 사고 처리비는 수행된 사건 비용이므로 경기 종료·접속 해제 때 환불하지 않는다. 수리 같은 선택 서비스는 기존 완료 시 확정/미완료 취소 규칙을 유지한다. 사람/봇 모두 같은 비용과 타이머를 사용한다.

싱글의 일시정지는 타이머/컨디션을 멈추며 PVP 로컬 메뉴는 호스트 시간을 멈추지 않는다. 재접속/봇 승계는 사건 ID·지불 여부·남은 처리 상태를 이어받는다. PVP 사고를 캠페인 저장에 쓰지 않는다.

## 공업사 시설

**공업사 한 종류, 은계2곳·A2 PVP2곳**을 초기 배치 목표로 제안한다. 각 맵의 서로 다른 생활권에서 접근 가능하도록 나누고 기존 도로/건물을 크게 재구성하지 않는다. 정확한 좌표는 지도 실측·주행 공간 검사 후 정한다. 좌표 검증 전 배치 완료로 표시하지 않는다.

- 표현: 작은 정비 건물/간판, 렌치 지도 핀, 밝은 정비칸, 진입/출구 표시. 실내 보행이나 수리 애니메이션 없이 외부 정차 메뉴로 이용.
- 규모: 시설당 일반 수리칸1개 + 견인 전용칸2개 + 대기칸1개. PVP 전체 견인칸4개로 참가자4대 D0 상황을 수용한다. 모든 칸은 통행 차로 밖에 배치.
- 일반 수리: 탑승객 없이 기존 정차 속도/방향 조건을 만족하면 F로 견적 확인. 가격·시간·회복 내구도와 부족분 미납을 표시한 뒤 수리. 엔진 정지, 연료·청결·피로 회복 없음.
- 안내: 내구도50 이하에서 공업사 안내를 제안하고, 지도/F7에서도 선택 가능. 수리는 손상이 있으면 언제든 선택. 경로 시간/서비스 시간을 구분한다.
- 점유: 일반칸은 선착순·중복 예약 금지, 대기 취소는 무청구. 대기 중 컨디션은 자연 경과. 견인칸은 예약 확인 후 청구/이동, 지불한 예약은 수리까지 유지. 모든 칸이 찼으면 다른 공업사를 안내한다.
- 자력 이동 가능 D>0은 공업사까지 운전한다. 길가 원격 수리/무료 견인 버튼은 제공하지 않는다. 수리 종료 후 칸을 비우도록 안내하며 봇은 출차한다. PVP 무응답 장기 점유는 수리 완료 후10초에 같은 부지 내 검증된 빈 출차 공간으로 옮기는 복구안으로 처리하고, 빈 공간이 없으면 이동을 강행하지 않는다.
- 봇: 기존 수리 필요도/비용 판단을 유지하며 시설 목적지만 공업사로 연결한다. 시설 간 경로·점유를 비교하고 플레이어와 동일 비용·시간을 부담한다.

### 기존 주유소 수리에서 이전

새 플레이의 주유소는 주유/세차, 공업사는 수리/견인으로 역할을 나눈다. **기존 저장에 유료 예약된 주유소 정비칸은 해당 수리 완료까지 호환 유지**하며 재견인/재청구하지 않는다. 진행 중 거래·예약 ID를 먼저 복원하고 기존 예약이 없을 때만 새 공업사 후보를 사용한다. 새 공업사/진출입 검증이 실패한 지도는 기존 지원 시설을 임시 fallback으로 남기며 조용히 예약을 폐기하지 않는다.

공업사는 게임용 시설임을 문서화한다. 신규 지도 JSON/배포 입력을 실제 변경하는 구현에서는 로컬 입력 manifest·관련 OSM 대조 설정·지도 ZIP·배포 manifest를 다시 생성/검증한다. 이번 기획 작업은 지도를 변경하지 않는다.

## 저장·화면·검증 계약

사건 상태는 감지→정차→처리 대기/진행→완료→복귀로 나누고 사건 ID, 상대 ID, 운송 결과 확정 여부, 비용 거래 ID, 남은 시간/호스트 완료시각, 복귀/시설 예약을 저장한다. 구 저장에 사건 정보가 없으면 진행 사고 없음으로 복원하며 비용을 소급하지 않는다. 돈/미납/비용·운송 취소·시간 경과 각각1회만 반영한다.

결과 화면 예: ‘보행자 접촉 / 운송 중단·실수령0원 / 처리비3,000원 / 처리45초 / 추가 피로 없음·시간 경과 적용 / 내구도70·수리 권장’. 확정 운임 보존 사례는 그 결과로 문구를 바꾼다. 실제 피로 예상량은 현재 공복 상태로 계산하고 완료 뒤 실제량을 보여준다.

구현 수용 검사:

1. 차량/벽/지면·저속접촉/후진/고속 관통·일반보행자/대기승객/탑승객 제외, 연속 접촉·복구 유예·동시 충돌의 비용/감점 중복 없음.
2. 공차/픽업/운송/도착 확정·하역/졸음/D0 동시 발생, 다른 차량이 수락한 피해 승객, 운임 확정 보존.
3. 잔액0·미납·공복25/10 경계·피로100·최종일 경계·일시정지·앱 재시작 단계별 거래1회.
4. 공업사 진출입 실제 물리 주행, 일반/견인칸 점유·4대D0·모든 칸 점유·기존 유료 예약 저장 호환.
5. PVP 호스트/참가자/봇·재접속·경기 종료 직전 사고, 공통 시계와 차량별 잠금·최종 비용 복제.
6. 사람20분/3일 체감: 사고 인지, 처리시간 지루함, 수리 이동 거리, 사고 후 미납 탈출 가능성, 반복 사고 빈도. 자동검사와 별도 기록.

우선 구현 순서는 공통 사고 사건/장부·시간 → 결과 화면/운송 예외 → 공업사 배치/예약 이전 → LAN/봇·저장 검증이다. 수치 확정과 실제 배치는 다음 단계이며 이 문서 작성만으로 구현/검증 체크를 올리지 않는다.
