# 승객 승하차 지점 다양화

기준일: 2026-10-26. **기존 S01~S12 + 일반 영업용 포켓 12곳, 총 24개 후보**와 실제 대기 승객 분포가 구현됐다. 변경 전 사양·좌표 보정 과정은 [변경 이력](../design-history/content-design/14-passenger-stop-variety-history.md), 승객 운송은 [04](04-passengers-and-reservations.md), 고정 9코스는 [09](09-prototype-scenarios.md)를 따른다.

## 콘텐츠와 적용 범위

| 콘텐츠 | 조건·처리 | 상태 |
|---|---|---|
| 고정 PS01~09 | 기존 S01~S12와 상황 연결 보존. 상황 필수 경유·하루 전체 완주 없음 | 구현 |
| 일반 호출 | 가능한 후보에서 일반 호출 2개·고정 코스 1개 혼합. 현재 위치와 공유 방향 경로의 접근 거리·운송 길이 고려 | 구현 |
| 길가 승객 | 실제 보이는 대기 승객과 안전 정차 조건을 충족한 경우 승차 시도 | 구현 |
| 목적지 변경·경유 | 공통 후보에서 안전하고 연결된 지점 사용. 한 운송 ID·한 번 정산 유지 | 구현 |
| 형상 | 아스팔트 정차 공간·폭 1.9m 대기 보도·기존 보도 연결. 차량 전체 폭/길이, 건물·횡단보도·교차로 제외 검사 | 자동 형상 검사, 실제 현장 미확인 |
| 데이터 | `config/maps/eungye-passenger-stops.json`, 생성·검사 `tools/build_passenger_stop_catalog.py` | 게임 전용 보완, 원본 지도/필수 입력을 덮지 않음 |
| 검증 표시 | `game-only-field-unverified` 유지 | 게임 후보를 실제 합법 정차 장소로 확정하지 않음 |

## 실제 대기와 재등장 조건

| 조건 | 동작 |
|---|---|
| 기본 길가 분포 | 캠페인·영업일·안정 지점 ID로 일부(시험값 35%) 배치. 24개 후보가 모두 승객을 갖지는 않음 |
| 갱신 | 영업 경과 120초마다 먼 지점만 갱신, 택시 90m 이내 승객은 갑자기 출현/소멸하지 않음 |
| 빈차의 가용 호출 | 해당 승차지에 대기 승객 표시 |
| 수락한 호출 | 분포·재호출 대기와 관계없이 예약된 호출 승객 보장. 실제 탑승 시 숨김. 개인 예약 기능과 구분 |
| 빈 길가 지점 | 보이지 않는 승객을 태울 수 없음 |
| 비어 있던 하차지 | 하차 후 90초 동안 자동 신규 호출·길가 대기 제외 |
| 이미 대기자가 있는 하차지 | 기존 승객 유지 |
| 운송 중 목적지 | 다른 가용 호출 때문에 대기자를 강제 배치하지 않음. 자연 분포상 있을 수도 없을 수도 있음 |
| 청결·구토 후 승차 | 시도·거부·호출 제한은 [15](15-drunk-passengers-and-cleanliness.md) 기준. 후보 존재가 승차 성공을 보장하지 않음 |
| 저장 | 분포·갱신 차수·남은 갱신시간·안정 ID 보존. 재실행 재추첨 금지 |
| 구 저장·지도 편집 | 새 필드 없는 저장은 진행 운송 보존하며 분포 이행, 편집 시 ID 재매핑 |

## 후보 유형과 배치 조건

| 유형 | 의도한 경험 | 확인할 조건 |
|---|---|---|
| 주거지 인접 | 출근·귀가·짧은 생활 운송 | 보도 대기·안전 연석·건물 출입 동선 |
| 상업·생활 시설 | 식사·쇼핑·업무 | 시설 입구와 정차 위치 분리, 진출입/주차 방해 없음 |
| 대중교통 연결부 | 환승·긴 운송 | 버스 정차 구역·횡단보도·교차로를 피한 별도 자리 |
| 의료·교육 주변 | 시간 민감·이동 편의 요구 | 실제 이름은 확인 후 사용, 출입구·보행 안전·정차 가능 여부 |
| 외곽 연결 도로 | 동네 간 긴 운송 | 해당 방향 진입/이탈·반대편 유턴 강제 여부 |

위 유형은 역할 분류이며 특정 시설의 존재나 후보별 대사 구현을 뜻하지 않는다. 후보별 차로 방향·연석·보도 대기점·경로·신호/표지·정차 제한·교차로/횡단보도 거리·시설 출입 근거를 기록한다. 불확실한 후보는 공개 대신 검토 대상으로 남긴다.

## 경로·유효성·승객 요구

| 항목 | 규칙·조건 |
|---|---|
| 안정 ID | 표시명과 분리된 stopId·지도/카탈로그 리비전·접근 차로/방향·대기 위치·유형·검증 상태 |
| 호출 가능 | 현재 위치→승차지→목적지가 연결되고 픽업 시간 예산 안에 도달 가능한 후보 |
| 안전 정차 | 진행 방향 오른쪽 연석·저속·올바른 방향, 승객은 보도 대기. 반대편·차도 중앙·교차로·횡단보도 유도 금지 |
| 무효 후보 | 형상 변경·차로 폐쇄·횡단보도 추가로 부적합해지면 숨김. 진행 운송을 다른 장소로 임의 이동하지 않음 |
| 중복·반복 | 점유·재호출 대기·직전 조합 고려. 후보가 적으면 반복 허용, 허위 경로 생성 금지 |
| 거리 구성 | 짧은/중간/긴 운송 혼합, 남은 시간·연료·피로 안내를 함께 고려. 초과 영업 가능 규칙 유지 |
| 호출 정보 | 목적지·약정 운임·요구 만족도를 수락 전 표시. 핵심 요청은 탑승 뒤 등장 |
| 요청 불가 | 목적지/경유 후보가 없거나 연결이 사라지면 원래 운송 유지·중립 결과 |
| 기한 | 합법적 대기·접근 거리를 반영, 먼 승차지가 요청을 처음부터 실패시키지 않도록 구성 |
| 만족도 | [11](11-passenger-request-effects.md) 기준. 지점 유형만으로 만족도·보너스 자동 지급 없음 |
| 시간대·유형별 대사 | 수요 연출 후속 항목, 현재 구현 완료로 표시하지 않음 |

`MapStop.CanStop`은 연석 위치·방향·속도 판정이며 법정 거리 전체와 실제 현장 적법성을 확인하는 시스템은 아니다. 정차 관련 법규·현장 대조는 [02 법규 평가](02-driving-evaluation.md)와 [06 맵](06-world-map-and-driving.md)의 근거 관리 기준을 따른다.
