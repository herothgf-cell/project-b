# 경기 흐름과 공통 규칙

상태: 기획 초안 / PVP 미구현  
작성일: 2026-10-27

## 문서의 책임과 결정 상태

이 문서는 경기 시작·공통 시계·마감·중도 이탈·결과 확정 시점을 정의한다. 승객 상태는 [승객과 운임](04-passengers-and-fares.md), 점수 계산과 동점은 [점수와 결과](05-scoring-and-results.md)가 소유한다.

| 구분 | 내용 |
|---|---|
| 사용자 확정 | 실제 사용자끼리 한정된 자체 제작 공간에서 운송·운전 성과로 경쟁한다. |
| 본 문서 제안 | 초대방에서 준비를 맞추고, 서버의 동일한 경기 시계로 시작·마감한다. |
| 본 문서 제안 | 본 경기 종료 후 이미 승차한 운송만 공통 추가 시간 안에 완료할 수 있다. |
| 미정 | 참가 규모, 본 경기 길이, 추가 시간 채택 여부·길이, 재접속 허용 시간, 최종 이탈 정책. |

설정 후보와 승인 상태는 [결정·밸런스](09-decisions-and-balance.md)에서만 관리한다. `MatchDurationSeconds`는 경기 생성에 필요한 설정이며, 특정 길이를 제품 기본값으로 확정하지 않는다.

## 공통 권한과 경기 구성

여기서 서버는 경기 상태를 확정하는 논리적 권한을 뜻한다. 방장 호스트와 전용 서버 중 어떤 배치를 사용할지는 [네트워크·빌드](07-network-and-build.md)의 검증 대상이다.

- 방장은 방 설정 변경과 시작을 요청한다. 시작 가능 여부·시각·경기 결과를 임의로 확정하지 않는다.
- 클라이언트는 입력과 준비 상태를 요청하고, 서버가 승인한 상태·설정 버전·이벤트 순서를 표시한다.
- 경기 생성 시 `MatchId`, 지도·콘텐츠 버전, 공급 시드, 참가 명단, 점수 설정, 시간 설정을 함께 동결한다.
- 시간·점수·차량 설정을 바꾸려면 로비로 돌아가 새 경기 구성을 만든다. 진행 중 방장에게 별도 변경 권한을 주지 않는다.
- 메뉴·지도·입력 장치 변경·일시적 접속 끊김은 공통 시계를 멈추지 않는다. 로컬 `Time.timeScale`을 경기 시계로 사용하지 않는다.

## 경기 상태와 전환 소유자

아래 상태명은 신규 데이터 계약 제안이며 현재 구현된 타입이 아니다. 전환의 최종 소유자는 모두 서버다.

| 상태 | 진입 조건 | 허용 행동·표시 | 다음 상태와 조건 |
|---|---|---|---|
| `Lobby` | 방 생성 또는 재경기 구성 | 참가·자리 선택·설정 확인 | 방장 시작 요청과 유효 구성 확인 후 `Preparing` |
| `Preparing` | 명단·설정 버전 동결 | 지도 로드·동일 버전 확인·준비 응답 | 전원 준비 후 `Countdown`; 실패·철회 시 `Lobby` |
| `Countdown` | 서버가 공통 시작 틱 예약 | 시작 안내, 차량 이동·승차·점수 잠금 | 예약 틱에 `Running`; 참가 조건 훼손 시 `Lobby` |
| `Running` | 공통 시작 틱 도달 | 빈차 이동·승차·운송·하차·위반 판정 | 본 경기 종료 틱에 `Closing` 또는 `Settling` |
| `Closing` | 공통 추가 시간이 있고 본 경기 종료 | 신규 승차 잠금, 허용된 기존 운송 하차 | 공통 최종 종료 틱에 `Settling` |
| `Settling` | 공통 최종 종료 틱 도달 | 조작·새 판정 잠금, 승인 이벤트 정산 | 원장·운송 상태 대조 성공 시 `Results` |
| `Results` | 결과 스냅샷 확정 | 순위·항목별 내역·재경기 선택 | 새 경기 구성으로 `Lobby` 또는 방 종료 |
| `Aborted` | 권한 유실·필수 상태 손상 등 경기 무효 | 중단 사유·미확정 상태 안내 | 방 종료 또는 새 경기의 `Lobby` |

`Preparing` 실패는 실패한 참가자·버전·시간 초과 사유를 표시한다. 조용히 미준비자를 경기에서 제외해 시작하지 않는다. 카운트다운 취소는 새 시작 틱을 예약하기 전까지 모든 차량을 잠근다.

## 시작 절차와 첫 경쟁 기회

| 조건·행동 | 서버 처리 | 결과·예외 |
|---|---|---|
| 참가자가 준비 선택 | 로드·구성 일치·조작 가능 상태 확인 | 준비 표시와 실제 시작 가능 상태를 구분 |
| 방장 시작 요청 | 참가 조건과 필수 설정 검증 | 필수 시간 값·유효 맵이 없으면 시작 거절 |
| 시작 틱 도달 | 차량 조작·공유 승객 공급을 같은 틱에 개방 | 로딩 속도나 방장 여부로 먼저 승차할 수 없음 |
| 경기 시작 후 참가 요청 | 초기안은 관전 또는 다음 경기 대기 | 진행 중 선수 합류·기록 승계는 제외 제안 |
| 재경기 선택 | 새 `MatchId`와 공급·배치 구성 생성 | 이전 승객·운임·원장·준비 상태를 재사용하지 않음 |

첫 공급의 접근성·배치 검증은 [승객 공급](04-passengers-and-fares.md#공급과-접근-기회의-공정성)에서 정의한다. 차량 위치만 대칭이라고 동등한 접근 기회로 간주하지 않는다.

## 공통 시각과 처리 경계

서버는 실제 적용한 고정 시뮬레이션 틱을 기준으로 아래 시각을 배포한다. 화면의 초 단위 반올림값은 판정 근거가 아니다.

| 값 | 정의 | 판정에 쓰는 의미 |
|---|---|---|
| `StartTick` | 서버가 승인한 시작 틱 | 이 틱부터 조작·경기 사건을 허용 |
| `MainEndTick` | 시작 틱에 본 경기 설정 길이를 더한 경계 | 이 틱부터 신규 승차 금지 |
| `FinalEndTick` | 본 경기 종료에 공통 `FinishGraceSeconds`를 더한 경계 | 이 틱부터 신규 하차·주행 사건 금지 |
| `RulesVersion` | 동결된 경기 규칙 식별자 | 시간 환산·경계 처리·점수 계약 일치 확인 |

서버는 설정 초를 틱으로 바꾼 실제 경계값을 시작 전에 고정한다. 추가 시간은 음수가 될 수 없으며, 추가 시간이 없는 구성에서는 두 종료 틱이 같다.

- 승차의 유효 구간은 `StartTick ≤ 승인 틱 < MainEndTick`이다. 본 경기 종료와 같은 틱의 승차 요청은 거절한다.
- 하차와 주행 사건의 유효 구간은 `StartTick ≤ 확정 틱 < FinalEndTick`이다. 최종 종료와 같은 틱에는 완료를 새로 만들지 않는다.
- 같은 틱에서는 시간 경계 적용 → 지도 경계·복구 상태의 유효성 확인 → 유효 주행 사건 반영 → 승하차 처리 → 원장 변경의 순서로 처리한다. 경계 밖 지름길이나 복구 중 위치로 승하차를 먼저 확정하지 않는다.
- 서버에 늦게 도착한 요청을 클라이언트가 주장한 과거 시각으로 소급 승인하지 않는 것을 초기안으로 한다. 지연 편향은 [플레이테스트](10-playtest-and-acceptance.md)에서 측정한다.

## 본 경기 종료와 최종 마감

| 조건 | 행동·처리 | 점수·운송 결과 |
|---|---|---|
| `MainEndTick` 도달 | 공급·신규 승차 중지, 대기 승객 만료 | 내비 선택·승차 요청 중 표시만으로 운송 자격을 얻지 않음 |
| 본 경기 종료 전에 승차 확정 | `Closing`에서 기존 목적지까지 운송 허용 | 모든 선수에게 같은 `FinalEndTick` 적용 |
| 마감 시간 중 이미 빈차 | 신규 승차 불가, 공통 마감 대기 | 계속 운전하면 해당 주행 위반은 반영 |
| 공통 최종 종료 전에 유효 하차 | 기존 고정 기본운임·완료 보너스 정산 요청 | [점수 규칙](05-scoring-and-results.md)에 따라 한 번 확정 |
| `FinalEndTick`까지 미완료 | 차량 조작 잠금, 운송을 만료 처리 | 운임·완료 보너스 없음, 이미 확정된 위반 감점 유지 |

각 승객의 승차 시점부터 추가 시간을 새로 계산하지 않는다. 개인별 조기 종료 버튼·목적지까지 무제한 연장·남은 거리 비율 지급은 초기안에 없다. 미완료 운송에 대한 숨겨진 부분 운임도 없다.

추가 시간은 선수마다 다른 보정이 아니라 경기 전체의 마지막 완료 기회다. 추가 시간 없는 구성과 있는 구성을 비교한 뒤 최종 채택 여부를 결정한다.

## 결과 확정과 재전송

- `Settling`은 새 플레이를 허용하는 연장 시간이 아니다. 최종 종료 전에 서버가 이미 확정한 사건만 원장에 반영한다.
- 서버는 모든 승객의 종료 상태, 유일한 운송 정산, 사건별 누적 감점, 최종 종료 틱에 동결한 참가 자격을 대조한 뒤 `ResultVersion`을 발행한다.
- `Results` 진입이 최종 순위 확정 시점이다. 그 전 순위는 잠정이며 결과 화면에 확정 여부를 표시한다.
- 중복 패킷·화면 재열기·재접속은 같은 결과 스냅샷을 다시 전달할 뿐 정산을 다시 실행하지 않는다.
- 필수 원장 누락·상태 불일치를 해결할 수 없으면 승자를 추정하지 않고 `Aborted`로 기록한다. 순위 산식은 [05](05-scoring-and-results.md)만 따른다.

## 중도 이탈과 접속 끊김 정책 초안

선수의 연결 상태와 경기 상태를 분리한다. 아래는 초대방 시제품 권고안이며, 공개 경쟁의 최종 정책은 [미결정 항목](09-decisions-and-balance.md)이다.

| 상황 | 서버 처리 | 참가·운송·결과 |
|---|---|---|
| 시작 전 게스트 연결 끊김 | 준비·카운트다운 취소 후 로비 복귀 | 인원 확인과 준비를 다시 진행 |
| 경기 중 게스트 일시 끊김 | 서버가 차량 제동·안전 격리, 입력 중지 | 재접속 유예 동안 슬롯·기존 승객·확정 원장을 유지 |
| 동일 선수 유예 내 복귀 | 인증된 동일 참가자에게 서버 상태 재전달 | 남은 공통 시간으로 계속, 누락 시간 보상 없음 |
| 최종 종료 틱까지 유예 만료 또는 명시적 나가기 승인 | 해당 선수를 `Withdrawn`으로 확정 | 미완료 운송 취소, 확정 기록 보존, 승자 자격 제외 |
| 유예 중 최종 종료 도달 | 미완료 운송 만료, 당시 참가 자격 동결 | 유예가 남았다면 기존 완료 실적으로 순위 대상 유지. 마감 연장·자동 완료 없음 |
| 최종 종료 이후 유예 만료 또는 나가기 | 연결·결과 수신 상태만 갱신 | 이미 동결한 참가 자격·최종 순위를 변경하지 않음 |
| 결과 확정 전 방장 호스트 권한 유실 | 초기안은 경기 전체 `Aborted` | 미검증 호스트 이관으로 결과를 이어 붙이지 않음 |
| 결과 확정 전 전용 서버 권한 유실 | 복구 보장이 없는 초기안은 `Aborted` | 일부 클라이언트 기록만으로 승자를 선정하지 않음 |
| 결과 확정 후 권한 서버 종료 | 이미 수신한 확정 결과 스냅샷 유지 | 못 받은 클라이언트는 결과 미수신·확인 불가 표시. 새 승자 추정이나 무효화 없음 |
| 최종 종료 전 모든 선수 이탈 | 경기 중단 사유 확정 | 승자 없는 중단 결과만 제공 |

재접속 유예 중 차량은 다른 선수의 길을 막거나 자동 운송하지 않게 한다. 격리 직전까지 확정된 위반은 보존하고, 서버의 격리·복구 이동은 주행 보상·위반·운임 거리로 계산하지 않는다.

상대 이탈만으로 즉시 승리시키지 않는다. 남은 선수는 공통 종료까지 진행하고, 완료 운송과 참가 자격을 갖춘 경우에만 [승자 조건](05-scoring-and-results.md#순위와-동점)을 적용한다. 관전 전환·명시적 이탈 후 선수 복귀는 다음 경기부터 허용하는 것을 제안한다.

참가 자격의 기준 시각은 `FinalEndTick`이다. 같은 틱에는 그 틱까지 승인된 명시적 이탈과 `ReconnectExpiryTick ≤ FinalEndTick`인 유예 만료를 먼저 반영한 뒤 자격을 동결한다. 유예 만료 틱이 더 뒤이면 일시 단절만으로 자격을 잃지 않는다. `Settling`이 오래 걸려도 이후 연결 변화로 자격을 다시 판정하지 않는다. 클라이언트가 주장한 과거 나가기 시각을 소급 적용하지 않는다.

## 지도 오류와 복구 불가

안전한 복구 지점이 일시적으로 점유된 경우 차량을 격리한 채 같은 합법 경로의 후방 후보를 다시 확인한다. 대기·재시도 한도는 [09](09-decisions-and-balance.md)의 `RecoveryPolicy`로 동결하며 공통 경기 시계는 멈추지 않는다.

한도 안에 유효 지점을 찾지 못하거나 지도·경로 오류로 복귀가 불가능하다고 확정되면, 초기 초대방에서는 경기 전체를 `Aborted`로 처리하는 것을 제안한다. 시스템 복구 실패를 선수의 자발적 이탈로 바꾸거나 다른 선수를 자동 승리시키지 않는다. 기존 원장은 진단용으로 보존하되 확정 순위로 게시하지 않고, 해당 지도 구성은 수정·재검증 전 새 경기 선택에서 제외한다. 이는 검증용 초기 정책이며 공개 경기의 악용·복구 정책은 P5 진입 전에 다시 판단한다.

## 구현에 필요한 데이터와 수용 확인

| 데이터 항목 제안 | 필요한 내용·불변 조건 |
|---|---|
| 경기 스냅샷 | `MatchId`, 상태, `RulesVersion`, 지도·콘텐츠·공급 시드, 동결 설정 |
| 공통 시간 | 시작·본 종료·최종 종료 틱, 서버 현재 틱, 설정 초를 틱으로 환산한 결과 |
| 참가 기록 | 안정된 `PlayerId`, 준비 버전, 연결 상태, 재접속 만료 틱, 이탈 사유 |
| 종료 기록 | 종료 유형, 최종 종료 틱의 참가 자격 스냅샷, 원장 마지막 순번, `ResultVersion`, 확정 또는 무효 사유 |

| 확인 장면 | 통과 조건 |
|---|---|
| 종료 경계의 동시 승차·하차 | 같은 서버 틱이면 모든 클라이언트에 같은 승인·거절 결과 표시 |
| 마지막 직전 승차와 일찍 승차한 운송 | 남은 추가 시간이 다르지 않고 같은 최종 종료에 잠김 |
| 게스트 끊김·복귀·유예 만료 | 공통 시계·확정 감점 유지, 중복 승객·운임·새 슬롯 생성 없음 |
| 방장 종료·결과 수신 중 재연결 | 무효 사유 또는 같은 확정 결과 재전달, 임의 승자 생성 없음 |

세부 검증 목록과 출시 전 게이트는 [플레이테스트·수용 기준](10-playtest-and-acceptance.md), 개발 순서는 [로드맵](08-development-roadmap.md)으로 연결한다.
