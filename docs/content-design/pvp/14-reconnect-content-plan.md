# PVP 재접속·승객 공통 콘텐츠 연동 계획

사용자 승인: 재접속/남은 검증, 완료된 승객·내구도 확인 후 PVP 적용, 다른 작업 보존, 이력·커밋·푸시.
실행: executing-plans/TDD. 기본 계약은 pvp/01·07·08, 승객 구현 근거는 main9d05a40의 배포/검증 이력. 내구도·수리는 해당 이력상 미구현.

1. 완료된 main만 PVP worktree에 merge. LATEST 충돌은 양쪽 유지. 캠페인 소스/배포는 main 그대로 보존.
2. PvpReconnectRegistry: 서버 난수256bit 자격, 한 guest slot, 연결 중 중복복귀/다른 자격/정확한 만료 경계/명시 이탈 거절. 유예30초는 시험값. 호스트 상실은 복구불가. 자격은 프로세스 메모리에만 두고 로그/로컬 저장에 기록하지 않음. 직접IP의 암호화되지 않은 신뢰 LAN 실험 한계를 유지.
3. PvpNetworkSession: 연결ID와 서버 슬롯 분리, 서버가 disconnect를 감지한 시점에 즉시 정지·시각 격리·상태 보존. 새 연결epoch마다 입력/예측 이력을 초기화하고 서버 스냅샷으로 복원. client 자동/수동 재시도, 제한시간/거절 원인 표시. 명시 나가기는 자격 폐기. 원격 차량은 수신 목표에 보간하되 실제 권한 상태와 분리.
4. 완료된 PassengerBehaviorState를 호출하는 PvpPassengerCatalog: 유형/변주/초기 대사 재사용, 캠페인 저장·점수·청결 효과를 호출하지 않는 미리보기. Host 권한으로 선택하며 reconnect에도 같은 선택복원. 11특수유형34변주와 일반승객 확인. 실제 승객 경쟁/정산은 P3 게이트 이후.
5. Editor red→green: 자격 위조/중복/유예/이탈, 전체 catalog/효과격리, epoch/restore, 보간경계. 실제 Player: 정상/재접속/잘못된자격/유예만료/명시이탈/호스트종료 + 지연손실. 기존 campaign·passenger 모델/배포manifest/Strict. 가능하지 않은 다른PC·사람조작감은 미완료로 명시.
6. 적용 검토표: 완료 승객 요소별 즉시연동/후속조정, 내구도0/충돌책임/수리비시간/복구경제는 후보와 확정 분리. 최신 이력·로드맵 갱신, feature/pvp-prototype push.

판단: P2 전체를 통과하기 전 실제 승객·정산 확대 금지 계약을 유지하므로 이번 콘텐츠 연동은 공통데이터의 실제 PVP 미리보기와 서버복원까지만 구현한다. 새 수치/경제/내구도 코드를 캠페인 확정으로 간주하지 않는다.
실행 완료 범위와 실제 결과는 [날짜별 이력](../../work-history/2026-10-29-pvp-reconnect-content.md)에 기록했다. 독립 리뷰의 이력 소진/일시 중복 거절 복귀 누락을 수정하고 실제 패킷 차단 후 재가속 검사로 보완했다. 다른PC·사람조작감/P2 전체 게이트는 남아 있다.
