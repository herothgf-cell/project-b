문서의 책임과 결정 상태

이 문서는 PVP 총점·완료 보너스·위반 감점 원장·순위·동점을 정의한다. 기본운임 원약정은 승객·운임, 최종 순위 확정 시점과 이탈 자격은 경기 흐름이 소유한다.

구분 내용
사용자 확정운임과 운전 점수가 승패에 기여하며, 운임의 영향이 충분해야 한다.
본 문서 제안완료 기본운임 환산 + 완료운송 안전 보너스 − 모든 주행의 위반 감점.
본 문서 제안부호 있는 누적 원장, 운송 없는 선수의 승자 제외, 동률이면 공동 순위 허용.
미정운임 환산율·안전 보너스·사건별 감점의 수치와 최종 상대 비중.

수치 후보는 결정·밸런스에서만 관리한다. 이 문서의 계산 예시는 산술 검증용 가상 입력이며 밸런스 기본값이 아니다.

점수 산식과 정수 계산

선수 p의 총점은 Score(p) = Σ FareScore(t) + Σ CompletionBonus(t) − Σ Penalty(e)다. t는 서버가 완료 정산한 운송, e는 해당 선수에게 귀속한 고유 주행 사건이다.

항목 정의 반영 시점
FareScore(t)floor(QuotedBaseFare(t) / FareWonPerPoint)유효 하차 완료 정산 때 한 번
CompletionBonus(t)안전 자격이 있으면 floor(FareScore(t) × SafeTripBonusRate), 그 외에는 없음운임과 같은 완료 정산 때 한 번
Penalty(e)같은 사건에서 확정된 감점 후보 중 가장 큰 감점량사건 확정 즉시, 이후 상향분만 추가 반영
Score(p)모든 원장 증감의 합계서버 원장 순번 갱신 때마다

FareWonPerPoint > 0, SafeTripBonusRate ≥ 0이며 감점량은 음이 아닌 정수여야 한다. 운임 환산을 운송별로 먼저 내림하고, 그 정수에 보너스율을 곱해 다시 내림한다. 전체 운임을 합친 뒤 다시 환산하지 않는다. 비율은 정수 분자·분모 또는 동일한 고정소수점 규약으로 저장해 모든 서버·화면에서 같은 결과를 만든다.

총점에는 게임 규칙상의 상한·하한을 두지 않는다. 음수도 그대로 유지하며, 캠페인의 제한된 범위 운전 점수를 재사용하거나 음수 누적을 지우지 않는다. 저장·계산 자료형의 범위 초과는 오류로 검출하고 숫자가 반대 부호로 돌아가게 두지 않는다.

승객 만족도 S/M/R, 캠페인 운전 점수의 운임 배율, 캠페인 실수령을 위 식에 추가로 곱하지 않는다. 04가 확정한 원약정 기본운임만 사용한다.

완료운송 안전 보너스

보너스의 초기 제안은 유효하게 완료했고, 직전 유효 완료 직후부터 이번 완료까지의 안전 구간에서 자격을 잃지 않은 경우에만 지급하는 운임 비례 가산이다. 첫 구간은 경기 시작부터이며 빈차로 승객을 찾는 주행도 포함한다. 운전 중 별도 양의 점수를 계속 쌓는 구조는 두지 않는다.

조건·행동 안전 자격·보너스 이유·예외
경기 시작 또는 직전 유효 완료 직후새 안전 구간 시작기존 누적 감점은 그대로 유지
빈차·탑승 중 새로운 고유 사건의 양수 감점 확정현재 구간의 안전 자격 해제감점 원장은 즉시 반영하되 추가 중복 감점을 만들지 않음
이미 감점한 사건의 상향 확정최초 귀속 안전 구간 유지차액은 계속 차감하되 같은 사건을 다음 구간의 새 위반으로 세지 않음
구간 중 위반 없이 유효 하차완료 보너스 지급 후 구간 종료단순 정차가 아니라 실제 운송 완료가 필요
구간 중 위반 후 유효 하차운임 환산만 지급, 보너스 없이 구간 종료잃은 자격을 같은 길 반복·대기로 회복하지 않음
승차·운송 취소·재접속·차량 복구현재 구간과 안전 자격 유지손님을 바꾸거나 연결을 끊어 빈차 위반을 지울 수 없음
운송 만료·미완료완료 보너스 없음, 새 구간 생성 없음진행률·목적지 근접·입력 전송만으로 보너스를 만들지 않음

같은 틱의 위반과 하차 순서는 01의 공통 처리 순서를 따른다. 하차 확정 이벤트까지 이전 구간에 넣고 그 다음 이벤트부터 새 구간으로 본다. 사건에 최초 감점 시점의 SafetySegmentId를 기록해 상향 때도 유지한다. 하차 시 보너스를 고정하며 이후 운전 상태로 지난 운송을 다시 계산하지 않는다.

안전 자격 해제는 지급 조건의 변화이며 별도 음수 항목이 아니다. 접촉·차량 흔들림·필요한 급제동만으로 자격을 해제하지 않고, 책임이 확인되어 감점이 확정된 사건만 사용한다. 결과에는 즉시 감점과 보너스 미지급 사유를 구분해 보여 준다. 상대 비중은 09의 비교 플레이에서 결정한다.

모든 주행의 즉시 감점

주행 상황 처리 막아야 할 악용
빈차로 승객을 찾는 중확인된 위반을 즉시 총점에 차감빈차일 때만 난폭 운전하고 승차 때 기록 초기화
탑승 운송 중같은 방식으로 차감하고 운송 안전 자격 갱신운임 정산 때까지 감점을 미루어 취소로 회피
마감 추가 시간 중유효 경기 틱의 주행 위반 계속 반영운송 완료 후 남은 시간의 위반을 무시
신호 대기·주차·같은 구간 왕복양의 점수·회복 지급 없음대기 시간·루프·반복 상호작용으로 점수 생산
판정 근거 부족보류 사유만 기록하고 확정 감점 없음추정만으로 불리한 점수를 먼저 부여
서버 격리·복구 이동점수 사건 생성 대상에서 제외재접속 보호 이동으로 이익·불이익 발생

어떤 행동이 법규 위반인지, 같은 사건의 공간·시간 경계를 어떻게 묶는지는 주행·교통이 정의한다. 그 문서는 판정 근거와 사건 분류를 제공하고, 이 문서는 금액·점수 반영 방식을 소유한다.

동일 사건의 중복 감점 방지

서버는 원인·접근·연속 행동을 묶은 IncidentId를 발급한다. 센서 프레임, 클라이언트 재전송, 관찰 컴포넌트 수를 새로운 사건 수로 보지 않는다.

  • 사건별로 AppliedPenalty(e)를 저장한다. 새 확정량이 더 크면 Delta = NewPenalty − AppliedPenalty만 음수 원장에 추가한다.
  • 같은 사건에서 정지선 침범 뒤 더 큰 신호 위반이 확정되어도 두 감점을 합산하지 않는다. 최종 사건 감점은 가장 큰 하나다.
  • 더 작거나 같은 판정·같은 사건 버전의 재전송은 원장을 바꾸지 않는다.
  • 서로 독립된 실제 위반은 각각 별도 사건으로 기록한다. 임의의 긴 시간창 하나로 모든 위반을 무한히 합치지 않는다.
  • 충돌·연속 접촉·복수 법규의 사건 묶음은 02의 규칙을 공유하며, 점수 시스템이 자체 타이머로 다시 판정하지 않는다.

계산 검증 예시: 같은 사건에서 감점량 2가 먼저 확정되고 이후 7로 상향되면 원장에는 −2, −5가 남는다. 총 감점은 7이며 9가 아니다. 같은 사건을 다시 전송해도 합계가 바뀌지 않는다. 이 수치는 실제 사건 배점 제안이 아니다.

정산 원장과 멱등 처리

거래 종류 고유 키 제안 원장 변화 반드시 함께 확정할 상태
완료 운송MatchId + TripId + Completion운임 환산·안전 보너스의 항목별 가산승객 Completed, 운송 완료 틱, 고정 약정·안전 자격
사건 최초 확정·상향MatchId + PlayerId + IncidentId + Revision아직 반영하지 않은 감점 차이사건 최종 감점량·적용 버전
취소·만료운송 종료 키와 사유미지급 사실 기록, 새 양의 점수 없음종결 상태와 기존 사건 원장 유지
결과 확정MatchId + ResultVersion점수를 재지급하지 않고 집계 스냅샷 생성원장 마지막 순번·참가 자격·최종 순위

완료 상태 변경과 운임·보너스 기록은 하나의 원자적 처리 단위로 묶는다. 중간 실패 후 재시도해도 두 항목이 모두 한 번만 반영되거나 아직 둘 다 미확정이어야 한다. 완료만 됐는데 운임이 사라지거나, 운임만 두 번 들어오는 상태를 허용하지 않는다.

서버 원장을 결과의 근거로 삼으며 클라이언트는 LedgerSequence와 총점 버전을 표시한다. 중복 이벤트는 무시하고, 누락 순번을 발견하면 서버 스냅샷·누락 항목을 요청한다. 화면의 임시 합계로 서버 원장을 덮어쓰지 않는다.

결과 확정 전에 승인된 항목을 반영하는 절차는 01을 따른다. 클라이언트가 늦게 보낸 과거 하차 주장이나 임의 과거 점수는 정산 근거가 아니다.

순위와 동점

승자 후보는 서버에서 유효 완료 운송이 있고, 이탈·무효로 참가 자격을 잃지 않은 선수다. 운송을 하지 않은 선수는 총점이 더 높게 보이더라도 승자가 될 수 없다.

참가 자격은 01의 최종 종료 틱 스냅샷을 사용한다. 그 시각에 재접속 유예가 남아 있던 선수의 자격을 정산 중 연결 만료로 뒤집지 않는다.

비교 순서 기준 의도
우선유효 총점 내림차순운임·완료 안전·실제 위반을 함께 비교
동점 후속완료 원약정 기본운임 합계 내림차순환산 내림에서 사라진 운송 성과 차이 반영
다시 동점고유 사건의 총 감점량 오름차순실제 확정된 위반 부담이 적은 선수 우선
모두 동일공동 순위·공동 승자접속 순서·선수 ID·방장 여부로 억지 승자를 만들지 않음

공동 순위 뒤의 순번은 앞선 선수 수를 반영하는 경쟁 순위 방식을 제안한다. 화면 정렬에 안정된 선수 ID를 쓸 수는 있으나 순위·승자 자격에 영향을 주지 않는다.

완료 운송 없는 선수는 결과 하단에 완료 운송 없음, 이탈 선수는 중도 이탈, 무효 경기는 경기 무효로 분리한다. 확정 점수·감점 내역은 숨기지 않는다. 모든 선수에게 완료 운송이 없으면 승자 없음이며, 음수인 유효 완료 선수보다 빈차 정차 선수의 점수가 높아도 이 원칙은 같다.

최종 순위는 01의 Results에서만 확정된다. 그 이전 실시간 목록은 잠정 순위이며, 종료 이후 점수 역산으로 이미 완료한 운송을 다시 평가하지 않는다.

계산 검증 사례

아래는 산술 검증용 가상 설정이다. 운임 환산을 100원당 1점, 안전 완료 보너스율을 10%, 예시 위반을 7점으로 가정한다. 실제 후보값·채택 여부는 09만 소유한다.

입력 사례 계산 기대 결과
기본운임 10,000원, 구간 무위반 완료100 + 10총점 110, 완료 건수 반영
기본운임 10,000원, 탑승 중 예시 위반 후 완료100 + 0 − 7총점 93, 보너스 미지급 사유 표시
기본운임 10,000원, 승차 전 빈차 위반 후 완료100 + 0 − 7총점 93, 승차로 안전 자격 초기화 없음
기본운임 14,000원, 같은 위반 후 완료140 + 0 − 7총점 133, 운임 차이가 승패에 기여하는 사례

첫 사례의 완료 통지를 반복 수신기존 110 유지운임·보너스·완료 건수 모두 중복 없음

별도 자격 검증용 가상 입력: A는 운송 없이 총점 0, B는 유효 완료 가산 5와 누적 감점 12로 총점 −7이다. 두 선수 모두 이탈하지 않았다면 승자 후보는 B뿐이다. 운송을 피해서 감점 없는 0을 지키는 전략으로 승리하지 못한다.

환산 내림은 별도로 경계값을 검증한다. 같은 가상 환산율에서 기본운임 150원인 완료 두 건의 운임 점수 합은 1 + 1이며, 합계 운임 300원을 나중에 환산한 값으로 바꾸지 않는다. 이 예시 역시 실제 운임표가 아니다.

결과 화면·데이터·수용 확인

데이터 항목 제안 결과에 필요한 내용
운송 정산TripId, 원약정, 운임 환산, 안전 구간 ID·시작 이벤트·자격·미지급 사유, 완료 틱
사건 정산IncidentId, 최초 귀속 SafetySegmentId, 분류·판정 근거 참조, 현재 감점량, 반영 차이, 버전
선수 집계총점, 완료 운임 합계, 운임 점수, 완료 보너스 합계, 총 감점, 완료 건수
최종 결과자격 상태·제외 사유, 순위·공동 순위, 원장 순번, 규칙·결과 버전

화면은 총점 옆에 운임·완료 안전·위반의 구성을 보여 주고, 사건별 근거를 열 수 있게 한다. 원약정 예상액과 확정된 점수는 구분하며, 미완료 운임을 이미 얻은 수익처럼 합산하지 않는다. 배치·알림은 UI·피드백이 정의한다.

수용 확인에는 빈차 위반 유지, 사건 상향 차이, 동시 하차의 단일 정산, 음수 순위, 무운송 승자 제외, 공동 승자, 마감 직전 확정 사건을 포함한다. 최종 목록과 측정 방법은 플레이테스트·수용 기준으로 연결한다.

2026-10-29 정산 구현

정수 원장·완료 원자 확정·사건 상향 차액·안전 구간·음수/동점·무운송 제외·최종 자격 동결을 구현하고 모델과 실제 두 Player를 구분해 검사했다. Host 결과는 공개 랭킹 신뢰 근거가 아니다. 수용 범위, 실제 결과를 따른다.
