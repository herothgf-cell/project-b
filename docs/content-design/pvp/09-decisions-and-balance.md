## 상태를 읽는 방법

| 표기 | 의미 | 개발자가 다루는 방법 |
|---|---|---|
| 사용자 확정 | 대화에서 사용자가 명시한 방향 | 구현 계획의 제약으로 유지 |
| 초안 기본안 | 논의를 구체화하기 위해 정한 권고안 | 시험 구현의 출발점이며 사용자 최종 확정으로 표현하지 않음 |

## 시험 설정 후보의 단일 출처

아래 숫자는 제품 기본값이나 구현 완료 값이 아니다. 시행한 조합만 시험 기록에 남기며, 비교 전에는 우열을 단정하지 않는다. 게임이 시작될 때 선택한 설정을 서버가 고정하고 설정 버전을 참가자에게 공유한다.

| 설정 키 | 후보·상태 | 용도 / 확정 조건 |
|---|---|---|
| PlayerCount | 최초 실접속 2인, 확대 후보 4인 | 인원에 따른 승객 공급·만남 빈도·교통 부하를 분리 측정 |
| MatchDurationSeconds | 필수 양수 설정. 비교 후보 240 / 360 / 480초, 제품 기본값 미정 | 완료 운송 수·재경기 의향·초기 위치 영향으로 판단. 후보를 10분 확정으로 읽지 않음 |
| FinishGraceSeconds | 0 / 30초 비교 | 장거리 운송의 마감 불이익과 결과 대기 시간을 함께 비교 |
| FareWonPerPoint | 초기 계산 비교값 100원/점 | 원화 표시와 포인트를 구분. 반올림 규칙은 [05](05-scoring-and-results.md)에만 정의 |
| FareTable | `BaseFare` / `IncludedDistance` / `DistanceStep` / `DistanceStepFare` 모두 미정 | [04](04-passengers-and-fares.md)의 기준 합법 경로로 공급 시 약정. P3 착수 시 시험표를 정하고 P4에서 운송 유형별 수익을 조정 |
| SafeTripBonusRate | 0.05 / 0.10 비교 | 운임 중심 원칙을 유지하면서 동등 운임의 운전 차이를 보상 |
| ViolationPenaltyTable | 사건 종류별 시험표를 별도 설정 데이터로 관리, 아직 수치 미정 | 해당 위반으로 절약한 시간과 추가 운임을 측정한 뒤 배점. 캠페인 감점을 자동 복사하지 않음 |
| WaitingPassengerTarget | 참가자 수 + 1을 초기 공급 후보로 사용 | 장기 무배차와 특정 승객 독점 여부를 보고 조정 |
| PickupStopHoldSeconds | 미정 | 멈춘 상태 확인과 반응성을 함께 측정. 전송 순서만으로 승객을 주지 않음 |
| PickupGeometryToleranceProfile | 위치·방향·정차 속도 허용 오차 미정 | 승차·하차 영역과 차로 방향을 함께 검증. P1에서 기하 후보를 만들고 P3에서 판정 시험 |
| PickupExpirySeconds | 미정 | [04](04-passengers-and-fares.md)의 승객 상태 전이와 함께 비교 |
| ReconnectGraceSeconds | 미정 | 공통 경기 시간을 멈추지 않는 재접속 복구. 양수 유예를 사용할지는 P2에서 결정 |
| SignalCycleProfile | 맵·접근 방향별 시험 설정, 최종 주기 미정 | 신호를 읽고 합법적으로 빠르게 이동할 수 있어야 함 |
| TrafficPopulationProfile | 미정 | 실제 선택을 만드는 교통과 단순 대기 시간을 구분. 기존 캠페인 수량 자동 복사 금지 |
| VehicleHandlingProfile | 가속·조향·회전 안정화·제동·코너 보정별 비교 설정 | 최고속도 하나만으로 합격 판단하지 않음 |
| ControlAssistPolicy | 조작 보조 허용 범위·무입력 감속 설정 미정 | 같은 방의 차량 성능 조건을 통일. P1에서 비교하고 P2에서 입력 유실·재연결 동작 확인 |
| ObservationToleranceProfile | 위반 관측 지속 조건·오차·사건 종료 조건 미정 | [02](02-driving-and-traffic.md)의 사건 근거를 P3 전에 설정. 순간 튐과 독립된 실제 위반을 구분 |
| RecoveryPolicy | 복구 요청 제한·안전 지점 재확인·점유 대기 한도 미정 | P1에서 경계·후방 복구 시험 설정을 정하고 P2에서 네트워크 복원 확인. 복구 실패의 경기 처리는 [01](01-match-flow-and-rules.md#지도-오류와-복구-불가) |
| ArenaScaleProfile | 이동 시간과 경로 분기 수로 먼저 비교, 면적 미정 | 법규 준수 운송 반복이 성립한 뒤 미터 단위 크기 고정 |
| NetworkSimulationRate | 네트워크 후보별 호환 주기 검증 후 결정 | 서버 부하·조작 반응·위치 보정량을 같이 확인 |
| ClaimLagCompensationPolicy | 초기안은 서버 처리 틱 기준, 과거 승차·하차 소급 승인 없음 | P2~P3에서 Host/원격 참가자의 지연 편향 측정. 보상 도입 여부·허용 범위는 미정이며 채택 시 01·04·07 함께 변경 |
| NetworkTestProfile | 로컬 기준, 왕복 지연 50 / 100 / 150ms, 패킷 손실 0 / 1 / 3%를 단계별 비교 | 시험 환경 입력이며 허용 품질 보장 수치가 아님. 모든 조합 전수검사가 필수라는 뜻도 아님 |

실행 테스트의 짧은 타이머·가상 운임·가상 사건 배점은 제품 밸런스와 구분해 테스트 픽스처에 둔다. 자동검사에서 쓰는 시간이 경기 시간 결정으로 승격되지 않도록 한다.

## 변경 절차

1. 사용자 결정 또는 시험 근거를 이 문서에 날짜·근거와 함께 기록한다.
2. 규칙 소유 문서와 설정 버전을 갱신한다. 같은 수치를 여러 본문에 복사하지 않는다.
3. 해당 [QA 항목](10-playtest-and-acceptance.md)과 [개발 단계](08-development-roadmap.md)의 영향을 기록한다.
4. 진행 중인 경기는 시작 시 고정된 설정을 유지하고, 변경은 다음 경기부터 적용한다.
5. 문서 초안, 자동검사 통과, 실제 온라인 플레이 완료를 서로 다른 상태로 기록한다.

## 2026-10-29 시험 구현 후보 기록

VehicleHandlingProfile A/B와 ArenaScaleProfile은 [Task 2 이력](../../work-history/2026-10-29-pvp-arena-integration.md)의 실제 자동 측정값을 가진 시험 후보다. `Content/Maps/PvpArena01.asset`은 외곽 좌표 ±60m와 정차점 ±72m의 회색 상자 맵이며 최종 규모가 아니다. 경로 추정 속도는 외곽18m/s·내부7m/s 비교 입력이다. NPC/신호가 없으며 실제 속도 보장이나 최종 제한속도 규칙이 아니다. 차량 A/B 중 최종 채택은 사람 조작감과 P2 검증 이후 결정한다. 경기 시간·인원·배점·충돌·SDK 상태는 유지한다.


## 직접 IP 후보 추가 (2026-10-29)

사용자가 Fusion SDK/App ID 미준비와 대안 확인을 답했다. 따라서 NGO1.12.0 + Transport1.5.0을 현재 Unity2022.3.62f2에 설치하고 직접 IP 2인 주행을 시험한다. 이는 기존 대안의 검증 착수이며 Fusion 기술 실패나 NGO 최종 채택 결정이 아니다. Relay/계정/인터넷 초대방은 추가하지 않는다. NGO의 기본 보간을 완전한 예측이라고 부르지 않고, 별도 입력 이력·권한 ACK·재계산을 구현했다. 입력은 서버 tick당 한 번만 적용하며 한꺼번에 도착한 조작 상태는 최신 것으로 합친다.

실제 빌드 GUID·맵 hash·프로토콜·주행 규칙이 같아야 입장 가능하다. 테스트용 고정50Hz/차량A/2인/무접촉이며 경기 시간은 정하지 않는다. [측정 결과·남은 항목](../../work-history/2026-10-29-pvp-direct-ip-network.md).

직접 IP 후보는 패킷 사이 입력을 최대10서버tick(200ms) 유지하고 이후 입력 유실 감속한다. 시험값이며 실제 연결 종료·재접속 정책을 대신하지 않는다. buildGUID가 달라 Editor와 Player 또는 별도 재빌드 간 접속은 거절될 수 있다.
