# 택시 PVP 기획·개발 계획

상태: 기획 초안 / PVP 미구현  
작성일: 2026-10-27  
작업 브랜치: feature/pvp-prototype  
참고 기준: main 60b15edd6094d9a6383de4d0c75c4a40d49eda40

자체 제작 맵에서 실제 플레이어들이 승객 운송으로 경쟁하는 별도 PVP 모드의 기획이다. 운임이 승패에 충분한 영향을 주며, 민첩한 조작과 운전의 정확성도 성적을 만든다. 기존 은계 시뮬레이션의 규칙과 현재 구현 상태는 [상위 기획](../README.md)을 따른다.

이번 작업은 새 브랜치의 문서 작성이다. PVP 실행파일·전용 맵·네트워크·경기 기능은 아직 구현하지 않았다. 경기 시간, 최종 인원, 배점, 충돌 정책, 네트워크 SDK 채택은 아래에서 확정과 제안을 구분한다.

## 현재의 핵심 구분

| 구분 | 내용 |
|---|---|
| 사용자 확정 | 실제 사용자 PVP, 제한된 공간, 자체 제작 맵, 충분한 운임 영향과 운전 점수, 빠르고 민첩한 경기 |
| 확정하지 않은 것 | 경기 시간. 이전 대화의 10분 제안은 제품 규칙이 아님 |
| 초기 권고안 | 공유 승객 선점, 실제 2인 검증 후 규모 확대, 별도 실행파일, 초기 택시 간 충돌 OFF |
| 기술 권고안 | Photon Fusion 2 Host 및 초대방부터 검증, 전용 서버·공개 경쟁은 후속 |
| 세부 상태의 기준 | [09 결정 대장](09-decisions-and-balance.md). 이 표를 새 결정의 독립 근거로 쓰지 않음 |

## 문서 작성 원칙

- 규칙은 담당 문서 한 곳에 정의하고 상대 링크로 연결한다.
- 플레이 규칙, 개발 순서, 기술 구조, 검증 기록을 구분한다.
- 제품 설정 후보는 09에만 모은다. 계산 예시나 자동검사 픽스처는 확정 배점이 아니다.
- 현재 캠페인 기능을 PVP 구현 완료로 표시하지 않는다.
- 원격에서 확정되지 않은 차량 상태·승객 소유권·운임을 최종 결과로 다루지 않는다.
- 문서 수정은 PVP 소스·지도·빌드 변경과 구분해서 작업 이력에 남긴다.
- 상위 캠페인 본문과 사용자 마인드맵의 규칙을 PVP 초안으로 덮어쓰지 않는다.

## 개발을 이어갈 때

1. 저장소 AGENTS.md와 [최신 인계](../../work-history/LATEST.md)를 읽고 작업 브랜치를 확인한다.
2. [09](09-decisions-and-balance.md)의 미정 사항과 해당 단계의 의존성을 확인한다.
3. [08](08-development-roadmap.md)의 한 단계/작업 단위로 구현하고 [10](10-playtest-and-acceptance.md)의 증거를 남긴다.
4. 완료 체크는 실제 결과를 확인한 범위에만 한다. 이번 기획 작성으로 제품 작업을 완료 처리하지 않는다.
