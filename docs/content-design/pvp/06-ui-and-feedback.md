# PVP 화면·입력·피드백

상태: 기획 초안 / PVP 미구현  
작성일: 2026-10-27  
담당: 플레이어가 보는 정보와 선택, 결과 설명. 배점과 서버 상태 전이는 담당 문서를 참조한다.

## 정보 우선순위

운전 중에는 진행 방향과 다음 행동이 먼저 읽혀야 한다. 운임·순위는 짧게 확인할 수 있게 하고, 세부 기록은 안전하게 확인할 때 펼친다. 화면을 열어도 공통 경기 시간은 계속 흐른다.

| 우선순위 | 필요한 정보 | 표현 원칙 |
|---|---|---|
| 즉시 행동 | 다음 회전, 승하차 목표, 신호, 마감 상태 | 차로·목표와 연결된 짧은 표시. 팝업으로 조작을 막지 않음 |
| 운송 판단 | 약정 운임, 목적지, 예상 소요, 상대 확보 여부 | 예상과 확정 상태를 구분 |
| 경쟁 상황 | 현재 순위, 누적 운임 점수, 운전 가감점, 상대 위치 | 읽을 수 있는 작은 요약으로 유지 |
| 회고 | 사건별 감점 근거, 운송별 정산, 최종 순위 | 결과 또는 펼친 기록에서 확인 |

## 대기방에서 확인하는 조건

- 참가 인원, 같은 차량 성능·주행 보조 조건, 맵 이름.
- 이번 경기의 시간·마감 정책·충돌 정책·점수 규칙 요약.
- 준비 여부와 시작 가능 여부.
- 설정이 바뀌면 이전 준비 상태를 해제하고 다시 확인하게 한다.
- 참가자가 서로 다른 맵/규칙 버전을 사용하면 시작을 막고 업데이트 안내를 한다.

“이번 방은 시험 설정”과 “정식 랭킹 경기”는 실제 운영 기능에 맞게 표시한다. 초기 초대방을 정식 랭킹 경기로 표시하지 않는다. 설정값의 근거는 [09](09-decisions-and-balance.md)에서 관리한다.

## 운전 중 HUD

| 영역 | 표시할 내용 | 표시하지 않거나 따로 보는 내용 |
|---|---|---|
| 길안내 | 현재 목표와 다음 회전, 접근 차로, 재탐색 상태 | 매 프레임 바뀌는 내부 경로 계산 정보 |
| 승객 카드 | 대기/승차 확인 중/탑승/종료 상태, 약정 운임, 목적지, 예상 소요 | 아직 받지 않은 운임을 누적 성적에 더한 값 |
| 경기 정보 | 남은 공통 시간, 본 경기/마감 유예 구분, 순위 | 개인 PC의 시계로 계산한 다른 종료 시각 |
| 성적 요약 | 완료 운임 점수, 운전 가감점, 합계 | 캠페인 운전점수·M/S/R를 혼합한 지표 |
| 차량 | 속도, 필요한 방향 표시, 복구 가능 여부 | PVP에서 사용하지 않는 식사·피로·청결 게이지 |
| 경쟁 지도 | 공용 승객, 상대 택시 위치와 빈차/탑승 중 상태 | 상대의 선택 목표·목적지 공개는 별도 확정 전 기본 노출하지 않음 |

초기 HUD의 차량 속도 단위와 운임 원화 표시는 일관되게 유지한다. 운임 금액과 경기 포인트는 다른 단위라는 것을 라벨로 구분한다.

## 승객 선택과 선점 피드백

| 조건·행동 | 즉시 보여주는 것 | 서버 확정 후 보여주는 것 |
|---|---|---|
| 지도에서 손님 선택 | 내비 목표와 예상 경로 | 승객 소유권은 바뀌지 않음 |
| 정차 조건 미달 | 방향/위치/정차 상태 중 부족한 조건 | 유효 승차 없음 |
| 승차 요청 | 확인 중 표시, 반복 입력으로 요청 누적하지 않음 | 내 승객으로 확정 또는 확보 실패 |
| 상대가 먼저 확보 | 대상 상태 갱신, 다른 후보 접근 가능 | 해당 승객을 내 운송으로 표시하지 않음 |
| 하차 요청 | 도착 확인 중 표시 | 확정 운임·보너스·완료 상태 |

네트워크 예측으로 차를 움직이는 것과 승차/운임을 확정하는 것은 구분한다. 확정되지 않은 승객이나 금액을 최종 결과처럼 보여주지 않는다.

“확보”는 현장에서 서버가 탑승을 승인한 결과를 가리키며 별도 예약 상태가 아니다. “승차 확인 중”은 로컬 요청 표시이고, 상대가 먼저 탑승하면 승인되지 않은 표시를 철회한다.

## 짧은 사건 알림

| 사건 | 필요한 설명 | 피해야 할 표현 |
|---|---|---|
| 운임 정산 | 완료 운임, 이번 안전 보너스, 누적 성적 | 클릭할 때까지 멈추는 모달 결과창 |
| 위반 확정 | 사건 이름, 감점, 판단한 상황의 짧은 근거 | 정상 제동을 단순히 “난폭 운전”으로 단정 |
| 더 큰 위반으로 사건 갱신 | 같은 사건의 추가 차액과 최종 감점 | 이전 감점과 새 감점을 모두 더해 표시 |
| 판정 보류 | 필요할 때만 불확실 상태를 설명 | 확인되지 않은 위반에 확정 감점 표시 |
| 마감 진입 | 신규 승차 종료와 현재 운송의 최종 마감 | 사람마다 다른 유예 시간처럼 보이는 안내 |
| 연결 끊김 | 진행 중인 공통 경기와 복구 가능 여부 | 로컬 일시정지가 전체 경기를 멈춘다는 인상 |

운송 영수증에 이미 반영된 주행 감점을 요약할 때는 “운행 중 반영된 감점”으로 표시하고 다시 차감하지 않는다.

결과 확정 뒤 방장이 종료해도 이미 받은 결과를 경기 무효로 바꾸지 않는다. 확정 결과를 받지 못한 화면에는 결과 미수신·확인 불가를 표시하고 로컬 합계로 승자를 추정하지 않는다.

## 지도와 입력

지도는 현재 차량·승객·목표·진입 방향이 읽히도록 한다. 짧은 경로와 빠른 경로의 선택은 실제 길안내 결과와 연결되어야 하며, 선택만으로 승객이 예약되지는 않는다.

개인 메뉴와 지도는 네트워크 경기 시간을 멈추지 않는다. 주행 입력의 활성 여부와 UI 입력 초점을 명시적으로 관리해 메뉴 키가 가속·승차로 중복 처리되지 않게 한다. 메뉴를 열기 위한 안전 정차는 가능하지만 정차 자체에 경기 점수를 주지 않는다.

카메라는 자기 차량만 따라간다. 다른 참가자의 접속·퇴장이 내 카메라 대상을 바꾸면 안 된다. 키보드·패드의 가속/제동/조향/승하차/지도/기록/복구 기능을 같은 의미로 제공한다. 세부 키 배치는 조작 시험에서 확인한다.

## 최종 결과

| 항목 | 플레이어가 알 수 있어야 하는 내용 |
|---|---|
| 순위 | 서버가 확정한 결과와 동점 여부 |
| 운송 실적 | 완료 횟수, 기본 운임 합계, 운임 환산점수 |
| 운전 기여 | 완료 운송 안전 보너스와 위반 감점 각각 |
| 최종 점수 | 구성 요소를 더하면 같은 값이 되는 성적 |
| 예외 | 미완료 운송, 기권/실격/경기 무효 등 실제 적용 사유 |
| 상세 | 운송과 사건별 한 번씩 반영된 정산 내역 |
| 다음 행동 | 같은 방 재경기 또는 나가기 |

운임이 앞섰는데 패배했다면 어느 감점이 차이를 만들었는지, 운임 차이로 이겼다면 운송 실적이 어떻게 기여했는지 설명할 수 있어야 한다. 단위나 순위 계산법을 추측하게 만들지 않는다.
