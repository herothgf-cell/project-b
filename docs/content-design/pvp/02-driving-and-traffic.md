# PVP 주행·교통·법규 판정

상태: 기획 초안 / Task 2 오프라인 후보 구현·자동 검사, 사람 수용 검증 전
작성일: 2026-10-27

## 목적과 문서 경계

가속·회전·경로 선택을 자주 판단하는 빠른 운송 경쟁을 만든다. 최고속도만 높이지 않고 출발 응답, 저속 회전, 감속 후 재가속을 함께 조정한다.
이 문서는 조작, 교통 상태, 관측할 위반 사건을 소유한다. 감점·안전 보너스·승패 계산은 [05 점수·결과](05-scoring-and-results.md), 입력 표시·카메라 조작 안내는 [06 UI](06-ui-and-feedback.md)가 소유한다.
사용자가 확정한 방향과 제안의 상태, 모든 조작·판정 임계값 후보는 [09 결정·밸런스](09-decisions-and-balance.md)를 따른다. 아래 동작은 구현할 규칙 초안이며 현재 성능의 측정 결과가 아니다.

## 기존 내용에서 가져올 원칙

| 확인한 근거 | 가져올 원칙 | PVP에서 새로 설계할 부분 |
|---|---|---|
| [기존 주행·교통 기획](../01-driving-and-traffic.md) | 진행 방향별 신호, 필요한 제동의 보호, 같은 사건 중복 차감 방지 | 캠페인 운전 점수·만족도·회복 수치를 이식하지 않음 |
| [기존 화면·길안내 기획](../05-interface-and-navigation.md) | 연결된 합법 경로, 정차 방향, 수동 가감속 | 경쟁 중 메뉴로 경기나 다른 차량이 멈추지 않는 입력 처리 |
| [DriveSession.cs](../../../unity/EungyeTaxi/Assets/Scripts/DriveSession.cs) | 현재 택시·카메라·교통·캠페인이 한 세션에서 연결됨 | PVP 세션과 입력 권한 분리는 [07 네트워크·빌드](07-network-and-build.md)에서 설계 |

기존 기획에 기재된 성능·교통 수량·배점은 PVP 기본값이 아니다. 조작 비교는 같은 차량·노면·경로 조건에서 기존 실행과 PVP 후보를 각각 측정한다.

## 입력 계약

| 입력·상황 | 차량 동작 초안 | 예외·보호 |
|---|---|---|
| 가속 | 입력 크기에 따라 구동력을 요청하며 출발 지연을 줄임 | 최고속도 도달을 순간 이동처럼 처리하지 않음 |
| 좌우 조향 | 차량 진행축 기준으로 조향하고 입력 해제 시 안정적으로 복귀 | 카메라 방향·뒤보기·화면 회전에 따라 조향축이 뒤집히지 않음 |
| 제동 | 주행 방향의 속도를 줄이고 정차를 유지 | 위험 회피, 코너 진입, 승하차 접근의 강한 제동 자체는 위반이 아님 |
| 후진 전환 | 충분히 감속한 정차 상태에서 명시적 후진 의도를 확인 | 제동 버튼을 길게 눌렀다는 이유만으로 고속 주행에서 후진으로 전환하지 않음 |
| 가속·제동 동시 입력 | 제동 우선으로 처리 | 조합 입력으로 가속·제동 한계를 우회하지 못함 |
| 키보드·연속 입력 장치 | 동일한 차량 성능 한계와 서버 입력 계약 적용 | 키보드는 조향 변화율을 보정하되 더 큰 회전 성능을 제공하지 않음 |
| 입력 해제·장치 연결 끊김 | 구동 요청을 해제하고 서버가 정한 안전 감속 상태로 전환 | 멈춘 클라이언트의 마지막 가속 입력을 무기한 유지하지 않음 |
| 메뉴·지도·결과 상세 열기 | 차량과 경기 시계는 계속 진행 | 메뉴 입력과 주행 입력의 충돌 처리·고지는 06에서 정의 |
| 위치 복구 요청 | 서버에 복구 가능 여부를 요청 | 클라이언트가 위치·속도·운송 단계를 직접 확정하지 않음 |

키 배치·재설정 화면은 06, 입력 누락 처리와 예측·보정은 07의 책임이다. 조작 보조의 허용 범위는 09에서 결정하며 자동 승객 접근·자동 제동을 기본 동작으로 간주하지 않는다.

## 조작감의 목표와 비교 방법

| 항목 | 구현 방향 초안 | 같은 조건에서 비교할 관측값 |
|---|---|---|
| 출발·재가속 | 신호 출발과 코너 탈출에서 입력을 빨리 체감 | 입력 시작부터 구동 반응까지의 지연, 기준 구간 통과 시간 |
| 저속 조향 | 정차점 진입과 좁은 연결로에서 과도한 전후진 없이 회전 | 같은 코너의 최소 통과 공간, 수정 조향·후진 횟수 |
| 고속 조향 | 급격한 좌우 입력에도 진행 방향을 읽을 수 있게 제한 | 차선 변경 후 흔들림, 의도한 경로 복귀까지의 시간 |
| 방향 전환 | 감속·회전·재가속이 끊기지 않고 이어짐 | 같은 연결로 진입부터 탈출까지의 시간과 경계 침범 |
| 접지·횡미끄럼 | 기본 회전은 접지로 해결하고 과한 횡미끄럼은 회복 가능하게 함 | 같은 코너의 횡이탈 거리, 조향 해제 후 자세 안정 시간 |
| 제동 | 정차점·신호선 앞에서 감속 결과를 예측할 수 있음 | 같은 진입 속도에서의 정지 거리와 정차 오차 |
| 후진·재출발 | 잘못 든 입구에서 제한된 공간으로 빠져나올 수 있음 | 합법 복구에 필요한 조작 횟수와 정체 시간 |
| 시점 독립성 | 선택한 시점과 상관없이 같은 입력은 같은 차량 상태를 만듦 | 동일 입력 재생의 위치·속도·조향 결과 차이 |

차량 중심의 제자리 회전, 벽에 붙여 가속하는 주행, 필수 드리프트는 기본 운송 기술로 요구하지 않는다. 손쉬운 회전과 고속 안정성의 균형을 먼저 비교한다.
카메라 흔들림·시야각으로 빠른 느낌을 보완할 수 있지만 물리 성능의 대체 근거로 삼지 않는다. 카메라를 바꿨을 때 충돌 판정·제동 거리·시야 밖 신호 규칙이 달라져서는 안 된다.
검증 방법과 합격 판단의 소유 문서는 [10 플레이테스트·인수](10-playtest-and-acceptance.md)이며, 이 문서에는 측정값이나 통과 결과를 선기입하지 않는다.

## 주행 상태와 복구

| 상태·조건 | 행동·결과 | 유지해야 할 정보 |
|---|---|---|
| 정상 도로 주행 | 차량 입력을 적용하고 합법 도로 연결을 추적 | 현재 차로·방향·접근 중인 교차로 |
| 미끄러짐·시설 접촉 | 입력을 유지하며 조향·제동으로 회복 가능 | 접촉 사건과 운송 상태, 이미 발생한 위반 |
| 뒤집힘·지형 끼임 | 서버가 움직임·노면 상태를 확인한 뒤 복구 허용 | 복구 사유와 마지막 유효 도로 위치 |
| 경계 밖·불법 지름길 진입 | 지도 경계 규칙에 따라 주행을 차단하거나 복구 | 경계 사건, 기존 위반, 운송 소유권 |
| 복구 확정 | 검증된 복구 지점으로 이동하고 잔여 속도 제거 | 운임 약정·위반 원장·경기 시계는 초기화하지 않음 |
| 복구 직후 | 정상 도로 진입을 확인한 뒤 승하차 판정 재개 | 이동 자체를 승차·하차·정상 구간 통과로 인정하지 않음 |
| 복구 지점 사용 불가 | 다른 검증된 후방 지점을 찾거나 안전 정차 상태 유지 | 목적지·승객 가까이 임의 이동하지 않음 |

복구 지점의 배치와 경로 이득 방지는 [03 지도·콘텐츠](03-map-and-content.md)가 정의한다. 복구 요청 제한·무입력 감속·회복 판정의 수치 후보는 09에 둔다.
복구는 교통 위반을 지우거나 새 승객을 선점하는 수단이 아니다. 반복 요청으로 충돌·경계 사건을 쪼개거나 종료 시각을 늦출 수 없다.

## 교통 상태와 판정 근거

신호·NPC·진입 판정의 기준은 서버가 확정한 경기 시계와 지도 버전이다. 클라이언트는 표시와 예측을 하며 자기 화면의 신호색만으로 위반·면책을 확정하지 않는다.

| 근거 | 서버가 관측할 내용 | 판정에서 제외할 근거 |
|---|---|---|
| 신호 접근 | 접근 차로·진행 동작·정지선 통과 시각·해당 신호 단계 | 옆 차로 신호, 클라이언트 단독 타이머 |
| 도로 이동 | 이전·현재 위치 사이의 이동과 실제 차로·연결로 | 한 프레임의 점 위치만으로 빠른 통과를 누락하는 판정 |
| 보행·양보 | 보호 구역과 실제 교차 중인 이동, 회피 가능성 | 보행 신호색만으로 모든 차량을 일괄 가해 처리 |
| 진로 변경 | 변경 전후 차로·안전 공간·상대의 실제 진행 | 상대 차량이 급제동했다는 단일 사실 |
| 속도·방향 | 지도에 지정된 제한과 일정 구간의 실제 이동 | 순간 보정 위치, 교차로 회전 중 임시 방향 |
| 충돌 | 접촉 상대·접촉 시작/종료·진입 경로·상대 움직임 | 접촉했다는 이유만으로 법규 위반 책임 확정 |

증거가 충돌하거나 서버 상태가 부족한 사건은 확정 감점으로 보내지 않고 판정 보류 사유를 남긴다. 지연 보정의 시간 범위와 로그 형식은 07이 소유한다.

## 관측할 위반 유형

| 사건 유형 | 성립에 필요한 관측 | 제외·같은 사건 처리 |
|---|---|---|
| 적색 정지선 침범 | 자기 접근의 적색에 정지선을 넘고 교차로 진입 전 정차 | 이후 같은 접근에서 적색 진입이 생기면 별개 사건을 추가하지 않음 |
| 적색 교차로 진입 | 해당 진행 동작의 금지 단계에 교차로 경계를 통과 | 정상 진입 뒤 신호가 바뀐 차량의 교차로 이탈은 제외 |
| 우회전 정지 누락 | 지도에 지정된 정지 의무와 실제 정지 기록의 불일치 | 전용 신호 위반·보행 보호 위반과 같은 접근 사건으로 연결 |
| 우회전 전용 신호 위반 | 우회전 전용 금지 단계에서 해당 연결로 진입 | 잠깐 정차했다는 사실만으로 허용하지 않음 |
| 보호 대상 통행 방해 | 보호 대상의 실제 진행과 차량 이동이 충돌 구역에서 충돌·회피를 유발 | 필요한 제동, 안전하게 양보한 진행은 제외 |
| 금지 회전·금지 연결 | 실제 이동이 지도에서 금지한 차로 연결을 통과 | 길안내 선을 벗어났다는 이유만으로 위반을 만들지 않음 |
| 역주행 | 방향이 정해진 도로에서 반대 진행이 지속 | 허용 정차점의 후진, 정상 회전, 서버 위치 보정 제외 |
| 제한속도 위반 | 제한이 표시된 구간에서 허용 오차·관찰 조건을 넘김 | 제한 전환의 짧은 오차를 프레임마다 별도 사건으로 만들지 않음 |
| 금지 끼어들기·진로 방해 | 지정 금지 구역 침범 또는 서버가 확인한 위험한 경로 충돌 | 일반적인 합법 차로 변경, 충돌 OFF의 단순 겹침 제외 |
| 인도·도로 경계 침범 | 주행 금지 영역에 실제 진입하거나 불법 연결로 사용 | 정상 승하차 진입 영역·복구 이동과 구별 |

급가속·급제동·큰 조향 입력은 독립적인 법규 위반 유형으로 만들지 않는다. 필요한 회피 제동과 민첩한 주행을 보호하고, 위험한 결과가 있으면 그 결과의 사건 증거로 판단한다.
충돌·차량 흔들림이 안전 보너스에 미칠 영향과 같은 사건 내 최종 감점 선택은 05에서 정의한다. 캠페인 만족도 감소를 PVP에 추가로 합산하지 않는다.

## 반복 사건과 점수 전달

| 단계 | 사건 처리 | 중복 방지 원칙 |
|---|---|---|
| 사건 시작 | 경기·차량·대상 구역·연속 행동을 식별하는 서버 사건 ID 부여 | 승객 탑승 여부가 바뀌어도 진행 중 사건 ID는 유지 |
| 사건 진행 | 같은 접근·접촉·침범의 증거를 기존 사건에 추가 | 프레임·네트워크 재전송·클라이언트 재접속으로 새 사건 생성 금지 |
| 위반 확대 | 정지선 침범 뒤 적색 진입 등 더 강한 사실로 갱신 | 최초 사건과 별도 감점 요청을 보내지 않고 기존 사건 갱신 |
| 사건 종료 | 유효 구역을 벗어나고 정상 상태 복귀가 확인되면 종료 | 경계에서 짧게 흔들린 것을 새 접근으로 취급하지 않음 |
| 새로운 행동 | 종료 후 새로운 접근·접촉이 확인되면 새 사건 생성 | 같은 길을 다시 운전했다는 이유로 모든 이후 위반을 면책하지 않음 |
| 점수 전달 | 확정 사건 ID·유형·시각·근거를 점수 원장에 전달 | 지급·차감·수정의 멱등성은 05, 전송 보장은 07에서 정의 |

위반 사건은 빈차·승객 접근·운송 중 모두 관측한다. 신호 대기, 같은 구간 왕복, 조작 보조 사용, 복구 완료는 보너스 획득 사건이 아니다.

## NPC 교통과 플레이어 충돌

| 상황 | 초안 정책 | 경쟁을 해치는 경우의 처리 |
|---|---|---|
| 플레이어끼리 접촉 | 초기 검증은 충돌 OFF를 후보로 비교 | 정식 정책은 미정이며 단순 겹침으로 상대를 가해 판정하지 않음 |
| NPC 없는 조작 시험 | 도로·신호·차량 비교를 먼저 수행 | NPC가 없다는 결과를 교통 포함 합격으로 확대하지 않음 |
| NPC 포함 경기 | 서버가 스폰·경로·신호 반응을 확정 | 클라이언트마다 다른 장애물을 독립 생성하지 않음 |
| NPC를 이용한 간접 방해 | 택시–NPC 접촉·밀기 정책을 택시 간 충돌과 별도로 비교 | NPC 장벽으로 장기 봉쇄가 되면 접촉 정책·우회 공간·정체 복구를 조정하고 피해자를 일괄 감점하지 않음 |
| 정차점·합류부 | 승하차 진입과 출구를 계속 막는 생성 금지 | 장기 막힘은 콘텐츠 결함으로 기록하고 공급·경로와 함께 조정 |
| 정상 신호 대기 | 짧고 예상 가능한 대기와 합법 우회 선택 제공 | 빨리 달리려면 항상 위반해야 하는 신호 주기를 허용하지 않음 |
| NPC 정체·오류 복구 | 서버가 공통으로 복구하며 안전한 이동 공간 확보 | 바로 앞 장애물을 갑자기 삭제해 특정 차량만 이득을 보게 하지 않음 |
| 보행자 장면 | 합법 경로·시야·양보 공간이 있는 장면부터 추가 | 드문 무단횡단이나 돌발 방해를 초기 필수 콘텐츠로 두지 않음 |

NPC 규모·충돌 실험 순서·참가 규모의 결정 상태는 09, 콘텐츠 프리셋은 03이 관리한다. 동일 조건의 비교·지연 상황·반복 사건 시험은 10에서 연결한다.

## 구현으로 넘길 항목

차량 상태와 서버 판정기를 먼저 분리하고 카메라·화면 연출은 해당 상태를 읽도록 한다. 신규 코드·에셋 경로는 [08 개발 로드맵](08-development-roadmap.md)의 **신규 제안, 아직 없음** 목록을 기준으로 정한다.
다음 단계에서는 조작 후보 간 측정, 합법 경로의 경쟁력, 사건 ID의 지속 범위를 함께 확인한다. 이 문서의 작성은 차량·교통·네트워크 구현 또는 검증 완료를 뜻하지 않는다.
