# 공용 승객과 고정 기본운임

상태: 기획 초안 / 초기 시작 기반 구현, 본문 경기 기능은 미구현
작성일: 2026-10-27

## 문서의 책임과 결정 상태

이 문서는 승객 공급·현장 승차·운송 소유권·고정 기본운임을 정의한다. 경기 종료와 이탈은 [경기 흐름](01-match-flow-and-rules.md), 운임의 점수 환산·완료 보너스는 [점수](05-scoring-and-results.md)가 소유한다.

| 구분 | 내용 |
|---|---|
| 사용자 확정 | 같은 한정 공간에서 승객 운송을 경쟁하며, 운임이 승패에 충분히 기여해야 한다. |
| 본 문서 제안 | 공유 승객을 실제 현장에서 먼저 유효하게 승차한 선수가 운송한다. |
| 본 문서 제안 | 합법 경로로 산정한 기본운임을 공급 시 고정하고 실제 우회 거리로 늘리지 않는다. |
| 미정 | 공급량·재공급 조건·대기 만료 시간·거리별 운임표·첫 공급 보호의 최종 강도. |

모든 설정 후보와 승인 상태는 [결정·밸런스](09-decisions-and-balance.md)에서 관리한다. 기존 [캠페인 승객·운임](../02-passengers-and-fares.md)의 현장 승하차 의미는 참고하되, 만족도·운전 점수에 따른 실수령 보정을 이 문서에 가져오지 않는다.

## 탐색과 소유권을 구분하는 흐름

| 단계 | 플레이어 행동 | 서버 처리·결과 | 예외 |
|---|---|---|---|
| 탐색 | 공유 목록·대기자·기본운임 확인 | 같은 공급 정보와 상태 버전 전달 | 보이지 않는 미공개 승객을 클라이언트가 생성하지 않음 |
| 내비 선택 | 승객 핀·목록 항목 선택 | 접근 경로만 안내 | 예약·선점·소유권·픽업 기한이 생기지 않음 |
| 현장 승차 요청 | 빈차로 유효 승차 구역에 정차 후 상호작용 | 위치·방향·속도·승객 상태·경기 상태 검증 | 입력 전송·버튼 강조만으로 탑승 확정 아님 |
| 승차 확정 | 서버 승인 수신 | 승객 소유자와 `TripId`를 원자적으로 확정 | 경쟁 요청 중 승인된 운송만 존재 |
| 운송 | 고정 목적지로 이동 | 소유자·약정·주행 사건 유지 | 경로 재탐색으로 약정 변경 없음 |
| 하차 요청 | 지정 목적지 방향으로 정차 후 상호작용 | 유효 도착과 운송 종료를 검증 | 반대편 차로·구역 밖·마감 뒤 하차 불가 |
| 완료 | 승인 결과 확인 | 완료 상태와 정산 요청을 한 번 생성 | 중복 요청은 같은 결과 재전달 |

초기안은 한 선수가 동시에 한 승객만 운송한다. 예약 큐·승객 교환·목적지 변경·경유·캠페인 요청/취객/청결 경제는 초기 검증 범위에서 제외하는 제안이다.

## 승객의 서버 상태

아래 상태와 필드는 신규 계약 제안이며 현재 구현된 타입이 아니다. `승차 요청 중`은 클라이언트의 대기 표시로만 사용한다.

| 상태 | 의미 | 허용 전환과 소유자 |
|---|---|---|
| `PendingSupply` | 공급 후보를 만들고 지도·경로·운임 유효성을 검증 중 | 서버가 유효 후보만 `Waiting`으로 공개 |
| `Waiting` | 모든 선수에게 공개된 현장 대기 승객 | 서버 중재 성공 시 `Onboard`; 기한·마감 시 `Expired`; 콘텐츠 오류 시 `Cancelled` |
| `Onboard` | 단일 소유자·단일 `TripId`가 확정된 운송 | 유효 하차 시 `Completed`; 최종 마감 시 `Expired`; 이탈·시스템 취소 시 `Cancelled` |
| `Completed` | 유효 하차와 정산 자격이 확정됨 | 종결 상태, 동일 운송을 다시 열지 않음 |
| `Expired` | 대기 만료 또는 공통 최종 마감에 미완료 | 종결 상태, 만료 사유와 시각 보존 |
| `Cancelled` | 서버가 이탈·콘텐츠 오류 등으로 중단 | 종결 상태, 취소 사유와 기존 원장 보존 |

`Waiting → Onboard`에서 소유권 획득과 탑승을 하나의 확정으로 처리한다. 멀리서 선점한 뒤 도착하는 별도 예약 상태는 초기안에 없다. 종료한 승객을 재공급하려면 기존 객체를 되살리지 않고 새 `PassengerId`를 발급한다.

## 현장 판정과 단일 승차 중재

| 검증 항목 | 서버가 확인할 사실 | 거절 시 안내 |
|---|---|---|
| 대상 | 요청의 경기·승객·상태 버전이 유효하며 `Waiting`임 | 이미 탑승·만료·다른 경기의 승객 |
| 선수 | 유효 참가자, 연결되어 조작 가능, 현재 빈차 | 운송 중·재접속 대기·이탈 상태 |
| 지도 유효성 | 같은 틱의 경계 판정이 끝났고 복구·격리 중이 아니며 유효 주행 영역에서 접근함 | 경계 밖 이동·복구 위치로 승하차할 수 없음 |
| 위치 | 차량의 지정 기준점이 해당 연석의 승차 영역 안에 있음 | 지정 정차 구역으로 접근 |
| 방향 | 해당 접근 차로와 지정 정차 방향을 만족 | 반대편 차로에서 태울 수 없음 |
| 정차 | 실제 서버 속도와 정차 유지 조건을 만족 | 속도를 낮추고 정차 유지 |
| 시각 | 대기 만료 전이며 신규 승차가 허용된 경기 틱임 | 기한 만료·마감으로 신규 승차 종료 |

판정 거리·방향 허용 오차·정차 속도·유지 시간은 [09](09-decisions-and-balance.md)의 설정 후보다. 단순 직선거리만으로 차로·중앙분리대·연석을 건너뛴 승차를 허용하지 않는다. 하차도 목적지에 지정한 별도의 방향·구역으로 같은 원칙을 적용한다.

지도 밖·비주행 영역을 통과해 얻은 접근 이득은 [03의 복구 규칙](03-map-and-content.md#지도-경계와-위치-복구의-악용-방지)에 따라 먼저 해소한다. 정상 도로 위 신호·회전 위반은 별도 주행 감점으로 처리하며 그 사실만으로 유효 완료 운송의 기본운임을 취소하지 않는다.

- 서버는 같은 처리 틱의 유효 요청을 모아 같은 상태 스냅샷에서 검증한다.
- 먼저 유효하게 처리된 서버 틱을 우선한다. 같은 틱 경쟁은 경기 시드·승객 ID·안정된 선수 ID로 만든 사전 결정 순서로 해결하는 것을 제안한다.
- 방장 여부·화면 클릭 시각·클라이언트가 보고한 거리·점수 순위는 중재 우선권이 아니다. 같은 틱 안의 패킷 수신 순서도 승리 조건으로 쓰지 않는다.
- 승객 상태 버전과 선수의 빈차 상태를 함께 비교·갱신한다. 승객 중복 소유와 한 선수의 동시 다중 승차를 모두 막는다.
- 같은 `ClaimRequestId`의 재전송은 이전 승인·거절을 돌려준다. 다른 요청 ID라도 이미 끝난 상태를 다시 승차시키지 않는다.
- 경쟁에서 진 선수는 빈차로 남으며 감점·취소 비용을 받지 않는다. 내비가 가리키던 승객의 소유 변경을 즉시 알린다.

서버 틱을 가로지르는 통신 지연 차이는 남을 수 있다. 이는 숨겨진 보정으로 해결했다고 주장하지 않고 지역·호스트 여부·접근 상황별 승차 성공 편향을 측정해 [09](09-decisions-and-balance.md)에서 판단한다.

## 공급과 접근 기회의 공정성

| 공급 단계 | 제안 정책 | 검증해야 할 실패 |
|---|---|---|
| 첫 공급 | 모든 선수가 조작을 시작하는 틱에 동시에 공개 | 로드·화면 표시 순서 때문에 먼저 받을 수 있는 공급 |
| 시작 배치 | 각 시작 지점의 합법 접근 경로·신호·회전 비용으로 후보를 검증 | 직선거리만 같고 한 선수만 먼 합법 우회가 필요한 배치 |
| 공급 구성 | 서로 접근 가능한 복수 선택지를 확보하고 경로·운임 유형을 섞음 | 첫 승차 한 번으로 다음 공급까지 독점하는 배치 |
| 후속 공급 | 서버가 공유 가용량과 유효 후보를 보고 동일 규칙으로 보충 | 특정 선수 화면에만 먼저 등장하거나 점유 차량과 겹치는 공급 |
| 운송 종류 | 짧은 경로·연결도로·외곽 경로의 합법 완료 기회를 비교 | 운임만 크고 정상 운전으로 마감 전 완료하기 어려운 후보 |
| 반복 경기 | 시작 지점 교대와 같은 시드의 비교 플레이 | 특정 출발 위치·선수 ID에 고정되는 누적 이점 |

첫 공급 보호는 초기 기회의 불균형을 줄이기 위한 제안이다. 비공개 예약이나 패배 선수에게만 다른 운임을 주는 규칙으로 바꾸지 않는다. 지도 공급 후보의 좌표·방향·안전 공간은 [맵·콘텐츠](03-map-and-content.md)가 소유한다.

대기 승객이 없으면 서버는 유효 후보를 재검사하고 공급 지연 사유를 기록한다. 경로가 없는 승객을 급히 만들지 않는다. 국소적인 공급 부족이 반복되면 후보·재공급 설정을 수정하며, 점수 조작으로 덮지 않는다.

## 원약정 기본운임의 정의

`QuotedBaseFare`는 출발 승차 방향에서 목적지 하차 방향까지 연결된 **기준 합법 경로**의 거리로 계산한 게임 내 원약정 운임이다. 모든 선수에게 공개할 때 고정하며, 같은 승객의 승차 승자가 달라져도 바뀌지 않는다.

기준 경로는 동결된 도로 그래프에서 허용 차로·회전·진입 방향을 지키는 가장 짧은 경로를 제안한다. 동거리 후보는 안정된 경로 ID 순으로 선택한다. 현재 교통 속도·플레이어의 실제 위치는 기본운임 경로를 바꾸지 않는다.

| 요소 | 운임에 반영 | 반영하지 않는 것 |
|---|---|---|
| 출발·도착 | 공급 시 확정한 승하차 위치·방향 | 선수가 선택한 다른 내비 목표 |
| 기준 거리 `L` | 동결된 기준 합법 경로의 길이 | 픽업까지 공차 이동·실제 우회·왕복·제자리 이동 |
| 운임표 | 해당 경기의 기본액·포함 거리·거리 단계액 | 운전자 개인의 캠페인 등급·현금·저장 데이터 |
| 운행 중 지연 | 약정은 유지 | 신호 대기·정체·접속 끊김·공통 추가 시간 할증 |
| 운전 결과 | [05](05-scoring-and-results.md)에서 별도 점수 처리 | 캠페인 운전 점수·만족도 `S/M/R`·기존 실수령 배율 |

운임표 초안의 계산은 `F = BaseFare + DistanceStepFare × ceil(max(0, L − IncludedDistance) / DistanceStep)`이다. 금액은 정수 최소 단위, 거리는 공통 정수 길이 단위로 저장하고 `DistanceStep > 0`을 검증한다. 금액 계수·포함 거리·단계 길이는 [09](09-decisions-and-balance.md)에서만 정한다.

위 `F`가 `QuotedBaseFare`다. 경로 길이의 단위 변환과 단계 올림은 공급 때 한 번 계산하고 결과를 저장한다. 승차·하차 시 다시 다른 그래프로 계산하지 않는다. 실제 운송이 유효하게 완료되었을 때만 이 금액을 [점수로 환산](05-scoring-and-results.md#점수-산식과-정수-계산)한다.

## 취소·만료·경로 오류

| 조건 | 승객·운송 처리 | 결과·보호 |
|---|---|---|
| 내비만 선택한 대기 승객 만료 | `Waiting → Expired`, 해당 안내 갱신 | 플레이어가 맡은 운송의 취소로 기록하지 않음 |
| 공급 후 지도 데이터 오류 발견 | 서버가 `Cancelled`와 사유 확정 | 승객을 다른 목적지·운임으로 몰래 바꾸지 않음 |
| 운송 중 길을 잘못 듦·회전을 놓침 | 합법 경로 재안내, 기존 운송 유지 | 우회 거리가 늘어도 기본운임 증가 없음 |
| 게스트 일시 끊김 | [01](01-match-flow-and-rules.md)의 유예·격리 적용 | 연결 상태만으로 새 승객이나 자동 하차를 만들지 않음 |
| 명시적 이탈·재접속 유예 만료 | `Onboard → Cancelled` | 미완료 운임·완료 보너스 없음, 기존 위반 기록 유지 |
| 본 경기·최종 마감 | [01의 경계](01-match-flow-and-rules.md#본-경기-종료와-최종-마감)에 따라 대기·운송 만료 | 개인별 연장·부분 운임 없음 |

초기안에는 승객을 유리하게 다시 뽑는 임의 중도 취소 버튼을 두지 않는다. 별도의 승객 운송 제한시간도 우선 추가하지 않고 공통 경기 마감을 사용한다. 두 기능의 도입 필요성은 [09](09-decisions-and-balance.md)에 남긴다.

시스템 경로 오류가 한 후보에 한정되면 해당 후보를 중단하고 원인을 기록한다. 경기 공정성을 보장할 수 없는 광범위한 오류의 무효 처리는 [01](01-match-flow-and-rules.md)을 따른다. 자동 지급·추정 운임으로 완료 건수를 만들지 않는다.

## 콘텐츠·데이터 계약과 확인 사례

| 데이터 항목 제안 | 필요한 내용·불변 조건 |
|---|---|
| 승객 공급 | `PassengerId`, 공급 시드, 공개 틱, 대기 만료 틱, 상태·상태 버전 |
| 정차 지점 | 출발·도착 ID, 접근 차로·정차 방향, 서버 판정 영역, 안전 공간 |
| 경로 약정 | 지도·그래프·운임표 버전, 기준 경로 ID·거리, `QuotedBaseFare` |
| 소유권 | `OwnerPlayerId`, `TripId`, 승차 확정 틱, 승인 요청 ID |
| 종료 증거 | 하차 확정 틱·위치·방향, 완료/취소/만료 사유, 정산 식별자 |

| 확인 장면 | 통과 조건 |
|---|---|
| 두 선수가 같은 승객에 동시 현장 입력 | 한 소유자·한 운송만 생성되고 패자에게 결과 설명 |
| 먼 곳에서 핀 선택 후 다른 선수가 도착 | 현장 유효 승차가 가능하며 선택자가 소유권을 주장할 수 없음 |
| 중앙분리대 반대편 또는 역방향 정차 | 가까워도 승하차 거절, 올바른 접근 방향 안내 |
| 같은 승객을 정상 경로·고의 우회로 각각 완료 | 동일 원약정 운임, 추가 거리에서 별도 수익 없음 |
| 완료 패킷 반복·대기 만료와 승차 경합 | 종결 상태와 정산이 한 번만 생기며 모든 화면에 일치 |

공급 다양성·접근 시간·완료율·무효 경로 비율의 측정은 [플레이테스트](10-playtest-and-acceptance.md)에 연결한다.

## 공통 승객 콘텐츠 연결 (2026-10-29)

완료된 캠페인 일반+11특수유형의37변주·초기 대사를 PVP 네트워크 미리보기에 연결했다. 실제 승객 소유권/운송/정산이나 캠페인 준비·오염 수치를 적용한 것이 아니다. [요소별 적용 표](15-content-application-review.md)와 [실제 검증 이력](../../work-history/2026-10-29-pvp-reconnect-content.md)을 따른다.

## 2026-10-29 기본 경쟁 운송 구현

서버 공유 공급·합법 경로의 고정 약정·동일 tick 단일 소유권·현장 승하차·경기/선수/요청 ID 재전송·종결 상태를 구현했다.37변주 초기 대사는 실제 기본 운송에도 표시한다. 수면/준비/응답/오염 효과는 후속이다. [수용 범위와 미검증](17-competition-acceptance.md)을 따른다.
