# PVP 검증·플레이테스트·완료 기준

상태: 검증 계획 / P1 기반 코드 검사 일부 수행, Unity·온라인 검증 대기
작성일: 2026-10-27
담당: 개발 뒤 무엇을 어떻게 확인할지 정의. 아래 제품 검증은 이번 문서 작성으로 수행된 것이 아니다.

## 검증 결과를 구분하는 기준

| 검증 | 확인할 수 있는 것 | 대신할 수 없는 것 |
|---|---|---|
| 문서 검사 | 링크·구조·결정 상태·요구사항 추적 | PVP 코드·게임 빌드·온라인 기능 |
| 순수 규칙 자동검사 | 정산·상태 전이·이벤트 중복·마감 경계 | 조작감·실제 물리·화면 가독성 |
| 같은 PC 복수 실행 | 기본 접속과 소유권·동기화 연결 | 다른 인터넷 환경·실제 패킷 손실 |
| 다른 PC 실제 접속 | 입력·차량·공통 상태·접속 예외 | 전체 이용자 환경의 안정성 |
| 지연·손실 주입 | 특정 통신 조건에서 보정·복구·중복 방지 | 모든 네트워크 상황의 품질 보장 |
| 사람 플레이 | 운임 경쟁·조작·경로 판단·경기 길이 | 규칙 자동검사의 완전성 |
| 배포 검사 | 실행폴더·시작점·버전·설정·재현 | 실제 사용자 전체의 플레이 검증 |

검증 기록에는 대상 커밋/빌드, 맵 버전, 규칙 버전, 참가 수, 경기 설정, 환경, 결과, 미검증 항목을 함께 적는다. 자동검사 성공만으로 “PVP 완성”이라고 표시하지 않는다.

## 조작·맵 측정표

| 측정 항목 | 기록할 값 | 해석 |
|---|---|---|
| 가속 응답 | 입력부터 가속 시작, 순항 속도 도달 시간 | 도로 길이에 비해 재가속이 지나치게 길지 않은가 |
| 조향 응답 | 입력부터 차체 방향 변화, 반대 입력/복귀 반응 | 빠르게 반응하면서 목표 차로를 유지하는가 |
| 코너 | 진입·통과·탈출 시간, 충돌·경계 침범 | 경로 선택의 실력 차이가 생기는가 |
| 운송 한 사이클 | 접근·대기·승차·탑승 운송·하차·다음 탐색 | 속도감이 어디에서 끊기는가 |
| 경로 비교 | 합법 주행으로 각 대안의 시간·교통·다음 기회 | 신호 위반 없는 대안끼리 경쟁력이 있는가 |
| 온라인 보정 | 보정 거리·빈도, 도로 폭 대비 오차, 부당 감점 의심 | 물리/네트워크 오차가 승부를 대신하는가 |

현행 차량의 성능이나 사용자의 느낌을 측정 없이 수치로 단정하지 않는다. 후보 설정을 같은 코스·같은 입력 조건으로 비교한 기록을 남긴다.

## 밸런스 시험 방법

1. 맵·교통·승객 공급 조건과 경기 설정을 기록한다.
2. 출발 위치를 교대하거나 균등한 시작 세트를 사용해 위치 효과를 분리한다.
3. 운임·완료 횟수·빈차 비율·위반·최종 성적을 함께 본다.
4. 수익이 높은 전략이 조작과 판단에서 나온 것인지, 우연한 승객 공급이나 위반 이득에서 나온 것인지 구분한다.
5. 한 번에 여러 조작·맵·배점을 바꾸지 말고 비교 이유를 기록한다.
6. 참가 인원과 경기 시간의 최종 결정은 이 기록 이후 [09](09-decisions-and-balance.md)에 남긴다.

감점은 “안전 운전이 항상 승리하도록” 맞추지 않는다. 큰 운임 우위가 경미한 실수에도 유지되는 경우와, 반복 위반의 추가 수익이 상쇄되는 경우를 모두 시험한다.

## 재접속 증거 추가 (2026-10-29)

`tools/test_pvp_reconnect.ps1`은 정상 복귀·위조 거절·유예 종료·명시 퇴장·실제 패킷 차단 복구·호스트 종료를 독립 Player로 검사한다. 복귀는 같은 서버 슬롯/선택/위치와 새로운 epoch, 복귀 후 권한 차량 이동까지 확인한다. 서버 만료 정확한 경계·중복 연결·옛 epoch 거절은 Editor 모델 검사다. 실제 화면은 한글 HUD/승객 대사 확인이며 수동 운전 검사가 아니다. [검사별 결과와 미완료 수용](../../work-history/2026-10-29-pvp-reconnect-content.md)을 근거로 사용하며 P2 전체 통과로 표시하지 않는다.
