# 완료 승객 콘텐츠·내구도 PVP 적용 검토

기준: main `9d05a40`, [승객 구현·배포 이력](../../work-history/2026-10-29-passenger-types-implementation.md), [캠페인 승객 기획](../02-passengers-and-fares.md), [내구도·수리 기획](../03-life-and-economy.md). 다른 채팅의 완료 소스·배포를 병합하고 원본을 수정하지 않았다. 현재 내구도·수리는 **캠페인에서도 미구현**이다.

## 승객 유형별 요소

이번 실제 연결은 `PvpPassengerCatalog`의 유형·변주·초기 대사 읽기, 네트워크 HUD 미리보기, 서버 선택과 재접속 복원이다. 일반3 + 특수34 =37개이며 아래 모든 유형에 적용했다. 실제 승차·운송·응답 선택·정산·오염 효과는 이번 PVP 실행에 연결하지 않았다.

| 콘텐츠 | 완료된 캠페인 요소 | 이번 PVP 반영 | 실제 경기 적용 때 필요한 조건 |
|---|---|---|---|
| 일반 | 차분한 인사·풍경 감상·짧은 인사3 | 공통 모델 미리보기 | 기본 운임·거리·승객 소유권 |
| 취객 | 말 많은 밤·미안한 손님·조용한 귀가3 | 같은 대사·변주 재사용 | 발생 빈도·불편 효과가 운임/시간 선택과 균형을 이루는지 별도 비교 |
| 잠자는 승객 | 미리 부탁·대화 중 수면·얕은 잠·깊은 잠4 | 초기 콘텐츠 재사용 | 깨우기/도착 확정 순서, 경기 종료와 동시 발생 처리 |
| 승차감 민감 | 출발·회전·회복 반응3 | 초기 콘텐츠 재사용 | PVP 민첩한 차량의 가속/조향과 운전 점수 기준 조정 |
| 재촉·불만 | ETA·신호 대기·도착 직전 확인3 | 초기 콘텐츠 재사용 | 합법 경로·공유 신호를 기준으로 약속 판정, 위반 유도 방지 |
| 경로 확인 | 큰길·짧은 길·익숙한 길3 | 초기 콘텐츠 재사용 | 자체 PVP 맵의 합법 경로/예상 시간 사용 |
| 용무·경유 | 미리 부탁·중간 용무·복귀3 | 초기 콘텐츠 재사용 | 유효 경유 지점/예약·소유권, 고액 단건과 짧은 여러 건 비교 |
| 짐 많은 승객 | 큰 가방·상자·흔들리기 쉬운 짐3, 적재/하역 | 초기 콘텐츠 재사용 | 안전 정차 중 서버 진행, 소요 시간과 추가 운임 별도 균형 |
| 흙 묻은 짐 | 가방·화분·작업 짐3, 보호 준비/오염 사건 | 초기 콘텐츠 재사용 | 청결 자체의 PVP 채택 판단, 사건 중복 적용 방지 |
| 음식·음료 | 간식·음료·도시락3, 섭취 허용/밀봉/정리 | 초기 콘텐츠 재사용 | 서버 사건 시드, 사전 위험 안내, 불리한 결과의 반복 추첨 방지 |
| 정밀 하차 | 입구·보행 동선·안전 지점3 | 초기 콘텐츠 재사용 | 자체 지도 안전 승하차 공간 검증; 캠페인 지도 지점 자동 이식 금지 |
| 대화·반복 질문 | 고민·지역 질문·반복 질문3 | 초기 콘텐츠 재사용 | 주행 중 입력 부담/시야 방해, 응답 이력의 서버 복원 |

## 공통 상태·효과 연결 경계

| 요소 | 현재 PVP 상태 | 후속 구현 계약 |
|---|---|---|
| 유형·변주·초기 대사 | 구현. 공통 모델에서 새 객체를 읽고 불변 카드만 노출 | 공통 모델 변경 시 전체37개 검사를 실행 |
| 선택 권한 | 구현. client는 범위 내 index만 요청, 서버가 확정 | 현재는 콘텐츠 미리보기 선택이며 실제 경쟁 승객 선점이 아님 |
| 단절·복귀 | 구현. 같은 슬롯/선택/차량 위치 보존, 새 epoch 입력만 허용 | 실제 운송 ID·승객 상태·정산 완료 ID까지 이어서 복원해야 함 |
| 요청 응답 기억/수면/준비/하역 | 캠페인 완료, PVP 미연결 | 서버 시간·명시적 상태 전이·단일 완료 처리로 연결 |
| 음식/짐 오염 | 캠페인 완료, PVP 미연결 | 청결 채택 결정 후 경기/운송/사건 ID로 한 번만 적용 |
| 수치 | 캠페인10초, 청결2/6/5 등 시험값을 PVP에 적용하지 않음 | 경기 시간·맵 이동 시간·운임·운전 배점을 함께 조정 |
| 승패/경제 | 미구현 | 고액 단건 대 짧은 여러 건의 전략을 검증. 경기 시간을10분으로 고정하지 않음 |

P2 전체 게이트와 공유 신호/장애물 수용 후 Task4/5의 소유권·운송·정산을 먼저 완성하고 위 행동을 연결한다. 콘텐츠가 보인다는 이유로 실제 PVP 승객 운송 완료로 표시하지 않는다.

## 내구도·수리 적용 검토

| 요소 | 캠페인 상태 | PVP 적용 가능성과 제안 | 이번 반영 |
|---|---|---|---|
| 충돌 손상 | 기획. 충돌 사건 강도/중복 차감 방지 | 서버의 접촉 사건 ID와 강도로 판정 가능. 클라이언트 자기 손상 제출 금지 | 검토만 |
| 차량 간 충돌/과실 | PVP와 별도 정책 | 현재 주행 시험 무접촉 유지. 접촉/밀기 채택 전 고의 길막·피해 귀속 수용 필요 | 기존 정책 유지 |
| 내구도0 운행 불가 | 캠페인 사용자 확인 방향, 미구현 | PVP 후보. 제동/안전 정지·회복 공간·복귀 시간을 먼저 설계 | 코드 미연결 |
| 성능 변화 | 캠페인은 수리비·시간 중심 | PVP 민첩성 훼손/역전 불가능 상태 방지. 속도·조향 저하를 자동 추가하지 않음 | 후보 |
| 수리비·시간 | 캠페인 수치 시험안 | 경기 내 운송 기회 손실과 비교. 캠페인 잔액/부채/날짜를 가져오지 않음 | 후보 |
| 견인/안전 복귀 | 기획. 전용 공간 예약 필요 | 자체 지도 빈 공간, 점유 예약, 전진 이득·상대 방해 방지 | 후보 |
| 단절/기술 복구 | 내구도 원본 모델 없음 | 도입 후 서버 상태 보존, 재접속 무료 수리·중복 청구 방지 | 현재 위치/미리보기만 보존 |
| 승객/정산 동시 발생 | 기획의 도착 경계와1회 취소 | PVP 운임 확정/경기 종료/손상 순서부터 정의. 캠페인 수치를 승패 산식으로 오인하지 않음 | 후보 |

내구도 구현 완료 커밋이 생기면 순수 상태 모델·사건 중복 방지 부분부터 재검토한다. 현재 존재하지 않는 기능을 연결 완료로 표시하거나 다른 채팅 대신 캠페인 내구도를 구현하지 않는다.
## 기본 경쟁 운송 후속 갱신

2026-10-29 후속에서 공통 승객의 소유권·승하차·약정·정산을 실제 네트워크에 연결했다. 위 표의 유형별 준비/응답/수면/청결 효과와 내구도는 그대로 미연결이다. [최신 수용 범위](17-competition-acceptance.md), [실제 검사](../../work-history/2026-10-29-pvp-shared-competition.md)를 우선한다.
