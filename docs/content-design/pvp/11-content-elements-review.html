2026-10-29 추가 요구: 승객·내구도 PVP 적용

사용자는 캠페인에서 진행 중인 승객·내구도 작업을 PVP에도 적절히 반영하도록 요청했다. 반영 방향은 요구사항이며, 아래 PVP 규칙·수치와 도입 시점은 검토안이다. 기존 초기 범위 제외 문구는 기본 온라인 경기 검증 단계에 대한 제한으로 유지하고, 확장 검토 대상에서 영구 제외한다는 의미로 해석하지 않는다.

요소 PVP 적용 검토안 선행 검증·미정 사항
승객 유형·대화·준비/하역유형별 예상 시간·보상·위험을 선택 전에 공개해 고액1건과 짧은 여러 건의 선택을 강화기본 승차 소유권·완료 정산 검증 후 소수 유형부터 비교, 유형/수치 미정
음식·음료·오염운송 중 선택과 정차 정리의 시간 비용으로 비교캠페인 청결 경제·대기시간을 그대로 이식하지 않음; 진행 중인 승객 구현의 검증 완료 커밋을 기준으로 검토
충돌 내구도경기 안에서 누적 손상과 수리 여부 선택을 비교서버 사건 확정·중복 손상 방지·가해/피해 귀속 검증 선행, 택시 간 충돌 정책 미정 유지
수리·운행 불가·복구수리 시간/비용과 운송 기회 손실 비교, 운행 불가 뒤 복귀 경로 보장캠페인 내구도0 운행 불가는 캠페인 확정 사항; PVP 적용·복귀시간·점수 차감 방식은 별도 검토
공정성·저장경기별 초기화와 서버 승인 상태를 기준으로 설계캠페인 성장·잔액·차량 상태가 경쟁 우위를 주지 않도록 검증; 청결/내구도와 운전 감점의 중복 불이익 비교

실행 순서: Task2 잔여 화면·사람 조작감 확인 → Task3 실제 네트워크 주행 → Task4/5 기본 승객 경쟁·정산 → 위 확장 비교. 기획·데이터 경계 검토는 병행 가능하며 구현 순서는 각 게이트를 따른다. 다른 채팅의 미완료 소스를 복사하거나 수정하지 않고 완료 커밋을 통합한 뒤 재사용 가능 부분과 PVP 규칙을 구분한다.

검증 권한 갱신: 사용자가 완료 후 Unity 화면 확인을 허용했다. 화면 확인과 실제 사람 조작감 검증은 구분한다. 지속적인 PC 조작이나 키보드·마우스 자동 입력으로 권한을 확대하지 않는다. 이번 문서 작업에서 Unity 실행·화면 확인은 하지 않았다.
