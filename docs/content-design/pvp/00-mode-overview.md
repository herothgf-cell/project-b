# PVP 모드 개요

상태: 기획 초안 / 초기 시작 기반 구현, 본문 경기 기능은 미구현
작성일: 2026-10-27
담당: 경험 목표, 접근 대안, 초기 범위와 확장 경계.

## 만들려는 경험

직접 제작한 작은 도시 경기장에서 실제 플레이어들이 승객을 확보하고 운송한다. 승객 선택, 경로 판단, 민첩한 운전으로 더 많은 운임을 벌며 운전의 정확성도 승패에 기여한다. 운송이 끝나면 다음 영업 판단으로 빠르게 이어진다.

핵심 질문은 “어떤 손님을 어떤 경로로 운송해야 남은 기회에서 가장 좋은 성적을 얻는가?”다. 자체 제작 맵과 PVP 조작은 이 판단을 짧고 반복 가능한 행동으로 만들기 위한 수단이다.

## 사용자 요구와 설계 초안의 구분

사용자가 명시한 방향은 실제 사용자 PVP, 제한된 공간, 충분한 운임 영향, 운전 점수 반영, 자체 제작 맵, 민첩하고 빠른 경기 흐름이다. 경기 시간은 미정이다. 기획 작성 이후 별도 브랜치에서 초기 시작 기반을 구현·검증했고 자체 시험장 개발을 진행한다. 실제 범위는 [최신 검증 이력](../../work-history/2026-10-29-pvp-review-validation.md)을 따른다.

공유 승객 선점형, 초기 충돌 OFF, 2인에서 시작하는 검증, Photon Fusion 2 Host 및 초대방은 현재의 권고안이다. 최종 확정과 시험 수치는 [결정 대장](09-decisions-and-balance.md)에서 관리한다.

## 한 번의 경기에서 하는 일

| 흐름 | 플레이어가 판단하는 것 | 기대하는 결과 |
|---|---|---|
| 준비 | 규칙·맵·차량 조건을 확인하고 참가 준비 | 같은 조건과 종료 규칙을 알고 시작 |
| 탐색 | 운임, 접근 거리, 목적지, 경쟁자 위치를 비교 | 지금 확보할 승객을 선택 |
| 확보 | 합법적인 접근과 정차로 공용 승객 승차 | 다른 플레이어와 경쟁한 결과가 즉시 드러남 |
| 운송 | 긴 고속 경로와 짧은 코너 경로, 교통 흐름을 비교 | 조작과 지도 이해로 운송 효율 차이 발생 |
| 하차 | 도착 조건을 정확히 충족 | 확정 운임과 운전 결과를 이해 |
| 다음 운송 | 하차 지역과 남은 시간을 보고 다시 선택 | 다음 판단으로 끊김 없이 연결 |
| 결과 | 운임과 운전의 기여를 비교 | 왜 이기거나 졌는지 설명하고 재경기 |

상태 전이는 [01 경기 진행](01-match-flow-and-rules.md), 운송은 [04 승객·운임](04-passengers-and-fares.md), 승패는 [05 점수·결과](05-scoring-and-results.md)가 담당한다.

## 성공해야 할 세 가지 경쟁

| 경쟁 | 잘한 플레이 | 피해야 할 결과 |
|---|---|---|
| 영업 판단 | 큰 운임과 다음 승객 기회를 함께 비교 | 최고액 손님 또는 가장 짧은 운송만 항상 정답 |
| 운전 효율 | 정확한 코너·정차·재가속으로 시간을 절약 | 신호를 무시해야만 속도감을 얻음 |
| 운전 품질 | 같은 운임에서는 더 안전하고 정확한 플레이가 우세 | 적게 운송해도 운전점수만으로 쉽게 승리 |

큰 운임 우위는 경미한 실수로 쉽게 사라지지 않아야 한다. 반복 위반의 시간 이득이 항상 유리해서도 안 된다. 두 조건은 실제 시간·수익 비교로 조정한다.

## 검토한 접근 대안

| 접근 | 얻는 것 | 비용·제약 | 현재 판단 |
|---|---|---|---|
| 개인 배차 기록 경쟁 | 비슷한 운송 기회로 조작·영업 실력 비교 | 상대 때문에 내 선택이 바뀌는 상황이 적음 | 초기 성능·공정성 비교용 대안 |
| 공용 승객 영업 경쟁 | 선점, 위치, 다음 운송 선택이 직접 연결 | 공급·출발 조건·동시 승차 판정 필요 | 첫 게임성 초안 |
| 팀 단위 회사 대항 | 구역 분담·협력·합산 성적 | 역할·팀 균형·대기 인원까지 추가 설계 | 후속 후보 |

구현 방식은 새 브랜치에서 같은 Unity 프로젝트의 전용 시작점과 별도 실행파일로 검증한다. 별도 Unity 프로젝트 복제는 의존성이 실제로 크게 갈라질 때 재검토한다. 장기 분기와 서버 방식의 비교는 [07](07-network-and-build.md)에 둔다.

## 후속 범위

추가 맵, 수요 이벤트, 승객 특성, 팀전, 물리 충돌 규칙, 외형 수집, 공개 매칭·전적·랭킹은 초기 경기의 결과를 보고 선택한다. 승객 강탈 아이템, 전투, 강제 꼴찌 보정, 캠페인 차량 성능 이월은 현재 초안에 포함하지 않는다.

캠페인의 생활·청결·졸음·정비·장기 경제는 기존 모드의 경험으로 유지한다. PVP 첫 경기에서는 그 시스템을 그대로 연결하지 않고 운송 경쟁을 검증한다.

## 기존 기획을 참고하는 경계

| 기존 문서 | 참고할 부분 | PVP에서 새로 정할 부분 |
|---|---|---|
| [주행·교통](../01-driving-and-traffic.md) | 관찰 가능한 사건, 중복 평가 방지, 안전한 판단 | 민첩한 조작, 경기용 교통 조건, 판정 권한 |
| [승객·운임](../02-passengers-and-fares.md) | 방향을 고려한 승하차, 운송 한 번 정산 | 공용 승객 소유권, 경기용 고정 약정 |
| [생활·경제](../03-life-and-economy.md) | 지역 수요와 공차 기회의 차이 | 판당 초기화, 경기 성과 중심 자원 |
| [캠페인·회고](../04-campaign-and-feedback.md) | 사건 근거와 결과 설명 | 공통 종료·순위·재경기 |
| [화면·길안내](../05-interface-and-navigation.md) | 정보 우선순위, 경로·목표 구분 | 상대 상태와 경기 HUD, 개인 메뉴만 열기 |

현재 main에서 완료된 캠페인 기능을 PVP 구현 완료로 세지 않는다. 코드 재사용도 그대로 붙이는 작업량으로 추정하지 않는다.
