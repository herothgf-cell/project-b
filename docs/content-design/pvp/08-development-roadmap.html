순수 코드 검사 — 실제 수행

저장소 루트에서 아래 중 사용 가능한 환경의 명령을 실행한다. Windows 스크립트는 .NET SDK 8+/Python 조합 또는 기존 .NET Framework C# 컴파일러를 사용한다. 이번 실행 환경에서는 Python/.NET SDK 경로를 수행했고 Windows PowerShell 경로 자체는 미수행이다.

powershell -ExecutionPolicy Bypass -File tools/test_pvp.ps1
python tools/test_pvp.py
# dotnet이 PATH에 없는 경우
python tools/test_pvp.py --dotnet /absolute/path/to/dotnet

기대 결과는 PVP_ISOLATION_OK cases=8과 PVP_TWO_PROCESS_DIAGNOSTICS_OK다. 후자는 두 .NET 검사 프로세스의 파일 분리이며, Unity Player 두 대의 온라인/물리 검증이 아니다. Python 러너는 성공 결과를 artifacts/pvp-tests/result.txt에 남긴다. Windows .NET Framework 대체 경로는 콘솔 출력과 종료 코드를 확인한다.

Python 러너는 검증 시작 시 이전 성공 기록을 지운다. 실패한 재실행 뒤 오래된 성공 기록이 남지 않는지 확인하는 회귀 검사는 아래와 같으며, 이번 작업에서 1/1 통과했다.

python -m unittest discover -s tests -p test_pvp_runner.py -v

Unity Editor 검사와 Windows 빌드 — 준비됨, 미수행

$PvpUnityEditor를 실제 Unity 2022.3.62f2 실행파일 절대 경로로 지정한다. Windows64 빌드 지원 모듈이 필요하다. 같은 프로젝트를 다른 Unity 프로세스에서 닫고, 작업 중인 씬은 먼저 저장한 뒤 저장소 루트에서 실행한다. 빌드 메서드는 실행 중 플랫폼을 바꾸지 않으므로 -buildTarget Win64를 반드시 지정한다. 에디터 메뉴를 사용할 때도 Windows x86_64로 전환·재컴파일을 마친 뒤 실행한다.

& $PvpUnityEditor -batchmode -quit -projectPath unity/EungyeTaxi -buildTarget Win64 -executeMethod Pvp.Editor.PvpBuild.BuildClient -logFile artifacts/pvp/build-client.log

각 명령의 종료 코드 0과 실제 로그의 PVP_EDITOR_ISOLATION_OK / PVP_BUILD_OK를 함께 확인한다. Editor 검사는 실제 설정을 바꾸고 복원하지만 비용이 큰 BuildPipeline 호출만 대체한다. 그 검사 성공이 실제 Player 빌드 성공을 대신하지 않는다. 빌드 메뉴는 Taxi > PVP > Build isolated Windows client다.

작업별 인계와 완료 표시

각 Task는 저장소 작업 규칙에 따라 요구·변경 파일·실제 명령·로그 위치·자동/사람/배포 결과·미검증 항목을 날짜별 이력에 남기고 LATEST.md를 갱신한다. PVP 작업을 기존 게임의 전체 수동 검증 완료로 표시하지 않는다. 원격 반영된 커밋 해시는 실제 확인 후 기록하고, 작업 이력에 자기 자신을 포함할 해시를 추측하지 않는다. 다음 실행자는 먼저 현재 작업 트리와 최신 인계를 확인하고 첫 미완료 Task의 게이트부터 진행한다. 이미 추가된 기반 코드를 다시 생성하지 말고, 남은 Unity 실행 검증부터 확인한다.

2026-10-29 후속 검증

Task 1 실제 Unity 검사·빌드·두 Player·초기 UI 결과와 콘텐츠별 검토표를 추가했다. 본문 과거 미수행 설명은 첫 기반 커밋 당시 상태이며, 이번 실제 결과를 우선한다. Task 2 계약은 구체 구현 계획을 따른다.

Task 2 후속 진척 (2026-10-29)

  • 자체 지도·방향 연결·도달성·복구 비전진과 차량 입력/상태 복원 자동 검사.
  • 회색 상자 시험장·차량A/B·최단/예상최속 합법 경로·오프라인 시작 연결.
  • Unity Editor 통합 및 실제 Player 입력 모델 검사. 정확한 결과와 한계.
  • 실제 화면·키보드/패드·사람 조작감·전체 코스 비교. 사용자 요청으로 PC UI 자동 조작 중단.

실제 파일은 계획의 이름과 일부 다르다: PvpMapRuntime.cs에 도로 런타임/경로 계산, Editor/PvpMapTests.cs·PvpVehicleTests.cs·PvpTask2Tests.cs에 기존 정적 Run 방식 검사를 둔다. 새 테스트 패키지를 추가하지 않았다.

직접 IP 네트워크 후속 (2026-10-29)

실제 작업·검증 기록과 실행 계획을 따른다.

  • Task2: 표시된 실제 Player 화면에서 한글HUD·차량·도로 방향·경로·복구 안내 확인. 자동 주행 입력이며 사람 조작감·실물 패드·전체 코스 수용은 미완료.
  • Task3 대안: 사용자 Fusion SDK/App ID 미준비 및 대안 요청에 따라 NGO1.12.0 직접 IP 주행 시험 구현. Host/Client 2인, 서버50Hz, 입력 예측·ACK 재계산, 동일 buildGUID/프로토콜/지도/규칙 승인, 입력 폭주 병합. 공유 장애물/신호·재접속은 미구현.
  • 실제 독립 Player·지연/손실 측정값은 날짜별 이력에만 기록한다. SDK 최종 선택과 P2 전체 게이트를 자동 통과시키지 않는다.
  • 다음: 별도PC LAN 접속과 사람 조작감 비교, 주행 중 보정/원격차량 보간·단절/재접속 복원·부하 측정. 검증 결과로 Fusion/NGO 채택 판단. 승객·내구도 연동은 다른 작업 완료 커밋 이후.

재접속·완료 콘텐츠 연동 후속 (2026-10-29)

  • 동일 프로세스/생존 호스트 재접속, 서버 슬롯/epoch 검증, 위조·중복·만료·명시 퇴장 규칙, 원격 차량 표시 보간.
  • Unity Editor/clean Windows 빌드, 실제 Player6시나리오, RTT150ms/손실3%에서4초 패킷 차단 후 복귀·재가속·정지, 기존 네트워크 회귀. 실제 수치·명령·범위.
  • 완료 main9d05a40 승객 공통 모델37변주 미리보기·서버 선택 복원. 유형·효과·내구도 적용 표.
  • 다른PC LAN/인터넷, 실제 사람 조작감/패드/전체 코스, 공유 신호·장애물/부하 수용. P2 전체 게이트는 아직 미통과.
  • P3 실제 승객 소유권·운송·정산 후 준비/응답/오염 연결. 내구도는 캠페인에서도 미구현이므로 완료 소스가 생긴 뒤 별도 검토.

현재 SDK 직접IP NGO와 차량A·무접촉·30초 유예는 시험 설정이다. 최종 SDK/인원/배점/충돌 정책과 경기 시간은 확정하지 않았다.

공유 교통→승객/정산 후속 (2026-10-29)

사용자가 다른PC/사람 수용을 별도로 정리하고 후속 구현까지 진행하도록 지시했다. Task3의 공통 신호/이동 장애물 최소 장면과 Task4/5 기본2인 운송 경로를 구현했으며, 정확한 실제 결과는 날짜별 이력을 따른다.

  • 공유 상태·단일 소유권·경계·원장·재접속/이탈·결과 일치는 자동 검사 범위에서 확인한다.
  • Task4/5의 최소 화면은 시간 설정/준비·목표/승하차·거절·점수 구성·결과를 제공한다.
  • P2 전체(다른PC/사람), 전체 코스 물리 운송, 공유 일반NPC/법규 전체·부하/템포는 계속 미완료다.
  • 다음은 환경별 잔여 목록에 따라 실제 LAN/사람 운전과 Task6 교통 판정 확장을 진행한다. 유형별 준비/수면/오염과 내구도는 별도 후속이다.

2026-10-29 실제 입력 주행·공유 교통 후속

최신 수용·환경별 잔여 표와 실제 검사 이력을 따른다. 위치 제어 없이 실제 모터 입력으로 운송하고 서버 NPC2대/보행1명·신호/우회전/지속 속도·방향/접촉 책임·보류를 연결했다. 이전의 해당 미구현/미검증 설명은 당시 기록이다. 다른PC·사람/화면 시야·복합 교통/금지차로 자산은 별도 수용으로 남긴다.

기존2참가자 모델에 로컬 봇을 넣어 사람 한 명이 한 실행 창에서 직접 운송/NPC/법규/정산을 시험한다. 모델 각7회·실제 Player 정상/위반 각2회 운송, fixture/경계0·위반3감점·메뉴 복귀/재시작과 기존2Player/재접속/격리 회귀를 확인했다. 사용법/요소별 범위는 21, 명령/실패 보완/배포는 이력. 시간은 입력값이며10분으로 확정하지 않는다. 봇 난도/수익 경쟁·사람/화면·다른PC·장기 교통 수용은 별도다.

확장 맵·은계형 UI·주유 시설 — 2026-10-29

사용자 지시대로 화면/UI→지도·법규 데이터→자체 시험장 확장/승객 거점→서비스 시설을 일괄 구현한 뒤 통합 검사를 실행했다. 기존 지도 반입이 아니라 PVP 외곽1,760m·전체520×440m 확장이다. 23번 요소별 표/사용법, 실제 실패·수정·검증 이력을 최신 기준으로 따른다. 합류 접근로도 같은 신호 사건으로 연결했고 주유 비용은 위반과 분리한다. 제품 경기 시간·배점/교통량/서비스 후보의 최종 확정이나 사람/다른PC 전체 수용으로 표시하지 않는다.
