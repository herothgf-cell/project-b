밸런스 시험 방법

  1. 맵·교통·승객 공급 조건과 경기 설정을 기록한다.
  2. 출발 위치를 교대하거나 균등한 시작 세트를 사용해 위치 효과를 분리한다.
  3. 운임·완료 횟수·빈차 비율·위반·최종 성적을 함께 본다.
  4. 수익이 높은 전략이 조작과 판단에서 나온 것인지, 우연한 승객 공급이나 위반 이득에서 나온 것인지 구분한다.
  5. 한 번에 여러 조작·맵·배점을 바꾸지 말고 비교 이유를 기록한다.
  6. 참가 인원과 경기 시간의 최종 결정은 이 기록 이후 09에 남긴다.

감점은 “안전 운전이 항상 승리하도록” 맞추지 않는다. 큰 운임 우위가 경미한 실수에도 유지되는 경우와, 반복 위반의 추가 수익이 상쇄되는 경우를 모두 시험한다.

2026-10-27의 기획 단계에서는 제품 QA를 모두 미수행으로 두었다. 당시 문서 검증은 기획 작업 이력에 보존한다. 2026-10-29에는 설정 검증·저장 경로·로그 분리·빌드 설정 복원 코드의 독립 검사를 수행했다. 이는 QA-ISO-01의 기반 코드 증거이며, Unity 씬 로드·실제 Player·QA-BUILD-01 전체 통과는 아니다. 정확한 실행 결과와 남은 항목은 P1 작업 이력을 따른다.

재접속 증거 추가 (2026-10-29)

tools/test_pvp_reconnect.ps1은 정상 복귀·위조 거절·유예 종료·명시 퇴장·실제 패킷 차단 복구·호스트 종료를 독립 Player로 검사한다. 복귀는 같은 서버 슬롯/선택/위치와 새로운 epoch, 복귀 후 권한 차량 이동까지 확인한다. 서버 만료 정확한 경계·중복 연결·옛 epoch 거절은 Editor 모델 검사다. 실제 화면은 한글 HUD/승객 대사 확인이며 수동 운전 검사가 아니다. 검사별 결과와 미완료 수용을 근거로 사용하며 P2 전체 통과로 표시하지 않는다.

공유 경기 검증 범위

검사별 구분과 환경별 잔여를 따른다. 실제 Player 운송 검사는 서버 전용 위치 제어 fixture로 메시지/소유권/정산을 검사하며 전체 코스 물리 주행이나 사람 운전 완료를 뜻하지 않는다. 장애물 차단은 실제 authority motor step, 완료 재전송은 실제 RPC 수신 표식을 요구한다.

2026-10-29 실제 입력 주행·공유 교통 후속

최신 수용·환경별 잔여 표와 실제 검사 이력을 따른다. 위치 제어 없이 실제 모터 입력으로 운송하고 서버 NPC2대/보행1명·신호/우회전/지속 속도·방향/접촉 책임·보류를 연결했다. 이전의 해당 미구현/미검증 설명은 당시 기록이다. 다른PC·사람/화면 시야·복합 교통/금지차로 자산은 별도 수용으로 남긴다.
