촬영월과 확인일은 구분한다. 좌표·치수·신호 시간은 게임 추정이다. 이번에 전 구간을 실측하거나 이전 넓은 상류2차로 주행 경로를 재작성하지 않는다. 원본 NGII91은 좌회전 포켓 식별 번호이며 차선 수가 아니다. 명시한 원본 입력 약10~13m 구간에서만 보조 화살표/내부 흰 구분선을 그리며, 겹치는 같은 방향의 임시 표시를 대체한다. 중앙선·반대편·우회전 곡선과 통행 연결은 보존한다.

`signalHead`는 생성 신호 접근의3/4구 외형만 지정한다. 작성 신호는 기존 `vehicleSignal.type`을 사용한다. `lanePresentation`은 기존 활성 입력→활성 회전 연결→활성 출구에서 역할을 읽는다. 둘 다 시설 메타데이터이며 새로운 통행 규칙이 아니다. 지도 원본/필수 입력 SHA256은 정식 저장 후 갱신한다.

## 좌회전 대기 감지

Q/E 입력은 우선한다. 입력이 없을 때 정지선 전40m 안의 현재 차로를 확인한다. 좌회전 전용 차로는 기존 연결로, 공유 차로는 현재 유효한 내비의 바로 다음 좌회전 연결로 수요를 보완한다. 다른 축·지나친 정지선·차로 밖·끊긴 연결·비활성 출구·오래된 내비·U턴으로 추론하지 않는다. 기존 보호 신호 단계에 수요를 더하며 금지된 접근을 허용하지 않는다.

## 승객 표시·요청

- 승객 카드는 기사 선택 이후 승객 반응을 표시한다. 기사 선택 문구·응답 기록·효과 계산은 별도로 유지한다. 문장 바깥의 쌍 큰따옴표만 제거하며 문장 속 인용은 보존한다.
- 사용자 승인에 따라 주행 중에도 새 요청을 표시한다. 실제 주행20초 간격·진행도·85% 이후 제한·응답 대기 및 수면/작업/다른 선택/일시정지/모달 차단은 유지한다. 안전정차2초와 같은 실제 작업 조건은 그대로다.
- 새 기본 요청0/1/2건 비중은15/60/25. SafeStop 상대 가중치3, DestinationChange2, ViaStop2로 조정한다. 나머지 요청·프리셋·활성 여부를 보존한다. 기본 가용14종 기준 활동3종 합계는7/28이며 실제 등장률은 경로·승객별 가용성에 따라 다르다.
- 진행 중 운송의 저장된 계약/설정을 바꾸지 않는다. 새 캠페인·새 PVP 방의 기본값과 로컬 사용자 프로필의 해당6개 값만 대상이다. 기존 캠페인의 저장된 설정과 요청 슬롯은 보존하며, 주행 중 표시/새 반응 코드는 기존 캠페인에도 적용된다. 기존 가져오기용 프리셋은 작성 당시 값일 수 있다.
- 운전 점수 알림은 두 시점 모두 실제 내비 아래12배율픽셀 간격으로 배치한다.
