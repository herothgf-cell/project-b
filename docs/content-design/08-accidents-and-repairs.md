# 사고·수리 후속 기획서

작성일: 2026년 10월 16일 · 버전: 0.4 · 상태: 프로토 제외·후속 기획 초안

[로드맵](00-RoadMap.md) · [기획 총괄](README.md) · [맵·주행](06-world-map-and-driving.md)

사고가 발생했을 때 운송과 영업에 어떤 변화가 생기는지 정리한 후속 기획이다. **이번 프로토에서는 신규 사고 콘텐츠를 모두 비활성으로 두며, 아래 흐름·화면·비용을 개발 범위에 넣지 않는다.**

## 적용 범위

| 항목 | 프로토 적용 | 구분·후속 방향 |
|---|---|---|
| 기존 물리충돌 | 기존 구현 유지 | 차량 물리에서 발생하는 충돌. 신규 사고 이벤트 도입을 의미하지 않음 |
| 기존 충돌 매너 감점 | 기존 구현 사실: 조건부 -10 | 충돌 속도·접촉 조건·중복 억제에 따른 기존 점수. 사고 책임·파손 정도 판정이 아님 |
| 사고 이벤트 | 제외·기획만 | 기존 충돌을 별도 사고 흐름으로 전환하는 조건은 미정 |
| 차량 파손 | 제외·기획만 | 파손 상태·외형·운행 가능 여부를 연결하는 규칙은 미정 |
| 사고 기록·책임판정 | 제외·기획만 | 관찰 사실과 게임상 처리 판단을 분리. 실제 법적 책임·과실비율을 추정하지 않음 |
| 사고로 인한 운송 종료 | 제외·기획만 | 승객 안내·운임 처리·대체 이동은 [04 승객](04-passengers-and-reservations.md)과 후속 연계 |
| 수리비·복구비 | 제외·기획만 | 비용 항목·금액·결제 시점 모두 미정. [05 경제](05-daily-operation.md)와 후속 연계 |
| 수리 대기·영업 불가 | 제외·기획만 | 중단 시간·시간 처리·복귀 조건 미정 |
| 사고 보험청구 | 제외·기획만 | 청구 가능 조건·게임상 보전 방식·처리 시점 미정. 현실 보험금 추정 없음 |
| 보험 갱신·세금 납부일 관리 | 프로토 포함, [05](05-daily-operation.md) 담당 | 사용자가 확정한 일상 비용 관리. 사고 보험청구와 분리 |
| 개인 예약과 사고의 연계 | 제외·기획만 | 개인 예약 자체도 프로토 제외. 예약 취소·변경·신뢰 영향은 후속 검토 |

현재 물리충돌은 [TaxiController](../../unity/YeongtongTaxi/Assets/Scripts/TaxiController.cs), 충돌 매너 감점은 [DrivingManners](../../unity/YeongtongTaxi/Assets/Scripts/DrivingManners.cs)의 기존 구현을 확인했다. 이번 문서 작업은 이 코드를 변경하거나 새 사고 기능을 추가하지 않는다.

## 후속 플레이 흐름

| 단계 | 플레이어 경험 | 기록·처리 제안 | 결정할 사항 |
|---|---|---|---|
| 상황 발생 | 접촉 또는 운행 불가 상태를 인지 | 발생 전후 차량·도로·신호 상태 보존. 연속 접촉은 같은 사건인지 확인 | 이벤트 진입 조건, 단순 접촉과 처리 대상 구분 |
| 안전조치 | 주행을 멈추고 상황 안내 확인 | 조작 가능 상태·안전한 정차/복구 필요 여부 안내 | 조작 범위, 정차 불가 시 지원 방식, 안내 표현 |
| 기록·책임 확인 | 관찰된 사실과 확인되지 않은 내용을 확인 | 행동·상대 반응·도움 사용 여부 기록. 근거가 없으면 판단 보류 | 게임상 책임 처리 기준, 설명·재검토 방식 |
| 운송 종료·승객 안내 | 계속 운송 가능한지와 종료 결과를 확인 | 운송 중단 시 승객에게 이유와 이후 처리를 짧게 안내 | 운송 유지/종료 기준, 운임·매너·대체 이동 처리 |
| 수리·비용·보험 | 운행 상태와 처리 선택지를 확인 | 견적·비용 발생·결제·보전 상태를 구분해 안내 | 수리비·보험 적용·미납·처리 순서·시간 |
| 영업 복귀 | 운행 가능한 상태에서 다시 호출을 선택 | 복귀 위치·차량 상태·남은 영업시간·완료 내역 표시 | 복귀 조건, 대기 표현, 새 호출 허용 시점 |

모든 단계는 후속 설계안이다. 현재 프로토의 물리충돌을 계기로 사고 화면·수리 청구·보험 처리·추가 영업시간 손실을 발생시키지 않는다.

## 상태와 비용 표시

| 구분 | 후속 최소 정보 | 처리 원칙 |
|---|---|---|
| 사건 카드 | 상황·행동·주변 영향·판단 상태 | 사실, 추정, 보류를 구분. 충돌 여부만으로 책임 확정 금지 |
| 차량 상태 | 운행 가능 여부·수리 필요 여부 | 물리적 끼임·이탈 등 기술적 복구와 게임상 파손을 구분 |
| 운송 결과 | 진행/종료·승객 안내·운임 처리 상태 | [04](04-passengers-and-reservations.md)의 후속 규칙 확정 후 적용 |
| 비용 내역 | 발생 비용·결제·미납·보험 보전 | [05](05-daily-operation.md)와 후속 연계. 비용 발생과 지급을 중복 합산하지 않음 |
| 수리 진행 | 선택한 처리·남은 상태·복귀 가능 시점 | 수리 대기 방식은 미정. 장시간 실제 대기를 강제하지 않는 방향 |
| 보험 | 갱신 상태와 사고 청구 상태 | 프로토의 갱신 관리가 자동으로 사고 보전 기능을 제공하지 않음 |

## 재시작·복습·예외

| 상황 | 후속 처리 제안 | 프로토와의 관계 |
|---|---|---|
| 같은 충돌이 여러 번 감지됨 | 동일 사건을 식별해 비용·보상·운송 종료의 중복 처리 방지 | 기존 매너 감점의 중복 억제와 별도 설계 |
| 충돌 원인·책임이 불명확함 | 사실을 보존하고 책임 판단·해당 비용 확정 보류 | 신규 책임판정 기능은 비활성 |
| AI·맵 오류로 차량이 끼임 | 기술적 복구로 구분하고 오류 자체를 사고 책임·청구 근거로 사용하지 않음 | 기존 복귀 조작은 신규 유료 사고 복구가 아님 |
| 사고 처리 도중 종료·재시작 | 사건·운송·차량·비용을 같은 저장 기준으로 복원하거나 함께 되돌림 | 구체 저장 시점은 후속 확정. 부분 복원·중복 지급 방지 |
| 사고 장면 복습 | 실제 영업 기록과 분리된 연습 상태 사용 | 사고 복습도 프로토 제외. 후속 연습에서는 영업 비용·보험 보전을 재지급하지 않음 |
| 잔액 부족·수리 중 마감 | 비용과 영업 상태를 설명하고 다음 진행 선택 제공 | 미납·기간 목표 영향은 [05](05-daily-operation.md), [07 캠페인](07-campaign.md)과 후속 검토 |
