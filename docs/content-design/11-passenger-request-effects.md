# 승객 요청별 선택 효과와 피드백

## 2026-10-26 운임·보너스 개정안

**기획 상태: 미구현·경제 밸런스 검증 전.** 아래 안은 기존의 `M >= R` 100% / 미달 70% 기본 운임과 요구치 공통 보너스 상한을 교체한다. 현재 실행 파일의 지급 규칙은 아래 2026-10-23 구현 상태와 다르므로 기획값을 현재 지급액으로 표기하지 않는다.

### 기본 운임

- `F`는 목적지 변경·경유를 반영한 **최종 약정 운임**, `R`은 요구 만족도, `S`는 하차 시 확정한 최종 승객 만족도다. 운전 만족도 `M`은 `S`의 주행 변화에 한 번 반영하며 운임에서 두 번째 문턱으로 쓰지 않는다.
- 시간 내 정상 하차의 미달 점수 `G = max(0, R-S)`, 감액률 `d = min(0.20, 0.005 × G)`로 한다. 실제 기본 운임은 `floor((F × (1-d))/10) × 10원`이다. `S >= R`이면 감액 없이 `F`를 지급한다. 테스트용 운임은 10원 단위이며, `F`가 10원 단위가 아닌 경우 약정액 그대로 지급할지 반올림할지는 데이터 정책에서 확정한다.
- 시간 초과 후 하차는 `S`와 관계없이 기본 운임·보너스 모두 0원이다. 픽업 취소·승차 거부도 지급하지 않는다. 정당한 대기·합법적 우회에 별도 감액을 주지 않으며, 실제 관찰된 결과만 `S`에 반영한다.
- 예: `F=5,000원, R=85`에서 `S=85/81/73/45`의 기본 운임은 각각 `5,000/4,900/4,700/4,000원`이다. 마지막은 감액 상한 20%에 걸린다. 점수 차가 같으면 요구치와 무관하게 감액률이 같다.

### 보너스

- 공통 기준 상한 `C0 = min(F × 0.10, 500원)`에 요구치 가중치 `w(R)`를 곱한다. 기존 요구치 `R=60/70/85`의 가중치는 각각 `0.6/0.8/1.0`이다. 운송별 상한 `C = floor(C0 × w(R) / 10) × 10원`이다.
- 시간 내 `S < R`이면 0원, `S >= R`이면 `floor(C × [0.2 + 0.8 × (S-R)/(100-R)] / 10) × 10원`이다. 같은 점수 차를 추가로 얻어도 높은 `R`은 상한이 크고 `100-R` 구간이 짧아 보너스 상승폭이 크다. `R=100`은 현 요구치 목록에 없으므로 도입 전에 분모 예외를 정한다.
- `F=5,000원`일 때 `R=60`은 `S=60/80/100`에서 보너스 `60/180/300원`, `R=70`은 `S=70/85/100`에서 `80/240/400원`, `R=85`는 `S=85/93/100`에서 `100/310/500원`이다. 기존 85점 사례는 유지하면서 낮은 요구치의 최대액을 줄이는 시험값이다.
- 하차 결과·F8·장부에는 `F / 만족도 미달 G / 감액률·감액액 / 실제 기본 운임 / 보너스 / 합계`와 `S / R`을 표시한다. 같은 운송 ID의 정산은 한 번만 기록하고 저장·복원 후 재계산하지 않는다. 기존 완료 운송의 지급액을 소급 변경하지 않는다.

### 검토·검증 기준

두 안 중 `M` 차이에 따른 점진 감액은 기존 운전 점수의 역할을 유지하지만 승객 요청·청결·도착 보상이 기본 운임에서 빠진다. **`S-R` 차이 기준을 권장**한다. 승객이 체감한 최종 결과를 한 번만 정산에 반영하고, `M`의 급가감속·충돌 감점도 `S`를 통해 운임에 영향을 준다. 수치(0.5%/점·20% 상한·가중치)는 수동 20분·3일 경제 검증 후 조정한다. 구현 전 `S=R`, `S=R-1`, 감액 상한, 요구치별 보너스 상승, 시간 초과, 변경 약정, 저장·중복 정산을 자동 검사한다.

## 2026-10-23 만족도 표시와 실제 점수 연결 보정

- 주행 HUD와 증감 알림은 내부 운전 만족도 `M=100`을 승객 만족도로 표시하지 않는다. 현재 `S=clamp(S0+(M-100)+확정된 요청 변화,0,100)`와 요구 `R`을 표시한다. 요청 버튼 선택만으로 점수가 오르지 않는 규칙은 유지한다.
- 도착 시간 가산은 첫 유효 도착에만 더한다. 기상 대기 중에는 확정 결과를 표시하고, 저장 복원에서 다시 추첨·가산하지 않는다.
- 청결 가산은 시작 점수에 포함된다. 예: `R85-D12+청결3=시작76`. HUD는 `시작76 · 청결+3 포함`, 결과/F8은 `기본73 + 청결3 = 시작76`과 주행·요청·시간 변화를 보여준다. 이때 하차 시 청결3을 다시 더하지 않는다.
- 운행 점수는 누적 법규 사건 장부에 별도로 연결한다. 신규 결과에는 하차 시 누적 운행 점수를 저장하며 예전 결과의 없는 값은 0점으로 오표시하지 않는다.


2026-10-23 구현 상태: 새 시작 만족도·요청/주행/안전 조기 도착의 최종 만족도·공통 보너스를 구현했다. 요구 점수 도달 시에도 보너스를 지급하며, 요청 버튼 자체와 법규 점수는 직접 가산하지 않는다. 모델·위치 제어 자동 검증이며 수동 경제 밸런스는 남아 있다. 안정 주행 M 회복은 미구현이다. [검증 기록](../work-history/2026-10-23-passenger-care-connectivity.md).

## 2026-10-23 최신 기획 · 만족도와 보너스 개편 (개발 전)

이 절은 2026-10-23에 구현된 **현행 빌드 기준**이다. 기본 운임의 일괄 100%/70%와 공통 보너스 상한은 위 2026-10-26 개정안이 구현되면 교체한다.

사용자 결정: 명칭은 **보너스**다. 요청 종류에 관계없이 시간 내 정상 하차한 운송은 최종 만족도 `S`가 승객의 요구 만족도 `R`에 **도달하면** 보너스를 받는다. `S > R`일 때는 초과한 만큼 금액이 증가한다. 요청 이행은 `S`를 올리는 여러 행동 중 하나이며 보너스 지급의 별도 필수 조건이 아니다. CH04/05·EV03/04, 조용한 운행·ETA 문의, 요청을 안전상 보류한 운송도 같은 만족도 기준을 적용한다. 단, **요청에 답변하는 버튼 자체**는 만족도를 올리지 않는다.

`Tref`가 없거나 비정상적으로 짧으면 시간 가산은 0으로 두고 사유를 보인다. 조기 도착을 위한 확정된 신호·속도 위반, 충돌 등 위험 운전이 있으면 **시간 가산만 0**으로 한다. 이것은 법규 성향 점수를 승객 만족도로 복사하는 것이 아니라 위험한 운전으로 시간을 단축한 보상을 막는 조건이다. 신호 대기·교통 정체·합법적 우회는 시간 가산이 없을 수 있지만 추가 만족도 감점이나 요청 미이행을 자동 만들지 않는다. ETA 문의에서 운전자가 안내한 시각은 대화 결과로 별도 기록하고, `Tref`를 유리하게 다시 설정하지 않는다.

| 하차 조건 | 기본 운임 | 보너스 |
|---|---:|---:|
| 시간 내 정상 하차, `S >= R` | 현행 주행 운전 만족도 `M` 기준 100% 또는 70% | 아래 산식으로 1회 지급 |
| 시간 내 정상 하차, `S < R` | 현행 주행 운전 만족도 `M` 기준 100% 또는 70% | 0원 |
| 운송 제한시간 초과 후 하차 | 0원 | 0원 |

시작 만족도의 무작위 차이만으로 기본 운임을 깎으면 운전자에게 불공정하므로 **기본 운임의 현행 `M` 기준 100%/70%/시간 초과 0원은 유지**한다. 보너스는 별도 만족도 `S`로 평가하며, 기본 운임 지급률이 70%여도 `S>=R`이면 보너스 대상이다. 이 경우 결과에 두 판정의 근거를 각각 표시한다.

보너스 상한 `C = min(최종 약정 운임의 10%, 500원)`을 모든 운송에 공통 적용한다. `S = R`이면 `C`의 20%를 최소 보너스로, `S > R`이면 `C × [0.2 + 0.8 × (S-R)/(100-R)]`를 10원 단위 내림 지급한다. `S=100`은 `C` 전액이다. 예를 들어 최종 약정 5,000원·`R=85`·`S=85`이면 **100원**, `S=93`이면 **310원**, `S=100`이면 **500원**이다. `R=100` 같은 신규 요구치는 분모 예외를 별도 정의하기 전까지 사용하지 않는다. 금액·무작위 범위·시간 계수는 플레이 테스트용 제안값이다.

하차 결과·F8·장부는 `최종 약정 운임 / 실제 기본 운임 / 보너스 / 합계`와 `S0 + Δdrive + Δrequest + Δtime = S`, `R`, 도착 비교를 함께 표시한다. 목적지 변경·경유의 추가 거리 약정은 기본 운임에 먼저 반영하며 보너스는 그 최종 약정에서 한 번만 계산한다. 운송 ID로 중복 정산을 막고 저장·복원에도 동일한 추첨값과 결과를 유지한다. **이 절은 2026-10-22 보너스 산식·범주별 제외를 대체해 현재 빌드에 적용됐다. 위 2026-10-26 운임·보너스 개정안은 아직 미구현이다.**

## 이전 구현 · 하차 만족도와 감사 보너스 (신규 산식으로 교체 예정)

**수정안:** 하차 때 기존 운송 운전 만족도 점수 `M`에 요청 이행 결과 `Δ`를 반영해 `최종 만족도 S = clamp(M + Δ, 0, 100)`을 계산한다. 호출에 표시되는 승객의 **요구 점수 `R`(60·70·85점)**를 얼마나 넘었는지에 따라 보너스가 달라진다. 한 운송에 핵심 요청이 하나라서 `Δ`는 한 번만 적용한다. 기본 운임의 100%/70%/0원 판정은 기존 `M`과 운송 기한을 그대로 쓰며, `S`는 하차 피드백과 보너스 계산에만 사용한다. 100점에서 긍정 변화가 상한에 걸려도 결과에는 `요청 이행 +8점, 최종 100점`처럼 변화량을 표시한다. 수치는 테스트 초깃값이다.

| 요청 범주 | 이행·좋은 응대 `Δ` | 수락했으나 미이행·응답 기회 무시 `Δ` | 안전상 보류·불가·관찰 불명 `Δ` | 감사 보너스 상한 |
|---|---:|---:|---:|---:|
| DR 운전 방식 | +8 | -10 | 0 | 최종 약정 운임의 10%, 최대 500원 |
| CH 대화·편의 | +5 | -5 | 0 | 최종 약정 운임의 5%, 최대 300원 |
| EV 변경·사건 | +6 | -8 | 0 | 최종 약정 운임의 8%, 최대 400원 |

`초과 점수 E = max(0, S - R)`, `보너스 비율 = E / (100 - R)`로 계산한다. **실제 보너스 = 10원 단위 내림(범주별 상한액 × 보너스 비율)**이다. 목적지 변경·경유로 운임을 다시 약정했다면 상한액에는 최종 확정 운임을 쓴다. 정확히 요구 점수에 도달하면 0원, 최종 만족도 100점이면 범주별 상한액이다. 기존 제안의 큰 증가값(+20 등)은 요구 점수 85점 운송을 대부분 즉시 100점으로 만들어 차등 보너스가 사라지므로, 위 표의 증가·감소 폭을 작은 테스트 값으로 조정했다. 예를 들어 최종 약정 운임 5,000원·요구 점수 85점·DR 상한액 500원일 때, 기존 운전 만족도 점수 85점에서 DR 요청 이행 +8점이면 최종 만족도 93점·초과 8/15점이므로 **260원**이다. 최종 만족도 100점이면 **500원**이다.

`실제 지급 기본 운임 100% + 요청 결과 긍정(Δ>0) + 확정된 법규 위반 없음 + 시간 내 하차`가 모두 충족되어야 1회 지급한다. 요구 점수 미달로 기본 운임 70%를 받거나 시간 초과로 0원을 받으면 최종 만족도 `S`가 높아도 보너스가 없다. 약정 운임·미터 표시를 수정하지 않고 결과 화면과 장부에 `기본 운임 / 최종 만족도 M+Δ / 요구 점수 R / 초과 점수 E / 감사 보너스 / 합계`로 따로 기록한다. 결과·하루 순수익·저장 복원에도 같은 금액을 한 번만 반영한다. 선택 버튼을 누르기만 하거나 요청을 안전하게 거절한 경우는 보너스 0원이다.

한국관광공사는 국내 택시의 대다수가 미터기로 요금을 받고 팁을 요구하지 않는다고 [안내한다](https://english.visitkorea.or.kr/svc/contents/contentsView.do?menuSn=477&vcontsId=140661). 따라서 이 보상은 실제 택시 요금 제도나 필수 팁을 재현한다는 뜻이 아니라 **게임 안의 선택적 감사 보너스**다. [서울시 요금 안내](https://sftc.seoul.go.kr/seoul/mulga/main/contents.do?menuNo=200023)의 미터 요금과 혼동되지 않도록 이름과 결산 항목을 분리한다.

| 언제쯤 도착할까요 | `내비 예상보다 조금 빠르게` / `내비 예상 시간에 맞춰` / `내비보다 조금 여유롭게` → 현재 ETA와 선택한 예상 도착 시각을 함께 표시 | 선택 시점의 ETA를 기준으로 안내 목표를 기록. 주행 중 ETA가 바뀌면 남은 예상 시간과 최초 안내 시각을 구분하여 표시 | 실제 도착 시각과 최초 안내 시각 차이를 `예상보다 빠름/예상 범위/늦어짐`으로 표시. 늦어진 이유가 합법적 대기·우회면 함께 설명 | 현재는 단일 ETA 안내·감점0, 3선택지·비교 기록 신규 |

ETA 세 선택지는 제안 초깃값으로 각각 `현재 ETA - min(30초, ETA의 10%)`, `현재 ETA`, `현재 ETA + min(30초, ETA의 10%)`를 안내 시각으로 쓴다. 예를 들어 내비 ETA가 4분이면 `약 3분 36초 / 약 4분 / 약 4분 24초`다. 화면에는 “교통에 따라 달라질 수 있는 예상”이라고 명시한다. 빠른 선택을 눌러도 차량 성능·내비 경로·운송 기한은 바뀌지 않는다. 실제 도착이 안내 시각보다 15초 넘게 빠르면 `예상보다 빠름`, ±15초면 `예상 범위`, 15초 넘게 늦으면 `늦어짐`으로 표시한다. **예상 미달 자체로 운전 만족도 감점이나 법규 위반을 만들지 않는다**. 기존 운송 시간 초과는 별도로 지급 0원 처리한다. 선택 직후의 ETA가 계산되지 않으면 세 선택지를 열지 않고 `현재 경로를 확인한 뒤 안내할게요`로 보류한다.

## 운전 방식 DR01~05

| 요청 | 선택지와 즉시 피드백 | 운행 중 효과 | 하차 후 피드백 | 현재/추가 |
|---|---|---|---|---|
| DR01 차멀미·승차감 | `부드럽게 모시겠습니다` / 안전상 보류 → `급가속·급제동에 더 민감한 승객` 표시 | 수락 뒤 **불필요한** 급가속·급제동의 승객 운전 만족도 감점을 현행 각 -2점에서 각 -4점으로 변경. 같은 사건에 기본 -2점을 더해 -6점으로 처리하지 않음. 위험 회피 제동 예외·충돌 감점은 기존대로 | 각 급가속/급제동 횟수와 감점, 필요한 제동으로 제외한 횟수를 구분. 이벤트가 없으면 `편안한 운행` | 기존은 이벤트 횟수 관찰·결과만 제공, 조건부 감점 강화 신규 |
| DR02 제시간 도착 | `규칙을 지키며 가겠습니다` / 안전상 보류 → 기존 운송 기한 재표시 | 빠른 내비 경로 제안은 가능하지만 위반·위험 운전으로 보너스를 받을 수 없음. 기한과 법규 사건을 관찰 | 남은 기한·위반 건수·정시 여부. 신호 대기로 늦은 코스는 별도 밸런스 문제로 기록 | 기존 목표/결과 유지, 진행 중 기한·안전 안내 강화 |
| DR03 큰길 선호 | `가능한 큰길로 안내` / 안전상 보류 → 변경 전후 거리·ETA 표시 | 큰길 후보가 있는 경우에만 내비 큰길 우선. 실제 큰길 비율 측정 | 안내 비율과 실제 비율, 15%포인트 허용 오차, 불가 이유. 합법적 우회로 목표 미달은 추가 감점 없음 | 기존 경로·비율 판정 유지, 선택 직후 비교 보완 |
| DR04 짧은 길 선호 | `주행 가능한 짧은 길로 안내` / 안전상 보류 → 변경 전후 거리·ETA 표시 | 합법·연결 가능한 도로의 짧은 경로 적용. 실제 이동 거리 측정 | 안내 거리 대비 실제 거리와 참고 기준(125%+30m), 우회 사유. 별도 운전 만족도 감점 없음 | 기존 경로·거리 판정 유지, 선택 직후 비교 보완 |
| DR05 안전한 하차 | `가까운 안전 지점으로 변경` / `원래 목적지 유지` → 후보 위치·추가 거리·새 약정/기한 미리 보기 | 수락한 안전 승하차 지점으로 목적지·내비 변경. 아무 곳에서나 하차 허용하지 않음 | 제안한 지점과 실제 하차 지점·변경 운임을 한 운송 결과에 표시. 후보가 없으면 원래 운행 유지 | 기존 목적지 변경 유지, 미리 보기·결과 이유 보완 |

DR01 감점 초깃값은 현재 `DrivingManners` 코드의 실제 급가속·급제동 -2점 기준이다. 04 문서 감점표도 이번 기획 작업에서 코드 기준으로 정정했다. 동일 물리 사건을 요청 평가와 기본 운전 만족도에서 두 번 차감하지 않는다. 수락 전에 발생한 사건에는 강화 감점을 소급 적용하지 않는다. 감점 강화만으로 법규 성향 점수를 바꾸지 않는다.

예를 들어 DR01을 수락한 뒤 불필요한 급제동이 한 번 발생하면 기존 -2점 대신 -4점과 `차멀미 배려 요청 중 급제동`을 표시한다. 보행자를 피하기 위한 필요한 제동으로 판정되면 해당 급제동 감점은 0점이며 승객 요청 실패로도 세지 않는다.

## 개발·검증 분리

| 우선 | 구현할 것 | 확인할 것 |
|---|---|---|
| 1 | 기본 ETA 3선택지·선택 시각과 실제 도착 비교, DR01 조건부 감점 | 교통 지연·시간 초과·필요한 급제동·동일 사건 1회 차감 |
| 2 | 기존 DR/CH/EV의 선택 직후·하차 후 설명을 공통 형식으로 정리 | 경로/목적지/운임이 실제로 바뀌는 요청과 대사 전용 요청을 정확히 구분 |
| 3 | 조용한 선택 후속 대사 억제, 요청별 판정 불가 이유 | 안전상 보류·응답 기회 없음·후보 경로 없음·재시작에서 결과 중복 없음 |
| 4 | DR/CH/EV 요청 만족도·조건부 감사 보너스·장부 연결 | 기본 운임 100%/70%/0원 보존, 10원 단위/상한·예외·저장 복원·하차 중복 처리 검사 |

현재 `Y/I/U` 입력과 안전 정차 판정은 유지할 수 있으나, ETA의 세 답변은 의미가 보이는 별도 선택 표시가 필요하다. 버튼 표기 방식은 현재 말풍선 UI 안에서 정하고 운전 중 긴 선택지를 띄우지 않는다. 위 내용은 기획이며 코드·빌드 적용 및 자동/수동 검증은 별도 작업이다.

## 2026-10-22 구현 판정 범위

이 절이 과거 미구현 문구보다 우선한다. ETA Y/I/O·U 보류, DR01 -4점 대체, 만족도 Δ·10원 단위 비례 보너스·종류별 제외, 하차/F8·장부/저장 연결을 구현했다. 기본 운임 100%/70%/시간 초과0원은 유지한다. 현재 내비 ETA는 분 단위이고 선택지의 차이가 보이도록 선택 예상은 소수1자리 분으로 표시한다. ETA 오차 자체 감점은 없다.

DR02/03/04 미달 중 합법적 대기·교통 우회 여부를 확정할 수 없는 경우 중립으로 기록한다. CH04/05·EV03/04는 기획대로 보너스 제외다. 음악은 실제로 바뀌었다고 표시하지 않는다. 조용한 선택은 대화 억제 상태로 기록하며 현재 추가 자동 잡담 생성 기능은 없다. 위치 제어/모델 검증과 실제 수동 플레이를 구분하고 최신 작업 이력의 결과를 따른다.
