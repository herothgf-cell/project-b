# 승객·운송·요청·운임

> 2026-11-07 후속 확장: 수면+소지품, 메스꺼움·온도 민감·젖은 우산, 조용한 약속 위반의 최신 동작은 [기획19](19-passenger-trait-expansion.md)를 우선한다. 아래 기존 수치/24종 목록은 1차 기준이며 새 기본값은 기존24+신규6=30종(활성29)이다.

현재 기준은 **승객 프리셋 + 요소 조합 + 개별값**이다. 2026-11-07 신규12명을 추가해 총24명/23명 활성으로 운영한다. 짧은길(ShortRoad)·빠른길/짧은길 추천(RouteAdvice)과 기존 경로확인 프리셋은 새 기본 배정에서 제외한다. 큰길·ETA는 유지한다. [신규 요소/밸런스표17](17-passenger-roster-v1.md), [요청/선택표07](07-passenger-dialogue.md), [개별설정16](16-passenger-preset-overrides.md), [작업 이력](../work-history/2026-11-07-passenger-roster-v1.md).

## 승객을 구성하는 요소

| 요소 | 기획 역할 | 현재 사용값 | 실제 효과 연결 |
|---|---|---|---|
| 프리셋 | 승객 정체성·제작 단위 | ID·이름·소개·사용·가중치 | 같은 조합도 다른 대사/수치 가능 |
| 대화 성향 | 대화 빈도·응대 성격 | 표준/조용함/대화 선호 | 수다 제한/대화 행동, 안전 안내 유지 |
| 신체 상태 | 운송 중 반응 조건 | 음주/졸림/승차감 민감 | 구토·기상/수면/승차감 요청 |
| 이동 목적 | 대표 요청 후보 | 급함/경유 용무/안전 하차 | ETA/정시도착·경유·장소 변경 |
| 소지품 | 작업과 오염 조건 | 큰 짐/흙 묻은 짐/음식 | 적재·보호·섭취·흘림·정리 |
| 대사/선택 | 행동 슬롯별 콘텐츠 | 승차·선택·후속·요청·상황 | 실제 주 행동/요청/사건 조건에 표시 |
| 개별값 | 공통값 일부 교체 | 확률·시간·청결·S/F 단계 효과 | 명시값 우선, 미지정 공통상속 |
| 배정 그룹 | 등장 빈도/한도 호환 | 일반·음주·기존 특수 그룹 | 행동은 그룹명이 아니라 실제 특성으로 결정 |
| 운송 상태 | 플레이 중 변하는 값 | 선택완료·수면·적재남은시간·구토예정 | 저장/복원·중복효과 방지 |

기존12프리셋은 기본 행동 자료로 보존하고 신규12명의 조합은17의 요소별 표를 따른다. 새 승객은 유형 코드를 늘리지 않고 기존 특성·대사·개별값을 조합한다. 음주+졸림, 수면+소지품, 대표요청2개 등 지원하지 않는 조합은 검증에서 차단한다. 새 행동/사건 종류는 별도 구현이 필요하다.

공통 선택 효과는 [밸런스 v1](../passenger-balance-v1.md)을 유지하고, 현재 등장 비중·신규 승객별 수치는17이 우선한다. 진행 중 운송과 사용자 프로필은 당시 구성/수치를 보존한다. 아래 역사적 행동 모듈 표의 수치는 **공통값**이며 신규 개별값이 있으면 그 값을 쓴다.

본문은 기존 싱글 기준이다. PVP는 유형·요청·운임 공통 로직을 재사용하며, 도시 수요·공용8호출/별도길가3명·공유점유·봇 응대는 [PVP 전용 적용표28](pvp/28-passenger-parity.md)을 따른다. 싱글 규칙·저장 체계는 유지한다.

## 선택지별 단계 효과 설정

요청·유형·상황의71개 답변은schema2 프로필에서 각각 **즉시 / 운행 중 / 운송 종료** 효과를 독립 소유한다. 현재 기본 수치는 위 밸런스 v1을, 사용자 프로필은 실제 선택한 답변 값을 따른다. General 유형과 하차 후 LostItem은 효과 선택지 목록에서 제외한다. [구현 기준](../superpowers/specs/2026-11-06-independent-choice-effects.md), [편집·이관 안내](../content-tuning-tool-guide.md)를 따른다.

- 즉시/종료 S·피로는 점과 적용 직전 현재값 대비%를 더한다. 승차 전 선택은 실제 승차 확정 때 즉시1회 적용한다.
- 운행 중 S·피로는 점/분과 활성화 기준값 대비%/분을 더한다. 활성화 기준값은 즉시 효과 적용 뒤 고정해 저장하며 정상 운송의 영업시간에 비례한다. 자연 피로 증가율 추가%와 급가감속 M 감점 추가점도 답변별로 설정한다.
- 요청 종료 S만 각−100~100으로 제한한 소수 기여를 합산·반올림한 뒤 기존 `common.requestCap`을 적용한다. 즉시/운행 중/유형·상황 종료 S는 이 상한 밖이며 최종 S·피로는0~100이다.
schema2에서는 `choice.*`의 단계별 효과가 현재 선택 값을 담당한다. 프리셋에 남은 구 `request.*.success/failure`는 이관/기존 방식과 구별하며 새 효과값으로 잘못 읽지 않는다.

- 0은 추가 효과 없음이다. 기존 자연 피로·경로·안전 판정·물리 작업은 유지한다. 취소·운송 중단에는 종료 효과를 지급하지 않고, 도착 확정·취소·메뉴 일시정지 뒤에는 운행 중 효과를 진행하지 않는다. ETA 세 답변·공감 두 수락 답변도 서로 독립적이다.
- 음식 즉시 효과와 Comfort의 M 추가값은 새 장부에서만 적용해 구전용 분기와 중복하지 않는다. schema1 운행 저장은 기존 방식으로 끝내며 새 캠페인/방부터 새 설정을 적용한다. LAN은 호스트 장부를 복제하며 [현재 호환 계약](pvp/30-native-lan.md)을 따른다.

## 호출에서 하차까지

| 단계 | 플레이어 행동 | 결과 | 예외 |
|---|---|---|---|
| 호출 탐색 | 출발·도착·예상 운임과 경로 확인 | 선택만으로 배차하지 않음 | 탑승 후 요청을 호출 목록에 미리 공개하지 않음 |
| 수락 | 별도 수락 확정 | 승차 목표·픽업 기한 부여 | 픽업 기한은 max(150, 실제 접근거리m/3+150)초 |
| 길가 승차 | 실제 대기자에게 접근해 정차·F | 호출 목록 없이 승차 시도 | 보이지 않는 손님을 태울 수 없음 |
| 픽업 | 올바른 차로 방향·연석·저속 정차 후 F | 승차·시작 만족도·요구치·약정 확정 | 청결/졸음/점유/기한 조건 충족 필요 |
| 운송 | 목적지 안내에 따라 운전·요청 대응 | 실제 주행·응대·시간을 경험 | 중간 경유 정차와 최종 하차 구분 |
| 하차 | 지정 지점 방향·저속 정차 후 F | 만족도·운임 결과 확정 | 동일 운송 한 번 정산 |
| 운송 기한 초과 | 목적지까지 계속 운송 | 하차 뒤 기본 운임·보너스0원 | 비용은 유지, 도중 승객을 없애지 않음 |

도로 교통 상황은 통상 운송 동선에서 만나는 관찰 구역이다. 상황 통과/평가 완료를 승차·하차 조건 또는 강제 경유지로 사용하지 않는다. 승객이 명시적으로 수락한 목적지 변경·EV02 용무 경유와 구분한다. 대기 승객은 보도에 배치하고 택시 정차 칸은 도로 방향에 맞춘다.

승하차 장소는 기존12곳과 게임용 정차공간12곳, 총24후보다. 가용 호출은 일반2개와 대표 코스1개를 섞어 제공한다. 모든 장소에 항상 손님이 있지는 않으며, 보이는 대기자는 갱신 중 갑자기 눈앞에 생기거나 사라지지 않게 한다. 사용한 빈 하차지는90초간 신규 대기·호출을 쉬고, 이미 있던 대기자는 유지한다.

## 승하차 공간이 막혔을 때

| 조건·선택 | 결과 | 시간·평가 영향 |
|---|---|---|
| 일반 게임용 정차공간 일시 점유 | 임시 정차 차량이 원래 공간을 사용 | 눈앞 갑작스러운 출현·차량/승객 겹침 방지 |
| 현재 목표가 점유됨 | 원래 위치를 유지하고 안전하게 대기 | 같은 호출/운송 유지, 점유를 이유로 임의 취소하지 않음 |
| 대기 해소 | 30초 뒤 앞이 비면 차량이1.5m/s로7m 이동 | 앞이 막히면 더 기다림, 정확히30초 해소 보장 아님 |
| 강제 지연 보호 | 잔여 대기+이동 예상+10초, 최대90초를 사건당 한 번 기한 보정 | 탑승 중 시스템 강제 대기는 ETA/경로 요청 미이행으로 감점하지 않음 |
| 다른 장소 선택 | 작성·검증된 대체 포켓이 있을 때만 제안·동의 후 변경 | 현재 작성 쌍은 아래 P1·P2 항목. 대안이 없으면 원래 장소에서 대기 |

영업시간·연료는 계속 소모되며 추가 운임 할증은 없다. 대기 버튼 반복이나 이어하기로 보호 시간을 중복 적립하지 않는다. 고정 코스·생활시설은 이 일반 정차공간 점유와 구분한다.

## 승객의 시간 난도

| 성향 | 탑승 후 기한 | 의도 |
|---|---|---|
| 여유 | ceil(max(90, 안전 ETA×1.75+상황 대기+45))초 | 안정 운전·응대 여유 |
| 보통 | ceil(max(90, 안전 ETA×1.45+상황 대기+45))초 | 표준적인 영업 판단 |
| 급함 | ceil(max(90, 안전 ETA×1.20+상황 대기+45))초 | 같은 길에서도 시간 관리 필요 |

난도·요청은 같은 손님을 다시 수락하거나 이어하기했다고 바뀌지 않는다. 신호를 무시해야만 달성하는 조건을 의도하지 않는다. 목적지·경유 변경 때는 같은 난도를 유지하고 필요한 추가 시간/약정을 먼저 알린다.

## 요청의 발생과 선택

| 조건 | 처리 | 플레이 영향 |
|---|---|---|
| 한 운송 | 요청0/1/2건을25/60/15% 비중으로 배정 | 요청 없는 조용한 운송도 존재 |
| 등장 시점 | 승차 또는 운행 중 안전 정차 | 주행 중 응답 강요 없음, 한 번에 대화 하나 |
| 운행 중 요청 | 진행률25~65%의 시점 이후, 실제 주행20초 이상과 별개 안전 정차 기회 | 급정지·정차 반복으로 요청을 다시 뽑지 않음 |
| 하차 접근 | 진행률85% 또는 유효 도착 이후 새 요청 종료 | 제시할 기회 없던 요청은 미발생 중립 |
| 충돌하는 약속 | 큰길/짧은 길·추천·목적지·경유·안전 하차 등 경로형은 최대1개 | 서로 양립할 수 없는 지시를 동시에 주지 않음 |
| 안전상 보류·정당한 거절·후보 없음 | 중립 | 대답 버튼만으로 운전 점수 가감 없음 |

표시된 대화에는 운행 중에도 응답할 수 있다. 새 운행 중 요청의 발생 시점·미응답 불이익의 정차 기회 판정과 실제 준비/재고정/용무 작업은 기존 안전 정차 조건을 유지한다. 안전한 실제 작업은 속도0.1m/s 이하2초·교차로/횡단보도 밖 조건에서 진행한다. 요청 응답은 영업 시계를 멈추는 수단이 아니다.

## 현재 요청14종과 하차 후 사건1종의 행동과 결과

아래 표는 실제 행동·약정·예외를 정의한다. 즉시/운행 중/종료 효과와 미응답 수치는 [밸런스 v1](../passenger-balance-v1.md), 성공/실패·판정 불가는 [실제 판정표](../content-tuning-request-outcomes.md)를 따른다. 종료 요청 합계 상한과 다른 효과의 경계는 위 단계 효과 규칙을 따른다.

| 요청 | 선택·행동 | 결과·영향 | 예외 |
|---|---|---|---|
| 조용한 운행 | 조용한 응대/보류 | 불필요한 후속 수다 억제·종료 효과 | 안전한 응답 기회를 무시하면 현재 프로필의 미응답 M 감점, 요청에서 중복 감점 없음 |
| 도착 시간 문의 | 조금 빠르게/내비대로/여유 예상 | 안내와 실제 도착 비교 설명·선택별 즉시 효과 | 기한·차량 성능 변경 없음 |
| DR01 차멀미 | 부드러운 운전 약속·실제 승차감 유지 | 수락 뒤 급가감속 강화 평가, 하차 때 전체 목표 평가 | 개별 주행 배점은 [주행 평가](01-driving-and-traffic.md#행동별-평가), 필요한 제동 제외 |
| DR02 정시 도착 | 법규를 지키며 기한 내 운송 | 기한·실제 위반 관찰 | 재촉으로 약정 기한을 줄이지 않음 |
| DR03 큰길 | 큰길 우선 경로 이행 | 실제 큰길 비율, 안내 대비15%p 여유 | 합법 우회/관찰 부족은 중립 |
| DR05 안전 하차 | 제안된 안전 목적지 확인·변경 | 실제 지정 장소 하차 | 후보 없으면 원래 목적지 유지 |
| CH01 고민 이야기 | 공감/조용한 배려 | 선택에 맞는 응대 | 조용히 배려해도 정상 응대 |
| CH03 면접 응원 | 격려/조용한 준비 배려 | 응대 반응 | 실제 면접 결과·합격 보상 없음 |
| CH04 음악 | 가능한 범위 안내 | 텍스트 응대 | 실제 음악 재생/변경 없음 |
| CH05 요금 부족 | 약정 안내/하차 때 결제 확인 | 요금 규칙 설명 | 대화만으로 할인·추가 부채 생성 없음 |
| CH06 지역 대화 | 지역 응답/안전 운행 안내 | 짧은 대화 | 검증되지 않은 지역 사실 보장 없음 |
| EV01 목적지 변경 | 새 목적지·운임·기한 확인 후 변경 | 같은 운송의 최종 목적지 변경 | 다른 운송을 중복 생성하지 않음 |
| EV02 중간 경유 | 안전 경유 확인·F 정차·원래 목적지 복귀 | 같은 운송의 경유 목표 | 경유 중에도 시간 흐름 |
| EV03 분실물 | 하차 뒤 보관/신고·전달 절차 안내 | 텍스트 후속 사건, 요청 변화0 | 운행 중 요청 수에 미포함, 원래 운임 소급 변경/반환 퀘스트 없음 |
| EV04 불법 요구 | 안전 거절/정차 후 설명 | 안전 거절의 선택 효과 | 불법 수락 선택 없음, 실제 위반은 별도 관찰 |

ETA 안내는 현재 예상시간 ±min(30초, ETA의10%) 또는 그대로다. 실제 도착과15초 이내 차이는 예상 범위로 설명하며 ETA 오차만으로 감점하지 않는다. CH01/03/06의 미응답 감점도 현재 프로필 기준이며 안전한 응답 기회가 없었으면 중립이다.

제외 보관: DR04 ShortRoad 및 CH02 RouteAdvice는 기본 enabled=false/weight0. 구 저장/사용자 프로필 호환용 코드·대사는 남기지만 새 기본 운송에서 추첨하지 않는다.

## 운임과 보너스

F는 목적지·경유 변경을 반영한 최종 원약정, A는 승차 시 운전 점수로 보정한 약정이다. 모든 floor10은10원 단위 내림이다.

| 조건 | 기본 지급 | 보너스·예외 |
|---|---|---|
| 운전 점수0~70 | 보정률0.9+0.1×점수/70 | 점수는 승차 때 고정 |
| 운전 점수70~100 | 보정률1+0.1×(점수−70)/30 | A=floor10(F×보정률) |
| 기한 내 S≥R | A 전액 | 아래 만족도 보너스 지급 |
| 기한 내 0<S<R | floor10(min(F,A)×S/R) | 보너스0, 만족도 미달에 양의 운임 할증 미적용 |
| S=0 또는 도착 기한 초과 | 0원 | 기본 운임·보너스 모두0 |
| 승차 전 취소·거부 | 지급 없음 | 완료 운송처럼 계산하지 않음 |

보너스 상한 C=floor10(min(F×10%,500원)×가중치), R=60/70/85의 가중치는0.8/1.0/1.3이다. 보너스는 floor10(C×[0.2+0.8×(S−R)/(100−R)])이다. 예를 들어 F=5,000원·R=70에서 S=70/85/100이면 보너스100/300/500원이다. 대화 버튼의 선택이나 요청 종류만으로 이 공통 보너스를 막거나 보장하지 않는다.

## 재사용 행동 모듈과 구 저장 호환

2026-10-29 일반 승객과11개 특수 유형의 구현을 반영했다. 준비 작업·음식 섭취/흘림·저장과 응대 흐름을 포함한다. BuildHybrid·Player 기능/새 프로세스 복원 검증을 통과했으며 화면·배포의 완료 증거와 남은 검증은 [작업 이력](../work-history/2026-10-29-passenger-types-implementation.md)에서 확인한다. 아래 수치는 체감 검증 전 시험값이다. 구형 저장의 진행 중 운송은 기존 유형·요청·취객 동작을 유지하며 새 유형으로 재추첨하지 않는다.

### 유형·요청·사건의 구분

| 구분 | 의미 | 예시·관계 |
|---|---|---|
| 승객 프리셋·특성 | 이번 운송의 특징과 반응 구성 | 현재24프리셋(23활성)과 지원 특성 조합. 기존 유형은 행동 모듈/배정 호환용 |
| 개별 요청 | 승객이 제시하고 플레이어가 응답하는 구체적 요구 | 조용한 운행·부드러운 운전·경유. 기존 요청0~2개 안에 배정 |
| 운송 중 사건 | 답변·운전·상태·진행에 따라 발생하는 변화 | 구토 예고·약속한 경유 도착·짐 하역. 유형 자체와 별개 발생 여부 |
| 응대 방식 | 플레이어가 고른 대화 방식 | 짧게 설명·공감·집중 안내. 별도 승객 유형을 하나 더 붙이지 않음 |

취객은 ‘진상’의 하위 분류로 고정하지 않는다. 취한 손님도 협조적일 수 있다. 초기 구현은 주 유형 하나였으며, 현재는15의 제한된 특성 조합으로 확장한다. 음주+조용함+짐+경유 같은 조합을 허용하되, 수면+소지품 등 독립 진행기가 필요한 조합과 대표 요청 중복은 검증에서 차단한다. 일반 배정 그룹은 특성 없음/조용함만 허용해 쉬는 운송을 보존한다.

### 구현 유형: 실제 운행·상태에 미치는 영향

일반 승객은 유형 선택창 없이 기존 요청을 이용한다. 아래11개는 기존 행동 모듈이다. 경로확인은 현재 기본 구성에서 비활성이다. 기본 변주는 기존 고정 시드를 유지하며 새 프리셋은15의 조합 규칙을 따른다. 취객/수면은 공통 기상 절차, 승차감/재촉/경로/경유/정밀 하차는 대표 요청, 짐/오염 짐/음식은 작업·청결 사건에 연결한다. 정밀 하차는 기존 검증된 SafeStop 후보만 사용한다. 특성 배정만으로 돈·청결·내구도를 차감하지 않는다.

| 유형 | 변주 수 | 실제 행동·조건 | 운행·차량 영향 |
|---|---:|---|---|
| 취객 | 3 | 취중 대사·구토 예고·기존 구토/잠듦 사건 | 구토 오염과 세차 전 호출 잠금, 기상 절차 |
| 잠자는 승객 | 4 | 이동 중 잠듦·도착 후 깨우기·조건부 재응답 | 미응답 요청 중립 보류, 기상 대기·첫 도착 운임 유지 |
| 승차감 민감형 | 3 | DR01 요청에 실제 응답·운전 관찰 | 기존 주행/요청 평가에 반영, 중복 감점 없음 |
| 재촉·불만형 | 3 | ETA/DR02 요청·진행과 답변에 대한 반응 | 기존 시간/요청 평가, 위험 운전 강요 보상 없음 |

| 짐 많은형 | 3 | 안전 정차 적재10초·하역10초 | 영업시간 경과·하역 뒤 다음 호출 |

### 같은 유형 안의 대화·행동 변주

**유형1개가 고정 대본1개를 뜻하지 않는다.** 같은 운행 영향이라도 소개 방식·발생 시점·이전 답변·실제 운전·하차 반응이 달라진다. 각 유형은 기본 흐름과 변주를 두되, 문장만 무작위로 바꿔 앞뒤가 모순되지 않게 한다. 운송마다 주 유형1개와 기본 변주1개를 고정하고, 그 안에서 실제 사건/응답에 따라 분기한다. 변주와 현재 단계도 저장한다. 모든 변주를 한 운송에서 차례로 재생하지 않는다.

유형의 **공통 확인 / 집중 안내**는 실제 버튼 “짧게 확인하고 설명” / “운전에 집중하며 조용히 안내”다. DR·CH·EV 대표 요청의 수락·거절은 별도 기존 선택창에서 처리하며 유형 버튼만으로 약정하지 않는다. 보통 유형은 첫 선택1회, 얕은 잠만 조건부 추가 선택1회를 제공한다. 대표 요청이 없는 유형의 공통 하차 반응은 확인한 변주를 기억한 감사 / 조용한 배려에 감사 / 미응답이면 안전 도착 인사다. 대표 요청 유형은 아래 요청 상태·결과 반응을 사용한다.

승차감·재촉·경로 확인·경유·정밀 하차는 대표 요청의 미제시/답변 대기/수락/안전 보류/성공/중립/미달 상태와 실제 답변 문구를 저장한다. 수락 뒤 후속은 실제 답변 확인에 아래 변주 반응을 덧붙인다. 미제시·답변 대기에는 약속하지 않았음을, 보류에는 원래 운행 유지를 알리며 합의를 꾸며내지 않는다. 하차 때는 실제 요청 평가에 따라 이행 감사/미달 확인/중립 확인/보류 유지로 반응한다. 아래 표의 “요청 결과 반응”은 이 공통 처리를 뜻하고 추가 점수를 만들지 않는다.

후속 유형 대사는 저장한 응답·이동시간·진행과 현재 주행 점수 M을 사용한다. 승차감 및 흔들리는 짐의 안심/불편 분기는 M≥90 기준이며 개별 코너·신호·분기점 이벤트를 별도 검출하지 않는다. 실제 운전·경로 이행은 기존 대표 요청 관찰·평가가 담당한다. 얕은 잠 질문은 한 번만 가능하며 수면 전환과 후속은 진행85% 이전에만 발생한다.

| 지역 질문 | 동네 이야기가 궁금하다는 말 | 공통 확인 / 집중 안내 | 확인하면 이야기한 동네를 창밖으로 본다는 반응, 집중 안내면 억제 | 공통 감사. 실제 지역 지식 답변·경로 변경 없음 |
| 반복 질문 | 앞서 물었던 내용 재확인 | 공통 확인 / 집중 안내 | 확인하면 앞 답변이 생각난다는 반응, 집중 안내면 종료. 새 후속 선택창 없음 | 공통 감사. 반복 자체 감점·보상 없음 |

### 구현 범위 선택 이유

기존 요청을 이용하는 운송 반응에 준비·청결 사건을 더해11개 유형을 구현했다. 임의 좌표의 정밀 하차는 제외하고, 작성된 대체 쌍과 합의한 용무 대기는 아래 P1·P2 범위를 따른다. 좋은 응대에는 안심·감사·원활한 하차로 반응하며 직접 현금 보너스 산식이나 임의 수리비를 붙이지 않는다. 음식 허용의 응대 효과는 선택 효과 기준을 따른다.

### 상태 영향형의 공통 사건 정책

| 유형 | 발동·사전 선택 | 결과·회복 | 수치·중복 규칙 |
|---|---|---|---|
| 짐 많은형 | 승차 직전 적재 안내, 정차 확인 후 작업 | 적재/하역 중 영업시간 경과. 하역 뒤 새 호출, 운임은 첫 유효 도착 기준 | 적재10초·하역10초 시험값. 적재는 승차 준비에서 운송 기한 시작 전, 픽업 기한은 작업 시작 때 확정. 버튼 반복/재개로 시간 중복 소모 금지 |
| 오염 가능 짐형 | 적재 전에 보호 깔개 사용 / 그대로 싣기 | 보호는 준비시간 추가, 실제 오염은 하차 때 청결 반영·세차로 복구 | 보호10초·추가 오염0, 미보호 하차 추가 청결-5 시험값. 기존 일반 하차-2와 별도1회. 물품/보호 선택을 확정·저장한 뒤 적용 |
| 음식·음료 소지형 | 소지 단서 뒤 안전 정차에서 밀봉 보관 요청 / 섭취 허용 / 정차 후 정리. 허용 선택 전 청결 위험 안내 | 밀봉은 추가 오염0, 정리는 안전 작업10초 뒤 추가 오염0. 섭취 허용 선택 확정 즉시 프로필의 만족도 효과(최대100), 저장/반복 응답으로 중복 가산 없음. 허용 뒤 아래 P1·P2의 실제 이동 조건으로 섭취가 발생하면 청결-2, 미리 고정된25% 흘림 사건이 발생하면 추가-6 | 일반 하차-2와 별도, 섭취/흘림 각1회. 음식 부스러기·음료 자국을 같은 섭취 흔적 정책으로 처리. 미응답/안전 응답 기회 없음은 섭취 불허·추가 오염0. 짧은 운송에서 섭취 사건이 발생하지 않아도 허용 응대의 즉시 효과는 유지하며 추가 청결 차감만0이다. 운전 방식에 따른 흘림 확률 배수 없음 |
| 용무·경유형 확장 | 기존 경유에 더해 ‘정차 뒤 용무 대기’ 조건과 약정 먼저 안내 | 대기까지 수락한 경우 원래 목적지로 이어짐. 기한에 약정 대기를 포함, 영업 시계는 경과 | 대기20초 시험값, 추가 대기 할증 없음. 현재 합의한 경유 용무에 적용하며 이전 저장은 기존 방식 보존 |
| 정밀 승하차형 | 기존 검증된 SafeStop 제안만 제시·수락 | 대안 없음/거절이면 원래 지정점, 감점 없음 | 현재 작성된 대체 쌍만 별도로 제공. 즉석 새 좌표·임의 후보 생성은 제외 |

실제 작업 대기는 안전 정차에서만 경과하며 이동하면 보류한다. 게임 일시정지 중에는 경과하지 않는다. 준비 작업은 한 운송에서1종만 허용하며 짐/음식/용무 대기를 중첩하지 않는다. 음식 사건은 구토가 아니므로 그 자체로 구토 전용 호출 잠금을 설정하지 않는다. 청결 기준에 따른 세차 필요 여부는 기존 정책을 따른다. 변주·흘림 판정은 후보 시드로 고정하고 새 운송의 오염 사건 식별자는 실제 운송 ID에 연결한다. 같은 후보로 다른 운송을 하더라도 정당한 새 오염은 적용하고 같은 운송의 재개는 중복 적용하지 않는다. 선택·흘림 판정·작업 잔여시간·사건 적용 여부를 저장해 재개·취소·날짜 변경으로 다시 추첨하거나 중복 차감하지 않는다. 차량 내구도는 충돌 규칙으로만 감소한다. 승객 불만·짐 자체로 내구도를 깎지 않는다. 기본 프로필의 유형/상황 추가 피로는0이며 사용자 선택지 효과로 설정한 피로만 별도로 적용한다. 경과시간의 일반 피로/연료 영향은 기존 경제 규칙을 따른다.

### 유형과 기존 요청의 배정 연결

| 조건 | 처리 |
|---|---|
| 대표 요청이 필요한 유형 | 승차감 민감→DR01, 재촉→ETA 또는 DR02, 경로 확인→기존 경로 요청1개, 용무/경유→EV02, 정밀 승하차→DR05(SafeStop). 기존0~2개 요청 슬롯 중1개를 그 요청으로 배정 |
| 대화·상태 중심 유형 | 대화·반복 질문은 대표 CH 요청을 강제 배정하지 않고 점수 없는 유형 대사를 진행하며 호환 기존 요청은 별도로 유지. 취객·수면·짐·오염 짐의 상태 사건은 요청 점수와 별도다. 음식 허용 응대는 즉시 선택지 만족도로 요청 종료 합계 상한 밖에서 반영하며 유형 선택창도 공통 대화 예산에 포함 |
| 요청0개 추첨 | 대표 요청이 필요한 유형은 배정 대상에서 제외. 취객·일반 또는 별도 약정 없는 후보만 가능 |
| 경유/경로 후보 없음 | 해당 유형은 제외하고 같은 시드로 가용 유형에 재배정. 부적합 요청을 강제로 만들지 않음 |
| 두 번째 요청 | 유형/첫 요청과 호환되는 것만 허용. 경로 변경 최대1개·공통 대화 예산 유지 |
| 요청 등장 시점 | 승차 또는 안전 중간 정차의 기존 규칙 유지. 아직 제시하지 않은 요청의 불이행을 성향 대사로 감점하지 않음 |
| 적재 등 승차 전 선택 | 기존 요청과 합산해 공통 선택창 예산 안에서 처리. 안전 거절하면 유형 사건 없이 기존 운송 유지, 새 운임 페널티 없음 |
| 평가 | 대표 요청 결과는 기존 평가1회. 유형 후속 반응에는 추가 점수 없음. 미발생·안전 거절·관찰 부족은 중립 |

확률 배정은 요청 수→가용 유형→호환 요청 종류/시점 순으로 함께 확정한다. 진행 중 기존 저장 승객은 기존 유형·요청을 유지한다. 새 타입을 늘려도 취객이 다시 희귀해지지 않도록 아래 취객 기회 보완과 별도 유형 가중치를 구분한다.

### 공통 등장 빈도

새 배정은 아래 규칙을 사용한다. 구형 저장의 진행 중 운송은 기존 배정을 유지한다. 등장 빈도와 구토 빈도를 함께 높이지 않는다.

| 항목 | 시험 규칙 | 예외·목적 |
|---|---|---|
| 기본 취객 빈도 | 배정 가능한 운송의30% | 시간·지역 제한 없이 짧은 Proto에서도 체험 |
| 미등장 보완 | 연속 비취객3명 실제 탑승 후 다음 배정 가능 승차는 취객 | 동일 후보·호출 갱신·재수락으로 다시 뽑지 않음 |
| 하루 한도 | 실제 취객 탑승 최대2명 | 기존1명보다 체험 기회 확대, 한도 이후 보완 예약은 다음 날로 유지 |
| 부담 분산 | 모든 특수 유형 뒤 일반 승객1명 확보 | 취객 보완이 대기 중이어도 이 휴식 구간 우선 |
| 짧게 끝낸 영업 | 실제 승차가 적으면 미등장 가능 | 매일 무조건1명 보장으로 표시하지 않음 |
| 상태 확정 | 승차 자격 확인 후 승차 준비 진입 때 영업의 다음 승차 순번에 유형 예약, 같은 순번에는 같은 결과 | 준비 전 유형 비공개. 취소/거부 후 예약 유지, 실제 탑승 완료 때만 순번·보완·한도 소모 |
| 저장 | 성향 예약·연속 미등장·휴식 구간·하루 한도와 확정된 승객을 함께 보존 | 실제 취객 탑승 때 미등장 카운터 초기화, 날짜 변경은 하루 한도만 초기화 |
| 돌발 사건 | 구토·기상 지연 확률과 세차 규칙은 기존 유지 | 빈도 변경으로 비용이 늘어나는지는 따로 검증 |

취객은 공통 승객 유형 중 하나다. 위 등장 시험안의 취객 미선정 시 다른 특수 유형을 배정하는 전체 확률30%를 적용하되, 예전 비취객3종 균등 배정안은 대체한다. 비취객 특수 유형 추첨에 당첨되면 그 운송의 가용 유형에서 균등 선택한다. 휴식 구간에는 모든 특수 유형을 제외하고 일반 승객의 기존 요청은 유지한다. 취객 보완은 다른 유형을 만났더라도 비취객 탑승으로 계산한다. 한도·보완·휴식 때문에 시험 확률이 실제 전체 탑승 비율과 같지는 않다.

### 공통 대화 흐름과 평가

| 단계·조건 | 동작 | 중복·안전 보호 |
|---|---|---|
| 승차 | 주 유형 소개, 기존 요청이 있으면 그 내용에 연결 | 위 유형/요청 호환 배정 사용. 제시·수락 전 목적지/기한 변경 금지 |
| 선택 응답 | 일반 유형은 공통 확인 / 집중 안내2개, 짐·음식은 작업에 맞는2~3개 | 운행 중에도 입력 가능. 실제 준비/정리 작업은 안전 정차에서만 진행. 일반 대사에는 버튼을 매번 붙이지 않음 |
| 다음 반응 | 이전 답변+관찰된 사건으로 분기 | 같은 대사 랜덤 반복만으로 상호작용 완료 표시 금지 |
| 후속 질문 | 기존 요청과 합쳐 운송당 선택창 최대3회, 성향 자체는 최대2회 | 일반 유형 후속은 이동30초 뒤 선택 없는 반응이다. 얕은 잠의 위치 질문만 별도 후속 선택이며 기존 요청2개가 배정되면 억제한다. 준비 선택과 첫 승차 요청은 순차 제시 가능하나 공통 횟수에 포함. 경로 약정 변경은 최대1개 |
| 우선순위 | 구토/운행 불가 경고 → 기존 요청 → 성향 후속 → 일반 수다 | 선택창은1개, 새 경고가 답변을 덮거나 자동 선택하지 않음 |
| 일반 대사 | 기존 취객 잡담은12~20초 간격. 유형 소개는 경과8초 구간, 후속은 실제 이동 누적30~38초 구간, 의미 있는 상태 변경 안내는6초 | 선택창·작업 표시는 별도 유지. 조용한 약속·집중 안내 후 일반 대사 억제. 새 질문은85% 진행 또는 유효 도착 이후 종료 |
| 짧은 운송·기회 없음 | 후속 대사 없이 도착 반응으로 마무리 | 미응답/미발생 중립, 새 질문을 위해 정차·지각을 강제하지 않음 |
| 평가 | 성향별 독립 호감도 게이지/추가 요금 없음 | 요청 종료 결과는 요청 합계 상한 안에서1회 반영. 유형/상황 선택 효과는 별도 장부이며 현재 기본값은 밸런스 표 참조 |
| 실제 위험 운전 | 기존 주행 평가와 요청 관찰 사용 | 같은 충돌·급제동을 성향 불만으로 다시 차감하지 않음 |
| 기억·재개 | 마지막 응답·대사 단계·대기 질문·경계 설정·평가 완료를 보존 | 재시작으로 질문/보상 재발생 금지, 이미 확정된 운임 불변 |

유형의 집중 안내 선택은 후속 일반 대사를 억제한다. 대표 요청은 별도 응답·실제 관찰로 평가하고 하차 결과는 기존 S/R·운임 산식을 사용한다.

## 대화 선택의 실제 효과 표시 (출하 기본값)

선택지에는 기사 행동과 상태 효과를 분리해 표시한다. 즉시/운행 중/종료 판정, 확률 오염, 안전 정차 작업을 구별한다. 현재 수치의 단일 기준은 [밸런스 v1](../passenger-balance-v1.md)·실제 활성 프로필이며 과거 +5/+8/-10 표를 재사용하지 않는다. 구 저장은 저장 당시 방식으로 마친다.

| 표시 | 기준 |
|---|---|
| 즉시 효과 | 선택 직후 실제 S·피로 전후 값과 상한 적용량 |
| 운행 중 효과 | 점/분·%/분 등 단위를 구분, 일시정지/도착 후 중지 |
| 종료 효과 | 관찰한 성공/실패/판정 불가에 맞는 선택지 값, 중복 지급 없음 |
| 물리 작업/청결 | 위 상태 사건 표의 실제 시간·조건·발생량, 일반 하차 변화와 구분 |
| 상세 원인 | 원인·실제 증감치로 표시, 운전 점수·M·S를 혼합하지 않음 |

선택 효과 편집은 성공/실패 감지기를 추가하지 않는다. Quiet 약속 위반 관찰 부재·목적지/경유 실패 도달 제한 등은 [판정표](../content-tuning-request-outcomes.md)에 명시한다. 실제 표시 방식은 [05 화면](05-interface-and-navigation.md)·[07 대사](07-passenger-dialogue.md)를 따른다.

## P1·P2 상황 반응과 용무 대기

| 관찰/유형 | 실제 동작 | 반복·평가·저장 경계 |
|---|---|---|
| 실제 신호 대기18초 | 관찰 가능한 해당 접근 신호를 기준으로 대기 반응 | 단순 경과시간만으로 신호 대사를 만들지 않음. 실제 상황 질문 최대2회, 전체 질문 최대3회·간격20초 |
| 수면 승객의 충격 | 실제 충격으로 깨어남. 유효한 응답을 기다린 후 차분한 운행15초에 재수면 | 응답 제한/조용히 가기/도착 접근 때문에 질문이 생략돼도 영구 각성하지 않음. 일시정지·도착 후 시간 제외 |
| 음식 허용 | 선택지 즉시 효과 유지. 새 운송은 이동 중 섭취20초 후 청결-2, 예정된 흘림은 추가 이동5초 뒤-6 | 실제 충격이 예정된 흘림을 앞당길 수 있음. 밀봉/흘림 미예정은 강제 오염 없음. 동일 사건1회·기존 저장의 사건 시점 유지 |
| 짐 충격 반응 | 안전 정차5초에 짐 재고정 | 임의 내구도 손상 없음. 실제 작업 때만 시간 진행 |
| 승차감 민감·재촉·경로 확인 등 | 실제 사건과 이전 답변에 따른 발화/선택. 대화 응답은 운행 중에도 가능. 실제 작업은 안전 정차 때만 | 필요한 안전 제동은 별도 만족도 감점 사유로 사용하지 않음. 구토 등 긴급 대사·기존 요청 우선 |
| 합의한 경유 용무 | 수락 전에 무료20초 대기를 제시. 경유지 안전 정차에서 진행 후 원래 목적지로 복귀 | 같은 운송ID/약정 운임. 새 운송에 대기 기한1회 포함. 이전 저장은 기존 경유 방식 유지 |
| 원래 승하차 장소 점유 | 작성·검증된 대체 포켓 제안, 명시적 동의 후 같은 승하차로 처리 | 일반 승하차 목록24개 유지. 안전 경로·빈 포켓·짧은 보행 동선이 없으면 대기. 실제 도로 주정차 허용 주장 없음 |

대체 장소는 게임용 EG-GAME-02 → EG-ALT-02-A 한 쌍부터 운영한다. 실제 도로 근거가 확인된 승하차 지점과 구분한다. 대기/도보 진행·응답·일회성 청결 사건·용무 잔여 시간은 저장 복원하며, 재개로 보상이나 비용을 중복하지 않는다.


2026-11-03 대화 표시·기사 대사·운행 중 선택은 [대화 스크립트](07-passenger-dialogue.md)를 따른다. 요청 발생 시점/실제 정차 작업/배점은 이 문서 기준을 유지한다.


2026-11-07: 같은 특성의 대사·사건 확률·선택 효과·오염/작업 시간은 [승객별 개별 설정](16-passenger-preset-overrides.md)으로 교체 가능하다. 미지정은 공통 상속이며 등장 정책·운임 정책은 그대로다.


## 2026-11-07 비 오는 날 승차

[비 프로토18](18-rain-prototype.md)를 따른다. 성공 승차마다 추가 청결 감소(기본2)를 한 번 기록하며 승차 직전 청결 보너스 평가 후 적용한다. 현재 승객의 운송/만족도 시작값을 취소하거나 재계산하지 않는다. 기존 시간·하차 오염/세차는 유지한다.

## 2026-11-09 호출판 연속 반복 보완

은계 호출은 기존24정차 후보/도달 가능한 방향 경로/지역 분산·대표 코스를 유지한다. 새 호출판 생성 시 직전 offers의 승차지를 임시로 참고하고, 같은 공간 분리 조건을 만족하는 후보 중에서는 이전 판에 없던 승차지를 우선한다. 새 후보가 부족하면 기존 분산 완화/순위 대체를 허용하므로 무조건 재노출 금지 규칙은 아니다. 대표 코스에도 공통 적용하며 PVP 공유 호출판 생성 규칙과 저장 형식은 바꾸지 않는다.

실제 초기 위치·4수요시점×24판 검사에서는 시간대별14~16곳·직전판 반복0을 확인했다. 모든 위치/장시간 운송의 보장은 아니며 [구현·검증 이력](../work-history/2026-11-09-passenger-cards-call-variety.md)을 따른다. 지도 선택 시 예상 피로 등 예측 카드는 숨기고 운임/승하차/수락·불가 사유는 표시한다.
