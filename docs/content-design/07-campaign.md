# 3일 영업 캠페인과 결과 비교

## 2026-10-22 확정 변경 · 3일×20분

이 절이 과거 독립 하루/새 하루 설명보다 우선한다. 하루 종료는 날짜1~2에 정산 후 다음 날 선택, 날짜3에 최종 누적 수입·지출·순수익을 보여준다. 고정 목표 조기 종료는 없다. 다음 날 현금·미납·연료·포만감·운행 점수를 이어가고 야간 수면으로 피로60만 회복한다. 야간 회복은 다음 날의1,200초를 소비하지 않는다. 새 캠페인은 날짜1·현금10,000원·연료60%·포만감80·피로10·운행 점수100으로 초기화한다.

기존 하루 저장과 분리한 campaign-3day20-v1.json을 사용한다. 완료 날짜와 다음 날 시작을 함께 저장하며, 진행 중 종료 시 해당 날짜 시작 상태를 복원한다. 다음 날 저장 실패 시 정산 화면/기존 파일을 보존한다. 마지막 승객은 목적지 하차 후 정산하며 결과 팝업을 닫으면 마감 정산을 진행한다. 수동3일 수익 밸런스는 미검증이다.


기준일: 2026-10-21 · 버전: 1.0 · 상태: 하루20분 구현·자동 검사 완료, 수동 밸런스 미검증

3일 동안 하루20분씩 승객·경로·식사·휴식을 선택하고 누적 실제 순수익을 비교한다. 고정 목표 금액 성공/실패는 사용하지 않는다. 운전자 상태는 [10 운전자 기획](10-driver-condition.md), 비용은 [05 경제](05-daily-operation.md)가 기준이다.

## 시간 규칙

| 항목 | 기획 |
|---|---|
| 사용자 확정 | 하루20분, 컨디션은 영업 시간·식사·휴식 선택에 영향 |
| 표시 시각 제안 | 08:00~20:00의 12시간을 영업 예산1,200초에 대응 |
| 변환 | 예산1초 = 게임36초, 예산1분 = 게임36분 |
| 주행·신호 대기·빈차 이동 | 실제1초마다 예산1초 경과 |
| 메뉴·일시정지·계획 선택·복습·결과 | 영업/운송 타이머·컨디션 정지. 기존 전체 정지 규칙 유지 |
| 식사 | 게임30분 = 예산50초를 즉시 경과 |
| 수면 | 게임60분 = 예산100초를 즉시 경과 |
| 주유·연료 지원 | 기존 예산10초/30초 유지, 컨디션은 깨어 있는 경과로 처리 |
| 실측 길이 | 메뉴 시간·마지막 운송은 추가, 식사·수면의 건너뛴 시간은 실제 조작 시간에서 빠짐 |

20분은 쉬지 않고 영업했을 때의 기준 예산이다. 식사1회·수면1회라면 실제 영업 조작 예산은 17분30초이며 메뉴·마지막 운송은 별도다. 압축 시각은 가상의 하루 표현이고 실제 도로 통행 시간을 재현하지 않는다. 낮·밤 조명 시스템 추가는 범위 밖이다.

승객 픽업/운송 기한과 ETA는 기존의 실제 플레이 초 단위를 유지하고 ‘남은 운송 시간’으로 표시한다. 하루 시각과 혼동하지 않게 한다. 휴식은 승객이 없는 때만 가능하며 수락한 미탑승 호출은 취소 후 이용한다.

|---|---|

| 영업 | 호출·운송·빈차 이동·주유·식사·휴식 선택 |

| 시간 종료 | 신규 수락 중단·미탑승 호출 취소. 탑승 중이면 마지막 목적지 하차까지 계속 |
| 마지막 운송 | 원래 기한 유지, 초과해도 승객 유지 후 목적지에서 기존 지급 규칙 적용. 추가 실제 시간·거리·비용은 기록 |

| 다시 하기 | 1~2일차 정산 후 다음 날: 현금·미납·연료·포만감·운행 점수 이월, 야간 수면으로 피로60 회복(최소0). 3일 종료 후 새 캠페인은 초기화 |

영업 종료 뒤 추가 운송 시간에는 새로운 하루를 열지 않는다. 표시 시각은 ‘20:00 이후 마지막 운송’과 추가 소요로 구분한다. 피로·포만감은 기존 운송을 끊거나 조작을 바꾸지 않으며 주행 연료·운송 기한은 계속 적용한다.

## 승객 구성과 반복

| 구간 | 구성 방향 |
|---|---|
| 초반 | 비교적 짧은 코스·쉬운 승하차로 시작 |
| 중반 | 기존 법규/선택 코스와 식당 접근이 쉬운 목적지 후보 혼합 |
| 후반 | 남은 시간·피로를 보고 짧은 운송/휴식/퇴근 선택 |
| 반복 | 9개 코스·17요청을 재사용. 같은 조건 재도전과 다른 후보 선택 가능 |

기존 한 경로 자동 주행이 약350초였던 점을 고려해 3~5건을 초기 체험량 후보로 측정한다. 9코스 전부를 하루에 강제하지 않고 건수·수익을 보장하지 않는다. 경로·픽업 기한·운임을 조정할 때 코스 설정 버전을 기록하고 기존 결과와 섞지 않는다. 구체 배정은 [09 시나리오](09-prototype-scenarios.md)를 따른다.

## 1일차부터 다시 시작

새 UI는 ‘새 하루 시작’으로 변경한다. 진행 중 다시 시작은 확인 후 저장 성공 때만 초기화하며 해당 회차는 완료 비교에서 제외한다. 취소·저장 실패는 현재 운송과 저장을 보존한다. 현재 하루의 운행 점수는 새 회차에서100점으로 시작하고 이전 완료 결과 요약은 별도 보존한다.

기존 회계 정산 저장과 운행 사건 즉시 저널 저장은 역할을 유지한다. 구3일 저장을 새1일 기록으로 덮어쓰지 않고 별도 모드/설정 버전으로 새 회차를 만든다. 중도 종료·이어하기는 현재 저장 경계에 맞춰 현금·연료·컨디션을 함께 복원하며 새 중간 저장 시스템은 이번 필수 범위가 아니다.

## 구현·저장 경계 (2026-10-21)

기본 은계는 `PrototypeSettings.ForOneDay()`의 1,200초 모드다. 구 `campaign-v2.json`은 읽거나 덮어쓰지 않고 새 `campaign-day20-v1.json`과 별도 `.driving` 저널을 사용한다. 진행 중 재실행은 하루 시작의 현금·연료·포만감·피로로 함께 복원하며 운행 사건 저널은 유지한다. 완료 정산은 최종 상태를 복원한다. 새 하루 확인·저장 성공 후 ID와 운행 점수를 초기화하며 이전 완료 요약은 계속 보존한다. 중도 재시작은 완료 비교에 넣지 않는다.

결과는 종료 사유·순수익·생활 이용·예산 경과·마지막 운송 추가 시간·실제 경과(메뉴 포함)를 구분한다. 동일 버전/교통 설정의 이전 완료 결과만 비교한다. 별도 프로세스 재실행과 저장 실패/취소 자동 검증은 작업 이력을 따른다. 수동 하루 밸런스는 아직 미검증이다.


## 2026-10-21 자연 운송 경로 정정

승객9코스를 강제 상황 경유 없는 일반 경로로 재배치했다. 비교 설정 버전은 `eungye-day20-v2-natural`이며 이전 코스 버전과 자동 순수익 비교를 섞지 않는다. 기존 완료 기록은 보존한다. 하루1,200초·컨디션·마감 규칙은 유지한다.


## 2026-10-22 호출 접근 밸런스

초반/후반 짧은 코스 정렬의 픽업 거리와 중반 식당 접근 거리를 공유 방향 도로 경로로 계산한다. 픽업 기한의 신호 대기 여유를 보완하고 비교 버전을 `eungye-day20-v3-access-rest`로 올린다. 하루1,200초·컨디션·생활비·운임은 유지한다. 실제 하루 체험량은 계속 검증 중이다.

## 2026-10-22 생활 동선 추가

동부 주유소 인근 휴식 주차구역 추가를 승인받아 적용한다. 정상 시작은 기존 은계 주차장이고 추가 구역은 수면 전용이다. 비교 버전은 eungye-day20-v3-access-rest이며 이전 완료 결과를 삭제하지 않는다. 운임·식사3,000원/50초·수면무료/100초·10% 주유400원은 이번 변경에서 유지한다.

## 2026-10-22 감사 보너스·생활 안내

운송별 감사 보너스는 조건 충족 시 한 번만 기본 운임에 더해 수입·순수익·현금 장부에 반영한다. 기본 운임·보너스·합계는 운송 기록에서 분리 표시한다. 04/11의 계산 규칙을 따른다. 하차 후 생활 거점 선택은 안내이며 하루 예산이나 퇴근 규칙은 바꾸지 않는다. 보행 전용 신호 구간 추가에 따른 하루 수익 체감은 수동 재검증 대상이다.
