## 3. 1차 개별 수치

S=승객 만족도, F=기사 피로. 아래는 새 승객의 명시적 개별값이며 나머지는 공통값 상속이다. 오염은 실제 사건 발생 시 차감. 구토 청결은 고정 min(현재,10)이며 아래 확률과 별개다.

| 승객 | 즉시 선택 효과 | 확률·작업·오염 | 요청 이행 효과 |

| 야간근무를 마친 손님 | 선택1 S+1, F+0<br>선택2 S+1, F+0 | 흔들림 후 안정 시간: 6초 | 공통 요청 효과 |

개별·공통 효과는 별도 사건이면 함께 누적된다. 예: 짐 경유 손님은 적재 수락+2와 경유 성공+5로 +7 가능하며 운전·청결·기한 평가는 별도다. 두 요청 종료 합계는 ±10, 최종 S/F는0~100. 수다 유형+2/F+1 뒤 지역대화+3/F+1도 별도로 가능하다. 모든 운행 중 점/분·비율은0으로 두어 기다리기·반복 응답만으로 점수를 벌지 않는다.

## 4. 공통 등장·요청 1차 설정

| 요소 | 설정 | 의도 |
|---|---|---|
| 요청0/1/2개 | 25/60/15% | 복합 행동이 늘어도 요청2건 과밀을 줄임 |
| 음주 배정 | 기존30%·하루 최대2·강제 등장 정책 유지 | 신규 음주 프리셋은 기존 한도 안에서 나눔 |
| 일반 특수 그룹 상대 가중치 | 수면1·승차감3·급함2·경로0·경유1·짐2·오염짐1·음식1·정밀하차2·수다2 | 작업·오염 부담 그룹을 낮게, 운전/응대 위주 |
| 그룹 내부 | 기존 프리셋1, 신규는 요소표 수치 | 같은 그룹에서 새 변주를 함께 경험 |
| 요청 상대 가중치 | Quiet3·ETA2·Comfort3·OnTime2·LargeRoad1·SafeStop2·Empathy2·Interview2·Music1·FareHelp2·LocalChat2·DestinationChange1·ViaStop1·RejectIllegal1 | 안전·일상 응대를 중심으로 유지 |
| 제외 | ShortRoad0/비활성·RouteAdvice0/비활성·경로확인 프리셋/그룹0 | 짧은길/빠른길 선택 제거 |
| 하차 후 분실물 | 기존 별도 사건 유지 | 요청 슬롯 추첨과 구분 |

가중치는 가용 후보 내 상대 비중이며 전체 등장%가 아니다. 기존 특수 뒤 일반 운송·경로 가용성·대표요청 슬롯 조건을 유지한다. 큰길 요청과 도착 예상 안내는 경로 최적화 선택이 아니므로 유지한다. 제외된 요청의 구 코드/데이터는 기존 저장과 사용자 프로필 호환용으로 보존하고 새 기본 후보에서만 제외한다.

## 5. 기획자 편집·검증 기준

- 관리창 default/기본값 복원으로 현재24명 구성을 확인한다. [가져오기용 전체 프로필](../../config/content/presets/passenger-roster-v1.json), [승객 원본](../../config/content/passenger-roster-v1.json).
- 기존 사용자 저장 프로필을 불러오면 그 프로필의 승객 구성이다. 새 목록이 필요하면 새 프로필 또는 가져오기를 사용한다. 진행 중 세션은 저장 당시 설정으로 유지한다.
- 요청 문구만으로 생기지 않는 기능: 면접 결과·지역 사실 보장·새 경유지·짐 파손/보상·음악 실제 조작.
- 1차 수치는 사람 플레이로 확정한 값이 아니다. 운송별 S 초과량·요청 이행률·세차빈도·준비/경유 시간·대화 읽기 부담을 후속 측정한다.
- 구현/배포/검사 범위는 [작업 이력](../work-history/2026-11-07-passenger-roster-v1.md).
