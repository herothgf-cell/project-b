# 기획 및 프로토타입 로드맵

**2026-10-21 범위 변경:** 보험·세금은 프로토 제외. 갱신/납부 메뉴·비용·세금 미납·보험 출발 제한·완납 성공 조건을 제거한다. 3일×12분·순수익30,000원과 주유/식비/주차는 유지한다. 아래 과거 납부 설계는 후속 참고이며 현재 범위로 집계하지 않는다. G 전체지도·독립 점수 게이지와 수동 운전 보완을 반영한다.

기준일: 2026년 10월 20일 · 버전: 0.6 · 상태: 구현·검증 대조 및 남은 작업 갱신

## 세계관과 주요 경험

| 항목 | 방향 |
|---|---|
| 세계관 | 경기가 어려워져 실직한 주인공이 돈을 벌기 위해 택시를 운전 |
| 성장 | 운전·지역·경로 판단에 익숙해지며 편한 길을 찾음 |
| 선택 | 정체에서 기다릴지 우회할지 판단하고 결과를 경험 |
| 법규 | 한국 법규를 준수하는 운전을 경험하고 독립적인 성향 기록으로 확인 |
| 시간 | 3일 × 하루 12분, 누적 순수익 30,000원 목표 |
| 공간 | 은계 기반 도로 + 판단 상황을 위한 가상 연결도로·시설 허용 |
| 영업 | 프로토는 개인택시. 법인택시는 후속 |

## 상태와 범위 기준

| 표시 | 의미 |
|---|---|
| 포함 | 프로토 개발 목표에 넣음. 현재 구현 완료와는 다름 |
| 부분 포함 | 표에 적힌 최소 기능만 구현, 나머지는 후속 |
| 제외 | 이번 프로토에서는 개발하지 않음 |
| 기획만 | 후속 플레이 흐름은 작성하되 프로토 개발·검증 범위에서 제외 |
| 수치 제안 | 문서화된 게임 초깃값. 실제 법정 금액·확정 밸런스가 아님 |

현재 상태는 출구 결과·지도 가독성 보완을 포함한 main 코드와 [통합 검증](../prototype-completion-validation.md)을 대조한 결과다. 구현·자동 검사와 수동 플레이·현장 확인을 구분한다. 1일차 재시작 추가 검증은 [캠페인](07-campaign.md#1일차부터-다시-시작)과 통합 검증 문서를 따른다.

## 웹 추가 기획의 개발 연결 (2026-10-20)

10월 19일 반영된 승객 확장·법규 후보 62개·은계 접근 시 운전 계획 선택 기획을 [개발 체크리스트](../prototype-development-checklist.md#2026-10-20-웹-추가-기획을-반영한-개발-목록)의 P4/P5/P6으로 연결했다. 지도 선택 이벤트는 출구 1구간·우회전 1교차로부터, 승객은 기존 기능을 사용하는 요청부터 검증한다. 법규 후보 전체 자동화는 현재 완료 기능이나 일괄 프로토 필수가 아니다. A-01 캐주얼 그래픽·HUD 시안은 사용자 정정에 따라 프로토 제외다.

## 남은 개발·검증 우선순위

핵심 시스템 구현 이후의 수동 검증·수정이 중심이다. 원안의 미구현 편의 기능과 필수 검증의 구분은 [최신 잔여 작업표](../prototype-development-checklist.md#최신-남은-작업-요약)를 따른다.

1. 일반 차량이 있는 환경에서 출구 A/B/C와 거점 진출입을 수동으로 완주하고 발견된 막힘·시야 문제 수정.
2. 위험 회피 급제동·신호 접근의 맥락 판정과 무위반 완주 확인. 자동 캠페인에 적색 진입 기록이 남아 있다.
3. 정상/우회/위반 선택의 반복 캠페인 시간·순수익 비교와 연료/기한 조정.
4. OSM 보류 규제·임시 시설·차로 연결 현장 대조.
5. 현재 PC의 기존 1/3인칭 필수 HUD 가독성·키보드 주행·빌드/조작 문서 확인. 실물 패드·새 PC 검증은 프로토 제외.

주유의 현재 UI는 50%포인트 보충 1종, 연료 경고는 15%다. 원안의 가득 주유·호출별 연료 예측은 미구현으로 [경제 문서](05-daily-operation.md)에 남긴다. 예약·단골·사고·수리·보험 청구는 계속 제외한다.

## 반영한 사용자 결정

| 항목 | 확정 방향 | 세부 기획 제안 |
|---|---|---|
| 보험·세금 | 프로토 제외 | 메뉴·비용·부채 발생·납부 성공 조건 없음 |
| 캠페인 | 3일 × 12분·누적 순수익 30,000원 | 순수익 목표로 성공 판정, 실제 플레이 후 밸런스 조정 |
| 개인 예약 | 프로토 제외·기획만 | 후속 관계→예약→픽업→완료/취소 흐름은 04 |

금액·연료 소모·법규 감점·성향 기준 횟수는 테스트할 제안값이다. 후속 예약·사고의 세부 결정을 이유로 프로토 개발을 막지 않는다.

## 프로토 개발 순서와 완료 기준

실행할 작업과 체크 상태는 [우선순위별 개발 체크리스트](../prototype-development-checklist.md)에서 관리한다. 현재 구현·보완·신규 개발을 구분한다.

| 단계 | 목표 | 필요한 기획 | 개발·검증 완료 조건 |
|---|---|---|---|
| 1 | 맵과 주행 기반 정리 | 06의 주행·시설·AI 범위 | 은계 영업·거점 접근과 보조/수동 주행 가능 |
| 2 | 두 대표 상황 | 01 상황표 + 02 법규 근거·감점 | 출구 세 선택 및 우회전 조건별 판단 재현 |
| 3 | 독립 법규 기록 | 02·03의 사건·성향·저장 | 승객 매너와 분리된 카드·누적·재시작 |
| 4 | 승객과 경제 | 04 요청·보상, 05 거점·생활비 | 요청 대응·실제 주유/식사/주차 결제·중복 차감 방지 |
| 5 | 짧은 캠페인 완주 | 07 진행 목표·03/05 저장 | 준비→운송→거점 방문→정산→성공/실패→재도전 |

개발 기간·인원은 자원 확인 후 산정한다. 프로토에서 법규를 지키는 정상 운전으로 비용을 감당하고 수익 목표를 달성할 여지가 있는지 확인한다.

## 일반 교통 검증 반영 (2026-10-20)

일반 차량 24대와 거점 3곳 진출입·출구 대기 후 우회전을 물리 주행으로 검증했다. 다른 방향 정지선 오판, 가상 신호와 NPC 상태 불일치, 우회전 후 횡단보도 급제동 예외를 수정했다. 출구 B/C는 일반 교통을 유지한 위치 제어 경계 검사까지이며 전 구간 수동 검증은 남는다. [검증 조건·결과](../prototype-live-traffic-validation.md)를 참조한다. 새 기능의 다음 순서는 P4 지도 접근 선택 이벤트, P5-01 승객 요청 최소 확장이다.

## 법규 확장 검토 정정 (2026-10-20)

F01~F62는 혼동 사례만 추린 목록이 아니라 일반 수칙과 특수 상황까지 수집한 백로그다. [검토 결과](../road-law-confusion-review.md)에서 26/22/14개로 분류하고, 점멸 신호·비보호 좌회전·우선권·택시 승하차 예외 등 조건이 바뀌는 장면을 교육 후보로 추렸다. 캐주얼 그래픽·HUD 시안·실물 패드·새 PC 검증은 프로토 잔여 작업에서 제외한다.

## 은계 혼동 연습 1차 (2026-10-20)

F02·F03 점멸 비교, F06 녹색 출구 정체 비교, F05 비보호 좌회전의 적색/대향차/빈 도로를 기존 연습에 추가했다. 상황 설명·판단 위치·행동별 결과·같은 조건 재시도를 제공하며 실제 규제와 창작 교육 시설을 구분한다. 다음 후보는 거점 보도 횡단과 무신호 우선관계다. [구현과 검증](../eungye-confusion-practice-validation.md).


## 은계 일반 영업의 법규 상황 구역 (2026-10-20)

사용자 요청의 최종 적용 위치는 기본 은계 지도다. 승객 승차 후 목적지까지 내비가 점멸·출구 정체·비보호 좌회전 구역을 경유하고, 같은 차량으로 상황 판단과 운송을 이어간다. 지도/차량 교체·자동 일시정지 없이 결과 알림과 정차 시 상세 설명을 제공한다. 선택형 연습은 동일 조건 재시도 수단으로 유지한다. [배치 7곳·시간 예산·관찰·검증](../eungye-in-service-law-zones.md)을 따른다. 이 연속 운송 기능은 P4의 자동 정지·운전 계획 팝업을 완료했다는 뜻은 아니다.
