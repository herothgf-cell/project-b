# 콘텐츠 범위와 다음 개발

콘텐츠의 조건·수치는 아래 담당 문서에서 한 번만 정의한다. 개발 완료 표시는 [체크리스트](../prototype-development-checklist.md), 명령·빌드·검증 결과는 [최신 작업 이력](../work-history/LATEST.md), 이전 계획은 [로드맵 이력](../design-history/content-design/00-RoadMap-history.md)에 둔다.

## 핵심 경험

| 요소 | 플레이어가 하는 일 | Proto 경계 |
|---|---|---|
| 영업 | 은계에서 호출 또는 길가 승객을 태워 안전하게 운송 | 개인택시 한 대, 기존 승객/도로망 |
| 판단 | 정체에서 대기·우회, 교차로에서 신호·보행자 확인 | 대표 상황과 관찰 가능한 법규. 선택 버튼만으로 채점하지 않음 |
| 응대 | 승객의 기대·요청·취객 사건에 대응 | 텍스트·경로·운전 행동. 음성 연기·복잡한 대화 제외 |
| 생활 | 주유·식사·수면·세차 방문과 비용/시간 선택 | 빈차 정차 서비스, 현금·미납·순수익 |
| 하루 | 예정20분 영업과 초과 영업/휴식, 3일 결과 비교 | 고정3만원 성공/실패 판정 없음 |
| 숙련 | 법규 사건·승객 결과를 읽고 동일 상황 연습 | 영상 리플레이·장기 레벨 성장 제외 |

## 남은 Proto 구현과 검증

사용자가 선택한 후속 순서는 **P11 승객 요청 다양화 → P12 지역별 수요·공차 수익성 → P13 승하차 공간 점유**다. [17 확장 기획](17-proto-operation-expansion.md)에 범위·검토할 수치·마인드맵 변경안을 정리했다. 모두 신규 개발 잔여이며, 이번 문서 반영으로 구현 완료가 되지 않는다. 핵심 플레이 기반은 있으나 P11/저장 안정성/수동 캠페인 검증이 남아 **Proto 개발 완료 또는 다듬기만 남은 상태는 아니다.** P12/P13 확장 마감과 기존 Proto 마감은 구분한다.

| 구분 | 남은 내용 | 진행 조건·완료 기준 |
|---|---|---|
| 신규 구현 | 요청 무작위 배정·승차/중간 정차 발생·복수 요청 | 04 변경 기획 기준. 현재는 완료 운송 수에 따라17종 순환·승차 시1건. 저장된 목록/시점·충돌·개별 평가·UI·구형 저장 이관 구현 필요 |
| 후속 확장 | 지역별 수요·공차 수익성 → 승하차 공간 점유 | 17의 P12→P13. 기획만·미구현, 수치/대체 정차 세부 정책 검토 필요 |
| 안정화 | 고빈도 저장 파일 교체 경고 | 재현 원인 진단·실패 보존/재시도·복원 검증. 자동 검사 일부 통과와 별도로 해결 필요 |
| 구현 후 통합 검증 | 대표 코스·교차로·24정차 후보·거점 왕복 | 위치 제어 사례와 전 구간 물리 주행·사람의 수동 운전을 구분. 막힘·진입/합류·필요한 제동·시야 확인 |
| 구현 후 밸런스 | 사람의20분/초과 영업/3일 플레이 | 만족도·보너스·식사·수면·연료·취객·대기·세차의 시간과 순수익 비교 |
| 구현 후 사용성 | HUD/요청·결과 가독성, Unity 편집 GUI, 장시간 교통·성능 | 실제 입력·프레임 지연·주행 밀도 확인. 자동 상태 검사로 완료 표시하지 않음 |
| 조건부 보완 | 발견된 지도 연결·신호/차로·시설 문제 | 근거가 있는 지점만 수정. 전수 현장 조사 중단 방침 유지 |

승객/법규 기본 시스템, 9코스, 17종 요청, 24개 정차 후보,3일 캠페인, 생활 거점, 청결·세차, 진행 운송 저장, 점수 회복과 전체 지도 편집은 이미 기반이 있다. 과거 빈 체크나 미구현 문구를 근거로 같은 기능을 다시 개발하지 않는다.

## 추가할 만한 시뮬레이션 제안

아래는 아직 선택하지 않은 제안이며 자동으로 Proto 필수 범위에 추가하지 않는다. 지역 수요는 사용자 선택에 따라17의 후속 확장으로 옮겼다.

| 제안 | 추가되는 판단·재미 | 최소 범위·주의점 |
|---|---|---|
| 승하차·짐 싣기 시간 | 짧은 운송도 승하차 시간이 들어 영업 동선에 차이 | 승차 때 예상 대기5~10초를 보여주는 시험안. 긴 강제 대기·새 조작 없이 빈도 조절 |
| 혼잡 상황에 대한 승객 반응 | 정체를 설명하거나 합법적 우회를 제안하며 응대 | 이미 관찰한 교통만 근거로 짧은 요청 변주. 통제 불가능한 지연을 운전자 탓으로 감점하지 않음 |

새 요소를 넣기 전 현재 대화 빈도·수동 영업 밸런스를 확인한다. 대사나 대기로 영업 시간이 과도하게 소모되면 빈도부터 줄인다.
