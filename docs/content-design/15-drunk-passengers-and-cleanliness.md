# 취객 운송과 차량 청결도

| 항목 | 반영 내용 | 검증 경계 |

## 경험 목표와 범위

| 목표 | 프로토에서 제공할 경험 | 경계 |
|---|---|---|
| 취객 운송 | 일반 호출·길가 승객 중 취객을 태워 기존 목적지까지 운송 | 기존 9개 상황 코스·17종 요청의 경로·목표는 그대로. 취객은 별도 **승객 특성**이며 운송당 요청 1개 제한에 포함하지 않음 |
| 돌발 구토 | 운송 중 확률적으로 발생하고 하차 뒤 청결도가 급락 | 구토 연출은 짧은 대사·비자극적인 효과음/표시로 제한. 주행 조작 강제 변경·사고 판정·법규 점수 변화 없음 |
| 잠든 승객 | 목적지에 도착해 깨워도 즉시 하차하지 않아 영업 시간이 흐름 | 도착 시각으로 운송 기한 판정. 대기 때문에 도착 운임을 0원으로 바꾸지 않음 |
| 청결 관리 | 더러운 차는 다음 승객의 승차 거부, 깨끗한 차는 승차 시 만족도 소폭 상승 | `운전 만족도 M`, 법규 성향과 분리. 주유소 세차·실내 청소로 회복 |

## 발생과 운송 흐름

| 순서·상태 | 발생·선택 | 결과·예외 |
|---|---|---|
| 취객 지정 | 수락한 운송마다 고정된 시드로 **20%** 후보 추첨, 하루 실제 탑승 최대 1명. 승차 지점에서 취객임을 대사·자세로 알림 | 같은 호출 재표시·저장 복원에 재추첨하지 않음. 청결 거부·픽업 취소 후보는 하루 한도를 소모하지 않음. 9개 코스의 학습 목표와 요청 1개를 덮어쓰지 않음 |
| 승차 | 청결도 30점 이상이고 기존 승차 조건 충족 | 현재 목적지·약정 운임·기한 유지. 취객 전용 추가 운임 없음 |
| 구토 | 취객 운송의 **25%**, 운송 중 1회만. 발생 예정이면 운송 진행률 30~70% 지점에서 알림 | `구토 발생` 플래그와 운송 ID 기록. 당장 차를 세우거나 경로를 바꾸도록 강제하지 않고 목적지까지 간다. 운전 만족도·승객 만족도·법규 점수 즉시 감점 없음 |
| 목적지 도착 | 기존 방향·정차 조건을 맞춰 F로 하차 시도 | **최초 유효 도착 시각**과 기한 충족 여부를 확정. 보너스의 조기 도착 비교도 이 시각 사용. 이후 택시 영업 시계는 계속 흐름 |
| 취객 기상 | 취객 운송의 **30%**는 첫 기상 시도에 반응하지 않음 | 도착 지점에서 최소 **15게임초** 대기. 이후 F로 다시 깨우면 하차, 별도 입력이 없어도 **30게임초**에 자동 기상·하차. 안내 대사와 남은 대기 표시 |
| 하차 완료 | 일반 또는 지연 하차가 끝남 | 운송 ID당 기본 운임·보너스 1회 정산. 구토했다면 그때 `청결도=min(현재 청결도, 10)` 적용. 다음 호출 전 주유소 방문 권장 |

구토와 기상 지연은 독립 추첨이므로 한 운송에서 둘 다 일어날 수 있다. 정차 위치를 벗어나면 자동 하차하지 않고 돌아와 안전하게 정차하도록 안내한다. 기상 대기 상한에 도달한 뒤 다시 정차하면 즉시 하차한다. 대기 중 다른 호출 수락·시설 이용·다른 승객 승차는 막는다. 영업 마감 시각이 지나도 탑승 승객을 먼저 하차시키고 기존 마감 정산으로 이어진다. **도착 전** 기한 초과는 기존 0원 규칙을 유지한다.

확률은 운송 ID에 묶어 1회만 확정한다. 자동 검증에는 확률을 기다리지 않도록 `일반 / 구토 / 기상 지연 / 둘 다` 고정 사례를 제공한다. 별도 취객 요청이 아니므로 DR/CH/EV 요청 효과·응답 대사와 겹치지 않게 사건 알림을 순차 표시한다.

## 차량 청결도와 승차 거부

| 항목 | 프로토 규칙 | 이유·표시 |
|---|---|---|
| 청결도 `C` | 0~100점, 새 캠페인 100점. 영업일·재실행에 유지 | 차량 상태이며 승객별 운전 만족도 `M`과 독립 |
| 평상시 운송 | 하차가 끝날 때 `C - 2`점, 최저 0 | 시간이 흐르며 관리 필요. 구토 운송에서는 아래 급락을 우선 적용하고 -2를 추가 청구하지 않음 |
| 구토 후 하차 | `C = min(C, 10)` | 하차 전에는 이미 태운 승객의 운송·운임을 유지. 하차 이후의 영업에 영향 |
| 높은 청결도 | 승차 시 `C >= 80`이면 시작 승객 만족도 `S0`에 **+3점** | 새 만족도 기획의 `S0=R-D`를 확정한 뒤 한 번 가산. `M`·요구 만족도 `R`·기본 운임 판정에는 미반영. 현재 구형 만족도 코드와 함께 구현 전 |
| 보통 청결도 | `30 <= C < 80`: 승차 가능, 만족도 가산 없음 | 불필요한 반복 감점 없음 |
| 낮은 청결도 | `C < 30`: 승차 위치에서 승객이 “차가 너무 더러워서 못 타겠어요”라고 말하며 거부 | 탑승·운송 ID 생성·초기 만족도 추첨·운임 없음. 수락 호출은 `청결 거부`로 종료하고 대기 승객은 재생성 쿨다운. 법규·`M` 감점 없음 |
| 경고 | `C < 30`이면 HUD·호출 카드에 세차 필요를 미리 표시 | 그래도 호출을 선택·수락할 수 있어 현장 거부 경험은 남기되, 첫 거부 뒤에는 세차 전 재수락을 차단해 반복 헛걸음을 막음 |

길가 승객도 같은 거부 규칙을 사용한다. 거부를 기존 `운송 기한 초과`나 `완료 운송`으로 집계하지 않는다. 청결도만으로 기존에 탑승한 승객을 중도 하차시키거나 운임을 줄이지 않는다. 높은 청결도 +3점은 **승차 시 한 번**만 적용하고 세차를 운송 도중 이용할 수 없으므로 한 운송에서 반복 가산되지 않는다.

## 주유소 세차·실내 청소

| 항목 | 프로토 규칙 |
|---|---|
| 이용 위치 | 기존 은계 주유소 3곳의 지정 정차 구역. 빈차·저속·방향·영업 상태 검사를 기존 주유와 공유. 새 세차장 지도 시설은 만들지 않음 |
| 메뉴 | F7 주유소 메뉴에 **세차·실내 청소**를 주유와 별도 선택지로 표시. 연료 구매 없이 단독 이용 가능 |
| 이용 효과 | 청결도 100점으로 회복. **2,000원·30게임초** 소모, 엔진 정지. 취소 시 비용·시간·청결 변화 없음 |
| 자금 부족 | 식사처럼 비용을 미납으로 기록하고 세차는 진행 가능. 청결 때문에 새 영업이 영구 차단되지 않도록 함 |
| 시간 부족 | 남은 영업 시간이 30초 미만이면 시작 불가, 비용 없음. 다음 날 이월된 청결도와 주유소 방문 가능 |
| 정산·저장 | `세차` 거래를 주유·식사와 구분해 장부·일일 비용·순수익에 1회 반영. 청결도·거부·구토·기상 지연 결과를 저장·복원 |

하차 후 생활 거점 추천에서 `C < 30`이면 **주유소(세차 필요)**를 연료 부족보다 우선 권장한다. 안내는 실제 주유소 입구까지이며 플레이어가 직접 진입·정차해 세차를 확정한다. 단지 추천을 눌렀다는 이유로 결제하거나 차를 자동 이동시키지 않는다.

## 화면과 예시

| 위치 | 보여줄 정보 |
|---|---|
| 주행 좌측 하단 | 기존 **연료 표시의 오른쪽**에 청결도 아이콘·막대·`C/100` 수치. 30 미만은 색뿐 아니라 `세차 필요` 글자 표시 |
| 호출·승차 | 수락 전 낮은 청결 경고, 실제 픽업에서 승차 거부 대사·주유소 안내. 취객은 승차 시 대사로 인지 |
| 운송 중 | 구토 시 짧은 승객 대사와 `하차 후 청결 저하 예상` 안내. 노골적인 화면 효과는 사용하지 않음 |
| 도착 후 | 기상 지연 시 `도착 완료 · 손님이 일어나지 않습니다`와 대기 초·다시 깨우기 표시. 도착 시각과 운임 판정은 유지 |
| 운송 결과·일일 장부 | 구토·기상 지연·도착/하차 시각, 정산 금액, 하차 후 청결도, 세차 거래·비용을 각각 표시 |

예: `R=70`, 탑승 전 `C=100`이면 새 만족도 규칙에서 `S0=70-8+3=65`가 될 수 있다. 취객이 운송 중 구토하고 정시에 목적지에 도착했으나 30초 뒤 하차했다면 운임·보너스의 시간 판정은 **첫 유효 도착 시각**을 쓴다. 하차 뒤 `C=10`이 되고, 다음 호출의 승객은 승차 위치에서 거부한다. 주유소에 들러 2,000원·30초를 사용하면 `C=100`으로 회복되어 다시 승객을 태울 수 있다. 숫자는 밸런스 테스트용이다.

## 개발 순서와 완료 기준

| 우선 | 구현 항목 | 완료 확인 |
|---|---|---|
| 1 | 차량 청결 상태·저장·HUD, 일반 운송 -2, 주유소 세차 | 날짜/재시작 이월, 비용·시간·미납·중복 거래, 3해상도 HUD |
| 2 | 높은 청결의 `S0 +3` 및 낮은 청결 승차 거부 | 기존 `M` 운임/법규 분리, 호출·길가 공통 처리, 거부 기록·재수락 방지 |
| 3 | 취객 특성·구토 발생과 하차 후 청결 급락 | 9코스·17요청 유지, 운송당 1회·저장 복원, 기존 탑승 승객 운송 완료 |
| 4 | 유효 도착 시각 확정·기상 지연 상태 | 15/30초 경계, 도착 기한과 하차 시각 분리, 이동/마감/시간 초과 예외, 중복 정산 방지 |
| 5 | 위치 제어·자동 물리·수동 하루 운행 | 취객·청결 변화의 빈도, 세차 이동·비용과 하루 순수익, 거부 피드백 체감 구분 검증 |

구토·기상 지연은 게임의 돌발 사건이며 실제 사고·수리 콘텐츠가 아니다. 사실 확인이 필요한 의학적 대응이나 강제 하차 조작은 프로토 범위에 넣지 않는다.
