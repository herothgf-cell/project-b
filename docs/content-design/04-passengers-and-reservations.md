# 승객 운송과 매너 및 요구 콘텐츠

기준일: 2026년 10월 19일 · 버전: 0.7 · 상태: 기존 구현 6de26a5 및 검증 결과 대조 + 운전·대화·돌발 요청 후속 기획 추가

승객은 목적지와 간단한 요구를 제공한다. 승객 매너는 이번 운송의 만족 조건이며, 누적 법규 성향과 별도로 평가한다. 아래 신규 수치는 게임용 조정 초깃값이다.

**2026-10-21 별도 기획:** [프로토 시나리오](09-prototype-scenarios.md)에 승객별 승차·하차 위치와 경로상의 법규/선택 상황 9코스를 추가했다. 기존 조용한 운행·도착 문의, 완료 운송 수에 따른 요청 교대, Y 수락·U 안전상 보류를 유지한다. 아래 DR/CH/EV 확장과 분리하며 코스 제작의 선행 조건으로 요청 확장을 요구하지 않는다. 코스는 기획 초안이며 게임 적용 전이다.

## 현재 구현과 검증 범위

조용한 운행/도착 문의, 수락·안전상 보류, 완료/시간 초과/연료 고갈의 운송 결과 저장이 구현됐다. 지급액·요구/최종 매너·감점 이유·응답 결과를 기록하며 운송 ID로 중복 기록을 막는다. 마감 시 미탑승 취소와 마지막 탑승 운송의 원래 기한 유지도 검사했다.

**남은 확인:** 위험 회피 급제동의 실제 주행 맥락과 합법적 대기 시 운송 기한 밸런스는 추가 검증이 필요하다. 개인 예약·단골은 계속 기획만 유지한다.

근거: [통합 검증](../prototype-completion-validation.md) · [개발 체크리스트](../prototype-development-checklist.md). 아래 상세 표는 목표 설계를 포함하므로 표의 ‘포함’만으로 검증 완료를 뜻하지 않는다.

## 운송 흐름과 예외

| 순서 | 플레이어 행동 | 결과·예외 |
|---|---|---|
| 선택 | 호출 3개 또는 길가 승객의 목적지·요금·기한·매너 요구 확인 | 수락 전 거절 무료, 동시 운송 불가 |
| 픽업 | 안내된 방향·위치에 정차 후 승차 | 주행 중·반대 방향에서는 탑승하지 않음 |
| 운송 | 경로 선택, 승객 요청 대응 | 탑승 때 매너 100점 및 운송 제한 시간 시작 |
| 하차 | 목적지의 지정 위치에 정차 | 지급액과 감점 이유, 법규 기록을 서로 다른 카드로 표시 |
| 시간 초과 | 기존 임무 실패 처리 | 운임 0원. 해당 운행 비용은 유지 |
| 연료 고갈 | 현재 구현: 현재 운송 즉시 종료 | 기본 운임 0원. 복구 30게임초는 영업 시간에만 반영하며 종료한 운송 기한을 재개하지 않음 |
| 영업 마감 | 신규 수락 중단 | 미탑승 호출 취소, 탑승 임무는 완료 또는 시간 초과 후 정산 |

기한은 상황별 정상 운전과 대기를 포함해 달성 가능하도록 조정한다. 기존 시간 초과 0원 규칙을 유지하되 합법적인 대기로 실패가 반복되는 코스는 기한·거리·교통을 먼저 보정한다. 법규 성향 점수로 시간을 연장하거나 운임을 깎지 않는다.

연료 고갈의 공급량·지원 비용·마감 경계는 [경제 기획](05-daily-operation.md)을 따른다. 연료 고갈 지원은 프로토에 포함하는 운영 예외이며, 사고 수리 콘텐츠와 구분한다. 위 흐름을 추가하는 게임 코드는 이번 문서 작업에서 변경하지 않았다.

## 매너 감점표

‘기존’은 기존 감점 값이며 요청 감점은 현재 추가 구현된 값이다. 같은 사건은 지속되는 동안 반복 감점하지 않으며 위험 회피·원인 불명 장면은 맥락을 확인한다.

| 요소 | 감점 | 상태 | 적용 조건과 예외 |
|---|---:|---|---|
| 신호·진행 방향 위반, 우회전 전 필요한 정지 위반 | -12 | 기존 | 같은 교차로의 중복 신호 감점 방지. 새 법규 점수를 그대로 복사하지 않음 |
| 비보호 좌회전·우회전 양보 위반 | -8 | 기존 | 기존 차량 양보 판정 유지, 보행자 판정과의 중복은 장면별 구분 |
| 차량·시설 충돌 | -10 | 기존 | 같은 충돌 연속 감점 방지. 상대 책임·복구 직후 접촉 판정 개선 필요 |
| 불필요한 급가속 | -3 | 기존 | 키 입력 1회가 아닌 지속 차량 움직임 기준 |
| 불필요한 급제동 | -4 | 기존 | 위험 회피 예외 코드 존재, 실제 주행 맥락 검증은 남음 |
| 도로 경계·인도 침범 | -5 | 기존 | 지속 침범 중 반복 차감하지 않음 |
| 조용한 운행 요청 미처리 | -5 | 구현 | 정차 후 응답 기회가 있었을 때 한 번. 안전상 보류는 감점 없음 |
| 도착 시간 문의 | 0 | 구현 | 응답을 유도하는 대사. 바쁜 교차로에서 미응답을 벌주지 않음 |
| 합법적 대기·우회, 부적절한 요구 거절 | 0 | 유지 원칙 | 승객의 재촉·불만 대사 자체를 감점 조건으로 쓰지 않음 |
| 법규 성향 점수 하락 | 0 | 분리 원칙 | 이 점수만으로 승객 매너·운임을 자동 변경하지 않음 |

출처: [현재 감점 코드](../../unity/YeongtongTaxi/Assets/Scripts/DrivingManners.cs), [점수·지급 코드](../../unity/YeongtongTaxi/Assets/Scripts/MannerLedger.cs). 현재 구현의 자동 감점과 위 표의 예외 보완안은 개발 시 구분해야 한다.

## 요구와 응답

| 요청 | 제공 방식 | 처리 | 완료 피드백 |
|---|---|---|---|
| 조용히 가고 싶어요 | 운송당 최대 1회 후보 | 간단 수락으로 조용한 모드 표시. 라디오 전체 기능은 불필요 | ‘조용히 운행하겠습니다’ |
| 얼마나 걸릴까요 | 정체 또는 경로 변경 뒤 1회 후보 | 현재 ETA 안내 버튼, 정차 때까지 보류 가능 | 예상 시간임을 표시 |
| 빨리 가 주세요 | 일부 승객의 상황 대사 | 법규와 기한 변경 없음 | 무리한 운전을 요구하는 추가 목표 없음 |
| 창문·음악 선곡·복잡한 대화 | 프로토 제외 | 후속 승객 변형 | 해당 없음 |

최대 1회는 요청 종류별 제한이 아니라 운송당 상호작용 요청 1개를 뜻한다. 재촉 대사는 핵심 판단 장면을 가리지 않는 빈도로 제공한다.

## 승객 요구 확장 기획 (2026-10-19 추가 · 후속 개발 대상)

이 절은 기존 구현과 분리한 **추가 콘텐츠 기획**이다. 아래 DR/CH/EV 항목은 구현·검증 완료로 간주하지 않는다. 현행 프로토의 조용한 운행/ETA 문의, `Y` 수락·`U` 안전상 보류, 운송당 요청 1개, 매너 지급률 100%/70%, 시간 초과 0원은 변경하지 않는다. 향후 유형을 늘릴 때도 법규 평가와 승객 만족도는 독립적으로 기록한다.

### 1. 운전 방식에 관한 요구 (DR)

| ID | 승객 요구/대사 | 운전자 목표와 기존 기능 연계 | 성공·실패 판단 / 안전 예외 | 후속 결과 |
|---|---|---|---|---|
| DR01 승차감 | “차멀미가 심해요. 부드럽게 운전해 주세요.” | 가감속·제동을 안정적으로 제어. 기존 `DrivingManners`의 급가속·급제동·충돌 판정 활용 | 운송 중 불필요한 급가감속·충돌 최소화. 돌발 위험 회피의 필요한 급제동은 실패로 취급하지 않음 | 부드러운 운행 달성/미달 표시; 추가 팁은 미확정 |
| DR02 정시 도착 | “급해요. 최대한 빨리 가 주세요.” | 내비의 빠른 길/짧은 길 비교 후 합리적인 경로 선택 | 기존 운송 제한시간 내 도착 및 법규 준수. 위반·위험 운전으로 시간을 벌도록 보상하지 않으며 신호 대기·우회 감안해 기한 조정 | 정시 도착 결과와 만족도 표시; 보너스 수치는 후속 조정 |
| DR03 큰길 선호 | “골목길 말고 큰길로 가 주세요.” | 도로 폭·차로수 기반 큰길 우선 경로 선택(경로 옵션 확장 필요) | 경로 그래프상 큰길 후보가 있는 경우에만 출현. 현실 도로 규제 미확인 구간은 확정적으로 안내하지 않음 | 선호 경로 이행/불가 안내를 운송 결과에 기록 |
| DR04 짧은 길 선호 | “골목길이어도 괜찮으니 짧게 가 주세요.” | 짧은 길 선택을 우선 검토 | 합법·주행 가능한 도로만 사용. 좁은 길·일방통행·회전 금지 불확실 구간을 임의 통과하지 않음 | 경로 선택 결과와 승객 반응 |
| DR05 안전 정차 | “여기서 바로 세워 주세요!” | 안전한 정차 지점 탐색 후 하차 제안 | 교차로·횡단보도·통행 방해 등 위험한 곳에서는 즉시 정차 요구를 거절하고 가까운 안전 지점을 안내 | 안전 정차 선택은 감점 없음; 실제 하차 지점 변경은 후속 경유/하차 처리 필요 |

**설계 경계:** DR01·DR02는 기존 물리/매너·내비 데이터를 활용하는 우선 후보이지만, 승객 전용 목표 판정기와 결과 기록은 신규 개발이다. DR03·DR04는 단순 `Tab` 빠른 길/짧은 길과 별개의 *큰길 우선* 경로 비용 계산이 필요하다. DR05는 지정 승하차 지점 규칙을 유지하면서 안전 정차 가능 위치를 선별하는 후속 시스템이 필요하며, 현재 어디서든 하차 가능한 기능으로 해석하지 않는다.

### 2. 대화와 편의에 관한 요구 (CH)

대화 선택은 실제 운전 중 긴 텍스트 입력을 요구하지 않는다. 짧은 선택지 2~3개와 자동 응답 문구를 제공하고, 복잡한 선택은 안전 정차 시에만 허용한다. 대화는 승객을 인간적으로 느끼게 하는 짧은 연출이며 관계도/단골 시스템을 이번 절에 도입하지 않는다.

| ID | 승객 대사/요구 | 응답 선택지 예시 | 설계 결과·주의점 |
|---|---|---|---|
| CH01 고민 이야기 | “오늘 속상한 일이 있었어요.” | “무슨 일 있으셨어요?” / “조용히 가실까요?” | 공감 또는 조용한 응대 모두 존중. 대화 강요·침묵 페널티 없음 |
| CH02 길 추천 | “어느 길로 가는 게 좋을까요?” | “빠른 길” / “짧은 길” | 현재 내비의 ETA·거리 비교와 연계. 제안 후 안내한 경로 적용 여부를 명확히 표시 |
| CH03 면접 응원 | “오늘 면접인데 잘할 수 있을까요?” | “응원합니다!” / “조용히 준비하실 수 있게 운행할게요.” | 짧은 격려/배려 대사와 종료 반응. 합격 여부 등 외부 결과를 게임이 단정하지 않음 |
| CH04 음악 변경 | “라디오 음악 좀 바꿔 주세요.” | “바꿔 드릴게요.” / “안전한 때에 조절할게요.” | 초기에는 텍스트 반응만. 실제 오디오·선곡·라디오 UI는 별도 구현 이후에만 연동 |
| CH05 요금 부족 | “택시비가 조금 부족한데요.” | “요금 안내해 드릴게요.” / “가능한 결제 방법을 확인해 볼게요.” | 현재 약정 운임·지급률을 임의로 바꾸지 않음. 할인/미수금은 별도 경제 기획 및 동의 흐름 결정 후 개발 |
| CH06 동네 대화 | “이 동네에서 오래 일하셨어요?” | “이 근처는 익숙해요.” / “안전하게 모셔다드릴게요.” | 게임 내 지역 대사만 사용. 실제 현장 지식이나 사실 미검증 정보를 보장하지 않음 |

**대화 규칙:** 기본 승객 요청이 이미 진행 중이면 새 대화창을 중첩하지 않는다. 진행 중 대화는 교차로·회전·긴급 제동 등 운전 집중 구간에선 자동 연기하며, 응답 지연 자체를 감점하지 않는다. 응답 선택이 승객 취향과 다르더라도 법규 위반 또는 매너 위반으로 환산하지 않는다. 음악·창문 등의 차량 조작은 현행 프로토 범위 밖이다.

### 3. 운행 도중 발생하는 돌발 요청·사건 (EV)

| ID | 사건 트리거 / 승객 대사 | 플레이어 선택 | 상태·경로·운임 처리 방향 | 예외·완료 피드백 |
|---|---|---|---|---|
| EV01 목적지 변경 | 운행 중 “다른 곳으로 목적지를 바꿀 수 있을까요?” | 새 목적지 수락 / 원래 운행 유지 제안 | 수락하면 목적지·경로·ETA·약정 요금을 재계산하는 **미래 기능**. 변경 전후 조건을 승객/운전자에게 확인 | 접근 불가 목적지·마감 충돌 시 거절 가능, 위반 없이 거절하면 감점 없음. 변경 내역은 같은 운송 ID에 기록 |
| EV02 중간 경유 | “약국에 잠깐 들렀다 가 주세요.” | 경유 수락 / 경유 불가 안내 | 안전한 경유 정차 지점, 추가 거리·시간·요금의 사전 안내 필요. 경유 중 운송 상태를 유지하는 단계 신설 | 경유 중 시간 정지·무료 연장 자동 적용 금지. 제한시간 및 요금 정책 합의 후 구현 |
| EV03 분실물 | 하차 뒤 지갑 등을 발견하거나 다음 손님이 분실물 발견 | 분실물 보관·신고 / 안전한 전달 절차 안내 | 이전 운송 ID와 연결되는 별도 후속 사건으로 기록. 새 탑승/운임 중복 지급 없이 진행 | 기본 구현에서는 실제 물건·인벤토리/반환 경로 없음. 향후 보상·후속 퀘스트 검토 |
| EV04 불법 요구 | “빨간불이어도 그냥 가 주세요.” | 안전을 이유로 거절 / 정차 후 설명 | 불법 요구를 수락 가능한 운전 미션으로 만들지 않음. 실제 교통 위반은 기존 독립 법규 관찰기가 판정 | 거절·안전상 보류는 감점 없음. 무리한 운전에 추가 보상을 지급하지 않으며 승객 대사와 법규 판정 분리 |

**돌발 이벤트 원칙:** 한 번에 처리 중인 요청 또는 돌발 이벤트는 하나만 노출한다. 기본 호출·승하차·운송과 충돌하거나 영업 마감이 임박하면 이벤트를 생성하지 않거나 안전하게 종료한다. 분실물 후속 사건은 기존 운송 결과를 수정하지 않으며, 별도 ID로 추적한다. 수락/거절 이후 상태를 저장·복구할 때 중복 요금·중복 이벤트가 발생하지 않도록 한다.

### 요구 콘텐츠 공통 운영·검증 기준 (후속)

| 항목 | 권장 규칙 / 검증 항목 |
|---|---|
| 표시 시점 | 탑승 직후 또는 주행이 안정된 순간에 짧은 대사 표시. 교차로·좌우회전·위험 발생 중 팝업 확대 금지 |
| 응답 방식 | 기존 `Y` 수락·`U` 안전상 보류 호환을 우선. 다지선다 선택은 안전 정차 또는 간단 입력으로 제한 |
| 요청 빈도 | 초기 확장 검증은 **운송당 핵심 요청 1개**를 유지. 돌발 상황의 추가 출현 빈도는 플레이테스트 후 결정 |
| 성공 판정 | 운송 목표와 요청 목표 분리. 합법적 대기·위험 회피 급제동·정당한 거절을 실패로 잘못 판정하지 않음 |
| 보상 | 현행 약정 운임 100%/70%, 기한 초과 0원 유지. 팁·별도 보너스·할인·경유 할증은 경제 정책 결정 전 미지급 |
| 기록 | 운송 ID, 요청 ID, 유형, 발생 시점, 수락/거절/보류, 판정 근거, 완료 결과를 남기는 모델 제안. 법규 기록은 독립 |
| 프로토 회귀 | 기존 요청 2종, 안전상 보류 무감점, 요청의 중복 확정 방지, 3일 경제·정산·저장, 기본 경로 및 승하차 동작 유지 |
| 검증 상태 | 표에 있는 새 요청은 **기획만 완료**. C# 단위 검사와 Unity Player 상황별/수동 운행 검증 전까지 ‘구현’으로 승격하지 않음 |

**개발 분할 제안:** 1차는 DR01·DR02·CH02·CH03·EV04처럼 현재 시스템을 재사용하는 요청, 2차는 DR03·DR04·DR05·EV01·EV02의 경로/하차 상태 변경, 3차는 CH04·CH05·EV03처럼 별도 차량 편의·경제·후속 사건 시스템이 필요한 콘텐츠로 구분한다. 이는 일정 확정이나 구현 지시가 아니라 기획 우선순위이다.

## 매너 실패와 보상

| 종료 상태 | 지급 | 다른 결과 |
|---|---:|---|
| 기한 내 완료·매너 요구 이상 | 약정 운임 100% | 운송 완료 |
| 기한 내 완료·매너 요구 미달 | 약정 운임 70% | 부족 점수와 주요 감점 이유 표시 |
| 매너 0점이지만 기한 내 완료 | 약정 운임 70% | 자동 게임오버·추가 벌금 없음 |
| 시간 초과 | 0원 | 기존 처리. 중복 미달 페널티 없음, 이미 발생한 비용 유지 |
| 연료 고갈로 운송 종료 | 기본 운임 0원 | 신규 프로토 설계. 이미 발생한 비용 유지, 지원 뒤 같은 임무를 재개·재지급하지 않음 |
| 하루 정산·다음 승객 | 해당 없음 | 법규 히스토리 유지, 승객 매너는 다음 탑승 때 초기화 |

예시: 약정 5,000원·요구 70점에서 신호 -12, 충돌 -10, 양보 -8이면 70점으로 5,000원 지급한다. 별도 급제동 -4가 적용되면 66점으로 3,500원 지급한다. 법규 사건 기록은 별도로 남는다. 원 단위 절사는 기존 정수 계산을 따른다.

## 단골과 개인 예약의 후속 기획

단골·개인 예약은 사용자 결정에 따라 이번 프로토에서 제외한다. 아래 표는 후속 개발을 위한 설계이며 현재 기능이나 프로토 완료 조건이 아니다. 연락 동의·제안·알림은 가상 승객과 게임 안에서 주고받는 연출이며 실제 연락처 수집이나 외부 메시지 전송을 뜻하지 않는다.

| 단계 | 진입·표시할 정보 | 플레이어 선택 | 다음 상태·관계 피드백 |
|---|---|---|---|
| 일반 승객 운송 | 기존 목적지·매너 요구·간단 요청 | 기존 호출 또는 길가 운송 수행 | 완료 결과와 요청 대응을 기록. 한 번의 운송으로 단골을 확정하지 않음 |
| 재이용·선호 확인 | 다시 만난 승객의 게임 내 이름·이전 요청·선호 | 기억한 선호에 응답, 현재 운송 우선 | 승객이 재이용 의사를 보이는 관계 단계로 연결. 발생 빈도·조건은 미정 |
| 예약 연락 동의 | 승객의 게임 내 예약 제안 수신 요청 | 동의 또는 거절. 나중에 수신 중지 가능 | 동의한 관계에만 개인 예약 후보 생성. 거절 자체로 기존 운임·매너·법규 점수를 깎지 않음 |
| 예약 제안 | 희망 날짜·픽업 시간 범위·장소·목적지·예상 운임·선호 | 조건과 현재 일정을 확인 | 수락 전에는 약속이나 점유 시간으로 확정하지 않음 |
| 수락·거절 | 이동·예상 운송 시간과 필요한 여유 | 수락, 거절, 조건 변경 제안 | 수락해야 예약 확정. 거절은 무료를 기본 제안으로 두고, 변경은 승객의 게임 내 재동의 후 확정 |
| 시간 충돌 확인 | 현재 운송·기존 예약·마감 시간과 겹침, 예상 지각 | 신규 제안 거절 또는 확정 전 시간 변경 | 다른 예약을 몰래 취소하거나 강제 중복 수락하지 않음. 예약 후 교통 지연이 생기면 지연 안내·변경·취소 선택 |
| 픽업 접근 | 약속 시간 범위·안내 경로·대기 장소 | 안전하게 이동·정차, 필요하면 지연 안내 | 수락 시각과 도착 시각을 구분. 신호 위반을 전제로 한 기한을 설정하지 않음 |
| 예약 승차·운송 | 승객 확인·현재 요구·목적지 | 기존 운송 흐름으로 승차·운송·하차 | 승차 때 운송별 매너와 기한을 시작. 예약 약속 기록은 별도 유지 |
| 완료 | 실제 지급액·약속 이행·요청 대응 | 결과 확인 | 재이용 의사·선호 기억의 짧은 피드백. 예약 할증·팁·관계 보너스는 미정이며 자동 지급하지 않음 |
| 취소·미탑승 | 취소 주체·시점·사유, 지각·승객 부재 구분 | 사전 취소 또는 대기 종료 | 운송 완료와 구분하여 기록. 취소 수수료·대기 한도·관계 영향은 후속 결정 |
| 관계 피드백 | 약속 이행·사전 안내·선호 대응 기록 | 이전 결과 확인·예약 수신 중지 | 행동 근거를 설명하고 법규 성향과 자동 연동하지 않음. 낮은 관계를 운전 위반으로 기록하지 않음 |

| 예외 | 후속 처리 원칙 | 추가로 정할 것 |
|---|---|---|
| 합법적 대기·우회로 도착 지연 | 예상 도착 변경과 안내 여부를 기록. 지연만으로 법규·승객 매너 감점 확정 금지 | 지각 허용 범위·승객 응답 |
| 탑승 전 승객 취소·부재 | 빈차 이동과 약속 취소를 구분. 완료 운임을 지급하지 않음 | 취소 보상·노쇼 대기 시간 |
| 연료 부족·영업 종료와 충돌 | 수락 전 예상 부족을 알리고, 확정 뒤에는 안전한 운송 종료를 우선 | 예약 승계·재조정 여부 |
| 사고로 운행 불가 | [사고·수리 후속 기획](08-accidents-and-repairs.md)의 승객 중단·예약 변경 처리에 연결 | 운임·안내·관계 영향. 사고 범위와 함께 결정 |
| 재시작·중복 입력 | 예약 하나가 중복 확정·완료·취소되지 않도록 상태를 구분 | 예약 ID·저장 경계·기존 일일 저장 확장 |

| 후속 미정 항목 | 설계 경계 |
|---|---|
| 단골 조건·제안 빈도 | 횟수·확률·관계 점수 수치는 미정. 짧은 운송 경험을 해치지 않는 범위에서 검증 |
| 동시 예약 수·시간 여유 | 상한·픽업 시간 범위·허용 지각·대기 시간 미정. 확정 전 일정 충돌을 설명 가능해야 함 |
| 보상·취소 비용 | 기본 운임과 실제 지급의 중복을 막고, 적용 조건은 수락 전에 표시. 숫자는 후속 제안·검증 대상 |
| 확장 한계 | 개인 기사와 승객의 재이용·약속 경험에 한정. 직원·차량 증식·회사 배차·장기 경영으로 확장하지 않음 |
