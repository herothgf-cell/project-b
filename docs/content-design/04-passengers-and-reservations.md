# 승객 운송·운전 만족도·요청 기획

상태: 승객 운송과 요청 17종, 요구치 차이에 따른 운임·보너스, 게임 정차 후보·취객·청결도를 구현·자동 검증했다. 안정 주행 운전 만족도 회복(+2/구간·최대 +6)도 구현했다. 사람의 수동 운전과 경제 체감은 남아 있다. 기존 구현을 재구성한 변경 기록은 [별도 문서](04-passengers-and-reservations-history.md)에 보존한다.

회복을 조금 쉽게 하는 **미구현 기획안**은 [2026-10-26 운전 만족도·승객 만족도 회복 완화안](04-passengers-and-reservations-history.md#2026-10-26-운전-만족도승객-만족도-회복-완화안--기획만)에 있다. 아래 500m/60초·급가감속 감점만 회복하는 규칙은 현재 실행 기준이다.

관련 기획: [요청별 선택·효과·결산](11-passenger-request-effects.md) · [승하차 지점 다양화](14-passenger-stop-variety.md) · [취객·청결도](15-drunk-passengers-and-cleanliness.md) · [9개 상황 코스](09-prototype-scenarios.md) · [법규 성향](02-driving-evaluation.md) · [일일 경제](05-daily-operation.md) · [캠페인](07-campaign.md) · [프로토 범위](../prototype-scope.md).

## 시스템의 역할과 적용 범위

| 요소 | 게임 안에서 하는 일 | 현재 구현 / 다음 개발 |
|---|---|---|
| 호출·길가 승객 | 조건을 확인하고 승객 한 팀을 운송 | 구현. 지도에서 호출 선택 후 별도 수락, 픽업·하차 |
| 운전 만족도 `M` | 이번 운송의 실제 주행과 안전을 평가. 탑승 시 100점 | 감점·급가감속 감점의 안정 주행 회복 구현. 물리 주행 체감은 후속 |
| 최종 승객 만족도 `S` | 시작 기대치, 주행, 요구 이행, 도착 시간을 합산해 하차 평가 | `S0 + 주행 변화 + 요청 변화 + 도착 시간 가산` 구현. HUD·알림·결과는 같은 S를 표시 |
| 요구 만족도 `R` | 승객이 바라는 기준 60·70·85점 | 구현. 새 기획에서는 `S >= R`부터 보너스 |
| 법규 성향·운행 점수 | 위반·준수의 독립적인 장기 기록 | 별도 시스템. 요청 대답만으로 가감하지 않음 |
| 취객·차량 청결도 | 운송 중 구토, 도착 후 기상 지연, 다음 승객 승차 거부와 주유소 세차 | [취객·청결도](15-drunk-passengers-and-cleanliness.md) 구현·자동 검사. 기존 요청 1개 제한과 별도 |
| 단골·개인 예약 / 사고 수리 | 후속 운송·관계·중단 상황 | 기획만, 프로토 제외. [사고·수리](08-accidents-and-repairs.md) 참조 |

운전 만족도는 운송마다 초기화되며 법규 성향 점수의 다른 이름이 아니다. 운전자 피로·포만감은 새 승차 가능 시점에 영향을 주되 주행 점수나 운임을 직접 변경하지 않는다([운전자 상태](10-driver-condition.md)).

## 운송 흐름과 예외

| 단계 | 플레이어 판단·조작 | 상태·결과 |
|---|---|---|
| 호출 선택 | 지도 핀/목록에서 출발·도착, 예상 운임·기한, `R`, 접근 경로 확인 | 선택만으로 배차하지 않음. 별도 수락 버튼 또는 길가 승차. 호출 카드에는 탑승 후 요청을 미리 공개하지 않음 |
| 픽업 | 현재 도로 방향에 맞춰 승차 위치에 저속 정차 | 호출 수락부터 픽업 기한 `max(180초, 실제 접근 경로거리/3 + 180초)`. 기한 초과면 미탑승 호출 취소 |
| 탑승·운송 | `M=100` 시작, 요청 1개 제시, 경로·운전·응답 선택 | 승하차는 교통 상황 체험을 필수 조건으로 삼지 않음. 승차 시 `S0=clamp(R-D+청결 가산,0,100)`을 확정·저장. `D=-12,-8,-4,0,4,8,12`로 요구치 미만·동일·초과가 모두 가능 |
| 하차 | 지정된 안전 지점에 방향·저속 조건을 맞춰 정차 | 기본 운임, 보너스, 운전 만족도 변화, 요청 결과, 법규 기록을 구분 표시. 운송 ID로 중복 정산 방지 |
| 운송 시간 초과 | 승객을 목적지까지 유지 | 실제 하차 후 기본 운임·보너스 모두 0원. 발생한 비용은 유지 |
| 연료 고갈·영업 마감 | 연료 지원 또는 새 승차 중단 | 탑승 중 지원 시 같은 운송·내비·기한 유지, 20% 주유·1,800원·30게임초. 마감 전 탑승 승객은 하차까지 운송 |

승하차 성공 시 비상등이 켜지고 출발하면 해제된다. 하차 결과 팝업에서는 운송·영업 시간을 멈추고 다음 호출 수락을 막는다. 일반 영업의 새 승하차 후보는 [14](14-passenger-stop-variety.md)에서 정의하며 고정 9코스와 기존 S01~S12를 유지한다.

취객이 도착 후 바로 깨지 않으면 유효 도착 시각을 먼저 확정하고 최대 30게임초 동안 하차를 기다린다. 영업 시계는 흐르지만 기상 지연만으로 이미 정시에 도착한 운송을 시간 초과로 바꾸지 않는다. 구토한 취객의 차량 청결도 급락은 **실제 하차 뒤** 적용한다. 자세한 상태·확률·예외는 [취객·청결도 기획](15-drunk-passengers-and-cleanliness.md)을 따른다.

## 운전 만족도 감점·상승 요인

`M`은 주행 경험을 보여주는 0~100점이다. 감점과 안정 주행 회복을 구현했다. 법규 위반 여부 자체는 [법규 성향](02-driving-evaluation.md)에 따로 남긴다. 요청의 실제 이행은 원칙적으로 `S`의 요청 변화에 반영하고 `M`에 다시 더하지 않는다.

| 운전 사건 | `M` 변화 | 상태 | 판정·예외 |
|---|---:|---|---|
| 신호·진행 방향 또는 우회전 전 정지 위반 | -12 | 구현 | 같은 교차로 사건 중복 차감 방지 |
| 좌·우회전 양보 위반 | -8 | 구현 | 관찰된 해당 통행 사건만 반영 |
| 차량·시설 충돌 | -10 | 구현 | 같은 접촉의 연속 차감 방지. 사고 콘텐츠는 별도 |
| 불필요한 급가속·급제동 | 각 -2 | 구현 | 지속 움직임 기준. 필요한 위험 회피 제동은 제외 |
| DR01 차멀미 요청 수락 뒤 불필요한 급가속·급제동 | 각 -4 | 구현 | 위 -2를 **대체**, 더하지 않음. 수락 전 사건에 소급 적용하지 않음 |
| 도로 경계·인도 침범 | -5 | 구현 | 지속 침범 중 반복 차감 방지 |
| 조용한 운행 요청을 안전한 응답 기회가 있는데 놓침 | -5 | 구현 | 안전상 보류·응답 불가능 상황은 감점 없음 |
| 안정적인 주행 구간 | +2/구간, 운송당 최대 +6 | 모델·편집기 검증, 물리 주행 후속 | 불필요한 급가감속 없이 실제 이동 500m 또는 이동 중 누적 60초마다 1회. 정차·동일 구간 반복으로 쌓지 않음. 해당 운송의 **급가감속으로 잃은 점수만** 회복하고 100점 상한 |
| 합법적 신호 대기·우회, 위험 회피 제동, 부적절한 요구 거절 | 0 | 유지 원칙 | 불이익 없음. 서 있는 것만으로 회복 점수도 주지 않음 |

회복은 안전하고 부드러운 운전을 운송 중 회복 기회로 표현한다. 충돌·신호·양보·인도 침범 감점은 이 규칙으로 지우지 않는다. 예를 들어 급제동 -2 뒤 안정 주행을 충족하면 +2로 돌아오지만, 신호 위반 -12 뒤 안정 주행만으로 12점을 회복할 수 없다. 실제 이동한 10m 공간 칸마다 거리 14m·이동 시간 20초까지만 쌓는다. 각 칸은 처음 진입한 방향에서 더 멀리 전진한 부분만 인정하고, 칸을 떠난 뒤 재진입해도 다시 적립하지 않는다. 정차·같은 구간 왕복 적립을 막으며, 활성 칸의 진행 상태까지 운송 저장에 포함한다. 회복 조건·거리·상한은 물리 주행 테스트에서 조정할 초깃값이다. DR01의 개별 급가감속은 `M`에서 한 번만 차감하고, 요청 전체 이행 여부는 하차 때 `Δrequest`로 한 번 판정한다. 구현 근거: [DrivingManners.cs](../../unity/EungyeTaxi/Assets/Scripts/DrivingManners.cs) · [MannerLedger.cs](../../unity/EungyeTaxi/Assets/Scripts/MannerLedger.cs).

### P8-07 안정 주행 회복 구현 사양 (2026-10-26 검토안)

기존 +2/구간·운송당 최대 +6의 의미를 다음과 같이 고정한다. 승차 후 **실제 전진 이동**에서 속도 1m/s 이상인 표본만 적립한다. 이전에 같은 운송에서 통과한 도로 구간·방향의 거리는 다시 적립하지 않는다. 정차·후진·순간 이동·위치 복구·운송 외 이동은 거리와 시간에 넣지 않는다. 새 구간에서 누적 **고유 이동 거리 500m 또는 이동 중 60초** 중 하나를 먼저 달성하면 회복 기회 1회를 판정하고 해당 누적값을 소모한다. 두 조건을 동시에 달성해도 1회이며 같은 표본을 다음 구간에 이월하지 않는다.

급가속·급제동의 실제 감점액만 `회복 가능 잔액`에 더한다. 감점이 쿨다운에 막혔거나 필요한 위험 회피 제동이면 더하지 않는다. 회복액은 `min(2, 회복 가능 잔액, 6-해당 운송 누적 회복액, 100-M)`이다. 감점이 없는 안정 주행은 100점을 넘기거나 미래 감점을 대비해 회복을 예치하지 않는다. 충돌·신호·양보·도로 경계·미응답 감점은 회복 가능 잔액에 들어가지 않는다. 급가감속 사건이 발생하면 진행 중인 안정 구간 거리·시간을 0으로 돌리고 새 관찰을 시작한다.

승차·다음 운송에서 회복 가능 잔액/누적 회복액/진행 거리·시간/고유 통과 구간을 새로 시작한다. 영업 중 저장·복원에는 이 값들을 보존하고, 구형 저장에는 0에서 시작한다. 회복 사건은 `운전 만족도 +2 · 안정 주행`처럼 즉시 알리고 `M`, 실시간 승객 만족도 `S`, 하차 결과/F8에 한 번만 반영한다. 법규 성향 점수는 변경하지 않는다. 모델 경계 검사와 위치 제어 검사는 물리 주행·수동 20분 경제 체감을 대신하지 않는다.

## 최종 승객 만족도와 운임

| 값·판정 | 적용 규칙 | 구현 상태 |
|---|---|---|
| 시작 만족도 `S0` | `clamp(R - D + Δclean,0,100)`, `D`는 승객별 `-12,-8,-4,0,4,8,12` 중 하나. 승차 시 청결도 80점 이상이면 `Δclean=+3`, 아니면 0. 승객 후보 ID에 묶어 저장·복원 | 요구치 미만·동일·초과 시작 구현, 청결 +3은 S0에 한 번 포함 |
| 주행 변화 `Δdrive` | `M - 100`. 위 감점과 회복이 반영됨 | 운전 만족도 감점·회복 반영 |
| 요청 변화 `Δrequest` | 실제 이행·미이행·정당한 보류의 결과만 반영 | 17종의 기존 결과 판정 |
| 시간 변화 `Δtime` | 탑승 시 정상 내비 ETA 대비 **안전한** 조기 도착에 0~12점. 늦었다는 이유만으로 추가 감점 없음 | 첫 유효 도착에 확정·저장. 운행 중 예상 가산 없음 |
| 최종 `S` | `clamp(S0 + Δdrive + Δrequest + Δtime, 0, 100)` | 구현. 운행 중 주행·확정 요청 변화, 도착 후 확정 결과 표시 |
| 기본 운임 | 기한 내 최종 `S`가 `R`에 못 미치면 차이 1점당 최종 약정 운임의 0.5%씩 감액(최대 20%, 10원 단위 내림). `S >= R`이면 100%, 시간 초과면 0원 | 구현·모델/위치 제어 검사 |
| 보너스 | 기한 내 `S >= R`이면 지급. 요구치 `R=60/70/85`에 따라 상한과 초과 1점당 증가폭을 높임 | 구현·모델/위치 제어 검사 |

변경 운임·보너스의 수치 예시와 정산 경계는 [11 운임 개정안](11-passenger-request-effects.md#2026-10-26-운임·보너스-개정안)을 따른다. 운전 만족도 `M`은 주행 변화 `M-100`으로 `S`에 반영하며 기본 운임에서 다시 별도 문턱으로 판정하지 않는다. 위험 운전으로 시간을 줄였다면 시간 가산은 0이다.

## 승객 요청과 응답

탑승 후 운송당 핵심 요청 **1개**를 제시한다. 말풍선의 선택지를 마우스로 고르며 Y/I/O/U 키는 동일한 선택 처리에 연결한다. 차량 이동 중 또는 교차로 인접 시 응답을 보류하고 안전 정차 후 선택한다. 응답 지연이나 합법적 거절·보류만으로 점수를 깎지 않는다. 버튼 자체가 보상이 아니라 **이후 실제 행동·안내**가 평가 대상이다.

| 유형 | 요청·선택의 핵심 | 적용 효과와 하차 판정 |
|---|---|---|
| 기본 · 조용한 운행 | 조용히 운행 / 안전상 보류 | 후속 대사를 줄이고 실제 조용한 응대 시 요청 만족 +5. 안전한 기회가 있었는데 무시했다면 `M` -5와 중복 요청 감점 없음 |
| 기본 · 도착 시간 문의 | 내비 ETA보다 조금 빠르게 / 내비 시간만큼 / 조금 여유롭게 / 보류 | 안내 시각을 기록해 실제 도착과 비교. 선택만으로 차 성능·기한·경로·요청 만족도 변경 없음 |
| DR01 승차감 | 부드러운 운전 약속 / 보류 | 수락 뒤 불필요한 급가감속의 `M` 감점 각 -4 대체. 실제 승차감으로 요청 결과 판정 |
| DR02 정시 도착 | 가능한 빠른 합법 경로 / 보류 | 원래 기한과 실제 위반을 확인. 재촉만으로 기한 변경·불법 운전 보상 없음 |
| DR03 큰길 선호 | 큰길 경로 / 보류 | 큰길 후보가 있을 때만 제시, 내비와 실제 큰길 주행 비율 비교 |
| DR04 짧은 길 선호 | 합법적인 짧은 길 / 보류 | 실제 경로·거리 비교. 합법적 우회는 미이행으로 단정하지 않음 |
| DR05 안전 정차 | 검증된 하차 후보 수락 / 원래 장소 유지 | 후보·추가 거리·약정·기한을 먼저 확인하고 실제 지정 지점 하차를 판정 |
| CH01 고민 대화 / CH03 면접 | 공감·격려 / 조용한 배려 / 보류 | 강요 없이 응대와 후속 반응을 평가. 외부 사건 결과를 단정하지 않음 |
| CH02 길 추천 | 빠른 길 / 짧은 길 / 보류 | 현재 내비의 ETA·거리 차이를 보여주고 선택 경로를 적용 |
| CH04 음악 / CH05 요금 부족 | 제공 범위 또는 약정·결제 안내 / 보류 | 실제 오디오 변경·할인·미수금 없이 정확히 안내했는지 평가 |
| CH06 지역 대화 | 지역 응답 / 안전 운행 안내 / 보류 | 사실 확인 안 된 지역 정보를 보장하지 않는 짧은 대화 |
| EV01 목적지 변경 / EV02 경유 | 새 지점·거리·요금·기한 확인 후 수락 / 원래 운행 | 같은 운송 ID 유지. 경유는 F 정차 확인 후 원래 목적지로 안내. 약정 변경과 보너스 별도 정산 |
| EV03 분실물 | 하차 후 보관·신고 / 전달 절차 안내 | 원래 운송의 별도 후속 텍스트 사건. 이미 끝난 만족도·보너스 소급 수정 없음 |
| EV04 불법 요구 | 안전하게 거절 / 정차 후 설명 | 불법 수락 선택지 없음. 거절은 중립, 실제 위반은 별도 관찰 |

DR의 실제 목표 달성/불필요한 미이행은 요청 변화 **+8/-10**, CH는 **+5/-5**, EV01~02는 **+6/-8**을 테스트 초깃값으로 쓴다. EV03·EV04와 ETA 문의는 요청 변화가 중립이어도 공통 `S>=R` 보너스 대상이다. 후보 없음·안전상 보류·합법적 우회·판정 불가는 중립으로 남긴다. 각 요청의 선택지 문구, 운행 중 피드백, 예외와 실제 구현 차이는 [11 요청별 효과](11-passenger-request-effects.md)를 기준으로 한다.

DR05·EV01·EV02의 새 장소는 기존 필수 상황 완료 후 **검증된 안전 지점**만 사용한다. 변경 전후 거리·약정·남은 기한을 표시하고 한 번 확정한다. 경유 중에도 운송 시간이 흐르며 목적지 변경·경유 자체로 법규 점수를 올리지 않는다. DR03/04의 목표를 판단할 수 없는 지연·우회는 판정 불가로 남긴다. 요청을 중첩 표시하거나 교차로에서 긴 선택을 강요하지 않는다.

## 단골과 개인 예약의 후속 기획

프로토에서는 제외한다. 일반 운송 → 재이용·선호 확인 → 게임 안의 연락 동의 → 조건이 보이는 예약 제안 → 일정 충돌 확인·수락 → 안전한 픽업·운송 → 약속 이행 피드백으로 잇는다. 거절·수신 중지는 가능하고 거절 자체로 운임·운전 만족도·법규 성향을 깎지 않는다. 한 번의 운송으로 단골을 확정하지 않는다. 동시 예약 수, 지각·노쇼, 취소 비용, 관계 보상은 후속 결정 사항이다. 당시 상세 단계와 예외는 [변경 기록](04-passengers-and-reservations-history.md#단골과-개인-예약의-후속-기획)에 보존한다.
