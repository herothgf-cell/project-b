# 승객 운송·운전 만족도·요청 기획

이 문서는 현재 콘텐츠 규칙과 다음 변경 목표를 다룬다. 날짜별 변경 경위와 이전 규칙은 [승객 기획 이력](../design-history/content-design/04-passengers-and-reservations-history.md)에 보존한다. 구현·검증 상태는 [개발 체크리스트](../prototype-development-checklist.md)와 [작업 이력](../work-history/LATEST.md)에서 확인한다.

관련 기획: [요청별 선택·효과·결산](11-passenger-request-effects.md) · [승하차 지점 다양화](14-passenger-stop-variety.md) · [취객·청결도](15-drunk-passengers-and-cleanliness.md) · [9개 상황 코스](09-prototype-scenarios.md) · [법규 성향](02-driving-evaluation.md) · [일일 경제](05-daily-operation.md) · [캠페인](07-campaign.md) · [프로토 범위](../prototype-scope.md).

## 시스템의 역할과 적용 범위

| 요소 | 게임 안에서 하는 일 | 현재 구현 / 다음 개발 |
|---|---|---|
| 호출·길가 승객 | 조건을 확인하고 승객 한 팀을 운송 | 구현. 지도에서 호출 선택 후 별도 수락, 픽업·하차 |
| 운전 만족도 `M` | 이번 운송의 실제 주행과 안전을 평가. 탑승 시 100점 | 감점·급가감속 감점의 안정 주행 회복 구현. 물리 주행 체감은 후속 |
| 최종 승객 만족도 `S` | 시작 기대치, 주행, 요구 이행, 도착 시간을 합산해 하차 평가 | `S0 + 주행 변화 + 요청 변화 + 안심 회복 + 도착 시간 가산` 구현. HUD·알림·결과는 같은 S를 표시 |
| 요구 만족도 `R` | 승객이 바라는 기준 60·70·85점 | `S >= R`부터 보너스 지급 |
| 법규 성향·운전 점수 | 위반·준수의 장기 기록, 승차 시 기본 운임 보정 | 신규 준수+3. 요청 대답만으로 가감하지 않음. `M`·`S`와 별도 |
| 취객·차량 청결도 | 운송 중 구토, 도착 후 기상 지연, 다음 승객 승차 거부와 주유소 세차 | [취객·청결도](15-drunk-passengers-and-cleanliness.md) 구현·자동 검사. 요청 건수와 별도 |
| 단골·개인 예약 / 사고 수리 | 후속 운송·관계·중단 상황 | 기획만, 프로토 제외. [사고·수리](08-accidents-and-repairs.md) 참조 |

운전 만족도는 운송마다 초기화되며 법규 성향 점수의 다른 이름이 아니다. 운전자 피로·포만감은 식사·휴식 선택과 졸음에 연결된다. 피로100에서도 초과 영업·새 승차는 가능하며, 상태값 자체로 점수나 운임을 직접 변경하지 않는다([운전자 상태](10-driver-condition.md)).

## 운송 흐름과 예외

| 단계 | 플레이어 판단·조작 | 상태·결과 |
|---|---|---|
| 호출 선택 | 지도 핀/목록에서 출발·도착, 예상 운임·기한, `R`, 접근 경로 확인 | 선택만으로 배차하지 않음. 별도 수락 버튼 또는 길가 승차. 호출 카드에는 탑승 후 요청을 미리 공개하지 않음 |
| 픽업 | 현재 도로 방향에 맞춰 승차 위치에 저속 정차 | 호출 수락부터 픽업 기한 `max(180초, 실제 접근 경로거리/3 + 180초)`. 기한 초과면 미탑승 호출 취소 |
| 탑승·운송 | `M=100` 시작, 운송별 요청 0~2개를 서로 다른 시점에 제시, 경로·운전·응답 선택 | 승하차는 교통 상황 체험을 필수 조건으로 삼지 않음. 승차 시 `S0=clamp(R-D+청결 가산,0,100)`을 확정·저장. `D=-12,-8,-4,0,4,8,12`로 요구치 미만·동일·초과가 모두 가능. 복수 요청은 변경 기획이며 현행 빌드 미적용 |
| 하차 | 지정된 안전 지점에 방향·저속 조건을 맞춰 정차 | 완료창은 최초 예상/운임 조정/실수령 3줄과 주요 만족도 원인. 운임·요청·법규 상세는 F8. 운송 ID로 중복 정산 방지 |
| 운송 시간 초과 | 승객을 목적지까지 유지 | 실제 하차 후 기본 운임·보너스 모두 0원. 발생한 비용은 유지 |
| 연료 고갈·예정 영업시간 경과 | 연료 지원 또는 초과 영업 | 탑승 중 지원 시 같은 운송·내비·기한 유지, 20% 주유·1,800원·30게임초. 20분 경과 시 피로100으로 초과 영업 가능, 빈차로 생활 거점에서 휴식·종료 |

승하차 성공 시 비상등이 켜지고 출발하면 해제된다. 하차 결과 팝업에서는 운송·영업 시간을 멈추고 다음 호출 수락을 막는다. 일반 영업의 새 승하차 후보는 [14](14-passenger-stop-variety.md)에서 정의하며 고정 9코스와 기존 S01~S12를 유지한다.

취객이 도착 후 바로 깨지 않으면 유효 도착 시각을 먼저 확정하고 최대 30게임초 동안 하차를 기다린다. 영업 시계는 흐르지만 기상 지연만으로 이미 정시에 도착한 운송을 시간 초과로 바꾸지 않는다. 구토한 취객의 차량 청결도 급락은 **실제 하차 뒤** 적용한다. 자세한 상태·확률·예외는 [취객·청결도 기획](15-drunk-passengers-and-cleanliness.md)을 따른다.

## 운전 만족도 감점·상승 요인

`M`은 주행 경험을 보여주는 0~100점이다. 감점과 안정 주행 회복을 구현했다. 법규 위반 여부 자체는 [법규 성향](02-driving-evaluation.md)에 따로 남긴다. 요청의 실제 이행은 원칙적으로 `S`의 요청 변화에 반영하고 `M`에 다시 더하지 않는다.

| 운전 사건 | `M` 변화 | 상태 | 판정·예외 |
|---|---:|---|---|
| 신호·진행 방향 또는 우회전 전 정지 위반 | -12 | 구현 | 같은 교차로 사건 중복 차감 방지 |
| 좌·우회전 양보 위반 | -8 | 구현 | 관찰된 해당 통행 사건만 반영 |
| 차량·시설 충돌 | -10 | 구현 | 같은 접촉의 연속 차감 방지. 사고 콘텐츠는 별도 |
| 불필요한 급가속·급제동 | 각 -2 | 구현 | 지속 움직임 기준. 필요한 위험 회피 제동은 제외 |
| DR01 차멀미 요청 수락 뒤 불필요한 급가속·급제동 | 각 -4 | 구현 | 위 -2를 **대체**, 더하지 않음. 수락 전 사건에 소급 적용하지 않음 |
| 도로 경계·인도 침범 | -5 | 구현 | 지속 침범 중 반복 차감 방지 |
| 조용한 운행 요청을 안전한 응답 기회가 있는데 놓침 | -5 | 구현 | 안전상 보류·응답 불가능 상황은 감점 없음 |
| 안정적인 주행 구간 | +2/구간, 운송당 최대 +6 | 모델·편집기 검증, 물리 주행 후속 | 불필요한 급가감속 없이 실제 이동 350m 또는 이동 중 누적 45초마다 1회. 정차·동일 구간 반복으로 쌓지 않음. 해당 운송의 **급가감속으로 잃은 점수만** 회복하고 100점 상한 |
| 합법적 신호 대기·우회, 위험 회피 제동, 부적절한 요구 거절 | 0 | 유지 원칙 | 불이익 없음. 서 있는 것만으로 회복 점수도 주지 않음 |

회복은 안전하고 부드러운 운전을 운송 중 회복 기회로 표현한다. 충돌·신호·양보·인도 침범 감점은 이 규칙으로 지우지 않는다. 예를 들어 급제동 -2 뒤 안정 주행을 충족하면 +2로 돌아오지만, 신호 위반 -12 뒤 안정 주행만으로 12점을 회복할 수 없다. 실제 이동한 10m 공간 칸마다 거리 14m·이동 시간 20초까지만 쌓는다. 각 칸은 처음 진입한 방향에서 더 멀리 전진한 부분만 인정하고, 칸을 떠난 뒤 재진입해도 다시 적립하지 않는다. 정차·같은 구간 왕복 적립을 막으며, 활성 칸의 진행 상태까지 운송 저장에 포함한다. 회복 조건·거리·상한은 물리 주행 테스트에서 조정할 초깃값이다. DR01의 개별 급가감속은 `M`에서 한 번만 차감하고, 요청 전체 이행 여부는 하차 때 `Δrequest`로 한 번 판정한다. 구현 근거: [DrivingManners.cs](../../unity/EungyeTaxi/Assets/Scripts/DrivingManners.cs) · [MannerLedger.cs](../../unity/EungyeTaxi/Assets/Scripts/MannerLedger.cs).

### 안정 주행 회복 규칙

승차 후 속도0.5m/s 이상인 실제 이동 표본을10m 공간 칸별 새 진행 경계로 적립한다. 같은 칸의 되돌아감·재진입, 정차·순간 이동·위치 복구·운송 외 이동은 적립하지 않는다. 새 구간에서 누적 **고유 이동 거리350m 또는 이동 중45초** 중 먼저 달성한 조건으로 회복 기회1회를 판정하고 누적값을 소모한다. 두 조건을 동시에 달성해도1회이며 같은 표본을 다음 구간에 이월하지 않는다.

급가속·급제동의 실제 감점액만 `회복 가능 잔액`에 더한다. 감점이 쿨다운에 막혔거나 필요한 위험 회피 제동이면 더하지 않는다. 회복액은 `min(2, 회복 가능 잔액, 6-해당 운송 누적 회복액, 100-M)`이다. 감점이 없는 안정 주행은 100점을 넘기거나 미래 감점을 대비해 회복을 예치하지 않는다. 충돌·신호·양보·도로 경계·미응답 감점은 회복 가능 잔액에 들어가지 않는다. 급가감속 사건이 발생하면 진행 중인 안정 구간 거리·시간을 0으로 돌리고 새 관찰을 시작한다.

승차·다음 운송에서 회복 가능 잔액/누적 회복액/진행 거리·시간/고유 통과 구간을 새로 시작한다. 영업 중 저장·복원에는 이 값들을 보존하고, 구형 저장에는 0에서 시작한다. 회복 사건은 `운전 만족도 +2 · 안정 주행`처럼 즉시 알리고 `M`, 실시간 승객 만족도 `S`, 하차 결과/F8에 한 번만 반영한다. 법규 성향 점수는 변경하지 않는다. 모델 경계 검사와 위치 제어 검사는 물리 주행·수동 20분 경제 체감을 대신하지 않는다.

그 기회에 실제 `M` 회복이0이면 `S`의 안심 회복을 판정한다. `min(2,4-운송 누적 안심 회복,max(0,R-현재 S))`만큼 `Δcomfort`를 늘린다. `M` 회복이1점이라도 발생했다면 같은 기회의 안심 회복은0이다. 신호·충돌 등의 `M` 감점은 지우지 않으며 `S`의 안심 누적도4점을 넘지 않는다. 시작 만족도 미달에서도 안전한 새 구간을 주행하면 회복할 수 있다.

## 최종 승객 만족도와 운임

| 값·판정 | 적용 규칙 | 구현 상태 |
|---|---|---|
| 시작 만족도 `S0` | `clamp(R - D + Δclean,0,100)`, `D`는 승객별 `-12,-8,-4,0,4,8,12` 중 하나. 승차 시 청결도 80점 이상이면 `Δclean=+3`, 아니면 0. 승객 후보 ID에 묶어 저장·복원 | 요구치 미만·동일·초과 시작 구현, 청결 +3은 S0에 한 번 포함 |
| 주행 변화 `Δdrive` | `M - 100`. 위 감점과 회복이 반영됨 | 운전 만족도 감점·회복 반영 |
| 요청 변화 `Δrequest` | 실제 이행·미이행·정당한 보류의 결과만 반영 | 17종의 기존 결과 판정 |
| 시간 변화 `Δtime` | 탑승 시 정상 내비 ETA 대비 **안전한** 조기 도착에 0~12점. 늦었다는 이유만으로 추가 감점 없음 | 첫 유효 도착에 확정·저장. 운행 중 예상 가산 없음 |
| 안심 회복 `Δcomfort` | 위 안정 주행 기회에서 `M` 회복이 없을 때 +2/회·최대4·`R` 상한 | 별도 저장·알림·정산 |
| 최종 `S` | `clamp(S0 + Δdrive + Δrequest + Δtime + Δcomfort, 0, 100)` | 운송 중 주행·확정 요청·안심 변화, 도착 후 확정 결과 표시 |
| 기본 운임 | `S<R`이면 `floor10(min(F,A)×S/R)`, `S=0`이면0원. `S>=R`이면 보정 약정A 전액, 기한 초과0원 | 신규 운송부터 적용, 구형 정산 보존 |
| 보너스 | 기한 내 `S >= R`이면 지급. 요구치 `R=60/70/85`에 따라 상한과 초과 1점당 증가폭을 높임 | 구현·모델/위치 제어 검사 |

운임·보너스의 수치 예시와 정산 경계는 아래 계산 규칙을 따른다. 운전 만족도 `M`은 주행 변화 `M-100`으로 `S`에 반영하며 기본 운임에서 다시 별도 문턱으로 판정하지 않는다. 위험 운전으로 시간을 줄였다면 시간 가산은 0이다.

### 운임과 보너스 계산

`F`는 목적지 변경·경유를 반영한 최종 원약정 운임이며, `A`는 승차 시 고정한 운전 점수 `Dscore`로 보정한 약정이다. 운전 점수 0~70은 보정률 `0.9+0.1×Dscore/70`, 70~100은 `1+0.1×(Dscore-70)/30`을 적용한다. 즉 0/70/100점에 90%/100%/110%이며 `A=floor(F×보정률/10)×10원`이다. 점수의 관찰·누적은 [02 운전 점수](02-driving-evaluation.md#운전-점수와-운임-효과)를 따른다. 목적지 변경 때도 승차 당시 점수를 사용하고, 보너스 기준에는 보정 전 `F`를 써 점수 보정을 중복 적용하지 않는다.

- 신규 승차 정책4: `0<S<R`이면 기본 운임은 `floor(min(F,A)×S/R/10)×10원`. 요구치 미달에서는 승차 점수에 따른 양의 할증을 제외하고 기존 낮은 점수의 감액은 유지한다. `S=0`이면 기본 운임·보너스 모두0원, `S>=R`이면 `A` 전액이다. 예: `F=11,300원, A=12,430원, R=60`에서 `S=48/30/0`이면 `9,040/5,650/0원`이다. 과거 최대20% 감액 제한은 신규 운송에 적용하지 않는다.
- 보너스 상한 `C=floor(min(F×0.10,500원)×w(R)/10)×10원`. `R=60/70/85`의 가중치 `w`는 각각 `0.8/1.0/1.3`이다. 보너스는 시간 내 `S>=R`일 때 `floor(C×[0.2+0.8×(S-R)/(100-R)]/10)×10원`, 미달이면 0원이다. 요구치 100은 현재 목록에 없으며 도입 시 분모 예외를 정한다.
- `F=5,000원`에서 `R=60`은 `S=60/80/100`에 `80/240/400원`, `R=70`은 `S=70/85/100`에 `100/300/500원`, `R=85`는 `S=85/93/100`에 `130/400/650원` 보너스다.
- 첫 유효 도착이 기한을 넘으면 기본 운임·보너스 모두 0원. 취객 기상 대기는 첫 도착 판정을 바꾸지 않는다. 픽업 취소·승차 거부도 지급하지 않는다.
- HUD는 현재 `S`와 `R`, 상세 F8은 `S0 / Δdrive / Δrequest / Δcomfort / Δtime / S / R`을 사용한다. 청결 +3은 `S0`에 포함되며 다시 더하지 않는다. F8은 원약정·운전 점수 보정·만족도 감액·기본 운임·계산용 보너스·합계를 구분한다. 완료창은 최초 예상/운임 조정/실수령의 3줄을 유지한다. 기존 완료 운송은 저장된 정산을 보존하고 소급 재계산하지 않는다. 진행 중 구형 운송은 기존 정책2/3 약정을 유지하고 신규 승차부터 정책4를 저장한다. 만족도0으로0원이 된 운송을 시간초과라고 표시하지 않는다.

수치들은 현재 구현의 시험값이며 수동 경제 밸런스 완료를 뜻하지 않는다. 요청 종류별 보너스 제외 규칙이나 과거 `M>=R` 100%/미달70% 지급 규칙을 함께 적용하지 않는다.

## 승객 요청과 응답

### 요청 배정과 등장 시점 · 변경 기획, 미구현

현행 빌드는 완료 운송 수 순서로 17종을 순환하므로 첫 운송이 항상 `조용히 운행해 주세요`다. 또한 운송당 1개를 승차 직후 제시한다. 다음 변경에서는 호출/길가 승객 모두 **승객 후보 ID를 시드로 요청 0~2개**를 배정한다. 첫 승객·특정 출발지에 특정 요청을 고정하지 않는다. 시험 비율은 0개 20%·1개 60%·2개 20%다. 같은 호출 재표시·재수락·저장 복원으로 목록·순서·등장 시점이 바뀌지 않으며 완료 운송 수에 따라 요청 종류를 고정하지 않는다. 정차 후보·승객 특성·시나리오별 적합성에 맞지 않는 요청은 후보에서 제외하고 남은 종류에서 중복 없이 뽑는다. 운송별 요청 수·비율·아래 시간과 점수 상한은 **이번 문서 정리에서 제안한 시험값**이며 사용자 지정 확정 수치가 아니다. 실제 빈도는 수동 플레이 후 조정한다.

| 시점 | 제시 규칙 |
|---|---|
| 승차 직후 | 배정된 요청 중 일부는 탑승 대사로 시작한다. 0건 또는 후반 요청만 배정된 운송에는 승차 시 요청이 없어도 된다. |
| 운행 중 | 남은 요청은 운송 진행률과 안전 정차 기회를 함께 본다. 신호 대기처럼 합법적으로 멈췄거나 안전한 승하차/시설 정차 구역에 멈췄을 때 갑자기 대사를 띄울 수 있다. 차량이 움직이거나 교차로 판단·사전 계획·정산 화면이 열렸을 때는 표시를 대기열에 둔다. 단순 정차를 만들려고 불법·위험 정지를 유도하지 않는다. |
| 하차 접근 | 새 요청을 시작하지 않는다. 후반 요청에 안전한 정차 기회가 없었다면 미발생으로 기록하고 감점하지 않는다. |

한 번에 대화는 하나만 표시한다. 첫 요청의 응답과 적용 목표를 보존한 상태로 다음 요청을 제시하되, 목적지 변경·경유·안전 하차처럼 경로나 약정을 바꾸는 요청은 한 운송에서 서로 충돌하지 않도록 최대 하나만 배정한다. 반대 요구(큰길/짧은 길, 조용한 운행/대화 등)는 함께 배정하지 않는다. 실제 행동을 평가할 수 있는 남은 거리·시간이 없는 요청은 늦게 발생시키지 않는다. 취객 특성·구토·기상 지연은 이 요청 수에 포함하지 않고 별도 사건으로 순차 알린다.

요청별 상태는 `예정 → 제시 → 응답/안전상 보류 → 관찰 → 하차 정산`으로 따로 저장한다. `Δrequest`는 각 요청의 **확정된 결과만 합산**하되 총합은 -10~+10으로 제한하고, 이미 `M`이나 다른 요청에서 평가한 동일 사건을 중복 감점하지 않는다. 제시되지 않은 요청·안전상 응답 기회가 없던 요청은 0점이다. 첫 유효 도착 시점 이후의 요청은 새로 발생하지 않는다. 하차 결과/F8은 요청별 시점·응답·실제 관찰·점수와 합계를 구분한다. 현행 단일 요청 운송의 저장·정산 이력은 기존 값으로 읽는다.

발생 시점도 함께 추첨한다. 첫 요청은 승차 직후/운행 중을 같은 비중으로 배정하고, 두 번째 요청은 운행 중에만 배정한다. 운행 중 예약은 최초 운송 경로 진행률 25~65%에서 개별로 뽑아 순서대로 대기하며, 첫 운행 중 요청은 승차 후, 이후 요청은 직전 응답 후 실제 주행 20초 이상과 다음 별개 정차 기회를 요구한다. 정차 중 반복 추첨·재출발/급정지로 생성하지 않는다. 경로 변경으로 예약을 다시 뽑거나 도달한 진행 조건을 되돌리지 않으며, 목적지까지 남은 시간·거리로 이행 가능성을 재확인한다. 최초 도착 또는 진행률 85% 이후 아직 제시하지 못한 요청은 미발생 중립으로 닫는다. EV03 분실물은 하차 후 별도 사건으로 옮겨 이 운행 중 후보에서 제외한다.

`안전 정차`의 시험 기준은 실제 속도 0.1m/s 이하가 2초 유지되고 교차로 충돌 영역·횡단보도·회전 중이 아닌 상태다. 정지선 앞의 정상 신호 대기는 허용하되 출발 신호나 교통 상황에 즉시 대응해야 하므로 대화 때문에 시간을 멈추지 않는다. 현행 코드의 교차로 근접 일괄 응답 차단은 이 공간·상태 판정으로 바꿔야 한다. 주행을 재개하면 선택 입력을 보류하고 같은 요청을 다음 안전 정차 때 이어간다. 응답 대기 요청이 남으면 다음 요청은 줄을 서며 이행 관찰은 이전 요청별로 계속된다.

말풍선의 선택지를 마우스로 고르며 Y/I/O/U 키는 동일한 선택 처리에 연결한다. 응답 지연이나 합법적 거절·보류만으로 점수를 깎지 않는다. 버튼 자체가 보상이 아니라 **이후 실제 행동·안내**가 평가 대상이다.

개별 요청 17종의 대사·선택·효과·발생 가능 조건은 [11 요청별 콘텐츠](11-passenger-request-effects.md)에 모은다. 해당 표를 별도 문서에서 중복 관리하지 않는다.

## 단골과 개인 예약의 후속 기획

프로토에서는 제외한다. 일반 운송 → 재이용·선호 확인 → 게임 안의 연락 동의 → 조건이 보이는 예약 제안 → 일정 충돌 확인·수락 → 안전한 픽업·운송 → 약속 이행 피드백으로 잇는다. 거절·수신 중지는 가능하고 거절 자체로 운임·운전 만족도·법규 성향을 깎지 않는다. 한 번의 운송으로 단골을 확정하지 않는다. 동시 예약 수, 지각·노쇼, 취소 비용, 관계 보상은 후속 결정 사항이다. 당시 상세 단계와 예외는 [변경 기록](../design-history/content-design/04-passengers-and-reservations-history.md#단골과-개인-예약의-후속-기획)에 보존한다.
