# 승객과 요구 및 개인 예약 기획서

작성일: 2026년 10월 15일 · 버전: 0.2 · 상태: 승객 매너 독립성 보완안

## 기획 의도

승객은 운행의 목적과 작은 변화를 제공한다. 플레이어는 목적지까지 데려다주는 동안 승객의 요청에 대응하고, 안전한 운전으로 신뢰를 얻는다. 단골과 예약은 이전 운행이 다음 만남으로 이어지는 장치다. 복잡한 관계 관리나 회사 경영을 요구하지 않는다.

기존 기획에서 제외했던 단골을 이번 방향에 따라 포함한다. 관계의 핵심은 선호를 기억하고 약속을 지키는 경험이다. 점수를 올리기 위해 반복 대화를 수행하는 구조는 우선 범위에서 제외한다.

## 승객 매너와 법규 콘텐츠의 관계

현재 승객이 요구하는 매너 점수는 승객별 운송 시스템으로 유지한다. 별도의 법규 준수 성향은 빈차를 포함해 누적되는 콘텐츠이며, 그 성향 결과로 승객 요금·팁·단골 신뢰를 자동 변경하지 않는다. 승객이 경험한 승차감과 요구 대응은 매너·서비스의 기준으로 다루고, 법규 기록은 적용 조문과 행동에 따라 별도로 남긴다. 한 행동이 두 시스템에 관찰되더라도 판정 이유를 각각 설명한다.

## 승객을 만나는 방식

| 방식 | 사전에 아는 정보 | 플레이어의 선택 |
|---|---|---|
| 일반 호출 | 픽업 위치, 목적지, 예상 운임, 요청 | 현재 위치와 일정을 고려해 수락 또는 거절 |
| 길가 승객 | 손님 위치와 접근 가능 방향, 확인 후 목적지 | 안전한 승차 위치를 선택해 탑승 안내 |
| 개인 예약 | 예약 시간대, 장소, 목적지, 기존 선호 | 주유와 앞선 운송을 고려해 약속 수락 |

한 번에 탑승객 한 팀만 운송한다. 미래 예약은 현재 운송과 별개로 일정에 둘 수 있지만, 동시에 수행할 수 없는 예약을 중복 확정하지 않는다. 예약 수와 시간 간격은 추후 조정한다.

## 기본 운송 흐름

요청 확인 → 수락 → 픽업 이동 → 안전한 위치에 정차·탑승 → 목적지와 선호 확인 → 운송과 요청 대응 → 하차 위치 확인·정차 → 운임과 평가 → 재이용 가능성 또는 다음 운송.

수락 전에는 거절할 수 있다. 수락 후에는 운행 취소나 지연 안내가 가능하며 이유와 승객 영향에 따라 처리한다. 정상적인 교통 지연과 반복적인 무단 취소는 구분한다. 교통 상황을 예측할 수 없었다는 이유만으로 무조건 신뢰를 잃게 만들지 않는다.

## 승객 요구 콘텐츠

| 요구 | 플레이어 행동 | 평가 원칙 |
|---|---|---|
| 조용한 운행 | 대화를 줄이거나 라디오 조정 | 선호 존중 여부를 서비스에 반영 |
| 창문·라디오 조정 | 간단한 조작으로 수락하거나 안전한 시점까지 보류 | 즉각 반응보다 안전하게 처리했는지 고려 |
| 편안한 승차감 | 사전 감속과 안정적인 가감속 | 위험 회피를 위한 긴급 조작과 구분 |
| 도착 시간 문의 | 예상 시간 확인, 경로 선택, 지연 안내 | 법규를 지키면서 가능한 대응 인정 |
| 편의상 특정 위치 하차 | 가능한 장소 확인 후 대안 제시 | 부적절한 장소의 요청 거절을 실패로 처리하지 않음 |

요청은 운전 중 과도한 메뉴 탐색을 요구하지 않는다. 복잡한 대화는 정차 시 처리하고, 주행 중에는 간단한 수락·보류·설명으로 대응하는 안을 둔다. 교차로 판단과 겹치면 승객 요청이 잠시 기다릴 수 있어야 한다.

시간을 재촉하는 승객도 등장할 수 있으나 과속이나 위반을 성공 조건으로 만들지 않는다. 합리적인 대안을 안내했는데 승객이 불만을 보이는 경우, 승객 감정과 시스템의 서비스 평가는 구분해 보여준다.

## 단골과 개인 예약의 흐름

좋은 운송 경험 → 재이용 의사 표현 → 이후 예약 제안 → 일정 확인·수락 → 사전 준비 → 약속한 시간대에 픽업 → 반복 만남과 선호 기억.

단골 전환은 한 번의 큰 팁보다 반복되는 안전한 운송과 적절한 대응을 근거로 삼는 안이다. 모든 승객이 단골이 되지는 않으며, 정확한 전환 조건과 빈도는 후속 결정한다. 신뢰를 얻는 방식은 법규 위반을 동반한 빠른 도착에 유리하지 않게 설계한다.

예약 카드는 픽업 시간대를 사용하고 필요한 이동 여유를 보여준다. 현재 운송 종료 예상과 주유 필요를 함께 고려하도록 하며, 예약 직전에는 무리한 새 호출 수락을 경고한다. 경고가 확정 도착을 보장하지는 않는다.

| 예약 상태 | 플레이어 경험 | 다음 흐름 |
|---|---|---|
| 제안 | 일정과 조건 확인 | 수락 또는 거절 |
| 확정 | 예정 일정에 표시 | 일반 영업 또는 사전 준비 |
| 픽업 준비 | 이동 여유를 알려줌 | 픽업 이동 또는 지연 안내 |
| 수행 | 안전한 정차 후 탑승 | 일반 운송 규칙 적용 |
| 완료 | 약속과 선호 대응 기록 | 다음 재이용의 맥락 형성 |
| 변경·취소 | 이유와 승객 영향 안내 | 재조정 또는 예약 종료 |

연락 없는 불이행은 신뢰 저하 요인이 될 수 있다. 안전상 정차나 예기치 못한 도로 통제로 늦어진 경우는 안내와 재조정의 여지를 둔다. 예약 취소 수수료, 보상 금액과 시간대 폭은 확정하지 않는다.

## 연결 사례

단골 승객의 오후 예약을 수락했다. 앞선 일반 운송을 마친 뒤 연료가 부족해 주유소를 들른다. 픽업 이동 중 횡단보도에서 기다리게 되지만 예약 여유 안에 도착한다. 승객은 조용한 운행을 선호한다는 기록을 확인하고 라디오를 낮춘다.

하차 후 법규 준수, 부드러운 감속, 선호 대응을 각각 확인한다. 예약 완료는 신뢰의 근거가 되고, 횡단보도에서의 판단은 운전 히스토리에 남는다. 주유 비용과 운임은 하루 결산에 반영한다. 예약 보상이 법규 위반을 지우지는 않는다.

## 수익과 영업 형태의 관계

기본 운임은 운송 제공의 대가, 팁은 서비스의 부가 반응, 단골 신뢰는 다음 만남의 맥락으로 구분한다. 예약 추가 요금은 필수 요소로 두지 않는다. 지연 시 운임 처리와 운송 중단 규칙은 승객 매너·운송 보상 기획에서 별도로 정한다. 법규 성향 콘텐츠 추가만으로 기존 요금 규칙을 변경하지 않는다.

개인택시를 선택하면 단골이 기사에게 직접 요청하는 형태가 자연스럽다. 법인택시를 선택하면 회사 또는 배차 시스템을 통한 기사 지정 요청으로 표현할 수 있다. 이는 게임 설정 후보이며 실제 영업 제도의 허용 범위를 확정한 설명은 아니다. 기본 기사 설정은 [운영 배경 기획](05-daily-operation.md)에서 결정한다.

## 참고작과 차용 범위

Taxi Life 공식 소개에는 승객의 대화·라디오·창문 요청과 서비스에 따른 팁·평가가 제시되어 있다. 본 기획은 이러한 작은 상호작용을 참고하고, 법규 준수와 서비스 평가를 분리하여 적용한다. 개인 예약과 단골은 본 프로젝트의 추가 기획이다. [Taxi Life 공식 소개](https://store.steampowered.com/app/1351240/Taxi_Life_A_City_Driving_Simulator/), 확인일 2026년 10월 15일.

## 결정 사항과 검토 기준

초기 승객 성향 수, 요청 빈도, 단골 전환 기준, 동시 보유 예약 수와 취소 처리가 후속 결정이다. 승객 외형·배경과 운전 요구를 고정 연결하지 않고 성향으로 구성한다.

검토 시에는 요청이 주행에 작은 변화를 주는지, 반복 알림으로 피로를 만들지 않는지, 안전한 대응이 손해처럼 느껴지지 않는지, 단골 예약이 다시 만나고 싶은 이유를 만드는지 확인한다.
