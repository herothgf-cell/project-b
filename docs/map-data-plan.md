# 서울 경기 지도 데이터 도입안

작성일 및 수정일: 2026년 10월 14일 · 상태: 국토지리정보원 주 기반 도입 설계

국토지리정보원의 연속수치지형도와 제공되는 1:1,000 자료를 주 기반으로 사용한다. 첫 지역은 수원 영통역–반달공원으로 선정했고 은계지구를 별도 비교 후보로 추가했다. 영통 1:1,000 목록과 다운로드 신청서를 실제로 확인했다. 수원2296 NGI·NDA·XML은 확보해 31개 레이어·1,942개 도형과 속성 대응을 검사했다. 기존 남쪽 시험 구역은 인접 도엽이 필요하다. [원본 검토 보고서](ngii-sample-review.md)에 확보 파일 내부의 대안 시험 구역을 정리했다. 좌표계 확정·현행 도로 대조·엔진 임포트는 남아 있다. 최신 조사 결과와 시험 위치는 [지도 확보 확인 기록](map-acquisition-check.md)을 따른다.

## 1. 데이터 구성 결정

| 용도 | 주 자료 및 처리 | 역할 |
|---|---|---|
| 지역 기본 배치 | 국토지리정보원 연속수치지형도 | 도로·건물·하천 등의 연속적인 지리 배치 |
| 첫 지역 상세 형상 | 제공되는 1:1,000 수치지형도 | 도로 주변과 지물 형태의 상세 제작 기반 |
| 건물 보완 | 연속수치지형도 건물, 필요 시 GIS건물통합정보 | 건물 외곽·속성 보완 |
| 게임용 차로와 연결 | 원본 도형을 가공하고 검증한 자체 도로망 | AI·경로 탐색·교통 규칙 판정 |
| 교통 흐름과 신호 | 게임 내부 시뮬레이션 | 압축 지도와 게임 시간에 맞는 교통 상황 |
| OSM | 선택적 보조 후보 | 주 자료로 부족한 항목이 확인될 때만 별도 검토 |

‘연속’은 도엽을 연계해 활용하는 방식, ‘1:1,000’은 축척이다. 연속수치지형도 전체를 1:1,000 자료로 취급하지 않는다. 축척이 크다고 반드시 더 최근의 도로 상황을 반영하는 것도 아니다.

공식 수치지도 V2.0 설명은 도형과 속성정보를 포함한다고 안내한다. 연속 자료의 도로중심선과 건물도 별도로 제공된다. 실제 레이어명과 제공 속성은 내려받은 제품의 명세로 확인한다. [수치지도 V2.0](https://www.data.go.kr/data/15059719/fileData.do), [연속수치지형도 도로중심선](https://www.data.go.kr/data/15056842/openapi.do), [연속수치지형도 건물](https://www.data.go.kr/data/15125047/fileData.do)

## 2. 선정 지역과 후속 후보

선정 기준은 지역 인지 요소, 다양한 승하차 목적지, 작은 범위의 대안 경로, 교차로 제작 부담이다. 아래 평가는 공식 지역 안내를 바탕으로 한 설계상 판단이다. 도로망을 내려받아 비교한 점수나 실제 택시 수요·교통량 분석 결과는 아니다. 영통·은계의 제공 목록은 확인했으며 원본 범위·최신성·차로·통행 규칙 검증은 남아 있다.

| 우선순위 | 후보 범위 | 추천 이유와 플레이 제안 | 제한할 범위 |
|---|---|---|---|
| 1 선정 지역 | 경기 수원 영통역–반달공원 주변 일부 블록 | 역세권 상가·주택가·공원을 서로 다른 승하차 목적지로 구성하기 좋음. 본선 대기와 블록 우회 비교를 설계하는 후보 | 영통구 전체와 망포·광교 확장을 제외하고 핵심 8~12교차로로 한정 |
| 2 비교 후보 | 경기 시흥 은계호수공원 서남측 은계중앙로–은계호수로 주변 | 익숙한 도로로 재현과 주행 감각 검증. 검색 범위에서 2025년 1:5,000 확인, 1:1,000 미확인 | 별도 소규모 비교 장면. 영통과 연결 제외 |
| 후속 서울 후보 | 서울 공릉역–경춘선숲길 공릉동 구간 주변 | 주택가와 철길숲의 인지 요소를 활용한 서울 동네 운전. 골목 접근과 정차 위치 선택을 검증하는 후보 | 숲길 전체·화랑대까지의 확장은 제외, 보행 공간을 택시 지름길로 만들지 않음 |
| 후속 경기 후보 | 경기 성남 야탑역 주변 일부 블록 | 역 주변과 주거지 운행을 시작점으로 삼고 추후 탄천·운동장 방향의 목적지 차이를 확장 가능 | 첫 버전은 역 주변에 집중, 탄천 횡단·대형 시설 내부·복잡한 입체 연결을 확장 조건으로 둠 |

### 수원 영통역 주변을 먼저 추천하는 이유

수원시의 영통3동 개청 안내는 반달공원 인근 주택가, 영통중심상가와 아파트 단지를 같은 지역의 구성 요소로 소개한다. 이 자료는 지역 구성의 근거이며 현재 도로 통행이나 상가 영업 상태를 보증하는 자료는 아니다. [수원시 영통3동 지역 안내](https://www.suwon.go.kr/web/board/BD_board.view.do?bbsCd=1043&seq=20171226180618918)

게임에서는 이 구성을 이용해 주택가 호출, 상가 주변 길가 승객, 역 주변 정시 운행을 작은 범위에서 비교할 수 있다는 판단이다. 첫 지도에서는 공원을 길 찾기의 인지 요소로 쓰고 공원 내부 차량 주행은 넣지 않는다. 현행 상호를 그대로 재현하기보다 상가·주거 블록의 분위기를 살린다.

선정할 범위는 영통역과 반달공원을 기준점으로 삼되 연결 도로를 샘플에서 확인한 후 정한다. 지도 전체를 ‘평지’나 ‘격자형’으로 단정하거나 우회가 가능한 교차로 수를 미리 확정하지 않는다. 도엽 번호와 경계 좌표는 원본 검색 결과에서 취득한다.

### 서울 공릉역 주변의 장단점

서울시 공원 안내는 경춘선숲길 공릉동 구간을 다가구주택 밀집지역과 연결된 공간으로 소개하고 공릉역·태릉입구역을 접근역으로 안내한다. 이 지역의 철길숲과 주택가를 인지 요소로 활용할 수 있다. [서울시 경춘선숲길 안내](https://parks.seoul.go.kr/content.do?key=2604300009)

영통 후보보다 서울 동네의 골목 운행을 강조하려는 경우 우선할 만하다. 다만 작은 길의 차량 통행 여부, 일방통행과 승하차 위치를 확인하는 작업 비중이 커질 수 있다. 숲길·산책로는 운행 도로와 명확히 분리한다. 서울 배경을 첫 빌드에서 보여주는 것이 최우선이면 이 후보를 먼저 샘플 검사한다.

### 성남 야탑역 주변의 장단점

성남시 공공시설 안내에는 야탑동 장미로의 상가와 탄천로의 탄천종합운동장 등 지역 목적지가 확인된다. 이들을 단계적 확장의 기준점으로 사용할 수 있다. [성남시 공유안내지도](https://share.seongnam.go.kr/map/map), [성남시 탄천 시설 안내](https://snvision.seongnam.go.kr/20383)

첫 버전은 야탑역 주변 일부 블록으로 제한한다. 운동장·탄천까지 연결하는 범위는 지도 품질과 제작 예산 확인 후 확장한다. 역·주거·대형 시설을 오가는 영업 차이를 보여주기 좋다는 설계 판단이지만, 첫 시제품부터 모두 넣으면 교량·접근도로 등 제작 범위가 커질 수 있다. 실제 시설 운영이나 택시 수요를 게임 설정으로 단정하지 않는다.

### 세부 제작 경계 확정 조건

- 대상 범위와 주변 여유 영역의 필요한 도엽을 확보할 수 있다.
- 도엽별 촬영·조사·제작 시점을 확인하고 서로 다른 시점의 경계 오류를 보완할 수 있다.
- 검증용 출발·도착 쌍 3개에 각각 차량이 합법적으로 갈 수 있는 경로 2개 이상을 확보한다.
- 교차로 2~3개 시험 변환에서 좌표·도로·건물 배치가 맞고 위아래 도로가 잘못 연결되지 않는다.
- 핵심 8~12교차로와 승하차 10~12곳의 범위 안에서 주행을 구성할 수 있다.
- 사용한 자료의 조건에 따라 게임 자산으로 가공·배포할 수 있다.

영통 범위가 조건을 충족하지 않으면 경계를 조정하거나 은계 샘플을 비교한다. 공릉과 야탑은 후속 후보로 남긴다. 1:1,000 자료가 없는 구간은 사용 가능한 다른 축척으로 검증하되, 전 구간 1:1,000 기반이라고 표시하지 않는다. 추천 순위와 데이터 검증 결과는 별도로 관리한다.

## 3. 취득 경로와 절차

### 상세 수치지형도

공공데이터포털의 수치지도 V2.0 안내는 국토정보플랫폼으로 연결된다. 위치·주소·지명 검색 후 수치지형도 종류와 항목을 선택해 내려받는 방식이며 로그인과 대용량 전송 프로그램이 필요하다고 안내한다. 실제 제공 형식·축척은 선택한 도엽에서 확인한다. [공식 취득 안내](https://www.data.go.kr/data/15059719/fileData.do)

1. 국토정보플랫폼에서 우선 후보의 기준점인 영통역·반달공원을 검색한다.
2. 대상 범위에 걸치는 1:1,000 도엽의 존재와 인접 도엽을 확인한다.
3. 도엽번호, 지도 버전, 제작 연도, 제공 형식, 이용 조건을 기록한다.
4. 선택한 파일과 동반 속성·메타데이터를 원형 그대로 보관한다.
5. 파일 시점과 체크섬을 고정해 지도 가공의 재현성을 확보한다.

공식 고시정보에는 축척, 도엽번호와 촬영·조사·제작 연도가 제공된다. 이 목록의 CSV는 지도 도형 원본이 아니므로 원본 수치지형도와 별도로 취득한다. [도엽 고시정보](https://www.data.go.kr/data/15067684/fileData.do)

### 연속 자료

연속수치지형도 건물 자료는 SHP 형식으로 안내되며 브이월드 다운로드로 연결된다. 도로중심선은 WMS/WFS 서비스가 안내되어 있다. 대량 작업에는 제공되는 원본 파일을 우선하고, 파일 제공 여부가 확인되지 않은 레이어는 공식 벡터 서비스의 허용 범위와 호출 조건을 확인해 취득한다. WMS 표시 이미지를 도로 벡터처럼 취급하지 않는다. [건물 파일 안내](https://www.data.go.kr/data/15125047/fileData.do), [도로중심선 서비스](https://www.data.go.kr/data/15056842/openapi.do)

국가공간정보포털이라는 과거 명칭이나 검색 결과만으로 취득 경로를 고정하지 않는다. 해당 자료의 현재 공식 목록에서 연결하는 국토정보플랫폼·브이월드 경로를 따른다. 서로 다른 서비스의 계정·신청·다운로드 조건은 실제 취득 시 확인한다.

## 4. 변환과 게임용 가공

원본 취득 → 레이어·좌표 확인 → 도엽 병합 → 기준 도형 선정 → 시험 주행망 제작 → 선택적 거리 압축 → 차로·신호 보완 → 3D·AI·내비게이션 생성 → 주행 검증

| 단계 | 작업과 주의점 |
|---|---|
| 형식 정리 | SHP는 동반 파일을 함께 보관. NGI·DXF 등은 지원 변환 도구를 확인해 도형·속성이 유지되는 작업 형식으로 변환 |
| 좌표 확인 | 원본의 수평·수직 기준, 단위, 좌표계 정의를 읽고 지역 작업 좌표로 변환. 모든 국내 자료가 같은 좌표계라고 가정하지 않음 |
| 도엽 병합 | 경계의 끊긴 선·중복 건물·작은 틈을 검사. 서로 다른 제작 시점의 도형을 자동으로 겹쳐 합치지 않음 |
| 기준 도형 선정 | 같은 도로의 1:1,000 형상과 연속 중심선이 어긋나면 최신성·형상 품질을 보고 기준을 지정 |
| 도로망 구성 | 중심선·도로 경계에서 이동 경로 작성. 중심선이 없으면 직접 작성·검증. 실제 연결되는 평면 교차만 노드로 생성 |
| 차로·규칙 | 차로별 이동 곡선, 일방통행, 회전 제한, 정지선, 게임용 신호 주기를 보완 |
| 주변 지물 | 건물 외곽을 단순 입체화. 실제 높이·층수 값이 없으면 추정 높이를 명시. 도로 표면 높이와 주변 지형도 점검 |
| 게임 통합 | 동일한 가공 도로망에서 AI·미니맵·경로 탐색·거리 계산을 생성 |

QGIS 등 GIS 편집 도구에서 도형을 검사하고 GeoPackage 같은 작업용 형식으로 정리하는 흐름을 제안한다. NGI나 DXF의 변환 가능성과 속성 보존은 샘플에서 검증하며 프로그램 설치·도구 선택은 구현 단계에서 진행한다. 도형 코드·속성명을 확인하기 전 고정된 필드 이름을 가정한 변환기를 만들지 않는다.

차로 수, 통행 방향, 회전 제한, 제한속도, 고가·지하 연결이 충분히 제공되는지는 별도 확인한다. 세밀한 수치지형도라고 해서 내비게이션 그래프가 완성되어 있거나 모든 규칙이 담겼다고 보지 않는다. 원본 지형과 게임용 운행 규칙을 구분해 기록한다.

## 5. 지도 압축 원칙

- 우선 교차로 2~3개를 원본 상대 배치로 변환해 기준을 확인하고 거리 압축을 적용한다.
- 주요 연결, 교차로 순서, 지역의 인지 요소를 유지한다.
- 긴 반복 구간은 줄이되 차량 크기·도로 폭·제동·차로 변경 공간은 일괄 축소하지 않는다.
- 도로 변화에 맞춰 건물·하천·공원도 함께 이동한다.
- 고가·지하의 높이 차이와 연결 여부를 유지한다. 선이 만난다는 이유로 연결하지 않는다.
- 다른 도로를 관통하거나 합법적 대안 경로가 사라지지 않는지 검사한다.
- 원본 식별자·좌표와 게임 식별자·좌표의 대응을 보존한다.
- 압축된 게임 거리·시간으로 내비게이션·운임·연료를 계산한다.

첫 지도는 수작업 보정이 가능한 크기로 유지한다. 서울·경기 전역의 자동 압축·자동 3D 생성은 시제품 개발 범위에 포함하지 않는다.

## 6. 보조 자료의 사용 조건

GIS건물통합정보는 필요한 건물 속성이 부족할 때 보조 후보로 사용한다. 기준 건물 외곽을 중복 생성하지 않으며 출처와 시점에 따라 채택 도형을 정한다. [GIS건물통합정보](https://www.data.go.kr/data/15083092/fileData.do)

ITS의 표준노드링크와 교통 정보는 후속 교통 패턴 참고용 후보이다. 수치지형도 도로와 링크 식별자·분할 방식이 다를 수 있으므로 대응표가 필요하다. 첫 시제품은 실시간 교통 API를 연결하지 않는다. [ITS 제공 데이터](https://www.its.go.kr/opendata/intro)

OSM은 필수 원본에서 제외한다. 보조로 도형이나 속성을 가져오는 경우 출처와 실제 결합 범위를 기록하고 ODbL의 표시·파생 데이터베이스 조건을 검토한다. 참고·보조라는 명칭만으로 의무가 없어지는 것은 아니다. 국토지리정보원 자료만으로 생성한 데이터와 OSM에서 가져온 내용을 추적 가능하게 관리한다. [OSM 이용 조건](https://www.openstreetmap.org/copyright), [ODbL](https://opendatacommons.org/licenses/odbl/1-0/)

## 7. 이용 조건과 출처 관리

확인 시점의 수치지도 V2.0, 연속수치지형도 건물, 도로중심선 서비스 안내에는 무료·공공누리 제1유형이 표시되어 있다. 제1유형은 출처표시를 조건으로 변경·영리 이용을 허용한다. 개별 다운로드 파일의 별도 조건과 제3자 권리는 함께 확인한다. [V2.0 조건](https://www.data.go.kr/data/15059719/fileData.do), [공공누리 제1유형](https://www.kogl.or.kr/info/licenseType1.do)

안내 페이지의 허락 조건을 모든 국가 공간정보와 모든 1:1,000 파일에 일괄 적용하지 않는다. 데이터별 제품명·축척·버전·도엽·제작 시점·취득일·원본 URL·해시·좌표계·이용 조건·변환 이력을 목록으로 남긴다. 포털의 게시물 수정일은 개별 도엽의 조사일이 아니다.

게임의 데이터 출처 화면에는 실제 사용 자료명, 제공기관, 제작·취득 시점, 이용 조건, 원본 링크와 게임용 가공 사실을 표시한다. 공식기관이 게임을 인증·후원하는 것으로 오인시키지 않는다. 지도 데이터, 자체 모델과 텍스처, 게임 규칙의 출처를 각각 관리한다.

상용 지도 화면·항공영상·거리뷰 이미지는 이 도입안의 원본에 포함하지 않는다. 게임의 지도 화면은 가공한 벡터 자료에서 직접 생성한다.

## 8. 첫 데이터 작업의 산출물과 중단 기준

| 산출물 | 확인할 내용 |
|---|---|
| 후보 지역 검사표 | 영통·은계의 도엽 제공 여부, 연도, 형식, 실제 취득 결과 |
| 원본 목록 | 선택한 도엽·연속 레이어, 출처·조건·좌표계·버전 |
| 작업용 지역 데이터 | 중복·도엽 경계·좌표를 검사한 도로·건물·지형 |
| 교차로 2~3개 시험 장면 | 도로·건물 배치, 높이, 이동 경로와 충돌면 |
| 우회 경로 검사 | 검증용 출발·도착 쌍의 합법적 대안과 정상·정체 상황 비교 |
| 제작 견적 근거 | 수작업 보정 교차로 수, 누락 속성 수, 시험 장면 제작 소요 |
| 지도 배포 기록 | 실제 포함 자료의 표시 문구와 배포 가능 범위 |

1:1,000 도엽이 부족하거나 변환·연결 보정이 첫 시제품 예산을 넘으면 범위를 줄이거나 다른 후보를 검사한다. 누락을 숨긴 채 완전 자동 생성으로 진행하지 않는다. 초기에 실제 도엽 경계와 원본 파일을 검증하는 것이 엔진별 도로 생성기 제작보다 먼저다.
