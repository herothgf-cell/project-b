# 은계 일반 교통·거점·판정 검증

기준일: 2026년 10월 20일. Unity 2022.3.62f2, 은계 Hybrid 빌드, 시작 브랜치 main/a87f8e4.

## 확인한 결과

일반 차량 24대를 유지한 거점 진출입 6건과 출구 뒤 합류·우회전 1건을 택시 물리 주행으로 통과했다. 주행별 신호·급제동·충돌 매너 감점 및 독립 법규 감점은 0이다. 거점에서 같은 방향의 오른쪽 정차, 이용 취소 무차감, 주유·식사 결제까지 확인했다. 테스트한 주행에서는 교통 정체로 진행 불능이 되지 않았다.

| 주행 | 게임 시간 | 최대 경로 오차 | 진행이 없던 최장 구간 |
|---|---:|---:|---:|
| 임시 주유소 접근 | 24.0초 | 0.17m | 1.2초 |
| 임시 주유소 복귀 | 14.5초 | 0.02m | 1.0초 |
| 임시 식당 접근 | 25.3초 | 0.15m | 1.2초 |
| 임시 식당 복귀 | 12.4초 | 0.01m | 0.8초 |
| 임시 주차장 접근 | 24.0초 | 0.18m | 1.2초 |
| 임시 주차장 복귀 | 14.5초 | 1.15m | 0.9초 |
| 출구 대기 후 우회전 | 103.6초 | 2.34m | 18.0초 |

출구 검사 구간은 이번 실행의 `J4289_11068`이다. 교차로 출구 대기열 앞에서 기다리는 시간은 정상 정체에 포함한다. 해당 시설·신호는 게임의 임시 설정이며 현장 시설 검증을 뜻하지 않는다.

## 수정한 오류와 근거

| 오류 | 재현 | 수정·회귀 |
|---|---|---|
| 다른 접근 방향 정지선의 신호 오판 | 차량이 수직 방향을 향한 채 다른 정지선 경계를 조금 넘어도 매너 적색 감점·법규 사건 발생 | 두 관찰기에 진입 방향 정렬 확인 추가. 정방향 적색 진입 위반과 녹색 준수는 유지 |
| 화면과 일반 차량의 가상 신호 불일치 | 화면 녹색인데 기저 자연 신호 시간이 적색이면 NPC 정지, 반대 조건에서는 통과 가능 | 일반 차량도 `Observe`의 적용 신호 사용. 전용 우회전·좌회전 보행자 양보와 교통 간섭 조건 유지 |
| 우회전 뒤 횡단보도에서 필요한 급제동 미인식 | 진입 정지선을 지나 우측 도로로 회전한 뒤에는 보행자 상태가 있어도 필요한 제동으로 감지되지 않음 | 우측 출구 횡단보도의 위치·접근 방향·횡단 의도/횡단 중 관찰을 제동 예외에 연결. 실제 속도 변화로 보행자 제동 무감점과 위험 없는 급제동 감점 유지 검사 |

첫 경계 검사에서 위 오류의 실패를 확인한 뒤 수정했다. 독립 코드 검토에서 가상 녹색 좌회전에 보행자 조건이 빠지는 회귀를 찾아 보완했고, 모든 물리 주행의 신호·급제동·법규 감점을 검사하도록 검증을 강화했다. 가감속 자동화는 시험 운전자에만 있으며 일반 플레이의 H 보조는 조향만 제공한다.

## 출구 A/B/C와 회귀

- `live-exit-choices.txt`: 대기/뒤 합류는 사건 1건·감점 0, 직진 우회는 사건 1건·감점 0·L06 기회 없음, 앞부분 진입은 사건 1건·감점 15·L06 위반. 대기열 8대와 나머지 16대 NPC를 활성화하고 이동 누적도 확인했다. 접근 위치를 제어한 검사다.
- `driving-judgment-test.txt`: 정지선 방향, 정방향 적/녹색, 가상 신호와 기저 시간 불일치, 보행자 있는 좌회전 대기, 우회전 후 필요한 제동 무감점/불필요한 급제동 감점 검사 통과.
- `green-flow-smoke.txt`: 단독·2대·3대 녹색 직진 최소 9m/s, 불필요한 교차로 대기 0프레임, 적색·황색·출구 차단·교차로 점유 시 정지 통과.
- `practice-feedback-test.txt`: 기존 우회전 8사례의 현재 판정, 결과·재시도·이력 보존 회귀 통과.
- `tools/test_prototype.ps1`: C# 모델 8종 통과. 경제·납부·승객 지급·저장 모델의 동작 유지 확인.

`PrototypeBuild.BuildHybrid` 종료 0, 위 네 Player 검사와 우회전 연습 Player 검사 모두 종료 0. 실행 파일은 `builds/EungyeTaxi/EungyeTaxi.exe`다. 출력 파일은 로컬 `artifacts`에 생성되며 버전 관리에는 검사 소스와 이 검증 기록을 남긴다.

## 재현 방법과 한계

은계 빌드를 프로젝트 루트에서 다음 인자로 실행한다. 검사는 사용자 캠페인 저장을 읽거나 쓰지 않는다.

| 실행 인자 | 검사 |
|---|---|
| `-liveTrafficTest -hybridV2` | 물리 주행·일반 교통·거점·출구 A |
| `-liveExitChoicesTest -hybridV2` | 일반 교통 포함 A/B/C 판정 경계 |
| `-drivingJudgmentTest -hybridV2` | 판정 오류·필요 제동 경계 |
| `-greenFlowTest` | 기존 일반 차량 신호·대기열 회귀 |
| `-practice -practiceFeedbackTest` | 우회전 연습 회귀 |

각 물리 검사는 시작 위치만 배치한 뒤 실제 가속·제동 입력과 H 조향으로 주행했다. 거점 접근 약 110m·복귀 45m의 국소 검사이며 거점 간 전체 왕복이나 사람이 직접 운전한 검사와 구분한다. B/C는 위치 제어 분기 검사라 접근부터 끝까지 물리/수동 주행 완료로 표시하지 않는다. 24대 일반 교통이 있는 전체 3일 밸런스와 임시 규제 현장 대조는 미완료다. 실물 패드·새 PC 검증은 사용자 정정으로 프로토 제외다. 출구 최대 경로 오차 2.34m의 수동 조작감도 후속 확인한다.

## 추가 기획과 남은 개발

저장소에 반영된 승객 요청 확장(f789bf4), 법규 후보 62개(a6ee94f), 은계 지도 판단 선택 이벤트(a87f8e4)를 [체크리스트](design-history/prototype-development-checklist-history.md#2026-10-20-웹-추가-기획을-반영한-개발-목록)의 P4/P5/P6으로 분할했다. A-01 캐주얼 그래픽·HUD 시안은 이후 사용자 정정으로 프로토에서 제외했다. 이번 검증으로 이들 신규 기능을 구현 완료로 바꾸지 않았다.

다음 순서는 지도 접근 선택 이벤트 2곳 → 기존 기능 재사용 승객 요청 → 일반 교통 포함 3일 밸런스/현재 PC 빌드 확인이다. 법규 후보는 출처·적용 방향·예외가 확인되는 규칙부터 별도로 도입한다.
