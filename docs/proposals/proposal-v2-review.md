# 제안서 양식 검토 및 마인드맵 반영 — 2차

검토일: 2026-10-27. 대상: `project-b-game-proposal-v1.pptx` → `project-b-game-proposal-v2.pptx`.

## 검토 결론

필수 항목을 19개로 나누어 대조했다(프로토타입 존재 시 필수 2개 포함). 2차본에는 18개 항목의 내용이 들어 있으며, **실제 제안 참여 인원 정보 1개 항목은 미확정**이다. 요청에 따라 이름·인원은 ‘회사 제출 전 확인 필요’로 유지했다. 개발 인력안 6명을 실제 제안 참여 인원으로 간주하지 않았다.

1차본의 문제는 항목 누락보다 **현재 구현 중심이라 완성될 시뮬레이션의 장기 목표가 약한 것**이었다. 2차본은 마인드맵의 현재/후속 가지를 실제로 읽고 차량·관계·환경·경제가 서로 어떻게 영향을 주는지 보강했다. 양식의 경쟁작 장단점은 기획 관점의 강점/한계로 명시했고 아트 스타일도 ‘스타일라이즈드 3D 카툰’으로 구체화했다.

## 선택 항목

UI/UX(21), BM·타겟 마케팅(23), 개발 검증 목표(24), 아트 예시(19~20)를 포함했다. 매출·다운로드·리텐션 수치 목표는 미기재다. 24장의 첫 운송 완료율·재플레이 의향 목표는 **판매 성과 또는 리텐션 실측치가 아닌 제안 단계 플레이테스트 목표**다. 시장 규모와 매출 전망은 실측·회사 원가 확정 후 추가한다.

## 마인드맵을 게임 경험으로 전환한 부분

| 실제 참고 가지 | 제안서의 경험 설명 | 구분 / 슬라이드 |
|---|---|---|
| 맵·운전자·경제·승객·캠페인 | 운송→식사/휴식/관리→정산의 하루 선택 | 현재 기반 / 7~11 |
| 차량 구매 > 연비·연료 타입·트렁크·승차감·구매 방식 | 내가 받을 운송과 운영비에 맞춰 차를 선택 | 제품 목표 / 12·20 |
| 정비 소모품·인테리어·용품점 | 유지비·운행 공백·차량 애착과 재투자 | 제품 목표 / 12·15 |
| 단골·개인 예약 > 재이용·선호·연락 동의·일정 충돌 | 좋은 운행→재이용→예약→하루 계획 | 제품 목표 / 6·13 |
| 차량 내부 조작 > 에어컨·창문·음악 | 요청 답변을 실제 서비스 조작으로 확장 | 확장 후보 / 13 |
| 비/눈·와이퍼·브레이크·버스·사고 현장 | 같은 길에서도 운전 조건·경로 판단 변화 | 후속 후보 / 14 |
| 사고·보험·수리 / 대출·카드 대금 | 영업 중단·비용·재정 회복 판단 | 후속 후보 / 14~15 |
| 화장실·과식·PvP | 생활감과 번거로움/별도 모드의 효과 비교 후 채택 | 후속 검토 / 15~16·25 |

‘차량 종류가 달라지면 어떤 영업을 선택하는가’, ‘예약 때문에 정비·휴식을 언제 하는가’ 같은 연결 문장은 원본 아이디어를 제안서용으로 구체화한 설계 제안이다. 원본 마인드맵이 모든 세부 규칙을 확정했다는 뜻이 아니다. 추가 단속 아이디어는 초기 범위에 구체화하지 않았으며 실제 법규/벌금 수치를 새로 주장하지 않았다.

## 이미지와 범위

생활 거점·차량 성장 이미지는 내장 image_gen 도구로 새로 생성한 **목표 시안**이다. 현재 스크린샷·확정 게임 에셋·실제 은계 배치가 아니다. 이미지의 탑·건물은 아트 분위기 표현이며 신규 서울 지역 채택을 뜻하지 않는다. [이미지 출처·프롬프트](assets/concept-prompts-v2.md)에 파일과 사용 프롬프트를 보관한다.

마인드맵 원본·게임 기획 규칙·게임 코드·기본 빌드·입력 지도는 수정하지 않았다. 2차본에 넣은 기능은 회사가 검토할 제품 방향이며 즉시 구현 승인으로 처리하지 않는다. 확장 기능이 늘어도 기존 12개월/6명 예산이 자동으로 성립한다고 주장하지 않으며 M2 심의에서 다시 산정한다.
