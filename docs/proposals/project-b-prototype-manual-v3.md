# 오늘도 택시 — 제안서 시연 매뉴얼 (V3~V5 공용)

2026-11-06 V5 기준 갱신. 회사 내부 검토용. 작은 방·첫 구매 핵심은 구현되었고 차량 교체·이사는 장기 개발 제안이다.

## 실행

`builds/EungyeTaxi/EungyeTaxi.exe`를 실행한다. 실행 폴더 전체가 필요하다. 통합 메뉴에서 은계 싱글 또는 자체 도시 PVP를 선택한다. 제안서의 생활 성장 설명을 위한 시연은 은계 싱글을 사용한다. 기존 저장을 보존하려면 이어하기를 사용하고 새 회차 초기화는 주의한다. 현재 빌드는 `PrototypeBuild.BuildHybrid`, 배포 기준은 `distribution/EungyeTaxi-build-manifest.json`이다.

## 기본 조작과 시연

| 입력 | 기능 |
|---|---|
| WASD / 방향키 | 전후진·조향 |
| Space | 제동 |
| Q / E | 좌우 방향지시등 |
| C | 1인칭 / 3인칭 전환 |
| H | 조향 보조. 가감속·정차·양보는 직접 수행 |
| M | 지도·호출 |
| F | 현재 단계의 승차·경유·하차 상호작용 |
| F7 | 정차 시설 메뉴 |
| F8 | 상세 기록 |
| Esc | 일시정지·메뉴 닫기 |

1. 은계 싱글에서 현재 상태와 지도 호출을 확인한다. 공개된 정보만 비교하며 수락 전 숨겨진 목적지를 미리 알 수 있다고 설명하지 않는다.
2. 승차 위치와 방향을 맞춰 정차 후 F로 승차한다.
3. 신호·보행자·경로를 보며 운전하고, 요청 발생 시 화면 안내대로 응답한다. 대화 응답과 시설·승하차 등의 정차 조건을 구분한다.
4. 목적지에 정차해 하차하고 운임·요청 결과를 확인한다.
5. 빈차로 시설을 방문해 주유·식사·세차·휴식, 필요 시 공업사 수리 안내를 확인한다. 시설 내부의 유효 정차 조건을 맞춘다.
6. 마감 가능한 휴식/주차 거점에서 영업을 종료하고 수입·비용·순수익을 살펴본다. 전체 검토는 다음 날을 이어 3일을 진행한다.

사고·내구도 0·졸음으로 복구가 필요하면 실행본 안내를 먼저 따른다. 예정 20분은 즉시 강제 정산되는 시점과 같지 않다. 짧은 시연은 전체 3일 경제·조작감 검증을 대신하지 않는다.

## 현재 구현과 제안 구분

- 현재 기반: 은계 싱글 3일, 운송·요청·교통·시설·피로·사고·수리·견인·정산·저장. 통합 실행본에 자체 도시 PVP와 LAN 기반이 있다.
- 개인 생활 핵심 구현: 정산 뒤 내 공간, 조명/러그 미리보기·찜·구매·스타일 선택·보관·조명 조작, 개인 지출 분리, 다음 날/재실행 소유 유지. 처음 방과 비교 및 전체 과거 방 열람은 후속이다.
- 장기 미구현 기획: 연속 영업, 택시 교체, 아파트 이사, 소유물 이월. 현재 3일 반복 초기화를 장기 성장으로 설명하지 않는다.

## 승객 반응 시연

- 승객 유형 대화의 짧은 설명/조용한 안내 선택과 개별 운행 요청 수락은 별개다. 선택을 기억한 대사·감사를 확인한다. 모든 응답을 실제 운전 관찰 판정으로 설명하지 않는다.
- 취객: 말이 많거나 미안해하거나 조용히 가는 변형이 있다. 구토는 조건부 사건이며 매번 발생하지 않는다. 실제 오염 시 진행 중 운송은 마치고 신규 호출 제한·청결 저하에 맞춰 하차 뒤 세차한다.
- 잠자는 승객: 수면 중 무응답은 중립이다. 수면 전 수락한 운행 약속은 유지한다. 유효 목적지 도착 때 시간·운임을 확정하고 깨우는 대기로 지각/요금을 소급하지 않는다. 정차 상태에서 안내에 따라 15초 후 F 재깨우기, 30초 자동 하차 정책을 확인한다.
- 작은 방: 하루 정산 뒤 내 공간에서 미리보기/찜을 확인하고 조명 5,000원 또는 러그 8,000원을 선택한다. 개인 지출과 영업 순수익을 구분하고 다음 날 소유 유지를 확인한다. 구매하지 않아도 정상 진행한다.

이번 문서 작업에서 게임을 실행·재빌드하거나 새 기능을 구현하지 않았다. 방 기능의 구현·검증 근거는 [별도 구현 이력](../work-history/2026-11-06-personal-room-implementation.md)이다. 사람 장시간·전체 캠페인 및 다른 PC 수용 결과는 별도 작업 기록을 따른다.
