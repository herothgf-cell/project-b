# 기간 목표와 영업 정산 구현 · 2026-10-14

## 플레이 규칙

- 새 도전은 7일, 하루 600초, 목표 누적 순수익 100,000원으로 시작한다.
- 호출 및 길가 승객의 실제 지급 요금을 그날 수입으로 기록한다. 매너 미달이면 할인된 지급액만 수입에 반영한다.
- 주행비는 수평 물리 속도 × 고정 시간 간격으로 누적한 거리 1km당 180원, 공회전비는 플레이 1시간당 1,080원이다. 빈차·후진·마감 후 마지막 운송도 포함한다. 일시정지는 제외하며 R 순간 이동을 거리로 더하지 않는다.
- 보험료 2,000원과 식비 3,000원은 운송 실적과 무관하게 하루 마감 시 한 번 차감한다. 소수 기름값은 하루 합산 후 원 미만 올림한다.
- 하루 순수익 = 요금 수입 − 기름값 − 보험료 − 식비. 초기 자금은 없으며 순수익은 음수가 될 수 있다.
- 정차 후 N 또는 영업 마감 버튼으로 조기 마감한다. 시간이 다 되면 자동 마감한다. 승객이 탑승 중이면 해당 운송의 하차 또는 시간 초과까지 기다린다. 새 호출·길가 승차는 차단하고 미탑승 호출은 취소한다.
- 정산 이후 누적 순수익이 목표 이상이면 성공, 마지막 날에도 부족하면 실패한다. 성공·실패 화면에서 새 도전을 시작할 수 있다.

금액은 게임 균형을 위한 설정이며 실제 운영비·연료 가격을 검증한 수치가 아니다. 주유소와 연료 탱크는 이번 범위에 포함하지 않는다. 설정은 `EconomySettings`에 모아 두었으며 장기 플레이 난이도는 추가 체험을 통해 조정한다.

## 저장

`BusinessProgress`는 Unity 사용자 저장 경로의 `campaign-v1.json`에 완료된 정산 기록과 도전 시작 당시 설정을 저장한다. 임시 파일 작성 후 교체하고 `.bak`을 남긴다. 재실행 시 마지막 정산 화면을 복원하며 본 파일이 손상됐다면 백업을 시도한다. 진행 중인 하루는 저장하지 않는다.

저장 실패 시 정산 화면에 재시도 버튼을 표시한다. 다음 날 시작과 새 도전 시작은 저장 성공 후 진행한다. 새 도전 저장에 실패해도 기존 완료 장부를 버리지 않는다. 모든 자동 검사 인자는 실제 사용자 저장을 읽거나 쓰지 않으며, 경제 검사는 `artifacts/economy-player-checkpoint.json`을 사용한다.

## 구현 경계

- `EconomyLedger`: Unity와 분리한 비용·날짜·목표 상태 및 정산 기록 검증.
- `BusinessProgress`: 실제 주행량, 승객 완료, 영업 마감, 일시정지, 저장 연결.
- `BusinessHUD`: 주행 중 목표·오늘 예상 수익, 정산 내역, 다음 날·재시도·새 도전 버튼.
- `PassengerJobs`: 실제 지급액을 한 번 기록하고, 시간 초과를 정산 전에 중복 없이 집계한다.
- 기존 지도, 교통 신호, 일반 차량 경로, 매너 감점 값은 변경하지 않았다.

## 검증 결과

- Unity 2022.3.62f2 Windows 빌드 성공: `artifacts/unity-economy-build.log`의 `PROTOTYPE_BUILD_OK`.
- 독립 C# 경제 검사 21개 통과: 비용 합계, 원 미만 누적, 조기·최종일 성공, 기한 실패, 음수 순수익, 중복 정산·입금 차단, 일별 초기화, 체크포인트 복원·불일치 거부.
- 실제 Player 경제 검사 30개 통과: `artifacts/economy-smoke.txt`, 프로세스 종료 코드 0.
- 실제 주행에 따른 비용, 일시정지, R 복귀 거리 제외, 호출·길가 승객, 마지막 운송 후 마감, 시간 초과 정산, 다음 날, 성공·실패, 미탑승 취소, 이동 중 수동 마감 차단을 확인했다.
- 별도 검사 파일에 실제 저장·원자적 교체·백업을 수행했다. 임시 파일을 잠가 저장 실패를 유발하고 결과 보존·재시도를 확인했다. 로그의 두 `Sharing violation` 경고는 이 의도된 오류 주입 결과다. 실제 사용자 저장 파일의 내용은 변경되지 않았다.
- 기존 승객·경로·자동 카메라 검사 통과: `artifacts/economy-jobs-regression.log`.
- 기존 보호 좌회전·출구 대기·거울 렌더·시선 검사 통과: `artifacts/economy-cockpit-regression.log`.
- 독립 승객 상태 검사 9개, 매너·요금·조향 검사, 지도 Python 검사 6개 통과.
- 1280×720 화면의 주행 패널·1인칭 거울·정산·성공·실패 캡처를 확인했다. 정산 화면에서 거울·보조 카메라를 숨겨 내역과 겹치지 않는다.

경제 자동 검사는 날짜 경계를 빨리 확인하기 위해 시간을 진행시키고 승하차 위치로 차량을 이동시킨다. 7일 전체를 사람이 직접 운전한 난이도 검증을 대신하지 않는다. 정산 캡처 일부는 경계 검사 설정인 2일·10,000원 목표를 사용한다.

## 재현

1. `builds/YeongtongTaxi/YeongtongTaxi.exe` 실행.
2. 호출 1/2/3 또는 길가 손님 F로 운송하고, 목적지에서 F로 요금 수령.
3. 정차 후 N으로 마감해 비용 및 목표 부족액 확인.
4. 다음 날 영업 시작을 누르거나 게임 종료 후 재실행해 마지막 정산 복원 확인.
5. 자동 검사는 실행 인자 `-economyTest -logFile <로그 절대 경로>` 사용.
