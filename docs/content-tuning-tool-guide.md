# 승객·대화·효과·법규 설정 관리

실제 화면: [관리창](ui/2026-11-05-content-tuning/editor-1280.jpg) · [좁은 창](ui/2026-11-05-content-tuning/editor-800.jpg) · [게임 코어 미리보기](ui/2026-11-05-content-tuning/preview.jpg).

## 실행

저장소 루트의 **`설정 관리.cmd`를 더블클릭**한다. 브라우저에 로컬 관리창이 열린다. 이 PC에는 Node.js가 설치되어 있다. 다른 PC에서는 Node.js를 설치하고 다시 실행한다. 게임만 실행할 때는 Node.js가 필요 없다.

PowerShell로 실행할 때는 저장소 루트에서 다음 명령을 사용한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start_content_editor.ps1
```

주소는 실행할 때 표시한다. 인터넷 서비스가 아닌 이 PC의 관리창이며 다른 PC에서 접속할 수 없다. 창을 새로 열려면 실행기를 다시 사용한다. 관리 서버 오류가 표시되면 같은 창에 나온 설명을 확인한다.

## 설정을 바꾸는 순서

1. **새 프로필**에서 이름을 정한다. 프로필 이름에는 영문·숫자·`_`·`-`를 사용한다. 대사와 항목 검색은 한국어로 쓸 수 있다.
2. 왼쪽 분류를 고르고 가운데에서 검색한다. 오른쪽에서 기본값·편집값·단위·범위·영향·관련 설정을 함께 확인한다.
3. 숫자·문구·사용 여부를 수정한다. **이 항목 기본값**은 한 항목, **기본값으로**는 전체 값을 되돌린다. **저장값 복원**은 마지막 저장값으로 돌아간다.
4. **검증**으로 잘못된 값이나 모순된 조합을 확인하고 **저장**한다. 다른 관리창이 같은 프로필을 먼저 저장했으면 충돌을 알리므로 다시 불러와 비교한다.
5. **샘플 계산 미리보기**로 현재 편집값의 결과를 확인한다. **미리보기 입력 조정**에서 운임·운전 만족도 M·요구 만족도·청결 가산을 바꿔 비교할 수 있다. 정산·요청 점수·법규 사건은 각각 계산한다. 계산은 실제 게임 C# 코어로 실행하며 전체 운행 시뮬레이션은 아니다.
6. **분리 테스트 실행**으로 게임을 켜 직접 시험한다. 테스트 게임은 임시 저장 위치를 사용한다. 기존 캠페인을 삭제하거나 덮어쓰지 않는다.
7. 원하는 설정이면 **게임에 적용**한다. 다음 새 싱글 캠페인 또는 새 PVP 방부터 적용된다. 이미 실행 중인 운행과 기존 이어하기는 저장 당시 설정을 사용한다.

**게임에 적용**은 출하 실행본의 설정 파일을 바꾸는 동작이다. **저장**은 편집 프로필 보관, **내보내기/가져오기**는 다른 프로필/PC와 JSON 파일을 주고받는 용도다. 기본값으로 되돌린 뒤 다시 적용하면 원래 밸런스를 시험할 수 있다. 기존 저장에 변경 설정을 강제로 덮어씌우지는 않는다.

## 관리 항목

| 분류 | 내용 |
|---|---|
| 승객 요청 | 요청 사용·상대 가중치·성공/실패/미응답 점수 |
| 대화 선택지 | 요청·유형·상황별 대사·기사 답변·후속 대사 |
| 효과 | 음식 허용·섭취/흘림·청결·준비/하역·재고정·용무 시간 |
| 법규 | 현재 구현된 게임 감점·관찰 수치·M 영향·회복과 법규 참고 색인 |
| 공통 영향 요소 | 요청 개수 비중·시점·기한·요구/시작 만족도·운임/보너스 등 |

문구가 비어 있으면 원래의 동적 대사를 유지하는 항목은 설명을 확인한다. `{errandSeconds}` 같은 지원 자리표시는 현재 설정의 실제 값으로 바뀐다. 임의의 새 자리표시나 새 행동 스크립트를 만들지는 않는다.

읽기 전용 항목은 현재 구현의 고정 조건이나 참고 자료다. 실제 법규의 의미를 임의 수정하거나 미구현 감지기를 켜는 버튼이 아니다. 법규 점수와 승객 운전 만족도 M, 최종 승객 만족도, 운임은 서로 다른 지표이며 관련 항목을 따라 연결을 확인한다.

PVP는 호스트의 설정을 참가자와 봇이 공유한다. 참가자가 자기 PC에서 다른 프로필을 골라도 호스트 경기 설정을 바꾸지 않는다. 이번 설정 snapshot을 지원하는 LAN 버전으로 모든 PC의 실행본을 함께 업데이트해야 한다.

## 보관 위치와 복구

| 자료 | 저장소 기준 위치 |
|---|---|
| 기본 목록/프로필 | `config/content/catalog.json`, `default-profile.json` |
| 사용자 편집 프로필 | `config/content/profiles/` |
| 덮어쓰기 전 백업 | `config/content/backups/` |
| 다음 새 게임에 적용할 프로필 | `builds/EungyeTaxi/content/active-profile.json` |
| 관리창/샘플 계산 로그 | `artifacts/content-editor/` |
| 분리 테스트 캠페인 | 운영체제 임시 폴더의 `EungyeTaxi-content-tests/<실행별 ID>/` |

프로필이 손상되거나 지원하지 않는 버전이면 관리창 검증에서 오류를 표시한다. 게임의 active 파일이 잘못되면 원본을 보존하고 기본값으로 시작하며 설정 상태 안내에 오류를 표시한다. 저장된 캠페인의 snapshot이 잘못되면 기존 저장 복원 보호를 따른다.

동시에 같은 프로필을 저장하면 먼저 저장된 변경을 보존하고 나머지 창에 충돌을 표시한다. 서버 비정상 종료로 저장 잠금이 남은 경우에는 오류에 표시된 고정 잠금 파일을 모든 관리 서버가 종료된 뒤 정리한다. 저장 중인 프로필을 자동으로 덮어쓰지는 않는다.

사용자 프로필에는 크기240KiB, 문구 항목4000자 등의 제한이 있다. 개수 비중 합계100, 발생 진행률 순서, 요구 만족도 순서, 사용 가능한 후보 등의 관계도 함께 검사한다. 게임 파일을 직접 고치는 대신 관리창의 검증·내보내기를 사용한다.

배포 해시 검사 명령은 기존 `pwsh -File tools/update_distribution_manifest.ps1 -VerifyOnly`다. 사용자 active 프로필의 유효한 변경은 별도로 보고하고, 실행 파일·DLL·지도 등 출하 파일은 원래처럼 전체 크기/SHA256을 검증한다.
