## 실행

저장소 루트의 **`설정 관리.cmd`를 더블클릭**한다. 브라우저에 로컬 관리창이 열린다. 이 PC에는 Node.js가 설치되어 있다. 다른 PC에서는 Node.js를 설치하고 다시 실행한다. 게임만 실행할 때는 Node.js가 필요 없다.

PowerShell로 실행할 때는 저장소 루트에서 다음 명령을 사용한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start_content_editor.ps1
```

주소는 실행할 때 표시한다. 인터넷 서비스가 아닌 이 PC의 관리창이며 다른 PC에서 접속할 수 없다. 창을 새로 열려면 실행기를 다시 사용한다. 관리 서버 오류가 표시되면 같은 창에 나온 설명을 확인한다.

## 설정을 바꾸는 순서

1. **새 프로필**에서 이름을 정한다. 프로필 이름에는 영문·숫자·`_`·`-`를 사용한다. 대사와 항목 검색은 한국어로 쓸 수 있다.
2. 왼쪽 분류를 고르고 가운데에서 요청이나 상황을 검색한다. 목록은 개별 숫자가 아닌 요청·승객 유형·효과·법규 상황 단위다. 검색은 연결된 현재/기본 대사와 효과도 찾는다.
3. 먼저 **대화 흐름 미리보기**에서 실제 문구와 선택 결과를 확인한다. 선택지를 누르면 해당 답변·효과의 편집칸으로 이동한다. 숫자·문구·사용 여부를 수정하면 미리보기도 갱신된다. 항목 아래 **기본값**은 한 항목, 하단 **기본값으로**는 전체 값을 되돌린다. **저장값 복원**은 마지막 저장값으로 돌아간다. 공유 설정·세부 판정은 펼쳐서 확인한다.
4. **검증**으로 잘못된 값이나 모순된 조합을 확인하고 **저장**한다. 다른 관리창이 같은 프로필을 먼저 저장했으면 충돌을 알리므로 다시 불러와 비교한다.
5. 하단 **미리보기·테스트 및 적용 상태**를 펼치고 **샘플 계산 미리보기**로 현재 편집값의 결과를 확인한다. **미리보기 입력 조정**에서 운임·운전 만족도 M·요구 만족도·청결 가산을 바꿔 비교할 수 있다. 정산·요청 점수·법규 사건은 각각 계산한다. 이 계산은 실제 게임 C# 코어로 실행하며 전체 운행 시뮬레이션은 아니다. 위쪽 대화 흐름은 문구·설정 연결을 보여주는 미리보기다.
6. **분리 테스트 실행**으로 게임을 켜 직접 시험한다. 테스트 게임은 임시 저장 위치를 사용한다. 기존 캠페인을 삭제하거나 덮어쓰지 않는다.
7. 원하는 설정이면 **게임에 적용**한다. 다음 새 싱글 캠페인 또는 새 PVP 방부터 적용된다. 이미 실행 중인 운행과 기존 이어하기는 저장 당시 설정을 사용한다.

**게임에 적용**은 출하 실행본의 설정 파일을 바꾸는 동작이다. **저장**은 편집 프로필 보관, **내보내기/가져오기**는 다른 프로필/PC와 JSON 파일을 주고받는 용도다. 기본값으로 되돌린 뒤 다시 적용하면 원래 밸런스를 시험할 수 있다. 기존 저장에 변경 설정을 강제로 덮어씌우지는 않는다.

문구가 비어 있으면 원래의 동적 대사를 유지하는 항목은 설명을 확인한다. `{errandSeconds}` 같은 지원 자리표시는 현재 설정의 실제 값으로 바뀐다. 임의의 새 자리표시나 새 행동 스크립트를 만들지는 않는다.

읽기 전용 항목은 현재 구현의 고정 조건이나 참고 자료다. 실제 법규의 의미를 임의 수정하거나 미구현 감지기를 켜는 버튼이 아니다. 법규 점수와 승객 운전 만족도 M, 최종 승객 만족도, 운임은 서로 다른 지표이며 관련 항목을 따라 연결을 확인한다.

PVP는 호스트의 설정을 참가자와 봇이 공유한다. 참가자가 자기 PC에서 다른 프로필을 골라도 호스트 경기 설정을 바꾸지 않는다. 이번 설정 snapshot을 지원하는 LAN 버전으로 모든 PC의 실행본을 함께 업데이트해야 한다.

## 등장 가중치와 입력 범위

**사용 / 사용 안함**은 후보 포함 여부다. 숫자 항목의 **입력 가능한 값**은 저장할 수 있는 최솟값·최댓값이며 등장 확률을 뜻하지 않는다. 사용 여부나 대사에 숫자 범위를 표시하지 않는다.

등장 가중치는 **같은 추첨에 들어온 후보 사이의 상대 비중**이다. 세 후보가 1·1·2라면 첫 추첨 비중은 25%·25%·50%다. 모두 1이면 같은 후보군에서는 같은 비중이며, 0 또는 사용 안함은 후보에서 제외된다. 요청 화면에서 값을 바꾸면 현재 편집 프로필의 기준 비중도 갱신된다.

화면의 기준 비중은 **사용 가능한 일반 요청이 모두 후보라고 가정한 1차 추첨**이다. 전체 운송에서 실제 관측되는 등장 확률은 아니다. 실제 게임은 먼저 요청 0~2건을 배정하고, 승객 유형의 대표 요청·내비/안전한 경로 대안·진행률·안전 정차 기회·중복/상충 요청 제한을 적용한다. 분실물은 일반 가중치 추첨에서 제외되는 하차 후 별도 사건(사용 시 조건부 10%)이다.

## 선택지별 즉시·운행 중·운송 종료 효과

요청 답변·승객 유형 답변·운행 중 상황 답변 **71개**가 각각 독립된 효과를 가진다. 일반 승객(General)은 유형 선택지가 없고, 분실물(LostItem)은 실제 선택이 없는 하차 후 사건이므로 이 목록에서 제외한다. 같은 요청의 서로 다른 답변도 값을 공유하지 않는다. 예를 들어 ETA의 빠름/내비/여유 안내와 공감의 이야기 듣기/조용한 배려를 각각 다르게 설정할 수 있다. 대사·기존 경로 변경·안전 조건은 그대로 유지한다.

각 답변에서 다음 세 단계를 편집한다. 실제 지원하는 종료 결과만 표시한다.

각 선택지의 **운송 종료 후**에 이행 성공/이행 실패(미이행)/판정 불가를 구분한다. 이행 실패는 편안한 운행·제시간 도착·안전 하차·목적지 변경·경유 용무의 수락 답변에서 편집하며 만족도/피로 점·% 각각을 설정한다. 조용한 운행·ETA·공감 등은 현행 게임의 별도 실패 판정이 없어 해당 없음을 표시한다. 보류는 판정 불가이며 끝까지 답하지 않은 미응답과 구분한다. 취소·사고·견인은 종료 효과를 지급하지 않는 기존 규칙이다.

입력칸에는 이름·현재 값·복원 버튼을 우선 표시한다. 적용 시점/영향 대상·계산 설명·기본값/범위·기술 정보는 **설정 설명**, 선택 행동·판정의 긴 설명은 **선택 행동과 판정 조건**, 단계 전체 계산은 **단계 적용 방식**에서 펼친다. 사용 여부와 가중치가 공유하는 안내는 **등장 설정 안내** 한 곳에 모았다.

| 단계 | 만족도 S·기사 피로 항목 | 적용 기준 |
|---|---|---|
| 즉시 | 증감량(점), 현재값 대비 변화율(%) | 선택 확정 직전 현재값에 `점 + 현재값×%/100`을1회 적용. 승차 전 선택은 실제 승차 확정 때 적용 |
| 운행 중 | 증감량(점/분), 활성화 기준값 대비 변화율(%/분) | 즉시 효과 적용 뒤 활성화 때의 S·피로를 고정 기준값으로 보존. 경과 영업시간에 비례하며 저장·프레임 분할로 기준값을 다시 잡지 않음 |
| 운송 종료 | 성공/실패/판정 불가 각각 증감량(점), 현재값 대비 변화율(%) | 실제 기존 요청 판정으로1회 적용. 보류는 판정 불가, 유형/상황은 정상 목적지 하차 때 성공. 취소·사고·견인 등 운송 중단에는 종료 보상 없음 |

즉시/운행 중/유형·상황 종료 효과의 실제 S·피로는0~100으로 제한한다. 요청 종료의 S만 선택지별 계산값을 먼저−100~100으로 제한하고, 요청들의 소수 기여를 합한 뒤 반올림해 기존 `common.requestCap`(기본±10)을 적용한다. **즉시·운행 중·유형/상황 종료의 S는 이 요청 종료 합계 상한 밖에서 기여한다.** 최종 S는0~100이다. 요청 종료 피로도 다른 단계와 같이0~100에서 멈춘다.

운행 중 **자연 피로 증가율 추가(%)**는 기존 시간·허기에 따른 자연 피로 증가에 더하는 비율이다. 활성 선택의 합계를−100~1000%로 제한한다. 예를 들어+100%는 기존 자연 증가의2배,−100%는 자연 증가 억제이며 즉시/종료 피로 효과나 휴식을 없애지 않는다. **급가감속 M 추가 변화(점)**는 음수로 추가 감점, 양수로 감점 완화를 입력한다. -2는 기본 감점에2점 추가 감점, +2는2점 완화다. 활성 합계는−100~100점, 최종 감점은0이상이며 보상으로 바뀌지 않는다. 필요한 안전 제동 판정은 바꾸지 않는다.

**0은 해당 선택지의 추가 효과 없음**이다. 자연 피로·운행·기존 작업 전체를 정지시키는 값이 아니다. 운행 중 효과는 정상 운송의 영업시간을 따르므로 정차 중에도 적용하지만, 메뉴 일시정지·도착 확정 뒤·취소 뒤에는 진행하지 않는다. 반복 응답·저장·재접속은 즉시/종료 효과를 다시 지급하지 않는다.

기본 프로필은 기존 밸런스를 보존한다. 음식 허용의 기본 즉시 S+5는 새 선택지 효과로 한 번만 적용하며 기존 음식 전용 만족도를 중복 가산하지 않는다. Comfort 수락의 기본 M 추가 변화−2도 기존 강화 분기와 중복 적용하지 않는다. 청결·섭취/흘림·짐 작업·재고정·용무 시간은 기존 고정 행동으로 계속 표시한다. 기존 요청 success/failure, 음식 만족도, Comfort 강화 감점은 이관 원본/호환용 참조이며 새 선택지 값을 나중에 함께 바꾸지 않는다.

**답하지 않았을 때**는 안전한 응답 기회 뒤 끝까지 답하지 않은 경우의 기존 독립 결과다. 미응답 감점은 음수로 입력한다. 조용한 운행의 M 변화는 -100~0점이며 -2는 M 2점 감점, 0은 감점 없음이다. 기존 저장 설정을 불러와도 실제 감점은 유지된다. 선택한 보류와 구분한다. 조용한 운행/배려는 새 추가 상황 대화와 취객 일반 수다를 제한하며 별도 배정 요청·필수 안전/승하차 안내는 유지한다. 문구 편집은 표시 대사를 바꾸며 임의 행동 스크립트나 새 감지기를 만들지 않는다.

설정 키는 `choice.<선택지ID>.<단계>.<항목>`이며 새 프로필은schemaVersion2와 `choice.effects.version=1`을 사용한다. [현재 구현 기준](superpowers/specs/2026-11-06-independent-choice-effects.md)이 상세 기준이다. [이전 구조 조사](future-design/2026-11-06-choice-effects-structure-review.md)는 구현 전 상태를 설명하는 역사 자료다.

## 감점 입력과 변화율 계산 안내

법규 감점·운전 만족도 M 감점·음식/오염 짐 청결 감소는 **-2처럼 음수로 입력**하며 0은 해당 감점 없음이다. 기존 설정은 실제 감점을 유지해 표시한다. 선택지의 급가감속 M 추가 변화는 -2가2점 추가 감점, +2가2점 완화이고 0은 원래 감점 유지다. 회복량·확률·시간·상한은 원래 단위를 사용한다. 프로필 JSON은 기존 게임의 양수 감점량을 보존하며 화면 입력/표시만 변환하므로 기존 저장 파일을 직접 뒤집지 않는다.

각 입력의 **설정 설명**을 펼치면 계산 예시·기본값·입력 범위를 확인하며, 선택지가 있는 화면의 **변화율 계산법과 기본 자연 피로**를 펼치면 전체 기준을 볼 수 있다.

- 즉시·종료 %: 적용 직전 현재값 기준으로 한 번 계산. 피로20점의+10%는+2점, S70점의+10%는+7점. 고정 증감도 함께 합산한다.
- 운행 중 %/분: 즉시 효과 이후 활성화 때의 값을 고정한다. 피로 기준20점의+10%/분은+2점/분,30초에는+1점이며 복리가 아니다. 고정 점/분·자연 피로와 별도 합산한다.
- 자연 피로 증가율 추가 %: 현재 피로가 아닌 기본 자연 증가율에 곱한다. 기본4점/분에서+50%는6점/분,−50%는2점/분,−100%는0,0%는원래4점/분이다.

| 현재 포만감 | 싱글 기본 자연 피로 | PVP 기본 자연 피로 |
|---|---|---|
| 25 초과 | +4점/분 | +5점/분 |
| 10 이상~25 이하 | +6점/분 | +7.5점/분 |
| 10 미만 | +8점/분 | +10점/분 |

기존 기본 규칙 안내이며 실시간 기사 상태를 조회한 수치가 아니다. 포만감은 분당5점 줄어 구간을 넘는 순간 증가율도 달라진다. 영업시간이 흐르면 정차 중에도 증가하며 수면/휴식 중에는 자연 증가가 없다. 여러 활성 선택의 자연 피로 추가율은 합산 후−100~1000%로 제한한다. 0은 선택지의 추가 효과가 없다는 뜻이고 기본 자연 피로·기존 운전 사건을 없애지 않는다.

## 이전 프로필과 저장·LAN

구schema1 프로필을 열면 원래 스키마·해시·값을 엄격히 검증한 뒤 기존 설정으로 선택지 기본값을 채워 **메모리에서schema2로 이관**한다. 읽기만으로 원본을 덮어쓰지 않는다. 저장할 때는 원래revision과 이관 의미의 해시로 충돌을 확인하고, 덮어쓰기 전 원본을 `config/content/backups/`에 보존한다. 새 게임에서 구active 프로필을 읽어도 원본 파일은 그대로 둔다.

기존 캠페인/운행 snapshot의schema1은 그대로 복원해 이미 진행 중인 운송에 새 보상을 지급하지 않는다. 디스크 설정 변경은 다음 **새 캠페인 또는 새 PVP 방**부터 적용되며, 이어하기는 저장 당시 설정을 유지한다. 새 형식은 선택·활성화 기준값·누적 효과·마지막 영업시각을 저장한다.

LAN은 **프로토콜v9** 실행본끼리 연결한다. 호스트만 효과를 적용하고 참가자는 같은 프로필·장부 snapshot을 받는다. 참가자 PC의 별도 설정이나 재접속으로 보상이 추가되지 않는다. 이전 프로토콜 실행본과의 접속은 명시적으로 거부하므로 모든 PC의 실행본을 함께 갱신한다.

## 보관 위치와 복구

| 자료 | 저장소 기준 위치 |
|---|---|
| 기본 목록/프로필 | `config/content/catalog.json`, `default-profile.json` |
| 사용자 편집 프로필 | `config/content/profiles/` |
| 덮어쓰기 전 백업 | `config/content/backups/` |
| 다음 새 게임에 적용할 프로필 | `builds/EungyeTaxi/content/active-profile.json` |
| 관리창/샘플 계산 로그 | `artifacts/content-editor/` |
| 분리 테스트 캠페인 | 운영체제 임시 폴더의 `EungyeTaxi-content-tests/<실행별 ID>/` |

프로필이 손상되거나 지원하지 않는 버전이면 관리창 검증에서 오류를 표시한다. 게임의 active 파일이 잘못되면 원본을 보존하고 기본값으로 시작하며 설정 상태 안내에 오류를 표시한다. 저장된 캠페인의 snapshot이 잘못되면 기존 저장 복원 보호를 따른다.

동시에 같은 프로필을 저장하면 먼저 저장된 변경을 보존하고 나머지 창에 충돌을 표시한다. 서버 비정상 종료로 저장 잠금이 남은 경우에는 오류에 표시된 고정 잠금 파일을 모든 관리 서버가 종료된 뒤 정리한다. 저장 중인 프로필을 자동으로 덮어쓰지는 않는다.

사용자 프로필에는 크기240KiB, 문구 항목4000자 등의 제한이 있다. 개수 비중 합계100, 발생 진행률 순서, 요구 만족도 순서, 사용 가능한 후보 등의 관계도 함께 검사한다. 게임 파일을 직접 고치는 대신 관리창의 검증·내보내기를 사용한다.

배포 해시 검사 명령은 기존 `pwsh -File tools/update_distribution_manifest.ps1 -VerifyOnly`다. 사용자 active 프로필의 유효한 변경은 별도로 보고하고, 실행 파일·DLL·지도 등 출하 파일은 원래처럼 전체 크기/SHA256을 검증한다.
