# 프로토타입 통합 범위

기본 실행은 `builds/EungyeTaxi/EungyeTaxi.exe`, 개발 프로젝트는 `unity/EungyeTaxi`, 빌드는 `PrototypeBuild.BuildHybrid`다. 현재 콘텐츠의 기준은 [기획 목록](content-design/README.md), 개발·검증 상태는 [체크리스트](prototype-development-checklist.md), 날짜별 증거는 [작업 이력](work-history/LATEST.md)을 따른다. 이전 범위는 [보존 기록](design-history/prototype-scope-history.md)에 둔다.

## 경험 목표

현재 구현은 P11 요청 다양화·P12 수요/공차·P13 점유 대기와 후속 운전/시설/피로 수정까지 포함한다. 안전 대체 이동은 미구현이며 사람의 조작감·경제 체감은 별도다. [현재 플레이 기획](content-design/README.md), [가지별 마인드맵 검토](content-design/06-mindmap-review.md), [변경 이력](design-history/content-design/2026-10-27-design-decisions.md)을 구분해 읽는다.

| 질문 | 확인할 경험 |
|---|---|
| 운전 판단이 재미있는가 | 정체에서 대기·우회·진입 검토의 실제 시간과 거리, 신호·보행자 조건을 비교 |
| 운송과 응대가 연결되는가 | 승객의 요청·기대·취객 돌발 사건에 대응하고 결과를 이해 |
| 법규와 만족도를 구분하는가 | 캠페인 운전 점수와 운송별 M/S/R, 운임의 관계를 읽음 |
| 짧은 영업이 이어지는가 | 승객→도로 상황→주유/식사/휴식/세차→정산→다음 날 |

## 공통 상태·화면

| 요소 | 원칙 |
|---|---|
| 점수 | 운송M·승객S/요구R·누적 운전 점수 구분. 현재 운임 산식은04에만 정의 |
| 탑승 중 | 시간 초과에도 승객 유지 후 목적지 하차, 기상 대기는 첫 유효 도착 판정 유지. 피로100 노출120초는 안전 감속·정차 후 예외적으로 중도 하차/0원 취소 |
| 세차 | 구토 후 신규 호출 잠금, 길가 시도는 거부 대사로 인지, 세차 완료만 잠금 해제 |
| 시작·이어하기 | 기존 저장 유지, 새 캠페인은 확인 후 초기화. 오류 저장을 덮어쓰지 않음 |
| 정산 | 완료 팝업3줄(최초 예상·운임 조정·실수령), 상세는F8. 일일 장부 중복 거래 없음 |
| UI | 속도·내비·시간·연료·포만감·피로·청결·S/R·운전 점수, 요청과 취객 대사 우선순위 |
| 지도·자료 | 확인된 규제와 게임용 시설/상황 구분. 현장 전수 조사 중단 유지 |
| 조정 수치 | 요청 빈도·감점·회복·비용·소모량은 시험값. 새로운 제안은 승인된 범위와 구분 |

## 완료 판정

| 검증 종류 | 확인할 것 | 대신할 수 없는 것 |
|---|---|---|
| 모델/편집기 | 상태·산식·예외·저장 호환·중복 방지 | 실제 물리 운전·화면 체감 |
| 위치 제어 실행 | 실제 게임 객체·입력 경로·장부·UI·저장 연결 | 전 구간 자동/수동 주행 |
| 자동 물리 주행 | 차로·교차로·거점 진입/복귀·정지/충돌 | 사람의 조작감·난도 |
| 수동20분·3일 | 운송·식사·휴식·주유·세차 비용과 시간·순수익·가독성 | 현장 전체 도로 검증 |
| 배포 | BuildHybrid 실행·필수 입력 상태·실행폴더 SHA256 | 다른 물리 PC·실물 패드 체험 |

요청 배정은 구현됐으며 수동 빈도/경제 검증 잔여를 분리해 관리한다. 이미 구현된 회복·세차·운임·3일 캠페인을 과거 문구 때문에 미구현으로 되돌리지 않는다.

## 2026-10-26 추가 유턴 ④·⑤·⑥

기존 T1 3곳에 J7254 남서·J8066 남·J7973 동 접근 3곳을 추가한다. 좌회전 또는 보행 신호 조건, 진입 방향별 표지, 내비/NPC 경로와 정지선 판정을 연결한다. 확인되지 않은 반대 방향은 추가하지 않는다. 적용·검증 결과는 [작업 이력](work-history/2026-10-26-additional-uturns.md)을 따른다.
