# 첫 시제품 개발 범위

작성일: 2026년 10월 14일 · 상태: 전체 시제품 개발 범위 제안

현재 구현 단계는 이 문서의 전체 캠페인보다 앞선 **영통 한글 운송 시제품**이다. Unity2022.3.62f2에서 전체 확보 도엽·임시 택시·1/3인칭·자동 후방/측면 카메라·깜빡이·신호·일반 차량8대·호출/길가 승객·시간제한 운송·요금·도로 내비게이션을 구현했다. 기간 목표·유지비·매너 점수는 아직 없다. 현재 실행 범위와 조작법은 [프로젝트 안내](../unity/YeongtongTaxi/README.md), 전체 캠페인 목표는 아래 내용을 따른다.

완성 목표는 작은 실제 지역 기반의 3D 도시에서 호출·길가 손님을 태우고, 교통 상황에 대응해 운행하며, 비용을 정산해 3일 캠페인의 성공 또는 실패까지 도달하는 플레이 가능한 빌드다. 이 문서는 개발 범위이며 엔진별 구현 계획이나 개발 완료 보고가 아니다.

## 1. 검증할 질문

1. 키보드와 패드 양쪽에서 차량 조작을 쉽게 익힐 수 있는가?
2. 같은 출발지·목적지에서도 정체에 따라 경로를 바꾸는 판단이 유효한가?
3. 호출과 길가 손님 중 선택하는 것이 수익과 다음 위치에 영향을 주는가?
4. 하루 정산 결과를 보고 다음 날의 영업 전략을 바꾸고 싶은가?

## 2. 규모와 플레이 시간 제안

| 항목 | 첫 시제품 예산 |
|---|---|
| 플랫폼 | PC 싱글플레이, 키보드·패드 |
| 카메라 | 후방 3인칭 하나 |
| 차량 | 플레이어 택시 한 대, 일반 교통 차량의 공용 모델 |
| 지역 | 수원 영통역–반달공원 선정, 세부 경계는 원본 검증 후 확정 |
| 지도 원본 | 국토지리정보원 연속수치지형도 + 해당 지역에 제공되는 1:1,000 수치지형도 |
| 지도 | 압축 후 대략 1~2㎢를 상한 후보로 두되, 제작할 교차로 수를 우선 기준으로 삼음 |
| 교차로 | 핵심 8~12개, 복잡한 입체교차로는 초기 제외 |
| 경로 | 검증용 출발·도착 쌍 3개, 각 쌍에 합법적 대안 경로 2개 이상 |
| 승하차 위치 | 직접 검증한 10~12곳 |
| 승객 유형 | 일반형, 정시형, 승차감형 |
| 교통 사건 | 교차로 대기 증가, 정차 차량의 차로 방해 |
| 환경 | 주간·맑음 한 가지 |
| 캠페인 | 3일, 하루 신규 영업 15분 + 현재 임무 정리 최대 3분 |
| 캠페인 시간 | 순수 진행 약 45~54분, 메뉴·정산 시간 제외 |
| 개별 운송 | 탑승 후 약 2~4분을 초기 조정 목표로 설정 |

위 숫자는 실측치가 아니다. 해당 교차로 수로 대안 경로가 확보되지 않으면 지역 경계를 바꾸고, 지도 면적 확대는 마지막 수단으로 둔다. 서울과 경기도를 모두 구현하는 것은 첫 시제품의 조건이 아니다.

반달공원삼거리와 공원 남서 모서리 교차 지점을 먼저 시험 제작하고, 으뜸공원 동쪽 매영로–청명로 접점을 추가한다. 수원2296 원본 확보·기본 구조 검토 결과 위 구역은 경계에서 잘려 인접 도엽이 필요하다. 추가 취득 없이 시작할 대안은 확보 도엽 내부 T1–T2이며 이후 T3를 추가한다. [원본 검토 보고서](ngii-sample-review.md)의 수정안을 우선한다. 은계지구는 별도의 작은 비교 후보로 추가한다. 두 도시를 연결하는 지도는 만들지 않는다. 위치와 자료 상태는 [지도 확보 확인 기록](map-acquisition-check.md)을 따른다. 시험 통과 후 핵심 8~12교차로로 확장한다.

임무 기한, 교통 신호, 차량 이동은 같은 시뮬레이션 초를 사용한다. 게임 속 시계 표시는 꾸밀 수 있지만 서로 다른 배속을 적용해 기한과 실제 주행이 어긋나지 않게 한다. 일시정지에서는 모든 시뮬레이션 시간이 멈춘다.

## 3. 반드시 포함할 기능

| 시스템 | 최소 구현 | 완료 판단 |
|---|---|---|
| 차량 | 자동 변속, 가속·제동·후진·조향, 입력 보정, 충돌, 복구 | 양 입력 장치로 같은 코스 완주 |
| 도로 | 실제 데이터 기반 도로 골격, 차로, 충돌면, 교차로 연결 | 테스트 경로에 끊김·가짜 연결 없음 |
| 교통 AI | 차로 추종, 앞차 간격, 신호 정지·출발, 지정 사건 | 기본 흐름이 유지되고 사건으로 대기가 달라짐 |
| 내비게이션 | 미니맵 경로, 회전 안내, 거리·ETA, 이탈 후 재탐색 | 막힌 길·역주행 경로를 추천하지 않음 |
| 호출 | 조건 표시, 수락·거절, 픽업 제한시간 | 수락부터 하차까지 일관된 임무 상태 |
| 길가 승객 | 발견, 조건 확인, 정차 후 승차 | 호출 임무와 중복 수락되지 않음 |
| 평가 | 정시성, 신호·역주행·과속·충돌, 승차감 | 감점 이유와 정산 결과가 일치 |
| 경제 | 기본 운임·보너스, 연료 구매, 수리, 보험·식비 | 거래와 최종 달성액이 재계산 결과와 일치 |
| 캠페인 | 날짜 진행, 목표액, 일일·최종 정산, 재시작 | 3일 종료 후 성공·실패 분기 |
| 저장 | 일일 정산 후 저장, 다음 날 이어하기 | 중복 지급이나 이중 비용 차감 없이 복원 |
| 안내 | 첫 운행 조작·승하차·평가 설명 | 외부 설명 없이 첫 손님 운송 가능 |

주유·수리는 하나의 서비스 거점 메뉴로 처리한다. 식비와 보험은 자동 정산한다. 차에서 내려 걷는 기능은 만들지 않는다. 승객의 탑승·하차는 간단한 연출로 처리한다.

교통 AI는 가까운 차량을 우선 처리하고, 먼 구간의 혼잡은 구간별 비용으로 표현하는 방식을 제안한다. 차량 수와 성능 목표는 기준 PC를 정한 뒤 고정한다. 실제 도시 규모의 동시 교통 시뮬레이션을 약속하지 않는다.

## 4. 필요한 화면

- 시작 화면: 새 캠페인, 이어하기, 키보드·패드 설정, 데이터 출처.
- 주행 화면: 속도, 연료·차량 상태, 지도, 임무 조건, 기한, 남은 영업 시간.
- 호출 카드: 픽업까지의 시간, 목적지, 예상 운임, 승객 요구.
- 운행 정산: 기본 운임, 보너스, 감점 이유, 소요 시간.
- 일일 정산: 매출, 현금 지출, 미납 발생 비용, 달성액, 남은 필요 금액.
- 캠페인 결과: 최종 달성액, 성공·실패, 날짜별 비교, 다시 시작.

주행 중 호출 목록은 최대 3건만 표시하는 것을 초기값으로 제안한다. 간단한 선택 입력으로 조작하고 복잡한 경제 내역은 정차·정산 화면에 둔다.

## 5. 초기 범위에서 제외

서울·경기 전역, 다지역 스트리밍, 실시간 현실 교통 연동, 실제 신호주기 복제, 실사급 도시, 운전석 시점, 멀티플레이, 단골, 스토리 분기, 차량 구매·튜닝, 보행자 군중, 승하차 복합 애니메이션, 날씨·야간 변화, 피로·식당 운영, 세금·보험 청구 시뮬레이션, 모바일·콘솔 출시, 음성 내비게이션은 포함하지 않는다.

음성 안내를 제외해도 미니맵·회전 화살표·거리 안내로 내비게이션 기능은 제공한다. 교통 위반 판정은 문서에 명시한 항목에 한정한다.

## 6. 개발 순서와 중간 산출물

| 단계 | 작업 | 산출물과 통과 조건 |
|---|---|---|
| A 데이터 확인 | 국토지리정보원 도엽·연속 자료 취득, 좌표·시점·권리 확인, 교차로 2~3개 시험 변환 | 도엽 경계 접합과 주행 연결을 검증한 샘플, 대안 경로가 확인된 지역과 데이터 목록 |
| B 주행 기반 | 단순 도로·택시·입력·카메라·충돌 | 모든 테스트 도로를 직접 주행 가능 |
| C 교통 판단 | 신호·차량 대기·두 사건·내비게이션 | 정상/정체에서 유리한 경로가 달라짐 |
| D 영업 | 호출·길가 승객·기한·평가·운임 | 두 방식으로 픽업부터 하차까지 완료 |
| E 캠페인 | 비용·3일 진행·저장·최종 판정 | 처음부터 마지막 정산까지 완주 |
| F 조정 | 반복 플레이·버그 수정·가독성·성능 점검 | 아래 검증 항목 충족 |

달력 기준 개발 기간은 인원, 경험, 엔진과 사용 자산이 정해진 다음 산정한다. 지도 정제와 교차로 제작을 별도 작업으로 잡고, 단순히 지도 다운로드 시간만으로 계산하지 않는다.

## 7. 핵심 데이터 책임 제안

| 데이터 | 책임 |
|---|---|
| 도로망 | 방향·길이·통행·교차로 회전·원본 식별자 |
| 차로·신호 | AI 이동과 교통 규칙 판정의 공통 기준 |
| 교통 사건 | 위치·시작·종료·영향 범위·시드 |
| 승객 계약 | 픽업·하차 지점, 요금, 기한, 요구 점수, 상태 |
| 거래 기록 | 운임·보너스·주유·수리·고정비·미납, 중복 방지용 ID |
| 캠페인 저장 | 날짜, 현금, 미납, 차량·연료, 목표, 시드, 데이터 버전 |

3D 도로, 미니맵, 내비게이션과 AI를 다른 좌표 목록으로 따로 관리하지 않는다. 지도 변경 시 같은 도로망에서 다시 생성하고 수작업 보정은 별도 변경 파일에 기록한다.

## 8. 검증과 수용 기준

### 기능 검증

- 호출과 길가 승객 각각 픽업·운송·정산이 끝까지 동작한다.
- 수락 거절, 픽업 지각, 하차 지각, 취소, 시간 종료, 연료 고갈을 처리한다.
- 영업 15분 종료 시 신규 수락이 멈추고 정리 시간이 끝나면 반드시 정산으로 이동한다.
- 길을 벗어나도 합법적 경로를 다시 안내하고, 목적지에 접근 가능한 방향으로 유도한다.
- 모든 승하차 쌍의 도달 가능성을 검사한다. 고립된 지점은 계약 생성에서 제외한다.
- 적신호 위반·역주행·과속·충돌 판정을 의도적으로 재현하고, 정상 운전에서의 오탐을 확인한다.
- 운임·비용·미납은 거래 기록으로 재계산된다. 주유·수리의 중복 차감과 저장 재개 후 중복 지급이 없다.
- 성공과 실패 양쪽의 캠페인 결과를 재현한다.

### 핵심 재미 검증

동일한 출발·도착 쌍과 동일한 입력 조건에 대해 교통 시드만 바꿔 비교한다. 정상 교통에서는 본선이, 지정 정체 상황에서는 우회로가 유리한 테스트 사례를 적어도 하나씩 확보한다. 우회 이점 10% 이상을 초기 튜닝 목표로 두되 실측 결과와 즐거움을 보고 조정한다.

법규를 지킨 운행으로 기본 캠페인이 달성 가능해야 한다. 일부러 위반·충돌하는 주행을 비교해 기본 운임·보너스·수리 손실이 안전 운전을 지속적으로 불리하게 만들지 않는지 확인한다.

최초 소규모 테스트는 플레이어 3~5명을 대상으로 제안한다. 첫 승객 운송 성공 여부, 감점 이해 여부, 자발적 우회 선택, 다음 날 전략 변경 이유를 기록한다. 이 표본을 시장성의 통계적 증거로 해석하지 않는다.

### 금액 조정

먼저 여러 교통 시드에서 합법적 운전의 일일 수입과 지출을 측정한다. 초기 목표액은 일반적인 플레이에서 달성 가능하고 비효율적인 운행에서는 부족하도록 설정한다. 임의로 실제 택시 요금을 적용해 캠페인 난도를 결정하지 않는다.

### 빌드 검증

테스트 PC 사양과 해상도를 고정하고 프레임 시간·정지 현상·메모리를 기록한다. 개발 도구 없이 실행 가능한 빌드, 일일 저장, 데이터 출처 화면, 플레이 방법을 전달한다. 아직 기준 하드웨어가 없어 성능 통과 여부는 주장하지 않는다.
