# 2026-11-05 마인드맵 현황·미구현·사고 검토

현재 기획·코드를 대조한 요약이다. 사고 확장은 제안이며 구현 승인·상세 설계 완료가 아니다. 마인드맵의 50%는 구현 단계, 25%는 기획 완료, 0%는 기획 필요다. 중복 참조 노드 수를 독립 기능 수나 출시 완료율로 읽지 않는다.

## 마인드맵 요약

| 가지 | 구현된 범위 | 남은 범위 |
|---|---|---|
| 운전·교통 | 수동/보조 운전, 조향·S제동 개선, 수요 반응 신호, 일반차 성향 | 사람 조작감·장시간 정체 검증, 버스/전용 교통 기능·추가 법규 |
| 승객·영업 | 호출/길가 승객, 11유형·34변주, 요청/대화, 경유 용무, 게임용 대체 승하차 | 단골·예약, 장소 확대, 실제 음악·에어컨·창문 조작(보류) |
| 차량·생활·경제 | 연료·청결·피로·식사/휴식, 충돌 내구도·수리·견인, 시설 비교/대기 | 차량 구매·부품/꾸미기, 보험·대출/카드, 손상 외형·성능 저하 |
| 캠페인·화면 | 3일 영업·정산·저장, 시작 메뉴 간소화, 경로 표시 보존, 승하차/F안내·M 내 위치 강조 | 사람 20분/3일 경제·가독성 수용、별도 설정 메뉴 |
| PVP | A2 도시, 봇, LAN 최대4인, 자기차 예측/보정 | 다른PC·사람4명·장시간/지연손실 체감 검증. A3는 복원 이전 이력/후속 후보 |
| 환경·사고 확장 | 일반 보행/접촉 감점, 차량 손상·복구 | 야간·비/눈, 대인 사고 처리, 사고 현장·구조·보험/과실 |

P1/P2의 반응형 승객·상태 예측 계산·시설 혼잡·용무 대기·일반차 성향은 이미 구현됐다. 운송 중 상시 상태 예측 HUD 숨김과 계산 미구현을 혼동하지 않는다. 실제 비보호 접근 추가는 표지 근거 대기다.

## 사고: 코드로 확인한 현재 상태

- `unity/EungyeTaxi/Assets/Scripts/VehicleDamageController.cs`: 접촉면 수직 상대 접근속도로 손상을 계산하고 내구도 감소 안내·저장을 수행한다. 내구도0에서 운행 차단·정차 후 운송 실패 처리·수리/견인으로 연결된다. 이미 안내가 있으므로 신규 알림 추가보다 통합 가독성 개선이 먼저다.
- `unity/EungyeTaxi/Assets/Scripts/DrivingManners.cs`: 차량 충돌 감점에는 자기 이전속도/상대속도 등 별도 조건이 있다. 물리 손상과 운전 감점은 같은 판정이 아니다.
- `unity/EungyeTaxi/Assets/Scripts/AmbientPedestrianSystem.cs`: 일반 보행자는 차량과 몸통 거리·속도 조건으로 접촉 감점하며 재접촉 잠금을 둔다. 사고 후 정차/구조 사건은 없다.
- `unity/EungyeTaxi/Assets/Scripts/PassengerJobs.cs`: 대기 승객 외형은 collider를 제거하며 일반 보행자 접촉 흐름과 별도다. 두 집단의 접촉 처리를 맞추는 설계가 필요하다.
- 현재 내구도0 전에는 손상으로 조작 성능이 저하되지 않는다. 보험·과실·치료비·구급차는 미구현이다.

## 프로토에 넣을 사고 방향 제안

1. **결과 전달 개선**: 기존 손상/감점/운송 상태/다음 행동을 하나의 사고 요약으로 보여준다. 가장 작은 범위지만 사람을 치고 지나가는 문제는 남는다.
2. **간단한 사고 처리(추천)**: 1에 일반 보행자·대기 승객의 공통 접촉 사건, 짧은 비선정적 반응, 안전 정차 후 결과 확인과 복귀를 더한다. 사고를 인지하고 영업 손실을 이해하는 경험을 먼저 검증한다.
3. **보험·과실·현장 구조까지 확장**: 사고 책임/보전·교통 통제·구급차를 포함한다. 판정·경제·AI 범위가 커 후속으로 두는 편을 추천한다.

추천 흐름: 접촉 감지 → 사건1회 확정 → 상대 유형/손상/기존 감점 안내 → 필요 시 안전 정차 → 운송 결과 확인 → 운행 재개 또는 기존 견인·수리.

세부 기획에서 결정할 것: 경미/중대 구분 기준, 보행자 접촉 시 운송 중단 여부, 정차/처리 시간, 운임 보호/취소, 추가 비용 유무. 이 문서는 수치·비용·강제 정차 정책을 확정하지 않는다. 실제 법적 과실 판단을 게임 충돌 판정으로 대체하지 않는다.

공통 설계 조건: 기존 손상/감점 중복 적용 방지, 연속 밀기 사건 중복 방지, 싱글 저장/재개 중복 처리 방지, PVP 호스트 사건 권한·참가자 복제, 처리 중 다른 참가자 시간 유지. 기존 P15 수리비/견인비를 다시 청구하지 않는다.
