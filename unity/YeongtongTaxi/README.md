# 영통 택시 시뮬레이터 · 한글 시제품

## 경로 판단 중심 보조 운전 시험 브랜치

`feature/assisted-route-driving`의 비교 빌드는 루트 `Play-AssistedTrial.cmd`로 실행합니다. 실행 파일은 `builds/AssistedTaxi/AssistedTaxi.exe`이고, 시험 인자는 `-assistedTrial`입니다. 시험은 기존 캠페인 저장을 읽거나 쓰지 않습니다. 일반 실행에서는 기존 캠페인과 수동 조작으로 시작합니다.

- **H**: 보조/수동 전환. 도로 차로의 진행 방향에 맞춰 켜세요.
- **W/S, 위/아래**: 기존 가속·제동·후진. 후진 시 보조는 해제됩니다.
- **A/D, 좌/우**: 같은 방향 옆 차로로 한 번 변경. 편도 2차로에서 가능하며, 정지 중·교차로 직전·다른 이동 중에는 거절합니다. 옆 공간이 막혀 있으면 요청을 저장하지 않으므로 확인 후 다시 입력하세요.
- **Q/E 또는 패드 LB/RB**: 다음 교차로 좌/우회전 예약. 다시 누르면 직진 선택. 현재 차로에서 가능한 방향은 HUD에 표시합니다.
- **Space**: 직접 강한 제동. 신호와 앞차를 보고 직접 멈춰야 합니다.
- **F6/F7**: 시험 모드에서 정상/정체 조건으로 재시작. 택시·승객·교통·시간을 초기화합니다.

시험은 T1 진입부에서 출발해 T2 북서쪽 도착 구역에 정차하는 방식입니다. 하늘색은 본선, 주황색은 우회로, 초록색은 도착 구역입니다. 정체 조건은 본선의 세 정차 차량이 시험 시작 120초 뒤 제거되는 고정 조건으로, 실제 교통 예측이 아닙니다. 자동 경로 선택이나 신호 정지 기능은 없습니다. 좁은 도로(폭 9m 미만)는 첫 보조 범위에서 제외하며 도로 이탈 시 수동으로 복귀합니다.

차로 변경·회전은 물리 조향으로 수행합니다. 충돌을 막아주는 기능은 아니며, 높은 진입 속도와 다른 차량의 접근은 직접 판단해야 합니다. 현재 조향과 감속 수치는 시험용입니다. 게임 조작감과 재미는 사용자 플레이 검증이 필요합니다.

빌드: Unity 배치 메서드 `PrototypeBuild.BuildAssisted`. 자동 검사: `AssistedNetworkTests.Run`, Player `-assistedTest`, Player `-assistedTrial -trialTest`. 전체 경로 자동 검사는 별도의 시험 운전자가 가감속·신호·회전 선택을 공급하며, 일반 플레이에는 적용되지 않습니다.

Unity 2022.3.62f2 / Windows 64비트. 실행 파일은 프로젝트 루트의 `builds/YeongtongTaxi/YeongtongTaxi.exe`입니다. 같은 폴더의 Data와 DLL 파일을 함께 유지하세요. Unity에서는 `Assets/Scenes/FirstDrive.unity`를 열고 Play를 누릅니다. 장면은 실행 시 생성됩니다.

## 운송 체험

1. 화면 아래 호출 3개에서 픽업·목적지·예상 요금·제한 시간·매너 요구 점수를 보고 **1/2/3 또는 버튼**으로 선택합니다.
2. 하늘색 내비게이션 경로를 따라 픽업 구역으로 이동합니다. 손님이 서 있는 오른쪽 연석에 화살표와 같은 방향으로 시속 2km 미만으로 정차하고 **F**로 승차합니다.
3. 호출 없이 길가의 하늘색 손님 표시를 찾아 정차 후 **F**를 눌러도 운송이 시작됩니다.
4. 승차할 때 목적지 경로와 카운트다운이 시작됩니다. 도착해서 정차 후 **F**로 하차하면 기한 내 도착 요금이 지급됩니다. 매너 요구 점수에 미달하면 70%가 지급됩니다.
5. 시간 초과면 지급되지 않습니다. 결과 표시 4초 뒤 다음 호출을 선택할 수 있습니다.

한 번에 한 손님만 운송합니다. 받은 요금은 그날 장부에 쌓이고, 마감 때 비용을 빼서 기간 목표의 누적 순수익에 반영됩니다. 게임용 요금은 3,000원 + 경로 1m당 4원을 100원 단위로 올림한 값입니다. 제한 시간은 최소75초 또는 경로거리÷6+50초입니다. 실제 택시 운임이 아닙니다. 픽업까지의 이동은 승객 제한 시간에 포함하지 않습니다. R 복귀로도 운송 제한 시간은 초기화되지 않습니다.

## 기간 목표와 하루 정산

기본 도전은 **7일 안에 누적 순수익 100,000원**입니다. 하루는 실제 플레이 시간 **10분**이고 일시정지 중에는 영업시간과 기름값이 늘어나지 않습니다. 초기 자금은 따로 없으며 누적 순수익은 음수가 될 수 있습니다. 목표 달성 여부는 하루 비용을 모두 뺀 정산 시점에 판단합니다. 목표에 먼저 도달하면 성공, 7일차 정산까지 미달하면 실패입니다.

- 기름값: 실제 물리 이동 속도로 계산한 주행거리 **1km당 180원** + 시동 공회전 **1시간당 1,080원**. 빈차·후진·마지막 승객 운송도 포함합니다. 소수 비용은 누적 후 하루 단위로 원 미만 올림합니다. R 복귀의 순간 이동 거리는 청구하지 않습니다.
- 보험료: 하루 **2,000원**, 식비: 하루 **3,000원**. 운송이 없는 날도 마감하면 부과됩니다.
- 화면 왼쪽에 영업일·남은 시간·오늘 요금·비용 반영 예상 순수익·정산 누적·목표 부족액을 표시합니다.
- 안전한 곳에 시속 2km 미만으로 정차 후 **N / 영업 마감 버튼**을 누르면 일찍 마감합니다. 10분이 지나면 자동 마감합니다.
- 승객이 타고 있으면 새로운 호출을 막고 현재 승객 하차 또는 시간 초과까지 운행한 뒤 정산합니다. 아직 승차하지 않은 호출은 취소하며 실패 운송으로 세지 않습니다.
- 정산 화면에서 요금, 기름값, 보험료, 식비, 오늘 순수익, 누적 순수익, 남은 목표 금액과 영업일을 확인합니다. **다음 날 영업 시작**은 택시와 호출을 초기화하고 다음 날을 엽니다.
- 정산 완료 시 자동 저장하고, 재실행하면 마지막 정산 화면에서 이어갑니다. 진행 중인 하루의 미정산 수입·비용·운송은 저장되지 않습니다. 성공·실패 화면의 **새 7일 도전 시작**은 기존 기록을 초기화합니다.

저장 파일은 Unity `Application.persistentDataPath`의 `campaign-v1.json`이며 직전 저장의 `.bak` 백업을 유지합니다. 자동 검사 실행은 이 파일을 읽거나 수정하지 않습니다. 게임용 경제 설정은 `Assets/Scripts/EconomyLedger.cs`의 `EconomySettings`에서 변경합니다. 기존 저장에는 시작 당시 설정이 유지됩니다. 실제 연료 시세·보험 계약·택시 운영비를 재현하는 금액이 아니며, 주유소·연료 탱크·대출·차량 정비비는 아직 구현하지 않았습니다.

## 1인칭 거울과 코너 시야

C로1인칭에 들어가면 좌·우 사이드미러와 룸미러3개를 상시 표시합니다. 실제 도로·차량을 별도 카메라로 렌더링하고 거울처럼 좌우 반전합니다. 약30Hz 갱신, 시야180m이며 3인칭·수동 뒤보기에서는 렌더링하지 않습니다. 현재는 운전석 화면에 고정한 거울 패널 형태입니다.

시야각을72도에서82도로 넓히고, 조향할 때 이동 속도에 따라 최대18도까지 코너 쪽을 봅니다. V로 자동 보정을 끌 수 있습니다. Z/X 또는 오른쪽 스틱으로 최대65도 좌우 둘러보기, 놓으면 전방으로 복귀합니다. 대시보드와 운전대는 차체에 고정되어 고개를 돌릴 때 함께 따라 돌지 않습니다.

## 자동 보조 카메라

후진을 시작하거나 뒤로 움직이면 우측 아래 **후방 카메라**가 자동 표시됩니다. 좌/우 깜빡이를 켜면 해당 **측후방 카메라**가 표시됩니다. 후진이 깜빡이보다 우선합니다. 해제되면 화면이 사라집니다. 1인칭에서는 상시 사이드미러를 사용하므로 깜빡이 보조 화면은 중복 표시하지 않고, 후진 보조 화면만 추가로 표시합니다. 앞을 보며 운전할 수 있게 주 카메라는 유지합니다. C로 운전석/3인칭 전환, B로 수동 뒤보기 역시 사용할 수 있습니다.

## 내비게이션과 지도

- 미니맵과 도로 위 하늘색 선으로 도로 연결을 따라 안내합니다. 다음 회전·남은 경로 거리를 표시하고 약0.8초마다 현재 위치에서 다시 경로를 구합니다.
- 노란 점은 택시, 하늘색 점은 길가 손님, 주황색 점은 목표입니다. 지점 이름은 실제 지명이 확인되지 않아 **승하차 A~H**로 표시합니다.
- 우측 통행 차로와 도착 방향을 고려한 경로입니다. 중간 도로에서 즉시 반대 방향으로 돌도록 안내하지 않으며, 손님 쪽 연석으로 접근하도록 주변 도로를 돌아올 수 있습니다. 실제 회전 금지·일방통행·실시간 정체를 반영한 길 안내는 아니며, 음성 안내도 아직 없습니다.
- 기존260×275 범위에서 확보 도엽 전체444.03×555.27로 확대했습니다. 면적 약3.45배, 도로선232개(총 중심선 약4.98km), 건물303개입니다. T3와 순환 가능한 연결 도로가 포함됩니다. 지형은 평면입니다.
- 원본은 국토지리정보원 2008년 1:1,000 수원2296이며 `data/raw/ngii`에 보존했습니다. 투영 좌표계 미확정 상태로 상대 좌표를 미터로 임시 해석하며 축척을 임의 확대하지 않았습니다. 더 넓은 실제 지역에는 인접 도엽이 필요합니다.

## 차로와 교통

원본 차로수는 1(154개), 2(4개), 4(69개), 5(5개)입니다. 전부 왕복2차로인 지역이 아닙니다. 게임은 4를 왕복4차로로 표시하고, 5는 방향·회전차로 배분이 불명확하여 임시4차로로 표시합니다. 1·양방향 기록은 임시왕복2차로로 해석합니다. 원본 속성은 JSON에 별도로 보존합니다. **2008년 기록이며 현재 현장 차로 수는 미확정**입니다. 자세한 근거는 `docs/road-lanes-and-map-expansion.md`를 참고하세요.

T1·T2는 직진과 좌회전을 분리한 게임용56초 주기입니다. 주도로 직진12초·황색3초·전적색2초, 교차도로 직진10초·황색3초·전적색2초, 주도로 좌회전8초·황색2초·전적색2초, 교차도로 좌회전8초·황색2초·전적색2초 순서이며 T2는7초 시차입니다. 신호등에 녹색 좌회전 화살표가 표시되고 가까운 교차로의 직진/좌회전 상태를 HUD에도 표시합니다. 좌회전은 화살표에 따라 진행하며, 우회전 AI는 직진 녹색에만 진행합니다. 일반 차량12대가 직진 및 좌·우회전 경로를 운행합니다. 앞차·택시·건물 등을 경로를 따라 감지해 대기하며, 교차로 안과 출구가 비어 있을 때 한 차량씩 진입합니다. 회전 차량은 속도를 낮추고 방향지시등을 켭니다. 정지선 가까이 있는 선두 차량 중 먼저 도착했고 현재 신호와 출구 공간이 허용되는 차량이 진입 순서를 받습니다. 출구가 막힌 대기 차량이 다른 방향까지 붙잡지 않도록 제외합니다. 교차 도로 AI는 곡선 구간으로 직선 주행하지 않도록 교차로 양쪽60m 이내로 제한했습니다. 확대 지도의 모든 도로에 일반 차량이 배치된 것은 아닙니다.

보행자 횡단과 실제 지역별 회전 제한·신호 현시 반영은 후속 범위입니다. 차선·신호·차량·건물 외관과 운임은 게임용 시제품 설정입니다.

## 운전 안정화와 매너

크게 조향하면 코너 감속 보조가 가속을 서서히 제한하고 완만하게 제동합니다. 가속키를 계속 누른 채 돌아도 코너에서 계속 빨라지지 않게 하며, 끝까지 꺾으면 약15~16km/h를 유지합니다. 보조 작동 중에는 HUD에 표시됩니다. 1·3인칭 및 좌·우 회전에 동일하게 적용하며, 후진·작은 차선 보정·직진 가속·수동 강한 제동은 유지합니다. 고속 접근 시에는 회전 전에 직접 충분히 감속하세요.

고속에서는 조향각을 줄이고, 무게중심을 낮추며, 접지 중 차체 기울기와 회전을 보정합니다. 사고 충격을 없애거나 차체를 완전히 고정하지는 않습니다. 급한 코너에서는 먼저 속도를 줄이세요.

인도는 도로 바깥 여유 공간에 약2m 폭·16cm 높이로 생성한 게임용 연석입니다. 원본에서 확인한 실제 보도 형상은 아니며, 건물·교차 도로와 겹치는 구간은 생략됩니다.

매너는 승객 탑승 시100점으로 시작하고 HUD에 현재 점수·요구 점수·감점 사유를 표시합니다. R 복귀는 매너와 제한 시간을 초기화하지 않습니다. 빈차 상태도 운전 피드백은 표시하되 다음 승차 시 새로 시작합니다.

| 사건 | 감점 | 판정 |
|---|---:|---|
| 신호 위반 | 12 | 적색 진입, 화살표 없이 좌회전, 좌회전 전용 현시에 직진 |
| 충돌 | 10 | 저속 접촉·지면 착지를 제외한 차량·벽면 충돌 |
| 급가속 | 3 | 평활 가속도3.3m/s² 초과가0.25초 넘게 지속 |
| 급제동 | 4 | 평활 감속도5.5m/s² 초과가0.25초 넘게 지속 |
| 도로 경계·인도 침범 | 5 | 두 바퀴 이상 도로 밖에서 주행을0.7초 지속 |

정지선 통과 시 허용된 방향을 기록하고 실제 교차로 출구 방향으로 좌회전/직진 위반을 판정합니다. 깜빡이만 바꿔 판정을 피하지 못하며, 적색 진입을 같은 교차로 출구에서 다시 감점하지 않습니다. 같은 사건은 재발 대기시간과 지속 상태 잠금으로 중복 감점을 억제합니다. 승객 요구는60·70·85점이며 기한 내 요구 점수 달성 시 요금100%, 미달 시70%, 시간 초과 시0원입니다. 실제 법규의 과태료·벌점 또는 책임 판정을 재현한 값이 아닙니다.

## 한글 및 검증

게임 창 제목, HUD, 호출·승객·내비게이션·카메라·일시정지 메뉴는 한글입니다. Windows에 설치된 **맑은 고딕**을 사용하며 OS 글꼴 파일을 재배포하지 않습니다.

Unity 메뉴 `Taxi > Build Windows Prototype`에서 다시 빌드합니다. 지도는 프로젝트 루트에서 `python tools/export_drive_map.py`로 다시 변환합니다. 자동 검사는 실행 인자 `-smokeTest`(택시 물리), `-trafficTest`(교통), `-jobsTest`(승객·내비·자동 카메라), `-stabilityTest`(차체 안정성·매너·방향별 정차·회전·대기열), `-cockpitTest`(거울 실제 렌더·시선·보호 좌회전·출구 차단), `-flowTest`(384초 차량별 반복 완주·최대 정지시간), `-economyTest`(영업 마감·비용·승하차 입금·날짜·승패·저장 복원), `-turnTest`(1·3인칭 좌우 조향·코너 속도·기울기 비교)이며 결과·캡처는 `artifacts` 폴더에 저장됩니다. 승객 검사는 상태 전환을 분리하기 위해 승하차 위치로 차량을 이동시키므로 전체 운송 경로의 수동 주행까지 검증한 것은 아닙니다.
